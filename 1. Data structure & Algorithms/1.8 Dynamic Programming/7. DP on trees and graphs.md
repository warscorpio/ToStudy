## Topic A: Tree DP Fundamentals

### Section A1: Core Mechanics

**Q1. What is tree DP, and why does a tree's structure make bottom-up DP natural?**

A: Tree DP is a dynamic programming technique where subproblems are defined on subtrees: `dp[v]` represents the answer restricted to the subtree rooted at v. Two properties of trees enable clean DP: (1) **no cycles** — there is a unique path between any two nodes, eliminating ambiguity about how subproblems relate; (2) **clear parent-child hierarchy** — a rooted tree gives every node exactly one parent, making the transition direction unambiguous. Post-order DFS (process all children before the current node) maps directly onto the DP computation order: when computing `dp[v]`, all children's `dp` values are already finalized. Each node is visited exactly once — O(n) time for any tree DP that does O(1) work per node.

```
Array DP:      dp[i] depends on dp[i-1], dp[i-2], ...   (linear chain)
Tree DP:       dp[v] depends on dp[c] for all children c  (branching)

Post-order DFS computes dp[leaf] first, dp[root] last — exactly the right order.
No memoization key collision: each node is a unique subproblem.
```

**Q2. What is the "return value contract" in tree DP, and how does it differ from the global answer?**

A: The return value of the recursive function is what the parent node *needs from its child's subtree* — not necessarily the final answer. The global answer is often updated as a *side effect* at each node, using information from both the left and right subtrees simultaneously (which the parent never sees combined). This split is essential: the parent can only use one arm going downward into any child subtree, but the global optimal may pass through the current node using *both* arms. The return value serves the parent; the global update serves the answer.

```
Binary Tree Maximum Path Sum:

At node v:
  leftArm  = max single-arm path going INTO left child
  rightArm = max single-arm path going INTO right child

Global update:  globalMax = max(globalMax, v.val + leftArm + rightArm)
  ← uses BOTH arms: path crosses through v

Return to parent: v.val + max(leftArm, rightArm)
  ← uses ONE arm: parent can only extend in one direction down through v

These serve different purposes — global update ≠ return value.
```

**Q3. What is the "path-through-node" pattern, and why must negative subtree contributions be zeroed out?**

A: The path-through-node pattern applies when the optimal answer is a path that may cross through any node in the tree (not necessarily rooted at or ending at the root). For each node v, the best crossing path is `v.val + best_left_arm + best_right_arm`. A negative arm contribution (a subtree whose sum is negative) should be replaced with 0 — including that arm would make the path *worse*. This is expressed as `Math.max(0, dp(child))`: if the child's best arm is negative, treat it as 0 (don't extend into that subtree). Without this, paths through sparse negative subtrees are incorrectly penalized.

```
Tree:     -10
          /  \
         9   20
            /  \
           15    7

At node 20:
  leftArm  = max(0, dp(15)) = max(0, 15) = 15
  rightArm = max(0, dp(7))  = max(0, 7)  = 7
  crossing: 20 + 15 + 7 = 42   ← global max candidate
  return to -10: 20 + max(15, 7) = 35   ← best single arm

At node -10:
  leftArm  = max(0, dp(9))   = max(0, 9) = 9
  rightArm = max(0, dp(20))  = max(0, 35) = 35
  crossing: -10 + 9 + 35 = 34   ← global max candidate (42 already better)
```

**Q4. What are the two-state tree DP transitions for the "maximum independent set on a tree" problem?**

A: The maximum independent set on a tree: select a maximum subset of vertices such that no two adjacent vertices (parent-child) are both selected. Two states per vertex capture the constraint: `dp[v][0]` = maximum selection size in v's subtree when v is NOT selected; `dp[v][1]` = maximum when v IS selected. The transitions encode the adjacency constraint:

- `dp[v][1] = v.val + sum(dp[c][0] for all children c)` — if v is selected, no child can be.
- `dp[v][0] = sum(max(dp[c][0], dp[c][1]) for all children c)` — if v is not selected, each child can be either.

This is the canonical two-state tree DP. "House Robber III" is exactly this problem: houses are vertices, adjacent parent-child pairs cannot both be robbed.

```
Transitions:
  dp[v][1] = v.val + Σ dp[c][0]           child CANNOT be selected
  dp[v][0] =        Σ max(dp[c][0], dp[c][1])  child CAN be either

Leaf node:
  dp[leaf][0] = 0   (not selected, no children)
  dp[leaf][1] = leaf.val  (selected, no children to constrain)

Answer: max(dp[root][0], dp[root][1])
```

### Section A2: The Rerooting Technique

**Q5. What is the rerooting technique, and when is it necessary over a single-pass tree DP?**

A: A single-pass post-order tree DP computes the answer for each vertex *within its own subtree* (with the tree rooted at a fixed root, say 0). When the problem asks for the answer *from each vertex's perspective as the root* — for example, "the sum of distances from vertex v to every other vertex in the tree" — a single pass computes only the root's answer correctly. Re-running DFS from each vertex naively is O(n²). The rerooting technique achieves O(n) by computing the answer for all vertices in two passes: a bottom-up pass (compute subtree contributions) followed by a top-down pass (propagate the "outside world's" contribution downward from parent to child, re-using already-computed subtree values).

```
Single-pass: dp[v] = answer for subtree of v only (tree rooted at 0).
  Correct for the root; incomplete for other vertices.

Rerooting need: "if v were the root, what would the answer be?"
  v's subtree is the same, but v also has a "parent subtree" (the rest of the tree)
  = everything outside v's original subtree.

Two-pass:
  Pass 1 (bottom-up): compute dp_down[v] = subtree-only answer.
  Pass 2 (top-down):  compute dp_up[v] = "outside" contribution from v's parent.
  Full answer at v = combine(dp_down[v], dp_up[v]).
```

**Q6. Derive the rerooting recurrence for "Sum of Distances in Tree" step by step.**

A: Let `n` = total nodes, `sz[v]` = number of nodes in v's subtree (rooted at 0), `ans[v]` = sum of distances from v to all other nodes.

**Pass 1 (post-order)**:
- `sz[leaf] = 1`, `ans[leaf] = 0`.
- For internal v: `sz[v] = 1 + Σ sz[c]` over children c. `ans[v] = Σ (ans[c] + sz[c])` — each node in c's subtree is one step farther from v than from c, so add sz[c] per child.

**Pass 2 (pre-order, rerooting from v to child u)**:
Moving the "root perspective" from v to u — all distances are recalculated from u's viewpoint. Nodes in u's subtree (`sz[u]` of them) are now 1 step *closer* (they used to be 1 step farther from v than from u). Nodes outside u's subtree (`n - sz[u]` of them) are now 1 step *farther* (they used to be 1 step closer to v than to u). Recurrence: `ans[u] = ans[v] - sz[u] + (n - sz[u])`.

```
Before rerooting (v is root):
  Distance from v to a node w in u's subtree = 1 + dist(u, w)
  Distance from v to a node w outside u's subtree = dist(v, w)

After rerooting (u is root):
  Distance from u to w in u's subtree = dist(u, w)      → DECREASES by 1: sz[u] nodes
  Distance from u to w outside u's subtree = 1 + dist(v, w)  → INCREASES by 1: n-sz[u] nodes

ans[u] = ans[v] - sz[u] + (n - sz[u])
       = ans[v] + n - 2·sz[u]
```

## Topic B: DP on DAGs and Graphs

### Section B1: DAG DP

**Q7. Why does a DAG naturally support DP, and what is the topological order DP transition template?**

A: A DAG (directed acyclic graph) has no cycles, so a topological ordering exists: a linear arrangement of vertices where every edge goes from earlier to later in the order. This provides an unambiguous "computation direction" — exactly what DP requires. The template: define `dp[v]` as the answer at vertex v; compute dp values in topological order; at each v, combine dp values of all predecessors (vertices with edges into v). Since predecessors appear earlier in topological order, their dp values are already computed when v is processed.

```
dp[v] = f(dp[u₁], dp[u₂], ..., dp[uₖ], edge_weights)
  where u₁, ..., uₖ are all vertices with edges into v

Common instantiations:
  Longest path ending at v:  dp[v] = max(dp[u] + 1) for all u→v
  Shortest path to v:        dp[v] = min(dp[u] + w(u,v)) for all u→v
  Number of paths to v:      dp[v] = Σ dp[u] for all u→v
  Any path exists to v:      dp[v] = OR(dp[u]) for all u→v
```

**Q8. What is "memoized DFS on an implicit DAG," and when does a problem have this structure?**

A: Some problems have an *implicit* DAG structure: the vertices are states (e.g., matrix cells), the edges are valid transitions (e.g., moving to an adjacent cell with a strictly larger value), and the DAG property holds because some invariant (strictly increasing values, strictly decreasing index) prevents cycles. Memoized DFS computes `dp[v]` on demand: when `dp[v]` is first requested, recursively compute it from successors; cache the result. The implicit DAG guarantees termination (no infinite recursion). This avoids explicitly building the graph and explicitly sorting topologically — the recursion handles both.

```
Longest Increasing Path in a Matrix:
  State: (row, col) — each cell is a vertex.
  Edge: (r,c) → (r',c') if adjacent AND matrix[r'][c'] > matrix[r][c].
  DAG: strictly increasing values prevent cycles.

  dp[r][c] = 1 + max(dp[r'][c']) for all valid neighbors (r',c')
  Memoize: if dp[r][c] already computed, return it directly.

No explicit topological sort needed — DFS processes a cell's successors first,
ensuring all dependencies are resolved before the cell's own dp is recorded.
```

**Q9. How is Bellman-Ford a DP algorithm, and what does its two-dimensional state represent?**

A: Bellman-Ford computes shortest paths from a source in a graph with possibly negative edge weights. Its DP formulation: `dp[k][v]` = minimum cost to reach v from the source using **at most k edges**. Transition: `dp[k][v] = min(dp[k-1][v], min(dp[k-1][u] + w(u,v)) for all u with edge u→v)`. The first term handles "don't use the kth edge"; the second term relaxes across edges. Iterate k from 1 to V-1 (or k+1 for "at most k stops" variants). The two dimensions — edge count k and destination v — define a 2D DP table. In practice, only two layers (current and previous) are needed due to the layer-by-layer transition structure.

```
Standard Bellman-Ford DP:
  dp[0][src] = 0, dp[0][v] = ∞ for v ≠ src.
  dp[k][v] = min(dp[k-1][v], min(dp[k-1][u] + w(u,v)) for all edges (u,v))

Cheapest Flights with at most K stops:
  K stops = at most K+1 edges.
  Run K+1 relaxation rounds.
  CRITICAL: use a snapshot of the previous round (dp[k-1]) when computing dp[k].
  Using the current round's partial updates would allow paths longer than K+1 edges.
```

**Q10. How is Floyd-Warshall a DP algorithm, and what does "using vertices 0..k as intermediates" mean?**

A: Floyd-Warshall computes all-pairs shortest paths. DP state: `dp[k][i][j]` = shortest path from i to j using **only vertices {0, 1, ..., k}** as intermediate nodes (i and j themselves can always be endpoints). Transition: either the shortest path from i to j doesn't use vertex k as intermediate (`dp[k-1][i][j]`), or it does (`dp[k-1][i][k] + dp[k-1][k][j]`). Starting with `dp[-1][i][j] = w(i,j)` if edge (i,j) exists else ∞ (direct edges only), iterate k from 0 to V-1, gradually allowing more vertices as intermediates. The space-optimized in-place form computes `dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])` for each k in the outer loop.

```
dp[k][i][j] = min(dp[k-1][i][j], dp[k-1][i][k] + dp[k-1][k][j])

"If vertex k can serve as a middleman between i and j, should we use it?"

k=0: shortest paths using only vertex 0 as intermediate.
k=1: shortest paths using vertices 0 and 1 as intermediates.
...
k=V-1: shortest paths using any vertex as intermediate = true shortest paths.

In-place (k outer, i and j inner) is correct because:
  dp[k][i][k] = dp[k-1][i][k]  (no self-improvement via k: k → k costs 0)
  dp[k][k][j] = dp[k-1][k][j]  (same)
  So reading dp[i][k] and dp[k][j] before updating dp[i][j] is safe.
```

### Section B2: Graph DP vs Tree DP

**Q11. What makes DP on general graphs fundamentally harder than DP on trees or DAGs?**

A: Trees and DAGs have **acyclic structure**, which provides a natural computation order (topological for DAGs, parent-before-children for trees). General directed graphs may have cycles, making it impossible to order states so that every state's dependencies are computed before it. Standard DP on a cyclic graph would loop infinitely. Solutions: (1) **restructure the state space** to eliminate cycles — add a dimension that strictly decreases (like edge count k in Bellman-Ford, or a bitmask of visited nodes in TSP); (2) **detect and collapse cycles** first — find SCCs, condense into a DAG, then run DAG DP on the condensation; (3) **use iterative convergence** (Bellman-Ford) instead of a clean computation order. In contrast, undirected graphs are never amenable to standard DP without additional constraints.

```
Cyclic graph:  A → B → C → A.  dp[A] depends on dp[C] which depends on dp[A]. ✗

Fix 1 (add dimension):    dp[k][A]: shortest to A using ≤ k edges.
  dp[k][A] depends on dp[k-1][*] — no cycle across k layers. ✓

Fix 2 (condense SCC):     {A,B,C} form one SCC → single super-node in condensation DAG.
  Run DP on condensation DAG (acyclic). ✓

Fix 3 (iterative relaxation): repeat until convergence. ✓ (Bellman-Ford)
```

**Q12. When does a graph DP problem reduce to tree DP, and what technique enables this?**

A: Three common reductions: (1) **Spanning tree**: if the optimal answer only uses a spanning tree's edges (e.g., minimum spanning tree problems), the problem reduces to tree DP on the spanning tree. (2) **Condensation + DAG DP**: find SCCs, condense to a DAG, then run DAG DP. The SCCs themselves may be solved with tree DP internally (if each SCC is itself a tree). (3) **Centroid decomposition**: for path queries across all pairs of nodes in a tree, decompose the tree into a hierarchy of centroids — each level of the hierarchy enables O(n log n) DP over all paths.

## Topic C: Advanced Tree DP Patterns

**Q13. What is tree knapsack DP, and why is its total complexity O(n²) not O(n · k²)?**

A: Tree knapsack: given a tree where each node has a weight, and a budget K, maximize the total value of selected nodes in a connected subtree. State: `dp[v][j]` = maximum value using exactly j units of budget in v's subtree. Merging two children c₁ and c₂ into v naively costs O(sz[c₁] × sz[c₂]) — combining every budget allocation in c₁ with every in c₂. Summed over all merge operations in the tree, this is O(n²) by the "each pair of nodes in different subtrees is counted once" argument: any two nodes u (in some subtree) and v (in another subtree) contribute to exactly one merge operation — the LCA of u and v. Since there are O(n²) distinct pairs, total work is O(n²) regardless of K.

```
Tree knapsack transition at v, merging child c into v's existing dp:
  for j from current_budget down to 0:
    for j' from 0 to min(sz[c], K-j):
      dp[v][j+j'] = max(dp[v][j+j'], dp[v][j] + dp[c][j'])

Cost per merge: O(sz[v_so_far] × sz[c])
Total cost = Σ over all merges of (size of left subtree × size of right subtree)
           = O(n²)   ← by the distinct-pair argument
```

**Q14. What is the "virtual root" technique for handling edge-weighted tree DP?**

A: When edges carry weights (not vertices), the DP must account for the cost of traversing each edge. Instead of storing the edge weight separately, some implementations create a virtual intermediate node for each edge, turning the edge weight into a node weight. More commonly: pass the edge weight as a parameter into the recursive call for the child and incorporate it into the child's dp computation. The virtual root technique also helps when the tree must be "unrooted" — adding a virtual root connected to all nodes with zero-weight edges creates a rooted tree where the answer at the virtual root equals the answer for the unrooted problem.

## Topic D: Cross-Topic & Interview-Style Questions

**Q15. "Walk me through your thought process when you encounter a tree DP problem."**

A: Five questions in order:

1. **What is the subproblem?** — "What property of the subtree rooted at v do I need to compute?" Define `dp[v]` explicitly before writing any code.

2. **What does the recursive function *return*, and is it different from the global answer?** — If the optimal answer involves both children simultaneously (path crossing through a node), the return value and the global update are different: return one arm, update with both arms.

3. **How many states per node?** — One state: straightforward aggregate (height, sum, max depth). Two states: binary choice (rob/don't rob, select/don't select). More states: knapsack variants with a capacity dimension.

4. **What are the base cases?** — Null nodes (return 0 or appropriate sentinel), leaf nodes (return their own value with no child contributions).

5. **Do I need rerooting?** — If the problem asks for "the answer from every node as root" or "sum of distances to all nodes," a single pass gives only the fixed root's answer. Two passes (rerooting) are required.

**Q16. "What is the key structural difference between tree DP and grid DP?"**

A: Grid DP (2D array) processes cells in a fixed order (row by row, top-left to bottom-right) because transitions only go in one or two directions (right, down). It's a special case of DAG DP where the DAG is the grid with directed edges going right and down. Tree DP processes nodes in post-order (leaves first) because transitions go from children to parents. The key difference: in grid DP, the "parent" of each cell is fixed by direction; in tree DP, the parent is determined by the tree structure, and the number of children per node varies. Grid DP is always O(rows × cols); tree DP can have non-uniform branching factors, requiring care about how child results are combined.

**Q17. "How do you decide whether a path problem on a tree requires rerooting?"**

A: Ask: "does the optimal answer depend on the entire tree, not just a subtree?" A single-pass tree DP computes each node's answer *restricted to its subtree*. If the problem asks: "for each node v, what is the sum of distances from v to ALL other nodes?" — this requires the contribution of nodes outside v's subtree, which a single pass rooted at 0 only gives for v=0. If the problem asks "what is the maximum depth below any node?" — a single pass suffices (depth below v is a subtree property). Signal for rerooting: if the answer at v includes nodes not in v's subtree (when the tree is rooted at 0), rerooting is needed.

**Q18. In one sentence each, state the DP state and transition for each problem in this document.**

A:
- **Binary Tree Maximum Path Sum**: `arm[v]` = max single-arm path value going down from v — `arm[v] = v.val + max(0, arm[left], arm[right])`; global max updated at each v as `v.val + max(0,arm[left]) + max(0,arm[right])`.
- **House Robber III**: `dp[v] = (notRob, rob)` — `rob = v.val + notRob[left] + notRob[right]`; `notRob = max(notRob[left],rob[left]) + max(notRob[right],rob[right])`.
- **Sum of Distances in Tree**: Pass 1: `ans[v] = Σ(ans[c] + sz[c])`, `sz[v] = 1 + Σ sz[c]`; Pass 2 rerooting: `ans[u] = ans[v] - sz[u] + (n - sz[u])` when rerooting from parent v to child u.
- **Longest Increasing Path in a Matrix**: `dp[r][c]` = longest increasing path starting at (r,c) — `dp[r][c] = 1 + max(dp[neighbor])` for neighbors with strictly larger value; memoized DFS on the implicit DAG.
- **All Paths from Source to Target**: `paths[v]` = list of all paths from v to the target — `paths[v] = {[v] + path : for each neighbor u, for each path in paths[u]}`; base case `paths[target] = {[target]}`.
- **Cheapest Flights Within K Stops**: `dp[v]` after round i = min cost to reach v using at most i+1 edges — `dp[v] = min(prev[u] + w(u,v))` for all incoming edges; run k+1 rounds using a frozen snapshot of the previous round.

## Problem 1 — Binary Tree Maximum Path Sum

### Problem
Given the root of a binary tree where node values can be negative, return the maximum path sum of any non-empty path. A path is a sequence of nodes where each pair of adjacent nodes has an edge connecting them; a node can appear at most once.

```
Input:
    1
   / \
  2   3
Output: 6    // path: 2 → 1 → 3

Input:
   -10
   /  \
  9   20
      / \
    15    7
Output: 42   // path: 15 → 20 → 7
```

### Pattern Recognition
Post-order tree DP with a global maximum — at each node v, the best path *crossing through* v combines both arms; but what is *returned upward* to v's parent is only the best single arm. The return value and the global answer update are different quantities.

### Key Insight
Two quantities at each node serve different purposes: the "crossing value" (both arms + node value) updates the global maximum; the "arm value" (best single arm + node value) is returned to the parent so it can extend the path further upward. Negative arms should be clamped to 0 — extending a path through a negative-sum subtree makes it worse.

### Approach
Post-order DFS. At each node: compute `leftArm = max(0, dp(left))` and `rightArm = max(0, dp(right))`. Update `globalMax = max(globalMax, node.val + leftArm + rightArm)`. Return `node.val + max(leftArm, rightArm)` to the parent.

### Solution

```js
function maxPathSum(root) {
  let globalMax = -Infinity; // handles all-negative trees

  function dp(node) {
    if (!node) return 0; // null contributes 0 to any arm

    // Post-order: compute children first
    const leftArm  = Math.max(0, dp(node.left));  // clamp negative arms to 0
    const rightArm = Math.max(0, dp(node.right));

    // Global update: best path CROSSING through this node (uses both arms)
    globalMax = Math.max(globalMax, node.val + leftArm + rightArm);

    // Return to parent: best single-arm path going DOWN through this node
    // Parent can only extend in one direction — must choose the better arm
    return node.val + Math.max(leftArm, rightArm);
  }

  dp(root);
  return globalMax;
}
```

### Dry Run

```
Tree:    -10
         /  \
        9   20
            / \
           15   7

dp(9):   left=0 (null), right=0 (null).
  globalMax = max(-∞, 9+0+0) = 9.
  return 9.

dp(15):  left=0, right=0.
  globalMax = max(9, 15+0+0) = 15.
  return 15.

dp(7):   left=0, right=0.
  globalMax = max(15, 7+0+0) = 15.
  return 7.

dp(20):  leftArm=max(0, dp(15))=15. rightArm=max(0, dp(7))=7.
  globalMax = max(15, 20+15+7) = max(15, 42) = 42.
  return 20 + max(15, 7) = 20 + 15 = 35.

dp(-10): leftArm=max(0, dp(9))=9. rightArm=max(0, dp(20))=35.
  globalMax = max(42, -10+9+35) = max(42, 34) = 42.  ← 42 already better
  return -10 + max(9, 35) = -10 + 35 = 25.  ← returned but not needed (root)

Answer: 42. ✓  Path: 15 → 20 → 7.
```

### Complexity
- Time: O(n) — each node visited once in post-order.
- Space: O(h) — call stack depth = tree height. O(log n) balanced, O(n) skewed.

### Edge Cases
- **All negative values**: `max(0, dp(child))` clamps arms to 0, so the best path is the single maximum-value node. `globalMax` is initialized to `-Infinity` to handle this correctly — never `0`.
- **Single node**: left and right arms are both 0. `globalMax = node.val`. Correct.
- **Path doesn't go through root**: the global max is updated at every node — whichever node produces the maximum crossing path wins, regardless of its position.

### Follow-up Questions
- "What if the path must include the root?" — Remove the global variable; the answer is `dp(root)` itself (the best single arm from the root, which is the best root-inclusive path).
- "What if the path must be a root-to-leaf path?" — Change the base case: `if leaf: return node.val`. Never clamp to 0 (path must reach a leaf). Remove the crossing-path update.

## Problem 2 — House Robber III

### Problem
Robbers can rob houses arranged in a binary tree. Adjacent nodes (parent-child) cannot both be robbed. Find the maximum money that can be robbed without alerting police.

```
Input:
     3
    / \
   2   3
    \    \
     3    1
Output: 7    // rob nodes 3 (root's left), 3 (right of 2), 3 (root), 1 → actually rob 3,3,1=7? 
             // Optimal: rob root's left(2) children: 3+3 + root's right(3) child: 1 = 7? 
             // Actually: rob 3(left child of root), 3(right child of 3), 1 = no they're adjacent.
             // Rob root(3) + 3(grandchild left) + 1(grandchild right) = 3+3+1=7. ✓

Input:
         3
        / \
       4   5
      / \   \
     1   3    1
Output: 9    // rob 4's children (1+3) + 5 = 9? rob 4+5+1=10? 
             // rob 4(not root) + 5(not root) = 4+5=9 (root 3 not robbed). 
             // Or rob 1+3+5+1=10 but 5 and 1 are adjacent... 
             // Optimal: rob 4 and 5 (children of root 3): 4+5=9. ✓ (root 3 not robbed since 4 and 5 are adjacent to 3... wait 3 is parent of 4 and 5, so can't rob 3 if robbing 4 or 5)
             // Rob 4 + 5 = 9. Not robbing root(3). Grandchildren: 1+3=4 (rob 1 and 3, skip 4, skip 5, but then rob root: 3+1+3+1=8). So 9 is better. ✓
```

### Pattern Recognition
Two-state tree DP — each node has two states: robbed or not-robbed. The state determines which descendants can be robbed. Return a pair `[notRobbed, robbed]` at each node; parent combines them using the independent-set transition.

### Key Insight
The constraint "parent and child cannot both be robbed" is exactly the maximum independent set constraint on a tree. Two states per node capture it cleanly: the "robbed" state forces all children into the "not robbed" state; the "not robbed" state lets each child be either. Returning both states as a pair gives the parent full information to make the optimal choice independently per child.

### Approach
Post-order DFS. At each node, return `[notRob, rob]`. Combine: `rob = node.val + leftPair[0] + rightPair[0]`; `notRob = max(leftPair[0], leftPair[1]) + max(rightPair[0], rightPair[1])`. Answer: `max(dp(root)[0], dp(root)[1])`.

### Solution

```js
function rob(root) {
  function dp(node) {
    if (!node) return [0, 0]; // [notRobbed, robbed] — null contributes nothing

    const [leftNot,  leftRob]  = dp(node.left);
    const [rightNot, rightRob] = dp(node.right);

    // If this node IS robbed: neither child can be robbed
    const robbed = node.val + leftNot + rightNot;

    // If this node is NOT robbed: each child independently chooses its best state
    const notRobbed = Math.max(leftNot, leftRob) + Math.max(rightNot, rightRob);

    return [notRobbed, robbed];
  }

  const [notRob, rob] = dp(root);
  return Math.max(notRob, rob);
}
```

- **Linear chain (only left children)**: the two-state DP correctly handles linear chains — same as the array House Robber problem.

- "How does this relate to the linear array House Robber?" — Identical algorithm on a path graph (each node has at most one child). Tree version is a generalization.

## Problem 3 — Sum of Distances in Tree

### Problem
Given an undirected tree with `n` nodes, return an array `answer` where `answer[i]` is the sum of distances between node i and all other nodes.

```
Input:  n=6, edges=[[0,1],[0,2],[2,3],[2,4],[2,5]]
Output: [8,12,6,10,10,10]

Input:  n=1, edges=[]
Output: [0]
```

### Pattern Recognition
Two-pass rerooting — Pass 1 (post-order) computes subtree sizes and the answer for root 0. Pass 2 (pre-order) propagates the answer downward to each child using the rerooting recurrence `ans[u] = ans[v] - sz[u] + (n - sz[u])`.

### Key Insight
Moving the "root perspective" from parent v to child u changes every distance by exactly ±1: the `sz[u]` nodes in u's subtree are now 1 closer (they used to need an extra edge to reach v first); the `n - sz[u]` nodes outside u's subtree are now 1 farther. This additive update avoids recomputing all distances from scratch for each node.

### Approach
Build adjacency list. Pass 1: post-order DFS from node 0 — compute `sz[v]` (subtree size) and `ans[v]` (sum of distances in subtree). Pass 2: pre-order DFS from node 0 — for each child u, compute `ans[u] = ans[v] - sz[u] + (n - sz[u])`.

### Solution

```js
function sumOfDistancesInTree(n, edges) {
  const adj = Array.from({ length: n }, () => []);
  for (const [u, v] of edges) {
    adj[u].push(v);
    adj[v].push(u); // undirected tree
  }

  const sz  = new Array(n).fill(1); // sz[v] = subtree size rooted at v (pass 1)
  const ans = new Array(n).fill(0); // ans[v] = sum of distances from v to all nodes

  // Pass 1: post-order from root 0
  // Compute sz[v] and ans[0] (the correct answer for root 0)
  function dfs1(v, parent) {
    for (const u of adj[v]) {
      if (u === parent) continue;
      dfs1(u, v);
      sz[v]  += sz[u];            // accumulate subtree sizes
      ans[v] += ans[u] + sz[u];   // each node in u's subtree is 1 step farther from v
    }
  }

  // Pass 2: pre-order — propagate ans[v] to each child u via rerooting recurrence
  function dfs2(v, parent) {
    for (const u of adj[v]) {
      if (u === parent) continue;
      // Rerooting from v to u:
      //   sz[u] nodes in u's subtree: each 1 step closer to new root u
      //   n - sz[u] nodes outside: each 1 step farther from new root u
      ans[u] = ans[v] - sz[u] + (n - sz[u]);
      dfs2(u, v);
    }
  }

  dfs1(0, -1);
  dfs2(0, -1);

  return ans;
}
```

### Complexity
- Time: O(n) — two DFS passes, each O(n).
- Space: O(n) — sz, ans arrays; O(n) call stack for a path graph.

- **Path graph**: the formula generalizes correctly; pass 2 propagates the accumulating distance sums along the path.

- "What if we want the minimum instead of the sum?" — The rerooting recurrence no longer holds (min doesn't distribute over subtree splits the way sum does). Use O(n²) naive or a centroid-decomposition approach.

## Problem 4 — Longest Increasing Path in a Matrix

### Problem
Given an `m × n` integer matrix, return the length of the longest increasing path. From each cell, you can move in four directions (up, down, left, right). You may not move diagonally or outside the boundary.

```
Input:
  matrix = [[9,9,4],
            [6,6,8],
            [2,1,1]]
Output: 4   // path: 1 → 2 → 6 → 9

Input:
  matrix = [[3,4,5],
            [3,2,6],
            [2,2,1]]
Output: 4   // path: 3 → 4 → 5 → 6
```

### Pattern Recognition
Implicit DAG DP with memoized DFS — the matrix cells form a DAG where edges go from cell (r,c) to adjacent cells (r',c') with strictly larger values (strictly increasing prevents cycles). Longest path in this implicit DAG is computed via memoized DFS.

### Key Insight
The "strictly increasing" constraint creates a DAG: there is no way to return to a previously visited cell (its value was strictly smaller, and we can only move to strictly larger values). This guarantees the DFS terminates and memoization is valid — `dp[r][c]` is the same regardless of how we arrive at (r,c).

### Approach
Define `dp[r][c]` = longest increasing path starting at cell (r,c). Memoized DFS: if already computed, return cached value. Otherwise: `dp[r][c] = 1 + max(dp[r'][c'])` for all adjacent cells (r',c') with `matrix[r'][c'] > matrix[r][c]`. If no valid neighbor: `dp[r][c] = 1` (only this cell). Return the maximum dp value across all cells.

### Solution

```js
function longestIncreasingPath(matrix) {
  const m = matrix.length, n = matrix[0].length;
  const dp   = Array.from({ length: m }, () => new Array(n).fill(0)); // 0 = not computed
  const dirs = [[0,1],[0,-1],[1,0],[-1,0]];

  function dfs(r, c) {
    if (dp[r][c]) return dp[r][c]; // already computed — return memoized result

    dp[r][c] = 1; // minimum: just this cell
    for (const [dr, dc] of dirs) {
      const nr = r + dr, nc = c + dc;
      if (nr >= 0 && nr < m && nc >= 0 && nc < n && matrix[nr][nc] > matrix[r][c]) {
        // Edge to (nr,nc) exists in the implicit DAG (strictly larger value)
        dp[r][c] = Math.max(dp[r][c], 1 + dfs(nr, nc));
      }
    }
    return dp[r][c];
  }

  let result = 0;
  for (let r = 0; r < m; r++) {
    for (let c = 0; c < n; c++) {
      result = Math.max(result, dfs(r, c));
    }
  }
  return result;
}
```

## Problem 5 — All Paths from Source to Target

### Problem
Given a directed acyclic graph (DAG) with `n` nodes (0 to n-1), where `graph[i]` is a list of all nodes reachable from node i via a direct edge, find all possible paths from node 0 (source) to node n-1 (target). Return paths in any order.

```
Input:  graph = [[1,2],[3],[3],[]]
Output: [[0,1,3],[0,2,3]]

Input:  graph = [[4,3,1],[3,2,4],[3],[4],[]]
Output: [[0,4],[0,3,4],[0,1,3,4],[0,1,2,3,4],[0,1,4]]
```

### Pattern Recognition
DAG DP with memoized DFS — define `paths[v]` as all paths from v to the target (n-1). The DAG structure (no cycles, guaranteed by problem) ensures memoization is valid and DFS terminates. Build paths recursively from the target backward.

### Key Insight
`paths[v]` depends only on v's successors — not on how we reached v. Since the graph is a DAG (explicitly guaranteed), there are no cycles, and `paths[v]` is well-defined. Memoization stores `paths[v]` after first computation, avoiding re-traversal of the same subgraph for multiple paths passing through v.

### Approach
Memoized DFS from node 0. `dp(v)`: if `v == n-1`, return `[[n-1]]`. Otherwise: for each neighbor u of v, prepend v to each path in `dp(u)`. Cache and return. The DAG structure guarantees this terminates.

### Solution

```js
function allPathsSourceTarget(graph) {
  const n = graph.length;
  const memo = new Array(n).fill(null); // null = not yet computed

  // dp(v) = all complete paths from v to target (n-1), each starting with v
  function dp(v) {
    if (v === n - 1) return [[n - 1]]; // base: reached target — one trivial path
    if (memo[v] !== null) return memo[v]; // already computed — return cache

    memo[v] = [];
    for (const u of graph[v]) {
      // For each path from u to target, prepend v to get a path from v to target
      for (const path of dp(u)) {
        memo[v].push([v, ...path]);
      }
    }
    return memo[v];
  }

  return dp(0);
}
```

### Complexity
- Time: O(2^n × n) worst case — exponentially many paths in the worst case (a DAG can have 2^n distinct paths). Memoization saves re-exploring shared suffixes but cannot reduce the total output size.
- Space: O(2^n × n) for all paths stored in memo. O(n) call stack depth.

### Edge Cases
- **Source == target** (n=1): `dp(0)` returns `[[0]]`. A trivial single-node path.
- **No path exists** (disconnected or dead-end before target): if `graph[v]` is empty and `v != n-1`, `dp(v) = []` (no paths). Paths through v simply contribute nothing to ancestor nodes' path lists.
- **Long path with shared suffix**: e.g., many nodes all pointing to n-2 which points to n-1. dp(n-2) computed once, all its callers reuse the cached result. Memoization provides a large speedup here.
- **Single path**: if there's exactly one path from 0 to n-1, the function returns `[[0, ..., n-1]]`.

### Follow-up Questions
- "Count paths instead of listing them?" — Change `paths[v]` to an integer (count). `dp(v) = Σ dp(u)` for all neighbors u. Base case: `dp(n-1) = 1`. O(V+E) time.
- "Shortest path in terms of edge count?" — Standard BFS from 0. All paths variant doesn't directly help here.
- "What if the graph has cycles (general directed graph)?" — The memoization becomes invalid (infinite recursion). Must detect cycles (use DFS with "in-progress" state tracking) before applying the DP pattern.

## Problem 6 — Cheapest Flights Within K Stops

### Problem
Given `n` cities, an array of `flights` where `flights[i] = [from, to, price]`, a source `src`, destination `dst`, and integer `k`, find the cheapest price from src to dst with at most k stops. If no route exists, return -1.

```
Input:  n=4, flights=[[0,1,100],[1,2,100],[2,0,100],[1,3,600],[2,3,200]],
        src=0, dst=3, k=1
Output: 700   // 0→1→3, cost=100+600=700 (1 stop, k=1 ✓)
              // 0→1→2→3 costs 400 but needs 2 stops (k=1 ✗)

Input:  n=3, flights=[[0,1,100],[1,2,100],[0,2,500]], src=0, dst=2, k=1
Output: 200   // 0→1→2, 1 stop, cost=200
```

### Pattern Recognition
Bellman-Ford DP — `dp[v]` = minimum cost to reach v using at most k+1 edges (k intermediate stops). Run exactly k+1 relaxation rounds. Critical: use a snapshot of the previous round when computing the current round — otherwise a single chain of edges in one round could "piggyback" to create a path with more than k+1 edges.

### Key Insight
At most k stops = at most k+1 edges. Bellman-Ford's layer-by-layer DP naturally enforces this: round i computes the cheapest path using *exactly* i edges. The "frozen snapshot" (copying `dp` before each round) ensures each round only uses paths from the *previous* round — no path can use more than i edges after i rounds.

### Approach
Initialize `prices[src] = 0`, all others `Infinity`. Repeat k+1 times: take a snapshot `tmp = [...prices]`; for each flight `[u, v, w]`: if `prices[u] != Infinity`, set `tmp[v] = min(tmp[v], prices[u] + w)`. After the round, set `prices = tmp`. Return `prices[dst]` or -1 if still Infinity.

### Solution

```js
function findCheapestPrice(n, flights, src, dst, k) {
  let prices = new Array(n).fill(Infinity);
  prices[src] = 0; // cost to reach source = 0 with 0 edges

  // k stops = k+1 edges = k+1 relaxation rounds
  for (let round = 0; round <= k; round++) {
    // CRITICAL: snapshot prevents using this round's updates in the same round
    // Without snapshot: a chain A→B→C in one round could appear as a 2-edge path
    const tmp = [...prices];

    for (const [from, to, price] of flights) {
      if (prices[from] !== Infinity) {
        tmp[to] = Math.min(tmp[to], prices[from] + price);
      }
    }

    prices = tmp;
  }

  return prices[dst] === Infinity ? -1 : prices[dst];
}
```

### Complexity
- Time: O(k × E) — k+1 rounds, each scanning all E edges.
- Space: O(V) — two price arrays (current and snapshot).

### Edge Cases
- **k = 0 (no stops)**: only one round. Only direct flights from src can be used. If no direct flight to dst, return -1.
- **src == dst**: `prices[dst] = prices[src] = 0` initially. Return 0 without any rounds.
- **No path**: if dst is unreachable within k+1 edges, `prices[dst]` remains Infinity after all rounds. Return -1.
- **Negative weights**: Bellman-Ford handles negative weights correctly (unlike Dijkstra). The k-round constraint prevents negative-cycle exploitation — you can't accumulate negative cycles since you're limited to k+1 edges.
- **Multiple paths, some longer but cheaper**: the DP correctly finds the cheapest among all valid (≤ k stop) paths because it considers ALL edges in each round.

### Follow-up Questions
- "Dijkstra with a modified state for stop count?" — State `(city, stops_used)`. Priority queue ordered by cost. O(E × k × log(V×k)) — more complex but potentially faster for sparse graphs with large k.
- "What if k is very large (find the cheapest path regardless of stops)?" — Standard Bellman-Ford with V-1 rounds (without the snapshot). Or Dijkstra for non-negative weights.
- "Reconstruct the cheapest path?" — Store, at each `(city, round)`, which predecessor was chosen for the minimum. After finishing, trace back from `(dst, k+1)`.

## Quick Reference — Tree DP & Graph DP Pattern Decision Tree

```
What is the DP domain?
│
├── TREE DP (n nodes, n-1 edges, no cycles)?
│   │
│   ├── SINGLE STATE per node (max/min path, height, diameter)?
│   │   └── Post-order DFS. Return value = what parent needs (one arm).
│   │       Global max = updated at each node using BOTH arms.
│   │       Negative arms → clamp to 0 (max(0, dp(child))).
│   │
│   ├── TWO STATES per node (independent set, rob/not-rob)?
│   │   └── Return [state0, state1] from each node.
│   │       Transitions: state1 forces children into state0;
│   │                    state0 lets children choose freely.
│   │       Answer: max(dp(root)[0], dp(root)[1]).
│   │
│   ├── ANSWER FROM EVERY NODE AS ROOT (sum of distances)?
│   │   └── Two passes:
│   │       Pass 1 (post-order): compute sz[v] and ans[root].
│   │       Pass 2 (pre-order): ans[child] = ans[parent] - sz[child] + (n - sz[child]).
│   │
│   └── RESOURCE DISTRIBUTION OVER SUBTREES (tree knapsack)?
│       dp[v][j] = max value using j resources in v's subtree.
│       Merge children one by one: O(sz[c₁] × sz[c₂]) per merge = O(n²) total.
│
├── IMPLICIT DAG DP (matrix, strictly increasing conditions)?
│   └── Memoized DFS. Define dp[state] = answer from this state.
│       DAG property prevents cycles → memoization is valid.
│       DFS computes dependencies before the current state.
│
├── EXPLICIT DAG DP (topological structure given)?
│   ├── Longest/shortest path: dp[v] = max/min(dp[u] + w) for all u→v.
│   ├── Count paths:           dp[v] = Σ dp[u] for all u→v.
│   └── Collect paths:         dp[v] = {prepend v to each path in dp[u]}.
│       Process in topological order (or use memoized DFS).
│
├── GRAPH DP WITH EDGE COUNT CONSTRAINT (Bellman-Ford family)?
│   └── dp[k][v] = min cost to reach v using at most k edges.
│       Run k+1 rounds. SNAPSHOT before each round — mandatory.
│       At most k stops = at most k+1 edges.
│
└── ALL-PAIRS SHORTEST PATHS (Floyd-Warshall)?
    dp[k][i][j] = min dist i→j using only nodes {0..k} as intermediates.
    Transition: min(dp[k-1][i][j], dp[k-1][i][k] + dp[k-1][k][j]).
    In-place safe: k outer loop, i and j inner loops.
```

## Common Bugs Checklist

Before submitting any tree DP or graph DP solution, verify:

1. **Tree DP return value vs global answer: are they different quantities?** — If the optimal path crosses through a node using both subtrees, the return value (one arm + node value) and the global update (both arms + node value) are different. Returning the crossing value to the parent is wrong: the parent would double-count the second arm.

2. **Negative arm clamping: `max(0, dp(child))` not `dp(child)`?** — If a child's best path has negative sum, including it worsens the path. Clamp to 0. Missing this causes the algorithm to incorrectly penalize paths through sparse negative-value subtrees.

3. **Two-state tree DP: `rob = node.val + Σ children[i][0]` not `+ Σ max(children[i][0], children[i][1])`?** — When a node IS robbed, none of its children can be (fixed: child uses state 0). When NOT robbed, children choose freely (use max of their two states). Confusing these gives wrong answers for the "not robbed" case.

4. **Rerooting pass 2 uses `sz[u]` from pass 1 (original subtree size), not the "current" subtree size?** — After rerooting at u, u's subtree becomes the entire tree. But the formula `ans[u] = ans[v] - sz[u] + (n - sz[u])` uses the pass-1 value of `sz[u]` (the original subtree rooted at u). Do not update `sz[u]` during pass 2.

5. **DAG DP processes nodes in topological order, not arbitrary order?** — If a node is processed before all its predecessors are computed, `dp[v]` uses uninitialized values. Either sort topologically first or use memoized DFS (which naturally processes successors before the current node via recursion).

6. **Memoized DFS initializes the cache with a sentinel, not 0?** — In "longest increasing path," `dp[r][c] = 0` means "not yet computed." If 0 were a valid answer (though not here), a separate `visited` array would be needed. Always choose a sentinel that cannot be a valid dp value (0 works here since all paths have length ≥ 1).

7. **Bellman-Ford snapshot: copy `prices` before each round, not after?** — The snapshot must freeze the previous round's values. Reading from `prices` (frozen) and writing to `tmp` (current round) ensures no single round processes a chain longer than 1 edge. Writing directly to `prices` without a snapshot allows multi-hop paths within a single round.

8. **Bellman-Ford runs exactly k+1 rounds (not k) for k stops?** — At most k stops = at most k+1 edges. A loop running k times allows at most k edges = k-1 stops. Always run k+1 rounds (or loop from 0 to k inclusive).

9. **Floyd-Warshall in-place update order: k in outermost loop?** — The order must be: for k (intermediate node), for i, for j: `dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])`. If i or j is outermost, `dist[i][k]` or `dist[k][j]` may be incorrectly updated before being used, leading to paths that "use vertex k multiple times" in one iteration.

10. **Path-through-node global max: initialized to `-Infinity` not `0`?** — If all node values are negative (e.g., `[-3, -2, -5]`), a single-node path has negative sum. Initializing `globalMax = 0` would incorrectly return 0 (no path) instead of -2 (the best single-node path). Always initialize to `-Infinity` or the first node's value.

11. **All Paths DAG DP: memoization returns shared list objects?** — `memo[v]` stores a list of paths. If callers modify these lists (e.g., push additional elements), the cached result is corrupted. Always use `[v, ...path]` to create new arrays, not in-place mutation of cached path arrays.

12. **Tree traversal skips null nodes without returning the correct base-case value?** — Every tree DP recursive function must handle the null node case: `if (!node) return BASE_VALUE`. The base value depends on the operation: 0 for sums/max with clamping, `[0, 0]` for two-state DP, `[1, 0]` for height/size. Returning undefined or not returning from the null case corrupts all parent computations.

---

**Final Tip:** At the 5 YOE level, the decisive signal for tree DP problems is distinguishing three roles before writing any code: (1) **the return value contract** — "my function returns X to its caller, which is Y (not the final answer)"; (2) **the global answer update** — "the final answer is updated at each node using Z, which combines information from both subtrees simultaneously"; (3) **the state definition** — "dp[v] represents W for the subtree rooted at v." For the path-through-node pattern: *"I return the best single-arm value (node + one child) to the parent; I update the global max with both arms + node simultaneously; these are different because the parent can only extend in one direction while the crossing path uses both."* For rerooting: *"Pass 1 gives me sz[v] and the answer at root 0; pass 2 derives every other node's answer in O(1) from its parent's answer using the formula ans[u] = ans[v] - sz[u] + (n - sz[u]) — moving the root from v to u makes sz[u] nodes 1 closer and n-sz[u] nodes 1 farther."* Stating these three things before writing a single line is the mark of a senior who has internalized the pattern rather than the code.
