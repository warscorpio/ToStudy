## Part 1 — Theory & Interview Q&A

### Section 1: Fundamentals

**Q1. What is the matrix chain multiplication problem?**
A: Given a sequence of matrices `A₁, A₂, ..., Aₙ`, find the most efficient order to multiply them together. Matrix multiplication is associative — `(A×B)×C = A×(B×C)` — so the result is the same regardless of parenthesization, but the number of scalar multiplications required varies dramatically with the order. The goal is to find the parenthesization that minimizes the total number of scalar multiplications.

The input is a dimensions array `dims` of length `n+1` where matrix `Aᵢ` has dimensions `dims[i-1] × dims[i]`. The cost of multiplying an `a×b` matrix by a `b×c` matrix is `a × b × c` scalar multiplications.

```
Example: dims = [10, 30, 5, 60]
Matrices: A₁(10×30), A₂(30×5), A₃(5×60)

Option 1: (A₁×A₂)×A₃
  A₁×A₂: 10×30×5 = 1500 multiplications → result is 10×5
  (A₁×A₂)×A₃: 10×5×60 = 3000 multiplications
  Total: 4500 multiplications

Option 2: A₁×(A₂×A₃)
  A₂×A₃: 30×5×60 = 9000 multiplications → result is 30×60
  A₁×(A₂×A₃): 10×30×60 = 18000 multiplications
  Total: 27000 multiplications

Option 1 is 6× cheaper — parenthesization matters enormously.
```

**Q2. Why is brute force exponential, and what does that motivate?**
A: The number of ways to fully parenthesize a chain of n matrices is the (n-1)th Catalan number: `C(n-1) = (2(n-1) choose n-1) / n`. This grows exponentially — C(1)=1, C(2)=2, C(3)=5, C(4)=14, C(10)=4862, C(15)=742900. Trying all parenthesizations is infeasible for n ≥ 20.

The brute force exponential growth motivates DP: the problem has **optimal substructure** (the optimal split of the full chain uses optimal splits of sub-chains) and **overlapping subproblems** (the same sub-chain `[i, j]` is needed in many different parenthesizations of larger chains). This combination makes DP applicable and efficient.

**Q3. What is the subproblem structure — how is it defined?**
A: The subproblem is: "what is the minimum cost to multiply the sub-chain of matrices from index `i` to index `j`?" Define:

```
dp[i][j] = minimum number of scalar multiplications to compute Aᵢ × Aᵢ₊₁ × ... × Aⱼ
```

For a chain of n matrices (indices 1 to n), the answer is `dp[1][n]`.

**Q4. What is the recurrence relation?**
A: For every possible split point `k` (where `i ≤ k < j`), the chain `[i, j]` is split into `[i, k]` and `[k+1, j]`. The cost of this split is:

```
cost(i, j, k) = dp[i][k]                    ← cost of left sub-chain
              + dp[k+1][j]                  ← cost of right sub-chain
              + dims[i-1] × dims[k] × dims[j]  ← cost of combining the results
```

The `dims[i-1] × dims[k] × dims[j]` term is the cost of multiplying the left result (dimensions `dims[i-1] × dims[k]`) by the right result (dimensions `dims[k] × dims[j]`).

The recurrence:
```
dp[i][j] = min over all k from i to j-1 of:
             dp[i][k] + dp[k+1][j] + dims[i-1] × dims[k] × dims[j]

dp[i][i] = 0    (base case: a single matrix costs nothing to "multiply")
```

**Q5. Why is matrix chain multiplication classified as "interval DP"?**
A: Because the subproblem is defined by an **interval** `[i, j]` — a contiguous range of indices. The key characteristic of interval DP is that:
- Base cases are intervals of length 1: `dp[i][i] = 0`.
- Larger intervals depend on strictly smaller intervals (split into two non-overlapping sub-intervals).
- The fill order must process shorter intervals before longer ones — you cannot fill `dp[i][j]` until all `dp[i][k]` and `dp[k+1][j]` for `i ≤ k < j` are already computed.

Other interval DP problems include: burst balloons, palindrome partitioning, minimum cost to merge stones, and optimal binary search tree. They all share the "split the range at every possible point and combine sub-results" structure.

### Section 2: The Algorithm — Deep Dive

**Q6. What is the correct fill order for tabulation and why?**
A: Fill by increasing **chain length** (`len = j - i + 1`), starting from length 2 (the shortest non-trivial chain). For each length, iterate over all starting indices `i` and compute `j = i + len - 1`.

```
For len = 2: compute dp[1][2], dp[2][3], dp[3][4], ...
For len = 3: compute dp[1][3], dp[2][4], dp[3][5], ...
...
For len = n: compute dp[1][n]   ← final answer
```

Why this order works: when computing `dp[i][j]` for chain length `len`, every split produces sub-chains of length `< len` — which have already been computed in earlier iterations of the outer loop. This guarantees all dependencies are resolved.

**Q7. Walk through the complete tabulation algorithm with code.**
A:

```js
function matrixChainOrder(dims) {
  // dims[i-1] × dims[i] is the dimension of matrix Aᵢ (1-indexed)
  // dims has length n+1 for n matrices
  const n = dims.length - 1; // number of matrices

  // dp[i][j] = min multiplications for chain Aᵢ...Aⱼ (1-indexed)
  // Using 1-indexed for clarity; allocate (n+1) × (n+1)
  const dp = Array.from({length: n + 1}, () => new Array(n + 1).fill(0));
  // Base case: dp[i][i] = 0 (already 0 from fill)

  // Fill by chain length (len = 2 to n)
  for (let len = 2; len <= n; len++) {          // chain length
    for (let i = 1; i <= n - len + 1; i++) {   // starting index
      const j = i + len - 1;                   // ending index
      dp[i][j] = Infinity;                     // initialize to infinity

      // try every split point k
      for (let k = i; k < j; k++) {
        const cost = dp[i][k]
                   + dp[k + 1][j]
                   + dims[i - 1] * dims[k] * dims[j]; // combining cost

        if (cost < dp[i][j]) {
          dp[i][j] = cost;
        }
      }
    }
  }

  return dp[1][n]; // minimum cost for the full chain
}
```

**Q8. Walk through the memoization (top-down) version.**
A:

```js
function matrixChainMemo(dims) {
  const n = dims.length - 1;
  // memo[i][j] = -1 means not yet computed
  const memo = Array.from({length: n + 1}, () => new Array(n + 1).fill(-1));

  function dp(i, j) {
    if (i === j) return 0;          // base: single matrix
    if (memo[i][j] !== -1) return memo[i][j]; // cache hit

    let best = Infinity;

    for (let k = i; k < j; k++) {
      const cost = dp(i, k)
                 + dp(k + 1, j)
                 + dims[i - 1] * dims[k] * dims[j];
      best = Math.min(best, cost);
    }

    memo[i][j] = best;
    return best;
  }

  return dp(1, n);
}
```

**Q9. How do you also find the optimal parenthesization (not just the cost)?**
A: Maintain a `split[i][j]` table recording the optimal split point `k` for each interval `[i, j]`. After filling the DP table, recursively reconstruct the parenthesization from `split`:

```js
function matrixChainWithSplit(dims) {
  const n = dims.length - 1;
  const dp = Array.from({length: n + 1}, () => new Array(n + 1).fill(0));
  const split = Array.from({length: n + 1}, () => new Array(n + 1).fill(0));

  for (let len = 2; len <= n; len++) {
    for (let i = 1; i <= n - len + 1; i++) {
      const j = i + len - 1;
      dp[i][j] = Infinity;

      for (let k = i; k < j; k++) {
        const cost = dp[i][k] + dp[k + 1][j] + dims[i - 1] * dims[k] * dims[j];
        if (cost < dp[i][j]) {
          dp[i][j] = cost;
          split[i][j] = k; // record optimal split point
        }
      }
    }
  }

  // Reconstruct parenthesization
  function buildString(i, j) {
    if (i === j) return `A${i}`;
    const k = split[i][j];
    return `(${buildString(i, k)} × ${buildString(k + 1, j)})`;
  }

  return {
    minCost: dp[1][n],
    parenthesization: buildString(1, n)
  };
}
```

**Q10. What is the time and space complexity?**
A:
- **Time: O(n³)** — three nested loops: the outer two iterate over all O(n²) intervals, and the innermost loop tries O(n) split points per interval. Total: O(n²) intervals × O(n) splits = O(n³).
- **Space: O(n²)** — the DP table (and split table if tracking parenthesization) each have O(n²) entries.

This is asymptotically optimal for the general case with this approach. There exist O(n log n) algorithms (Hu-Shing algorithm) for the special case, but they are beyond interview scope and implementation complexity.

### Section 3: Interval DP Pattern

**Q11. What is the general interval DP template, and how does matrix chain fit into it?**
A: The interval DP template is:

```js
// General interval DP template
function intervalDP(input, n) {
  // dp[i][j] = answer for subproblem on interval [i, j]
  const dp = Array.from({length: n}, () => new Array(n).fill(BASE_VALUE));

  // Base cases: intervals of length 1
  for (let i = 0; i < n; i++) dp[i][i] = BASE_CASE_VALUE;

  // Fill by increasing length
  for (let len = 2; len <= n; len++) {
    for (let i = 0; i <= n - len; i++) {
      const j = i + len - 1;

      // Try every split point
      for (let k = i; k < j; k++) {
        const candidate = COMBINE(dp[i][k], dp[k+1][j], /* interval info */);
        dp[i][j] = OPTIMAL(dp[i][j], candidate);
      }
    }
  }

  return dp[0][n - 1]; // or dp[1][n] for 1-indexed
}
```

Matrix chain multiplication is the canonical example of this template. The differences between interval DP problems are:
- What `dp[i][j]` represents (min cost, max profit, count, etc.)
- What `COMBINE` computes (multiplication cost, burst profit, merge cost, etc.)
- What `OPTIMAL` chooses (min, max, sum, etc.)
- What the base case value is (0 for matrix chain, `nums[i]` for burst balloons, etc.)

**Q12. What other classic problems use the interval DP template?**
A: Four problems commonly paired with matrix chain in interviews:

- **Burst Balloons (LeetCode 312)**: `dp[i][j]` = max coins from bursting all balloons between `i` and `j`. Split point `k` = last balloon to burst in `[i, j]`. Combining cost = `nums[i-1] × nums[k] × nums[j+1]`.

- **Minimum Cost to Merge Stones (LeetCode 1000)**: merge k adjacent piles at each step; `dp[i][j]` = min cost to merge stones from `i` to `j` into one pile. Combining adds `sum(stones[i..j])` plus sub-costs.

- **Palindrome Partitioning II**: `dp[i][j]` = min cuts to partition `s[i..j]` into palindromes. Combining: `dp[i][k] + dp[k+1][j] + cut_cost`.

- **Optimal BST**: `dp[i][j]` = min expected search cost for keys `i` to `j`. Split point = root of optimal BST for that range.

**Q13. Why does interval DP require filling by length rather than by row or column?**
A: Because the dependency structure runs "inward" — a cell `dp[i][j]` depends on cells `dp[i][k]` and `dp[k+1][j]` for all `i ≤ k < j`. These sub-intervals are strictly contained within `[i, j]`, so they are all shorter. Filling by length guarantees shorter intervals are computed first. If you filled by row (i = 1, 2, ..., n) or by column (j = 1, 2, ..., n), you'd encounter cells `dp[k+1][j]` that span from `k+1` to `j` — which might be in the same or a later row but an earlier column — potentially uncomputed when needed. Length-order is the correct dependency-respecting fill order for all interval DP problems.

### Section 4: Variants & Extensions

**Q14. What is the "Burst Balloons" problem and how does its recurrence differ from matrix chain?**
A: Given an array of balloons `nums` where bursting balloon `i` yields `nums[i-1] × nums[i] × nums[i+1]` coins (with sentinels `nums[-1] = nums[n] = 1`), find the maximum coins obtainable by bursting all balloons.

The key insight — and the difference from matrix chain — is to think of `k` as the **last** balloon to burst in `[i, j]` (not the first). This avoids the dependency on already-burst balloons because the last balloon's neighbors are the boundary values `i-1` and `j+1` (outside the range), which are fixed (not burst within this interval).

```
dp[i][j] = max coins from bursting all balloons strictly between indices i and j
           (i and j are boundaries, not burst in this subproblem)

dp[i][j] = max over k from i+1 to j-1 of:
             dp[i][k] + dp[k][j] + nums[i] × nums[k] × nums[j]
```

Matrix chain: `k` is where the chain splits — everything left of `k` is one sub-chain, everything from `k+1` is another. Both sub-problems are independent (they never share matrices).

Burst balloons: `k` is the last to burst — when `k` bursts, all others in `[i, j]` are already gone, so its neighbors are exactly `nums[i]` and `nums[j]`.

**Q15. How do you handle the "minimum cost to merge stones" problem?**
A: Given `n` piles of stones and an integer `k` (you can only merge exactly `k` consecutive piles at a time into one), find the minimum cost to merge all into one pile. Cost of a merge = total stones in the merged group.

The key feasibility check: it's only possible to merge all piles into one if `(n - 1) % (k - 1) === 0`. If not, return -1.

```
dp[i][j] = min cost to merge piles i..j into one pile
           (only valid when (j - i) % (k - 1) === 0)

dp[i][j] = min over all valid splits into k sub-groups of:
             dp[i][k₁] + dp[k₁+1][k₂] + ... + dp[kₖ₋₁+1][j] + sum(piles[i..j])
```

For k=2 (merge any two adjacent groups), this simplifies to the standard interval DP with split points. For general k, the split must divide `[i, j]` into exactly k parts of sizes satisfying the feasibility condition.

**Q16. What is the optimal binary search tree problem?**
A: Given `n` keys with search frequencies `freq[i]` and `n+1` dummy key frequencies `dfreq[i]` (for searches falling between keys), find the BST arrangement minimizing expected search cost. The cost of a node at depth `d` is `(d+1) × freq[i]`.

```
dp[i][j] = minimum expected search cost for keys i..j as the subtree
w[i][j] = sum of all frequencies in range [i..j] (keys + dummies)

dp[i][j] = min over r from i to j (root of subtree [i,j]):
             dp[i][r-1] + dp[r+1][j] + w[i][j]

dp[i][i-1] = dfreq[i-1]   (base: empty subtree with just a dummy key)
```

The `+ w[i][j]` term comes from the fact that making any node the root increases all its descendants' depths by 1, adding `w[i][j]` to the total cost.

**Q17. How does the recurrence for "minimum number of palindrome partitions" work as interval DP?**
A: Given a string `s`, find the minimum number of cuts to partition it into palindromes.

```
dp[i][j] = minimum cuts for s[i..j]

dp[i][j] = 0 if s[i..j] is already a palindrome
dp[i][j] = min over k from i to j-1 of:
             dp[i][k] + dp[k+1][j] + 1
```

The palindrome check `isPalin[i][j]` can itself be precomputed with interval DP:
```
isPalin[i][j] = (s[i] === s[j]) && isPalin[i+1][j-1]
```

This makes the total algorithm O(n²) precomputation + O(n³) interval DP = O(n³). A more efficient O(n²) approach exists (1D DP + Manacher's), but the interval DP version demonstrates the pattern cleanly.

### Section 5: Complexity & Trade-offs

**Q18. Compare matrix chain multiplication's complexity to naive brute force.**
A:

| Approach | Time | Space | Notes |
|---|---|---|---|
| Brute force (all parenthesizations) | O(4ⁿ / n^(3/2)) | O(n) | Catalan number of orderings |
| Recursive without memo | O(2ⁿ) | O(n) call stack | Exponential — recomputes subproblems |
| Top-down memoization | O(n³) | O(n²) | Cache eliminates recomputation |
| Bottom-up tabulation | O(n³) | O(n²) | Same complexity, no recursion overhead |
| Hu-Shing algorithm | O(n log n) | O(n) | Beyond interview scope |

The DP improvement from exponential to O(n³) is dramatic — for n=20, brute force is infeasible (billions of operations), while DP completes in microseconds.

**Q19. Can the space be reduced below O(n²) for matrix chain?**
A: Not in general for the standard problem — you need all `dp[i][j]` values to compute the answer, and there are O(n²) intervals. Unlike 1D DP where space can often be reduced to O(1) by keeping only the previous row, the 2D interval structure requires the full table because `dp[i][j]` can depend on `dp[i][k]` and `dp[k+1][j]` for any `k` in between — you can't discard any previous interval.

For problems where you only need the final answer (not the split table), you can avoid the `split` array — reducing constant factors but not asymptotic space. The `dp` table itself is irreducible.

**Q20. What is the Hu-Shing algorithm and when would you mention it?**
A: The Hu-Shing algorithm (1982) solves the matrix chain problem in O(n log n) time and O(n) space by exploiting the geometric structure of the problem. It's a highly complex algorithm involving convex hull tricks and not expected in any interview. Mention it only if asked "is O(n³) optimal?" — the correct answer is "no, O(n log n) is achievable with the Hu-Shing algorithm, but O(n³) DP is the standard and expected interview solution." Knowing this bound exists signals depth without requiring you to implement it.

### Section 6: Scenario / Interview-Style Questions

**Q21. "An interviewer gives you the matrix chain problem for the first time. Walk through your thought process from scratch."**
A: A structured five-step approach:

1. **Recognize the decision**: at each step, you must choose where to split the chain. The choice is which pair to multiply first — this is the "variable" of the problem.

2. **Identify optimal substructure**: if the optimal solution splits the chain at position `k`, then the left sub-chain `[1..k]` and right sub-chain `[k+1..n]` must also be optimally parenthesized (otherwise, improving a sub-chain improves the whole solution — contradiction). This confirms DP is applicable.

3. **Define the subproblem**: `dp[i][j]` = min cost to multiply matrices `i` through `j`. State this out loud.

4. **Write the recurrence**: `dp[i][j] = min over k in [i, j-1] of { dp[i][k] + dp[k+1][j] + dims[i-1] × dims[k] × dims[j] }`. Base: `dp[i][i] = 0`.

5. **Determine fill order**: `dp[i][j]` depends on shorter intervals → fill by increasing length. Code the three nested loops.

State complexity at the end: O(n³) time, O(n²) space.

**Q22. "Why can't we use a greedy approach — always multiply the cheapest adjacent pair first?"**
A: Greedy fails because the locally cheapest multiplication may prevent globally cheaper computations later. Classic counterexample:

```
dims = [10, 1, 10, 1, 10]
Matrices: A(10×1), B(1×10), C(10×1), D(1×10)

Greedy (cheapest first):
  A×B costs 10×1×10 = 100, result is 10×10
  C×D costs 10×1×10 = 100, result is 10×10
  (A×B)×(C×D) costs 10×10×10 = 1000
  Total: 1200

Better approach:
  B×C costs 1×10×1 = 10, result is 1×1
  A×(B×C) costs 10×1×1 = 10, result is 10×1
  (A×(B×C))×D costs 10×1×10 = 100, result is 10×10
  Total: 120

Greedy gives 10× worse result.
```

The greedy choice ignores the effect on future multiplications. Only an exhaustive search over all split points (DP) guarantees the global optimum.

**Q23. "What if the matrices have special structure — e.g., all are square with the same dimension? Does the problem simplify?"**
A: If all matrices are `d × d` (square, same dimension), then every multiplication costs `d × d × d = d³` regardless of parenthesization — all orderings have identical cost (`n-1` multiplications each costing `d³`). The problem becomes trivial — any order is optimal. This is worth mentioning as a degenerate case where the input structure eliminates the optimization problem entirely.

More generally, if all matrices are square (but different sizes), the problem reduces to minimizing over different orderings, and the DP approach still applies — no simplification. Only equal-size square matrices eliminate the distinction.

**Q24. "Can you solve matrix chain multiplication with divide and conquer without memoization — and if not, why not?"**
A: Divide and conquer without memoization is exactly the naive recursive approach — exponential time. When we split `[1, n]` at position `k`, we recurse on `[1, k]` and `[k+1, n]`. For `k=1`, we solve `[2, n]`; for `k=2`, we solve `[1, 2]` and `[3, n]`. The sub-chain `[3, n]` appears in multiple branches — this is the overlapping subproblems property. Without memoization, the same sub-chain is solved exponentially many times. Divide and conquer works for problems with independent subproblems (e.g., merge sort: the left and right halves never overlap). It fails for problems with overlapping subproblems — which is exactly what DP (via memoization or tabulation) fixes.

**Q25. "An interviewer extends the problem: the matrix dimensions are given as ranges (not exact values) due to uncertainty. Can you still use DP?"**
A: With range dimensions `[lo_i, hi_i]`, the cost of multiplying depends on the actual dimensions chosen. This becomes a min-max optimization (minimize worst case) or expected value optimization (minimize expected cost). The DP structure is preserved — `dp[i][j]` = optimal cost for range `[i, j]` — but the combining cost `dims[i-1] × dims[k] × dims[j]` becomes a function of the range, and the optimization must account for the uncertainty model. For a worst-case model, substitute `hi_i` for `dims[i]` (upper bound on cost). For an expected-value model, integrate or approximate. The fill order and recurrence structure remain identical; only the cost function changes. This tests whether you understand the algorithm structurally rather than just memorizing it.

## Problem 1 — Matrix Chain Multiplication (Classic)

### Problem
Given an array `dims` representing matrix dimensions where matrix `i` has dimensions `dims[i-1] × dims[i]`, find the minimum number of scalar multiplications needed to compute the product of all matrices.

```
Input:  dims=[10, 30, 5, 60]
Output: 4500
        Best: (A₁×A₂)×A₃ = 10×30×5 + 10×5×60 = 1500 + 3000

Input:  dims=[40, 20, 30, 10, 30]
Output: 26000
        Best: A₁×((A₂×A₃)×A₄) = 20×30×10 + 40×20×10 + 40×10×30
                                 = 6000 + 8000 + 12000 = 26000

Input:  dims=[10, 20, 30, 40, 30]
Output: 30000
```

### Pattern Recognition
Interval DP — the answer for the full chain depends on splitting it into two sub-chains at every possible position. The same sub-chains appear in multiple full-chain splits → overlapping subproblems. Optimal split of the full chain requires optimal splits of sub-chains → optimal substructure.

### Subproblem Definition
`dp[i][j]` = minimum number of scalar multiplications to compute the product of matrices `Aᵢ` through `Aⱼ` (1-indexed).

### Recurrence
```
dp[i][i] = 0   (single matrix — no multiplication needed)

dp[i][j] = min over k from i to j-1 of:
             dp[i][k] + dp[k+1][j] + dims[i-1] × dims[k] × dims[j]

where dims[i-1] × dims[k] = dimensions of result of left chain [i..k]
      dims[k] × dims[j]   = dimensions of result of right chain [k+1..j]
      dims[i-1] × dims[k] × dims[j] = cost of one multiplication
```

### Top-Down Implementation

```js
function matrixChainMemo(dims) {
  const n = dims.length - 1; // number of matrices
  // memo[i][j]: min cost for chain Aᵢ..Aⱼ (-1 = uncomputed)
  const memo = Array.from({length: n + 1}, () => new Array(n + 1).fill(-1));

  function dp(i, j) {
    if (i === j) return 0;             // base: single matrix
    if (memo[i][j] !== -1) return memo[i][j]; // cache hit

    let best = Infinity;

    // try every split point k
    for (let k = i; k < j; k++) {
      const cost = dp(i, k)                    // cost of left sub-chain
                 + dp(k + 1, j)                // cost of right sub-chain
                 + dims[i - 1] * dims[k] * dims[j]; // combining cost

      if (cost < best) best = cost;
    }

    memo[i][j] = best; // cache before returning
    return best;
  }

  return dp(1, n); // full chain from matrix 1 to n
}
```

### Bottom-Up Implementation

```js
function matrixChainTab(dims) {
  const n = dims.length - 1;

  // dp[i][j]: 1-indexed; (n+1)×(n+1) table, initialized to 0
  const dp = Array.from({length: n + 1}, () => new Array(n + 1).fill(0));
  // dp[i][i] = 0 for all i (single matrix — already initialized)

  // fill by increasing chain length
  for (let len = 2; len <= n; len++) {          // chain length
    for (let i = 1; i <= n - len + 1; i++) {   // start index
      const j = i + len - 1;                    // end index
      dp[i][j] = Infinity;

      // try all split points within [i, j)
      for (let k = i; k < j; k++) {
        const cost = dp[i][k]
                   + dp[k + 1][j]
                   + dims[i - 1] * dims[k] * dims[j];
        dp[i][j] = Math.min(dp[i][j], cost);
      }
    }
  }

  return dp[1][n]; // answer: full chain A₁ to Aₙ
}
```

### Full Bottom-Up with Split Table (Returns Parenthesization)

```js
function matrixChainFull(dims) {
  const n = dims.length - 1;
  const dp = Array.from({length: n + 1}, () => new Array(n + 1).fill(0));
  const split = Array.from({length: n + 1}, () => new Array(n + 1).fill(0));

  for (let len = 2; len <= n; len++) {
    for (let i = 1; i <= n - len + 1; i++) {
      const j = i + len - 1;
      dp[i][j] = Infinity;

      for (let k = i; k < j; k++) {
        const cost = dp[i][k] + dp[k + 1][j] + dims[i-1] * dims[k] * dims[j];
        if (cost < dp[i][j]) {
          dp[i][j] = cost;
          split[i][j] = k; // record the optimal split point
        }
      }
    }
  }

  function reconstruct(i, j) {
    if (i === j) return `A${i}`;
    const k = split[i][j];
    const left = reconstruct(i, k);
    const right = reconstruct(k + 1, j);
    return `(${left} × ${right})`;
  }

  return {
    minCost: dp[1][n],
    parenthesization: reconstruct(1, n)
  };
}
```

## Problem 2 — Burst Balloons (LeetCode 312)

### Problem
Given `n` balloons with values `nums[i]`, bursting balloon `i` gives `nums[i-1] × nums[i] × nums[i+1]` coins (with `nums[-1] = nums[n] = 1`). Find the maximum coins obtainable by bursting all balloons.

```
Input:  nums=[3,1,5,8]   → 167
        Burst order: 1→5→3→8
        Coins: 3×1×5 + 3×5×8 + 1×3×8 + 1×8×1 = 15+120+24+8 = 167

Input:  nums=[1,5]        → 10
        Burst 1 first: 1×1×5=5, then 1×5×1=5. Total=10
        Or burst 5 first: 1×5×1=5, then 1×1×1=1. Total=6
        Best: burst 1 first → 10
```

### Pattern Recognition
Interval DP with a reversed split perspective. Instead of thinking "which balloon to burst first," think "which balloon is burst **last** in range `[i, j]`." The last balloon's neighbors are the boundaries `i-1` and `j+1` (which are not burst in this subproblem), giving a clean, independent subproblem.

### Subproblem Definition
Add sentinel balloons: `nums[-1] = nums[n] = 1`. Expand `nums` to include boundaries.

`dp[i][j]` = maximum coins from bursting all balloons **strictly between** indices `i` and `j` (boundaries `i` and `j` are not burst in this range).

### Recurrence
```
dp[i][j] = max over k from i+1 to j-1 of:
             dp[i][k] + dp[k][j] + nums[i] × nums[k] × nums[j]

where k is the LAST balloon burst in (i, j)
      nums[i] × nums[k] × nums[j] is its value when burst last
      (neighbors are i and j because all others in (i,j) are already burst)

dp[i][j] = 0 when j - i < 2   (no balloons strictly between i and j)
```

### Both Implementations

```js
// ── TOP-DOWN (Memoization) ──────────────────────────────────────
function maxCoinsMemo(nums) {
  // add boundary sentinels
  const arr = [1, ...nums, 1];
  const n = arr.length; // n+2 with sentinels
  const memo = Array.from({length: n}, () => new Array(n).fill(-1));

  function dp(i, j) {
    if (j - i < 2) return 0;      // no balloon strictly between i and j
    if (memo[i][j] !== -1) return memo[i][j];

    let best = 0;
    // k is the LAST balloon to burst in (i, j)
    for (let k = i + 1; k < j; k++) {
      const coins = dp(i, k)             // burst all between i and k first
                  + dp(k, j)             // burst all between k and j first
                  + arr[i] * arr[k] * arr[j]; // burst k last (neighbors are i, j)
      best = Math.max(best, coins);
    }

    memo[i][j] = best;
    return best;
  }

  // full range: between sentinel 0 and sentinel n-1
  return dp(0, n - 1);
}

// ── BOTTOM-UP (Tabulation) ─────────────────────────────────────
function maxCoinsTab(nums) {
  const arr = [1, ...nums, 1];
  const n = arr.length; // n+2 elements (with sentinels at 0 and n-1)

  // dp[i][j] = max coins from balloons strictly between i and j
  const dp = Array.from({length: n}, () => new Array(n).fill(0));

  // fill by increasing gap (j - i): gap=2 means one balloon between i and j
  for (let gap = 2; gap < n; gap++) {
    for (let i = 0; i < n - gap; i++) {
      const j = i + gap;
      // try each k as the last balloon burst in (i, j)
      for (let k = i + 1; k < j; k++) {
        const coins = dp[i][k] + dp[k][j] + arr[i] * arr[k] * arr[j];
        dp[i][j] = Math.max(dp[i][j], coins);
      }
    }
  }

  return dp[0][n - 1];
}
```

## Problem 3 — Minimum Cost to Merge Stones (LeetCode 1000)

### Problem
Given `n` piles of stones and integer `k`, you can merge exactly `k` consecutive piles into one (cost = total stones merged). Find the minimum cost to reduce to one pile. Return -1 if impossible.

```
Input:  stones=[3,2,4,1], k=2   → 20
        Merge [3,2]→5(cost 5), [4,1]→5(cost 5), [5,5]→10(cost 10). Total=20
        Or: [2,4]→6, [3,6]→9, [9,1]→10. Total=25
        Minimum is 20.

Input:  stones=[3,2,4,1], k=3   → -1
        4 piles, k=3: need (n-1)%(k-1)=3%2=1≠0 → impossible

Input:  stones=[3,5,1,2,6], k=3 → 25
```

### Pattern Recognition
Interval DP with feasibility constraint. `dp[i][j]` = min cost to reduce piles `i..j` to the fewest possible piles (one pile if `(j-i) % (k-1) === 0`). The split: divide into a group of size divisible by `(k-1)` and the remainder.

### Subproblem Definition
`dp[i][j]` = minimum cost to merge piles `i..j` into `ceil((j-i)/(k-1))` piles. If `(j-i) % (k-1) === 0`, this reduces to 1 pile.

### Recurrence
```
Feasibility: possible to merge all iff (n-1) % (k-1) === 0

dp[i][i] = 0   (single pile — no cost)

dp[i][j] = min over k-splits: split [i,j] into first chunk [i,m] of size
           divisible by (k-1), and rest [m+1,j]

Simplified (for k=2, merge any adjacent pair):
dp[i][j] = min over m from i to j-1 of:
             dp[i][m] + dp[m+1][j] + sum(stones[i..j])

For general k, merge step adds sum(stones[i..j]) only when
(j-i) % (k-1) === 0 (can reduce to one pile):
dp[i][j] += prefix[j+1] - prefix[i]   if (j-i) % (k-1) === 0
```

### Solution

```js
function mergeStones(stones, k) {
  const n = stones.length;

  // feasibility check
  if ((n - 1) % (k - 1) !== 0) return -1;

  // prefix sums for O(1) range sum queries
  const prefix = new Array(n + 1).fill(0);
  for (let i = 0; i < n; i++) prefix[i + 1] = prefix[i] + stones[i];

  const rangeSum = (i, j) => prefix[j + 1] - prefix[i]; // sum of stones[i..j]

  // dp[i][j] = min cost to merge piles i..j into minimum possible piles
  const dp = Array.from({length: n}, () => new Array(n).fill(0));

  // fill by length
  for (let len = k; len <= n; len++) {           // min useful chain length is k
    for (let i = 0; i <= n - len; i++) {
      const j = i + len - 1;
      dp[i][j] = Infinity;

      // split into [i..m] and [m+1..j], where m advances by (k-1) steps
      // this ensures [i..m] can reduce to exactly 1 pile
      for (let m = i; m < j; m += k - 1) {
        dp[i][j] = Math.min(dp[i][j], dp[i][m] + dp[m + 1][j]);
      }

      // if this range reduces to 1 pile, add the cost of the final merge
      if ((j - i) % (k - 1) === 0) {
        dp[i][j] += rangeSum(i, j);
      }
    }
  }

  return dp[0][n - 1];
}
```

## Problem 4 — Strange Printer (LeetCode 664)

### Problem
A printer can print a sequence of same characters in one turn (overwriting previous content). Given a string `s`, return the minimum number of turns to print it.

```
Input:  s="aaabbb"  → 2  (print "aaa", then print "bbb")
Input:  s="aba"     → 2  (print "aaa", then print "b" at position 2)
Input:  s="abacaba" → 4
```

### Pattern Recognition
Interval DP — the minimum turns to print substring `s[i..j]` depends on substrings. If `s[i] === s[k]` for some `k > i`, we can "extend" the first turn to cover both positions simultaneously (the printer can print across the gap and later overwrite the middle).

### Subproblem Definition
`dp[i][j]` = minimum turns to print substring `s[i..j]`.

### Recurrence
```
dp[i][i] = 1   (one character needs exactly one turn)

Base observation: dp[i][j] = dp[i+1][j] + 1
  (print s[i] in one extra turn, then handle s[i+1..j])

Optimization: if s[i] === s[k] for some k in (i, j]:
  dp[i][j] = min(dp[i][j], dp[i+1][k] + dp[k+1][j])
  (the turn that prints s[i] also covers s[k], so we
   save one turn by merging the two segments)
  Note: dp[i+1][k] not dp[i][k-1] because s[i]=s[k] are
  printed in the same turn, so we only need to handle i+1..k-1
  and k+1..j separately, but the s[k] is "free" since s[i]=s[k].
```

### Solution

```js
function strangePrinter(s) {
  const n = s.length;
  // dp[i][j] = min turns to print s[i..j]
  const dp = Array.from({length: n}, () => new Array(n).fill(0));

  // fill by length, starting from single characters
  for (let len = 1; len <= n; len++) {
    for (let i = 0; i <= n - len; i++) {
      const j = i + len - 1;

      // base: s[i..j] takes at least dp[i+1][j]+1 turns
      // (print s[i] separately, then handle rest)
      dp[i][j] = (i === j) ? 1 : dp[i + 1][j] + 1;

      // optimization: if s[i] appears again at position k,
      // the turn for s[i] can extend to cover s[k]
      for (let k = i + 1; k <= j; k++) {
        if (s[k] === s[i]) {
          // s[i] and s[k] printed in same turn
          // need: turns for s[i+1..k] (excluding s[k], covered by s[i]'s turn)
          //     + turns for s[k+1..j]
          const candidate = dp[i + 1][k] + (k + 1 <= j ? dp[k + 1][j] : 0);
          dp[i][j] = Math.min(dp[i][j], candidate);
        }
      }
    }
  }

  return dp[0][n - 1];
}
```

```
    k=1: s[1]='b'≠s[0]='a' → no optimization
    dp[0][1]=2  ("ab" needs 2 turns: print 'a', print 'b')

  dp[1][2]: base=dp[2][2]+1=2
    k=2: s[2]='a'≠s[1]='b' → no optimization
    dp[1][2]=2  ("ba" needs 2 turns)

len=3:
  dp[0][2]: base=dp[1][2]+1=3
    k=1: s[1]='b'≠s[0]='a' → skip
    k=2: s[2]='a'=s[0]='a' → optimization!
      candidate = dp[1][2] + 0 (k+1=3>j=2, no right part)
               = dp[0+1][2] + 0
               Wait — formula: dp[i+1][k] + dp[k+1][j]
               = dp[1][2] + dp[3][2]
               dp[3][2] is out of range (empty) = 0
               candidate = 2 + 0 = 2
    dp[0][2] = min(3, 2) = 2

return dp[0][2] = 2 ✓
("aba": print "aaa" in turn 1, print "b" at position 1 in turn 2)
```

### Complexity
- Time: O(n³) — three nested loops.
- Space: O(n²) — DP table.

### Edge Cases
- All same character: `dp[0][n-1] = 1` (print entire string in one turn).
- All distinct characters: `dp[0][n-1] = n` (one turn per character, no optimization possible).
- Empty string: n=0 → return 0.

### Follow-up Questions
- "What if the printer can print multiple different characters in one pass?" → Different model — more complex recurrence based on printer's actual capability.
- "Minimum cost where each print has a cost proportional to the length printed?" → Modify the recurrence to add length-based cost at each turn.

## Quick Reference — Interval DP Patterns

```
Interval DP Template:
  dp[i][j] = answer for subproblem on range [i, j]
  Base: dp[i][i] = base_value
  Fill: for len=2 to n, for i=0 to n-len, j=i+len-1
  Split: for k=i to j-1 (or i+1 to j-1 for "last" variants)
  Recurrence: dp[i][j] = optimal(dp[i][k] OP dp[k+1][j] OP combine_cost)
  Answer: dp[0][n-1] or dp[1][n]

Problem-Specific Differences:
  Matrix Chain:    split at k → left[i..k], right[k+1..j]
                   cost = dims[i-1]×dims[k]×dims[j]
                   optimize: min

  Burst Balloons:  k = LAST burst in (i,j) → "open" boundary subproblems
                   cost = arr[i]×arr[k]×arr[j]  (neighbors are boundaries)
                   optimize: max
                   Note: dp[i][k] means between i and k (exclusive)

  Merge Stones:    split at m stepping by (k-1)
                   cost = rangeSum(i,j) when (j-i)%(k-1)===0
                   optimize: min

  Strange Printer: extend when s[i]=s[k] (same char covers gap)
                   cost = dp[i+1][k] + dp[k+1][j]  (s[k] is free)
                   optimize: min

  Palindrome Partition: split at k; check if s[i..k] is palindrome
                   cost = 0 if palindrome, else dp[i][k]+dp[k+1][j]+1
                   optimize: min
```

## Common Bugs Checklist

Before finalizing any interval DP solution, verify:

1. **Fill by length, not by row/column** — the outer loop must iterate over `len` (chain length) from 2 to n. Iterating by row first (`for i from 1 to n`) causes accessing `dp[k+1][j]` values that may not yet be computed when `k+1 > i`.

2. **1-indexed vs 0-indexed consistency** — matrix chain is naturally 1-indexed (matrix `i` has dimensions `dims[i-1] × dims[i]`). Burst balloons uses 0-indexed array with sentinels. Choose one convention and apply it consistently. Off-by-one errors from mixing are the most common interview bug.

3. **`dp[i][j]` initialized to `Infinity` before the split loop** — for minimization problems, start with `Infinity` (not 0) so the first split point candidate replaces it. Starting at 0 gives the wrong answer of 0 for all intervals.

4. **Burst Balloons: `k` is the LAST burst, not the first** — using `k` as the first balloon to burst creates dependencies (neighbors of `k` change as others burst). The "last burst" formulation gives independent sub-problems with fixed boundaries. This is the core insight; getting it wrong makes the recurrence incorrect.

5. **Index bounds for combining cost** — in matrix chain, the combining cost is `dims[i-1] × dims[k] × dims[j]`. The indices `i-1`, `k`, `j` must all be valid indices into `dims` (0 to n). Check: `i-1 ≥ 0` (guaranteed since `i ≥ 1`), `k < n` (guaranteed since `k < j ≤ n`), `j ≤ n` (guaranteed by loop bounds). Verify analogous bounds for other interval DP problems.

6. **Feasibility check before running DP** — for merge stones: `if ((n-1) % (k-1) !== 0) return -1`. Skipping this check causes the DP to compute a finite answer for an infeasible instance, silently returning a wrong result.

---

**Final Tip:** At the 5 YOE level, matrix chain and its interval DP cousins are tested in one of three ways: implement the classic problem, explain the recurrence derivation (especially why `k` in burst balloons is the last balloon), or recognize that a new problem has the interval DP structure. The highest-signal move is to immediately state: "this is interval DP — I'll define `dp[i][j]` as the answer for the subrange, fill by increasing length, and try every split point." That framing, spoken before touching code, tells the interviewer you recognize the pattern structurally. Then the crucial second move: derive the combining cost formula from the problem definition rather than reciting it. Interviewers at this level ask "where does `dims[i-1] × dims[k] × dims[j]` come from?" — be ready to explain that the left sub-chain produces a `dims[i-1] × dims[k]` matrix, the right produces `dims[k] × dims[j]`, and multiplying them costs exactly `dims[i-1] × dims[k] × dims[j]` scalar operations.
