### Section 1: Fundamentals

**Q1. What is dynamic programming, and what are the two properties a problem must have for DP to apply?**
A: Dynamic programming (DP) is an algorithmic technique that solves a problem by breaking it into **overlapping subproblems**, solving each subproblem exactly once, and combining the results. It is applicable when a problem has exactly two properties:

- **Optimal substructure**: the optimal solution to the problem can be constructed from optimal solutions to its subproblems. If you can break the problem into smaller versions of itself and the best answer to the whole is built from the best answers to the parts, optimal substructure holds.
- **Overlapping subproblems**: the same subproblems recur multiple times during the naive recursive solution. If every subproblem is unique (as in merge sort), memoization provides no benefit — that's divide-and-conquer, not DP.

```
Example — Fibonacci:
fib(5) = fib(4) + fib(3)
fib(4) = fib(3) + fib(2)   ← fib(3) computed TWICE without DP
fib(3) = fib(2) + fib(1)   ← fib(2) computed THREE TIMES

Overlapping subproblems: ✓ (fib(3), fib(2) recomputed)
Optimal substructure:    ✓ (fib(n) = fib(n-1) + fib(n-2) — optimal by definition)

Without DP: O(2^n) — exponential
With DP:    O(n)   — each subproblem solved once
```

**Q2. What is the difference between memoization (top-down DP) and tabulation (bottom-up DP)?**
A: Both approaches solve each subproblem exactly once and store the result. They differ in direction and implementation style:

- **Memoization (top-down)**: start with the original problem, recurse into subproblems, and cache results in a hash map or array as they're computed. Subproblems are solved **lazily** — only those actually needed by the recursive calls are computed. The call order mirrors the natural recursive structure of the problem.
- **Tabulation (bottom-up)**: start with the smallest subproblems (base cases), fill a table iteratively in a predetermined order, and build up to the original problem. All subproblems in the table are computed, whether or not they're needed. No recursion — no call-stack overhead.

```js
// Memoization (top-down): natural recursion + cache
function fib(n, memo = {}) {
  if (n <= 1) return n;
  if (memo[n] !== undefined) return memo[n];  // cache hit
  memo[n] = fib(n - 1, memo) + fib(n - 2, memo);
  return memo[n];
}

// Tabulation (bottom-up): fill table from base cases upward
function fib(n) {
  if (n <= 1) return n;
  const dp = new Array(n + 1);
  dp[0] = 0; dp[1] = 1;
  for (let i = 2; i <= n; i++) {
    dp[i] = dp[i - 1] + dp[i - 2];
  }
  return dp[n];
}

// Space-optimized tabulation: only last two values needed
function fib(n) {
  if (n <= 1) return n;
  let prev2 = 0, prev1 = 1;
  for (let i = 2; i <= n; i++) {
    const curr = prev1 + prev2;
    prev2 = prev1;
    prev1 = curr;
  }
  return prev1;
}
```

| | Memoization | Tabulation |
|---|---|---|
| Direction | Top-down (recursive) | Bottom-up (iterative) |
| Subproblems solved | Only needed ones | All in table |
| Stack overhead | O(depth) call stack | O(1) — no recursion |
| Code style | Closer to brute force | Requires determining order |
| Space optimization | Harder | Natural (slide window) |

**Q3. What is the "recurrence relation," and why is it the most important step in any DP solution?**
A: The recurrence relation is the equation that expresses the solution to a problem of size n in terms of solutions to smaller subproblems. It is the mathematical heart of every DP solution — everything else (memoization table, iteration order, space optimization) is mechanical once the recurrence is correct.

Finding the recurrence requires asking: **"If I knew the optimal answers to all smaller subproblems, how would I compute the answer to the current one?"** The answer to this question, expressed precisely, is the recurrence.

```
Classic recurrences:

Fibonacci:
  dp[n] = dp[n-1] + dp[n-2]

0/1 Knapsack:
  dp[i][w] = max(dp[i-1][w],           // don't take item i
                 dp[i-1][w-weight[i]] + value[i])  // take item i (if w >= weight[i])

Longest Common Subsequence:
  dp[i][j] = dp[i-1][j-1] + 1                    if s1[i] === s2[j]
            = max(dp[i-1][j], dp[i][j-1])         otherwise

Edit Distance:
  dp[i][j] = dp[i-1][j-1]                        if s1[i] === s2[j]  (no op)
            = 1 + min(dp[i-1][j],                 // delete from s1
                      dp[i][j-1],                 // insert into s1
                      dp[i-1][j-1])               // replace

Coin Change (min coins):
  dp[amount] = 1 + min(dp[amount - coin] for each coin)
```

**Q4. What are the canonical DP problem archetypes, and what recurrence pattern does each use?**
A: At the 5–7 YOE level, interviewers expect pattern recognition — knowing which recurrence template applies to a new problem. The six primary archetypes:

- **Linear DP (1D)**: state is a single index. `dp[i]` depends on a small number of previous entries. Examples: Fibonacci, climbing stairs, house robber, coin change.
- **Grid/2D path DP**: state is `(row, col)`. Each cell depends on the cell above and/or to the left. Examples: unique paths, minimum path sum, triangle.
- **String DP**: state is `(i, j)` — position in two strings (or one string and itself for palindrome problems). Examples: LCS, edit distance, longest palindromic subsequence.
- **Knapsack DP**: state is `(item_index, remaining_capacity)`. A "yes/no" decision per item. Variants: 0/1 (item used at most once), unbounded (item used any times), partitioning (split array into groups).
- **Interval DP**: state is `(left, right)` — a subarray or substring. Depends on splitting at some middle point k. Examples: matrix chain multiplication, burst balloons, palindrome partitioning.
- **Tree/Graph DP**: state is a subtree rooted at a node. Result depends on children's DP values. Examples: diameter of binary tree, max path sum, house robber III.

```
Choosing the archetype:
1. One sequence, one pointer → Linear DP
2. Two sequences or one sequence vs. itself → String DP
3. 2D grid, move right/down → Grid DP
4. Binary choice (take/skip) with a capacity → Knapsack DP
5. "Best way to split/parenthesize a range" → Interval DP
6. Rooted subtree structure → Tree DP
```

**Q5. What is the difference between DP and greedy algorithms, and how do you know which applies?**
A: Both greedy and DP exploit optimal substructure. The difference:

- **Greedy**: makes the locally optimal choice at each step without reconsidering past decisions. Correctness requires a **greedy choice property** — making the locally best choice always leads to a globally optimal solution. Greedy is faster (usually O(n) or O(n log n)) but applies to fewer problems.
- **DP**: considers all possible choices at each step and picks the best, storing results to avoid recomputation. Correct whenever optimal substructure holds — no greedy choice property required. Slower (polynomial) but universally applicable to the class of problems with overlapping subproblems.

**How to distinguish**: if you can prove that the greedy choice is always safe (exchange argument, staying-ahead argument, or matroid structure), use greedy. If the optimal choice at each step depends on future decisions that you can't know without exploring, use DP.

```
Greedy works:    Activity selection, Huffman coding, Dijkstra, Kruskal's MST
DP required:     0/1 Knapsack, Edit Distance, LCS, Coin Change (general denominations)

Coin change with denominations [1, 3, 4], target=6:
  Greedy: 4+1+1=3 coins.
  DP:     3+3=2 coins ← greedy is WRONG here. DP is required.
```

### Section 2: State Design

**Q6. How do you identify the DP "state" — what it represents and what variables it must track?**
A: The state is the minimal set of information needed to uniquely identify a subproblem and determine its optimal answer, without knowing how you arrived at it (the **Markov property**). Designing the state correctly is the hardest part of DP.

The process: ask "what information do I need to compute the answer from this point forward?" Every piece of information that affects future decisions must be part of the state. Every piece that doesn't must be excluded (or the state space becomes unnecessarily large).

```
Example — House Robber:
  You're at house i. Do you need to know which earlier houses were robbed?
  No — you only need to know whether house i-1 was robbed (affects whether i is available).
  State: dp[i] = max money robbing houses 0..i, where house i is robbed OR skipped.
  Better: dp[i] = max money considering houses 0..i (regardless of whether i is robbed).
  Recurrence: dp[i] = max(dp[i-1], dp[i-2] + nums[i])
    → dp[i-1]: skip house i (whatever was optimal through i-1)
    → dp[i-2] + nums[i]: rob house i (can't rob i-1, so best through i-2 plus i's value)

Example — 0/1 Knapsack:
  You're considering item i with remaining capacity w.
  Do you need to know which specific items were taken before?
  No — only the remaining capacity matters (how much you can still carry).
  State: dp[i][w] = max value using items 0..i with capacity exactly w.
  → Two variables because both the item index AND remaining capacity affect future choices.

Example — Stock Trading (at most k transactions):
  State needs: day i, transactions remaining k, whether you currently hold stock.
  dp[i][k][holding] — three variables because all three affect valid future moves.
```

**Q7. What is "state space reduction," and what are the common techniques for it?**
A: State space reduction eliminates redundant dimensions from the DP table, reducing time and/or space complexity without changing correctness. The key techniques:

- **Rolling array / sliding window**: if `dp[i]` depends only on `dp[i-1]` (and maybe `dp[i-2]`), store only the last 1–2 rows instead of the full table. Reduces space from O(n) to O(1), or from O(n²) to O(n).
- **Dimension elimination via observation**: if one dimension of the state is always determined by another (e.g., `i + j = constant` along a diagonal), that dimension can be derived and eliminated.
- **Reordering the tabulation**: in knapsack problems, iterating the capacity dimension in reverse (for 0/1 knapsack) allows a 1D array to replace the 2D table — each item is considered at most once because reverse iteration prevents using the same item twice.

```js
// LCS: 2D → 1D rolling array
// Original: dp[i][j] depends on dp[i-1][j-1], dp[i-1][j], dp[i][j-1]
// Only the previous row is needed — store it as a 1D array

function lcs(s1, s2) {
  const m = s1.length, n = s2.length;
  let prev = new Array(n + 1).fill(0);

  for (let i = 1; i <= m; i++) {
    const curr = new Array(n + 1).fill(0);
    for (let j = 1; j <= n; j++) {
      if (s1[i-1] === s2[j-1]) {
        curr[j] = prev[j-1] + 1;       // diagonal: from previous row, previous col
      } else {
        curr[j] = Math.max(prev[j], curr[j-1]); // up or left
      }
    }
    prev = curr;
  }
  return prev[n];
}

// 0/1 Knapsack: 2D → 1D with reverse iteration
function knapsack01(weights, values, capacity) {
  const dp = new Array(capacity + 1).fill(0);

  for (let i = 0; i < weights.length; i++) {
    // Iterate BACKWARDS: prevents item i from being used more than once
    // Forward iteration would use item i multiple times (unbounded knapsack behavior)
    for (let w = capacity; w >= weights[i]; w--) {
      dp[w] = Math.max(dp[w], dp[w - weights[i]] + values[i]);
    }
  }
  return dp[capacity];
}
```

**Q8. How do you handle DP problems where the state space is a bitmask (bitmask DP)?**
A: Bitmask DP is used when the state must encode which subset of a small set has been "used" or "visited." A bitmask of k bits represents which of k elements are included in the current subset — 2^k possible states. This is practical for k ≤ 20–25 (beyond that, 2^k states become infeasible).

The classic application is the **Travelling Salesman Problem (TSP)**: `dp[mask][i]` = minimum cost to visit exactly the cities in `mask`, ending at city `i`. At each step, try extending to an unvisited city `j` (not in `mask`): `dp[mask | (1 << j)][j] = min(dp[mask | (1 << j)][j], dp[mask][i] + dist[i][j])`.

```js
// TSP with bitmask DP
function tsp(dist) {
  const n = dist.length;
  const FULL = (1 << n) - 1;          // all cities visited
  const INF = Infinity;
  // dp[mask][i] = min cost to visit cities in mask, currently at city i
  const dp = Array.from({ length: 1 << n }, () => new Array(n).fill(INF));
  dp[1][0] = 0; // start at city 0, only city 0 visited (mask = 0001)

  for (let mask = 1; mask <= FULL; mask++) {
    for (let i = 0; i < n; i++) {
      if (!(mask & (1 << i))) continue;     // i not in current mask — skip
      if (dp[mask][i] === INF) continue;    // unreachable state

      for (let j = 0; j < n; j++) {
        if (mask & (1 << j)) continue;      // j already visited — skip
        const newMask = mask | (1 << j);
        dp[newMask][j] = Math.min(dp[newMask][j], dp[mask][i] + dist[i][j]);
      }
    }
  }

  // Find minimum cost to visit all cities and return to start
  let ans = INF;
  for (let i = 1; i < n; i++) {
    ans = Math.min(ans, dp[FULL][i] + dist[i][0]);
  }
  return ans;
}
// Time: O(2^n × n²), Space: O(2^n × n)
```

### Section 3: Optimization Techniques

**Q9. What is the "push" vs. "pull" formulation of DP, and when does each apply?**
A: DP transitions can be written in two equivalent directions:

- **Pull formulation** (most common): `dp[i]` is computed by pulling from previously computed states — "what prior state can I come from?" The current state aggregates contributions from states that can reach it.
- **Push formulation**: when computing `dp[i]`, push its value forward to all states that `dp[i]` can contribute to — "what future state can I reach from here?"

```js
// Pull: dp[i] asks "where did I come from?"
// Coin change (min coins) — PULL
for (let amount = 1; amount <= target; amount++) {
  for (const coin of coins) {
    if (amount >= coin && dp[amount - coin] !== Infinity) {
      dp[amount] = Math.min(dp[amount], dp[amount - coin] + 1);
    }
  }
}

// Push: dp[i] says "what can I reach?"
// Coin change (min coins) — PUSH
for (let amount = 0; amount < target; amount++) {
  if (dp[amount] === Infinity) continue;
  for (const coin of coins) {
    if (amount + coin <= target) {
      dp[amount + coin] = Math.min(dp[amount + coin], dp[amount] + 1);
    }
  }
}
```

Pull is more natural when the recurrence naturally describes "how to get to state i." Push is more natural when each state has a clear set of "next states" it can produce — common in BFS-like DP, DAG shortest paths, and game theory DP. Both produce identical results; the choice is about readability and which direction is easier to bound-check.

**Q10. What is "DP with divide-and-conquer optimization," and what recurrence shape enables it?**
A: The divide-and-conquer optimization reduces O(n²) or O(kn²) DP to O(n log n) or O(kn log n) when the recurrence satisfies the **monotone minima** property: the optimal "split point" `opt(i)` is non-decreasing as `i` increases. Formally, for a recurrence `dp[i] = min over j < i of (dp[j] + cost(j, i))`, if `opt(i) ≤ opt(i+1)` for all i, divide-and-conquer on the index range applies.

This appears in: optimal BST construction, certain matrix chain problems, and 1D/1D DP optimizations.

```js
// D&C optimization template
// dp[i] = min over j in [lo_opt, hi_opt] of (dp_prev[j] + cost(j, i))
function solve(dp, dpPrev, lo, hi, optLo, optHi, cost) {
  if (lo > hi) return;
  const mid = (lo + hi) >> 1;
  let best = Infinity, opt = optLo;

  for (let j = optLo; j <= Math.min(mid, optHi); j++) {
    const val = dpPrev[j] + cost(j, mid);
    if (val < best) { best = val; opt = j; }
  }

  dp[mid] = best;
  solve(dp, dpPrev, lo, mid - 1, optLo, opt, cost);   // left half: opt ≤ current opt
  solve(dp, dpPrev, mid + 1, hi, opt, optHi, cost);   // right half: opt ≥ current opt
}
```

**Q11. What is the "Knuth optimization," and what additional condition does it require beyond monotone minima?**
A: The Knuth optimization applies to interval DP recurrences of the form `dp[i][j] = min over i ≤ k < j of (dp[i][k] + dp[k+1][j] + cost(i, j))` — the classic "optimal splitting of a range." Under two conditions — **monotone minima** (`opt(i,j) ≤ opt(i,j+1)`) AND **quadrangle inequality** (`cost(a,c) + cost(b,d) ≤ cost(a,d) + cost(b,c)` for a ≤ b ≤ c ≤ d`) — the optimal split point is bounded: `opt[i][j-1] ≤ opt[i][j] ≤ opt[i+1][j]`. This reduces the interval DP from O(n³) to O(n²).

```js
// Optimal BST, Matrix Chain, Palindrome Partitioning with Knuth optimization
function intervalDP(cost, n) {
  const dp  = Array.from({ length: n }, () => new Array(n).fill(0));
  const opt = Array.from({ length: n }, () => new Array(n).fill(0));

  // Base case: single elements
  for (let i = 0; i < n; i++) opt[i][i] = i;

  // Fill by increasing interval length
  for (let len = 2; len <= n; len++) {
    for (let i = 0; i <= n - len; i++) {
      const j = i + len - 1;
      dp[i][j] = Infinity;
      // Constrain k search using Knuth's bounds
      for (let k = opt[i][j-1]; k <= (j > 0 ? opt[i+1][j] : j); k++) {
        const val = dp[i][k] + dp[k+1][j] + cost(i, j);
        if (val < dp[i][j]) { dp[i][j] = val; opt[i][j] = k; }
      }
    }
  }
  return dp[0][n-1];
}
```

### Section 4: Common Patterns in Detail

**Q12. Walk through the complete thought process for the "longest increasing subsequence" (LIS) problem, from recurrence to optimization.**
A: LIS demonstrates the full DP design process and has three solution tiers — a distinguishing sign of deep understanding.

**Tier 1 — O(n²) DP**: define `dp[i]` = length of longest increasing subsequence ending exactly at index i. Recurrence: `dp[i] = 1 + max(dp[j] for j < i where arr[j] < arr[i])`. Answer: `max(dp[i])`.

**Tier 2 — O(n log n) patience sorting**: maintain a `tails` array where `tails[k]` = smallest tail element of all increasing subsequences of length k+1 seen so far. For each element, binary search for its position in `tails` — replace the first tail ≥ element, or extend `tails` if element is larger than all tails. Length of LIS = length of `tails`.

```js
// O(n²) DP
function lisN2(arr) {
  const n = arr.length;
  const dp = new Array(n).fill(1);      // every element is an LIS of length 1

  for (let i = 1; i < n; i++) {
    for (let j = 0; j < i; j++) {
      if (arr[j] < arr[i]) {
        dp[i] = Math.max(dp[i], dp[j] + 1);
      }
    }
  }
  return Math.max(...dp);
}

// O(n log n) patience sorting
function lisNLogN(arr) {
  const tails = []; // tails[k] = smallest tail of IS of length k+1

  for (const num of arr) {
    // Binary search: find first index in tails where tails[idx] >= num
    let lo = 0, hi = tails.length;
    while (lo < hi) {
      const mid = (lo + hi) >> 1;
      if (tails[mid] < num) lo = mid + 1;
      else hi = mid;
    }
    tails[lo] = num;  // replace or extend
  }
  return tails.length;
}

// Example: arr = [10, 9, 2, 5, 3, 7, 101, 18]
// O(n²) dp: [1, 1, 1, 2, 2, 3, 4, 4] → max = 4
// O(n log n) tails evolution:
//   10:  [10]
//   9:   [9]         (replace 10)
//   2:   [2]         (replace 9)
//   5:   [2,5]       (extend)
//   3:   [2,3]       (replace 5)
//   7:   [2,3,7]     (extend)
//   101: [2,3,7,101] (extend)
//   18:  [2,3,7,18]  (replace 101)
// Length = 4 ✓
```

**Q13. How does the "knapsack" pattern generalize to cover partition, subset sum, and unbounded variants?**
A: The 0/1 knapsack recurrence `dp[i][w] = max(dp[i-1][w], dp[i-1][w-weight[i]] + value[i])` is the template for an entire family of problems. Understanding its variations reveals the pattern:

- **Subset sum** (can we reach exactly target T?): binary values (0/1 knapsack where value = weight = item value, and target capacity = T). `dp[i][t] = dp[i-1][t] || dp[i-1][t-nums[i]]` — boolean instead of max.
- **Count of subsets summing to T**: replace `||` with `+` (count ways instead of existence). `dp[i][t] = dp[i-1][t] + dp[i-1][t-nums[i]]`.
- **Unbounded knapsack** (items reusable): iterate capacity forward (not backward) in the 1D version — `dp[w] = max(dp[w], dp[w-weight[i]] + value[i])` — so earlier updates (using item i) are available for reuse.
- **Partition equal subset sum**: can we split array into two equal-sum halves? Subset sum where T = totalSum / 2.
- **Coin change (min coins)**: unbounded knapsack where value = 1 (minimize coin count) and we want dp[target].
- **Coin change (count ways)**: unbounded knapsack counting ways to reach target. Iterate coins in outer loop, amounts in inner loop — or reverse — depending on whether order matters.

```js
// Subset sum: can we reach exactly T?
function subsetSum(nums, T) {
  const dp = new Array(T + 1).fill(false);
  dp[0] = true; // empty subset sums to 0

  for (const num of nums) {
    for (let t = T; t >= num; t--) { // reverse: 0/1 (each num used at most once)
      dp[t] = dp[t] || dp[t - num];
    }
  }
  return dp[T];
}

// Count ways to make change (order doesn't matter — combinations):
function countWays(coins, target) {
  const dp = new Array(target + 1).fill(0);
  dp[0] = 1; // one way to make 0: use no coins

  for (const coin of coins) {           // outer: coins (each used unlimited times)
    for (let t = coin; t <= target; t++) { // inner: forward (unbounded)
      dp[t] += dp[t - coin];
    }
  }
  return dp[target];
}

// Count ways where ORDER MATTERS (permutations):
function countWaysOrdered(coins, target) {
  const dp = new Array(target + 1).fill(0);
  dp[0] = 1;

  for (let t = 1; t <= target; t++) { // outer: amounts
    for (const coin of coins) {        // inner: coins (order matters → permutations)
      if (t >= coin) dp[t] += dp[t - coin];
    }
  }
  return dp[target];
}
```

**Q14. What is interval DP, and what is the template that covers burst balloons, matrix chain, and palindrome partitioning?**
A: Interval DP solves problems where the answer for a range `[l, r]` depends on answers for sub-ranges. The key insight: the **last operation** performed on the range (the last balloon popped, the last matrix multiplied, the last cut made) becomes the variable `k` in the recurrence. By trying all possible "last operations," the recurrence naturally decomposes the problem.

```js
// Interval DP template:
// dp[l][r] = optimal value for the subproblem on range [l, r]
// Try every possible "split" or "last element" k in [l, r]

// Fill by INCREASING interval length (ensures smaller subproblems solved first)
for (let len = 2; len <= n; len++) {            // interval length
  for (let l = 0; l + len - 1 < n; l++) {      // left boundary
    const r = l + len - 1;                      // right boundary
    dp[l][r] = <worst initial value>;
    for (let k = l; k < r; k++) {               // split point (or last element)
      dp[l][r] = optimal(dp[l][r],
                         dp[l][k] + dp[k+1][r] + <cost of combining>);
    }
  }
}

// Burst Balloons (LeetCode 312):
// dp[l][r] = max coins from bursting all balloons in (l, r) exclusive
// k = the LAST balloon burst in range (l, r) — its neighbors are l and r
// Padding: add sentinel balloons nums[-1]=nums[n]=1
function maxCoins(nums) {
  nums = [1, ...nums, 1];
  const n = nums.length;
  const dp = Array.from({ length: n }, () => new Array(n).fill(0));

  for (let len = 2; len < n; len++) {
    for (let l = 0; l < n - len; l++) {
      const r = l + len;
      for (let k = l + 1; k < r; k++) {
        // k is the LAST balloon burst between l and r (exclusive)
        dp[l][r] = Math.max(dp[l][r],
          dp[l][k] + nums[l] * nums[k] * nums[r] + dp[k][r]);
      }
    }
  }
  return dp[0][n-1];
}
```

**Q15. What is "DP on trees," and what are the two DFS passes it sometimes requires?**
A: Tree DP computes a value for each node based on its children's values, using a post-order DFS (process children before the current node). Many tree DP problems require only **one DFS** (bottom-up): the answer for a subtree is computed as a function of the answers for its children's subtrees.

Some problems require **two DFS passes** (rerooting technique): the first DFS computes values for all subtrees rooted at each node (bottom-up). The second DFS computes, for each node, the value when it becomes the root — incorporating the "upward" contribution from its parent (which was computed for the parent's subtree in the first pass and passed down in the second).

```js
// Tree DP — one pass (bottom-up): diameter of binary tree
function diameterOfBinaryTree(root) {
  let diameter = 0;

  function depth(node) {
    if (!node) return 0;
    const left  = depth(node.left);
    const right = depth(node.right);
    diameter = Math.max(diameter, left + right); // path through this node
    return 1 + Math.max(left, right);            // single-direction depth for parent
  }

  depth(root);
  return diameter;
}

// Tree DP — two passes (rerooting): sum of distances in tree
// First pass: count subtree sizes and distances downward
// Second pass: for each node as root, compute using parent's data
function sumOfDistancesInTree(n, edges) {
  const adj = Array.from({ length: n }, () => []);
  for (const [u, v] of edges) { adj[u].push(v); adj[v].push(u); }

  const count = new Array(n).fill(1); // subtree size
  const ans   = new Array(n).fill(0); // answer for each node as root

  // First DFS: root at 0, compute subtree sizes and downward distances
  function dfs1(node, parent) {
    for (const child of adj[node]) {
      if (child === parent) continue;
      dfs1(child, node);
      count[node] += count[child];
      ans[node] += ans[child] + count[child]; // every node in child's subtree is 1 farther
    }
  }

  // Second DFS: reroot — compute ans for all nodes using parent's answer
  function dfs2(node, parent) {
    for (const child of adj[node]) {
      if (child === parent) continue;
      // When rerooting from node to child:
      // - count[child] nodes get 1 closer (they were 1 farther in node's tree)
      // - n - count[child] nodes get 1 farther
      ans[child] = ans[node] - count[child] + (n - count[child]);
      dfs2(child, node);
    }
  }

  dfs1(0, -1);
  dfs2(0, -1);
  return ans;
}
```

### Section 5: Scenario / Interview-Style Questions

**Q16. "How do you approach a DP problem you've never seen before, step by step?"**
A: A five-step framework that applies to any DP problem:

**Step 1 — Verify DP applies**: does the problem ask for an optimal value (min/max), count of ways, or feasibility (can we achieve X)? Do subproblems overlap? If yes to both, DP likely applies.

**Step 2 — Define the state**: what is `dp[i]` (or `dp[i][j]`, etc.)? State it in a precise English sentence — "dp[i][j] is the minimum cost to convert s1[0..i-1] to s2[0..j-1]." The state definition is the contract that the recurrence must satisfy.

**Step 3 — Write the recurrence**: what choices exist at each state? For each choice, express the result in terms of smaller states. Verify the recurrence satisfies your state definition.

**Step 4 — Identify base cases**: what are the trivially solvable states (empty prefix, zero capacity, single element)? Missing or wrong base cases are the most common source of bugs.

**Step 5 — Determine order and optimize space**: in what order must states be computed so that dependencies are always resolved before they're needed? Can the table be reduced (rolling array, 1D instead of 2D)?

```
Applied to Edit Distance:
Step 1: minimum operations → optimization. Subproblems overlap (dp[i][j] used by dp[i+1][j], etc.) ✓
Step 2: dp[i][j] = min edit distance between s1[0..i-1] and s2[0..j-1].
Step 3: if s1[i-1]===s2[j-1]: dp[i][j] = dp[i-1][j-1]         (no op)
        else: dp[i][j] = 1 + min(dp[i-1][j],   // delete s1[i-1]
                                  dp[i][j-1],   // insert s2[j-1] into s1
                                  dp[i-1][j-1]) // replace s1[i-1] with s2[j-1]
Step 4: dp[i][0] = i (delete all of s1[0..i-1])
        dp[0][j] = j (insert all of s2[0..j-1])
Step 5: dp[i][j] depends on dp[i-1][*] and dp[i][j-1] → fill row by row, left to right.
        Space: only previous row needed → O(n) instead of O(mn).
```

**Q17. "When should you prefer memoization over tabulation in an interview setting?"**
A: Prefer memoization when:
- The recurrence is natural from the problem's recursive structure and tabulation order is non-obvious (e.g., interval DP, tree DP, DAG shortest path with arbitrary topology).
- Only a subset of states are actually reachable from the root problem — memoization avoids computing unreachable states; tabulation computes everything.
- The state space is sparse (e.g., bitmask DP where most masks are unreachable).
- Time pressure in an interview — memoization is easier to write correctly from a recursive brute force by adding a cache.

Prefer tabulation when:
- Space optimization is required (rolling array, 1D knapsack) — tabulation makes it natural; memoization's recursion structure makes it awkward.
- Stack overflow is a concern (very deep recursion).
- The interviewer specifically asks for an iterative solution.

**Q18. "You've written a DP solution. How do you verify the recurrence is correct before coding?"**
A: Three verification techniques:

**Trace a small example by hand**: pick an input small enough to verify manually (2-3 elements). Fill the DP table cell by cell, checking that each value matches what you'd compute by brute force. Any discrepancy reveals a bug in the recurrence or base case.

**Check boundary behavior**: does the recurrence work correctly at the boundaries? For string DP: do i=0 or j=0 cases fall correctly into base cases? For knapsack: does capacity=0 correctly return 0? Boundary bugs account for the majority of DP implementation errors.

**Verify "undo" semantics**: for each recurrence option, can you articulate in plain English what decision it represents? If any option doesn't have a clear real-world meaning (e.g., "take item i when capacity < weight[i]"), the recurrence is wrong.

**Q19. "Explain the difference between counting problems where order matters and where it doesn't — and how this changes the DP implementation."**
A: This is the critical distinction between **combinations** (order doesn't matter) and **permutations** (order matters) in DP counting.

- **Order doesn't matter** (combinations / unordered subsets): iterate items in the outer loop, amounts in the inner loop. Each item is "committed" once — items seen later can't appear before items seen earlier.
- **Order matters** (permutations / sequences): iterate amounts in the outer loop, items in the inner loop. At each amount, all items are considered as possible "last additions" — so [1,2] and [2,1] are counted separately.

```js
// Coin change — how many ways? Coins = [1,2], target = 3
// ORDER DOESN'T MATTER (combinations): [1,1,1], [1,2] → 2 ways
function countCombinations(coins, target) {
  const dp = new Array(target + 1).fill(0);
  dp[0] = 1;
  for (const coin of coins) {          // outer: coins
    for (let t = coin; t <= target; t++) { // inner: amounts
      dp[t] += dp[t - coin];
    }
  }
  return dp[target]; // = 2
}

// ORDER MATTERS (permutations): [1,1,1],[1,2],[2,1] → 3 ways
function countPermutations(coins, target) {
  const dp = new Array(target + 1).fill(0);
  dp[0] = 1;
  for (let t = 1; t <= target; t++) {  // outer: amounts
    for (const coin of coins) {        // inner: coins (all considered at each amount)
      if (t >= coin) dp[t] += dp[t - coin];
    }
  }
  return dp[target]; // = 3
}
```

**Q20. "What are the top five DP implementation bugs, and how do you avoid each?"**
A:

**Bug 1 — Wrong base case**: setting `dp[0] = 0` when it should be `dp[0] = 1` (or vice versa) poisons every value that depends on it. Fix: explicitly trace what the base case means (empty string, zero items, zero capacity) and set it to match.

**Bug 2 — Wrong iteration order in knapsack**: iterating the capacity dimension forward for 0/1 knapsack allows the same item to be used multiple times (unbounded behavior). Fix: always iterate capacity backward for 0/1 knapsack; forward for unbounded.

**Bug 3 — Off-by-one in array sizing**: `dp = new Array(n)` has valid indices 0..n-1; if you need `dp[n]`, you need `new Array(n+1)`. Fix: size the array to max_index + 1.

**Bug 4 — Incorrect initialization for min/max problems**: initializing `dp[i] = 0` when looking for a minimum causes the minimum to always be 0 (a smaller value than any real answer). Fix: initialize with `Infinity` for min problems, `-Infinity` for max problems, except for true base cases.

**Bug 5 — Missing "impossible" sentinel propagation**: in min-coin-change, if `dp[amount - coin]` is `Infinity` (that amount is unreachable), then `dp[amount - coin] + 1` overflows or produces a wrong value. Fix: check `dp[prev] !== Infinity` before using it, or handle with a specific "impossible" sentinel that propagates correctly.

**Q21. "How do you reconstruct the actual optimal solution (not just its value) from a DP table?"**
A: DP tables store optimal values but not the decisions that produced them. Reconstructing the path requires one of two approaches:

**Approach 1 — Trace back through the recurrence**: after filling the DP table, start from the final state and determine which "branch" of the recurrence was taken at each step — work backward until reaching a base case. This requires knowing the recurrence transitions, but no extra storage.

**Approach 2 — Store decisions in a separate table**: during the forward pass, maintain a `choice` or `parent` table that records which decision was made at each state. Reconstruct by following `choice` pointers from the final state to a base case.

```js
// Edit Distance — path reconstruction via backtracking
function editDistanceWithPath(s1, s2) {
  const m = s1.length, n = s2.length;
  const dp = Array.from({ length: m+1 }, () => new Array(n+1).fill(0));

  for (let i = 0; i <= m; i++) dp[i][0] = i;
  for (let j = 0; j <= n; j++) dp[0][j] = j;

  for (let i = 1; i <= m; i++) {
    for (let j = 1; j <= n; j++) {
      if (s1[i-1] === s2[j-1]) {
        dp[i][j] = dp[i-1][j-1];
      } else {
        dp[i][j] = 1 + Math.min(dp[i-1][j], dp[i][j-1], dp[i-1][j-1]);
      }
    }
  }

  // Backtrack to find operations
  const ops = [];
  let i = m, j = n;
  while (i > 0 || j > 0) {
    if (i > 0 && j > 0 && s1[i-1] === s2[j-1]) {
      i--; j--; // no operation
    } else if (i > 0 && j > 0 && dp[i][j] === dp[i-1][j-1] + 1) {
      ops.push(`Replace s1[${i-1}]='${s1[i-1]}' with '${s2[j-1]}'`); i--; j--;
    } else if (i > 0 && dp[i][j] === dp[i-1][j] + 1) {
      ops.push(`Delete s1[${i-1}]='${s1[i-1]}'`); i--;
    } else {
      ops.push(`Insert '${s2[j-1]}' into s1`); j--;
    }
  }

  return { distance: dp[m][n], operations: ops.reverse() };
}
```

## Problem 1 — Climbing Stairs / Coin Change

### Problem
**Part A**: You can climb 1 or 2 steps at a time. How many distinct ways can you reach step n?

**Part B**: Given coin denominations and a target amount, find the minimum number of coins needed. Return -1 if impossible.

```
Part A: n=5 → 8 ways
Part B: coins=[1,5,6,9], amount=11 → 3 coins (5+5+1 or 6+5... actually: 9+1+1=3? no. Let's check: 5+6=11=2 coins ✓)
        coins=[2], amount=3 → -1 (impossible)
```

### Pattern Recognition
Linear DP — `dp[i]` depends on a small, fixed number of preceding entries. Part A is pure Fibonacci. Part B is the canonical "min coins" problem showing how the same template extends to arbitrary choices and minimization.

### Key Insight
Part A: the number of ways to reach step n equals the sum of ways to reach step n-1 (take 1 step) and ways to reach step n-2 (take 2 steps) — exactly Fibonacci. Part B: the minimum coins to make `amount` equals 1 plus the minimum coins to make `amount - coin`, minimized over all valid coins — the recurrence captures "choose the last coin used."

### Approach
Part A: `dp[i] = dp[i-1] + dp[i-2]`. Base cases: `dp[0]=1` (one way to stand at bottom — do nothing), `dp[1]=1`. Space-optimize to two variables.

Part B: `dp[amount] = 1 + min(dp[amount - coin])` over all coins where `amount >= coin` and `dp[amount - coin] !== Infinity`. Initialize `dp[0]=0`, all others `Infinity`. Return `dp[target] === Infinity ? -1 : dp[target]`.

### Solution

```js
// Part A — Climbing Stairs
function climbStairs(n) {
  if (n <= 1) return 1;
  let prev2 = 1, prev1 = 1; // dp[0]=1, dp[1]=1
  for (let i = 2; i <= n; i++) {
    const curr = prev1 + prev2;
    prev2 = prev1;
    prev1 = curr;
  }
  return prev1;
}

// Part B — Coin Change (minimum coins)
function coinChange(coins, amount) {
  // dp[a] = minimum coins needed to make amount a
  const dp = new Array(amount + 1).fill(Infinity);
  dp[0] = 0; // 0 coins needed to make amount 0

  for (let a = 1; a <= amount; a++) {
    for (const coin of coins) {
      if (a >= coin && dp[a - coin] !== Infinity) {
        dp[a] = Math.min(dp[a], dp[a - coin] + 1);
      }
    }
  }

  return dp[amount] === Infinity ? -1 : dp[amount];
}
```

## Problem 2 — Longest Common Subsequence

### Problem
Given two strings, return the length of their longest common subsequence (a subsequence is obtained by deleting some characters without changing the order of remaining characters).

```
Input: s1="abcde", s2="ace"
Output: 3 (LCS: "ace")

Input: s1="abc", s2="abc"
Output: 3

Input: s1="abc", s2="def"
Output: 0
```

### Pattern Recognition
String DP with two-pointer state `dp[i][j]` — the canonical two-sequence DP problem. The recurrence branches on whether the current characters match, making it the foundation for edit distance, diff utilities, and DNA sequence alignment.

### Key Insight
`dp[i][j]` is defined as the LCS length of `s1[0..i-1]` and `s2[0..j-1]`. If the last characters match (`s1[i-1] === s2[j-1]`), they must both appear in the LCS — extend from `dp[i-1][j-1]`. If they don't match, the LCS either excludes the last character of s1 (`dp[i-1][j]`) or s2 (`dp[i][j-1]`) — take the max of both.

### Approach
Fill a `(m+1) × (n+1)` table row by row. Base cases: first row and column are all 0 (LCS of anything with empty string is 0). Space-optimize to two 1D arrays (previous row and current row).

### Solution

```js
function longestCommonSubsequence(s1, s2) {
  const m = s1.length, n = s2.length;

  // Space-optimized: only keep previous row
  let prev = new Array(n + 1).fill(0);

  for (let i = 1; i <= m; i++) {
    const curr = new Array(n + 1).fill(0);
    for (let j = 1; j <= n; j++) {
      if (s1[i-1] === s2[j-1]) {
        curr[j] = prev[j-1] + 1;               // characters match: extend diagonal
      } else {
        curr[j] = Math.max(prev[j], curr[j-1]); // no match: best of up or left
      }
    }
    prev = curr;
  }

  return prev[n];
}
```

- Time: O(m × n) — fill every cell of the table.
- Space: O(n) with rolling array (O(m × n) for full table).

### Edge Cases
- Either string empty: all `dp[0][j]` and `dp[i][0]` are 0 — base cases; loop produces all 0s; returns 0. ✓
- Identical strings: every diagonal match fires; returns `min(m, n)` = string length. ✓
- No common characters: no matches anywhere; all values stay 0; returns 0. ✓

### Follow-up Questions
- "Can you reconstruct the actual LCS?" → Keep the full 2D table; backtrack from `dp[m][n]`: if characters matched, go diagonal and record the character; if not, go to the larger of `dp[i-1][j]` and `dp[i][j-1]`.
- "How does this relate to edit distance?" → Edit distance adds insertion and deletion costs (and replacement) to the LCS framework. LCS counts matches; edit distance minimizes the total operations to convert one string to the other — the same two-pointer state, a slightly richer recurrence.

## Problem 3 — 0/1 Knapsack / Partition Equal Subset Sum

### Problem
**Part A (0/1 Knapsack)**: Given weights and values for n items and a capacity W, find the maximum total value of items that fit (each item used at most once).

**Part B (Partition Equal Subset Sum)**: Given an array of positive integers, determine if it can be partitioned into two subsets with equal sums.

```
Part A: weights=[1,3,4,5], values=[1,4,5,7], W=7 → 9 (items 2+3: weight=3+4=7, value=4+5=9)
Part B: nums=[1,5,11,5] → true ([1,5,5] and [11])
        nums=[1,2,3,5]  → false
```

### Pattern Recognition
0/1 Knapsack — binary choice (take or skip each item) with a capacity constraint. Part B is a reduction to subset sum, which is itself a special case of knapsack (value = weight, target T = totalSum/2).

### Key Insight
Part A: `dp[w]` = max value achievable with exactly capacity w. For each item, consider "take it" (requires w ≥ weight[i], adds value[i] to the solution for capacity w - weight[i]) or "skip it" (current dp[w] unchanged). Iterating capacity **backward** ensures each item is considered at most once (if we went forward, a just-updated dp[w - weight[i]] could already include item i).

Part B: target T = totalSum / 2 (if totalSum is odd, immediately false). Reduce to: "can we find a subset summing to T?" — boolean knapsack with the same backward iteration.

### Approach
1D dp array, items in outer loop, capacity (or target) in inner loop **backward from max to item's weight**.

### Solution

```js
// Part A — 0/1 Knapsack
function knapsack(weights, values, W) {
  const dp = new Array(W + 1).fill(0); // dp[w] = max value with capacity w

  for (let i = 0; i < weights.length; i++) {
    // Iterate BACKWARD: ensures item i used at most once
    for (let w = W; w >= weights[i]; w--) {
      dp[w] = Math.max(
        dp[w],                              // skip item i
        dp[w - weights[i]] + values[i]     // take item i
      );
    }
  }
  return dp[W];
}

// Part B — Partition Equal Subset Sum
function canPartition(nums) {
  const total = nums.reduce((s, n) => s + n, 0);
  if (total % 2 !== 0) return false; // odd total: impossible

  const target = total / 2;
  const dp = new Array(target + 1).fill(false);
  dp[0] = true; // empty subset sums to 0 — always achievable

  for (const num of nums) {
    // Backward: each num used at most once
    for (let t = target; t >= num; t--) {
      dp[t] = dp[t] || dp[t - num]; // can we reach t by including num?
    }
  }
  return dp[target];
}
```

```
  t=1: dp[1] = dp[1]||dp[0] = F||T = T

  t=11: dp[11] = dp[11]||dp[6] = F||F = F

  t=6:  dp[6]  = dp[6]||dp[1]  = F||T = T

(Subset {11} sums to 11; subset {1,5,5} sums to 11)
```

### Complexity
- Part A: O(n × W) time, O(W) space.
- Part B: O(n × target) = O(n × sum/2) time, O(sum/2) space.

### Edge Cases
- Part A, W=0: inner loop condition `w >= weights[i]` never true; dp[0]=0 returned. ✓
- Part B, single element: if num == target, dp[target] becomes true. ✓
- Part B, all elements equal and even count: e.g., [2,2,2,2] → target=4, achievable with two 2s. ✓
- Part B, total is odd: immediate false return before any DP. ✓
- Backward iteration critical: if forward, num=5 with dp[5]=T would set dp[10]=T using the same num=5, incorrectly allowing 5+5 from one element. ✓

### Follow-up Questions
- "What if each item can be used unlimited times (unbounded knapsack)?" → Iterate capacity **forward** instead of backward. The update `dp[w] = max(dp[w], dp[w-weight[i]] + value[i])` with forward iteration allows item i to be used multiple times (dp[w - weight[i]] may already include item i).
- "What if items can be grouped — take all or none from each group?" → Group knapsack: for each group, iterate capacity backward and try all group members at the current capacity — take the best item from the group (or none).

## Problem 4 — Longest Palindromic Subsequence / Minimum Insertions

### Problem
**Part A**: Given a string s, return the length of its longest palindromic subsequence.

**Part B**: Given a string s, return the minimum number of insertions needed to make s a palindrome.

```
Part A: s="bbbab" → 4 ("bbbb")
        s="cbbd"  → 2 ("bb")

Part B: s="mbadm" → 2 (insert 'a' and 'd' → "mabdabm" or "mdaadm"... actually "mbdadm"? Let's use the standard: "mabdam"=no. Answer is 2.)
```

### Pattern Recognition
Interval DP on a single string — `dp[l][r]` represents the answer for the substring `s[l..r]`. Part B reduces directly to Part A: minimum insertions = n - LPS length.

### Key Insight
Part A: if `s[l] === s[r]`, they form the endpoints of a palindrome, contributing 2 + the best palindrome inside (`dp[l+1][r-1]`). If they don't match, the LPS either excludes `s[l]` or excludes `s[r]` — take the max of `dp[l+1][r]` and `dp[l][r-1]`. Base cases: single characters have LPS length 1.

Part B: the key insight is that `n - LPS(s)` gives the minimum insertions. To make s a palindrome, you can reverse s and find LCS(s, reverse(s)) = LPS(s) — the characters NOT in the LPS need counterparts inserted. Alternatively, solve interval DP directly: if `s[l]===s[r]`, no insertion needed at boundaries; if not, insert one character to match either end.

### Solution

```js
// Part A — Longest Palindromic Subsequence (interval DP)
function longestPalindromeSubseq(s) {
  const n = s.length;
  // dp[l][r] = LPS length of s[l..r]
  const dp = Array.from({ length: n }, () => new Array(n).fill(0));

  // Base case: single characters
  for (let i = 0; i < n; i++) dp[i][i] = 1;

  // Fill by increasing interval length
  for (let len = 2; len <= n; len++) {
    for (let l = 0; l + len - 1 < n; l++) {
      const r = l + len - 1;
      if (s[l] === s[r]) {
        dp[l][r] = (len === 2 ? 0 : dp[l+1][r-1]) + 2; // both endpoints contribute
      } else {
        dp[l][r] = Math.max(dp[l+1][r], dp[l][r-1]); // exclude one endpoint
      }
    }
  }
  return dp[0][n-1];
}

// Part B — Minimum Insertions to Make Palindrome
// Method 1: reduction to LPS (simplest)
function minInsertions(s) {
  return s.length - longestPalindromeSubseq(s);
}

// Method 2: direct interval DP (shows the recurrence explicitly)
function minInsertionsDirect(s) {
  const n = s.length;
  const dp = Array.from({ length: n }, () => new Array(n).fill(0));
  // dp[l][r] = min insertions to make s[l..r] a palindrome
  // Base: single chars need 0 insertions; length 0 intervals: 0

  for (let len = 2; len <= n; len++) {
    for (let l = 0; l + len - 1 < n; l++) {
      const r = l + len - 1;
      if (s[l] === s[r]) {
        dp[l][r] = (len === 2 ? 0 : dp[l+1][r-1]); // matching ends: no insertion at boundary
      } else {
        dp[l][r] = 1 + Math.min(dp[l+1][r], dp[l][r-1]); // insert to match l or r
      }
    }
  }
  return dp[0][n-1];
}
```

### Dry Run

```
Part A: s = "bbbab" (n=5)

Base: dp[i][i]=1 for all i.

len=2:
  dp[0][1]: 'b'==='b' → dp[0][1]=0+2=2
  dp[1][2]: 'b'==='b' → 2
  dp[2][3]: 'b'==='a' → max(dp[3][3],dp[2][2])=max(1,1)=1
  dp[3][4]: 'a'==='b' → max(dp[4][4],dp[3][3])=max(1,1)=1

len=3:
  dp[0][2]: 'b'==='b' → dp[1][1]+2=1+2=3
  dp[1][3]: 'b'==='a' → max(dp[2][3],dp[1][2])=max(1,2)=2
  dp[2][4]: 'b'==='b' → dp[3][3]+2=1+2=3

len=4:
  dp[0][3]: 'b'==='a' → max(dp[1][3],dp[0][2])=max(2,3)=3
  dp[1][4]: 'b'==='b' → dp[2][3]+2=1+2=3

len=5:
  dp[0][4]: 'b'==='b' → dp[1][3]+2=2+2=4

Return dp[0][4] = 4 ✓ ("bbbb" is the longest palindromic subsequence)
```

### Complexity
- Time: O(n²) — fill every (l, r) pair; O(n) work per pair in the basic version.
- Space: O(n²) for the table. Can be reduced to O(n) with a rolling two-rows approach.

### Edge Cases
- Single character: `dp[0][0]=1`; loop for len>=2 never fires; returns 1. ✓
- All same characters: every `s[l]===s[r]`; LPS = n; min insertions = 0. ✓
- No repeated characters (all distinct): LPS = 1 (any single character is a palindrome of length 1); min insertions = n-1. ✓
- len=2, matched characters: `dp[l+1][r-1]` = `dp[l+1][l]` — an invalid range (l+1 > l = r-1 when len=2). Handle with `len === 2 ? 0 : dp[l+1][r-1]`. ✓

### Follow-up Questions
- "What's the difference between longest palindromic subsequence and longest palindromic substring?" → Subsequence: gaps allowed, interval DP, O(n²). Substring: contiguous, can use expand-around-center O(n²) or Manacher's O(n) — no DP needed. Subsequence is generally harder.
- "Can you solve this without interval DP by reducing to LCS?" → LPS(s) = LCS(s, reverse(s)). This is a clean reduction: the reversed string has the same characters; their LCS must be palindromic (matching forward and backward). O(n²) time and space, same complexity.

## Problem 5 — Word Break

### Problem
Given a string `s` and a dictionary of strings `wordDict`, return true if `s` can be segmented into a space-separated sequence of one or more dictionary words.

```
Input: s="leetcode", wordDict=["leet","code"]
Output: true ("leet" + "code")

Input: s="applepenapple", wordDict=["apple","pen"]
Output: true ("apple"+"pen"+"apple")

Input: s="catsandog", wordDict=["cats","dog","sand","and","cat"]
Output: false
```

### Pattern Recognition
Linear DP with string matching — `dp[i]` = can we segment `s[0..i-1]` using dictionary words? At each position, try all possible last words ending at position i. This is the "unbounded" variant (words can be reused) of a linear DP.

### Key Insight
`dp[i]` is true if there exists some `j < i` such that `dp[j]` is true AND `s[j..i-1]` is in the dictionary. We're looking backward from position i for any valid "last word" that bridges a valid prefix (dp[j]=true) to the current position. The Set lookup for the word makes this O(1) per candidate split.

### Approach
Build a Set from `wordDict` for O(1) lookup. `dp[0]=true` (empty string is trivially segmented). For each position i from 1 to n, try every j from 0 to i-1: if `dp[j]` is true and `s.slice(j, i)` is in the dictionary, set `dp[i]=true` and break.

### Solution

```js
function wordBreak(s, wordDict) {
  const n = s.length;
  const wordSet = new Set(wordDict);
  const maxLen = Math.max(...wordDict.map(w => w.length)); // optimization: limit j range

  // dp[i] = true if s[0..i-1] can be segmented using wordDict
  const dp = new Array(n + 1).fill(false);
  dp[0] = true; // empty prefix is trivially valid

  for (let i = 1; i <= n; i++) {
    // Try every possible last word s[j..i-1]
    for (let j = Math.max(0, i - maxLen); j < i; j++) {
      if (dp[j] && wordSet.has(s.slice(j, i))) {
        dp[i] = true;
        break; // found a valid segmentation ending at i — no need to try more j's
      }
    }
  }

  return dp[n];
}
```

### Dry Run

```
s="leetcode" (n=8), wordDict=["leet","code"], wordSet={"leet","code"}, maxLen=4

dp = [T, F, F, F, F, F, F, F, F]  (indices 0..8)

i=1: j=0: dp[0]=T, s[0..0]="l"? not in set. dp[1]=F.
i=2: j=0: "le"? no. j=1: dp[1]=F→skip. dp[2]=F.
i=3: j=0: "lee"? no. dp[3]=F.
i=4: j=0: dp[0]=T, "leet"? YES → dp[4]=T, break.
  dp = [T,F,F,F,T,F,F,F,F]

i=5: j=1..4. j=4: dp[4]=T, s[4..4]="c"? no. Others: dp[j]=F. dp[5]=F.
i=6: j=2..5. j=4: dp[4]=T, s[4..5]="co"? no. dp[6]=F.
i=7: j=3..6. j=4: dp[4]=T, s[4..6]="cod"? no. dp[7]=F.
i=8: j=4..7. j=4: dp[4]=T, s[4..7]="code"? YES → dp[8]=T, break.

Return dp[8] = true ✓
```

### Complexity
- Time: O(n × maxLen) with the maxLen optimization (O(n²) without it). The `s.slice(j,i)` call is O(word_length) — technically O(n × maxLen²) for slice cost; use string comparison tricks or trie to reduce.
- Space: O(n) for the dp array, O(total chars in dict) for the Set.

### Edge Cases
- Empty string: `dp[0]=true`; loop never runs; returns `dp[0]=true`. Typically the problem guarantees s is non-empty, but good to know. ✓
- No valid segmentation: all dp entries remain false except dp[0]; returns `dp[n]=false`. ✓
- Word reuse: "applepenapple" uses "apple" twice — the unbounded nature (j iterates all valid prefixes) handles this naturally. ✓
- Single-character words: maxLen=1; j range is [i-1, i-1] — only the previous position checked each step. ✓
- `s.slice(j, i)` is in dictionary but `dp[j]` is false: correctly skipped — both conditions must hold. ✓

### Follow-up Questions
- "What if you need to return all valid segmentations, not just feasibility?" → Replace `dp[i]: boolean` with `dp[i]: string[][]` — store all valid segmentations ending at position i. Or use backtracking with memoization: `memo[i]` = all segmentations of `s[i..n-1]`. O(2^n) worst case for results, but memoization ensures each position is processed once.
- "How would a Trie improve this?" → Build a Trie from the dictionary. At each position i, walk the Trie forward from i — each time you reach a word end and `dp[i]` is true, mark `dp[i + word.length]`. This avoids the slice and Set lookup overhead, running in O(n × maxLen) with better constants.

```
│   ├── "can we achieve" some condition (feasibility)
│   └── Overlapping subproblems (same subproblem appears in multiple recursive calls)

│

│   │
│   ├── ONE sequence, one pointer, dp[i] depends on dp[i-1] (or dp[i-k]):
│   │   └── LINEAR DP: climbing stairs, house robber, coin change, LIS (O(n²))
│   │         Recurrence: dp[i] = f(dp[i-1], dp[i-2], ..., dp[i-k])
│   │
│   ├── TWO sequences (or one sequence vs. itself):
│   │   └── STRING DP: LCS, edit distance, LPS, regex matching
│   │         State: dp[i][j] for s1[0..i-1] vs s2[0..j-1]
│   │         Recurrence branches on s1[i-1] === s2[j-1]
│   │
│   ├── 2D GRID, move right/down only:
│   │   └── GRID DP: unique paths, min path sum, dungeon game
│   │         State: dp[r][c] = answer reaching cell (r,c)
│   │         Recurrence: dp[r][c] = f(dp[r-1][c], dp[r][c-1])
│   │
│   ├── BINARY CHOICE (take/skip) with capacity:
│   │   └── KNAPSACK DP:
│   │         0/1: backward iteration. dp[w] = max(dp[w], dp[w-wt]+val)
│   │         Unbounded: forward iteration. Same recurrence.
│   │         Subset sum: boolean version. Partition: reduce to subset sum.
│   │         Count ways: sum instead of max/min.
│   │
│   ├── "BEST WAY TO SPLIT or PARENTHESIZE a range [l, r]":
│   │   └── INTERVAL DP: burst balloons, matrix chain, LPS, palindrome partition
│   │         State: dp[l][r] for subarray s[l..r]
│   │         Fill by INCREASING interval length (len=2,3,...,n)
│   │         Recurrence: try all split points k in [l, r]
│   │
│   ├── TREE / subtree structure:
│   │   └── TREE DP: diameter, max path sum, house robber III
│   │         Post-order DFS: compute for children before parent
│   │         Global variable for "arch" problems (value uses both children)
│   │         Rerooting (two DFS passes) for "each node as root" problems
│   │
│   └── SUBSET of a SMALL set (n ≤ 20):
│         └── BITMASK DP: TSP, assignment problems, min cost to visit all states
│               State: dp[mask][i] — which elements used, current position
│               O(2^n × n) time, O(2^n × n) space
│
├── IMPLEMENTATION CHECKLIST:
│   1. Define dp[i] (or dp[i][j]) precisely in English
│   2. Write recurrence: what choices exist? How do smaller answers combine?
│   3. Set base cases explicitly (dp[0], dp[i][0], dp[0][j])
│   4. Determine fill order (small→large, left→right, short interval→long)
│   5. Space-optimize if needed (rolling array, 1D for 2D knapsack)
│   6. Reconstruct path if needed (backtrack through table or store choices)
│
└── COMPLEXITY REFERENCE:
      Linear DP:   O(n) or O(n×k) time, O(n) or O(1) space
      String DP:   O(mn) time, O(min(m,n)) space (rolling row)
      Grid DP:     O(rows×cols) time, O(cols) space (rolling row)
```

## Common Bugs Checklist

Before submitting any DP solution, verify:

1. **State definition stated precisely in English before writing code?** — "dp[i] is the maximum profit using the first i items" is unambiguous. "dp[i] is the best answer at i" is not — it doesn't specify whether i is included, whether it's 0-indexed or 1-indexed, or what "at" means. An imprecise definition leads to recurrences that are technically consistent with the definition but wrong for the problem.

2. **Base cases explicitly set and correctly valued?** — `dp[0]` for linear DP, first row and column for 2D DP, single-element diagonals for interval DP. The most common bug: `dp[0]=0` when it should be `dp[0]=1` (counting problems: there is one way to achieve a sum of 0 — use no elements). Trace the base case meaning before coding.

3. **Infinity initialized for minimization problems, NOT 0?** — `new Array(n).fill(0)` for a minimum problem means every achievable amount appears to cost 0, making the minimum always 0. Use `Infinity` (or a large sentinel like `n + 1`). Then check `dp[prev] !== Infinity` before using it. For maximization, initialize non-base-case entries with `-Infinity` or `0` depending on whether negative values are possible.

4. **Knapsack inner loop direction correct (backward for 0/1, forward for unbounded)?** — Backward iteration ensures each item is used at most once (the "not yet updated by item i" values are to the right, which we've already passed). Forward iteration allows reuse. Swapping them produces silent wrong answers that pass most test cases but fail on inputs where an item could be used twice.

5. **Interval DP fills by INCREASING interval length (not by left boundary alone)?** — Filling by left boundary (i from 0 to n) processes dp[0][4] before dp[1][3] — which dp[0][4] may depend on — violating the dependency order. Always iterate `len` from 2 to n in the outer loop, then i (left boundary) in the inner loop.

6. **Two-pass string DP (like equality equations): ALL unions/matches processed before ANY contradiction checks?** — Processing interleaved means a contradiction check runs before all relationships are established, missing transitively implied equalities. Always complete all "building" passes before all "checking" passes.

7. **`s.slice(j, i)` (or equivalent substring) correctly extracts s[j..i-1] (not s[j..i])?** — In JavaScript, `s.slice(j, i)` returns characters at indices j, j+1, ..., i-1. Off-by-one here silently shifts every word match by one character, producing entirely wrong results that are hard to debug from the output.

8. **Reconstruction backtrack starts from the correct final state and uses the correct branching order?** — When multiple branches of the recurrence tie (e.g., dp[i-1][j] === dp[i][j-1] in LCS), the backtrack must consistently pick one branch and follow it to a base case. Switching branches mid-backtrack produces a garbled path. Also: backtrack from `dp[m][n]` (the final answer cell), NOT from `dp[0][0]` (that's forward reconstruction, which requires a different traversal).

9. **Bitmask DP: `mask & (1 << i)` checks membership before accessing dp[mask][i], and `mask | (1 << j)` for the new state (not XOR)?** — Using XOR (`mask ^ (1 << j)`) instead of OR (`mask | (1 << j)`) toggles the bit — if j was already in the mask, XOR would remove it, silently producing an invalid previous state. Always use OR to add a bit to the mask.

10. **Space-optimized rolling array doesn't read a value that was just overwritten?** — In 2D→1D rolling: `dp[j] = dp[j-1] + 1` can overwrite `dp[j]` which a future cell in the same row still needs as the "left neighbor." Use a temporary variable `prev = dp[j-1]` before updating, or process right-to-left when the recurrence reads from "right and above." The direction of safe iteration depends on which prior values the recurrence needs.

**Final Tip:** At the 5–7 YOE level, the interview signal is the ability to name the archetype immediately ("this is interval DP — I'll fill by increasing length with a split-point loop"), state the recurrence in one sentence before touching code, and identify the space optimization without being asked. The weakest candidates code a working O(mn) solution in the full 2D table; mid-level candidates know to reduce space; senior candidates proactively explain why the state is minimal (Markov property), what the base cases encode semantically, and how to reconstruct the actual solution — not just its value. The distinction between ordered and unordered counting (coin permutations vs. combinations — Q19's inner/outer loop swap) is a specific senior-level signal that many candidates get wrong even after passing easier DP problems.
