## Topic A: Longest Common Subsequence

### Section A1: Fundamentals

**Q1. What is a subsequence, and what distinguishes LCS from longest common substring?**

A: A **subsequence** is a sequence derived from another by deleting zero or more elements *without changing the relative order of the remaining elements* — the selected characters do not need to be contiguous. A **substring** (or subarray) requires the selected characters to be contiguous. `"ace"` is a subsequence of `"abcde"` (positions 0, 2, 4); `"bcd"` is both a substring and a subsequence. The distinction drives completely different DP formulations. LCS allows a gap between matched characters in either string; longest common substring requires both characters to be matched in an unbroken run. When a mismatch occurs in LCS, we carry forward the best result from dropping one character on either side (`max(dp[i-1][j], dp[i][j-1])`). In longest common substring, a mismatch *resets* the current run to zero.

```
s1 = "abcde", s2 = "ace"

LCS ("ace", length 3):   a _ c _ e   (gaps allowed between matched chars)
                          ↑   ↑   ↑

Longest common SUBSTRING ("a", length 1): only single characters are shared
  contiguous in BOTH strings at the same time.
  "ab" ∩ "ac" → 'a' is common at pos 0 of both, but not a shared 2-char run.
```

**Q2. What is the optimal substructure of LCS, and why does the recurrence split exactly two ways?**

A: The LCS problem has optimal substructure: the LCS of two strings can be derived from the LCS of their shorter prefixes. The recurrence splits into exactly two cases based on whether the *last characters* of the two current prefixes match. **Case 1 — match**: if `s1[i-1] == s2[j-1]`, then `dp[i][j] = dp[i-1][j-1] + 1`. The critical claim: these matching characters *must* appear in the LCS — we never do better by skipping them. Why? Any LCS that skips `s1[i-1]` has length at most `LCS(s1[0..i-2], s2[0..j-1])` ≤ `LCS(s1[0..i-2], s2[0..j-2])` ≤ LCS(without the matching char). Including the match gives `1 + LCS(s1[0..i-2], s2[0..j-2])`, which is at least as large — so taking the match is always optimal when characters are equal. **Case 2 — mismatch**: if `s1[i-1] ≠ s2[j-1]`, both cannot be in the LCS simultaneously (they would need to be matched to the same position). The LCS must be found within either `s1[0..i-2]` with all of `s2[0..j-1]` (skip s1's last character) or all of `s1[0..i-1]` with `s2[0..j-2]` (skip s2's last character): `dp[i][j] = max(dp[i-1][j], dp[i][j-1])`.

**Q3. What does `dp[i][j]` represent, and what are the three components of the recurrence?**

A: `dp[i][j]` = the length of the longest common subsequence of the first `i` characters of `s1` and the first `j` characters of `s2` (i.e., `s1[0..i-1]` and `s2[0..j-1]`). The 1-indexed convention avoids special-casing the boundary: the base case `dp[0][*] = dp[*][0] = 0` represents an empty prefix having LCS length 0 with anything.

```
Recurrence:
  if s1[i-1] == s2[j-1]:    dp[i][j] = dp[i-1][j-1] + 1
  else:                       dp[i][j] = max(dp[i-1][j], dp[i][j-1])

   ""  a  b  c
""  0  0  0  0
a   0  1  1  1      dp[1][1]: s1[0]='a'==s2[0]='a' → dp[0][0]+1 = 1
b   0  1  2  2      dp[2][2]: s1[1]='b'==s2[1]='b' → dp[1][1]+1 = 2
c   0  1  2  3      dp[3][3]: s1[2]='c'==s2[2]='c' → dp[2][2]+1 = 3

s1="abc", s2="abc" → LCS = 3 ✓
```

**Q4. How is the DP table traversed, and what does reconstruction backtracking look like?**

A: Fill the table row by row, left to right, top to bottom — each cell only depends on cells to its upper-left, upper, and left. Reconstruction: start at `(m, n)` and trace backward to `(0, 0)`, collecting characters: if `s1[i-1] == s2[j-1]`, the character is in the LCS — collect `s1[i-1]` and move to `(i-1, j-1)`; if `dp[i-1][j] > dp[i][j-1]`, the LCS came from skipping `s1[i-1]` — move to `(i-1, j)`; otherwise move to `(i, j-1)`. Characters are collected in reverse order (the last LCS character is found first during backtracking from `(m,n)`), so reverse the collected list at the end.

```js
function lcs(s1, s2) {
  const m = s1.length, n = s2.length;
  const dp = Array.from({ length: m+1 }, () => new Array(n+1).fill(0));

  for (let i = 1; i <= m; i++)
    for (let j = 1; j <= n; j++)
      dp[i][j] = s1[i-1] === s2[j-1]
        ? dp[i-1][j-1] + 1                     // match: take both characters
        : Math.max(dp[i-1][j], dp[i][j-1]);    // mismatch: skip one side

  // Reconstruction: backtrack from (m, n) to (0, 0)
  let i = m, j = n;
  const result = [];
  while (i > 0 && j > 0) {
    if (s1[i-1] === s2[j-1])   { result.push(s1[i-1]); i--; j--; }
    else if (dp[i-1][j] > dp[i][j-1]) i--;
    else                        j--;
  }
  return result.reverse().join(''); // reverse: collected back-to-front
}
```

**Q5. How is LCS space reduced from O(mn) to O(min(m,n)), and what does the rolling-row technique sacrifice?**

A: Each row of the DP table depends only on the *previous row* (`dp[i-1][*]`) — the full table is unnecessary. Keep two arrays: `prev` (previous row) and `curr` (current row). After computing each row, assign `prev = curr`. This reduces space from O(mn) to O(n). Choosing the shorter string as `s2` further reduces to O(min(m,n)). What is sacrificed: reconstruction requires the full table. With the rolling-row optimization, reconstruction is impossible from the compressed state alone. If reconstruction is needed, either store the full table (O(mn) space) or use the Hirschberg algorithm (O(min(m,n)) space reconstruction via divide-and-conquer, O(mn) time).

```js
function lcsLength(s1, s2) {
  if (s1.length < s2.length) [s1, s2] = [s2, s1]; // ensure s2 is shorter
  const n = s2.length;
  let prev = new Array(n+1).fill(0);

  for (const c1 of s1) {
    const curr = new Array(n+1).fill(0);
    for (let j = 1; j <= n; j++)
      curr[j] = c1 === s2[j-1]
        ? prev[j-1] + 1
        : Math.max(prev[j], curr[j-1]); // prev[j] = dp[i-1][j]; curr[j-1] = dp[i][j-1]
    prev = curr;
  }
  return prev[n]; // O(min(m,n)) space ✓
}
```

**Q6. What is the "two-sequence DP" general pattern, and which problems share its structure?**

A: Any problem asking about a relationship between two sequences s1 and s2 where the answer for `(s1[0..i-1], s2[0..j-1])` depends on `(s1[0..i-2], s2[0..j-1])`, `(s1[0..i-1], s2[0..j-2])`, and `(s1[0..i-2], s2[0..j-2])` — all three shorter prefixes — follows the same DP skeleton. The critical question for each problem: what do the three transitions mean semantically? The pattern: `dp[i][j]` = answer for first i chars of s1 and first j chars of s2; base cases at row 0 and column 0; transition splits on whether `s1[i-1] == s2[j-1]`.

```
Problem                   Match case                    Mismatch case
LCS                       dp[i-1][j-1] + 1             max(dp[i-1][j], dp[i][j-1])
Edit Distance             dp[i-1][j-1]  (no edit)      1+min(dp[i-1][j], dp[i][j-1], dp[i-1][j-1])
Distinct Subsequences     dp[i-1][j-1] + dp[i-1][j]   dp[i-1][j]
Min ASCII Delete Sum      dp[i-1][j-1]+ord(s1[i-1])    min(dp[i-1][j]+ord(s1[i-1]),
                                                            dp[i][j-1]+ord(s2[j-1]))
Longest Palindromic Subseq  (via LCS(s, rev(s)))
Interleaving Strings      (slightly different state)

Skeleton is always the same — only the merge formula changes.
```

**Q7. What is the "longest common substring" recurrence, and why does mismatch reset to zero?**

A: Longest common substring requires matched characters to be *contiguous* in both strings simultaneously. `dp[i][j]` = length of the longest common substring *ending at* `s1[i-1]` and `s2[j-1]`. Match case: `dp[i][j] = dp[i-1][j-1] + 1` (extend the run). Mismatch case: `dp[i][j] = 0` — the common substring ending at these two positions has zero length (it is broken). The global answer is `max(dp[i][j])` over all cells. Unlike LCS, where a mismatch carries forward a useful sub-result, here a mismatch means the current contiguous run is broken and must restart from scratch. Space: O(n) (one row), or O(1) if we only need the length (track a running max and reset on mismatch).

**Q8. What is the connection between LCS and edit distance, and when does LCS equal `m + n − 2 × LCS`?**

A: Edit distance (Levenshtein distance) counts the minimum number of insertions, deletions, and substitutions to transform `s1` into `s2`. When only insertions and deletions are allowed (no substitutions — the "delete-only" variant): the minimum number of deletions from both strings to make them equal is exactly `m + n − 2 × LCS(s1, s2)`. The intuition: every character in the LCS is kept in both strings (contributes 0 deletions); every character NOT in the LCS must be deleted from whichever string it appears in. Since the LCS has length L, there are `m - L` chars deleted from s1 and `n - L` from s2, totaling `m + n - 2L`. This identity connects three problems: LCS length, minimum deletions to equalize two strings, and shortest common supersequence length (`m + n - LCS`).

**Q9. What is the shortest common supersequence (SCS), and how does LCS directly compute it?**

A: The shortest common supersequence of s1 and s2 is the shortest string that contains both s1 and s2 as subsequences. Its length is `m + n - LCS(s1, s2)` — we merge both strings, sharing the LCS characters (which appear once instead of twice). Construction: run the LCS DP; backtrack the table using the same logic as LCS reconstruction, but include *both* characters on mismatches (include the skipped character in the supersequence): when skipping s1's character (moving up), append `s1[i-1]`; when skipping s2's character (moving left), append `s2[j-1]`; when characters match, append the shared character once. The SCS is built in reverse during backtracking, then reversed at the end.

### Section A2: Advanced LCS Patterns

**Q10. How does palindromic subsequence reduce to LCS, and what is the alternative diagonal DP?**

A: The Longest Palindromic Subsequence (LPS) of string `s` equals `LCS(s, reverse(s))`. This works because any palindromic subsequence read forward appears in `s`, and read backward appears in `reverse(s)` — so a common subsequence of `s` and `reverse(s)` is exactly a palindrome. The alternative is a direct interval DP on `s` itself: `dp[i][j]` = LPS of `s[i..j]`, filled diagonally (increasing substring length). Base cases: `dp[i][i] = 1` (single character is a palindrome of length 1). Transition: `dp[i][j] = dp[i+1][j-1] + 2` if `s[i] == s[j]` (extend palindrome by matching outer characters); `max(dp[i+1][j], dp[i][j-1])` otherwise (skip one end). The LCS approach is simpler to implement; the interval DP is slightly more space-efficient (only the `s`-indexed table, not the `s` × `reverse(s)` table).

**Q11. What is the "LCS reduces to LIS" relationship, and when does it apply?**

A: When one of the two sequences is a permutation of the other (or more generally, contains no duplicate elements), LCS(s1, s2) can be transformed into an LIS problem: (1) For each element of s2, record its position in s1; (2) The resulting sequence of positions P is such that an increasing subsequence of P corresponds to a common subsequence of s1 and s2; (3) The longest increasing subsequence of P equals the LCS. This transformation converts an O(mn) LCS problem into an O(n log n) LIS problem — a meaningful speedup when n is large. The prerequisite of no duplicates is critical: duplicates cause a position to map to multiple values in P, requiring more careful handling (only take the leftmost occurrence in s1 to avoid selecting the same element twice).

```
s1 = [3, 1, 4, 1, 5, 9, 2, 6]  (no dups: use with care)
s2 = [1, 4, 2, 9]

Position of s2[j] in s1:  pos = [1, 2, 6, 5]  (0-indexed positions in s1)
LIS of pos:  [1, 2, 5] or [1, 2, 6] → length 3
LCS(s1, s2) = 3  (e.g., [1,4,9] or [1,4,2])  ✓
```

**Q12. What is the distinct subsequences problem (LC 115), and how does its DP differ from LCS?**

A: Distinct Subsequences asks: how many distinct ways does `t` appear as a subsequence of `s`? `dp[i][j]` = number of ways to form `t[0..j-1]` using `s[0..i-1]`. Base: `dp[i][0] = 1` (empty t is a subsequence of any s in exactly 1 way); `dp[0][j] = 0` for j > 0 (non-empty t cannot be formed from empty s). Transition: `dp[i][j] = dp[i-1][j]` (always — don't use s[i-1] to match t[j-1]) plus `dp[i-1][j-1]` if `s[i-1] == t[j-1]` (use s[i-1] to match t[j-1]). The key difference from LCS: there is no "max" — we *sum* the ways. On a match, we add both choices (use this s-character or skip it); on a mismatch, we only skip the s-character (can never force a match).

## Topic B: Longest Increasing Subsequence

### Section B1: LIS Fundamentals

**Q13. What is the O(n²) LIS DP, and what does `dp[i]` represent?**

A: `dp[i]` = length of the longest strictly increasing subsequence ending at index `i` (including `nums[i]` itself). Transition: `dp[i] = 1 + max(dp[j] for j < i if nums[j] < nums[i])`, with the default `dp[i] = 1` if no such j exists (the subsequence consists of just `nums[i]`). Fill left to right; for each `i`, scan all `j < i` to find the best predecessor. Answer: `max(dp)`. Time O(n²), space O(n).

```js
function lisLength_n2(nums) {
  const n = nums.length;
  const dp = new Array(n).fill(1); // each element alone = LIS of length 1

  for (let i = 1; i < n; i++)
    for (let j = 0; j < i; j++)
      if (nums[j] < nums[i])
        dp[i] = Math.max(dp[i], dp[j] + 1);

  return Math.max(...dp); // LIS is the longest ending at any position
}
// dp[i] invariant: length of LIS ending at index i (nums[i] is the last element)
```

**Q14. What is the patience sorting insight enabling O(n log n) LIS?**

A: Patience sorting is a card-sorting game: deal cards one at a time; place each card on the leftmost pile whose top card is ≥ the new card (for strict LIS); if none, start a new pile. The number of piles at the end equals the LIS length. The computational insight: instead of tracking all piles, only track the *top card* of each pile (the smallest possible tail for increasing subsequences of each length). These tops form the `tails` array: `tails[k]` = the smallest tail element of all increasing subsequences of length `k+1` found so far. A smaller tail is always better — it is easier to extend a subsequence ending in a smaller value. When a new element x arrives, binary search finds the leftmost pile top ≥ x: replace that top with x (smaller tail, same length), or start a new pile if x beats all existing tops (LIS grows by 1).

**Q15. What is the `tails` array invariant, and why is it always strictly sorted?**

A: Invariant: `tails` is always strictly increasing (`tails[0] < tails[1] < ... < tails[L-1]`), and `tails[k]` is the minimum possible last element of any increasing subsequence of length `k+1` among all subsequences found so far. The sortedness is maintained inductively: when appending x (new pile), x > tails[last] — because no existing pile could accept x (all tops were < x), so x > all existing tops → sorted. When replacing `tails[pos]` with x: by definition `tails[pos] >= x` (why we chose this position) and `tails[pos-1] < x` (pos is the *leftmost* position ≥ x) → x fits between `tails[pos-1]` and the gap, maintaining the sorted order. The sortedness is what makes binary search applicable — without it, the binary search wouldn't be valid.

```
nums = [2, 6, 3, 4, 1, 7]

x=2: tails=[]. pos=0=tails.length → append. tails=[2].
x=6: tails=[2]. pos=1=tails.length → append. tails=[2,6].
x=3: tails=[2,6]. lower_bound(tails,3)=1 (tails[1]=6≥3). Replace. tails=[2,3].
x=4: tails=[2,3]. lower_bound(tails,4)=2=tails.length → append. tails=[2,3,4].
x=1: tails=[2,3,4]. lower_bound(tails,1)=0 (tails[0]=2≥1). Replace. tails=[1,3,4].
x=7: tails=[1,3,4]. pos=3=tails.length → append. tails=[1,3,4,7].

LIS length = tails.length = 4. ✓  (e.g., [2,3,4,7] or [1,3,4,7])
Note: tails is NOT the actual LIS — it's a running computational artifact.
```

**Q16. How does binary search fit into the tails-based algorithm, and what determines strict vs non-strict LIS?**

A: For each new element x, we binary search `tails` for the position to update. The comparison direction determines strictly increasing vs non-decreasing: **Strictly increasing LIS**: find leftmost `pos` where `tails[pos] >= x` (lower bound). Replace `tails[pos]` with x. This means: we allow x to be placed "before" equal elements — an equal element at `tails[pos]` is displaced (preventing x from forming a non-strictly increasing subsequence by using the same value). **Non-decreasing LIS**: find leftmost `pos` where `tails[pos] > x` (upper bound / strict lower bound). Replace `tails[pos]` with x. This allows equal elements to extend the subsequence (x can follow equal previous elements). The binary search implementation changes from `tails[mid] < x` (lower bound → finds first `>= x`) to `tails[mid] <= x` (finds first `> x`).

```js
function lisLength(nums) {
  const tails = [];

  for (const x of nums) {
    // Lower bound: leftmost position where tails[pos] >= x (strict LIS)
    let lo = 0, hi = tails.length;
    while (lo < hi) {
      const mid = (lo + hi) >> 1;
      tails[mid] < x ? lo = mid + 1 : hi = mid; // < for strict; <= for non-decreasing
    }
    tails[lo] = x; // replace or append (append when lo === tails.length)
  }

  return tails.length;
}
// For non-decreasing LIS: change tails[mid] < x to tails[mid] <= x
```

**Q17. How do you reconstruct the actual LIS sequence from the O(n log n) algorithm?**

A: The `tails` array is NOT the actual LIS — it's a computational artifact. Reconstruction requires additional bookkeeping: for each position `i` in `nums`, record: (1) the LIS length at that position (`lisLen[i]`) — the value of `lo + 1` after the binary search; (2) a parent pointer `parent[i]` — the index `j` in `nums` that was the last element before `nums[i]` in the optimal LIS ending at `i` (the index stored in `tails[lo-1]` at the time `nums[i]` is processed). After processing all elements, find the index `i*` with the maximum `lisLen[i]`; backtrack through parent pointers from `i*` to reconstruct the LIS in reverse.

```js
function lisReconstruct(nums) {
  const n = nums.length;
  const tails     = [];   // tails[k] = value of tail element
  const tailIdx   = [];   // tailIdx[k] = index in nums of tails[k]
  const parent    = new Array(n).fill(-1);
  const lisLen    = new Array(n).fill(1);

  for (let i = 0; i < n; i++) {
    let lo = 0, hi = tails.length;
    while (lo < hi) {
      const mid = (lo + hi) >> 1;
      tails[mid] < nums[i] ? lo = mid + 1 : hi = mid;
    }
    tails[lo]   = nums[i];
    tailIdx[lo] = i;
    lisLen[i]   = lo + 1;

    if (lo > 0) parent[i] = tailIdx[lo - 1]; // predecessor index
  }

  // Find endpoint of longest LIS
  let maxLen = 0, endIdx = 0;
  for (let i = 0; i < n; i++)
    if (lisLen[i] > maxLen) { maxLen = lisLen[i]; endIdx = i; }

  // Backtrack
  const result = [];
  for (let idx = endIdx; idx !== -1; idx = parent[idx]) result.push(nums[idx]);
  return result.reverse();
}
```

### Section B2: LIS Variants and Extensions

**Q18. What is the 2D LIS "Russian Dolls" pattern, and what is the critical sorting trick?**

A: Russian Dolls (LC 354): given envelopes `[w, h]`, envelope A fits inside B if `w_A < w_B` AND `h_A < h_B` (strictly). Find the maximum nesting depth. This is a 2D LIS problem: find the longest chain of envelopes where both dimensions are strictly increasing. The trick: sort envelopes by width ascending, but for equal widths, sort height *descending*. Then run standard 1D LIS (strictly increasing) on the heights alone. **Why descending heights for equal widths?** Two envelopes with the same width cannot nest (strict inequality required). With heights sorted descending for equal widths, any two envelopes from the same width group have decreasing heights — the LIS algorithm cannot select more than one from any equal-width group (to extend a strictly increasing subsequence, heights must increase, but within a same-width group they decrease). Without the descending trick, multiple same-width envelopes with increasing heights would incorrectly be selected.

```
envelopes = [[5,4],[6,4],[6,7],[2,3]]
Sort by width ASC, then height DESC for ties:
  [[2,3],[5,4],[6,7],[6,4]]   ← [6,7] before [6,4] (descending height for w=6)

LIS on heights: [3, 4, 7, 4]
  tails after 3: [3]
  tails after 4: [3, 4]
  tails after 7: [3, 4, 7]
  tails after 4: replace tails[1]=4 with 4 → [3, 4, 7] (no change since 4≥4 replaces)
  LIS length = 3. ✓  ([2,3]→[5,4]→[6,7])

Without descending sort for equal widths: heights=[3,4,4,7]
  tails after 3:[3], 4:[3,4], 4:[3,4,4]? No — 4≥4 so replace pos 1 with 4: [3,4].
  Then 7: [3,4,7]. Still length 3. But if w=6 had [4,7]: heights=[3,4,4,7],
  LIS=[3,4,7] → 3. Still OK here. But for [[1,1],[1,1]]: without trick → tails=[1,1]=len 2 ✗;
  with descending: heights=[1,1] → tails=[1]=len 1 ✓.
```

**Q19. What is the Longest Bitonic Subsequence, and how does it combine two LIS passes?**

A: A bitonic sequence first strictly increases then strictly decreases (or is entirely increasing or decreasing). The longest bitonic subsequence at index `i` has length `LIS_left[i] + LIS_right[i] - 1`, where `LIS_left[i]` = length of LIS ending at `i` (from left), and `LIS_right[i]` = length of LDS (longest decreasing subsequence) starting at `i` (equivalently, LIS of the reversed array starting at position `n-1-i`). The answer is `max(LIS_left[i] + LIS_right[i] - 1)` over all i. The `-1` avoids double-counting `nums[i]` (the peak). Both arrays are computed with the O(n²) LIS DP (tails-based approach would complicate the computation of `LIS_right`).

**Q20. What is the "number of LIS" problem, and how does the DP extend to track counts?**

A: Count distinct LIS (LC 673). Extend the O(n²) DP to track `(len[i], cnt[i])` — the LIS length ending at `i` and the number of such LIS. Initialize `len[i] = 1, cnt[i] = 1` for all i. For each `j < i` with `nums[j] < nums[i]`: if `len[j] + 1 > len[i]`: update `len[i] = len[j] + 1; cnt[i] = cnt[j]` (found a strictly better length, adopt its count). If `len[j] + 1 == len[i]`: `cnt[i] += cnt[j]` (found another path of the same best length, add its count). Answer: sum of `cnt[i]` for all `i` where `len[i] == maxLen`. The invariant: `cnt[i]` counts the number of distinct strictly increasing subsequences of length `len[i]` that end at `nums[i]`.

```js
function findNumberOfLIS(nums) {
  const n = nums.length;
  const len = new Array(n).fill(1);
  const cnt = new Array(n).fill(1);

  for (let i = 1; i < n; i++)
    for (let j = 0; j < i; j++)
      if (nums[j] < nums[i]) {
        if (len[j] + 1 > len[i]) { len[i] = len[j]+1; cnt[i] = cnt[j]; }
        else if (len[j] + 1 === len[i]) cnt[i] += cnt[j];
      }

  const maxLen = Math.max(...len);
  return len.reduce((acc, l, i) => acc + (l === maxLen ? cnt[i] : 0), 0);
}
```

**Q21. What is the connection between patience sorting and the actual card game?**

A: In the patience sorting card game, a deck is sorted by dealing cards face-up into piles following the rule: a card can only be placed on a pile whose top card has a *greater* value (or start a new pile). The optimal strategy (always place on the leftmost valid pile) has a remarkable property: the number of piles equals the LIS length. Furthermore, the top cards of the piles at any moment form a sorted sequence — which is exactly the `tails` invariant. The mathematical theorem (Dilworth's theorem in disguise): the minimum number of *decreasing* subsequences needed to partition the sequence equals the length of the longest *increasing* subsequence. The patience sort algorithm is a constructive proof of this theorem.

## Topic C: Cross-Topic & Interview-Style Questions

**Q22. Compare LCS and LIS: data structures, DP dimensionality, and what each dp cell represents.**

A:

| Dimension | LCS | LIS |
|---|---|---|
| Input | Two sequences s1, s2 | One sequence nums |
| DP dimensions | 2D: dp[i][j] | 1D: dp[i] or tails array |
| dp cell meaning | LCS of s1[0..i-1] and s2[0..j-1] | LIS length ending at index i |
| Time complexity | O(mn) | O(n²) naive; O(n log n) tails |
| Space complexity | O(mn) or O(min(m,n)) | O(n) |
| Key case split | s1[i-1] == s2[j-1]? | nums[j] < nums[i]? |
| Reconstruction | Backtrack 2D table | Track parent pointers |
| Optimal substructure | Match → diag+1; mismatch → max of two neighbors | Best predecessor + 1 |

**Q23. How do you identify a problem as LCS-type vs LIS-type vs a different DP?**

A: LCS-type signals: two input sequences; the word "common" in the problem statement; the answer involves matching elements from both sequences while preserving order; the DP state needs to track position in *both* sequences simultaneously. LIS-type signals: one input sequence; the words "increasing," "decreasing," "nesting," "chain"; the answer involves selecting elements from one sequence satisfying a monotone constraint; the DP state tracks position in *one* sequence and looks back at all previous positions. Other DP signals: "substring" or "subarray" (usually different — contiguous structure or Kadane's); "partition" or "subset" (0-1 knapsack or subset sum); "path" or "grid" (path DP); "all ways to do X" (combinatorial DP with summation not maximization). The deepest diagnostic: write out `dp[?][?] = ?` — if it requires two indices tracking positions in two different sequences, it's LCS-type; if one index suffices, it's likely LIS-type or 1D DP.

**Q24. State the invariant for each approach in one sentence each.**

A:
- **LCS 2D DP**: `dp[i][j]` always equals the length of the longest common subsequence of the prefix `s1[0..i-1]` and the prefix `s2[0..j-1]`, established before any current cell is filled by the entries it depends on.
- **LCS space-optimized**: `prev[j]` always equals what `dp[i-1][j]` would be in the full table — the LCS of the previous row's prefix of s1 with `s2[0..j-1]`.
- **LIS O(n²) DP**: `dp[i]` always equals the length of the longest strictly increasing subsequence that ends with `nums[i]` and uses only elements from `nums[0..i]`.
- **LIS tails (O(n log n))**: `tails[k]` always equals the minimum possible last element of any strictly increasing subsequence of length `k+1` found among all elements processed so far — and `tails` is always strictly sorted.
- **Number of LIS**: `cnt[i]` always equals the number of distinct strictly increasing subsequences of length `len[i]` that end exactly at `nums[i]`, where `len[i]` is the maximum such length.

**Q25. "Describe the three follow-up paths an interviewer typically takes after asking the basic LCS or LIS problem."**

A:
- **After LCS**: (1) "Reconstruct the actual subsequence, not just its length" — requires backtracking the DP table (O(m+n) time); (2) "Reduce space to O(min(m,n))" — rolling-row optimization, but note that reconstruction is lost; (3) "Extend to edit distance" — add the replace operation (third case in the transition) and change the base cases from 0 to i or j.
- **After LIS**: (1) "Can you do it in O(n log n)?" — the patience sort / tails binary search approach; (2) "Reconstruct the actual subsequence" — requires parent pointers alongside the tails tracking; (3) "Count the number of distinct LIS" — extend to the (len, count) pair tracking from Q20.
- **After Russian Dolls**: "What if you have three dimensions (width, height, depth)?" — Sort by first dim, then run 2D LIS on the remaining two dimensions using a segment tree or BIT indexed on the second dimension for O(n log n).

## Problem 1 — Longest Common Subsequence

### Problem

Given two strings `text1` and `text2`, return the length of their longest common subsequence. If there is no common subsequence, return 0.

```
Input:  text1 = "abcde", text2 = "ace"   → 3   // "ace"
Input:  text1 = "abc",   text2 = "abc"   → 3   // "abc"
Input:  text1 = "abc",   text2 = "def"   → 0   // no common characters
```

### Pattern Recognition
2D DP on two sequences — `dp[i][j]` = LCS of first i chars of text1 and first j chars of text2. The match/mismatch case split drives the three-transition recurrence.

### Key Insight
When `text1[i-1] == text2[j-1]`, these characters *must* appear together in the optimal LCS — skipping them can never improve the result. When they differ, the LCS is obtained by skipping one character from either side and taking the better outcome. These two cases are exhaustive — no other structural option exists for the last characters of two sequences.

### Solution

```js
function longestCommonSubsequence(text1, text2) {
  const m = text1.length, n = text2.length;
  // dp[i][j] = LCS length of text1[0..i-1] and text2[0..j-1]
  const dp = Array.from({ length: m+1 }, () => new Array(n+1).fill(0));
  // Base case: dp[0][*] = dp[*][0] = 0 (empty string has LCS 0 with anything)

  for (let i = 1; i <= m; i++) {
    for (let j = 1; j <= n; j++) {
      if (text1[i-1] === text2[j-1]) {
        dp[i][j] = dp[i-1][j-1] + 1; // match: include both characters
      } else {
        dp[i][j] = Math.max(dp[i-1][j], dp[i][j-1]); // skip one side, take the better
      }
    }
  }

  return dp[m][n];
}
```

### Dry Run

```
text1 = "abcde", text2 = "ace"

     ""  a  c  e
""    0  0  0  0
a     0  1  1  1   dp[1][1]: 'a'=='a' → dp[0][0]+1=1. dp[1][2]: 'a'≠'c' → max(0,1)=1. dp[1][3]: 'a'≠'e' → max(0,1)=1.
b     0  1  1  1   dp[2][1]: 'b'≠'a' → max(dp[1][1],dp[2][0])=max(1,0)=1. dp[2][2,3]: 'b'≠'c','e' → 1.
c     0  1  2  2   dp[3][1]: 'c'≠'a' → 1. dp[3][2]: 'c'=='c' → dp[2][1]+1=2. dp[3][3]: 'c'≠'e' → max(dp[2][3],dp[3][2])=max(1,2)=2.
d     0  1  2  2   dp[4][*]: 'd' matches nothing → propagate 2.
e     0  1  2  3   dp[5][3]: 'e'=='e' → dp[4][2]+1=2+1=3.

Return dp[5][3] = 3. ✓
```

### Complexity
- Time: O(mn) — two nested loops, each cell computed in O(1).
- Space: O(mn) for the full table; O(min(m,n)) with rolling-row optimization.

### Edge Cases
- One string is empty: all dp values remain 0 → returns 0.
- Identical strings: diagonal fills with 1, 2, 3, ... → returns min(m, n) = n.
- No common characters: no match case fires; table fills with 0s → returns 0.
- One string is a subsequence of the other: returns the length of the shorter string.

### Follow-up Questions
- "Reconstruct the actual LCS?" — Backtrack from `dp[m][n]`: match → go diagonal, collect character; mismatch → go to the larger neighbor.
- "Reduce space to O(min(m,n))?" — Use two rolling arrays (prev/curr); swap after each row. Reconstruction is no longer possible from the compressed state.
- "Handle Unicode?" — JavaScript's `===` on characters handles Unicode correctly; no change needed.

## Problem 2 — Edit Distance

### Problem

Given two strings `word1` and `word2`, return the minimum number of operations to convert `word1` to `word2`. Allowed operations: insert a character, delete a character, replace a character.

```
Input:  word1 = "horse", word2 = "ros"   → 3
  // horse → rorse (replace h→r), rorse → rose (delete r), rose → ros (delete e)
Input:  word1 = "intention", word2 = "execution" → 5
```

### Pattern Recognition
Two-sequence DP with three transitions on mismatch — the same skeleton as LCS but with three choices (insert, delete, replace) instead of two, and minimization instead of maximization.

### Key Insight
`dp[i][j]` = minimum edits to convert `word1[0..i-1]` to `word2[0..j-1]`. When `word1[i-1] == word2[j-1]`, no edit is needed: `dp[i][j] = dp[i-1][j-1]`. When they differ, we take the minimum of three operations: delete `word1[i-1]` (come from `dp[i-1][j]`), insert `word2[j-1]` (come from `dp[i][j-1]`), or replace `word1[i-1]` with `word2[j-1]` (come from `dp[i-1][j-1]`). The base cases differ from LCS: `dp[i][0] = i` (delete i characters to reach empty word2) and `dp[0][j] = j` (insert j characters to reach word2 from empty).

### Solution

```js
function minDistance(word1, word2) {
  const m = word1.length, n = word2.length;
  const dp = Array.from({ length: m+1 }, (_, i) => {
    const row = new Array(n+1);
    row[0] = i;        // dp[i][0] = i: delete i chars to reach empty word2
    for (let j = 1; j <= n; j++) row[j] = 0;
    return row;
  });
  for (let j = 0; j <= n; j++) dp[0][j] = j; // dp[0][j] = j: insert j chars

  for (let i = 1; i <= m; i++) {
    for (let j = 1; j <= n; j++) {
      if (word1[i-1] === word2[j-1]) {
        dp[i][j] = dp[i-1][j-1];                  // no operation needed
      } else {
        dp[i][j] = 1 + Math.min(
          dp[i-1][j],    // delete word1[i-1]
          dp[i][j-1],    // insert word2[j-1]
          dp[i-1][j-1]   // replace word1[i-1] with word2[j-1]
        );
      }
    }
  }

  return dp[m][n];
}
```

### Dry Run

```
word1 = "horse", word2 = "ros"

      ""  r  o  s
""     0  1  2  3   ← dp[0][j] = j (insert j chars)
h      1  1  2  3   dp[1][1]: 'h'≠'r' → 1+min(dp[0][1]=1, dp[1][0]=1, dp[0][0]=0) = 1 (replace)
o      2  2  1  2   dp[2][2]: 'o'=='o' → dp[1][1]=1. dp[2][1]: 'o'≠'r' → 1+min(2,1,1)=2.
r      3  2  2  2   dp[3][1]: 'r'=='r' → dp[2][0]=2.
s      4  3  3  2   dp[4][3]: 's'=='s' → dp[3][2]=2.
e      5  4  4  3   dp[5][3]: 'e'≠'s' → 1+min(dp[4][3]=2,dp[5][2]=4,dp[4][2]=3)=3.

Return dp[5][3] = 3. ✓
```

### Complexity
- Time: O(mn). Space: O(mn); reducible to O(min(m,n)) with rolling rows.

### Edge Cases
- Empty word1: `dp[0][j] = j` → returns n (pure insertions).
- Empty word2: `dp[i][0] = i` → returns m (pure deletions).
- Identical strings: diagonal match fills → all cells on the diagonal equal dp[i-1][j-1] → returns 0.
- One character: dp[1][n] = max(1 - matches, n) approximately.

### Follow-up Questions
- "Only deletions allowed (no insert or replace)?" — Reduce to LCS: minimum deletions = m + n - 2 × LCS(word1, word2).
- "Weighted operations?" — Replace cost with specific weights in the min formula; LCS relationship breaks.
- "Space to O(n)?" — Use two rows (prev/curr). Only diagonal's previous value needs special tracking: store `diagVal = prev[j-1]` before overwriting.

## Problem 3 — Longest Increasing Subsequence

### Problem

Given an integer array `nums`, return the length of the longest strictly increasing subsequence.

```
Input:  nums = [10,9,2,5,3,7,101,18]  → 4  // [2,5,7,101] or [2,3,7,101]
Input:  nums = [0,1,0,3,2,3]          → 4  // [0,1,2,3]
Input:  nums = [7,7,7,7,7,7,7]        → 1  // no two equal elements form strictly increasing
```

### Pattern Recognition
Two approaches: (A) O(n²) DP — `dp[i]` = LIS length ending at i; (B) O(n log n) patience sort — maintain `tails` array with binary search.

### Key Insight
**O(n²)**: `dp[i]` is determined by the best predecessor `j < i` with `nums[j] < nums[i]`. **O(n log n)**: the `tails` array is always sorted, enabling binary search. The key insight for tails: when we replace `tails[pos]` with `x`, we don't lose any information about the LIS *length* — we only improve the tail (smaller tails are easier to extend), and the invariant is preserved.

### Solution

```js
// Approach A: O(n²) DP
function lengthOfLIS_n2(nums) {
  const n = nums.length;
  const dp = new Array(n).fill(1); // every element alone = LIS of length 1

  for (let i = 1; i < n; i++)
    for (let j = 0; j < i; j++)
      if (nums[j] < nums[i])
        dp[i] = Math.max(dp[i], dp[j] + 1);

  return Math.max(...dp);
}

// Approach B: O(n log n) patience sort
function lengthOfLIS(nums) {
  const tails = []; // tails[k] = smallest tail of all IS of length k+1

  for (const x of nums) {
    // Binary search: find leftmost position where tails[pos] >= x
    let lo = 0, hi = tails.length;
    while (lo < hi) {
      const mid = (lo + hi) >> 1;
      tails[mid] < x ? lo = mid + 1 : hi = mid;
    }
    // lo === tails.length: x beats all tails → start new pile (LIS grows)
    // lo < tails.length:   x can replace tails[lo] (same length, better tail)
    tails[lo] = x;
  }

  return tails.length; // number of piles = LIS length
}
```

### Dry Run

```

x=9:  search [10]: 10≥9 → hi=0, lo=0. Replace tails[0]=9. tails=[9].
x=2:  search [9]:  9≥2 → hi=0, lo=0. Replace tails[0]=2. tails=[2].
x=5:  search [2]:  2<5 → lo=1=len(tails). Append. tails=[2,5].
x=3:  search [2,5]: mid=0→2<3→lo=1; mid=1→5≥3→hi=1; lo=1. Replace tails[1]=3. tails=[2,3].
x=7:  search [2,3]: 2<7,3<7 → lo=2=len. Append. tails=[2,3,7].
x=101: all <101 → append. tails=[2,3,7,101].

```

### Complexity
- **O(n²)**: Time O(n²), Space O(n).
- **O(n log n)**: Time O(n log n) — n elements, each with a binary search in O(log n). Space O(n) for tails.

### Edge Cases
- All descending: each element replaces tails[0] → tails.length stays 1. LIS = 1.
- All ascending: each element appends → tails.length = n. LIS = n.
- All equal: each element replaces tails[0] (since `tails[0] >= x` and `x = tails[0]`) → tails.length stays 1. LIS = 1. ✓ (strict increase requires different values)
- Single element: tails=[nums[0]] → LIS = 1.

### Follow-up Questions
- "Non-decreasing (weakly increasing) LIS?" — Change `tails[mid] < x` to `tails[mid] <= x` in the binary search. Equal elements can now extend the subsequence.
- "O(n log n) but also return the actual subsequence?" — Requires parent pointer tracking alongside tails (see Q17).
- "Longest decreasing subsequence?" — Reverse nums first, then find LIS; or flip the binary search comparison.

## Problem 4 — Russian Doll Envelopes

### Problem

You are given a 2D array `envelopes` where `envelopes[i] = [wi, hi]`. One envelope can fit inside another if and only if both width and height are strictly greater. Find the maximum number of envelopes you can Russian doll (nest).

```
Input:  envelopes = [[5,4],[6,4],[6,7],[2,3]]  → 3
  // [2,3] → [5,4] → [6,7]
Input:  envelopes = [[1,1],[1,1],[1,1]]         → 1
```

### Pattern Recognition
2D LIS — sort by width ascending, height descending for equal widths; then find standard O(n log n) LIS on heights.

### Key Insight
Nesting is a 2D partial order: valid if BOTH dimensions are strictly increasing. Sorting by width ascending allows the LIS on heights to capture the width constraint (heights are already ordered relative to widths). The descending height sort for equal widths is the critical trick: equal-width envelopes cannot nest, so their heights must form a *decreasing* subsequence within the sorted order — the LIS algorithm (seeking increasing subsequences) will pick at most one from any equal-width group.

### Solution

```js
function maxEnvelopes(envelopes) {
  // Sort: width ASC; for equal widths, height DESC (prevents multiple same-width selection)
  envelopes.sort((a, b) => a[0] !== b[0] ? a[0] - b[0] : b[1] - a[1]);

  // Extract heights; find LIS on heights (O(n log n))
  const heights = envelopes.map(e => e[1]);
  const tails = [];

  for (const h of heights) {
    let lo = 0, hi = tails.length;
    while (lo < hi) {
      const mid = (lo + hi) >> 1;
      tails[mid] < h ? lo = mid + 1 : hi = mid;
    }
    tails[lo] = h;
  }

  return tails.length;
}
```

- "Three dimensions (width, height, depth)?" — Sort by width ASC, then height DESC for equal widths, then depth DESC for equal (width, height). Run 2D LIS on (height, depth) using a segment tree or BIT indexed on height values.
- "Non-strict nesting (≤ instead of <)?" — Change both the sort order (equal-dim handling changes) and the binary search direction in LIS.

## Problem 5 — Longest Palindromic Subsequence

### Problem

Given a string `s`, return the length of the longest palindromic subsequence in `s`.

```
Input: s = "bbbab"  → 4   // "bbbb"
Input: s = "cbbd"   → 2   // "bb"
```

### Pattern Recognition
Two equivalent approaches: (A) LCS of `s` and `reverse(s)` — direct reduction. (B) Interval DP — `dp[i][j]` = LPS of `s[i..j]`, filled diagonally. Both are O(n²) time, O(n²) space (O(n) space with rolling array for interval DP).

### Key Insight
Any palindromic subsequence of `s` reads the same forward and backward — it is a common subsequence of `s` and its reverse. The LCS(s, rev(s)) captures exactly the longest such common subsequence. The interval DP is more space-efficient and avoids creating the reversed string: when outer characters match, they wrap an inner palindrome and extend it by 2; when they don't, the best palindrome is found by skipping one end.

### Solution

```js
// Approach A: LCS(s, reverse(s)) — conceptually simplest
function longestPalindromeSubseq_lcs(s) {
  const rev = s.split('').reverse().join('');
  const n = s.length;
  const dp = Array.from({ length: n+1 }, () => new Array(n+1).fill(0));

  for (let i = 1; i <= n; i++)
    for (let j = 1; j <= n; j++)
      dp[i][j] = s[i-1] === rev[j-1]
        ? dp[i-1][j-1] + 1
        : Math.max(dp[i-1][j], dp[i][j-1]);

  return dp[n][n];
}

// Approach B: Interval DP — O(n²) time, O(n) space with rolling array
function longestPalindromeSubseq(s) {
  const n = s.length;
  // dp[i][j] = LPS length of s[i..j]
  const dp = Array.from({ length: n }, () => new Array(n).fill(0));

  for (let i = 0; i < n; i++) dp[i][i] = 1; // single char: palindrome of length 1

  // Fill by increasing substring length
  for (let len = 2; len <= n; len++) {
    for (let i = 0; i <= n - len; i++) {
      const j = i + len - 1;
      if (s[i] === s[j]) {
        dp[i][j] = (len === 2 ? 0 : dp[i+1][j-1]) + 2; // match outer chars: +2
      } else {
        dp[i][j] = Math.max(dp[i+1][j], dp[i][j-1]); // skip one end
      }
    }
  }

  return dp[0][n-1];
}
```

```
  i=0,j=1: s[0]='b'==s[1]='b' → dp[0][1]=0+2=2.
  i=1,j=2: s[1]='b'==s[2]='b' → dp[1][2]=2.
  i=2,j=3: s[2]='b'≠s[3]='a' → max(dp[3][3],dp[2][2])=max(1,1)=1.
  i=3,j=4: s[3]='a'≠s[4]='b' → max(dp[4][4],dp[3][3])=1.

  i=0,j=2: 'b'=='b' → dp[1][1]+2=1+2=3.
```

### Complexity
- Time: O(n²) — O(n²) subproblems, each O(1).

### Edge Cases
- All same character: LPS = n (the entire string is a palindrome).
- Already a palindrome: LPS = n.
- No repeated characters: LPS = 1.
- Length 1: dp[0][0] = 1.

### Follow-up Questions
- "Minimum insertions to make s a palindrome?" — `n - LPS(s)`. Inserting characters that mirror the non-palindromic parts.
- "Shortest palindrome containing s?" — Different problem — not directly LPS.
- "Count distinct palindromic subsequences?" — Requires careful inclusion-exclusion; harder than LPS length.

## Problem 6 — Number of Longest Increasing Subsequence

### Problem

Given an integer array `nums`, return the number of distinct longest increasing subsequences.

```
Input: nums = [1, 3, 5, 4, 7]  → 2   // [1,3,5,7] and [1,3,4,7]
Input: nums = [2, 2, 2, 2, 2]  → 5   // each single element [2] is its own LIS of length 1
```

### Pattern Recognition
Extended O(n²) LIS DP tracking `(len[i], cnt[i])` — LIS length ending at index i and the number of such distinct subsequences of that length.

### Key Insight
When `dp[j] + 1 > dp[i]`: a strictly better LIS length was found; adopt the predecessor's count exactly (only this path length matters now). When `dp[j] + 1 == dp[i]`: another path achieving the same maximum LIS length was found; accumulate its count. These two cases together maintain the invariant: `cnt[i]` always equals the exact number of distinct LIS of length `len[i]` ending at `nums[i]`.

### Solution

```js
function findNumberOfLIS(nums) {
  const n = nums.length;
  const len = new Array(n).fill(1); // LIS length ending at index i
  const cnt = new Array(n).fill(1); // number of LIS of that length ending at i

  for (let i = 1; i < n; i++) {
    for (let j = 0; j < i; j++) {
      if (nums[j] < nums[i]) {
        if (len[j] + 1 > len[i]) {
          len[i] = len[j] + 1;  // found a longer LIS ending at i
          cnt[i] = cnt[j];      // adopt predecessor's count exactly
        } else if (len[j] + 1 === len[i]) {
          cnt[i] += cnt[j];     // another path with the same best length
        }
      }
    }
  }

  const maxLen = Math.max(...len);
  // Sum counts of all positions that achieve the maximum LIS length
  return len.reduce((acc, l, i) => acc + (l === maxLen ? cnt[i] : 0), 0);
}
```

### Dry Run

## Problem 7 — Minimum ASCII Delete Sum for Two Strings

### Problem

Given two strings `s1` and `s2`, return the lowest ASCII sum of deleted characters to make `s1` and `s2` equal.

```
Input: s1 = "sea", s2 = "eat"  → 231
  // Delete 's'(115) from "sea" and 't'(116) from "eat": "ea" == "ea". 115+116=231.
Input: s1 = "delete", s2 = "leet" → 403
  // Delete 'd','e','e'(100+101+101=302) from s1; delete 'e'(101) from s2: "let"=="let". 302+101=403.
```

### Pattern Recognition
Weighted two-sequence DP — a variant of LCS where instead of maximizing count of matched characters, we maximize the sum of ASCII values of matched characters (the "weighted LCS"), then subtract from the total ASCII sum.

### Key Insight
Equivalent formulation: minimize sum of ASCII values deleted = total ASCII sum of both strings minus 2 × (sum of ASCII values of characters in the longest common subsequence weighted by ASCII). So `answer = sum(s1) + sum(s2) - 2 × maxMatchASCII`, where `maxMatchASCII` is solved by a DP that maximizes ASCII value of common characters. Direct DP: `dp[i][j]` = minimum ASCII delete sum to equalize `s1[0..i-1]` and `s2[0..j-1]`. This is equivalent to the standard LCS DP with ASCII values as weights.

### Solution

```js
function minimumDeleteSum(s1, s2) {
  const m = s1.length, n = s2.length;
  // dp[i][j] = min ASCII sum to delete to equalize s1[0..i-1] and s2[0..j-1]
  const dp = Array.from({ length: m+1 }, () => new Array(n+1).fill(0));

  // Base: delete all of s1 prefix to match empty s2
  for (let i = 1; i <= m; i++) dp[i][0] = dp[i-1][0] + s1.charCodeAt(i-1);
  // Base: delete all of s2 prefix to match empty s1
  for (let j = 1; j <= n; j++) dp[0][j] = dp[0][j-1] + s2.charCodeAt(j-1);

  for (let i = 1; i <= m; i++) {
    for (let j = 1; j <= n; j++) {
      if (s1[i-1] === s2[j-1]) {
        dp[i][j] = dp[i-1][j-1]; // keep both characters: no deletion cost
      } else {
        dp[i][j] = Math.min(
          dp[i-1][j] + s1.charCodeAt(i-1), // delete s1[i-1]
          dp[i][j-1] + s2.charCodeAt(j-1)  // delete s2[j-1]
        );
      }
    }
  }

  return dp[m][n];
}
```

### Dry Run

```

  dp[0][0]=0. dp[1][0]=115('s'). dp[2][0]=216('se'). dp[3][0]=313('sea').
  dp[0][1]=101('e'). dp[0][2]=198('ea'). dp[0][3]=314('eat').

  j=1 (s2[0]='e'): 's'≠'e' → min(dp[0][1]+115=216, dp[1][0]+101=216) = 216.
```

### Complexity
- Time: O(mn). Space: O(mn); O(min(m,n)) with rolling rows.

### Edge Cases
- Empty s1: delete everything from s2; answer = sum(ASCII of s2).
- Identical strings: no deletions needed; answer = 0.
- No common characters: must delete everything from both strings; answer = sum(s1) + sum(s2).

### Follow-up Questions
- "Return which characters to delete?" — Backtrack the DP table: when `s1[i-1] == s2[j-1]`, go diagonal (no deletion); otherwise go toward the smaller neighbor, collecting the deleted character.
- "Minimum deletions (count, not ASCII sum)?" — This is `m + n - 2 × LCS(s1, s2)` by the identity from Q8 — or equivalently, replace `charCodeAt(i-1)` with `1` throughout.

```
│   │
│   ├── Match = no cost; mismatch = min of 3 operations → Edit Distance
│   │   dp[i][j] = dp[i-1][j-1]  or  1+min(dp[i-1][j], dp[i][j-1], dp[i-1][j-1])
│   │
│   ├── Match = sum counts; mismatch = don't use s1's char
│   │   → Distinct Subsequences: dp[i][j] = dp[i-1][j] + (match?dp[i-1][j-1]:0)
│   │
│   └── Match = keep char (no cost); mismatch = pay to delete → Min ASCII Delete Sum
│         dp[i][j] = dp[i-1][j-1]  or  min(dp[i-1][j]+cost1, dp[i][j-1]+cost2)
│
├── ONE SEQUENCE — find increasing/decreasing/monotone pattern?
│   ├── Length of LIS, O(n²) → dp[i] = 1+max(dp[j] for j<i, nums[j]<nums[i])
│   ├── Length of LIS, O(n log n) → patience sort: tails array + binary search
│   │     Strict: lower_bound (find first tails[pos]>=x, use <)
│   │     Non-decreasing: upper_bound (find first tails[pos]>x, use <=)

│   └── Reconstruct LIS → parent[] array + tailIdx[] alongside tails

│   └── Min insertions to palindrome → n - LPS(s)
│

│   └── Sort dim1 ASC, dim2 DESC for equal dim1 → LIS on dim2 only
│       Critical: DESC sort prevents multiple same-dim1 envelopes from being selected
│
└── COMMON IDENTIFIERS:

    One sequence, "increasing"/"decreasing"/"chain": → LIS family
    "Transform"/"edit": → edit distance
    "Palindrome"+"subsequence": → LPS = LCS(s, rev(s))
```

## Common Bugs Checklist

Before submitting any LCS or LIS solution, verify:

1. **LCS off-by-one: accessing `s1[i]` instead of `s1[i-1]` inside the 1-indexed table?** — The DP table is 1-indexed: row i corresponds to the prefix of length i, meaning the character compared is `s1[i-1]` (0-indexed into the string), not `s1[i]`. Writing `s1[i]` skips the first character of s1 and compares the wrong character, producing a silently wrong LCS that may be off by 1 or more. Mnemonic: "i in the table = i characters considered = index i-1 in the string."

2. **Edit distance base cases forgotten or reversed?** — `dp[i][0] = i` (convert s1[0..i-1] to empty = delete i chars); `dp[0][j] = j` (convert empty to s2[0..j-1] = insert j chars). A common mistake: setting all base cases to 0 (treating them as empty-to-empty). This causes the algorithm to think it costs 0 edits to reach any prefix, severely underestimating the answer. Another mistake: swapping them (`dp[i][0] = j` or `dp[0][j] = i`).

3. **LCS space-optimized: forgetting `diagVal` when rolling rows?** — The rolling-row optimization updates `dp[j]` in-place. When computing the match case `dp[i][j] = dp[i-1][j-1] + 1`, `dp[i-1][j-1]` in the compressed form is `prev[j-1]` from the previous row. But if `curr` overwrites `dp[j-1]` before `dp[j]` is computed (since we iterate j left-to-right in one row), `prev[j-1]` might already be the current row's value. Fix: store `diagVal = prev[j-1]` before updating `prev[j-1]` (after computing `curr[j-1]`), then use `diagVal` for the match case.

4. **LIS O(n log n): tails.length (not max(tails)) is the LIS length?** — `tails` is an artifact — it contains the smallest possible tails of various-length subsequences, *not* an actual LIS. Its *length* is the LIS length. `Math.max(...tails)` is NOT the LIS length; it is the largest tail element, which is coincidentally the last element of tails if tails is sorted (which it always is), but it's a value, not a count. The LIS length is always `tails.length`.

5. **LIS: wrong binary search comparison for strict vs non-decreasing?** — For strict increase: binary search for the leftmost `tails[pos] >= x` — use `tails[mid] < x ? lo = mid+1 : hi = mid`. For non-decreasing: leftmost `tails[pos] > x` — use `tails[mid] <= x ? lo = mid+1 : hi = mid`. Using the non-decreasing comparison for strict LIS allows equal elements to coexist in tails, falsely extending the LIS with equal values (e.g., `[3,3,3]` would give tails=[3] correctly with strict, but tails=[3,3,3] with non-decreasing, falsely claiming LIS=3).

6. **Russian Doll Envelopes: sorting heights ascending (not descending) for equal widths?** — The descending sort is the whole trick. Sorting heights ascending for equal widths means same-width envelopes have increasing heights — the LIS on heights would happily select multiple same-width envelopes (since their heights form an increasing sequence), producing a wrong answer. Always: width ASC, then height DESC for ties.

7. **Number of LIS: count not initialized to 1?** — Each `cnt[i]` should start at 1 (the trivial LIS of just `nums[i]` alone). If initialized to 0, the accumulation logic never assigns a non-zero count (since no `cnt[j]` is ever added unless `len[j]+1 > len[i]` triggers `cnt[i] = cnt[j]`, which requires cnt[j] to already be correct). Initialize `cnt[i] = 1` for all i before the inner loop.

8. **Palindromic subsequence interval DP: not handling length-2 substrings separately?** — For `len=2`, the inner substring `s[i+1..j-1]` has length 0, so `dp[i+1][j-1]` should be 0 (empty palindrome). If `dp` is initialized to 0 (by default), this works for length 2 case only if `j = i+1`, since `dp[i+1][i]` (empty range where end < start) is 0. Make sure `dp` is initialized to 0 for all cells, and guard the diagonal fill: `dp[i][j] = (s[i] === s[j]) ? (len === 2 ? 0 : dp[i+1][j-1]) + 2 : max(dp[i+1][j], dp[i][j-1])`.

9. **LCS reconstruction: not reversing the collected result?** — Backtracking from `(m,n)` to `(0,0)` collects characters in reverse order (last LCS character first). `result.push(s1[i-1])` adds the last matched character before the first matched one. Returning `result.join('')` without reversing gives the LCS backward. Always: `return result.reverse().join('')` after the backtracking loop.

10. **LIS O(n²): taking max of dp[i] over wrong range or using the initial value wrong?** — `dp[i]` must be initialized to 1 (not 0): a single element always forms an LIS of length 1. If initialized to 0, no predecessor is found for the global minimum element → dp stays 0 → incorrect. Also, the final answer is `Math.max(...dp)`, not `dp[n-1]` — the LIS need not end at the last element. A common mistake: returning `dp[n-1]` (the LIS ending at the last position), which is wrong whenever the actual LIS ends earlier.

---

**Final Tip:** At the 5 YOE level, the decisive signal for LCS problems is naming *what the three dependency cells in `dp[i][j]` represent semantically* — not just reciting the formula. *"`dp[i-1][j-1]`is the LCS of both prefixes without their last characters — the sub-problem we solve when we match the two last characters and include both in the LCS. `dp[i-1][j]` is the best LCS achievable if we decide `s1[i-1]` is NOT in the optimal LCS — we skip it. `dp[i][j-1]` is the best LCS achievable if `s2[j-1]` is NOT in the optimal LCS — we skip it. The match case takes the diagonal-plus-one because when both last characters are equal, including both in the LCS is always at least as good as any alternative."* For LIS problems: *"the `tails` array's invariant — `tails[k]` is the minimum possible tail of any increasing subsequence of length k+1 among all elements processed so far — is why the array is always sorted and why binary search is valid. We replace `tails[pos]` with x not because x is better in isolation, but because a smaller tail is a better 'springboard' for future extensions: a subsequence of the same length but with a smaller tail can be extended by more future elements than one with a larger tail."* And for the Russian Dolls trick: *"sorting heights descending for equal widths ensures that any two envelopes in the same width group form a decreasing height sequence — the LIS algorithm, which seeks increasing sequences, can select at most one from any such decreasing group, which is precisely the constraint that equal-width envelopes cannot nest inside each other."*
