## Topic A: Shortest Path Fundamentals

### Section A1: Fundamentals

**Q1. What is the shortest path problem, and what are its three main variants?**
A: The shortest path problem asks: given a weighted graph and one or more source nodes, find the minimum-cost path (sum of edge weights) to one or more destination nodes. The three main variants differ in source and destination scope:

- **Single-source, single-destination**: shortest path from one fixed source `s` to one fixed destination `t`. In practice, all single-source algorithms compute all destinations simultaneously — stopping early at `t` is possible but rarely improves worst-case complexity.
- **Single-source, all-destinations (SSSP)**: shortest path from one fixed source `s` to every other vertex. Dijkstra's and Bellman-Ford solve this.
- **All-pairs (APSP)**: shortest path between every pair of vertices. Floyd-Warshall solves this directly; running Dijkstra's or Bellman-Ford from each vertex also works.

```
Single-source (from s):           All-pairs:
s → a: 3                          dist[i][j] for all i, j
s → b: 7
s → c: 2
```

**Q2. What are the three shortest path algorithms, and what is the single most important distinguishing factor between them?**
A: The three algorithms and their distinguishing factor — **whether negative edge weights are allowed**:

| Algorithm | Negative weights | Negative cycles | Source model | Time complexity |
|---|---|---|---|---|
| Dijkstra's | ❌ No | ❌ No | Single source | O((V + E) log V) |
| Bellman-Ford | ✅ Yes | ✅ Detects | Single source | O(V · E) |
| Floyd-Warshall | ✅ Yes | ✅ Detects | All pairs | O(V³) |

Dijkstra's is the fastest for non-negative weights. Bellman-Ford handles negative weights but is slower. Floyd-Warshall computes all-pairs in one pass — preferable when all pairwise distances are needed and V is small (V ≤ 500 or so).

**Q3. What is edge relaxation, and why is it the core operation shared by all three algorithms?**
A: Edge relaxation is the fundamental operation: given an edge `(u, v, w)`, check whether the known shortest distance to `v` can be improved by going through `u`. If `dist[u] + w < dist[v]`, update `dist[v] = dist[u] + w`. All three algorithms are defined by *how* and *in what order* they apply relaxation:

```js
function relax(u, v, w, dist) {
  if (dist[u] + w < dist[v]) {
    dist[v] = dist[u] + w;
    return true; // relaxation was productive
  }
  return false;
}
```

- **Dijkstra's**: relaxes edges in order of current shortest known distance from source — always processes the globally nearest unvisited vertex next (greedy).
- **Bellman-Ford**: relaxes all edges V-1 times in arbitrary order — guarantees convergence by the structure of shortest paths (at most V-1 edges in any simple shortest path).
- **Floyd-Warshall**: relaxes through intermediate vertices — for each triple `(i, k, j)`, checks if going `i → k → j` improves `dist[i][j]`.

**Q4. What does it mean for a shortest path algorithm to be "correct," and what assumption does each algorithm require?**
A: A shortest path algorithm is correct if `dist[v]` converges to the true shortest distance for every reachable vertex `v`. The required assumptions:

- **Dijkstra's**: no negative edge weights. The greedy property — once a vertex is finalized (popped from the priority queue), its distance is optimal — only holds when all weights are non-negative. A negative edge could create a shorter path through an already-finalized vertex, violating the invariant.
- **Bellman-Ford**: no negative-weight cycles reachable from the source. A negative cycle allows arbitrarily short paths (walk the cycle repeatedly to decrease cost infinitely) — "shortest path" becomes undefined. Bellman-Ford *detects* negative cycles (but cannot produce a shortest path through them).
- **Floyd-Warshall**: handles negative edges. Detects negative cycles via the diagonal: if `dist[i][i] < 0` after the algorithm, node `i` is on a negative cycle.

**Q5. What is the "shortest path tree," and why is storing the predecessor array (`prev`) important?**
A: The shortest path tree is a spanning tree of the graph rooted at the source, where the unique path from source to any vertex `v` in the tree is a shortest path in the original graph. The predecessor array `prev[v]` stores the node immediately before `v` on the shortest path from source — enabling path reconstruction by backtracking from destination to source.

```js
// Path reconstruction using prev array:
function reconstructPath(prev, source, dest) {
  const path = [];
  let curr = dest;
  while (curr !== null && curr !== undefined) {
    path.push(curr);
    curr = prev[curr];
  }
  if (path[path.length - 1] !== source) return []; // no path exists
  return path.reverse(); // source → ... → dest
}

// During relaxation, update prev:
if (dist[u] + w < dist[v]) {
  dist[v] = dist[u] + w;
  prev[v] = u; // v is now reached optimally through u
}
```

The predecessor array adds O(V) space and transforms "what is the shortest distance?" into "what is the shortest path?" — a distinction interviewers frequently probe.

### Section A2: Advanced Patterns

**Q6. What is the priority queue variant of Dijkstra's, and why does it outperform the naive O(V²) version?**
A: The naive Dijkstra's scans all unvisited vertices to find the minimum-distance one — O(V) per extraction, O(V²) total. The priority queue (min-heap) variant stores `(distance, vertex)` pairs and always extracts the minimum in O(log V). Edge relaxations push updated distances as new entries rather than decreasing existing ones (decrease-key), giving O(E log V) total — a significant improvement for sparse graphs where E << V².

```
Naive Dijkstra:          O(V²)         — optimal for dense graphs (E ≈ V²)
Binary heap Dijkstra:    O((V+E) log V) — optimal for sparse graphs (E << V²)
Fibonacci heap Dijkstra: O(V log V + E) — theoretical optimum, rarely implemented
```

The "lazy deletion" trick in the binary heap version: when a shorter path to `v` is found, push a new `(dist, v)` entry rather than decreasing the existing key. When a vertex is popped, check if its stored distance equals the current best — if not, skip it (it's a stale entry). This avoids implementing decrease-key at the cost of slightly more heap entries.

**Q7. Why does Dijkstra's fail with negative edge weights? Provide a concrete counterexample.**
A: Consider:

```
Graph:  A → B (weight 1)
        A → C (weight 4)
        C → B (weight -10)

Source: A. Correct shortest path to B: A→C→B = 4 + (-10) = -6.

Dijkstra's execution:
  dist = {A:0, B:∞, C:∞}
  Extract A (dist=0). Relax: dist[B]=1, dist[C]=4.
  Extract B (dist=1). B is FINALIZED. (dist[B]=1 recorded as optimal)
  Extract C (dist=4). Relax: dist[B] = min(1, 4-10) = -6.
  But B is already finalized — Dijkstra's ignores this update.

Result: dist[B] = 1. Correct answer: -6. ✗
```

The invariant "extracted vertices have optimal distances" breaks the moment a negative edge can improve an already-finalized vertex's distance. Bellman-Ford avoids this by not finalizing distances until all V-1 rounds of relaxation complete.

**Q8. What is Bellman-Ford's proof of correctness — why exactly V-1 iterations?**
A: In any graph with V vertices, any simple shortest path (no repeated vertices — a cycle would only add cost if no negative cycles exist) has at most V-1 edges. After k iterations of relaxing all edges, Bellman-Ford guarantees that `dist[v]` is correct for all paths using at most k edges. Therefore after V-1 iterations, all shortest paths (which use at most V-1 edges) are correctly computed.

Formal induction: after iteration 1, all 1-hop shortest paths are correct. After iteration 2, all 2-hop shortest paths are correct. After iteration k, all k-hop shortest paths are correct. Since no simple shortest path has more than V-1 hops, V-1 iterations suffice.

```
V vertices → at most V-1 edges in any simple path.
After k iterations: dist[v] = shortest path using ≤ k edges.
After V-1 iterations: dist[v] = true shortest path. ✓

Negative cycle detection: if ANY relaxation succeeds in iteration V,
a path shorter than V-1 edges exists → must use a cycle → negative cycle.
```

**Q9. How does Floyd-Warshall use dynamic programming, and what does `dist[i][k][j]` mean conceptually?**
A: Floyd-Warshall is a 3D DP where `dist[k][i][j]` = shortest path from `i` to `j` using only vertices `{0, 1, ..., k}` as intermediate nodes. The recurrence:

```
dist[k][i][j] = min(
  dist[k-1][i][j],           // don't use vertex k as intermediate
  dist[k-1][i][k] + dist[k-1][k][j]  // use vertex k as intermediate
)
```

Since `dist[k][i][k] = dist[k-1][i][k]` and `dist[k][k][j] = dist[k-1][k][j]` (the path to/from k itself doesn't change when k is added as an intermediate), the 3D array reduces to 2D — the `k` dimension can be updated in-place:

```js
for (let k = 0; k < n; k++)      // try each vertex as intermediate
  for (let i = 0; i < n; i++)    // for each source
    for (let j = 0; j < n; j++)  // for each destination
      dist[i][j] = Math.min(dist[i][j], dist[i][k] + dist[k][j]);
```

The outer loop over `k` is the DP "stage" — at the end of stage `k`, `dist[i][j]` equals the shortest path from `i` to `j` through any subset of `{0, ..., k}`. The initialization: `dist[i][i] = 0`, `dist[i][j] = weight(i,j)` if edge exists, else `Infinity`.

**Q10. What is the SPFA (Shortest Path Faster Algorithm), and when is it useful?**
A: SPFA is a queue-based optimization of Bellman-Ford: instead of relaxing all edges every iteration, maintain a queue of vertices whose distances were recently improved. Only relax edges from queued vertices — avoiding redundant relaxation of already-stable vertices. In the best case (sparse graphs, few improvements), SPFA runs in O(E); worst case (adversarial inputs, dense negative-weight graphs) degrades to O(V·E) like Bellman-Ford.

```js
function spfa(graph, source, n) {
  const dist = new Array(n).fill(Infinity);
  const inQueue = new Array(n).fill(false);
  dist[source] = 0;
  const queue = [source];
  inQueue[source] = true;

  while (queue.length > 0) {
    const u = queue.shift();
    inQueue[u] = false;

    for (const [v, w] of graph[u]) {
      if (dist[u] + w < dist[v]) {
        dist[v] = dist[u] + w;
        if (!inQueue[v]) { queue.push(v); inQueue[v] = true; }
      }
    }
  }
  return dist;
}
```

SPFA is useful for competitive programming with mixed positive/negative weights (no negative cycles) — faster than Bellman-Ford in practice but lacks the worst-case guarantee of Dijkstra's. In interviews, Bellman-Ford is the standard expected answer for negative-weight graphs.

## Topic B: Dijkstra's Algorithm

### Section B1: Fundamentals

**Q11. Walk through Dijkstra's algorithm step by step with the priority queue implementation.**
A: Dijkstra's maintains a priority queue (min-heap) of `(distance, vertex)` pairs and a `dist` array initialized to Infinity (except source = 0). At each step: extract the minimum-distance vertex `u`; for each neighbor `v` of `u`, relax the edge — if `dist[u] + weight(u,v) < dist[v]`, update `dist[v]` and push `(dist[v], v)` to the heap.

```js
function dijkstra(graph, source, n) {
  const dist = new Array(n).fill(Infinity);
  const prev = new Array(n).fill(null);
  dist[source] = 0;

  // Min-heap: [distance, vertex]
  // JavaScript doesn't have a built-in min-heap — simulate with a sorted approach
  // or use a proper MinHeap class. Here we show the logic clearly:
  const heap = [[0, source]]; // [dist, node]

  while (heap.length > 0) {
    // Extract minimum (in practice: heap.pop() from a proper min-heap)
    heap.sort((a, b) => a[0] - b[0]); // O(n log n) — use real heap in production
    const [d, u] = heap.shift();

    // Lazy deletion: skip stale entries
    if (d > dist[u]) continue;

    for (const [v, w] of (graph[u] || [])) {
      const newDist = dist[u] + w;
      if (newDist < dist[v]) {
        dist[v] = newDist;
        prev[v] = u;
        heap.push([newDist, v]);
      }
    }
  }

  return { dist, prev };
}
```

**Q12. What is the "lazy deletion" pattern in Dijkstra's, and why is it correct?**
A: When a shorter path to `v` is found, the old `(oldDist, v)` entry remains in the heap alongside the new `(newDist, v)`. When `(oldDist, v)` is later extracted, `oldDist > dist[v]` (the current best) — this is the stale entry. The `if (d > dist[u]) continue` guard skips it. This is correct because: (a) the earlier, correct `(newDist, v)` entry was already extracted and processed; (b) processing a stale entry would recompute distances already found to be optimal, wasting work but not corrupting correctness. The cost: the heap may hold O(E) entries instead of O(V), raising complexity from O((V+E) log V) to O(E log E) = O(E log V) — the same asymptotically.

**Q13. How does Dijkstra's extend to finding the k-shortest paths?**
A: Yen's algorithm extends Dijkstra's to k-shortest simple paths. A simpler variant for k-shortest paths (allowing repeated vertices): modify Dijkstra's to pop each vertex up to k times instead of skipping it after the first pop. When a vertex `v` is popped for the kth time, its kth shortest path distance is recorded. This works because each pop of `v` from the min-heap corresponds to the next-shortest way to reach `v`. O(kE log V) time — a direct extension of the standard algorithm.

**Q14. What modifications are needed to handle multiple sources or multiple destinations in Dijkstra's?**
A: **Multiple sources**: initialize `dist[s] = 0` for all source nodes `s` and push all of them into the heap simultaneously. The algorithm naturally computes the shortest distance from the nearest source to every vertex — equivalent to adding a virtual super-source connected to all real sources with zero-weight edges.

**Multiple destinations (single target)**: run standard Dijkstra's from the source; stop as soon as the target is extracted from the heap (its distance is finalized). No modification to the algorithm — just add an early termination check.

**Multiple pairs**: run Dijkstra's once per source for all-pairs on sparse graphs with non-negative weights — O(V · E log V) total, better than Floyd-Warshall's O(V³) when E << V².

### Section B2: Advanced Patterns

**Q15. What is "0-1 BFS," and when does it replace Dijkstra's?**
A: 0-1 BFS applies when edge weights are either 0 or 1 (binary weights). Using a standard BFS queue: push 0-weight neighbors to the front of the deque (they don't increase distance), push 1-weight neighbors to the back (they increase distance by 1). This achieves O(V + E) — faster than Dijkstra's O((V+E) log V) by exploiting the restricted weight structure.

```js
function bfs01(graph, source, n) {
  const dist = new Array(n).fill(Infinity);
  dist[source] = 0;
  const deque = [source]; // use a deque (front/back operations)

  while (deque.length > 0) {
    const u = deque.shift(); // pop front
    for (const [v, w] of graph[u]) {
      if (dist[u] + w < dist[v]) {
        dist[v] = dist[u] + w;
        if (w === 0) deque.unshift(v); // push front (0-weight: same level)
        else         deque.push(v);    // push back  (1-weight: next level)
      }
    }
  }
  return dist;
}
```

0-1 BFS is the key technique for problems like "minimum flips to make a binary matrix connected" or "minimum cost path with free passes."

**Q16. How does Dijkstra's apply to the "network delay time" problem, and what is the termination condition?**
A: Network delay time asks: given a network of nodes with weighted directed edges representing signal propagation times, find the time for a signal sent from source `k` to reach all nodes. This is a direct SSSP: run Dijkstra's from `k`; the answer is `max(dist)` over all reachable nodes. If any node is unreachable (`dist[v] = Infinity`), return -1. The termination condition is natural — process all reachable nodes; the maximum final distance is the answer.

## Topic C: Bellman-Ford Algorithm

### Section C1: Fundamentals

**Q17. Walk through the Bellman-Ford algorithm step by step.**
A: Bellman-Ford initializes `dist[source] = 0`, all others Infinity. Then runs V-1 iterations, each relaxing all edges. After V-1 iterations, run one more iteration — if any relaxation succeeds, a negative cycle is reachable from the source.

```js
function bellmanFord(edges, source, n) {
  // edges: array of [u, v, weight]
  const dist = new Array(n).fill(Infinity);
  const prev = new Array(n).fill(null);
  dist[source] = 0;

  // V-1 relaxation rounds
  for (let i = 0; i < n - 1; i++) {
    let updated = false;
    for (const [u, v, w] of edges) {
      if (dist[u] !== Infinity && dist[u] + w < dist[v]) {
        dist[v] = dist[u] + w;
        prev[v] = u;
        updated = true;
      }
    }
    if (!updated) break; // early termination: no improvement → converged
  }

  // Negative cycle detection: one extra round
  for (const [u, v, w] of edges) {
    if (dist[u] !== Infinity && dist[u] + w < dist[v]) {
      return { dist: null, hasNegativeCycle: true }; // cycle detected
    }
  }

  return { dist, prev, hasNegativeCycle: false };
}
```

The `if (!updated) break` early termination optimization: if an entire round produces no relaxation, the algorithm has converged — no further iterations will change anything. This brings the best case to O(E) (already converged after 1 round) while maintaining O(V·E) worst case.

**Q18. How does Bellman-Ford detect and report which vertices are affected by a negative cycle?**
A: Run the standard V-1 iterations. Then run a Vth iteration — any vertex `v` whose distance is updated in this round is either on a negative cycle or reachable from one. To find all vertices affected by negative cycles, use BFS/DFS from all such `v` vertices discovered in round V — all vertices reachable from these are also affected (their "shortest path" is -Infinity).

```js
// After V-1 rounds, find negative-cycle-affected vertices:
const affected = new Array(n).fill(false);

// Vth round: mark directly affected vertices
for (const [u, v, w] of edges) {
  if (dist[u] !== Infinity && dist[u] + w < dist[v]) {
    affected[v] = true;
    dist[v] = -Infinity; // mark as negative-infinity
  }
}

// BFS/DFS from affected vertices to mark all downstream nodes
const queue = [...affected.keys()].filter(i => affected[i]);
while (queue.length > 0) {
  const u = queue.shift();
  for (const [nu, v, w] of edges) {
    if (nu === u && !affected[v]) {
      affected[v] = true;
      dist[v] = -Infinity;
      queue.push(v);
    }
  }
}
```

**Q19. What is the relationship between Bellman-Ford and dynamic programming on DAGs?**
A: On a DAG (no cycles, so no negative cycle concern), shortest paths can be computed in O(V + E) using a topological order — process vertices in topological order, relaxing outgoing edges from each. This is Bellman-Ford specialized to DAGs: since the topological order ensures each vertex is processed after all its predecessors, a single pass (1 "iteration") suffices instead of V-1.

```js
function dagShortestPath(graph, topoOrder, source) {
  const dist = new Array(topoOrder.length).fill(Infinity);
  dist[source] = 0;

  for (const u of topoOrder) {
    if (dist[u] === Infinity) continue; // unreachable from source
    for (const [v, w] of graph[u]) {
      dist[v] = Math.min(dist[v], dist[u] + w);
    }
  }
  return dist;
}
```

This O(V + E) DAG shortest path is the foundation for dynamic programming on sequences (LIS, edit distance, coin change) when modeled as DAG paths — every DP recurrence is a shortest (or longest) path on an implicit DAG.

### Section C2: Advanced Patterns

**Q20. How is Bellman-Ford used in distance-vector routing protocols?**
A: Distance-vector routing (used in RIP — Routing Information Protocol) is a distributed implementation of Bellman-Ford: each router maintains a distance vector (estimated cost to every destination) and periodically exchanges it with neighbors. On receiving a neighbor's vector, each router updates its own by checking if going through the neighbor improves any distance — exactly the relaxation step. After sufficient exchanges (at most V-1 rounds in a network of V routers), all distances converge to the true shortest paths. The "count to infinity" problem (slow convergence after a link failure) is a known issue with naive distance-vector routing, solved by split-horizon or poison-reverse — essentially detecting and breaking negative feedback cycles.

**Q21. What is the "cheapest flights within k stops" problem, and why does it use a Bellman-Ford variant?**
A: The problem asks for the cheapest flight from source to destination with at most k stops (k+1 edges). Standard Dijkstra's doesn't directly support the "at most k edges" constraint. Bellman-Ford naturally does: after exactly `i` iterations, `dist[v]` = cheapest path using at most `i` edges. Run only `k+1` iterations (not V-1), using a **copy** of the previous iteration's distances to prevent using more than the allowed edges in one round.

```js
function findCheapestPrice(n, flights, src, dst, k) {
  let dist = new Array(n).fill(Infinity);
  dist[src] = 0;

  for (let i = 0; i <= k; i++) {     // k stops = k+1 edges = k+1 iterations
    const next = [...dist];            // copy to prevent using new distances in same round
    for (const [u, v, w] of flights) {
      if (dist[u] !== Infinity && dist[u] + w < next[v]) {
        next[v] = dist[u] + w;
      }
    }
    dist = next;
  }

  return dist[dst] === Infinity ? -1 : dist[dst];
}
```

The copy (`next = [...dist]`) is critical: using the same array would allow paths longer than `i` edges within a single iteration — the classic Bellman-Ford "use previous round's values" discipline.

## Topic D: Floyd-Warshall Algorithm

### Section D1: Fundamentals

**Q22. Walk through Floyd-Warshall initialization and the triple loop.**
A: Floyd-Warshall initializes a 2D matrix `dist[i][j]`:
- `dist[i][i] = 0` for all `i` (distance to self).
- `dist[i][j] = weight(i, j)` if edge `(i, j)` exists.
- `dist[i][j] = Infinity` if no edge from `i` to `j`.

Then the triple loop: for each intermediate vertex `k`, for each source `i`, for each destination `j`, update `dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])`. The outer loop over `k` is the DP stage — at stage `k`, all shortest paths through vertices `{0, ..., k}` are computed.

```js
function floydWarshall(n, edges) {
  // Initialize distance matrix
  const dist = Array.from({ length: n }, (_, i) =>
    Array.from({ length: n }, (_, j) => (i === j ? 0 : Infinity))
  );

  // Set direct edge weights
  for (const [u, v, w] of edges) {
    dist[u][v] = Math.min(dist[u][v], w); // handle multiple edges: take minimum
  }

  // Triple loop: try each vertex k as an intermediate
  for (let k = 0; k < n; k++) {
    for (let i = 0; i < n; i++) {
      for (let j = 0; j < n; j++) {
        if (dist[i][k] !== Infinity && dist[k][j] !== Infinity) {
          dist[i][j] = Math.min(dist[i][j], dist[i][k] + dist[k][j]);
        }
      }
    }
  }

  // Negative cycle detection: dist[i][i] < 0 for any i
  for (let i = 0; i < n; i++) {
    if (dist[i][i] < 0) return { dist: null, hasNegativeCycle: true };
  }

  return { dist, hasNegativeCycle: false };
}
```

**Q23. Why does the order of the three loops matter — specifically, why must `k` be the outermost loop?**
A: The correctness of Floyd-Warshall depends on the DP invariant: when computing `dist[i][j]` using intermediate vertex `k`, the values `dist[i][k]` and `dist[k][j]` must represent shortest paths using only intermediates from `{0, ..., k-1}`. If `k` is not the outermost loop — say `i` or `j` is outermost — then `dist[i][k]` or `dist[k][j]` may have already been updated to use intermediates beyond `{0, ..., k-1}`, violating the DP invariant and producing incorrect results.

```
Correct (k outermost):
  At k=2, dist[i][2] = shortest path i→2 using only {0,1} as intermediates. ✓
  At k=2, dist[2][j] = shortest path 2→j using only {0,1} as intermediates. ✓
  → dist[i][j] through k=2 is correct.

Wrong (i outermost):
  When i=3, j=1, k=2: dist[3][2] might already use k=3 as intermediate (updated
  in an earlier i iteration) → the invariant is violated → incorrect result. ✗
```

**Q24. How does Floyd-Warshall handle path reconstruction (not just distances)?**
A: Maintain a `next[i][j]` matrix alongside `dist[i][j]`. Initialize `next[i][j] = j` if there's a direct edge from `i` to `j`, else `null`. When `dist[i][j]` is updated through `k`: set `next[i][j] = next[i][k]` (the first step from `i` toward `k` is also the first step toward the now-optimal path `i→j`). To reconstruct the path from `i` to `j`: follow `next[i][j]` until reaching `j`.

```js
// Initialization:
const next = Array.from({ length: n }, () => new Array(n).fill(null));
for (const [u, v] of edges) next[u][v] = v;
for (let i = 0; i < n; i++) next[i][i] = i;

// In the triple loop, when dist[i][j] is improved through k:
if (dist[i][k] + dist[k][j] < dist[i][j]) {
  dist[i][j] = dist[i][k] + dist[k][j];
  next[i][j] = next[i][k]; // first step from i is still the first step toward k
}

// Path reconstruction:
function getPath(next, i, j) {
  if (next[i][j] === null) return []; // no path
  const path = [i];
  while (i !== j) { i = next[i][j]; path.push(i); }
  return path;
}
```

### Section D2: Advanced Patterns

**Q25. What is the transitive closure problem, and how does Floyd-Warshall solve it?**
A: The transitive closure of a directed graph is a matrix `reach[i][j]` where `reach[i][j] = true` if there is any path from vertex `i` to vertex `j` (regardless of weight). Replace the Floyd-Warshall distance matrix with a boolean reachability matrix: instead of `min(dist[i][j], dist[i][k] + dist[k][j])`, use `reach[i][j] = reach[i][j] || (reach[i][k] && reach[k][j])`. This is Warshall's original algorithm (Floyd added the weighted generalization).

```js
function transitiveClosure(n, edges) {
  const reach = Array.from({ length: n }, (_, i) =>
    Array.from({ length: n }, (_, j) => i === j) // reach[i][i] = true
  );
  for (const [u, v] of edges) reach[u][v] = true;

  for (let k = 0; k < n; k++)
    for (let i = 0; i < n; i++)
      for (let j = 0; j < n; j++)
        reach[i][j] = reach[i][j] || (reach[i][k] && reach[k][j]);

  return reach;
}
```

**Q26. When is Floyd-Warshall preferable to running Dijkstra's V times?**
A: Floyd-Warshall is preferable when: (1) **negative weights exist** — Dijkstra's can't be used; (2) **the graph is dense** (E ≈ V²) — Floyd-Warshall O(V³) vs. V × Dijkstra's O(V · V² log V) = O(V³ log V), so Floyd-Warshall wins; (3) **V is small** (V ≤ 500) — the constant in O(V³) is very small (3 nested loops, simple operations); (4) **implementation simplicity matters** — 10 lines of code vs. V calls to a complete Dijkstra implementation.

Running V × Dijkstra's is preferable when: (1) **the graph is sparse** (E << V²) — V × O(E log V) = O(VE log V) << O(V³) for sparse graphs; (2) **only a subset of all-pairs distances are needed** — run Dijkstra's only from the needed sources.

## Topic E: Cross-Topic & Interview-Style Questions

**Q27. "Given a weighted graph, how do you decide which algorithm to use?"**
A: I apply a three-question decision tree in order:

1. **Are there negative edge weights?**
   - No → Dijkstra's (single source) or V × Dijkstra's (all-pairs for sparse graphs).
   - Yes → proceed to question 2.

2. **Do I need single-source or all-pairs distances?**
   - Single source → Bellman-Ford (handles negatives, detects negative cycles).
   - All pairs → Floyd-Warshall (handles negatives, detects negative cycles, O(V³)).

3. **Are there constraints on path length (e.g., at most k edges)?**
   - Yes → Modified Bellman-Ford (run exactly k iterations with copied arrays).
   - No → standard algorithm from above.

Special cases: 0-1 weights → 0-1 BFS (O(V+E)). DAG with any weights → topological order DP (O(V+E)). Unweighted graph → BFS (O(V+E)).

**Q28. "Bellman-Ford runs V-1 iterations over all edges. Can you optimize it for sparse graphs where most relaxations are no-ops?"**
A: Yes — two optimizations: (1) **Early termination**: if an entire iteration produces no relaxation (`updated = false`), the algorithm has converged — stop immediately. Best case O(E), worst case O(V·E). (2) **SPFA (queue-based)**: maintain a queue of vertices whose distances changed; only process outgoing edges from those vertices in the next iteration. Effectively O(E) in most practical cases, O(V·E) worst case. Both are valid interview answers — state the trade-off: SPFA is faster in practice but loses the simple worst-case guarantee of standard Bellman-Ford.

**Q29. "How would you find the shortest path in an unweighted graph?"**
A: Use BFS. In an unweighted graph, all edge weights are 1, so BFS naturally finds shortest paths by level: level 0 is the source, level 1 is all neighbors, level 2 is all neighbors' neighbors, etc. BFS is O(V + E) — strictly faster than any weighted shortest path algorithm. The BFS `dist` array (initialized to -1 or Infinity) serves as the distance array; the BFS parent array serves as the predecessor array for path reconstruction. Using Dijkstra's on an unweighted graph is correct but wasteful — it degrades to O((V+E) log V) for no benefit.

**Q30. "In one sentence each, state the core invariant maintained by each algorithm."**
A:
- **Dijkstra's**: the extracted-minimum vertex always has its final shortest distance — because all edge weights are non-negative, no future path through an unvisited vertex can improve an already-finalized distance.
- **Bellman-Ford**: after k iterations, `dist[v]` equals the true shortest path from source to `v` using at most k edges — because each iteration extends all known paths by one edge.
- **Floyd-Warshall**: after processing intermediate vertex `k`, `dist[i][j]` equals the shortest path from `i` to `j` using only vertices `{0, ..., k}` as intermediates — because the DP builds up the set of allowed intermediates one vertex at a time.

**Q31. "How do you handle graphs where multiple edges exist between the same pair of nodes?"**
A: For Dijkstra's and Bellman-Ford: multiple edges are handled naturally — the relaxation step considers each edge independently, always keeping the minimum. For Floyd-Warshall initialization: if multiple edges `(u, v)` exist, initialize `dist[u][v]` to the minimum weight among all parallel edges. During the triple loop, only the initialized minimum matters — the algorithm doesn't distinguish multiple edges from a single minimum-weight edge once the distance matrix is initialized.

**Q32. "What modifications are needed to find the longest path instead of shortest?"**
A: For **DAGs**: negate all edge weights and run the shortest path algorithm — the shortest path on negated weights is the longest path on original weights. Alternatively, use the same topological DP but replace `Math.min` with `Math.max`.

For **general graphs**: the longest simple path problem is NP-hard (equivalent to Hamiltonian path). No polynomial-time algorithm exists for general graphs. Bellman-Ford with negated weights would find the "shortest" path on negated graphs, but negative cycles (originally positive cycles) make shortest paths undefined. For Dijkstra's: negating weights introduces negative edges, which Dijkstra's cannot handle.

## Problem 1 — Network Delay Time (Dijkstra's)

### Problem
You are given a network of `n` nodes, labeled `1` to `n`, and a list of directed travel times `times[i] = [u, v, w]` (from node `u` to node `v` with travel time `w`). A signal is sent from node `k`. Return the minimum time for all nodes to receive the signal. If some nodes are unreachable, return -1.

```
Input:  times = [[2,1,1],[2,3,1],[3,4,1]], n=4, k=2
Output: 2
(Signal reaches 1 at t=1, reaches 3 at t=1, reaches 4 at t=2)

Input:  times = [[1,2,1]], n=2, k=2
Output: -1  (node 1 unreachable from node 2)
```

### Pattern Recognition
Single-source shortest path with non-negative weights → Dijkstra's algorithm. The answer is the maximum of all shortest path distances from source `k` — the time for the last node to receive the signal.

### Key Insight
All travel times are positive, so Dijkstra's invariant holds — each node finalized in the priority queue has its true minimum travel time. The answer is `max(dist[1..n])`: the signal reaches all nodes simultaneously from source `k`, and the total time is determined by the slowest (farthest) node. If any node is unreachable (`dist[v] = Infinity`), return -1.

### Approach
Build an adjacency list from `times`. Run Dijkstra's from node `k` (1-indexed). After processing all reachable nodes, find the maximum distance. Return -1 if any node is unreachable.

### Solution

```js
function networkDelayTime(times, n, k) {
  // Build adjacency list (1-indexed nodes)
  const graph = Array.from({ length: n + 1 }, () => []);
  for (const [u, v, w] of times) graph[u].push([v, w]);

  // Dijkstra's from source k
  const dist = new Array(n + 1).fill(Infinity);
  dist[k] = 0;

  // Min-heap: [distance, node] — using array sorted each step for clarity
  // In production: use a proper MinHeap for O(log n) extract-min
  const heap = [[0, k]];

  while (heap.length > 0) {
    heap.sort((a, b) => a[0] - b[0]);
    const [d, u] = heap.shift(); // extract minimum distance node

    // Lazy deletion: skip if we've already found a shorter path to u
    if (d > dist[u]) continue;

    for (const [v, w] of graph[u]) {
      const newDist = dist[u] + w;
      if (newDist < dist[v]) {
        dist[v] = newDist;
        heap.push([newDist, v]); // push new entry (lazy — old entry remains)
      }
    }
  }

  // Find the maximum distance among all nodes (1..n)
  let maxDist = 0;
  for (let i = 1; i <= n; i++) {
    if (dist[i] === Infinity) return -1; // node i unreachable
    maxDist = Math.max(maxDist, dist[i]);
  }

  return maxDist;
}
```

### Edge Cases

- "Return the order in which nodes receive the signal?" → Track the extraction order from the heap — nodes are extracted in non-decreasing distance order. The extraction sequence is the signal reception order.

## Problem 2 — Cheapest Flights Within K Stops (Bellman-Ford)

### Problem
There are `n` cities connected by some flights. Given an array `flights` where `flights[i] = [from, to, price]`, find the cheapest price from `src` to `dst` with at most `k` stops. Return -1 if no such route exists.

```
Input:  n=4, flights=[[0,1,100],[1,2,100],[2,0,100],[1,3,600],[2,3,200]],
        src=0, dst=3, k=1
Output: 700  (0→1→3, 1 stop, cost=100+600=700)

Input:  n=3, flights=[[0,1,100],[1,2,100],[0,2,500]], src=0, dst=2, k=1
Output: 200  (0→1→2, 1 stop, cost=200)
```

### Pattern Recognition
Bellman-Ford with exactly `k+1` iterations — the "at most k stops" constraint maps directly to "at most k+1 edges," and Bellman-Ford's iteration count controls the maximum number of edges used. Dijkstra's cannot directly enforce this edge-count constraint.

### Key Insight
After exactly `i` Bellman-Ford iterations, `dist[v]` = cheapest flight using at most `i` edges (i-1 stops). Run `k+1` iterations. The critical correctness requirement: use a **copied distance array** from the previous round when computing the current round — this prevents "chaining" multiple relaxations within the same round, which would allow paths using more than `i` edges in a single iteration.

### Approach
Initialize `dist[src]=0`, all others Infinity. Repeat `k+1` times: copy `dist` to `next`; relax all flights using `dist` (previous round) values into `next`; replace `dist = next`. Return `dist[dst]` or -1 if still Infinity.

### Solution

```js
function findCheapestPrice(n, flights, src, dst, k) {
  // dist[v] = cheapest cost to reach v with at most (current iteration) edges
  let dist = new Array(n).fill(Infinity);
  dist[src] = 0;

  // k stops = k+1 edges = k+1 relaxation rounds
  for (let i = 0; i <= k; i++) {
    // CRITICAL: copy previous round's distances
    // Prevents using more than i+1 edges in a single round
    const next = [...dist];

    for (const [from, to, price] of flights) {
      // Relax using dist (previous round), write into next (current round)
      if (dist[from] !== Infinity && dist[from] + price < next[to]) {
        next[to] = dist[from] + price;
      }
    }

    dist = next; // advance to current round
  }

  return dist[dst] === Infinity ? -1 : dist[dst];
}
```

- Time: O(k · E) — k+1 iterations, each scanning all E flights.
- Space: O(V) — two distance arrays of size n (dist and next).

### Edge Cases
- `k=0` (direct flight only, 0 stops): 1 iteration; only direct edges from `src` are relaxed. Returns direct flight cost or -1.
- No path within k stops: `dist[dst]` remains Infinity → return -1.
- Negative prices: Bellman-Ford handles negative weights (flights can't have negative prices in practice, but the algorithm works). No negative cycle concern since there are no negative-weight cycles in airline pricing.
- `src === dst`: dist[src]=0 from initialization; returned immediately as 0.

- "What if k is very large (essentially unlimited stops)?" → Standard Dijkstra's — the stop constraint is irrelevant, so use the most efficient algorithm for the unconstrained case.

## Problem 3 — Find the City With the Smallest Number of Reachable Cities (Floyd-Warshall)

### Problem
There are `n` cities numbered `0` to `n-1` and `edges[i] = [from, to, weight]` representing bidirectional weighted roads. Given a `distanceThreshold`, return the city with the smallest number of cities reachable within the threshold. If multiple cities qualify, return the one with the greatest label.

```
Input:  n=4, edges=[[0,1,3],[1,2,1],[1,3,4],[2,3,1]], distanceThreshold=4
Output: 3
  City 0: reachable within 4 = {1(3), 2(4)} → 2 cities
  City 1: reachable within 4 = {0(3), 2(1), 3(2)} → 3 cities
  City 2: reachable within 4 = {1(1), 3(1), 0(4)} → 3 cities
  City 3: reachable within 4 = {1(4), 2(1)} → 2 cities
  Cities 0 and 3 both have 2 — return 3 (greater label). ✓
```

### Pattern Recognition
All-pairs shortest path on a small graph → Floyd-Warshall. The problem asks for distances between every pair of cities, which is exactly what Floyd-Warshall computes. With n ≤ 100, O(n³) is perfectly feasible.

### Key Insight
Floyd-Warshall computes `dist[i][j]` for all pairs in one O(n³) pass. After that, for each city `i`, count the number of cities `j ≠ i` with `dist[i][j] ≤ distanceThreshold`. The answer is the city with the minimum count — ties broken by largest index (iterate from high to low, keeping the last minimum).

### Approach
Initialize the distance matrix. Set direct edge weights (symmetric for undirected). Run the triple loop. For each city, count reachable cities within threshold. Track the minimum count and corresponding city (prefer larger index on ties by scanning `n-1` down to `0`).

### Solution

```js
function findTheCity(n, edges, distanceThreshold) {
  // Initialize distance matrix
  const dist = Array.from({ length: n }, (_, i) =>
    Array.from({ length: n }, (_, j) => (i === j ? 0 : Infinity))
  );

  // Set direct edge weights (bidirectional)
  for (const [u, v, w] of edges) {
    dist[u][v] = w;
    dist[v][u] = w; // undirected: both directions
  }

  // Floyd-Warshall: try each vertex k as intermediate
  for (let k = 0; k < n; k++) {
    for (let i = 0; i < n; i++) {
      for (let j = 0; j < n; j++) {
        // Guard against Infinity + w overflow
        if (dist[i][k] !== Infinity && dist[k][j] !== Infinity) {
          dist[i][j] = Math.min(dist[i][j], dist[i][k] + dist[k][j]);
        }
      }
    }
  }

  // For each city, count cities reachable within distanceThreshold
  let resultCity = -1;
  let minReachable = Infinity;

  for (let i = 0; i < n; i++) {
    let reachable = 0;
    for (let j = 0; j < n; j++) {
      if (i !== j && dist[i][j] <= distanceThreshold) reachable++;
    }
    // Update if strictly fewer reachable, OR equal reachable but larger index
    if (reachable <= minReachable) {
      minReachable = reachable;
      resultCity = i; // scanning 0..n-1, so later i with equal count wins
    }
  }

  return resultCity;
}
```

## Problem 4 — Bellman-Ford with Negative Cycle Detection

### Problem
Given a directed weighted graph with `n` vertices (0-indexed) and a list of edges `[u, v, w]`, find the shortest paths from source vertex `0` to all other vertices. If a vertex is reachable via a negative cycle, its distance is `-Infinity`. If it is unreachable, return `Infinity`.

```
Input:  n=5, edges=[[0,1,1],[1,2,2],[2,3,-6],[3,1,3],[0,4,5]]
Output: dist=[0, -∞, -∞, -∞, 5]
  (cycle 1→2→3→1 has weight 2+(-6)+3=-1 → negative cycle → nodes 1,2,3 are -∞)
  (node 4 is reachable only via 0→4, no negative cycle on this path → dist[4]=5)
```

### Pattern Recognition
Bellman-Ford with negative cycle detection and propagation — V-1 rounds for convergence, then a Vth round to identify vertices directly relaxable via negative cycles, followed by BFS/DFS to mark all downstream vertices as `-Infinity`.

### Key Insight
After V-1 rounds, any vertex whose distance can still be reduced is on or downstream of a negative cycle. The Vth round identifies these vertices directly. From each such vertex, BFS through the graph marks all reachable vertices as `-Infinity` — because any path through a negative cycle can be made arbitrarily short by traversing the cycle more times.

### Approach
Run standard Bellman-Ford for V-1 rounds. Run a Vth round — collect all vertices `v` that can still be relaxed as `negCycleAffected`. BFS from all `negCycleAffected` nodes to mark all reachable vertices as `-Infinity`. Return the `dist` array.

### Solution

```js
function bellmanFordNegCycle(n, edges, source = 0) {
  const dist = new Array(n).fill(Infinity);
  dist[source] = 0;

  // Build adjacency list for BFS propagation
  const adj = Array.from({ length: n }, () => []);
  for (const [u, v, w] of edges) adj[u].push(v);

  // V-1 relaxation rounds
  for (let i = 0; i < n - 1; i++) {
    for (const [u, v, w] of edges) {
      if (dist[u] !== Infinity && dist[u] + w < dist[v]) {
        dist[v] = dist[u] + w;
      }
    }
  }

  // Vth round: detect vertices directly relaxable (on or adjacent to negative cycle)
  const negCycleAffected = new Set();
  for (const [u, v, w] of edges) {
    if (dist[u] !== Infinity && dist[u] + w < dist[v]) {
      negCycleAffected.add(v); // v can be reduced further → affected by negative cycle
    }
  }

  // BFS from all affected vertices: mark all reachable nodes as -Infinity
  const queue = [...negCycleAffected];
  while (queue.length > 0) {
    const u = queue.shift();
    dist[u] = -Infinity;
    for (const v of adj[u]) {
      if (dist[v] !== -Infinity) {
        dist[v] = -Infinity;
        queue.push(v);
      }
    }
  }

  return dist;
}
```

### Complexity
- Time: O(V · E) — V-1 rounds of relaxation, Vth round detection, BFS O(V+E).
- Space: O(V + E) — dist array, adjacency list for BFS, queue.

### Edge Cases
- No negative cycle: Vth round produces no relaxations; `negCycleAffected` is empty; BFS does nothing; return the standard Bellman-Ford result.
- All nodes in one big negative cycle reachable from source: all get marked `-Infinity`.
- Node unreachable from source: `dist[u] = Infinity` → the condition `dist[u] !== Infinity` prevents relaxation from unreachable nodes, so they stay `Infinity` (not falsely marked `-Infinity`).
- Self-loop with negative weight `[u, u, -1]`: after V-1 rounds, `dist[u]` keeps decreasing. Vth round: `dist[u] + (-1) < dist[u]` → `negCycleAffected.add(u)`. BFS from `u` marks all reachable nodes. Correct.

### Follow-up Questions
- "Return -1 instead of -Infinity for affected nodes?" → Change `dist[u] = -Infinity` to `dist[u] = -1` in the BFS phase — same logic, different sentinel.
- "Use Floyd-Warshall to detect all-pairs negative cycles?" → After Floyd-Warshall, check `dist[i][i] < 0` for any `i` — that node is on a negative cycle. To mark all affected pairs: `if dist[i][k] != Infinity && dist[k][k] < 0 && dist[k][j] != Infinity then dist[i][j] = -Infinity`.

## Quick Reference — Shortest Path Algorithm Decision Tree

```
What are the properties of the graph and query?
│
├── UNWEIGHTED graph (all edges weight 1)?
│   └── BFS: O(V+E) — fastest possible, no algorithm needed for SSSP
│
├── ALL edge weights NON-NEGATIVE?
│   │
│   ├── Single source → all destinations (SSSP)?
│   │   └── Dijkstra's: O((V+E) log V) with binary heap
│   │       Use when: general non-negative weights, sparse or dense graph
│   │
│   ├── Edge weights are 0 or 1 only?
│   │   └── 0-1 BFS: O(V+E) — deque, push 0-weight to front
│   │
│   ├── Edge weights are small integers [0..k]?
│   │   └── Dial's algorithm: O(V+E+k) — bucket queue
│   │
│   └── All-pairs shortest path (APSP)?
│       ├── Dense graph (E ≈ V²) → Floyd-Warshall: O(V³)
│       └── Sparse graph (E << V²) → V × Dijkstra's: O(VE log V)
│
├── NEGATIVE edge weights (NO negative cycles)?
│   │
│   ├── Single source?
│   │   ├── General → Bellman-Ford: O(VE)
│   │   ├── DAG → Topological sort DP: O(V+E)
│   │   └── At most k edges → Modified Bellman-Ford: O(k·E)
│   │
│   └── All-pairs?
│       └── Floyd-Warshall: O(V³)
│           (or Johnson's algorithm for sparse: O(VE + V² log V))
│
├── NEGATIVE CYCLES may exist?
│   ├── Detect existence only?
│   │   ├── Single source → Bellman-Ford Vth round check
│   │   └── All-pairs → Floyd-Warshall diagonal check (dist[i][i] < 0)
│   │
│   └── Identify affected vertices?
│       └── Bellman-Ford Vth round + BFS propagation
│           Marks all cycle-reachable vertices as -Infinity
│
├── CONSTRAINT: at most k edges in path?
│   └── Modified Bellman-Ford: run exactly k iterations
│       MUST use copied array from previous round (no chaining)
│       Alternative: Dijkstra on (node, stops) state space
│
└── GRAPH is a DAG (directed, acyclic)?
    └── Topological sort DP: O(V+E)
        Works for ANY edge weights (positive, negative, zero)
        Process vertices in topological order, relax outgoing edges
```

## Common Bugs Checklist

Before submitting any shortest path solution, verify:

1. **Dijkstra's: guarding against negative weights before choosing it?** — Dijkstra's produces silently wrong answers (not errors) on graphs with negative edges. Always confirm all weights ≥ 0 before using Dijkstra's. If any weight is negative, switch to Bellman-Ford.

2. **Dijkstra's lazy deletion: checking `if (d > dist[u]) continue` after extraction?** — Without this guard, stale heap entries cause redundant processing. Worse: in some implementations, they cause incorrect relaxations from out-of-date distance values. Always skip entries where the extracted distance exceeds the current best.

3. **Bellman-Ford: using a COPY of the previous round's distances?** — Required for "at most k edges" problems (`findCheapestPrice`). Without copying, one round can chain multiple relaxations, using more edges than allowed. In standard Bellman-Ford (no edge limit), copying is optional but safe — skipping it can cause faster convergence but is still correct for SSSP.

4. **Bellman-Ford: initializing `dist[source] = 0` before the rounds, not inside?** — Initializing inside the loop resets the source distance every round. Must set `dist[source] = 0` once before any iteration.

5. **Floyd-Warshall: `k` must be the outermost loop (not `i` or `j`)?** — See Q23. Any other loop order violates the DP invariant and produces incorrect all-pairs distances. The outer `k` loop is non-negotiable.

6. **Floyd-Warshall: guarding against `Infinity + Infinity` overflow?** — `dist[i][k] + dist[k][j]` when both are `Infinity` overflows in languages with fixed integer types (produces a negative number, triggering false updates). Always check `dist[i][k] !== Infinity && dist[k][j] !== Infinity` before updating. In JavaScript, `Infinity + Infinity = Infinity`, so overflow isn't an issue — but the guard is still good practice.

7. **Floyd-Warshall: initializing the diagonal to 0 before edges?** — `dist[i][i] = 0` must be set before adding edge weights. If an edge `(i, i, w)` exists (self-loop), the edge weight might overwrite the diagonal — ensure `dist[i][i] = Math.min(dist[i][i], w)` to correctly keep 0 for non-negative self-loops (or detect negative self-loops).

8. **Disconnected graphs: checking for `Infinity` in the final distances?** — If the graph is disconnected, some `dist[v]` values remain `Infinity`. Problems asking for "maximum distance" or "sum of distances" will return wrong answers if Infinity is not handled. Always check for unreachable nodes (return -1, skip in aggregation, or handle per problem specification).

9. **1-indexed vs. 0-indexed nodes?** — Many graph problems use 1-indexed nodes (nodes 1..n). Allocate `dist` of size `n+1`, initialize `dist[source] = 0` where `source` is the 1-indexed value, and skip index 0 in aggregations. Mixing 0-indexed and 1-indexed is the most common off-by-one error in graph problems.

10. **Bellman-Ford negative cycle propagation: BFS from Vth-round-relaxable vertices, not just marking them directly?** — A vertex relaxed in round V is on or adjacent to a negative cycle — but downstream vertices (reachable from it) are also affected (their paths go through the negative cycle). Must BFS from all Vth-round vertices to mark all affected nodes as `-Infinity`.

**Final Tip:** At the 5 YOE level, interviewers expect you to choose among the three algorithms — and justify the choice — before writing a single line of code. The decisive signal of genuine mastery is delivering this justification in one sentence per algorithm: "Dijkstra's because all weights are non-negative and I need SSSP — the greedy extraction of the minimum-distance vertex is valid when no negative edge can retroactively improve a finalized distance." Then immediately: "If weights could be negative, I'd switch to Bellman-Ford — its V-1 iteration structure guarantees correctness by building shortest paths hop-by-hop, at the cost of O(VE) instead of O(E log V)." And: "If I needed all-pairs, Floyd-Warshall — its triple-loop DP tries each vertex as an intermediate, building up the set of allowed intermediates one at a time until all pairs are solved in O(V³)." Articulating all three trade-offs fluently before touching the keyboard is what distinguishes a senior practitioner from someone who has memorized three separate templates.
