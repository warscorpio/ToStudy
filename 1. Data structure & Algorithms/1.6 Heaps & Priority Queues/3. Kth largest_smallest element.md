## Topic A: Approaches & Trade-offs

### Section A1: The Four Approaches

**Q1. What are the four main approaches to finding the Kth largest/smallest element, and what are their trade-offs?**

A: Four fundamentally different techniques exist, each optimal for a different scenario:

**Sorting**: sort the array, index directly. O(n log n) time, O(1) extra space (in-place sort). Simplest to implement but wastes work — sorts the entire array when only one element's rank matters. Use only when the sorted order is needed for other purposes anyway.

**Heap of size k**: maintain a heap of exactly k candidate elements. O(n log k) time, O(k) space. Optimal when k is small relative to n, when data arrives as a stream, or when the structure must handle dynamic insertions. A min-heap for kth largest, max-heap for kth smallest (the heap holds the k extreme elements; its top is the boundary element).

**QuickSelect**: partial quicksort — partition around a pivot, recurse only into the half containing the kth position. O(n) average, O(n²) worst case, O(log n) average call stack. Optimal for static arrays when a single answer is needed and k is arbitrary. Worst case is avoidable with random pivot selection.

**Binary search on value**: search over the *value range* rather than indices. For each candidate value `mid`, count how many elements are ≤ `mid`. O(n log V) where V = value range. Useful for sorted matrices and other structured inputs where element counting is efficient.

```
Approach       | Time          | Space  | When to use
---------------|---------------|--------|----------------------------------
Sort           | O(n log n)    | O(1)   | Simplicity; sorted order needed
Min/max heap   | O(n log k)    | O(k)   | Streaming; dynamic; small k
QuickSelect    | O(n) avg      | O(log n) | Static array; arbitrary k; best avg
Binary search  | O(n log V)    | O(1)   | Sorted matrix; structured input

For interviews: state the trade-off → then implement the one that fits.
```

**Q2. What is QuickSelect, and how does it exploit the partition step to avoid sorting both halves?**

A: QuickSelect is a selection algorithm derived from quicksort. Quicksort's partition step places a pivot at its correct sorted position and ensures all elements to the left are smaller, all to the right are larger. QuickSelect uses the same partition but only recurses into *one* side — the side that contains the kth position. Quicksort recurses into both halves (O(n log n)); QuickSelect recurses into at most one half at each level (O(n) on average).

The key invariant after partitioning: the pivot is at its final sorted index `p`. If `p == k-1` (0-indexed for kth smallest): found. If `p > k-1`: kth element is in the left half — recurse left. If `p < k-1`: kth element is in the right half — recurse right with adjusted k. Each level does O(n) work for the partition; on average, each level halves the remaining subarray.

```
Array: [3, 1, 4, 1, 5, 9, 2, 6], find 4th smallest (k=4)

Partition around pivot=6 (index 7 → moves to index 6 after partition):
  Elements < 6: {3,1,4,1,5,2} (6 elements) → pivot at index 6.
  p=6 > k-1=3: 4th smallest is in LEFT half [3,1,4,1,5,2].

Partition [3,1,4,1,5,2] around pivot=2 (index 5 → moves to index 1):
  Elements < 2: {1} (1 element) → {1,2,...}: pivot at index 1.
  p=1 < k-1=3: adjust k: need (4-1-1=2)nd smallest in RIGHT half.

Continue recursing into one half at each step...
```

**Q3. How does the Lomuto partition scheme work, and what is the pointer invariant it maintains?**

A: Lomuto uses two pointers `i` and `j` and a fixed pivot (typically the last element). Invariant: at any point during the scan, `arr[left..i]` contains elements ≤ pivot, and `arr[i+1..j-1]` contains elements > pivot. `j` is the scan pointer advancing rightward; `i` is the boundary between the "≤ pivot" and "> pivot" regions.

Steps: initialize `i = left - 1`; scan `j` from `left` to `right - 1`; whenever `arr[j] <= pivot`: increment `i` and swap `arr[i]` with `arr[j]`. After the scan: swap `arr[i+1]` with the pivot at `arr[right]`. The pivot lands at index `i+1`, which is its correct sorted position. Return `i+1`.

```js
function partition(arr, left, right) {
  const pivot = arr[right]; // Lomuto: last element as pivot
  let i = left - 1;         // i: boundary of "≤ pivot" region (exclusive)

  for (let j = left; j < right; j++) {
    if (arr[j] <= pivot) {
      i++;
      [arr[i], arr[j]] = [arr[j], arr[i]]; // swap small element to left region
    }
  }
  // Place pivot at its correct sorted position
  [arr[i + 1], arr[right]] = [arr[right], arr[i + 1]];
  return i + 1; // pivot's final index
}

// Invariant after partition(arr, left, right):
//   arr[left..i] ≤ arr[i+1] ≤ arr[i+2..right]
//   arr[i+1] is at its final sorted position
```

**Q4. What is the average-case time complexity argument for QuickSelect, and why does random pivot selection help?**

A: With a random pivot, the expected position of the pivot after partition is uniformly distributed over the n positions. On average, the pivot falls near the middle, splitting the problem roughly in half. The recurrence is `T(n) = T(n/2) + O(n)`, which solves to T(n) = O(n) by the master theorem (case where the recursion tree's total work is dominated by the root level: n + n/2 + n/4 + ... = 2n = O(n)).

Worst case occurs when the pivot is always the minimum or maximum — one side is empty, one has n-1 elements: `T(n) = T(n-1) + O(n)` = O(n²). A random pivot makes this worst case extremely unlikely — for any fixed adversarial input, the probability of O(n²) performance decreases exponentially with n. In practice, always use random pivot selection.

```
Average case recurrence (random pivot, splits at expected median):
T(n) = T(n/2) + O(n)
     = O(n) + O(n/2) + O(n/4) + ...
     = O(n × (1 + 1/2 + 1/4 + ...))
     = O(n × 2) = O(n) ✓

Worst case (always smallest pivot, e.g., sorted array + Lomuto last element):
T(n) = T(n-1) + O(n)
     = O(n + (n-1) + (n-2) + ... + 1) = O(n²) ✗

Fix: shuffle array before QuickSelect, or pick random pivot index at each step.
```

**Q5. What is the three-way partition (Dutch National Flag variant), and when does it improve QuickSelect?**

A: Standard two-way partition places elements into two groups: ≤ pivot (left) and > pivot (right). With many duplicate elements equal to the pivot, the pivot lands at one position but many equal elements scatter across both halves — the pivot's "equal" group is not isolated, causing redundant comparisons in future recursion. Three-way partition creates three groups: `< pivot` (left), `= pivot` (middle), `> pivot` (right). After partition, all elements equal to the pivot are at their final positions — if the kth element falls in the "= pivot" group, the search terminates immediately without further recursion. For arrays with many duplicates (e.g., `[1,1,1,1,1,1,2]`), three-way partition degrades QuickSelect's worst case from O(n) per level (with duplicates all becoming bad pivots) to O(n) total (all duplicates resolved in one pass).

```js
function threeWayPartition(arr, left, right) {
  const pivot = arr[left + Math.floor(Math.random() * (right - left + 1))];
  let lo = left, mid = left, hi = right;

  while (mid <= hi) {
    if (arr[mid] < pivot)       { [arr[lo], arr[mid]] = [arr[mid], arr[lo]]; lo++; mid++; }
    else if (arr[mid] === pivot) { mid++; }
    else                        { [arr[mid], arr[hi]] = [arr[hi], arr[mid]]; hi--; }
  }
  // After: arr[left..lo-1] < pivot, arr[lo..hi] === pivot, arr[hi+1..right] > pivot
  return [lo, hi]; // range of pivot values
}
```

### Section A2: Heap Mechanics

**Q6. How do you implement a MinHeap in JavaScript for interview use, and what are the critical index formulas?**

A: JavaScript has no built-in priority queue. A binary heap is stored as an array where the parent-child relationship is maintained by index arithmetic: parent of index `i` is `Math.floor((i-1)/2)`; left child is `2*i+1`; right child is `2*i+2`. The heap property: for a min-heap, `arr[parent] ≤ arr[child]` for all nodes. `push`: append to end, sift up (swap with parent while smaller than parent). `pop`: swap root with last element, remove last, sift down (swap with the smaller child while larger than a child). Both operations are O(log n).

```js
class MinHeap {
  constructor(comparator = (a, b) => a - b) {
    this.heap = [];
    this.cmp = comparator; // cmp(a,b) < 0 means a has HIGHER priority (comes first)
  }

  size()  { return this.heap.length; }
  peek()  { return this.heap[0]; } // min element (highest priority)

  push(val) {
    this.heap.push(val);
    this._siftUp(this.heap.length - 1);
  }

  pop() {
    if (this.size() === 1) return this.heap.pop();
    const top = this.heap[0];
    this.heap[0] = this.heap.pop(); // move last to root
    this._siftDown(0);
    return top;
  }

  _siftUp(i) {
    while (i > 0) {
      const parent = Math.floor((i - 1) / 2);
      if (this.cmp(this.heap[i], this.heap[parent]) < 0) {
        [this.heap[i], this.heap[parent]] = [this.heap[parent], this.heap[i]];
        i = parent;
      } else break;
    }
  }

  _siftDown(i) {
    const n = this.size();
    while (true) {
      let smallest = i;
      const l = 2 * i + 1, r = 2 * i + 2;
      if (l < n && this.cmp(this.heap[l], this.heap[smallest]) < 0) smallest = l;
      if (r < n && this.cmp(this.heap[r], this.heap[smallest]) < 0) smallest = r;
      if (smallest === i) break;
      [this.heap[i], this.heap[smallest]] = [this.heap[smallest], this.heap[i]];
      i = smallest;
    }
  }
}

// Max-heap: negate the comparator
const maxHeap = new MinHeap((a, b) => b - a);
// Min-heap of arrays sorted by first element:
const pairHeap = new MinHeap((a, b) => a[0] - b[0]);
```

**Q7. Why does finding the Kth LARGEST use a MIN-heap, and the Kth SMALLEST use a MAX-heap — the opposite of intuition?**

A: The pattern inverts because the heap's top is what gets *ejected* when the heap exceeds size k. For the kth LARGEST: maintain a min-heap of exactly k elements (the k largest seen so far). When a new element arrives: if it's larger than the heap's minimum (the smallest of the current top-k), it belongs in the top-k — eject the heap minimum, insert the new element. The heap top is always the kth largest (the smallest element among the k largest). If a new element is ≤ the heap minimum, it cannot displace any of the current top-k — ignore it. The min-heap efficiently finds and ejects the "worst" member of the current top-k.

```
Kth LARGEST → MIN-heap of size k:
  Heap contains: [k largest elements seen so far]
  heap.top = min of those k elements = kth largest overall
  New element x: if x > heap.top → pop min, push x (x is "better" than the worst of top-k)
                 if x ≤ heap.top → ignore (x cannot displace any of the top-k)

Kth SMALLEST → MAX-heap of size k:
  Heap contains: [k smallest elements seen so far]
  heap.top = max of those k elements = kth smallest overall
  New element x: if x < heap.top → pop max, push x (x is "better" than the worst of bottom-k)
                 if x ≥ heap.top → ignore

Memory hook: heap type is OPPOSITE to what you're finding.
             "Kth LARGEST" → MIN-heap (min-heap ejects things too small to be in top-k)
```

## Topic B: The Two-Heap Pattern

### Section B1: Median and Percentile Queries

**Q8. What is the two-heap pattern for "Find Median from Data Stream," and what invariants must the two heaps maintain at all times?**

A: Split all seen elements into two halves using two heaps: a max-heap for the lower half (elements ≤ median) and a min-heap for the upper half (elements ≥ median). Two invariants are maintained after every insertion:

**Invariant 1 — Size balance**: `maxHeap.size` equals `minHeap.size` (even total n) OR equals `minHeap.size + 1` (odd total n). The max-heap holds the extra element when n is odd.

**Invariant 2 — Order**: `maxHeap.top ≤ minHeap.top`. Every element in the lower half is ≤ every element in the upper half.

Median derivation: if sizes are equal → median = `(maxHeap.top + minHeap.top) / 2`. If max-heap is larger → median = `maxHeap.top`.

Addition algorithm: always add the new element to the max-heap first (this may temporarily violate Invariant 2 — an element larger than min-heap's top lands in max-heap). Fix order: if `maxHeap.top > minHeap.top`, move max-heap's top to min-heap. Fix size: if `minHeap.size > maxHeap.size`, move min-heap's top to max-heap.

```
Two-heap structure after inserting [1, 2, 3]:
  maxHeap (lower): [2]      ← max-heap, top=2 is the "left median"
  minHeap (upper): [3]      ← min-heap, top=3 is the "right median"
  maxHeap.size(1) == minHeap.size(1) → even → median = (2+3)/2 = 2.5

After inserting 4:
  Add 4 to maxHeap: [4,2] (max-heap temporarily)
  maxHeap.top(4) > minHeap.top(3) → move 4 to minHeap.
  maxHeap=[2], minHeap=[3,4]. Sizes: 1 vs 2 → rebalance: move 3 to maxHeap.
  maxHeap=[3,2], minHeap=[4]. Sizes: 2 vs 1. maxHeap.size > minHeap.size.
  median = maxHeap.top = 3. ✓ (sorted: [1,2,3,4], median=2.5... wait)

Let me recalculate: [1,2,3,4] → median should be (2+3)/2=2.5.
maxHeap=[2,1], minHeap=[3,4]. sizes=2,2 → median=(2+3)/2=2.5 ✓
```

**Q9. How does the two-heap pattern generalize beyond median to arbitrary kth-percentile queries?**

A: The median is the 50th percentile — the point where exactly half the elements are on each side. For the kth-percentile (e.g., kth smallest of n elements), the split is: maintain a max-heap of exactly k elements (the k smallest seen so far) and a min-heap of the remaining n-k elements (the n-k largest). The max-heap's top is the kth smallest element overall. This is exactly the "kth smallest via max-heap of size k" pattern extended to a dynamic setting with rebalancing. The two-heap median is the special case where k = ⌊n/2⌋ — but since n changes dynamically, the rebalancing logic handles the floor/ceiling distinction automatically.

## Topic C: Binary Search on Value

**Q10. How does binary search on value work for Kth Smallest in a Sorted Matrix, and why is binary search on indices incorrect?**

A: For a sorted matrix (each row and column sorted), binary search on *indices* fails because there's no direct formula mapping an index to a rank — the matrix is not fully sorted (elements don't map to a 1D sorted sequence by index). Binary search on *values* works: pick a candidate value `mid = (lo + hi) / 2`; count how many matrix elements are ≤ `mid`. If `count < k`: the kth smallest is larger than `mid` → `lo = mid + 1`. If `count >= k`: the kth smallest is ≤ `mid` → `hi = mid`. When `lo == hi`: the search converges to the exact kth smallest value (which is guaranteed to be an element in the matrix, not a value between elements — see edge cases).

```
Why value range works:
  lo = matrix[0][0] (global minimum)
  hi = matrix[n-1][n-1] (global maximum)
  Every iteration halves the value range.
  Convergence: lo == hi == kth smallest element value.

Why binary search on indices fails:
  matrix = [[1,5,9],[10,11,13],[12,13,15]]
  Index (0,1) gives 5. Is 5 the 2nd smallest? Yes.
  But there's no formula rank(i,j) = something useful without counting.
```

**Q11. What is the "staircase" counting technique for counting elements ≤ mid in a sorted matrix?**

A: Start at the top-right corner `(0, n-1)`. At each step: if `matrix[row][col] ≤ mid`, all elements in this column from row 0 to the current row are also ≤ mid (the column is sorted ascending top-to-bottom) — add `row + 1` to the count and move right (`col++`). If `matrix[row][col] > mid`, move up (`row--`) to find a smaller element. This "staircase" moves right or up — at most `n + n = 2n` steps total — O(n) per count call.

```
matrix = [[1,5,9],[10,11,13],[12,13,15]], n=3, count elements ≤ 11:

Start: (row=0, col=2), count=0.
  matrix[0][2]=9 ≤ 11 → count += 0+1 = 1 (column 2, rows 0..0). col++ → col=3 out of bounds.
  Wait — start from TOP-RIGHT is (0, n-1) = (0, 2).

Let me redo with correct staircase (top-right, move left or down):

Start: row=0, col=2. count=0.
  matrix[0][2]=9 ≤ 11 → count += (row+1) = 1 (elements in column 2: just row 0). col++.
  col=3 > n-1: stop inner while. row++.
  row=1: col starts again... 

Actually the standard staircase starts at BOTTOM-LEFT (row=n-1, col=0) and moves right or up:

row=n-1=2, col=0. count=0.
  matrix[2][0]=12 > 11 → move up (row--). row=1.
  matrix[1][0]=10 ≤ 11 → count += col+1 = 1. col++. col=1.
  matrix[1][1]=11 ≤ 11 → count += col+1 = 2. col++. col=2.
  matrix[1][2]=13 > 11 → move up (row--). row=0.
  matrix[0][2]=9 ≤ 11 → count += col+1 = 3. col++. col=3 ≥ n.
  Done. Total count = 1+2+3 = 6? 

Elements ≤ 11: {1,5,9,10,11} = 5 elements. Let me recheck...
Actually count += col+1 accumulates the column count from left: col+1 = number of elements in current row up to and including col that are ≤ mid.

At matrix[1][0]=10 ≤ 11: this means matrix[1][0..0] ≤ 11 → add col+1=1. count=1.
At matrix[1][1]=11 ≤ 11: matrix[1][0..1] ≤ 11 → add col+1=2. count=3.
  But wait — we already counted col 0 in the previous step!
  
The correct staircase (bottom-left start, move right or up):
  At each (row, col): if matrix[row][col] ≤ mid: count += row+1 (all elements in this column, rows 0..row, are ≤ mid since column is sorted). Move right (col++).
  Else: move up (row--).

row=2, col=0. 
  matrix[2][0]=12 > 11 → row--. row=1.
  matrix[1][0]=10 ≤ 11 → count += row+1 = 2 (col 0 has rows 0..1: {1,10}). col++. col=1.
  matrix[1][1]=11 ≤ 11 → count += row+1 = 2 (col 1 has rows 0..1: {5,11}). col++. col=2.
  matrix[1][2]=13 > 11 → row--. row=0.
  matrix[0][2]=9 ≤ 11 → count += row+1 = 1 (col 2 has rows 0..0: {9}). col++. col=3.
  col ≥ n. Stop. Total count = 2+2+1 = 5. ✓ (elements ≤ 11: {1,5,9,10,11})
```

## Topic D: Cross-Topic & Interview-Style Questions

**Q12. "Walk through your thought process when you see 'Kth largest/smallest' in a problem."**

A: Four diagnostic questions in order:

1. **Static vs dynamic?** — Is the array fixed (given all at once) or does data arrive as a stream (dynamic insertions, queries after each insert)? Static → QuickSelect or sort. Dynamic/streaming → heap of size k.

2. **Single query vs multiple queries?** — Single answer needed → QuickSelect (O(n) average, best for one shot). Multiple queries on the same data → build a sorted array or heap structure once, query many times.

3. **Is there structure (sorted matrix, sorted subarrays)?** — Sorted matrix or other structured input → binary search on value. Unstructured array → heap or QuickSelect.

4. **Is k close to n/2 (median)?** — Finding the exact median dynamically → two-heap pattern. Single-query median → QuickSelect with k = n/2.

```
Decision flowchart:

Is data static?
  YES → Is there structure (sorted matrix)?
    YES → Binary search on value, O(n log V)
    NO  → QuickSelect O(n) avg, or min-heap O(n log k)
  NO (streaming) → Is k == n/2 (median)?
    YES → Two-heap pattern, O(log n) per insert, O(1) median
    NO  → Min/max-heap of size k, O(log k) per insert, O(1) query
```

**Q13. "What is the exact space complexity of each approach, and which should you use in a memory-constrained environment?"**

A: Comparing space usage across all four approaches:

| Approach | Extra Space | Notes |
|---|---|---|
| Sort (in-place) | O(log n) | Sort stack space; O(1) for heapsort |
| Min/max heap | O(k) | Exactly k elements in the heap |
| QuickSelect | O(log n) avg | Call stack depth (O(n) worst case without tail recursion) |
| Binary search on value | O(1) | Just lo, hi, mid variables |

For memory-constrained environments: binary search on value (if applicable) → O(1); in-place QuickSelect (iterative) → O(1) extra; sort → O(1) with heapsort. The heap approach uses O(k) space — acceptable when k is small, but could be up to O(n) when k = n/2 (median).

**Q14. "Why does the heap approach not achieve O(n) time like QuickSelect, despite also being a selection algorithm?"**

A: QuickSelect achieves O(n) by narrowing the search space at each level — after one partition, at most one half is explored. The heap approach processes every element with an O(log k) heap push or pop — it never eliminates any element from consideration early (it must see every element to verify it's not in the top k). The O(n log k) cost is unavoidable for the heap: n elements × O(log k) per element. QuickSelect's O(n) comes from the fact that, on average, elements are processed fewer times — elements in the wrong half of the first partition are never seen again.

The heap wins in practice when k << n (log k is tiny) or when data is streaming (QuickSelect requires all data upfront). QuickSelect wins on random-access static arrays when k is arbitrary.

**Q15. "When is QuickSelect's worst case triggered, and how does shuffling defend against it?"**

A: QuickSelect's O(n²) worst case occurs when every partition step picks the minimum or maximum element as the pivot — producing a split of size (0, n-1). For Lomuto's scheme (last element as pivot), this happens on a sorted or reverse-sorted array. An adversary can craft an input that always picks the worst pivot for any deterministic pivot selection strategy. Shuffling the array randomly before applying QuickSelect (or choosing a random pivot index at each partition step) neutralizes adversarial inputs: no fixed input arrangement can consistently produce bad pivots after random shuffling. The probability of O(n²) performance on a randomly shuffled input decreases faster than any polynomial — the expected runtime is O(n) with high probability.

**Q16. "In one sentence each, state the invariant that each approach maintains."**

A:
- **Sort**: after sorting, `arr[k-1]` is the kth smallest element — the array's sorted order encodes every element's rank simultaneously.
- **Min-heap of size k (kth largest)**: the heap always contains the k largest elements seen so far; its top is the smallest of those k elements — the kth largest overall.
- **Max-heap of size k (kth smallest)**: the heap always contains the k smallest elements seen so far; its top is the largest of those k elements — the kth smallest overall.
- **QuickSelect**: after each partition, the pivot is at its correct final sorted index; the kth element lies either at the pivot or in the half whose index range contains k-1.
- **Two-heap (median)**: the max-heap holds all elements ≤ median, the min-heap holds all elements ≥ median, with sizes differing by at most 1 and `maxHeap.top ≤ minHeap.top` always.
- **Binary search on value**: at every step, the kth smallest element's value lies in the range `[lo, hi]`; `lo == hi` when the exact value is found.

## Problem 1 — Kth Largest Element in an Array

### Problem
Given an integer array `nums` and an integer `k`, return the kth largest element in the array. Note that it is the kth largest in sorted order, not the kth distinct element.

```
Input:  nums = [3,2,1,5,6,4], k = 2     → Output: 5
Input:  nums = [3,2,3,1,2,4,5,5,6], k = 4  → Output: 4
```

### Pattern Recognition
QuickSelect (optimal single-query solution) + min-heap of size k (for comparison). QuickSelect: partial partition, recurse only into the half containing index `n-k` (0-indexed position of kth largest in sorted ascending order). Min-heap: maintain k largest elements; heap top = kth largest.

### Key Insight
The kth largest is the element at index `n-k` in a 0-indexed sorted ascending array. QuickSelect finds this in O(n) average by partitioning and recursing into only the relevant half. The min-heap maintains the k largest with O(n log k) by keeping a running "candidate set" and evicting the worst candidate whenever a better one is found.

### Approach — QuickSelect
Translate: kth largest = (n-k+1)th smallest = element at 0-indexed position `n-k` in sorted ascending order. Use QuickSelect to find position `n-k`. At each step: partition around a random pivot; if pivot position == `n-k`, return `arr[n-k]`; if pivot position > `n-k`, recurse left; else recurse right.

### Solution

```js
// Approach 1: QuickSelect — O(n) average, O(1) extra space
function findKthLargest(nums, k) {
  const target = nums.length - k; // 0-indexed position of kth largest in sorted array

  function quickSelect(left, right) {
    // Random pivot to avoid worst-case O(n²) on sorted input
    const pivotIdx = left + Math.floor(Math.random() * (right - left + 1));
    [nums[pivotIdx], nums[right]] = [nums[right], nums[pivotIdx]]; // move pivot to end

    const pivot = nums[right];
    let i = left - 1; // boundary: arr[left..i] ≤ pivot

    for (let j = left; j < right; j++) {
      if (nums[j] <= pivot) {
        i++;
        [nums[i], nums[j]] = [nums[j], nums[i]];
      }
    }
    // Place pivot at its correct sorted position
    [nums[i + 1], nums[right]] = [nums[right], nums[i + 1]];
    const pivotPos = i + 1;

    if (pivotPos === target) return nums[pivotPos];   // found!
    if (pivotPos > target)  return quickSelect(left, pivotPos - 1);  // target in left
    return quickSelect(pivotPos + 1, right);           // target in right
  }

  return quickSelect(0, nums.length - 1);
}
```

## Problem 2 — Kth Largest Element in a Stream

### Problem
Design a class to find the kth largest element in a stream. The class should be initialized with `k` and an initial array `nums`. Each time `add(val)` is called, it returns the kth largest element of the current stream.

```
KthLargest kthLargest = new KthLargest(3, [4,5,8,2]);
kthLargest.add(3);  // stream = [4,5,8,2,3], return 4
kthLargest.add(5);  // stream = [4,5,8,2,3,5], return 5
kthLargest.add(10); // stream = [4,5,8,2,3,5,10], return 5
kthLargest.add(9);  // stream = [4,5,8,2,3,5,10,9], return 8
kthLargest.add(4);  // return 8
```

### Pattern Recognition
Min-heap of exactly size k — the heap permanently holds the k largest elements seen so far; its top (minimum of those k) is always the kth largest. Each new element either joins the heap (displacing the smallest of the current top-k) or is ignored.

### Key Insight
The heap is a "sliding window of k largest elements" — as new elements arrive, the heap either accepts them (if they're larger than the current kth largest) or rejects them. The invariant — "heap contains exactly the k largest elements seen so far, heap top = kth largest" — is maintained after every add in O(log k) time.

### Approach
Constructor: build min-heap from `nums`, trim to size k by repeatedly popping if `heap.size > k`. `add(val)`: if `heap.size < k` OR `val > heap.peek()`: push val; if `heap.size > k`: pop. Return `heap.peek()`.

### Solution

```js
class KthLargest {
  constructor(k, nums) {
    this.k = k;
    this.heap = new MinHeap(); // min-heap: top = kth largest

    for (const num of nums) {
      this._add(num);
    }
  }

  _add(val) {
    this.heap.push(val);
    // Keep only the k largest — eject the smallest if heap exceeds k
    if (this.heap.size() > this.k) {
      this.heap.pop(); // removes the minimum: the (k+1)th largest
    }
  }

  add(val) {
    this._add(val);
    return this.heap.peek(); // always the kth largest
  }
}
```

### Follow-up Questions

- "What if you need to support remove(val) in O(log k)?" — Standard heaps don't support arbitrary deletion efficiently. Use a "lazy deletion" heap: mark elements as deleted; pop while the top is marked deleted. Amortized O(log k).

## Problem 3 — K Closest Points to Origin

### Problem
Given an array of `points` where `points[i] = [xi, yi]` and an integer `k`, return the `k` closest points to the origin `(0, 0)`. The answer may be in any order.

```
Input:  points = [[1,3],[-2,2]], k = 1
Output: [[-2,2]]    // distances: √10 vs √8 — [-2,2] is closer

Input:  points = [[3,3],[5,-1],[-2,4]], k = 2
Output: [[3,3],[-2,4]]
```

### Pattern Recognition
Max-heap of size k ordered by squared distance — maintain the k closest points seen so far; eject the farthest (heap top) when a closer point arrives. Squared distance (`x² + y²`) preserves order and avoids expensive `Math.sqrt` calls.

### Key Insight
"K closest" = k smallest distances. This is a kth-smallest problem applied to distances. A max-heap of size k holds the k closest points — its top is the farthest among the k closest. If a new point is closer than the farthest of the current top-k, it belongs in the result and the farthest is ejected. Alternatively, QuickSelect on squared distances finds the kth smallest distance in O(n) and partitions the array so the first k elements are the k closest.

### Approach — Max-Heap
Define `dist(p) = p[0]² + p[1]²` (squared Euclidean — no sqrt needed). Maintain a max-heap of size k ordered by distance. For each point: push it; if heap size > k, pop the farthest. Return all remaining heap elements.

### Solution

```js
function kClosest(points, k) {
  // Max-heap ordered by squared distance (largest distance = heap top)
  const heap = new MinHeap((a, b) => b[2] - a[2]); // max-heap: larger dist = higher priority

  for (const [x, y] of points) {
    const dist = x * x + y * y; // squared distance — no Math.sqrt needed
    heap.push([x, y, dist]);

    // If we have more than k points, eject the farthest (heap top in a max-heap)
    if (heap.size() > k) {
      heap.pop(); // removes the point with the largest squared distance
    }
  }

  // Remaining k elements are the k closest points
  return heap.heap.map(([x, y]) => [x, y]);
}

// Alternative: QuickSelect on squared distances — O(n) average, O(1) extra space
function kClosestQuickSelect(points, k) {
  const dist = p => p[0] * p[0] + p[1] * p[1];

  function partition(left, right) {
    const pivotDist = dist(points[right]);
    let i = left - 1;
    for (let j = left; j < right; j++) {
      if (dist(points[j]) <= pivotDist) {
        i++;
        [points[i], points[j]] = [points[j], points[i]];
      }
    }
    [points[i + 1], points[right]] = [points[right], points[i + 1]];
    return i + 1;
  }

  function select(left, right) {
    const p = partition(left, right);
    if (p === k - 1) return;           // first k elements are exactly the k closest
    if (p < k - 1) select(p + 1, right);
    else select(left, p - 1);
  }

  select(0, points.length - 1);
  return points.slice(0, k); // first k elements after QuickSelect are the k closest
}
```

- **Points with negative coordinates**: squared distance is always non-negative — negative coordinates are handled correctly.

- "3D points?" — Use `x² + y² + z²` for squared Euclidean distance. All approaches scale directly.

## Problem 4 — Find Median from Data Stream

### Problem
The median is the middle value in an ordered list. Implement `MedianFinder` with `addNum(int num)` and `findMedian()` operations.

```
MedianFinder mf = new MedianFinder();
mf.addNum(1);   // arr = [1]
mf.findMedian() // return 1.0
mf.addNum(2);   // arr = [1,2]
mf.findMedian() // return 1.5   ((1+2)/2)
mf.addNum(3);   // arr = [1,2,3]
mf.findMedian() // return 2.0
```

### Pattern Recognition
Two-heap (max-heap lower half + min-heap upper half) — maintain the invariant that the lower half is always ≤ the upper half, and the size difference is at most 1. The median is derivable in O(1) from the two heap tops.

### Key Insight
A sorted array's median is determined by the boundary between its two halves. The max-heap's top is the largest element in the lower half (the "left median"); the min-heap's top is the smallest element in the upper half (the "right median"). For odd totals: the extra element is in the max-heap (by convention) — it IS the median. For even totals: the median is the average of the two tops.

### Approach
`lower` = max-heap, `upper` = min-heap. `addNum(num)`:
1. Push `num` to `lower`.
2. If `lower.top > upper.top` (order violated): move `lower.top` to `upper`.
3. Rebalance sizes: if `upper.size > lower.size`, move `upper.top` to `lower`.

`findMedian()`: if sizes equal → `(lower.top + upper.top) / 2`; else → `lower.top`.

### Solution

```js
class MedianFinder {
  constructor() {
    this.lower = new MinHeap((a, b) => b - a); // max-heap: holds smaller half
    this.upper = new MinHeap((a, b) => a - b); // min-heap: holds larger half
  }

  addNum(num) {
    // Step 1: always add to the lower (max) heap first
    this.lower.push(num);

    // Step 2: fix order — ensure lower.top ≤ upper.top
    if (this.upper.size() > 0 && this.lower.peek() > this.upper.peek()) {
      this.upper.push(this.lower.pop()); // move over-large element to upper
    }

    // Step 3: rebalance sizes — lower should have equal or one more element
    if (this.upper.size() > this.lower.size()) {
      this.lower.push(this.upper.pop()); // move from upper to lower
    }
    // Invariant after addNum:
    //   lower.size == upper.size  OR  lower.size == upper.size + 1
    //   lower.top <= upper.top
  }

  findMedian() {
    if (this.lower.size() === this.upper.size()) {
      // Even total: average of the two "middle" elements
      return (this.lower.peek() + this.upper.peek()) / 2;
    }
    // Odd total: extra element is in lower (by rebalancing convention)
    return this.lower.peek();
  }
}
```

- **Integer overflow**: `(lower.peek() + upper.peek()) / 2` — for large integers in languages with fixed-width integers, use `lower.peek() / 2 + upper.peek() / 2` to avoid overflow.

### Follow-up Questions
- "Follow-up: if all integers are in [0,100]?" — Use a count array of size 101; findMedian scans the array to find the kth-percentile position. O(1) per addNum (just increment); O(100) = O(1) per findMedian.
- "Follow-up: if 99% of values are in [0, 100]?" — Use the count array for [0,100]; handle outliers separately with a small heap. Amortized O(1) for the common case.
- "Kth percentile instead of median?" — Maintain lower heap of size k, upper heap of size n-k. Rebalancing rule: lower.size stays exactly k. Lower.top is the kth smallest.

## Problem 5 — Kth Smallest Element in a Sorted Matrix

### Problem
Given an `n × n` matrix where each row and column is sorted in ascending order, find the kth smallest element in the matrix.

```
Input:  matrix = [[1,5,9],[10,11,13],[12,13,15]], k = 8
Output: 13

Input:  matrix = [[-5]], k = 1
Output: -5
```

### Pattern Recognition
Binary search on value — binary search over the value range `[matrix[0][0], matrix[n-1][n-1]]`; for each candidate `mid`, count how many elements are ≤ `mid` using the O(n) staircase technique; converge when `lo == hi`.

### Key Insight
The matrix is not fully sorted (it can't be flattened into a 1D sorted array by reading row by row). But we can binary search on values: pick a candidate value `mid`; count elements ≤ `mid` using the staircase; adjust lo/hi. The answer is guaranteed to be an actual matrix element (the binary search converges to the smallest value for which `count ≥ k`).

### Approach
`lo = matrix[0][0]`, `hi = matrix[n-1][n-1]`. While `lo < hi`: `mid = (lo + hi) >> 1`; `count = countLessOrEqual(mid)`. If `count < k`: `lo = mid + 1` (the kth element is > mid). Else: `hi = mid` (the kth element is ≤ mid). Return `lo`.

`countLessOrEqual(mid)`: start at `(row=n-1, col=0)` (bottom-left). While in bounds: if `matrix[row][col] ≤ mid`: count += `row + 1` (entire column up to row); `col++`. Else: `row--`. Return count.

### Solution

```js
function kthSmallest(matrix, k) {
  const n = matrix.length;
  let lo = matrix[0][0];        // global minimum
  let hi = matrix[n-1][n-1];   // global maximum

  // Count elements ≤ mid using staircase traversal — O(n)
  function countLessOrEqual(mid) {
    let count = 0;
    let row = n - 1;   // start at bottom-left corner
    let col = 0;

    while (row >= 0 && col < n) {
      if (matrix[row][col] <= mid) {
        // All elements in column col, rows 0..row, are ≤ mid (column sorted ascending)
        count += row + 1;
        col++;       // move right to next column
      } else {
        row--;       // this row's element is too large — move up
      }
    }
    return count;
  }

  while (lo < hi) {
    const mid = lo + Math.floor((hi - lo) / 2);
    const count = countLessOrEqual(mid);

    if (count < k) {
      lo = mid + 1; // kth element is strictly greater than mid
    } else {
      hi = mid;     // kth element is ≤ mid (mid could be the answer)
    }
  }

  return lo; // lo == hi == kth smallest element's value
}
```

### Dry Run


### Complexity
- Time: O(n × log(max - min)) — at most O(log V) binary search iterations (V = value range), each with O(n) staircase count.
- Space: O(1) — only scalar variables.

### Edge Cases
- **1×1 matrix**: lo = hi = matrix[0][0]. Loop doesn't execute. Returns the only element. Correct for k=1.
- **k = 1**: first iteration's count will be 0 < 1 (if lo < all elements) or immediately converge. Returns global minimum `matrix[0][0]`.
- **k = n²**: binary search converges to the global maximum `matrix[n-1][n-1]`.
- **Duplicate values** (e.g., two 13s): count correctly counts all occurrences; binary search converges to 13 when count ≥ k, guaranteeing a matrix element is returned.
- **Why `lo = mid + 1` is safe**: if `count < k`, the kth element is strictly greater than `mid`. Since `mid` may not be a matrix element, `mid + 1` might also not be — but binary search will continue converging. The final `lo` is guaranteed to be a matrix element because: at convergence, `lo = hi = smallest value where countLessOrEqual ≥ k`, and that value exists in the matrix (it's the kth smallest element).

### Follow-up Questions
- "Heap-based approach?" — Use a min-heap of (value, row, col) pairs; start with all first-column elements; pop k times; each pop adds the right neighbor (next element in the same row). O(k log n) time. Better when k << n² but worse when k is large.
- "Unsorted matrix — Kth smallest?" — QuickSelect on a flattened copy: O(n²) average. Or sort: O(n² log n).

## Problem 6 — Top K Frequent Elements

### Problem
Given an integer array `nums` and an integer `k`, return the `k` most frequent elements. You may return the answer in any order.

```
Input:  nums = [1,1,1,2,2,3], k = 2  → Output: [1,2]
Input:  nums = [1], k = 1            → Output: [1]
```

### Pattern Recognition
Frequency HashMap + min-heap of size k ordered by frequency — build a frequency map first; then use a min-heap to maintain the k most frequent elements, evicting the least frequent when heap exceeds size k. This is the heap complement to the bucket-sort approach (covered in the hashing document).

### Key Insight
This is a kth-largest problem applied to frequencies rather than values. The min-heap of size k holds the k highest frequencies seen so far; its top is the least frequent of the current top-k. When a new element's frequency exceeds the heap top, it displaces the least-frequent entry. After processing all distinct elements, the heap contains exactly the k most frequent.

### Approach
Build `freq` map. For each `(value, count)` in `freq`: push `[count, value]` to a min-heap ordered by count; if heap size > k, pop. Return all elements from the heap.

### Solution

```js
function topKFrequent(nums, k) {
  // Step 1: build frequency map
  const freq = new Map();
  for (const num of nums) {
    freq.set(num, (freq.get(num) ?? 0) + 1);
  }

  // Step 2: min-heap of size k ordered by frequency
  // Heap stores [frequency, value] — comparator on frequency
  const heap = new MinHeap((a, b) => a[0] - b[0]); // min-heap: lowest freq = top

  for (const [val, count] of freq) {
    heap.push([count, val]);
    if (heap.size() > k) {
      heap.pop(); // eject the element with the lowest frequency
    }
  }

  // Step 3: extract values from heap
  return heap.heap.map(([count, val]) => val);
}
```

### Dry Run

```
nums = [1,1,1,2,2,3], k=2.

Step 1 — Frequency map:
freq = {1→3, 2→2, 3→1}

Step 2 — Min-heap (ordered by frequency, size cap k=2):

[val=1, count=3]: push [3,1]. heap=[[3,1]]. size=1≤2.
[val=2, count=2]: push [2,2]. heap=[[2,2],[3,1]]. size=2≤2.
  (min-heap: 2 at top since 2<3)
[val=3, count=1]: push [1,3]. heap=[[1,3],[3,1],[2,2]]. size=3>2.
  pop() → removes [1,3] (lowest frequency=1). heap=[[2,2],[3,1]].

Step 3 — Extract: [[2,2],[3,1]] → values [2, 1].
Output: [1, 2] (order may vary) ✓

Verification: top-2 frequent in [1,1,1,2,2,3]: 1 (freq=3), 2 (freq=2). ✓
```

### Complexity
- Time: O(n + d log k) — O(n) to build the frequency map (d = number of distinct elements); O(d log k) for heap processing of d distinct elements.
- Space: O(d + k) — O(d) for frequency map, O(k) for heap.

### Edge Cases
- **k equals number of distinct elements**: all elements in the frequency map enter the heap, none are ejected. All distinct elements returned.
- **Multiple elements tied at the kth frequency**: the heap may return any k elements from the tie group — the problem allows any valid answer. If a specific tiebreaker is needed (e.g., lexicographically smaller), augment the comparator.
- **Single element array**: `freq = {nums[0]→1}`. Heap has one entry, k=1. Returns `[nums[0]]`.
- **All elements same frequency**: heap can't distinguish based on frequency alone — any k elements are a valid answer.

### Follow-up Questions
- "O(n) solution?" — Bucket sort: create an array of n+1 buckets indexed by frequency; place each element in its frequency bucket; scan from bucket n down to 1, collecting elements until k are gathered. O(n) time, O(n) space. (Covered in the hashing document.)
- "Top K frequent words (alphabetically tiebroken)?" — Augment comparator: `(a, b) => a[0] !== b[0] ? a[0] - b[0] : b[1].localeCompare(a[1])` — lower frequency OR alphabetically later (for min-heap, "lower priority" means ejected first). This ensures that among equal frequencies, alphabetically larger words are ejected first, keeping alphabetically smaller ones.
- "Online top-k frequent (stream of elements)?" — Keep the frequency map dynamically updated; after each update, check if the updated element's frequency now exceeds the heap's minimum — if so, update the heap. O(log k) amortized per element.

```
What is the problem's structure?
│
├── STATIC ARRAY, ONE ANSWER NEEDED (no streaming, no dynamic updates)?
│   ├── k is arbitrary → QuickSelect (random pivot)

│   │   target = n - k for kth largest (0-indexed in sorted ascending).

│   │   Min-heap of size k. O(log k) per insert, O(1) query.
│   │   Heap top = kth largest at all times.
│   │
│   └── k = n/2 (median) → Two-heap pattern

│       Invariant: sizes differ by ≤ 1, lower.top ≤ upper.top.
│
├── STRUCTURED INPUT (sorted matrix, sorted subarrays)?
│   └── Binary search on VALUE RANGE
│       lo = minimum, hi = maximum.

│       Adjust lo/hi based on count vs k.
│       O(n log V), O(1) space.
│

│
├── DISTANCE-BASED (k closest points)?
│   └── Max-heap of size k by distance. O(n log k), O(k) space.
│       No Math.sqrt needed — squared distance preserves order.
│
└── HEAP TYPE REMINDER:
    Kth LARGEST  → MIN-heap of size k (top = kth largest)
    Kth SMALLEST → MAX-heap of size k (top = kth smallest)
    MEDIAN       → max-heap (lower) + min-heap (upper)
```

## Common Bugs Checklist

Before submitting any kth element solution, verify:

1. **QuickSelect target index: `n - k` for kth largest (0-indexed ascending), not `k - 1`?** — Kth largest in ascending-sorted array is at index `n - k`. Index `k - 1` is the kth smallest. Confusing these returns the wrong element. Double-check: for k=1 (largest), target = n-1 = last element ✓. For k=n (smallest), target = 0 = first element ✓.

2. **QuickSelect: random pivot or shuffled input?** — Using the last (or first) element as a fixed pivot causes O(n²) on sorted or nearly-sorted input — the most common real-world scenario. Always either `Math.random()` to pick the pivot index, or shuffle the array before the call. Never use a fixed deterministic pivot in production QuickSelect.

3. **Lomuto partition: `arr[j] <= pivot` (not `< pivot`) to include elements equal to pivot on the left?** — With strict `<`, all elements equal to the pivot stay to the right, and the pivot is placed at index `i+1`. This means elements equal to the pivot are not grouped together, potentially causing O(n²) performance when all elements are equal. Use `<=` to group equal elements with the pivot's left side.

4. **Min-heap for kth LARGEST (not max-heap)?** — Counterintuitive but correct: the min-heap holds the k largest elements; its top (minimum of those k) is the kth largest. Using a max-heap for kth largest would give you the maximum, not the kth maximum. The memory hook: heap type is opposite to what you're finding.

5. **Heap size check: `size > k` (after push) triggers pop, not `size >= k`?** — You want exactly k elements in the heap. Push first, then pop if `size > k`. If you pop when `size >= k`, you'd pop when the heap has exactly k elements — reducing it to k-1. Always: push → if size > k: pop.

6. **Two-heap: rebalancing BOTH size violations, not just one direction?** — Two conditions to check: (1) `lower.size > upper.size + 1`: lower too big → move top to upper. (2) `upper.size > lower.size`: upper too big → move top to lower. Checking only one direction leaves the invariant broken half the time, producing incorrect medians for every other insertion.

7. **Two-heap: fixing ORDER (lower.top ≤ upper.top) BEFORE fixing SIZE?** — If you rebalance sizes before fixing the order, a large element from lower might stay in lower while a small element from upper gets pushed to lower — violating the order invariant. Always fix order first (move over-large lower.top to upper if needed), then fix sizes.

8. **Sorted matrix binary search: `lo = mid + 1` when count < k, NOT `lo = mid`?** — If count < k, the kth element is strictly greater than mid — so `lo = mid + 1`. Using `lo = mid` leads to an infinite loop when `hi = mid + 1` and count is consistently < k.

9. **Sorted matrix binary search: `hi = mid` (not `hi = mid - 1`) when count >= k?** — When count ≥ k, `mid` might be the answer — you can't exclude it with `hi = mid - 1`. Setting `hi = mid` preserves `mid` as a candidate. Combined with `lo = mid + 1` for the other branch, this guarantees convergence (the interval strictly shrinks: left moves up by 1, right stays at mid or moves down — never both staying).

10. **Sorted matrix staircase counting: `count += row + 1` (number of rows in the column from top to current), not just `count += 1`?** — At position (row, col), if `matrix[row][col] ≤ mid`, then all elements in column col from rows 0..row are ≤ mid (the column is sorted ascending). Add `row + 1` (row 0 through row inclusive). Adding just 1 undercounts by a factor of (row+1).

11. **QuickSelect returning after finding `pivotPos === target`?** — Once the pivot is at its correct sorted position and it equals the target index, return immediately. Forgetting this and continuing to recurse wastes time and may cause an off-by-one in the recursion bounds.

12. **Top K frequent: building frequency map BEFORE heap processing, not interleaving?** — The frequency of each element must be fully counted before determining which elements belong in the top-k heap. Interleaving (processing heap entries before all frequencies are known) gives incorrect frequencies for elements that appear later in the array.

---

**Final Tip:** At the 5 YOE level, the decisive signal for kth element problems is identifying *two axes* before writing code: (1) **Static vs streaming** — "Is the full array given upfront (QuickSelect/binary-search) or do elements arrive one by one (heap of size k / two-heap)?"; (2) **Structured vs unstructured** — "Does the input have exploitable structure like sorted rows and columns (binary search on value) or is it arbitrary (QuickSelect or heap)?". State these two decisions with justifications before touching any code: "This is a static, unstructured array and I need one answer — QuickSelect at O(n) average is optimal; I'll use a random pivot to avoid the sorted-input worst case." Or: "Elements arrive as a stream and I need the kth largest after every insertion — min-heap of size k gives O(log k) per insert and O(1) query, and I never need to see past elements again." That framing — naming the scenario, the structure, the algorithm, and its complexity in one sentence — is the mark of a senior who owns the selection problem family.
