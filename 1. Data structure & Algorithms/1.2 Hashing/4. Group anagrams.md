## Topic A: The Complement Lookup Pattern (Two-Sum Family)

### Section A1: Fundamentals

**Q1. What is the complement lookup pattern, and what structural property makes it different from the "count then query" approach?**

A: The complement lookup pattern is the canonical hashing technique where you *simultaneously build and query* the HashMap within a single pass. For any element `x`, the "complement" is the value `target - x` that, paired with `x`, satisfies the problem condition. Before inserting `x` into the map, you check whether its complement already exists — if it does, the pair is found. This differs from "count then query" (where the full count phase must complete before any query) because the answer here depends only on *elements seen so far*, not on the global distribution. The complement is a question about the past ("has any previous element been the right partner for me?"), making the interleaved build+query not just valid but optimal.

```
Count-then-query (wrong for Two Sum):
  Build full freq map, then scan for complement
  → Will find (x, x) as a pair when x appears only once

Complement lookup (correct):
  For each x, query map for (target-x) BEFORE inserting x
  → Only finds genuine distinct-index pairs
```

**Q2. Why must you query the map BEFORE inserting the current element in Two Sum?**

A: Querying after insertion causes false self-pairing. If `target = 10` and `x = 5`, inserting `5` then checking for `10-5=5` finds the same element paired with itself — violating the "different indices" constraint. The invariant is: *the map at query time contains only elements at indices strictly less than the current index*. This "elements seen so far" invariant, maintained by the pre-insert query, guarantees any complement found was at a distinct earlier position.

```
WRONG (query after insert):
  map.set(5, 0)        // insert index 0 (value 5)
  map.has(5) → true    // complement = 10-5=5 → found! But it's the SAME element.

CORRECT (query before insert):
  map.has(5) → false   // no complement yet
  map.set(5, 0)        // now insert
  ...later at index 3 with nums[3]=5...
  map.has(5) → true    // found at a genuinely different earlier index ✓
```

**Q3. How does the Two Sum complement pattern extend to "count pairs with sum k"?**

A: When the problem asks to *count* all pairs (not find one), duplicate elements matter. Two sub-cases:

- **Distinct elements**: each complement hit counts one new pair. Traverse left-to-right; for each `x`, add `freq.get(target-x) ?? 0` to a running count, then increment `freq[x]`. This avoids double-counting: each pair is discovered exactly once, when its *second* element is processed.
- **Same element forms a pair** (when `target` is even and `x = target/2`): the number of pairs from `c` copies of `x` is `c*(c-1)/2` — computed after the full count phase for that specific value.

```js
// Count all pairs summing to k — left-to-right accumulation avoids double-counting
function countPairs(nums, k) {
  const freq = new Map();
  let count = 0;

  for (const x of nums) {
    count += freq.get(k - x) ?? 0; // accumulate matches from earlier elements
    freq.set(x, (freq.get(x) ?? 0) + 1); // then record current element
  }
  return count;
}
```

**Q4. What is the "Three Sum" algorithmic reduction, and why can't a pure HashMap approach match the sort + two-pointer solution cleanly?**

A: Three Sum reduces to: for each element `nums[i]`, solve Two Sum on the remaining subarray with target `-nums[i]`. A pure HashMap approach works but produces duplicate triplets naturally — `[-1, 0, 1]` and `[-1, 1, 0]` would both appear. Deduplication requires either sorting each triplet before inserting into a results Set (extra overhead), or sorting the input first and skipping duplicates inline. The standard O(n²) solution sorts the array and uses two pointers for the inner Two Sum — sorted order makes duplicate-skipping (`while nums[i] == nums[i-1]: skip`) O(1), producing unique triplets cleanly without a results HashSet.

```
Two Sum (HashMap)          → O(n),   O(n)  extra space
Three Sum (sort+2-pointer) → O(n²),  O(1)  extra space (excl. output)
Four Sum  (sort+2-pointer) → O(n³),  O(1)  extra space
k-Sum (recursive reduction) → O(n^(k-1))
```

**Q5. How does the prefix-sum + HashMap pattern extend Two Sum to "subarray sum equals k"?**

A: Two Sum asks: do two *elements* sum to k? Subarray Sum asks: does any contiguous *subrange* sum to k? The connection: define `prefix[i]` as the running sum from index 0 to i. A subarray `[j..i]` has sum k iff `prefix[i] - prefix[j-1] = k`, i.e., `prefix[j-1] = prefix[i] - k`. This is exactly Two Sum, where one "element" is the current prefix sum and the other is a previously seen prefix sum stored in a HashMap. The map stores `{prefixSum → count of times seen}`, initialized with `{0 → 1}` (the empty prefix before any element).

```
Two Sum on array:        find i,j such that nums[i] + nums[j] = k
  → HashMap: has(k - nums[i]) among previous elements?

Subarray sum = k:        find j < i such that prefix[i] - prefix[j] = k
  → HashMap: has(prefix[i] - k) among previous prefix sums?

Same structure. The "complement" is now a prefix sum, not a raw element.
The HashMap's value type changes: index (Two Sum) → count (Subarray Sum).
```

**Q6. What is the "modular prefix sum" pattern for "subarray sum divisible by k"?**

A: A subarray `[j..i]` has sum divisible by k iff `(prefix[i] - prefix[j]) % k == 0`, which holds iff `prefix[i] % k == prefix[j] % k`. Store `{remainder → count}` (initialized `{0 → 1}`). At each step, query the count of the current remainder; add it to the result; then increment that remainder's count. Remainders must be normalized: `((prefix % k) + k) % k` handles negative prefix sums, since JavaScript's `%` can return negative values for negative operands.

```js
function subarraysDivByK(nums, k) {
  const remCount = new Map([[0, 1]]);
  let prefix = 0, result = 0;

  for (const x of nums) {
    prefix += x;
    const rem = ((prefix % k) + k) % k; // normalize to [0, k-1]
    result += remCount.get(rem) ?? 0;
    remCount.set(rem, (remCount.get(rem) ?? 0) + 1);
  }
  return result;
}
```

### Section A2: Advanced Patterns

**Q7. What is the "meet in the middle" technique for Four Sum II, and why does it reduce O(n⁴) to O(n²)?**

A: Four Sum II counts quadruples `(i,j,k,l)` from four arrays summing to 0. The naive four-loop approach is O(n⁴). Splitting into two pairs: enumerate all `n²` pairwise sums `A[i]+B[j]` into a HashMap in O(n²). Then for each of the `n²` pairs `(C[k], D[l])`, look up how many entries in the map equal `-(C[k]+D[l])` in O(1). Total: O(n²) time, O(n²) space. The key: hashing replaces two of the four nested loops, halving the complexity exponent. This "meet in the middle via HashMap" pattern generalizes to any problem that can be split into two independent halves.

```js
function fourSumCount(A, B, C, D) {
  const abSums = new Map();
  for (const a of A)
    for (const b of B)
      abSums.set(a + b, (abSums.get(a + b) ?? 0) + 1);

  let count = 0;
  for (const c of C)
    for (const d of D)
      count += abSums.get(-(c + d)) ?? 0;

  return count;
}
```

**Q8. What is the "longest subarray summing to k" problem, and how does the prefix-sum map differ from the count-pair variant?**

A: For counting pairs, the map stores `{prefixSum → count}`. For the longest subarray, the map stores `{prefixSum → first index where this sum occurred}` and records only the first occurrence (never overwriting). When a repeat prefix sum is found, the subarray between the first occurrence and the current index has sum 0 (or sum k after the complement transform), and its length is `currentIndex - storedIndex`. Using only the first occurrence ensures the maximum-length subarray is captured.

```js
function maxSubarraySumEqualsK(nums, k) {
  const firstSeen = new Map([[0, -1]]); // prefix sum → earliest index
  let sum = 0, best = 0;

  for (let i = 0; i < nums.length; i++) {
    sum += nums[i];

    if (firstSeen.has(sum - k)) {
      best = Math.max(best, i - firstSeen.get(sum - k));
    }
    if (!firstSeen.has(sum)) {
      firstSeen.set(sum, i); // only store FIRST occurrence
    }
  }
  return best;
}
```

**Q9. When should you use a HashMap vs a HashSet for complement-based problems?**

A: The distinction is whether you need *associated data* or just *existence*:

- **HashSet** — when only existence matters: "does the complement exist?", "have I seen this value?". Use when the answer is true/false, or when values themselves form the answer. Example: "does any pair in the array sum to k?" — a set of seen values, queried for the complement.
- **HashMap** — when associated data matters: "what *index* was the complement at?", "how many times was the complement seen?", "which strings share this fingerprint?". Use when finding a match requires retrieving metadata stored with the key.

```
"Does any pair sum to k?" → HashSet (existence only)
"Return indices of the pair" → HashMap {value → index}
"Count all pairs summing to k" → HashMap {value → count}
"Group strings by anagram class" → HashMap {fingerprint → list of strings}
```

## Topic B: Fingerprint Hashing (Group Anagrams Family)

### Section B1: Fundamentals

**Q10. What is the "fingerprint as HashMap key" technique, and what makes a valid fingerprint?**

A: A fingerprint is a canonical representation of a character multiset — two strings map to the same fingerprint if and only if they are anagrams of each other. A fingerprint is valid when it is: (1) **collision-free** — no two non-anagram strings produce the same fingerprint; (2) **canonical** — all anagram strings produce byte-for-byte identical fingerprints; (3) **efficiently computable** — ideally O(|string|). The two standard choices:

- **Sorted string** — `"eat" → "aet"`, `"tea" → "aet"`. O(L log L) per string. Simple and universally applicable to any character set.
- **Count vector serialized to string** — `"eat" → "1#0#0#0#1#0#...#1#..."`. O(L + σ) per string. Faster when L >> σ; requires a bounded alphabet.

```
"eat" → sort → "aet"    \
"tea" → sort → "aet"    → same fingerprint → same anagram group
"ate" → sort → "aet"    /

"tan" → sort → "ant"    → different fingerprint → different group
"bat" → sort → "abt"    → different fingerprint → different group
```

**Q11. Walk through the Group Anagrams algorithm from first principles.**

A: Group Anagrams: given an array of strings, collect all anagram strings into the same sub-list. Algorithm:

1. Create a `groups` HashMap: fingerprint → list of original strings.
2. For each string `s`: compute its fingerprint `key`.
3. If `key` is new, create an empty list at `groups[key]`; then push `s` into `groups[key]`.
4. Return all values of `groups`.

Time: O(N × L log L) with sorted-string fingerprint, or O(N × (L + σ)) with count-vector fingerprint, where N = number of strings, L = max string length, σ = alphabet size. Space: O(N × L) for the grouped output.

```js
// Approach 1: Sorted-string fingerprint — O(L log L) per string
function groupAnagrams(strs) {
  const groups = new Map();

  for (const s of strs) {
    const key = [...s].sort().join(''); // canonical form of the character multiset
    if (!groups.has(key)) groups.set(key, []);
    groups.get(key).push(s);
  }

  return [...groups.values()];
}

// Approach 2: Count-vector fingerprint — O(L + σ) per string (faster for long strings)
function groupAnagramsOptimized(strs) {
  const groups = new Map();

  for (const s of strs) {
    const count = new Array(26).fill(0);
    for (const ch of s) count[ch.charCodeAt(0) - 97]++;
    const key = count.join('#'); // delimiter prevents collisions (see Q13)
    if (!groups.has(key)) groups.set(key, []);
    groups.get(key).push(s);
  }

  return [...groups.values()];
}
```

**Q12. What are the trade-offs between the sorted-string and count-vector fingerprints?**

A:

| Property | Sorted String | Count Vector |
|---|---|---|
| Computation cost | O(L log L) | O(L + σ) |
| Key length | L characters | 2σ − 1 characters (with delimiters) |
| Works for Unicode | Yes (standard sort) | Only if σ is enumerable and bounded |
| Collision safety | Guaranteed | Guaranteed with proper delimiters |
| Code complexity | Minimal — one line | More verbose (count array + serialize) |
| When to prefer | Default choice; short strings; Unicode | Long strings over small alphabet (e.g. L > 100, σ = 26) |

For lowercase-letter strings, both are correct. The sort costs O(L log L) vs O(L) for the count vector — for very long strings or high-N inputs, the count vector wins. For simple interview use, sorted string is the safer default.

**Q13. Why is a delimiter required in the count-vector serialization, and what is the exact collision scenario without one?**

A: Without delimiters, `[1, 10]` and `[11, 0]` both serialize to `"110"` — a collision between two different frequency distributions, causing strings from different anagram groups to be bucketed together. With a delimiter like `#`, `[1, 10]` becomes `"1#10"` and `[11, 0]` becomes `"11#0"` — distinct and collision-free. The delimiter must be a character that cannot appear as part of a count digit (any non-numeric character works).

```
Without delimiter:
  freq of "a"=1, "k"=10  → "...1...10..."   → might serialize to "...110..."
  freq of "a"=11, "k"=0  → "...11...0..."   → same serialization "...110..." ← COLLISION

With '#' delimiter:
  [1, 10] → "1#10"    ← distinct
  [11, 0] → "11#0"    ← distinct ✓
```

### Section B2: Advanced Patterns

**Q14. What is the "isomorphic strings" problem, and how does it generalize the anagram fingerprint pattern?**

A: Two strings `s` and `t` are isomorphic if characters in `s` can be bijectively mapped to characters in `t` such that applying the map to `s` produces `t`. Unlike anagrams (same character multiset), isomorphism allows different characters — what must match is the *pattern of repetitions*. A two-map bijection check is required: `sToT` ensures each `s`-character always maps to the same `t`-character; `tToS` ensures no two `s`-characters map to the same `t`-character. A single `sToT` map catches invalid one-to-one violations but misses many-to-one violations (e.g., `s="ab"`, `t="aa"` would incorrectly pass with only `sToT`).

```js
function isIsomorphic(s, t) {
  const sToT = new Map(), tToS = new Map();
  for (let i = 0; i < s.length; i++) {
    const sc = s[i], tc = t[i];
    if ((sToT.has(sc) && sToT.get(sc) !== tc) ||
        (tToS.has(tc) && tToS.get(tc) !== sc)) return false;
    sToT.set(sc, tc);
    tToS.set(tc, sc);
  }
  return true;
}
// s="ab", t="aa" — without tToS: 'a'→'a' ✓, 'b'→'a' set without conflict, wrongly returns true.
// With tToS: when processing 'b'→'a', tToS already has 'a'→'a' (from 'a'), conflict caught ✓.
```

**Q15. What is the "word pattern" problem, and how does it extend isomorphic strings to the word level?**

A: Given a pattern string (e.g., `"abba"`) and a sentence (e.g., `"dog cat cat dog"`), determine if the sentence follows the pattern — each letter maps bijectively to a distinct word. It is structurally identical to isomorphic strings; only the granularity changes (characters → words). The same two-map bijection check applies unchanged; tokenize the sentence on spaces before comparing.

```js
function wordPattern(pattern, s) {
  const words = s.split(' ');
  if (pattern.length !== words.length) return false;

  const pToW = new Map(), wToP = new Map();
  for (let i = 0; i < pattern.length; i++) {
    const p = pattern[i], w = words[i];
    if ((pToW.has(p) && pToW.get(p) !== w) ||
        (wToP.has(w) && wToP.get(w) !== p)) return false;
    pToW.set(p, w);
    wToP.set(w, p);
  }
  return true;
}
```

## Topic C: HashSet Membership & Existence Patterns

### Section C1: Fundamentals

**Q16. What is the HashSet existence-check pattern, and when does it outperform a HashMap?**

A: A HashSet stores elements without associated values, supporting O(1) `has(x)` and `add(x)`. It answers two questions in O(1): (1) "Have I seen this element before?" — used for duplicate detection, cycle detection, and visited-node tracking; (2) "Does this specific value exist in this collection?" — used for complement lookups where only presence (not count or index) matters. Compared to a frequency HashMap, a HashSet uses less memory (no value storage), has simpler semantics (no `?? 0` boilerplate), and signals to the reader that count doesn't matter — it is the correct tool whenever the answer is purely yes/no.

```
"Does any pair sum to k?"       → HashSet — query has(complement) only
"What index was the complement?"→ HashMap {value → index}
"How many copies of x exist?"   → HashMap {value → count}
Rule: if you'd only ever call map.has() and never map.get(), use a Set.
```

**Q17. How does the "Longest Consecutive Sequence" problem use HashSet membership to achieve O(n)?**

A: The naive approach starts a counting chain from every element and may re-traverse the same sequence multiple times. The O(n) insight: only start a chain at `x` if `x-1` is NOT in the set (i.e., `x` is the sequence's minimum — its left endpoint). Every non-starting element (`x-1` in the set) is skipped outright in the outer loop, and is only visited during the extension of its sequence's start. Since each element starts at most one chain and is extended over at most once across all chains, total work is O(n).

```js
function longestConsecutive(nums) {
  const numSet = new Set(nums); // O(n) build, O(1) membership
  let best = 0;

  for (const x of numSet) {
    if (!numSet.has(x - 1)) {       // only start from left endpoints
      let length = 1;
      while (numSet.has(x + length)) length++;
      best = Math.max(best, length);
    }
  }
  return best;
}
// Total inner while iterations across all outer loop executions = n (amortized)
// → O(n) overall despite the nested structure
```

**Q18. What is the "Contains Duplicate II" pattern, and why does a sliding-window HashSet enforce the distance constraint exactly?**

A: Contains Duplicate II: are there indices `i`, `j` with `nums[i] == nums[j]` and `|i-j| <= k`? Maintain a HashSet representing the last `k` elements (the active window). For each new element: if already in the set, a duplicate within distance ≤ k exists — return true. Otherwise add it; if the set now has `k+1` elements, evict `nums[i-k]`. The set holds exactly the elements at indices `[i-k, i-1]` when checking `nums[i]`, so any membership hit guarantees a distance ≤ k. Eviction is exact: `nums[i-k]` is the oldest element that just fell outside the range.

```js
function containsNearbyDuplicate(nums, k) {
  const window = new Set();
  for (let i = 0; i < nums.length; i++) {
    if (window.has(nums[i])) return true;     // duplicate within distance k
    window.add(nums[i]);
    if (window.size > k) window.delete(nums[i - k]); // evict oldest out-of-range element
  }
  return false;
}
```

### Section C2: Advanced Patterns

**Q19. What does it mean to "normalize" an element into a canonical form before hashing, and what problems does it solve?**

A: Normalization transforms an element into a standard representation before using it as a HashMap key, so that elements that are "equivalent" under the problem's equivalence relation map to the same key. Examples: sorting a string's characters (Group Anagrams), lowercasing before hashing (case-insensitive grouping), computing absolute value (grouping by magnitude), rounding to nearest bin (range-based grouping). The key property: two elements `a` and `b` should be in the same group iff `normalize(a) == normalize(b)`. Normalization moves the equivalence logic entirely into key computation, leaving the HashMap to do straightforward equality matching.

```
Group by: anagram class    → normalize = sort characters
Group by: case-insensitive → normalize = toLowerCase
Group by: absolute value   → normalize = Math.abs
Group by: first letter     → normalize = s[0]
Group by: length           → normalize = s.length
```

**Q20. In what sense is the Group Anagrams problem a "partitioning" problem, and how does hashing solve it in one pass?**

A: Partitioning means dividing a set of elements into non-overlapping, collectively exhaustive subsets (groups) where membership in a subset is determined by an equivalence relation. For Group Anagrams, the equivalence relation is "same character multiset." The HashMap partitions automatically: each distinct key (fingerprint) corresponds to exactly one equivalence class (group), and each string is assigned to exactly one key. The single pass assigns every string to its class in O(1) per string — the HashMap is literally implementing a partition of the input set. Scanning all strings twice (once to collect all fingerprints, once to assign) would add no value; the assignment is deterministic and needs no global context.

## Topic D: Cross-Topic & Interview-Style Questions

**Q21. "Compare the Two Sum and Subarray Sum Equals K problems: what's structurally identical and what's different?"**

A: Both use the complement-lookup-in-a-HashMap pattern: for each element processed, query the map for the "needed complement," then update the map. What differs:

| Dimension | Two Sum | Subarray Sum = k |
|---|---|---|
| Key stored | Raw array value | Prefix sum |
| Value stored | Index | Count |
| Complement | `target - nums[i]` | `currentPrefixSum - k` |
| Init state | Empty map | `{0 → 1}` (empty prefix) |
| Action on match | Return `[savedIdx, i]` | `count += map.get(complement)` |
| Multiplicity | One pair (return early) | All pairs (accumulate) |

The structural template is identical; the instantiation of each slot changes based on whether you're matching elements or prefix sums, and whether you want one answer or a count.

**Q22. "Why does Group Anagrams require a HashMap of lists while Two Sum requires a HashMap of single values?"**

A: Two Sum's map is a one-to-one lookup: each value maps to exactly one index (in the standard formulation guaranteeing a unique answer). The map entry is a single scalar. Group Anagrams' map is a one-to-many bucketing: many strings can share the same fingerprint (be anagrams of each other), so the map entry is a list. This reflects the problem's type: Two Sum is a pair-finding problem (find two specific elements that satisfy a condition), Group Anagrams is a partitioning problem (sort elements into equivalence classes). The multiplicity of the mapping is a direct structural consequence of the problem type, not a coincidence.

**Q23. "Describe the decision process for choosing between a HashSet and a HashMap."**

A: Ask: "what do I need to retrieve when I find a match?" If the answer is "nothing — I just need to know the element exists," use a HashSet. If the answer is "the index," "the count," or "the list of strings with this fingerprint," use a HashMap with the appropriate value type. In code terms: if you'd only ever call `set.has(x)` and never need a corresponding `.get(x)`, use a Set. If `.get(x)` is needed, use a Map.

```
"Does x's complement exist?" → Set.has(complement)      → HashSet
"Where is x's complement?"  → Map.get(complement)       → HashMap {val → index}
"How many copies?"          → Map.get(x) for count      → HashMap {val → count}
"What shares this key?"     → Map.get(key) for list     → HashMap {key → string[]}
```

**Q24. "In one sentence each, what role does the HashMap play in each of the five Two-Sum-family problems?"**

A:
- **Two Sum**: the map is a *memo of past elements* — queried for each element's complement to find a previously seen partner at a distinct index.
- **Count pairs with sum k**: the map is a *frequency ledger* — each new element's complement count is accumulated, and the element's own count is recorded for future elements.
- **Subarray Sum equals k**: the map is a *prefix-sum history* — queried for the complement prefix sum that would make the current subarray sum exactly k.
- **Subarray sum divisible by k**: the map is a *remainder histogram* — equal remainders identify pairs of prefix sums whose difference is divisible by k.
- **Four Sum II**: the map is a *pairwise-sum catalog from the first two arrays* — the second two arrays' pair sums are looked up as complements against this catalog.

**Q25. "A candidate solution uses a nested for-loop with a HashMap inside. What's the likely bug?"**

A: Building and querying the same HashMap inside nested loops is almost always wrong for one of two reasons: (1) the outer loop has already populated the map when the inner loop runs — potentially allowing self-matching or order-dependency issues; or (2) the map is re-initialized inside the outer loop, throwing away information from prior outer iterations and breaking cross-iteration lookups. The correct structure for most two-pass problems is to complete the outer build loop entirely before starting any inner query loop, or to use a single merged-pass left-to-right traversal with the careful pre-insert query order (for complement problems). Nested loops with a shared mutable HashMap almost always signal a design error.

## Problem 1 — Two Sum

### Problem
Given an array of integers `nums` and an integer `target`, return indices of the two numbers that add up to `target`. Each input has exactly one solution; the same element cannot be used twice.

```
Input:  nums = [2, 7, 11, 15], target = 9
Output: [0, 1]     // 2 + 7 = 9

Input:  nums = [3, 2, 4], target = 6
Output: [1, 2]     // 2 + 4 = 6

Input:  nums = [3, 3], target = 6
Output: [0, 1]     // 3 + 3 = 6, but at distinct indices
```

### Pattern Recognition
Complement lookup — single-pass HashMap queried *before* each insertion. The map stores `{value → index}` to reconstruct the answer pair on a hit.

### Key Insight
For any element `x`, its required partner is `target - x`. If that partner was seen at an earlier index, it's already in the map — we have our answer. Querying before inserting maintains the "elements seen so far" invariant, ensuring we never pair an element with itself and never produce duplicate index pairs.

### Approach
One pass: for each `nums[i]`, compute `complement = target - nums[i]`. If `seen.has(complement)`, return `[seen.get(complement), i]`. Otherwise `seen.set(nums[i], i)`. Repeat.

### Solution

```js
function twoSum(nums, target) {
  const seen = new Map(); // value → index of first occurrence

  for (let i = 0; i < nums.length; i++) {
    const complement = target - nums[i];

    // Query BEFORE inserting — "elements seen so far" invariant
    if (seen.has(complement)) {
      return [seen.get(complement), i];
    }

    seen.set(nums[i], i); // record this element for future iterations
  }

  return []; // problem guarantees exactly one solution — never reached
}
```

### Dry Run

```
nums = [3, 2, 4], target = 6
seen = {}

i=0, nums[0]=3: complement=3. seen.has(3)? No. seen={3→0}.
i=1, nums[1]=2: complement=4. seen.has(4)? No. seen={3→0, 2→1}.
i=2, nums[2]=4: complement=2. seen.has(2)? YES → return [seen.get(2), 2] = [1, 2]. ✓

Verification: nums[1] + nums[2] = 2 + 4 = 6 = target ✓
```

### Complexity
- Time: O(n) — one pass; each HashMap operation is O(1) average.
- Space: O(n) — at most n entries in the map before a match is found.

### Edge Cases
- Negative numbers: complement arithmetic is sign-agnostic. `target=-3`, `x=2` → complement=`-5`; works correctly.
- Duplicate values (`[3,3]`, target=6): at i=0, insert `3→0`. At i=1, complement=3, found at index 0 → `[0, 1]`. Correct — the map holds only the *first* occurrence, and querying before inserting prevents self-pairing.
- Zero elements (`[0, 4, 0]`, target=0): at i=0, insert `0→0`. At i=2, complement=0 → found at index 0 → `[0, 2]`. Correct.
- Large array: one linear pass regardless of size; no pathological worst case.

### Follow-up Questions
- "What if multiple pairs exist?" — Remove the early return and collect all pairs into a result list. Check `i > seen.get(nums[i])` to avoid double-counting the same pair.
- "What if the array is sorted?" — Two pointers: `left=0`, `right=n-1`; advance `left` when sum < target, retreat `right` when sum > target. O(n) time, O(1) space — no HashMap needed.
- "Return values instead of indices?" — Replace HashMap with HashSet (existence only). Query `set.has(complement)` before `set.add(nums[i])`.

## Problem 2 — Group Anagrams

### Problem
Given an array of strings `strs`, group the anagrams together and return a list of groups. The answer may be in any order.

```
Input:  strs = ["eat","tea","tan","ate","nat","bat"]
Output: [["bat"], ["nat","tan"], ["ate","eat","tea"]]

Input:  strs = [""]
Output: [[""]]

Input:  strs = ["a"]
Output: [["a"]]
```

### Pattern Recognition
Fingerprint hashing — compute a canonical key for each string and group strings by key in a HashMap of lists. The fingerprint (sorted characters or count vector) is identical for all anagrams and distinct across non-anagram groups.

### Key Insight
All anagrams share the same sorted character sequence. Using that sorted sequence as a HashMap key automatically routes all anagrams to the same bucket in one pass — no pairwise comparison needed. The HashMap is literally implementing the partition of strings by their character multiset equivalence class.

### Approach
For each string `s`: compute `key = [...s].sort().join('')`. If `key` is new, initialize `groups.set(key, [])`. Push `s` into `groups.get(key)`. After all strings, return `[...groups.values()]`.

### Solution

```js
// Approach 1: Sorted-string fingerprint — O(N · L log L)
function groupAnagrams(strs) {
  const groups = new Map(); // fingerprint → list of anagram strings

  for (const s of strs) {
    const key = [...s].sort().join(''); // same for all permutations of a multiset
    if (!groups.has(key)) groups.set(key, []);
    groups.get(key).push(s);
  }

  return [...groups.values()];
}

// Approach 2: Count-vector fingerprint — O(N · (L + 26)) — avoids the sort
function groupAnagramsOptimized(strs) {
  const groups = new Map();

  for (const s of strs) {
    const count = new Array(26).fill(0);
    for (const ch of s) count[ch.charCodeAt(0) - 97]++;

    // '#' delimiter prevents collisions: "1#10" ≠ "11#0"
    const key = count.join('#');

    if (!groups.has(key)) groups.set(key, []);
    groups.get(key).push(s);
  }

  return [...groups.values()];
}
```

### Dry Run

```
strs = ["eat","tea","tan","ate","nat","bat"]
groups = {} (empty Map)

"eat"  → key = sort(['e','a','t']) = "aet"  → groups = {"aet": ["eat"]}
"tea"  → key = sort(['t','e','a']) = "aet"  → groups = {"aet": ["eat","tea"]}
"tan"  → key = sort(['t','a','n']) = "ant"  → groups = {"aet": [...], "ant": ["tan"]}
"ate"  → key = sort(['a','t','e']) = "aet"  → groups = {"aet": ["eat","tea","ate"], ...}
"nat"  → key = sort(['n','a','t']) = "ant"  → groups = {..., "ant": ["tan","nat"]}
"bat"  → key = sort(['b','a','t']) = "abt"  → groups = {..., "abt": ["bat"]}

Result: [["eat","tea","ate"], ["tan","nat"], ["bat"]] ✓
```

### Complexity
- **Sorted-string**: Time O(N × L log L), Space O(N × L). L log L per string for the sort.
- **Count-vector**: Time O(N × (L + σ)), Space O(N × L). O(L) per string to build count array + O(σ) to serialize. Strictly better when L >> log L (most practical cases with σ = 26).

### Edge Cases
- Empty string `""`: `sort()` of empty array = `""`. All empty strings share key `""` → grouped together.
- Single-character strings: each distinct character is its own key; no two distinct single chars are anagrams.
- All strings are anagrams of each other: one group containing all N strings.
- All strings are unique with no anagram pairs: N groups of size 1 each.
- Strings of different lengths: different-length strings cannot be anagrams; the fingerprint naturally differs (different lengths produce different sorted strings and different count vectors).

### Follow-up Questions
- "Unicode characters?" — Sorted-string fingerprint handles any Unicode via standard comparison sort. The count-vector approach requires a bounded σ — fall back to a `Map<char, int>` serialization for Unicode.
- "Case-insensitive grouping?" — Lowercase each string before fingerprinting: `s.toLowerCase()` before `sort()`.
- "Return groups sorted by size, largest first?" — Sort `[...groups.values()]` by `.length` descending after collecting.

## Problem 3 — Three Sum

### Problem
Given an integer array `nums`, return all unique triplets `[nums[i], nums[j], nums[k]]` such that `i`, `j`, `k` are distinct indices and `nums[i] + nums[j] + nums[k] == 0`.

```
Input:  nums = [-1, 0, 1, 2, -1, -4]
Output: [[-1, -1, 2], [-1, 0, 1]]

Input:  nums = [0, 1, 1]
Output: []

Input:  nums = [0, 0, 0]
Output: [[0, 0, 0]]
```

### Pattern Recognition
Sort + outer loop + two-pointer Two Sum — sort the array, fix the first element with an outer loop, then use two inward-moving pointers to find pairs summing to the negative of the first element. Duplicate skipping at both levels ensures unique triplets without a results HashSet.

### Key Insight
Sorting enables three things simultaneously: (1) two-pointer shrinking for the inner Two Sum step in O(n); (2) duplicate skipping for the outer element (`nums[i] == nums[i-1]`) in O(1); (3) duplicate skipping for the found inner pair in O(1) — by advancing past repeated values after each triplet is recorded. This is why the sort + two-pointer approach is cleaner than a pure HashMap approach: deduplication is essentially free once the array is sorted.

### Approach
Sort `nums`. For each `i` from 0 to n-3: skip if `i > 0 && nums[i] == nums[i-1]`. Break early if `nums[i] > 0` (no zero-sum triplet possible with a positive first element). Set `left = i+1`, `right = n-1`. While `left < right`: if `sum == 0`, record and skip duplicates for both pointers; if `sum < 0`, advance `left`; if `sum > 0`, retreat `right`.

### Solution

```js
function threeSum(nums) {
  nums.sort((a, b) => a - b); // ascending sort enables pointers + dedup
  const result = [];

  for (let i = 0; i < nums.length - 2; i++) {
    // Skip duplicate first elements
    if (i > 0 && nums[i] === nums[i - 1]) continue;

    // All remaining elements are positive → no zero-sum triplet possible
    if (nums[i] > 0) break;

    let left = i + 1, right = nums.length - 1;

    while (left < right) {
      const sum = nums[i] + nums[left] + nums[right];

      if (sum === 0) {
        result.push([nums[i], nums[left], nums[right]]);

        // Skip duplicates for the second element
        while (left < right && nums[left] === nums[left + 1]) left++;
        // Skip duplicates for the third element
        while (left < right && nums[right] === nums[right - 1]) right--;

        left++;
        right--;
      } else if (sum < 0) {
        left++;  // too small → move left pointer right to increase sum
      } else {
        right--; // too large → move right pointer left to decrease sum
      }
    }
  }

  return result;
}
```

### Dry Run

```

After sort: [-4, -1, -1, 0, 1, 2]

i=0, nums[0]=-4. left=1, right=5.
  sum=-4+(-1)+2=-3 < 0 → left++
  sum=-4+(-1)+2=-3 < 0 → left++ (left=2, pointing at second -1)
  sum=-4+(-1)+2=-3 < 0 → left++ (left=3)
  sum=-4+0+2=-2 < 0 → left++
  sum=-4+1+2=-1 < 0 → left++  (left=5=right) → stop. No triplets.

i=1, nums[1]=-1. i>0 but nums[1]=-1 ≠ nums[0]=-4 → no skip.
  left=2, right=5.
  sum=-1+(-1)+2=0 → push [-1,-1,2].

  sum=-1+0+1=0 → push [-1,0,1].
```

### Complexity
- Time: O(n²) — O(n log n) sort + O(n) outer loop × O(n) two-pointer inner scan.
- Space: O(1) extra (excluding output and sort's in-place stack space).

### Edge Cases
- All zeros `[0,0,0]`: sorted = `[0,0,0]`. i=0: sum=0, push `[0,0,0]`. Duplicate skipping finds no adjacent copies; left/right converge → result `[[0,0,0]]`. Correct.
- No valid triplets (all positive, all negative, or no combination reaches 0): outer break or no sum=0 hit → empty result.
- Length < 3: outer loop `i < n-2` runs 0 times → empty result.
- `[-2,0,0,0,0,2]`: outer i=0 produces one `[-2,0,2]`; the inner duplicate skipping advances past all extra zeros correctly.

### Follow-up Questions
- "Target other than 0?" — Replace `sum === 0` with `sum === target`; all other logic identical.
- "Use a HashMap instead of two pointers?" — For each outer `i`, build a set from `nums[i+1..n-1]`; for each `j > i`, check if `-(nums[i]+nums[j])` is in the set. Correct but requires a results Set for deduplication — more complex than sort+pointers and no asymptotic benefit.
- "How many unique triplets exist without returning them?" — Same algorithm; increment a counter instead of pushing; slightly faster in practice (no allocation).

## Problem 4 — Subarray Sum Equals K

### Problem
Given an integer array `nums` and an integer `k`, return the total number of contiguous subarrays whose elements sum to `k`.

```
Input:  nums = [1, 1, 1], k = 2
Output: 2     // [1,1] at [0..1] and [1,1] at [1..2]

Input:  nums = [1, 2, 3], k = 3
Output: 2     // [3] at [2..2] and [1,2] at [0..1]

Input:  nums = [-1, -1, 1], k = 0
Output: 1     // [-1,-1,1] sums to -1 (no); [-1,1] sums to 0 ✓ at [1..2]
              // Actually: prefix sums: 0,-1,-2,-1. -1 appears at idx 0 and idx 3 → subarray [1..2] ✓
```

### Pattern Recognition
Prefix sum + HashMap (complement lookup on accumulated sums) — the "query before update" single-pass structure of Two Sum applied to prefix sums instead of raw elements. The HashMap stores `{prefixSum → count}` rather than `{value → index}`.

### Key Insight
A subarray `[j..i]` sums to k iff `prefix[i] - prefix[j-1] = k`, i.e., `prefix[j-1] = prefix[i] - k`. At each position i, querying how many earlier positions had prefix sum exactly `prefix[i] - k` gives the count of valid subarrays ending at i. The `{0 → 1}` initialization represents the empty prefix, handling subarrays that start at index 0.

### Approach
Initialize `prefixCount = {0 → 1}`, `sum = 0`, `count = 0`. For each element `x`: `sum += x`. Query: `count += prefixCount.get(sum - k) ?? 0`. Update: `prefixCount.set(sum, (prefixCount.get(sum) ?? 0) + 1)`. Return `count`.

### Solution

```js
function subarraySum(nums, k) {
  const prefixCount = new Map();
  prefixCount.set(0, 1); // empty prefix: sum=0, seen once

  let sum = 0;
  let count = 0;

  for (const x of nums) {
    sum += x; // running prefix sum up to current index

    // How many earlier prefixes had sum = (current_sum - k)?
    // Each is a valid left boundary for a subarray ending here with sum k.
    count += prefixCount.get(sum - k) ?? 0;

    // Record current prefix sum AFTER querying (same "before insert" discipline as Two Sum)
    prefixCount.set(sum, (prefixCount.get(sum) ?? 0) + 1);
  }

  return count;
}
```

### Dry Run

```
nums = [1, 1, 1], k = 2
prefixCount = {0→1}, sum=0, count=0

x=1: sum=1. Query: prefixCount.get(1-2=-1) = undefined → 0. count=0.
     Update: prefixCount = {0→1, 1→1}.

x=1: sum=2. Query: prefixCount.get(2-2=0) = 1. count=1.
     Update: prefixCount = {0→1, 1→1, 2→1}.

x=1: sum=3. Query: prefixCount.get(3-2=1) = 1. count=2.
     Update: prefixCount = {0→1, 1→1, 2→1, 3→1}.

Answer: 2 ✓
Subarrays: [1,1] at [0,1] (prefix 0→2, length 2) and [1,1] at [1,2] (prefix 1→3, length 2).
```

### Complexity
- Time: O(n) — one pass; O(1) average per HashMap operation.
- Space: O(n) — at most n+1 distinct prefix sums in the map.

### Edge Cases
- Negative numbers: prefix sums can decrease and revisit earlier values; the count map handles this correctly since HashMap keys can be any integer and the count correctly accumulates.
- `k = 0`: counts subarrays summing to 0. The `{0→1}` initialization ensures subarrays from index 0 that sum to 0 are caught. Arrays of all zeros produce many such subarrays (e.g., `[0,0,0]` with k=0 → 6 subarrays).
- Entire array sums to k: at the last element, `sum-k=0` hits the `{0→1}` initialization entry — counted correctly.
- Duplicate prefix sums (e.g., `[1,-1,1,-1]`): the count map stores counts, not indices — when `sum-k` appears multiple times, all occurrences contribute to `count` in one lookup. Correct.

### Follow-up Questions
- "Longest subarray summing to k?" — Replace count map with first-index map `{prefixSum → earliest index}`. On each match, record `currentIndex - storedIndex` and take the max. Store only first occurrence (`if (!firstSeen.has(sum))`).
- "Subarray sum divisible by k?" — Replace key with `((sum % k) + k) % k`. Two equal remainders define a subarray whose sum is divisible by k. Use count map with `{0→1}` initialization.
- "Return one such subarray (not just count)?" — Store `{prefixSum → index}` mapping for a representative approach; reconstruct from stored left boundary index.

## Problem 5 — Longest Consecutive Sequence

### Problem
Given an unsorted integer array `nums`, return the length of the longest sequence of consecutive integers present in the array. Must run in O(n) time.

```
Input:  nums = [100, 4, 200, 1, 3, 2]
Output: 4     // sequence: [1, 2, 3, 4]

Input:  nums = [0, 3, 7, 2, 5, 8, 4, 6, 0, 1]
Output: 9     // sequence: [0, 1, 2, 3, 4, 5, 6, 7, 8]
```

### Pattern Recognition
HashSet membership — load all elements into a set for O(1) existence queries; only start counting a sequence from its leftmost element (where `x-1` is absent), so each element is processed as part of exactly one chain.

### Key Insight
Starting a count chain from an element `x` where `x-1` is also in the set wastes work — that chain will also be started (more completely) when we later reach `x-1`'s leftmost endpoint. By filtering to only true left endpoints (`x-1 not in set`), each element is visited as the start of at most one chain, and extended over at most once across all chains. Total inner loop iterations across all outer loop calls = n.

### Approach
Build `numSet` from `nums`. For each `x` in `numSet`: if `numSet.has(x-1)`, skip. Otherwise, count consecutive elements: `length=1; while numSet.has(x+length): length++`. Update `best = max(best, length)`.

### Solution

```js
function longestConsecutive(nums) {
  const numSet = new Set(nums); // O(n) — O(1) membership queries
  let best = 0;

  for (const x of numSet) {
    // Only begin a chain at the sequence's leftmost element
    if (!numSet.has(x - 1)) {
      let length = 1;

      // Extend the chain rightward as long as consecutive elements exist
      while (numSet.has(x + length)) {
        length++;
      }

      best = Math.max(best, length);
    }
  }

  return best;
}
// Amortized analysis: each element in numSet triggers the while loop at most once
// (only when it is the direct successor of a chain start).
// Total while iterations across all for-loop iterations ≤ numSet.size = O(n). ✓
```

### Dry Run

```
nums = [100, 4, 200, 1, 3, 2]

x=100: has(99)? No → start. length=1. has(101)? No. best=1.
x=4:   has(3)?  Yes → NOT a start. Skip.
x=200: has(199)? No → start. length=1. has(201)? No. best=1.
x=1:   has(0)?  No → start.
       has(2)? Yes → length=2.
       has(3)? Yes → length=3.
       has(4)? Yes → length=4.
       has(5)? No  → stop. best=4.
x=3:   has(2)? Yes → NOT a start. Skip.
x=2:   has(1)? Yes → NOT a start. Skip.

Answer: 4 ✓  (sequence: 1, 2, 3, 4)
```

### Complexity
- Time: O(n) — Set build is O(n). Each element is a start at most once (outer loop) and extended past at most once (inner while). Total iterations = 2n = O(n).
- Space: O(n) — the Set holds all unique elements.

### Edge Cases
- Empty array: loop doesn't execute → returns 0.
- All identical elements: `new Set([5,5,5]) = {5}`; one element, is a start, length=1. Correct.
- Duplicates in input: `Set` deduplicates automatically. `[1,1,2]` → `{1,2}`, longest sequence = 2.
- Negative numbers: `has(x-1)` works identically for negative values. `x=-3` checks `has(-4)`.
- Single-element array: that element has no predecessor → is a start → length=1.

### Follow-up Questions
- "Return the actual sequence, not just the length?" — When updating `best`, also store `startX = x`. After the loop, generate `[startX, startX+1, ..., startX+best-1]`.
- "What if duplicates are allowed and count toward length?" — Standard Set deduplication is still correct for the purpose of finding the *sequence*: `[1,1,2]` still has consecutive sequence `{1,2}`. If the problem wants total element count including duplicates, use a frequency map instead and extend the answer by the minimum frequency along the chain.
- "Sorted input — can we do O(n) with O(1) space?" — Yes: scan for the start of each run (where `nums[i] != nums[i-1]+1` after deduplication). O(n) time, O(1) space. Not applicable to unsorted input.

## Problem 6 — Four Sum II

### Problem
Given four integer arrays `nums1`, `nums2`, `nums3`, `nums4`, each of length `n`, return the number of tuples `(i, j, k, l)` such that `nums1[i] + nums2[j] + nums3[k] + nums4[l] == 0`.

```
Input:  nums1=[1,2], nums2=[-2,-1], nums3=[-1,2], nums4=[0,2]
Output: 2

Input:  nums1=[0], nums2=[0], nums3=[0], nums4=[0]
Output: 1
```

### Pattern Recognition
Meet-in-the-middle via HashMap — enumerate all n² pairwise sums from the first two arrays into a count map; for each of the n² pairs from arrays 3 & 4, look up the required complement in the map. Two O(n²) passes + O(1) per lookup = O(n²) total.

### Key Insight
Four nested loops is O(n⁴). Splitting into two pairs and connecting via a HashMap lookup reduces two of the four loops to a single O(1) query per pair, dropping the total to O(n²). The HashMap acts as a precomputed "catalog" of all achievable first-half sums with their multiplicities — each second-half pair simply queries against this catalog.

### Approach
Pass 1: for every `(a, b)` from `nums1 × nums2`, compute sum `s = a+b`; `abSums.set(s, count+1)`. Pass 2: for every `(c, d)` from `nums3 × nums4`, query `abSums.get(-(c+d)) ?? 0`; add to result. Return result.

### Solution

```js
function fourSumCount(nums1, nums2, nums3, nums4) {
  const abSums = new Map(); // (nums1[i]+nums2[j]) → count of pairs producing this sum

  // Pass 1: catalog all pairwise sums from the first two arrays
  for (const a of nums1) {
    for (const b of nums2) {
      const s = a + b;
      abSums.set(s, (abSums.get(s) ?? 0) + 1);
    }
  }

  let count = 0;

  // Pass 2: for each pair from arrays 3 & 4, find matching complement in catalog
  for (const c of nums3) {
    for (const d of nums4) {
      const need = -(c + d); // need a+b = -(c+d) for the total to equal 0
      count += abSums.get(need) ?? 0;
    }
  }

  return count;
}
```

### Dry Run

```
nums1=[1,2], nums2=[-2,-1], nums3=[-1,2], nums4=[0,2]

Pass 1 — build abSums from nums1 × nums2:
(1,-2)=−1 → abSums={-1:1}
(1,-1)=0  → abSums={-1:1, 0:1}
(2,-2)=0  → abSums={-1:1, 0:2}
(2,-1)=1  → abSums={-1:1, 0:2, 1:1}

Pass 2 — query for -(c+d) from nums3 × nums4:
(c=-1, d=0): need=−(−1+0)=1.   abSums.get(1)=1.  count=1.
(c=-1, d=2): need=−(−1+2)=−1.  abSums.get(-1)=1. count=2.
(c=2,  d=0): need=−(2+0)=−2.   abSums.get(-2)=0. count=2.
(c=2,  d=2): need=−(2+2)=−4.   abSums.get(-4)=0. count=2.

Answer: 2 ✓
```

### Complexity
- Time: O(n²) — two separate O(n²) loops; O(1) HashMap operations per iteration.
- Space: O(n²) — the `abSums` map can hold up to n² distinct pairwise sums in the worst case.

### Edge Cases
- All zeros (`[0],[0],[0],[0]`): `abSums = {0→1}`. Pass 2: need=0, `abSums.get(0)=1`, count=1. Correct.
- No valid quadruples: all complement lookups return `undefined ?? 0`; count stays 0.
- High multiplicities: if all n² pairs from arrays 1 & 2 produce the same sum, that entry in `abSums` holds value n². Each lookup in pass 2 adds n² to count — correctly counting n² × n² = n⁴ quadruples (all combinations).

### Follow-up Questions
- "Two arrays summing to 0?" — Degenerate case: `abSums` built from `nums1`; pass 2 queries `-nums2[j]`. This is exactly Two Sum (count variant).
- "Three arrays summing to 0?" — Build `abSums` from `nums1`; double loop over `nums2 × nums3`; query `-(nums2[j]+nums3[k])`. O(n²) time, O(n) space.
- "Return actual unique quadruples instead of count?" — Requires deduplication: sort all four arrays; use HashMap approach with a Set of sorted 4-tuples, or use the 4-pointer approach (sort + two outer loops + two pointers). The count problem is strictly easier than the distinct-tuple problem.

## Problem 7 — Contains Duplicate II

### Problem
Given an integer array `nums` and an integer `k`, return `true` if there exist two distinct indices `i` and `j` such that `nums[i] == nums[j]` and `|i - j| <= k`.

```
Input:  nums = [1, 2, 3, 1], k = 3   → true   // indices 0 and 3, distance 3 ≤ 3
Input:  nums = [1, 0, 1, 1], k = 1   → true   // indices 2 and 3, distance 1 ≤ 1
Input:  nums = [1, 2, 3, 1, 2, 3], k = 2 → false  // nearest dupes are distance 3
```

### Pattern Recognition
Sliding-window HashSet — maintain a Set of the last `k` elements. Membership in the set guarantees the matching element is within distance k. Evict `nums[i-k]` when the window exceeds size k.

### Key Insight
The window holds exactly the elements at indices `[i-k, i-1]` when we check `nums[i]`. Any hit means a copy of `nums[i]` exists in this range — i.e., within k positions. The eviction of `nums[i-k]` is exact: after adding `nums[i]`, the window would contain `k+1` elements (`i-k` through `i`), and `nums[i-k]` is at distance `k` from `nums[i]` — still within range. So we evict when size *exceeds* k (not when equals k), and delete `nums[i-k]`, which just fell out of range.

### Approach
For each index `i`: if `window.has(nums[i])` → return true. `window.add(nums[i])`. If `window.size > k`: `window.delete(nums[i-k])`.

### Solution

```js
function containsNearbyDuplicate(nums, k) {
  const window = new Set(); // elements at indices [i-k .. i-1]

  for (let i = 0; i < nums.length; i++) {
    // Found a matching element within the last k positions
    if (window.has(nums[i])) return true;

    window.add(nums[i]);

    // Evict the element that just fell outside the k-range
    if (window.size > k) {
      window.delete(nums[i - k]);
    }
  }

  return false;
}
```

### Complexity
- Time: O(n) — one pass; each Set operation is O(1) average.
- Space: O(min(n, k)) — the window holds at most `k` elements at any time.

### Edge Cases
- `k = 0`: the window immediately overflows after adding any element (`size > 0`), evicting the element just added. The window stays empty; no membership hit is ever possible → returns false. Correct — distance 0 means same index, and the problem requires distinct indices.
- All identical elements, `k ≥ 1`: at `i=1`, `window.has(nums[1]) = window.has(nums[0])` → true. Returns true immediately.
- `k ≥ n`: window never overflows; all elements remain in the window. Reduces to standard "any duplicate" check.
- Element exactly at distance `k`: at `i = j + k`, `nums[j]` is still in the window when checking `nums[i]` (eviction at size > k, not ≥ k). Returns true. Correct.

### Follow-up Questions
- "Return the actual indices of the duplicate pair?" — Replace HashSet with HashMap `{value → last seen index}`. On match: return `[map.get(nums[i]), i]`. On miss: `map.set(nums[i], i)` (overwriting ensures we have the most recent prior index, which keeps the window concept intact).
- "Contains Duplicate III — values differ by at most t, within k indices?" — The window still applies, but the membership check changes from equality to range: "is there any element in the window within value range `[nums[i]-t, nums[i]+t]`?" A balanced BST (TreeSet in Java) gives O(log k) per lookup. In JavaScript, the bucket-sort approach with bucket size `t+1` achieves O(1) per step.

```
What's the structural shape of this hashing problem?
│
├── FIND A PAIR with a given sum?
│   ├── Return indices of one pair → Two Sum
│   │   Single-pass map {value → index}. Query complement BEFORE insert.
│   │
│   ├── Count all pairs → count-pairs variant
│   │   Left-to-right: count += freq.get(k-x) ?? 0; then freq[x]++.
│   │
│   ├── Three-element triplet → Sort + outer loop + two pointers
│   │   Skip duplicate outer elements; skip duplicate inner pair after match.
│   │
│   └── Quadruples from four arrays → Four Sum II
│       Meet-in-the-middle: build abSums map; query -(c+d) for each C×D pair.
│
├── GROUP elements by an equivalence relation?
│   ├── Group by character multiset (anagrams) → fingerprint as key
│   │   Sorted-string: O(L log L). Count-vector: O(L + σ). HashMap of lists.
│   │
│   ├── Group by structural repetition pattern (isomorphic) → two bijection maps
│   │   sToT: each s-char always maps to same t-char.
│   │   tToS: no two s-chars map to the same t-char. Both maps required.
│   │
│   └── Group by word-level pattern → same as isomorphic, at word granularity
│
├── SUBARRAY with a sum condition?
│   ├── Sum equals k (count subarrays) → prefix sum + count map
│   │   Init {0→1}. Query map.get(sum-k) BEFORE updating map[sum]++.
│   │
│   ├── Sum equals k (longest subarray) → prefix sum + first-index map
│   │   Init {0→-1}. Store only FIRST occurrence. Length = i - storedIndex.
│   │
│   └── Sum divisible by k → modular prefix sum
│       Key: ((sum % k) + k) % k. Two equal remainders → valid subarray.
│
├── EXISTENCE / MEMBERSHIP queries?
│   ├── "Have I seen this element?" or "Does x exist in this set?" → HashSet
│   │
│   ├── "Duplicate within k positions?" → sliding-window HashSet of size k
│   │   Evict nums[i-k] when window.size > k (AFTER adding nums[i]).
│   │
│   └── "Longest run of consecutive integers?" → HashSet + left-endpoint filter
│       Only start counting from x where has(x-1) is false.
│
└── SPACE OPTIMIZATION fallbacks (when O(1) space is required)?
    ├── Two Sum on sorted array → two pointers, O(1) space.
    ├── Any duplicate in array with values [1..n] → negate-at-index trick.
    ├── Consecutive sequence (sorted allowed) → sort + linear scan, O(1) extra.
    └── Majority element (>n/2) → Boyer-Moore voting, O(1) space.
```

## Common Bugs Checklist

Before submitting any solution from this category, verify:

1. **Two Sum: querying the map AFTER insert instead of before?** — `map.set(x,i)` then `map.has(target-x)` allows self-pairing when `x == target-x`. Always query first, insert second. The invariant is "map contains only indices strictly before the current one."

2. **Subarray Sum: missing `{0 → 1}` initialization?** — Without it, subarrays that start at index 0 are never counted (their "prefix before them" is the empty prefix with sum 0, which would not be in an empty map). Always initialize `prefixCount.set(0, 1)` before the loop.

3. **Modular prefix sum: not normalizing negative remainders?** — JavaScript's `%` returns negative values for negative operands: `-7 % 3 === -1`, not `2`. Always normalize with `((sum % k) + k) % k` to map remainders into `[0, k-1]`.

4. **Group Anagrams: count-vector fingerprint missing delimiter?** — `[1,10]` and `[11,0]` both serialize to `"110"` without delimiters — a silent collision placing non-anagrams in the same group. Use `count.join('#')` to produce `"1#10"` vs `"11#0"`.

5. **Three Sum: not skipping duplicates after a found triplet?** — After recording `[nums[i], nums[left], nums[right]]`, you must advance `left` past all copies of `nums[left]` and retreat `right` past all copies of `nums[right]` before the `left++; right--` step — otherwise the same triplet is pushed multiple times.

6. **Three Sum: not skipping duplicate outer elements?** — Without `if (i > 0 && nums[i] === nums[i-1]) continue`, the same first element is processed multiple times, producing duplicate triplets in the output (e.g., `[-1,-1,0,1]` processes both `-1` entries and emits `[-1,0,1]` twice).

7. **Consecutive Sequence: iterating over `nums` instead of `numSet`?** — Duplicates in `nums` (e.g., `[1,1,2]`) cause `x=1` to be processed twice: a chain of length 2 is reported twice. Always iterate over the Set, not the original array.

8. **Contains Duplicate II: eviction at `size >= k` instead of `size > k`?** — With `>= k`, the window contains at most `k-1` elements, excluding `nums[i-k+1]` which is at distance `k-1` — a valid match would be missed. The window must hold indices `[i-k..i-1]` (k elements) when checking `nums[i]`; evict only when size exceeds k.

9. **Four Sum II: interleaving the two passes?** — The `abSums` catalog must be fully built from arrays 1 & 2 before any pair from arrays 3 & 4 is processed. Building and querying the same map in interleaved fashion corrupts the counts and produces wrong results.

10. **Isomorphic strings / Word Pattern: using only one bijection map?** — A single `s→t` map catches "one `s`-character maps to two different `t`-characters" but misses "two different `s`-characters map to the same `t`-character." Both `sToT` and `tToS` maps are required. The missing reverse map produces false positives for inputs like `s="ab"`, `t="aa"`.

**Final Tip:** At the 5 YOE level, the decisive signal for any hashing problem is naming the *invariant the map maintains*, not just its type. For Two Sum: *"the map holds elements at all indices strictly before the current one — so any complement hit is a genuine distinct-index pair."* For Subarray Sum: *"the map counts how many times each prefix sum has occurred — so `map.get(currentSum - k)` is exactly the number of valid left boundaries for subarrays ending here."* For Group Anagrams: *"the fingerprint is identical for all anagrams and distinct across non-anagram groups — it is a perfect surrogate key for the character-multiset equivalence relation."* For Longest Consecutive: *"we only start counting from true left endpoints — so each element participates in exactly one chain and total work is O(n) despite the nested loop structure."* Stating the invariant in one sentence before writing any code is the mark of a senior engineer who understands *why* the data structure is the right tool, not just *that* it produces the correct output.
