## Topic A: The Frequency Map Foundation

### Section A1: Fundamentals

**Q1. What is the frequency counting pattern, and what class of problems does it solve?**
A: The frequency counting pattern uses a HashMap (or direct-address array) to tally how many times each distinct element appears in a collection, transforming an O(n²) "scan-and-compare" approach into an O(n) single-pass build followed by O(1) per-element queries. It solves any problem whose answer depends on *how often* elements appear rather than *where* they appear: duplicate detection, majority elements, anagram checking, top-k frequent elements, character balance problems, and subarray/substring constraint problems where the binding constraint is an element's count. The pattern is one of the most frequently appearing in interviews precisely because it sits at the intersection of hashing fundamentals and a broad problem family.

```
Brute force "does X appear twice?": for each element, scan the rest → O(n²)
Frequency map "does X appear twice?": build freq map in O(n), query freq[X] in O(1) → O(n)
```

**Q2. How do you build a frequency map, and what are the three common implementation choices?**
A: Building a frequency map means iterating the input once and incrementing a counter for each element. The three implementation options differ in key-space constraints and performance:

**Option 1 — Direct-address array** (when keys are bounded integers or characters):
```js
const freq = new Array(26).fill(0);      // for lowercase letters
for (const ch of s) freq[ch.charCodeAt(0) - 97]++;
```
O(1) per operation, zero hashing overhead, maximum cache locality. Use when the key space is small and enumerable (26 letters, 128 ASCII, 256 bytes).

**Option 2 — HashMap / `Map`** (general keys):
```js
const freq = new Map();
for (const x of arr) freq.set(x, (freq.get(x) ?? 0) + 1);
```
O(1) average per operation, works for any hashable key type (strings, integers, objects with proper `hashCode`). The `?? 0` handles the first occurrence of a key without a separate existence check.

**Option 3 — Object literal** (JS-specific, string keys only):
```js
const freq = {};
for (const x of arr) freq[x] = (freq[x] ?? 0) + 1;
```
Slightly less safe than `Map` (prototype chain pollution possible for keys like `"constructor"`, `"__proto__"`), but common in competitive programming contexts. Prefer `Map` in production code.

**Q3. What is the "count then query" structure, and why does the pass order matter?**
A: Most frequency problems follow a strict two-phase structure: (1) **Count phase** — traverse the entire input building the frequency map; (2) **Query phase** — answer questions using O(1) map lookups. The phases must be separate in problems where the answer depends on the *global* distribution of elements (e.g., "does any element appear more than n/2 times?" requires counting all elements before any query makes sense). Conflating the phases — querying the map while still building it — produces incorrect answers for questions about global properties. The exception is the *complement lookup* pattern (two-sum family), where the query logically refers to "elements seen so far" and the interleaved build+query is intentional.

```
WRONG (conflated phases for majority element check):
for x in arr:
    freq[x]++
    if freq[x] > n/2: return x   // might return x before all elements counted

CORRECT (separate phases):
for x in arr: freq[x]++          // count phase — full traversal
for x, c in freq: if c > n/2: return x  // query phase
```

**Q4. What is the canonical "frequency fingerprint" technique, and what does it enable?**
A: A frequency fingerprint is a normalized representation of an element's character/digit distribution — typically a sorted tuple or a fixed-length count vector — that is identical for all inputs that are permutations of each other. Two strings are anagrams if and only if their frequency fingerprints match. Using the fingerprint as a HashMap key groups all permutations of the same multiset together in one O(n) pass, enabling anagram grouping, permutation detection, and isomorphism checks. The fingerprint effectively converts a *structural equivalence* question into a *key equality* question, which HashMap handles in O(1).

```
"eat"  → sorted: "aet"  → fingerprint key "aet"
"tea"  → sorted: "aet"  → same fingerprint → same anagram group
"tan"  → sorted: "ant"  → different fingerprint → different group

Alternative fingerprint (count vector, avoids O(k log k) sort):
"eat" → [1,0,0,0,1,0,...,1,0,0] (counts of a,b,c,...,z) → key "#1#0#0#...#1#..."
```

**Q5. What is the difference between a frequency map and a frequency array, and when should you choose each?**
A: A frequency map (HashMap) handles arbitrary key types with O(1) average operations and O(k) space where k is the number of distinct elements. A frequency array handles only enumerable, bounded integer keys (chars, small integers) with O(1) worst-case operations (no hashing, just array indexing) and O(σ) space where σ is the key-space size. The frequency array is always preferable when applicable — it's faster (no hash computation, no collision handling, better cache behavior), simpler (no null-check boilerplate), and uses deterministic O(σ) space regardless of input. The HashMap is necessary when the key space is large, unbounded, or non-integer (e.g., counting words in a document, counting arbitrary strings).

```
Key space: lowercase letters (σ=26) → frequency array, always
Key space: arbitrary strings        → HashMap, always
Key space: integers 0..10^9         → HashMap (array would need 10^9 slots)
Key space: integers 0..1000         → frequency array viable (1001 slots is small)
```

### Section A2: Advanced Patterns

**Q6. What is the "excess frequency" pattern, and which problems does it apply to?**
A: The excess frequency pattern applies when the problem asks whether one collection's element distribution is a *subset* of another's — e.g., "can string t be constructed from the characters of string s?" or "is t a subset-anagram of s?" Rather than building two separate frequency maps and comparing, build one map for the "supply" side and decrement it for each element from the "demand" side. If any count goes negative, the demand has exceeded the supply for that element — immediately return false. This one-map approach is cleaner and avoids a separate comparison loop.

```js
// "Is t constructible from s's characters?" pattern
function canConstruct(s, t) {
  const supply = new Map();
  for (const ch of s) supply.set(ch, (supply.get(ch) ?? 0) + 1);

  for (const ch of t) {
    if (!supply.get(ch)) return false; // 0 or undefined → supply exhausted
    supply.set(ch, supply.get(ch) - 1);
  }
  return true;
}
```

**Q7. What is the "delta frequency" pattern for sliding window problems?**
A: When a problem asks for all windows of fixed size `k` where a frequency condition holds (e.g., "find all anagram start indices in a string"), the naive approach rebuilds the frequency map from scratch for each window — O(k) per step, O(n·k) overall. The delta frequency pattern maintains the map incrementally: at each step, add the incoming character (right side of window) and remove the outgoing character (left side of window) — O(1) per step, O(n) overall. The window's "state" is tracked by how many characters currently satisfy their target count (`formed` counter); when `formed == required`, the window is valid.

```js
// Sliding window delta update:
// Step right: freq[incoming]++; if freq[incoming] == target[incoming]: formed++
// Step left:  if freq[outgoing] == target[outgoing]: formed--; freq[outgoing]--
```

**Q8. What is the "frequency of frequencies" meta-pattern?**
A: Some problems require reasoning about the distribution of counts themselves, not just the counts. A "frequency of frequencies" map tracks: for each count value `c`, how many distinct elements currently have count `c`. This enables O(1) answers to questions like "how many distinct elements appear exactly twice?" or "is there any element appearing more than k times?" — which would otherwise require scanning the entire frequency map. It's particularly useful in streaming problems (online algorithms) where the input arrives one element at a time and the query must be answered after each arrival.

```js
// Maintain both freq and freqOfFreq simultaneously:
function addElement(x, freq, freqOfFreq) {
  const oldCount = freq.get(x) ?? 0;
  if (oldCount > 0) {
    freqOfFreq.set(oldCount, freqOfFreq.get(oldCount) - 1);
    if (freqOfFreq.get(oldCount) === 0) freqOfFreq.delete(oldCount);
  }
  freq.set(x, oldCount + 1);
  freqOfFreq.set(oldCount + 1, (freqOfFreq.get(oldCount + 1) ?? 0) + 1);
}
// After each addElement: freqOfFreq.get(2) = number of elements appearing exactly twice
```

**Q9. What is bucket sort via frequency map, and how does it achieve O(n) for "top-k frequent elements"?**
A: After building a frequency map, instead of sorting entries by count (O(k log k) where k is distinct elements), create a "bucket array" of size `n+1` where `bucket[c]` holds all elements with count exactly `c`. Since no element can appear more than `n` times, `n+1` buckets suffice. Fill buckets in O(k), then scan from bucket `n` down to bucket `1`, collecting elements until `k` are gathered — O(n) total. This is a frequency-keyed bucket sort: it exploits the fact that counts are bounded integers (0 to n), making a counting sort (O(n)) possible where a comparison sort would be O(k log k).

```js
function topKFrequent(nums, k) {
  const freq = new Map();
  for (const x of nums) freq.set(x, (freq.get(x) ?? 0) + 1);

  // Bucket: index = count, value = list of elements with that count
  const bucket = Array.from({ length: nums.length + 1 }, () => []);
  for (const [val, cnt] of freq) bucket[cnt].push(val);

  const result = [];
  for (let c = bucket.length - 1; c >= 1 && result.length < k; c--) {
    result.push(...bucket[c]);
  }
  return result.slice(0, k);
}
```

## Topic B: Majority and Threshold Frequency Problems

### Section B1: Fundamentals

**Q10. What is the majority element problem, and what are the two approaches?**
A: Find the element appearing more than `⌊n/2⌋` times in an array (guaranteed to exist). Two approaches:

**HashMap approach** — O(n) time, O(n) space: build a frequency map; scan it for any entry with count > n/2.

**Boyer-Moore Voting** — O(n) time, O(1) space: maintain a `candidate` and a `count`. For each element: if `count == 0`, set `candidate = element`; if the element equals `candidate`, increment `count`; else decrement `count`. The candidate after the full pass is the majority element. The key insight: the majority element's votes cannot be fully cancelled by votes for all other elements combined (since it appears more than n/2 times), so it always survives as the final candidate.

```js
// HashMap approach:
function majorityElement(nums) {
  const freq = new Map();
  for (const x of nums) {
    freq.set(x, (freq.get(x) ?? 0) + 1);
    if (freq.get(x) > nums.length / 2) return x; // early exit on count phase
  }
}

// Boyer-Moore (O(1) space):
function majorityElementBM(nums) {
  let candidate = null, count = 0;
  for (const x of nums) {
    if (count === 0) candidate = x;
    count += (x === candidate) ? 1 : -1;
  }
  return candidate;
}
```

**Q11. How do you extend the majority element solution to find all elements appearing more than `⌊n/3⌋` times?**
A: At most two elements can appear more than n/3 times (since three such elements would account for more than n total occurrences — a contradiction). The HashMap approach: build a frequency map, collect all entries with count > n/3. The Boyer-Moore generalization: maintain *two* candidate/count pairs simultaneously, using the same cancellation logic extended to cancel three distinct values at once. After one pass, verify both candidates against the actual counts (a verification pass is required here, unlike the n/2 case, since the two candidates are not guaranteed to both satisfy the threshold — only candidates that might survive are identified, not confirmed).

```js
function majorityElementN3(nums) {
  // HashMap approach — simplest and most general:
  const freq = new Map();
  for (const x of nums) freq.set(x, (freq.get(x) ?? 0) + 1);
  return [...freq.entries()]
    .filter(([, cnt]) => cnt > Math.floor(nums.length / 3))
    .map(([val]) => val);
}
```

**Q12. What is the "element appears at least k times" family of patterns, and what is the threshold check?**
A: A broad family of problems asks: find all elements appearing at least (or exactly, at most) `k` times. The general pattern is always: build frequency map → filter by count condition. The count condition determines the query:
- **At least k**: `freq.get(x) >= k`
- **Exactly k**: `freq.get(x) === k`
- **At most k**: `freq.get(x) <= k`
- **More than k**: `freq.get(x) > k`
- **Unique (exactly 1)**: `freq.get(x) === 1`
- **Non-unique (more than 1)**: `freq.get(x) > 1`

The threshold-check is a filter on the map, not a search — always O(d) where d is the number of distinct elements. This family covers: finding duplicates (k=2), finding rare elements (k=1), finding dominant elements (k > n/constant), and many string/array cleanup problems.

### Section B2: Advanced Patterns

**Q13. What is the "minimum deletions to make all frequencies unique" problem, and how does the frequency-of-frequencies pattern solve it?**
A: Given a string, find the minimum number of character deletions so that no two characters have the same frequency. Standard approach: build a frequency map, then a frequency-of-frequencies map. Greedily process from the highest frequency downward: if a frequency `f` is occupied by more than one character, one character must be reduced to `f-1` (one deletion), then recursively resolve `f-1` if it's also occupied. Using a set to track occupied frequencies enables O(1) checks: for each character's current count, while the count is already occupied (and count > 0), decrement it (one deletion each time) until a free frequency is found.

```js
function minDeletions(s) {
  const freq = new Map();
  for (const ch of s) freq.set(ch, (freq.get(ch) ?? 0) + 1);

  const usedFreqs = new Set();
  let deletions = 0;

  for (let cnt of freq.values()) {
    while (cnt > 0 && usedFreqs.has(cnt)) {
      cnt--;        // reduce this character's frequency by 1 (one deletion)
      deletions++;
    }
    if (cnt > 0) usedFreqs.add(cnt);
  }
  return deletions;
}
```

**Q14. How does frequency counting extend to "check if a string can be rearranged into a palindrome"?**
A: A string can be rearranged into a palindrome if and only if at most one character has an odd frequency (that character occupies the center). Build a frequency map; count how many characters have odd counts. If that count is 0 or 1, a palindrome arrangement is possible. This is a direct frequency-threshold query: no sorting, no arrangement attempted — just a count of odd-frequency elements. A common optimization: use a HashSet (the "odd set") that adds a character on first occurrence and removes it on second — characters in the set at the end have odd frequencies. The set size at the end is the odd-frequency count.

```js
function canFormPalindrome(s) {
  const oddSet = new Set();
  for (const ch of s) {
    if (oddSet.has(ch)) oddSet.delete(ch); // even count → remove
    else oddSet.add(ch);                   // odd count → add
  }
  return oddSet.size <= 1;
}
```

## Topic C: Anagram and Permutation Patterns

### Section C1: Fundamentals

**Q15. What is the canonical anagram check, and what are the three ways to implement it?**
A: Two strings are anagrams if they contain the same characters with the same frequencies. Three implementations of increasing efficiency:

**Sort and compare** — O(n log n): sort both strings, compare. Simple, but O(n log n) due to the sort.

**Two frequency maps** — O(n): build `freq1` from `s`, `freq2` from `t`, compare maps. O(n) time, O(σ) space. The comparison step must check that both maps have the same keys with the same values — a full map equality check.

**One frequency map with +/− and zero-check** — O(n): increment for each char in `s`, decrement for each char in `t`. If all counts return to 0 (or the map is empty), strings are anagrams. More memory-efficient than building two maps.

```js
function isAnagram(s, t) {
  if (s.length !== t.length) return false;

  const freq = new Array(26).fill(0);
  for (let i = 0; i < s.length; i++) {
    freq[s.charCodeAt(i) - 97]++;
    freq[t.charCodeAt(i) - 97]--;
  }
  return freq.every(c => c === 0);
}
```

**Q16. What is the "find all anagram start indices" problem, and how does the delta-frequency sliding window solve it?**
A: Given a string `s` and a pattern `p`, find all start indices in `s` where a substring of length `p.length` is an anagram of `p`. The brute-force approach rebuilds the frequency map for each window — O(|s| × |p|). The sliding window approach: build the target frequency map from `p` and an initial window map from `s[0..|p|-1]`. Slide the window one character at a time — add the incoming character, remove the outgoing character. Track `formed`: the number of characters in the current window whose count matches the target. When `formed == |distinct chars in p|`, the window is a valid anagram — record the start index. Each slide is O(1); the total algorithm is O(|s| + |p|).

```js
function findAnagrams(s, p) {
  if (s.length < p.length) return [];

  const target = new Array(26).fill(0);
  const window = new Array(26).fill(0);
  for (const ch of p) target[ch.charCodeAt(0) - 97]++;

  const result = [];
  const len = p.length;

  for (let i = 0; i < s.length; i++) {
    window[s.charCodeAt(i) - 97]++;       // add incoming character

    if (i >= len) {
      window[s.charCodeAt(i - len) - 97]--; // remove outgoing character
    }

    if (i >= len - 1) {
      // Direct array comparison (O(26) = O(1) for fixed alphabet)
      if (window.every((c, idx) => c === target[idx])) {
        result.push(i - len + 1);
      }
    }
  }
  return result;
}
```

**Q17. Why is the "formed counter" approach faster than comparing the full frequency arrays at each step?**
A: Comparing two full frequency arrays at each step is O(σ) per step — O(σ × |s|) total. The `formed` counter tracks how many distinct characters in the target currently have their exact target frequency in the window; it's updated only when the incoming or outgoing character's count crosses the threshold from below or above. Most characters' counts don't change in a way that affects `formed` at any given step — so the `formed` counter is updated in O(1) per slide, and the valid-window check is `formed == required` in O(1), making the total algorithm O(|s| + |p|) rather than O(|s| × σ).

```js
// formed counter update logic on adding character ch:
window[ch]++;
if (target[ch] > 0 && window[ch] === target[ch]) formed++;

// formed counter update logic on removing character out:
if (target[out] > 0 && window[out] === target[out]) formed--;
window[out]--;
```

### Section C2: Advanced Patterns

**Q18. What is the "isomorphic strings" problem, and how does it generalize the anagram frequency pattern?**
A: Two strings `s` and `t` are isomorphic if characters in `s` can be mapped to characters in `t` (bijectively) such that substituting every character in `s` via the map produces `t`. Unlike anagrams (which require the same character multiset), isomorphism allows different characters as long as the *structural pattern* of repetitions is identical. Frequency pattern approach: check that `s` and `t` share the same frequency fingerprint *after normalizing each string to its pattern*. A more direct approach: maintain two maps — `sToT` and `tToS` — and at each position verify that `s[i]` always maps to `t[i]` and `t[i]` always maps back to `s[i]`. A violation at any position means the strings are not isomorphic.

```js
function isIsomorphic(s, t) {
  const sToT = new Map(), tToS = new Map();
  for (let i = 0; i < s.length; i++) {
    const sc = s[i], tc = t[i];
    if ((sToT.has(sc) && sToT.get(sc) !== tc) ||
        (tToS.has(tc) && tToS.get(tc) !== sc)) return false;
    sToT.set(sc, tc);
    tToS.set(tc, sc);
  }
  return true;
}
```

**Q19. What is the "word pattern" problem, and how does it extend isomorphic strings to word-level mapping?**
A: Given a pattern string (e.g., `"abba"`) and a sentence (e.g., `"dog cat cat dog"`), determine if the sentence follows the pattern — each letter in the pattern maps bijectively to a distinct word. It is structurally identical to isomorphic strings but operates at the word level instead of the character level. The two-map bijection check (letter → word, word → letter) applies unchanged; only the tokenization step differs (split the sentence on spaces to extract words before comparing).

```js
function wordPattern(pattern, s) {
  const words = s.split(' ');
  if (pattern.length !== words.length) return false;

  const pToW = new Map(), wToP = new Map();
  for (let i = 0; i < pattern.length; i++) {
    const p = pattern[i], w = words[i];
    if ((pToW.has(p) && pToW.get(p) !== w) ||
        (wToP.has(w) && wToP.get(w) !== p)) return false;
    pToW.set(p, w);
    wToP.set(w, p);
  }
  return true;
}
```

## Topic D: Subarray and Substring Frequency Constraints

### Section D1: Fundamentals

**Q20. What is the "minimum window substring" problem, and how does the two-pointer + frequency map solve it?**
A: Given strings `s` and `t`, find the shortest contiguous substring of `s` that contains all characters of `t` (including duplicates). Two pointers (`left`, `right`) expand and contract a window; a frequency map tracks the current window's character counts relative to `t`'s requirements.

The `formed` counter tracks how many distinct characters in `t` currently have their requirement met in the window. Expand `right` until `formed == required` (a valid window is found), then contract `left` as far as possible while the window remains valid (recording the minimum each time), then expand again. Each character is visited at most twice (once by `right`, once by `left`), giving O(|s| + |t|) overall.

```js
function minWindow(s, t) {
  if (!t.length) return "";

  const target = new Map();
  for (const ch of t) target.set(ch, (target.get(ch) ?? 0) + 1);

  const required = target.size; // distinct chars in t that must be satisfied
  let formed = 0;
  const window = new Map();

  let left = 0, minLen = Infinity, minLeft = 0;

  for (let right = 0; right < s.length; right++) {
    const ch = s[right];
    window.set(ch, (window.get(ch) ?? 0) + 1);

    if (target.has(ch) && window.get(ch) === target.get(ch)) formed++;

    // Contract from left while window is valid
    while (formed === required) {
      if (right - left + 1 < minLen) {
        minLen = right - left + 1;
        minLeft = left;
      }
      const out = s[left++];
      if (target.has(out) && window.get(out) === target.get(out)) formed--;
      window.set(out, window.get(out) - 1);
    }
  }

  return minLen === Infinity ? "" : s.slice(minLeft, minLeft + minLen);
}
```

**Q21. What is the "longest substring with at most k distinct characters" problem, and how does the shrink condition differ from minimum window substring?**
A: Find the longest substring of `s` containing at most `k` distinct characters. Same two-pointer structure as minimum window, but the shrink condition and objective are different: shrink when `window.size > k` (too many distinct characters), not when all targets are satisfied. The objective is to *maximize* the window rather than minimize it — record `right - left + 1` only when the window is valid (size ≤ k), updating `best` each time. The window map's *size* (not a `formed` counter) is the binding constraint.

```js
function longestSubarrayKDistinct(s, k) {
  const window = new Map();
  let left = 0, best = 0;

  for (let right = 0; right < s.length; right++) {
    const ch = s[right];
    window.set(ch, (window.get(ch) ?? 0) + 1);

    // Shrink when distinct count exceeds k
    while (window.size > k) {
      const out = s[left++];
      if (window.get(out) === 1) window.delete(out); // remove key if count hits 0
      else window.set(out, window.get(out) - 1);
    }

    best = Math.max(best, right - left + 1);
  }
  return best;
}
```

**Q22. What is the "subarrays with exactly k distinct elements" problem, and why can't a direct sliding window solve it?**
A: A direct sliding window cannot maintain an "exactly k distinct" window because the window cannot be validly shrunk when it has exactly k distinct elements — shrinking might drop it to k-1, breaking the invariant. The standard trick: convert "exactly k distinct" to `atMost(k) - atMost(k-1)`, where `atMost(k)` counts subarrays with *at most* k distinct elements (solvable with a standard shrink-when-exceed window). This decomposition works because: subarrays with exactly k distinct = all subarrays with ≤ k distinct minus all subarrays with ≤ k-1 distinct.

```js
function subarraysWithKDistinct(nums, k) {
  return atMost(nums, k) - atMost(nums, k - 1);
}

function atMost(nums, k) {
  const freq = new Map();
  let left = 0, count = 0;
  for (let right = 0; right < nums.length; right++) {
    freq.set(nums[right], (freq.get(nums[right]) ?? 0) + 1);
    while (freq.size > k) {
      const out = nums[left++];
      if (freq.get(out) === 1) freq.delete(out);
      else freq.set(out, freq.get(out) - 1);
    }
    count += right - left + 1; // all subarrays ending at right with ≤ k distinct
  }
  return count;
}
```

### Section D2: Advanced Patterns

**Q23. How does the "longest subarray with equal 0s and 1s" problem reduce to a prefix sum + frequency map?**
A: Replace every `0` with `-1`. Now "equal number of 0s and 1s" becomes "subarray sum equals 0". The prefix sum at index `i` records the running sum; a subarray `[j+1..i]` has sum 0 iff `prefixSum[i] == prefixSum[j]`. Use a HashMap storing `{prefixSum → first index where this sum was seen}`. At each position, if the current prefix sum was seen before, the subarray from that earlier index to the current index has sum 0 (equal 0s and 1s). The length is `i - firstSeen[prefixSum]`. Initialize `firstSeen[0] = -1` to handle subarrays starting from index 0.

```js
function findMaxLength(nums) {
  const firstSeen = new Map([[0, -1]]); // prefix sum → earliest index
  let sum = 0, best = 0;

  for (let i = 0; i < nums.length; i++) {
    sum += nums[i] === 1 ? 1 : -1; // map 0→-1, 1→1

    if (firstSeen.has(sum)) {
      best = Math.max(best, i - firstSeen.get(sum));
    } else {
      firstSeen.set(sum, i); // only store the earliest occurrence
    }
  }
  return best;
}
```

**Q24. What is the "check if two strings are k-anagrams" problem, and how does the excess frequency pattern solve it?**
A: Two strings are k-anagrams if one can be converted to the other by changing at most k characters. Build a frequency map from `s1`; subtract `s2`'s character counts from it. The sum of all *positive* residuals (counts where `s1` has more than `s2`) equals the number of character replacements needed — if this sum is ≤ k, the strings are k-anagrams. This is the excess frequency pattern applied with a threshold: after the combined +/- traversal, positive residuals represent "excess supply" in `s1` that must be replaced by characters `s2` has in excess — and these two quantities are always equal for equal-length strings.

```js
function areKAnagrams(s1, s2, k) {
  if (s1.length !== s2.length) return false;

  const freq = new Map();
  for (const ch of s1) freq.set(ch, (freq.get(ch) ?? 0) + 1);
  for (const ch of s2) freq.set(ch, (freq.get(ch) ?? 0) - 1);

  let changes = 0;
  for (const cnt of freq.values()) {
    if (cnt > 0) changes += cnt; // positive residual = characters to replace
  }
  return changes <= k;
}
```

**Q25. "How would you solve 'find the first non-repeating character in a stream' using frequency counting?" (online algorithm variant)**
A: Maintain a frequency map (updated on each new character) and a queue of characters in arrival order. On each new character: update `freq[ch]++`. To answer "what is the first non-repeating character right now?": drain the queue from the front, discarding any character whose frequency has exceeded 1 (it's now repeating), until either the queue is empty (no non-repeating character) or the front has `freq == 1` (the answer). The queue preserves arrival order; the frequency map provides O(1) count lookups. Each character enters the queue once and is dequeued at most once, so the total cost across all n arrivals is O(n).

```js
class FirstNonRepeatingStream {
  constructor() {
    this.freq = new Map();
    this.queue = []; // insertion-order queue
  }

  add(ch) {
    this.freq.set(ch, (this.freq.get(ch) ?? 0) + 1);
    this.queue.push(ch);
  }

  firstUnique() {
    // Drain repeating characters from the front
    while (this.queue.length && this.freq.get(this.queue[0]) > 1) {
      this.queue.shift();
    }
    return this.queue.length ? this.queue[0] : null;
  }
}
```

## Topic E: Cross-Topic & Interview-Style Questions

**Q26. "You're given two arrays and asked if one is a permutation of the other. Walk through your thought process."**
A: First, check lengths — unequal lengths immediately mean no. Then build a frequency map from the first array; for each element in the second array, decrement its count in the map and return false immediately if the count goes to 0 or below (excess demand). If the second array is fully processed without returning false, the arrays are permutations. Time: O(n), Space: O(k) where k is distinct elements. The "decrement-and-check" single-map approach is preferable to building two maps and comparing — it short-circuits early and avoids a separate map-equality traversal. For character arrays specifically, a 26-element or 128-element frequency array replaces the HashMap for better constant-factor performance.

**Q27. "A frequency map solution works but your interviewer asks for O(1) space. What's the fallback strategy for common frequency problems?"**
A: The O(1)-space fallback depends on the specific problem and what structure the input has:

- **Majority element (> n/2)**: Boyer-Moore voting — O(1) space, O(n) time.
- **Sorted array duplicate detection**: scan for adjacent equal elements — O(1) space.
- **Sorted array "find element appearing k times"**: binary search for the element's first and last occurrence, compute count as `lastIdx - firstIdx + 1` — O(log n) time, O(1) space.
- **Anagram check (fixed alphabet)**: sort both strings and compare — O(1) extra space if in-place sort is allowed (O(n log n) time).
- **Any problem where the input array can be modified**: use the array itself as a frequency store by negating values at index positions (the "index as hash" trick for arrays with values in range [1..n]).

The honest answer: frequency map O(1) downgrades are problem-specific. State which constraint the O(1) approach loses (usually generality or time complexity) when trading space for it.

**Q28. "How would you detect if any value in an array appears more than once, as efficiently as possible?"**
A: Three approaches by trade-off:

**O(n) time, O(n) space** — HashSet: insert each element; return true immediately on the first `has(element)` before `add(element)`. Best general-purpose answer.

**O(n log n) time, O(1) space** — Sort the array in place; scan for adjacent duplicates. Requires modifying the input.

**O(n) time, O(1) space** — Only possible with constraints: if values are in range `[1..n]`, use the "negate at index" trick — for each `x`, negate `arr[|x|-1]`; if it was already negative, `x` is a duplicate.

In an interview, state the O(n)/O(n) HashSet answer first (most general, simplest code), then offer the O(n log n)/O(1) sort answer as a space-optimization trade-off, then mention the O(n)/O(1) in-place trick as a constrained optimization — demonstrating that you know all three and can choose based on context.

**Q29. "In one sentence each, what does each of the five core frequency patterns actually do to the frequency map after building it?"**
A:
- **Threshold filter** (majority element, top-k frequent): scan the map and collect entries whose count satisfies `count OP threshold` — treating the map as a database table being filtered.
- **Fingerprint equality** (anagram check, grouping): compare maps or reduce them to a canonical key and check equality — treating the map as a signature.
- **Excess residual** (constructible string, k-anagram): decrement one map using another input, then check whether any counts went negative (exceeded supply) — treating the map as a budget.
- **Delta sliding window** (find all anagrams, minimum window): maintain a single window map incrementally with +/− operations per slide step, tracking a `formed` counter to check validity in O(1) — treating the map as a live window state.
- **Prefix-sum complement** (subarray sum equals k, equal 0s and 1s): store seen prefix sums in the map and look up the complement at each step — treating the map as a history of previously reached states.

## Problem 1 — Top K Frequent Elements

### Problem
Given an integer array `nums` and an integer `k`, return the `k` most frequent elements. The answer may be returned in any order.

```
Input:  nums = [1,1,1,2,2,3], k = 2
Output: [1, 2]

Input:  nums = [1], k = 1
Output: [1]
```

### Pattern Recognition
Frequency map + bucket sort — build a count map, then use count values as bucket indices to collect elements in O(n) without sorting by frequency (which would be O(d log d) where d is the number of distinct elements).

### Key Insight
No element can appear more than `n` times, so a bucket array of size `n+1` (indexed by count) can hold all elements grouped by their frequency. Scanning from the highest-count bucket downward collects the top-k elements in descending frequency order — no comparison-based sort required.

### Approach
Pass 1: build `freq` map — O(n). Pass 2: fill `bucket[count].push(element)` for each `(element, count)` pair — O(d). Pass 3: scan `bucket` from index `n` down to `1`, collecting elements into `result` until `k` elements are gathered — O(n). Return `result`.

### Solution

```js
function topKFrequent(nums, k) {
  // Pass 1: build frequency map
  const freq = new Map();
  for (const x of nums) {
    freq.set(x, (freq.get(x) ?? 0) + 1);
  }

  // Pass 2: fill bucket array (index = frequency count)
  // bucket[i] holds all elements that appear exactly i times
  const bucket = Array.from({ length: nums.length + 1 }, () => []);
  for (const [val, cnt] of freq) {
    bucket[cnt].push(val);
  }

  // Pass 3: collect top-k elements from highest bucket downward
  const result = [];
  for (let c = nums.length; c >= 1 && result.length < k; c--) {
    for (const val of bucket[c]) {
      result.push(val);
      if (result.length === k) return result;
    }
  }

  return result;
}
```

### Dry Run

```
nums = [1,1,1,2,2,3], k = 2

Pass 1 — frequency map:
freq = {1→3, 2→2, 3→1}

Pass 2 — bucket fill (size = nums.length+1 = 7):
bucket[3] = [1]
bucket[2] = [2]
bucket[1] = [3]
bucket[0], bucket[4..6] = [] (empty)

Pass 3 — collect top-2 from highest bucket:
c=6: bucket[6]=[] → skip
c=5: bucket[5]=[] → skip
c=4: bucket[4]=[] → skip
c=3: bucket[3]=[1] → result=[1], length=1 < 2 → continue
c=2: bucket[2]=[2] → result=[1,2], length=2 = k → return [1,2]

Answer: [1, 2] ✓
```

### Complexity
- Time: O(n) — three linear passes (frequency build, bucket fill, top-k collection), no comparison sort.
- Space: O(n) — frequency map holds at most `n` entries; bucket array has `n+1` slots.

### Edge Cases
- `k == d` (k equals the number of distinct elements): all elements are returned; the bucket scan naturally collects all of them.
- Multiple elements tied at the k-th frequency: the problem states any valid k-element answer is acceptable; the bucket scan may include one over another based on insertion order — both are correct.
- All elements identical (`[5,5,5]`, k=1): `freq = {5→3}`, `bucket[3]=[5]`, result is `[5]` — correctly handled.
- `k == 1` and multiple elements with the same highest frequency: only one is returned; acceptable per problem constraints.

### Follow-up Questions
- "What if k could be larger than the number of distinct elements?" → Cap k at `freq.size` before the collection phase, or return all distinct elements when k ≥ d.
- "Use a min-heap instead of bucket sort?" → Maintain a min-heap of size k over `(count, element)` pairs — O(d log k) time, O(k) space. Useful when k << d and you want to minimize space, but O(n log k) > O(n) so bucket sort is asymptotically superior.
- "Return results in frequency-descending order?" → The bucket scan already processes highest frequency first — just collect in that order and the result is sorted by descending frequency.

## Problem 2 — Minimum Window Substring

### Problem
Given strings `s` and `t`, return the minimum window substring of `s` such that every character in `t` (including duplicates) is included. If no such window exists, return `""`.

```
Input:  s = "ADOBECODEBANC", t = "ABC"
Output: "BANC"

Input:  s = "a", t = "a"
Output: "a"

Input:  s = "a", t = "b"
Output: ""
```

### Pattern Recognition
Two-pointer sliding window + target frequency map + `formed` counter — expand the right pointer until all target characters are satisfied (a valid window), then contract the left pointer to minimize the window while it remains valid, recording each valid minimum.

### Key Insight
The `formed` counter enables O(1) validity checking per pointer step. A character's satisfaction flips at most twice per window position (once when its count reaches the target, once when it drops below) — so `formed` changes O(1) times per step. Without `formed`, validity checking would require comparing the full window map against the target map — O(|t|) per step, degrading the total to O(|s| × |t|).

### Approach
Build `target` frequency map from `t`; set `required = target.size` (distinct chars to satisfy). Expand `right`: update `window[ch]`; if `window[ch] == target[ch]`, increment `formed`. When `formed == required`: record window if smaller than current best; contract `left`: if removing `s[left]` drops `window[ch]` below `target[ch]`, decrement `formed`; advance `left`. Repeat until `formed < required`, then expand again.

### Solution

```js
function minWindow(s, t) {
  if (!t.length) return "";

  // Build target frequency map
  const target = new Map();
  for (const ch of t) target.set(ch, (target.get(ch) ?? 0) + 1);

  const required = target.size; // number of distinct chars that must be satisfied
  let formed = 0;               // number currently satisfied in the window
  const window = new Map();

  let left = 0;
  let minLen = Infinity, minLeft = 0;

  for (let right = 0; right < s.length; right++) {
    const ch = s[right];
    window.set(ch, (window.get(ch) ?? 0) + 1);

    // Check if this character's requirement is now exactly met
    if (target.has(ch) && window.get(ch) === target.get(ch)) {
      formed++;
    }

    // Contract from left while window is valid (all requirements met)
    while (formed === required) {
      // Record this window if it's the smallest valid window so far
      if (right - left + 1 < minLen) {
        minLen = right - left + 1;
        minLeft = left;
      }

      const out = s[left++];
      // Check if removing this character breaks a requirement
      if (target.has(out) && window.get(out) === target.get(out)) {
        formed--;
      }
      window.set(out, window.get(out) - 1);
    }
  }

  return minLen === Infinity ? "" : s.slice(minLeft, minLeft + minLen);
}
```

- Space: O(|t| + σ) — target map holds at most |t| entries; window map holds at most σ (alphabet size) entries.

### Edge Cases
- `t` has duplicate characters (`t = "AAB"`): `target = {A→2, B→1}`, `required = 2`; the `formed` counter increments for `A` only when `window[A]` reaches 2, correctly requiring both A's.
- No valid window exists: `right` reaches `s.length` without ever achieving `formed == required`; `minLen` stays `Infinity`; correctly returns `""`.
- `s == t`: a window of length `|t|` starting at index 0 satisfies all requirements; the contraction phase finds this exact window.
- Single character `s` and `t`: one step of the outer loop sets `formed=1=required`, contracts once, records window of length 1.

### Follow-up Questions
- "What if you want all windows of minimum length, not just one?" → During contraction, when recording a new minimum, also record `minLeft`; after the full sweep, collect all windows of length `minLen` by scanning `s` for matches.
- "What if `t` contains characters not in `s`?" → `formed` can never reach `required`, so the outer contraction `while` never executes and `minLen` stays `Infinity` — correctly returns `""`.

## Problem 3 — Longest Substring with At Most Two Distinct Characters

### Problem
Given string `s`, return the length of the longest substring that contains at most two distinct characters.

```
Input:  s = "eceba"
Output: 3   ("ece")

Input:  s = "ccaabbb"
Output: 5   ("aabbb")
```

### Pattern Recognition
Sliding window + frequency map with `map.size` as the binding constraint — expand the right pointer freely, shrink the left pointer whenever the window's distinct character count exceeds 2. This is the "at most k distinct" pattern with k=2.

### Key Insight
The window map's `.size` property is the live distinct-character count. Deleting a key from the map (when its count drops to 0) keeps `map.size` accurate — the shrink condition `window.size > 2` triggers a left-advance until exactly 2 distinct characters remain. Every valid window's length is a candidate for `best`.

### Approach
Maintain a `window` frequency map and `left` pointer. For each `right`: add `s[right]` to the map. While `window.size > 2`: remove `s[left]` from the map (decrement count, delete key if count hits 0), advance `left`. After shrinking, update `best = max(best, right - left + 1)`.

### Solution

```js
function lengthOfLongestSubstringTwoDistinct(s) {
  const window = new Map(); // char → count in current window
  let left = 0, best = 0;

  for (let right = 0; right < s.length; right++) {
    const ch = s[right];
    window.set(ch, (window.get(ch) ?? 0) + 1);

    // Shrink from left until at most 2 distinct chars remain
    while (window.size > 2) {
      const out = s[left++];
      if (window.get(out) === 1) {
        window.delete(out); // removing last occurrence removes the distinct char
      } else {
        window.set(out, window.get(out) - 1);
      }
    }

    best = Math.max(best, right - left + 1);
  }

  return best;
}
```

```

right=1 'c': window={e:1,c:1}. size=2 ≤ 2. best=max(1,2)=2.
right=2 'e': window={e:2,c:1}. size=2 ≤ 2. best=max(2,3)=3.

  out=s[0]='e'. count=2→1. window={e:1,c:1,b:1}. size=3 > 2 → shrink:
  out=s[1]='c'. count=1→delete. window={e:1,b:1}. left=2. size=2 ≤ 2.
```

### Complexity
- Time: O(n) — `right` traverses `s` once; `left` traverses `s` at most once (each character enters and exits the window at most once).
- Space: O(1) — the window map holds at most 3 entries at any moment (one excess before shrinking); effectively O(1) regardless of input size.

### Edge Cases
- All identical characters (`"aaaa"`): `window.size` never exceeds 1; `best` grows to `n`.
- Only 1 or 2 distinct characters in `s`: the shrink condition never triggers; `best` is the full string length.
- Empty string: the loop never executes; returns 0.
- Generalizing to k distinct: replace `> 2` with `> k` — the exact same structure solves "at most k distinct characters."

### Follow-up Questions
- "Generalize to k distinct characters?" → Replace the literal `2` with parameter `k` — zero other changes. The pattern is identical.
- "What if you need exactly 2 distinct characters, not at most 2?" → Use the `atMost(2) - atMost(1)` decomposition from Q22 — the "exactly k" version cannot be directly maintained as a single window.

## Problem 4 — Valid Anagram

### Problem
Given two strings `s` and `t`, return `true` if `t` is an anagram of `s`, and `false` otherwise.

```
Input:  s = "anagram", t = "nagaram"
Output: true

Input:  s = "rat", t = "car"
Output: false
```

### Pattern Recognition
Single frequency array with +/− pass — increment for `s`, decrement for `t`, then verify all counts are zero. The key space is exactly 26 lowercase letters, making a direct-address array strictly preferable to a HashMap.

### Key Insight
Two strings are anagrams iff their character frequency distributions are identical. Building one combined +/− frequency array (rather than two separate maps and a map-equality comparison) reduces both the code complexity and the constant factor: one array, two passes, one zero-check — no map iteration, no key comparison overhead.

### Approach
Early exit if lengths differ. Build `freq[26]`: `++` for each char in `s`, `--` for each char in `t`. If any `freq[i] != 0`, the counts didn't balance — return false. Otherwise true.

### Solution

```js
function isAnagram(s, t) {
  if (s.length !== t.length) return false;

  // Direct-address frequency array: index = char - 'a'
  const freq = new Array(26).fill(0);

  for (let i = 0; i < s.length; i++) {
    freq[s.charCodeAt(i) - 97]++; // +1 for s's character
    freq[t.charCodeAt(i) - 97]--; // -1 for t's character
  }

  // All counts must return to zero for the strings to be anagrams
  return freq.every(c => c === 0);
}
```

### Dry Run

```
s = "anagram", t = "nagaram"
Lengths both 7 → proceed.

freq starts as [0,0,...,0] (26 zeros)

i=0: s='a'(idx 0)++, t='n'(idx 13)-- → freq[0]=1, freq[13]=-1
i=1: s='n'(idx 13)++, t='a'(idx 0)-- → freq[0]=0, freq[13]=0
i=2: s='a'(idx 0)++, t='g'(idx 6)-- → freq[0]=1, freq[6]=-1
i=3: s='g'(idx 6)++, t='a'(idx 0)-- → freq[0]=0, freq[6]=0
i=4: s='r'(idx 17)++, t='r'(idx 17)-- → freq[17]=0
i=5: s='a'(idx 0)++, t='a'(idx 0)-- → freq[0]=0
i=6: s='m'(idx 12)++, t='m'(idx 12)-- → freq[12]=0

freq = [0,0,...,0] (all zeros) → return true ✓
```

### Complexity
- Time: O(n) — one pass over both strings simultaneously; one O(26) = O(1) zero-check pass.
- Space: O(1) — fixed 26-element array, independent of input size.

### Edge Cases
- Different lengths: early return false before building the array — O(1).
- Single character strings: `s="a"`, `t="a"`: freq[0] increments then decrements to 0 → true. `s="a"`, `t="b"`: freq[0]=1, freq[1]=-1 → false.
- Unicode / non-lowercase input: the 26-element array assumption breaks. For general Unicode, use a HashMap: `freq.set(ch, (freq.get(ch)??0)+1)` for `s` and `--` for `t`, then check all values are 0.
- Empty strings: both lengths are 0, lengths match, freq stays all-zero → return true (two empty strings are vacuously anagrams of each other — correct by convention).

### Follow-up Questions
- "What if the inputs contain Unicode characters?" → Replace the direct-address array with a `Map<char, int>` — same two-pass +/− logic, O(n) time, O(σ) space where σ is the number of distinct characters.
- "Return the count of characters that differ between s and t (not just true/false)?" → Count positive residuals in `freq` after the two passes — each positive value represents a character `s` has in excess of `t`.

## Quick Reference — Frequency Pattern Decision Tree

```
What kind of frequency question is this?
│
├── COUNT OCCURRENCES OF EACH ELEMENT (foundation step)?
│   ├── Key space is small + enumerable (26 letters, ASCII) → direct-address array
│   │   freq[ch - 'a']++  →  O(1) per op, O(σ) space, best cache performance
│   └── Key space is large / unbounded / string → HashMap
│       freq.set(x, (freq.get(x) ?? 0) + 1)  →  O(1) avg per op, O(k) space
│
├── FIND ELEMENTS BY FREQUENCY (top-k, majority, threshold)?
│   ├── Top-k frequent → frequency map + bucket sort (O(n)) or min-heap (O(n log k))
│   ├── Majority element (> n/2) → frequency map OR Boyer-Moore (O(1) space)
│   └── Exactly / at least / at most k times → build freq map → filter by count condition
│
├── CHECK EQUIVALENCE (anagram, isomorphic, permutation)?
│   ├── Same character multiset (anagram) → single +/- freq array, check all-zero
│   ├── Same structural repetition pattern (isomorphic) → two bijection maps (s→t, t→s)
│   └── Group by equivalence → canonical fingerprint as HashMap key (sorted or freq vector)
│
├── SLIDING WINDOW WITH FREQUENCY CONSTRAINT?
│   ├── Fixed window, find all valid (find anagrams) → delta update + formed counter
│   ├── Variable window, maximize length (at most k distinct) → shrink on window.size > k
│   ├── Variable window, minimize length (min window substring) → shrink while formed==required
│   └── Exactly k distinct → atMost(k) - atMost(k-1) decomposition
│
├── SUBARRAY / PREFIX SUM WITH COUNT CONDITION?
│   ├── Subarray sum = k → prefix sum freq map, look up (sum - k)
│   ├── Equal 0s and 1s → map 0→-1, same as subarray sum = 0
│   └── Subarray with exactly k distinct → atMost decomposition
│
├── SUPPLY / DEMAND (can one string be built from another)?
│   └── Build supply freq map, decrement for demand; return false on first negative
│       (constructible string, k-anagram, magazine ransom note)
│
└── STREAM / ONLINE (query after each element arrival)?
    └── Maintain freq map + auxiliary structure for O(1) queries
        (first non-repeating in stream: freq map + queue;
         frequency-of-frequencies: freq map + freqOfFreq map)
```

## Common Bugs Checklist

Before submitting any frequency counting solution, verify:

1. **Initialized with `?? 0` (or equivalent), not unchecked increment?** — `freq[x]++` when `freq[x]` is `undefined` produces `NaN` in JavaScript (undefined + 1 = NaN), silently corrupting all subsequent counts for that key. Always use `freq.set(x, (freq.get(x) ?? 0) + 1)` or check existence first.

2. **Separate count and query phases where global distribution matters?** — Querying the frequency map mid-build gives a partial distribution, producing wrong answers for any question whose answer depends on all elements (majority, top-k, anagram check). Complete the count phase fully before querying — unless the problem explicitly asks about "elements seen so far" (two-sum complement lookup pattern).

3. **Deleting keys at zero count in sliding window maps?** — When a character's count drops to 0 during window shrinkage, delete the key (`window.delete(out)`) rather than leaving it with value 0. Failing to delete leaves zero-count entries in the map, inflating `window.size` and incorrectly triggering the shrink condition as if that character were still present.

4. **`formed` counter updates only when count crosses the exact threshold?** — Increment `formed` only when `window[ch]` goes from `target[ch]-1` to `target[ch]` (the requirement is just met), not on every increment. Decrement `formed` only when `window[ch]` drops from `target[ch]` to `target[ch]-1`. Any other threshold causes over/under-counting of satisfied requirements.

5. **Two bijection maps for isomorphism, not one?** — A single `s→t` map catches invalid mappings from `s` but misses cases where two different characters in `s` incorrectly map to the same character in `t`. The reverse `t→s` map is required to enforce bijectivity. Missing it produces false positives for strings like `s="ab"`, `t="aa"`.

6. **`?? 0` vs `|| 0` for frequency initialization?** — `freq.get(x) || 0` treats a stored value of `0` as falsy and resets it to `0` — correct by coincidence for non-zero counts, but semantically wrong. Prefer `?? 0` (nullish coalescing), which only falls back to `0` when the value is `null` or `undefined`, not when it's `0`.

7. **Bucket array size is `n+1`, not `n`?** — In bucket sort for top-k frequent, an element can appear at most `n` times. A bucket array of size `n` only has valid indices `0..n-1`, making `bucket[n]` out of bounds. Use `n+1` to accommodate a count of exactly `n`.

8. **`atMost(k) - atMost(k-1)` decomposition for "exactly k distinct" problems?** — A direct sliding window cannot maintain an "exactly k distinct" invariant because the shrink condition is ambiguous — you cannot shrink a valid exactly-k window without potentially dropping to k-1. Always decompose into two `atMost` calls; attempting a direct "exactly k" window produces overcounting or undercounting.

The decisive signal is a one-sentence statement like: "I'll build a supply map from `s`, then decrement it for each character in `t` — if any count goes negative, the supply is exhausted for that character and I return false immediately." That framing — naming the map's role, the operation performed, and the invariant checked — is what separates a confident senior answer from someone who memorized the code without understanding why the frequency map is the right tool here.
