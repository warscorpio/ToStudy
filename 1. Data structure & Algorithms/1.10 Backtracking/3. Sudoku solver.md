# DSA: Sudoku Solver — Backtracking — Theory, Interview Q&A & Practical Problems

---

## Part 1 — Theory & Interview Q&A

---

### Section 1: Fundamentals

**Q1. What is backtracking, and how does it differ from brute force?**
A: Backtracking is a systematic search technique that builds a solution incrementally, one piece at a time, and abandons a partial solution the moment it determines that the current path cannot possibly lead to a valid complete solution — "backing up" to the previous decision point and trying the next alternative. It is distinguished from brute force in one critical way: **pruning**. Brute force generates every possible complete candidate and tests each one. Backtracking never generates a candidate that violates constraints — it prunes invalid branches early, before completing them, potentially eliminating enormous subtrees of the search space with a single check.

The conceptual model: backtracking explores an implicit tree (the "search tree") where each node represents a partial solution and each edge represents a choice. When a constraint is violated at any node, the entire subtree rooted at that node is abandoned — no element of that subtree is ever examined.

**Q2. What are the three components every backtracking algorithm must define?**
A:
- **Choice**: what decision is made at each step? For Sudoku: which digit (1–9) to place in the current empty cell.
- **Constraint**: what makes a partial solution invalid and triggers backtracking? For Sudoku: the digit violates the row, column, or 3×3 box uniqueness rule.
- **Goal**: what constitutes a complete valid solution? For Sudoku: all 81 cells filled with no violations.

These three elements completely define a backtracking algorithm. Identifying them explicitly before coding is the highest-signal behavior in an interview — it demonstrates structural understanding, not just pattern memorization.

**Q3. What is the Sudoku problem statement?**
A: A 9×9 grid is partially filled with digits 1–9. The rules:
- Each row must contain all digits 1–9 exactly once.
- Each column must contain all digits 1–9 exactly once.
- Each of the nine 3×3 sub-boxes must contain all digits 1–9 exactly once.

Given a partially filled board (guaranteed to have a unique solution in well-posed puzzles), fill all empty cells to satisfy all three constraints simultaneously.

**Q4. Why is Sudoku a backtracking problem and not solvable greedily?**
A: Greedy approaches assign a digit to each cell based on local information (e.g., the only possible digit for that cell given current board state). This works for easy puzzles but fails for hard ones — a cell may have multiple valid digits at the time of assignment, and the locally "best" choice may make a later cell unsolvable. When that happens, backtracking is needed: undo the last assignment and try the next candidate.

Sudoku is NP-complete in its generalized n×n form (proven by Yato and Seta, 2003). For the fixed 9×9 case, the search space is finite (bounded at ~6.67 × 10²¹ possible grids before constraints), and backtracking with constraint propagation solves all instances efficiently. But no polynomial algorithm is known for the general case — backtracking is the fundamental approach.

**Q5. What is the search tree for Sudoku, and how large can it be?**
A: Each empty cell is a decision point with up to 9 branches (digits 1–9). The depth of the search tree equals the number of empty cells (up to 64 in a standard puzzle). Without pruning, the naive upper bound is 9^64 ≈ 10^61 — astronomically large.

With constraint checking (pruning invalid digits at each cell): the effective branching factor is much lower. In practice, Sudoku backtracking explores far fewer than even 10^6 nodes for standard puzzles — constraint propagation reduces the branching factor to near 1 for most cells. The "hardest" Sudoku puzzles (by search complexity) may require exploring thousands of nodes, but they terminate quickly in practice.

### Section 2: The Algorithm

**Q6. Write the standard backtracking Sudoku solver.**
A:

```js
function solveSudoku(board) {
  solve(board);
}

function solve(board) {
  // find the next empty cell
  for (let row = 0; row < 9; row++) {
    for (let col = 0; col < 9; col++) {
      if (board[row][col] === '.') {
        // try placing digits 1–9
        for (let digit = 1; digit <= 9; digit++) {
          const ch = String(digit);

          if (isValid(board, row, col, ch)) {
            board[row][col] = ch;  // make choice

            if (solve(board)) return true; // solution found — propagate up

            board[row][col] = '.'; // undo choice (backtrack)
          }
        }
        return false; // no valid digit works — trigger backtracking
      }
    }
  }
  return true; // no empty cell found — board is complete
}

function isValid(board, row, col, ch) {
  for (let i = 0; i < 9; i++) {
    // check row: does ch appear in this row?
    if (board[row][i] === ch) return false;

    // check column: does ch appear in this column?
    if (board[i][col] === ch) return false;

    // check 3×3 box: compute the box containing (row, col)
    const boxRow = 3 * Math.floor(row / 3) + Math.floor(i / 3);
    const boxCol = 3 * Math.floor(col / 3) + (i % 3);
    if (board[boxRow][boxCol] === ch) return false;
  }
  return true;
}
```

**Q7. Walk through the exact execution flow — what happens when `isValid` returns false for all digits at a cell?**
A: The inner `for (digit)` loop completes all 9 iterations without finding a valid digit. The function reaches `return false` after the loop. This `false` propagates back to the caller — the previous recursive call of `solve`. That caller sees `if (solve(board)) return true` evaluate to false, so it executes `board[row][col] = '.'` (undoing the choice it just made) and continues to the next digit in its own `for (digit)` loop. This cascade of `false` returns unwinds the recursion until a previous choice can be changed.

If `false` propagates all the way to the top-level call from `solveSudoku`, it means no solution exists — which can't happen for a well-posed Sudoku but is the correct behavior for an invalid input.

**Q8. Trace the 3×3 box calculation: for cell `(row, col)`, how do you iterate over all 9 cells in its box?**
A: The key formulas:
- Top-left corner of the box: `(3 × ⌊row/3⌋, 3 × ⌊col/3⌋)`
- For `i` from 0 to 8, the box cell is:
  - Row: `3 × ⌊row/3⌋ + ⌊i/3⌋`
  - Col: `3 × ⌊col/3⌋ + (i % 3)`

```
For row=4, col=5:
  Box top-left: (3×1, 3×1) = (3, 3)
  i=0: (3+0, 3+0)=(3,3)  i=1: (3+0, 3+1)=(3,4)  i=2: (3+0, 3+2)=(3,5)
  i=3: (3+1, 3+0)=(4,3)  i=4: (3+1, 3+1)=(4,4)  i=5: (3+1, 3+2)=(4,5)
  i=6: (3+2, 3+0)=(5,3)  i=7: (3+2, 3+1)=(5,4)  i=8: (3+2, 3+2)=(5,5)
```

This single formula encodes row check, column check, and box check in one loop — an elegant compression. Alternatively, the box can be checked separately with two explicit loops over `r in [0,1,2]` and `c in [0,1,2]`, which some find more readable:

```js
// Explicit box check — equivalent but clearer:
const startRow = 3 * Math.floor(row / 3);
const startCol = 3 * Math.floor(col / 3);
for (let r = startRow; r < startRow + 3; r++) {
  for (let c = startCol; c < startCol + 3; c++) {
    if (board[r][c] === ch) return false;
  }
}
```

**Q9. What is the time complexity of the naive backtracking Sudoku solver?**
A: The theoretical worst case is O(9^m) where m = number of empty cells (up to 81). This is because at each empty cell, we try at most 9 digits, and there are m recursive levels. In the absolute worst case (every digit is valid at every cell, which never happens in practice due to Sudoku constraints), the complexity is 9^81 — meaningless as a practical bound.

The actual complexity depends on the puzzle's difficulty and the degree of constraint propagation. For standard 9×9 Sudoku, the backtracking solver with O(1) validity checks terminates in milliseconds for all known puzzles. The "hardest" Sudoku by algorithmic difficulty explores at most ~10^5 nodes — far below the theoretical maximum.

A more meaningful bound: O(9^m × 9) per validity check (9 cells checked in each row/column/box check). But again, in practice m ≪ 81 effective branches due to pruning.

### Section 3: Optimizations

**Q10. What is the "Minimum Remaining Values" (MRV) heuristic, and why does it help?**
A: Instead of filling cells in fixed left-to-right, top-to-bottom order, MRV (also called "fail-first" or "most-constrained variable") always selects the empty cell with the **fewest valid digits remaining**. By filling the most constrained cell first, you:
- Detect failures earlier (cells with 0 valid digits trigger immediate backtrack without exploring other cells).
- Reduce effective branching factor (a cell with 1 valid digit has no branching — exactly 1 choice).
- Make more progress per recursive call on average.

```js
function findBestCell(board, candidates) {
  let minCount = 10, bestRow = -1, bestCol = -1;

  for (let row = 0; row < 9; row++) {
    for (let col = 0; col < 9; col++) {
      if (board[row][col] === '.') {
        const count = candidates[row][col].size;
        if (count < minCount) {
          minCount = count;
          bestRow = row;
          bestCol = col;
          if (count === 1) return [bestRow, bestCol]; // can't do better
        }
      }
    }
  }
  return [bestRow, bestCol];
}
```

MRV can reduce the search space by orders of magnitude for hard puzzles. It's the single most impactful optimization for Sudoku backtracking.

**Q11. What is constraint propagation, and how does it combine with backtracking?**
A: Constraint propagation actively reduces candidate sets based on current board state — without backtracking. The key technique for Sudoku is **Arc Consistency (AC-3)** or simpler naked singles / hidden singles:

- **Naked single**: if a cell has only one valid candidate, assign it immediately (no branching needed).
- **Hidden single**: if a digit can go in only one cell within a row, column, or box, assign it there.
- **Arc consistency**: when a value is assigned, propagate the removal of that value from all cells in the same row, column, and box, potentially revealing new naked singles.

Combining constraint propagation with backtracking:
```
while (naked singles exist): assign them (O(n) propagation)
if (board complete): return true
if (any cell has 0 candidates): return false (backtrack)
select cell with MRV (fewest candidates)
for each candidate digit:
    assign digit to cell
    propagate constraints
    recursively solve
    if successful: return true
    undo assignment, restore candidates (backtrack)
return false
```

This is the basis of Peter Norvig's celebrated Sudoku solver — constraint propagation alone solves most easy/medium puzzles without any backtracking. Hard puzzles require some backtracking, but with far fewer nodes explored.

**Q12. How do you use bitmask operations to speed up candidate tracking?**
A: Instead of a `Set` or array for candidates, use a bitmask where bit `d` represents whether digit `d` is still a valid candidate. A 9-bit integer (bits 1–9) encodes all candidates for one cell. Row, column, and box "used" sets are also bitmasks.

```js
// Initialize: rowUsed[r] = bitmask of digits used in row r
const rowUsed = new Array(9).fill(0);
const colUsed = new Array(9).fill(0);
const boxUsed = new Array(9).fill(0);

// When a digit d is placed at (r, c):
const bit = 1 << d;
rowUsed[r] |= bit;
colUsed[c] |= bit;
boxUsed[Math.floor(r/3)*3 + Math.floor(c/3)] |= bit;

// Available candidates at (r, c):
const used = rowUsed[r] | colUsed[c] | boxUsed[box(r,c)];
const available = (~used) & 0x3FE; // bits 1–9 (exclude bit 0)

// Count candidates: built-in popcount or bit tricks
const count = popcount(available);

// Undo: clear bit when backtracking
rowUsed[r] &= ~bit;
colUsed[c] &= ~bit;
boxUsed[box(r,c)] &= ~bit;
```

Bitmask operations reduce constraint checking from O(27) cell comparisons to O(1) bitwise OR and AND — a significant constant-factor speedup for a solver that explores many nodes.

**Q13. What is "forward checking" and how does it differ from full constraint propagation?**
A: Forward checking is a lightweight form of constraint propagation — when a digit `d` is assigned to cell `(r, c)`, immediately check whether any empty cell in the same row, column, or box now has **zero remaining candidates**. If so, the current assignment is invalid — backtrack immediately without exploring further.

Full constraint propagation (AC-3) goes further: it also checks whether removing `d` from neighboring cells' candidates causes those cells' assignments to be forced, which in turn might eliminate candidates from their neighbors, and so on — a cascade. Forward checking only looks one step ahead; AC-3 propagates until a fixed point.

For Sudoku interviews, forward checking is a reasonable optimization to mention. Full AC-3 is the production-quality approach but complex to implement in an interview setting.

### Section 4: Generalization & Variants

**Q14. How does the Sudoku backtracking pattern generalize to other constraint satisfaction problems (CSPs)?**
A: The Sudoku solver is an instance of the general CSP backtracking template:

```
function backtrack(assignment, variables, domains, constraints):
  if assignment is complete: return assignment  // goal reached

  var = selectUnassignedVariable(variables, assignment, domains)  // MRV
  for value in orderDomainValues(var, assignment, domains):       // LCV
    if isConsistent(var, value, assignment, constraints):
      assignment[var] = value
      inferences = propagate(var, value, domains, constraints)   // FC/AC-3
      if inferences ≠ failure:
        result = backtrack(assignment, variables, domains, constraints)
        if result ≠ failure: return result
      removeInferences(inferences, domains)
      delete assignment[var]

  return failure
```

This template powers: Sudoku, N-Queens, map coloring, crossword solving, scheduling, register allocation, and any problem expressible as "assign values to variables subject to constraints." Sudoku simply fills in: variables=empty cells, domains={1..9}, constraints=row/col/box uniqueness.

**Q15. What is the N-Queens problem, and how does the same backtracking approach apply?**
A: Place N non-attacking queens on an N×N chessboard. Queens attack each other if they share a row, column, or diagonal.

The backtracking structure mirrors Sudoku exactly:
- **Choice**: which column to place a queen in row `r`.
- **Constraint**: no two queens share a column or diagonal.
- **Goal**: all N queens placed without conflict.

```js
function solveNQueens(n) {
  const board = new Array(n).fill(-1); // board[r] = column of queen in row r
  const results = [];

  function backtrack(row) {
    if (row === n) {
      results.push([...board]); // complete solution
      return;
    }

    for (let col = 0; col < n; col++) {
      if (isQueenSafe(board, row, col, n)) {
        board[row] = col;   // place queen
        backtrack(row + 1); // recurse to next row
        board[row] = -1;    // undo placement
      }
    }
  }

  function isQueenSafe(board, row, col, n) {
    for (let r = 0; r < row; r++) {
      if (board[r] === col) return false;              // same column
      if (Math.abs(board[r] - col) === row - r) return false; // diagonal
    }
    return true;
  }

  backtrack(0);
  return results;
}
```

**Q16. What is the "Word Search" problem and how is it a backtracking variant?**
A: Given a 2D character grid and a word, determine if the word exists as a path through adjacent cells (4-directionally, each cell used at most once). Backtracking: try each starting cell, attempt to extend the path one character at a time, backtrack when the next character doesn't match or the cell is already used.

```js
function exist(board, word) {
  const rows = board.length, cols = board[0].length;

  function backtrack(r, c, idx) {
    if (idx === word.length) return true;    // all chars matched
    if (r < 0 || r >= rows || c < 0 || c >= cols) return false;
    if (board[r][c] !== word[idx]) return false;

    const temp = board[r][c];
    board[r][c] = '#'; // mark visited (in-place — undo after recursion)

    const found = backtrack(r+1, c, idx+1) || backtrack(r-1, c, idx+1) ||
                  backtrack(r, c+1, idx+1) || backtrack(r, c-1, idx+1);

    board[r][c] = temp; // restore (backtrack)
    return found;
  }

  for (let r = 0; r < rows; r++)
    for (let c = 0; c < cols; c++)
      if (backtrack(r, c, 0)) return true;

  return false;
}
```

The structure is identical to Sudoku: make a choice (mark cell as visited), check constraint (character matches), recurse, undo (restore cell).

### Section 5: Complexity & Design

**Q17. Compare the time complexity of backtracking with and without MRV for Sudoku.**
A: For a puzzle with 50 empty cells:

- **Without MRV** (left-to-right fill): cells are tried in fixed order regardless of how constrained they are. A cell early in the sequence may have 8 valid candidates while a later cell has only 1. Trying 8 branches before reaching the forced cell wastes work.

- **With MRV** (most-constrained first): forced cells (1 candidate) are filled immediately with no branching. Highly constrained cells (2–3 candidates) are tried next. The effective branching factor drops from ~3 on average (without MRV) to ~1.2 (with MRV) for typical Sudoku puzzles — reducing the search space by orders of magnitude.

Empirically, MRV-enabled solvers are 100–1000× faster than naive left-to-right backtracking on hard Sudoku instances. For the 9×9 case, both terminate instantly for all practical purposes; the difference matters for n×n Sudoku with large n.

**Q18. What are the three key design decisions that determine a backtracking algorithm's efficiency?**
A:
1. **Variable ordering** (which cell/variable to assign next): MRV picks the most constrained variable. Bad ordering leads to late failure detection.
2. **Value ordering** (which digit to try first): Least-Constraining Value (LCV) prefers values that leave the most options for neighboring variables — minimizing future conflicts. For Sudoku, trying digits that appear least frequently in the constraint neighborhood goes first.
3. **Constraint propagation depth** (how much to infer before branching): naked singles only (fast, some wasted backtracking), forward checking (moderate), AC-3 (thorough, minimal backtracking but expensive per node).

The right combination is problem-dependent. For Sudoku in an interview: implement the basic solver (correct), mention MRV and constraint propagation as optimizations (demonstrates depth), implement bitmask tracking if asked for the optimized version.

**Q19. How do you prove that the backtracking Sudoku solver is correct (always finds a solution if one exists)?**
A: By induction on the number of empty cells:

**Base case**: 0 empty cells. The board is complete. `solve()` finds no empty cell and returns `true` — correct.

**Inductive step**: assume the solver correctly handles boards with k-1 or fewer empty cells. Given a board with k empty cells, `solve()` finds the first empty cell `(r, c)` and tries all digits 1–9. For each digit `d` that passes `isValid`:
- It places `d` and recursively calls `solve()` on a board with k-1 empty cells.
- By inductive hypothesis, this recursive call correctly determines whether the partially filled board (with `d` placed) has a valid completion.
- If a completion exists, the recursion returns `true` and so does the current call.
- If no completion exists for any valid `d`, all return `false` and the current call returns `false`.

Since `isValid` is correct (checks all three Sudoku constraints), and the recursion correctly handles all sub-cases, the full algorithm is correct.

### Section 6: Scenario / Interview-Style Questions

**Q20. "Walk me through your backtracking template — how would you apply it to solve Sudoku from scratch?"**
A: The three-question framework:

1. **What is the choice?** At each step, I find the next empty cell and try placing each digit 1–9.

2. **What is the constraint?** A digit is invalid if it already appears in the same row, same column, or same 3×3 box.

3. **What is the goal/base case?** When there are no more empty cells, the board is complete — return true.

Then: make a choice (place a digit), check constraint (skip invalid digits), recurse (try to complete the rest), undo (remove the digit if recursion fails), try the next choice. If all 9 digits fail for a cell, return false — triggering backtracking in the caller.

**Q21. "Your Sudoku solver works but the interviewer says 'can you make it faster?' — what do you propose?"**
A: Three optimizations in order of impact:

1. **MRV (choose most-constrained cell)**: instead of scanning left-to-right for the next empty cell, find the empty cell with the fewest valid digits. Dramatically reduces effective branching factor.

2. **Bitmask constraint tracking**: maintain three arrays of bitmasks (`rowUsed[r]`, `colUsed[c]`, `boxUsed[b]`) tracking which digits are placed. Validity check becomes `(rowUsed[r] | colUsed[c] | boxUsed[b]) & (1 << digit)` — O(1) instead of O(27) cell scans.

3. **Naked singles propagation**: before choosing a cell to branch on, repeatedly apply forced assignments (cells with exactly 1 valid candidate). This often eliminates dozens of cells without branching, leaving only the genuinely ambiguous cells for the search.

Implementing all three produces a solver that handles any standard 9×9 Sudoku puzzle in under a millisecond.

**Q22. "What is the difference between backtracking and dynamic programming — when would you use each?"**
A: Both explore a structured solution space, but with different goals and strategies:

- **Backtracking** targets **finding one or all solutions** to a constraint satisfaction problem. It explores a tree of partial solutions, pruning branches that violate constraints. It doesn't store subproblem results — each recursive call is independent.

- **Dynamic programming** targets **optimizing an objective function** over problems with overlapping subproblems and optimal substructure. It stores computed subproblem results to avoid recomputation.

Choose backtracking when: the problem is about satisfying constraints (Sudoku, N-Queens, subset sum with exact target, graph coloring), and pruning can eliminate large portions of the search space. Choose DP when: the problem asks for minimum/maximum/count and the same subproblem recurs (knapsack, shortest path, LCS).

Some problems use both: branch-and-bound (backtracking with DP-computed bounds) or memoized backtracking (cache results of subproblems to avoid re-exploring identical states).

**Q23. "An interviewer gives you a partially filled grid and your solver returns false. What do you check first?"**
A: Three categories of bugs:

1. **`isValid` is wrong**: the most common error. Verify: (a) row check iterates all 9 columns; (b) column check iterates all 9 rows; (c) box check uses the correct top-left corner formula `(3×⌊row/3⌋, 3×⌊col/3⌋)`. A wrong box formula causes valid placements to be rejected or invalid ones to be accepted.

2. **Empty cell representation mismatch**: the solver scans for `'.'` (string) but the board uses `0` (integer) or vice versa. The initial board scan finds no empty cells and immediately returns true with an incomplete board.

3. **Missing backtrack (undo)**: the line `board[row][col] = '.'` after `solve(board)` returns false is missing. Without it, the board accumulates wrong guesses that block future valid placements.

Trace through a 2×2 subproblem manually to isolate which of these three is failing.

## Problem 1 — Sudoku Solver (LeetCode 37)

### Problem
Write a program to solve a Sudoku puzzle by filling empty cells (marked as `'.'`). The board is guaranteed to have a unique solution.

```
Input:
[["5","3",".",".","7",".",".",".","."],
 ["6",".",".","1","9","5",".",".","."],
 [".","9","8",".",".",".",".","6","."],
 ["8",".",".",".","6",".",".",".","3"],
 ["4",".",".","8",".","3",".",".","1"],
 ["7",".",".",".","2",".",".",".","6"],
 [".","6",".",".",".",".","2","8","."],
 [".",".",".","4","1","9",".",".","5"],
 [".",".",".",".","8",".",".","7","9"]]

Output: board filled with unique valid digits
```

### Pattern Recognition
Classic backtracking CSP. Three components: choice = digit 1–9 for each empty cell; constraint = row/col/box uniqueness; goal = no empty cells remain.

### Key Insight
Try each digit in order at the first empty cell found. If valid (no conflicts), place it and recurse. If the recursion fails (returns false), remove the digit (backtrack) and try the next. If all 9 digits fail, return false to trigger backtracking at the caller.

### Approach
Scan the board for the first `'.'`. For each digit 1–9: check `isValid` (O(27) checks), place if valid, recurse, undo if recursion fails. If no `'.'` is found, the board is complete — return true.

### Solution — Standard Backtracking

```js
function solveSudoku(board) {
  solve(board);
  // board is modified in-place; no return value needed for the outer call
}

function solve(board) {
  for (let row = 0; row < 9; row++) {
    for (let col = 0; col < 9; col++) {
      if (board[row][col] !== '.') continue; // skip filled cells

      // try each digit for this empty cell
      for (let d = 1; d <= 9; d++) {
        const ch = String(d);

        if (!isValid(board, row, col, ch)) continue; // constraint check

        board[row][col] = ch;           // CHOICE: place digit

        if (solve(board)) return true;  // GOAL: if rest is solvable → done

        board[row][col] = '.';          // BACKTRACK: undo placement
      }

      // no digit worked for (row, col) — signal failure to caller
      return false;
    }
  }

  // no empty cell found — board is complete
  return true;
}

function isValid(board, row, col, ch) {
  for (let i = 0; i < 9; i++) {
    // 1. Row check: scan all columns in this row
    if (board[row][i] === ch) return false;

    // 2. Column check: scan all rows in this column
    if (board[i][col] === ch) return false;

    // 3. Box check: map i (0–8) to the 9 cells in the 3×3 box
    //    top-left of box: (3*⌊row/3⌋, 3*⌊col/3⌋)
    //    offset from i: row_offset = ⌊i/3⌋, col_offset = i%3
    const boxRow = 3 * Math.floor(row / 3) + Math.floor(i / 3);
    const boxCol = 3 * Math.floor(col / 3) + (i % 3);
    if (board[boxRow][boxCol] === ch) return false;
  }
  return true;
}
```

### Solution — Optimized with Bitmasks

```js
function solveSudokuFast(board) {
  // Bitmask: bit d set means digit d is used in this unit
  const rowUsed = new Array(9).fill(0);
  const colUsed = new Array(9).fill(0);
  const boxUsed = new Array(9).fill(0);

  const boxIndex = (r, c) => 3 * Math.floor(r / 3) + Math.floor(c / 3);

  // Initialize bitmasks from the given board
  for (let r = 0; r < 9; r++) {
    for (let c = 0; c < 9; c++) {
      if (board[r][c] !== '.') {
        const d = parseInt(board[r][c]);
        const bit = 1 << d;
        rowUsed[r] |= bit;
        colUsed[c] |= bit;
        boxUsed[boxIndex(r, c)] |= bit;
      }
    }
  }

  function solve() {
    // Find the empty cell with fewest candidates (MRV)
    let minCount = 10, bestRow = -1, bestCol = -1;

    for (let r = 0; r < 9; r++) {
      for (let c = 0; c < 9; c++) {
        if (board[r][c] !== '.') continue;

        // available = digits NOT used in row, col, or box
        const used = rowUsed[r] | colUsed[c] | boxUsed[boxIndex(r, c)];
        const available = (~used) & 0x3FE; // mask bits 1–9 (0x3FE = 0b1111111110)

        if (available === 0) return false; // no valid digit — dead end

        const count = countBits(available);
        if (count < minCount) {
          minCount = count;
          bestRow = r;
          bestCol = c;
          if (count === 1) break; // can't do better — forced cell
        }
      }
      if (minCount === 1) break;
    }

    if (bestRow === -1) return true; // no empty cell — solved!

    const r = bestRow, c = bestCol;
    const used = rowUsed[r] | colUsed[c] | boxUsed[boxIndex(r, c)];
    let available = (~used) & 0x3FE;

    // try each available digit
    while (available) {
      const bit = available & (-available); // isolate lowest set bit
      const d = Math.log2(bit);             // digit value (1–9)
      available &= available - 1;           // clear this bit

      // place digit
      board[r][c] = String(d);
      rowUsed[r] |= bit;
      colUsed[c] |= bit;
      boxUsed[boxIndex(r, c)] |= bit;

      if (solve()) return true;

      // undo
      board[r][c] = '.';
      rowUsed[r] &= ~bit;
      colUsed[c] &= ~bit;
      boxUsed[boxIndex(r, c)] &= ~bit;
    }

    return false;
  }

  function countBits(n) {
    let count = 0;
    while (n) { count += n & 1; n >>= 1; }
    return count;
  }

  solve();
}
```

## Problem 2 — Valid Sudoku (LeetCode 36) — Verification Without Backtracking

### Problem
Determine if a 9×9 partially filled Sudoku board is valid. Only the filled cells need to be validated (no need to find a solution). A board is valid if no row, column, or 3×3 box contains duplicate digits.

```
Input: (same 9×9 board format, some cells are '.')
Output: true or false
```

### Pattern Recognition
Not backtracking — pure constraint checking. Scan each of the 27 units (9 rows + 9 columns + 9 boxes), verify no digit appears twice. This is the `isValid` logic from the solver, extracted to its full form.

### Key Insight
Three independent sets of checks (rows, columns, boxes), each verifiable with a Set or bitmask in O(9) per unit = O(243) = O(1) for fixed 9×9.

### Solution — Using Sets

```js
function isValidSudoku(board) {
  // Check all 9 rows
  for (let r = 0; r < 9; r++) {
    const seen = new Set();
    for (let c = 0; c < 9; c++) {
      const val = board[r][c];
      if (val === '.') continue;
      if (seen.has(val)) return false; // duplicate in row
      seen.add(val);
    }
  }

  // Check all 9 columns
  for (let c = 0; c < 9; c++) {
    const seen = new Set();
    for (let r = 0; r < 9; r++) {
      const val = board[r][c];
      if (val === '.') continue;
      if (seen.has(val)) return false;
      seen.add(val);
    }
  }

  // Check all 9 boxes
  for (let boxRow = 0; boxRow < 3; boxRow++) {
    for (let boxCol = 0; boxCol < 3; boxCol++) {
      const seen = new Set();
      for (let r = boxRow * 3; r < boxRow * 3 + 3; r++) {
        for (let c = boxCol * 3; c < boxCol * 3 + 3; c++) {
          const val = board[r][c];
          if (val === '.') continue;
          if (seen.has(val)) return false;
          seen.add(val);
        }
      }
    }
  }

  return true;
}
```

## Problem 3 — N-Queens (LeetCode 51) — Backtracking Generalization

### Problem
Place n non-attacking queens on an n×n chessboard. Return all distinct solutions. Each solution is a list of strings representing the board.

```
Input:  n=4
Output: [
  [".Q..","...Q","Q...","..Q."],
  ["..Q.","Q...","...Q",".Q.."]
]
```

### Pattern Recognition
Backtracking with one queen per row (structural simplification). Choice = column for queen in current row. Constraint = no conflict with queens in previous rows (same column or diagonal). Goal = all n rows filled.

### Key Insight
Since exactly one queen goes per row (one queen per column impossible to violate this), we can recurse row by row (row = depth of recursion). At each row, try each column; check only previously placed queens (no need to check below current row — not yet placed). This prunes immediately when any conflict is found.

### Solution

```js
function solveNQueens(n) {
  const results = [];
  const queens = new Array(n).fill(-1); // queens[r] = column of queen in row r

  function backtrack(row) {
    // GOAL: all n rows filled
    if (row === n) {
      results.push(buildBoard(queens, n));
      return;
    }

    // CHOICE: try each column for queen in this row
    for (let col = 0; col < n; col++) {
      // CONSTRAINT: no conflict with previously placed queens
      if (isQueenSafe(queens, row, col)) {
        queens[row] = col;        // place queen
        backtrack(row + 1);       // recurse to next row
        queens[row] = -1;         // undo (backtrack)
      }
    }
  }

  function isQueenSafe(queens, row, col) {
    for (let r = 0; r < row; r++) {
      if (queens[r] === col) return false;             // same column
      if (Math.abs(queens[r] - col) === row - r) return false; // diagonal
    }
    return true;
  }

  function buildBoard(queens, n) {
    return queens.map(col =>
      '.'.repeat(col) + 'Q' + '.'.repeat(n - col - 1)
    );
  }

  backtrack(0);
  return results;
}
```

### Optimized Solution — O(1) Conflict Check with Sets

```js
function solveNQueensOpt(n) {
  const results = [];
  const queens = new Array(n).fill(-1);

  // Track columns and diagonals in use
  const cols = new Set();
  const diag1 = new Set(); // row - col (same for cells on the same '\' diagonal)
  const diag2 = new Set(); // row + col (same for cells on the same '/' diagonal)

  function backtrack(row) {
    if (row === n) {
      results.push(queens.map(col =>
        '.'.repeat(col) + 'Q' + '.'.repeat(n - col - 1)
      ));
      return;
    }

    for (let col = 0; col < n; col++) {
      if (cols.has(col) || diag1.has(row - col) || diag2.has(row + col)) {
        continue; // conflict — skip this column
      }

      // place queen
      queens[row] = col;
      cols.add(col);
      diag1.add(row - col);
      diag2.add(row + col);

      backtrack(row + 1);

      // undo
      queens[row] = -1;
      cols.delete(col);
      diag1.delete(row - col);
      diag2.delete(row + col);
    }
  }

  backtrack(0);
  return results;
}
```

## Problem 4 — Combination Sum (LeetCode 39) — Backtracking with Repetition

### Problem
Given an array of distinct positive integers `candidates` and a target integer, return all unique combinations that sum to target. Numbers may be used unlimited times.

```
Input:  candidates=[2,3,6,7], target=7
Output: [[2,2,3],[7]]

Input:  candidates=[2,3,5], target=8
Output: [[2,2,2,2],[2,3,3],[3,5]]
```

### Pattern Recognition
Backtracking with unbounded choice — at each step, choose any candidate ≥ the previous choice (to avoid duplicates) and recurse with reduced target. Constraint: sum doesn't exceed target. Goal: sum equals target exactly.

### Key Insight
Start the candidate search from index `start` (not from 0) to avoid generating permutations of the same combination. Candidates are sorted so we can prune early: if `candidates[i] > remaining`, all subsequent candidates are also too large.

### Solution

```js
function combinationSum(candidates, target) {
  const results = [];
  candidates.sort((a, b) => a - b); // sort for early pruning

  function backtrack(start, remaining, current) {
    // GOAL: remaining reduced to exactly 0
    if (remaining === 0) {
      results.push([...current]); // record this combination
      return;
    }

    // CHOICE: try each candidate from index 'start' onward
    for (let i = start; i < candidates.length; i++) {
      // CONSTRAINT + PRUNING: candidate exceeds remaining sum
      if (candidates[i] > remaining) break; // sorted → all further are larger too

      current.push(candidates[i]);          // make choice
      backtrack(i, remaining - candidates[i], current); // same i: allow reuse
      current.pop();                         // undo choice (backtrack)
    }
  }

  backtrack(0, target, []);
  return results;
}
```

## Problem 5 — Word Search (LeetCode 79) — Grid Backtracking

### Problem
Given an m×n character grid and a word, return true if the word exists as a path through adjacent cells (4-directional), where each cell may only be used once.

```
Input:
board=[["A","B","C","E"],
       ["S","F","C","S"],
       ["A","D","E","E"]]
word="ABCCED"   → true  (A→B→C→C→E→D)
word="SEE"      → true  (S→E→E)
word="ABCB"     → false (can't reuse B)
```

### Pattern Recognition
Grid backtracking — explore paths through the grid. Choice = which adjacent cell to visit next. Constraint = character must match next word character AND cell must not be visited in the current path. Goal = all word characters matched.

### Key Insight
Mark visited cells in-place (replace with `'#'`) to avoid reuse in the current path. Restore after backtracking. This avoids a separate visited array and makes the "used in current path" state implicit in the board.

### Solution

```js
function exist(board, word) {
  const rows = board.length, cols = board[0].length;
  const dirs = [[1,0],[-1,0],[0,1],[0,-1]];

  function backtrack(r, c, idx) {
    // GOAL: matched all characters
    if (idx === word.length) return true;

    // bounds check and character match (CONSTRAINT)
    if (r < 0 || r >= rows || c < 0 || c >= cols) return false;
    if (board[r][c] !== word[idx]) return false;
    if (board[r][c] === '#') return false; // already visited in current path

    // CHOICE: mark current cell as visited (in-place)
    const temp = board[r][c];
    board[r][c] = '#'; // mark visited

    // try all 4 directions
    const found = dirs.some(([dr, dc]) => backtrack(r + dr, c + dc, idx + 1));

    // BACKTRACK: restore cell
    board[r][c] = temp;

    return found;
  }

  // try starting from every cell
  for (let r = 0; r < rows; r++) {
    for (let c = 0; c < cols; c++) {
      if (backtrack(r, c, 0)) return true;
    }
  }

  return false;
}
```

- "What if cells can be revisited?" → Remove the `'#'` marking; add a path length bound to prevent infinite loops on cyclic paths.

## Problem 6 — Generate Parentheses (LeetCode 22) — Backtracking with Invariant

### Problem
Given n pairs of parentheses, generate all combinations of well-formed parentheses.

```
Input:  n=3
Output: ["((()))","(()())","(())()","()(())","()()()"]
```

### Pattern Recognition
Backtracking with two constraints maintaining an invariant: `open < n` (can add `(` only if fewer than n open brackets used) and `close < open` (can add `)` only if there's an unmatched `(`). The goal is a string of length 2n.

### Key Insight
This is backtracking where the "constraint" is the invariant `close ≤ open ≤ n`. It prunes two kinds of invalid prefixes: too many `(` (open = n, can't add more), and too many `)` (close = open, adding `)` would create an unmatched closer). The base case (string of length 2n) is always valid by construction — no need to verify at the end.

### Solution

```js
function generateParenthesis(n) {
  const results = [];

  function backtrack(current, open, close) {
    // GOAL: string of length 2n
    if (current.length === 2 * n) {
      results.push(current);
      return;
    }

    // CHOICE 1: add '(' if we haven't used all n open brackets
    if (open < n) {
      backtrack(current + '(', open + 1, close);
    }

    // CHOICE 2: add ')' if there's an unmatched '('
    if (close < open) {
      backtrack(current + ')', open, close + 1);
    }
    // No explicit backtrack needed: string concatenation creates new string
    // (immutable — no in-place mutation to undo)
  }

  backtrack('', 0, 0);
  return results;
}
```

### Complexity
- Time: O(4^n / sqrt(n)) — Catalan number of valid strings × O(n) to build each.
- Space: O(n) recursion depth. Output: O(Catalan(n) × 2n) for all strings.

### Edge Cases
- n=0: base case immediately → record '' (empty string). Problem typically guarantees n ≥ 1.
- n=1: only "()" → one result.

### Follow-up Questions
- "Count only (not enumerate)?" → The n-th Catalan number: `C(n) = (2n choose n) / (n+1)`.
- "Generate in lexicographic order?" → The current code already generates in lexicographic order: '(' < ')' in ASCII, so trying '(' before ')' ensures lexicographic order.

## Quick Reference — Backtracking Template

```
Three Questions to Ask First:
  1. CHOICE:     What decision is made at each step?
  2. CONSTRAINT: What makes a partial solution invalid? (triggers backtrack)
  3. GOAL:       What constitutes a complete valid solution? (base case)

Universal Template:
  function backtrack(state):
    if goal(state): record/return solution
    for each choice c in valid_choices(state):
      if satisfies_constraint(state, c):
        apply(state, c)          ← make choice
        backtrack(new_state)     ← recurse
        undo(state, c)           ← BACKTRACK (critical)

Problem → Choice / Constraint / Goal:
  Sudoku:      digit 1-9 / row+col+box uniqueness / no empty cells
  N-Queens:    column in row / no col/diagonal conflict / n queens placed
  Word Search: adjacent cell / char match + not visited / all chars matched
  Comb Sum:    candidate ≥ previous / sum ≤ target / sum = target exactly
  Parentheses: '(' or ')' / open≤n, close≤open / length = 2n

Key Implementation Details:
  □ Always undo (backtrack) after recursion returns — symmetry of apply/undo
  □ Mark visited in-place for grid problems; restore after recursion
  □ Pass start index to avoid permutations (combination problems)
  □ Sort candidates for early pruning (break when candidate > remaining)
  □ Return false (not just return) when no choice works — signals caller to backtrack
```

## Common Bugs Checklist

Before finalizing any backtracking solution, verify:

1. **The undo step is always executed** — `board[row][col] = '.'` (Sudoku) or `current.pop()` (combination) must happen after the recursive call returns, whether it succeeded or failed. Missing the undo causes the state to accumulate incorrect choices that block future valid placements.

2. **Return false after all choices fail** — in Sudoku's `solve()`, after the `for (digit)` loop without finding a valid digit, `return false` must be reached. Missing this return causes the function to fall through to the row/column scanning loop and continue scanning — finding a different empty cell and incorrectly trying to fill it, producing wrong results.

3. **Base case is correct and reachable** — for Sudoku: the base case is "no empty cell found" (all 81 cells filled). This is only reached if `solve()` successfully fills every cell. If the scanning loop skips a cell incorrectly (e.g., the empty cell marker doesn't match), the base case is reached prematurely with an incomplete board.

4. **`isValid` checks the correct cell being filled, not the current value** — when checking `board[row][i] === ch`, `board[row][col]` is currently `'.'` (just cleared before the check). Don't confuse checking for the digit `ch` vs checking the existing value. The cell being filled is empty; the check scans other cells in the same unit.

5. **Box index formula** — `boxRow = 3 * Math.floor(row / 3) + Math.floor(i / 3)`, `boxCol = 3 * Math.floor(col / 3) + (i % 3)`. The most common error: using `row % 3` instead of `Math.floor(row / 3)` for the top-left box row. Verify with (row=4, col=5): box top-left should be (3,3), not (1,2).

6. **Visited marking and restoration in grid problems** — when using in-place marking (`board[r][c] = '#'`), the restore (`board[r][c] = temp`) must happen even if the recursion succeeds (if you're finding all solutions) or only on failure (if finding one solution and returning early). For early-return (`return found`), the `dirs.some(...)` pattern handles this: `found` is true → function returns before the restore line. Wrap restore in a `finally` block or ensure it's always reached.
