# DSA: Valid Parentheses & Variants — Theory, Interview Q&A & Practical Problems

---

## Part 1 — Theory & Interview Q&A

---

### Section 1: Fundamentals

**Q1. What is the "valid parentheses" problem class?**
A: The valid parentheses problem class covers any problem involving matching, balancing, or generating bracket-like structures — where every opening symbol has a corresponding, correctly ordered closing symbol. The canonical problem checks whether a string of `()[]{}` characters is valid. The broader class includes: generating all valid combinations, finding the minimum removals to make a string valid, counting minimum additions, scoring bracket expressions, and handling wildcards that can substitute for any bracket. The unifying data structure across all variants is the **stack** — it mirrors the LIFO (last-in-first-out) nature of bracket nesting.

**Q2. Why is a stack the natural data structure for parentheses problems?**
A: Because bracket nesting is inherently LIFO — the most recently opened bracket must be the first to be closed. When you see `([{`, the `{` was opened last so it must close first, then `[`, then `(`. A stack naturally tracks "what is the most recently opened, unclosed bracket" at every point in the traversal. Pushing on open brackets and popping on close brackets means the stack top always holds the innermost unmatched open bracket — exactly the one that must close next for the string to be valid.

**Q3. What are the three conditions that make a parentheses string valid?**
A:
1. **Matching type**: every closing bracket matches the type of the most recently opened unmatched bracket (e.g., `]` must match `[`).
2. **Correct order**: no closing bracket appears before its corresponding opener.
3. **Complete pairing**: every opener has a closer — the stack is empty at the end.

A string fails if: (a) a closing bracket doesn't match the stack top, (b) a closing bracket arrives when the stack is empty (no unmatched opener), or (c) the string ends with the stack non-empty (unmatched openers remain).

**Q4. What is the time and space complexity of the basic valid parentheses check?**
A: O(n) time — each character is visited exactly once, and each push/pop on the stack is O(1). O(n) space — in the worst case all characters are openers and all get pushed onto the stack (e.g., `(((((`). In practice the stack holds at most n/2 elements.

**Q5. Can you solve valid parentheses without a stack — purely with a counter?**
A: Only for the single-bracket type case (only `(` and `)`). Track a counter: increment on `(`, decrement on `)`. The string is valid if the counter never goes negative during the traversal and equals zero at the end. This works because with one bracket type there's no "type mismatch" to check — only count imbalance. For multiple bracket types (`()[]{}`) a counter is insufficient because `([)]` has balanced counts but is invalid — you need the stack to track type matching.

### Section 2: Core Algorithm Deep Dive

**Q6. Walk through the standard stack-based algorithm step by step.**
A: Build a map of closing → opening bracket pairs. Traverse the string character by character:
- **Open bracket** (`(`, `[`, `{`): push onto the stack.
- **Close bracket** (`)`, `]`, `}`): check if the stack is non-empty and the top equals the expected opener. If yes, pop. If no (stack empty or type mismatch) → invalid.
- **End of string**: valid if and only if the stack is empty.

```js
function isValid(s) {
  const stack = [];
  const match = { ')': '(', ']': '[', '}': '{' };

  for (const ch of s) {
    if (ch === '(' || ch === '[' || ch === '{') {
      stack.push(ch);                  // open bracket — push
    } else {
      // close bracket — must match top of stack
      if (stack.length === 0 || stack[stack.length - 1] !== match[ch]) {
        return false;                  // mismatch or empty stack
      }
      stack.pop();
    }
  }

  return stack.length === 0;           // valid only if all openers matched
}
```

**Q7. What is the "push the expected closer" optimization, and when is it useful?**
A: Instead of pushing the opening bracket and checking against a map on close, push the *expected closing bracket* when you see an opener. On a close bracket, simply check if it matches the stack top — no map lookup needed at close time:

```js
function isValidOptimized(s) {
  const stack = [];

  for (const ch of s) {
    if (ch === '(') stack.push(')');
    else if (ch === '[') stack.push(']');
    else if (ch === '{') stack.push('}');
    else {
      // close bracket — must equal the expected closer on top
      if (stack.pop() !== ch) return false;
    }
  }

  return stack.length === 0;
}
```

This is marginally cleaner — the comparison happens at one site instead of two, and there's no map object to maintain. The trade-off: you're storing the expected closer rather than the actual opener, which matters if you need to reconstruct the original bracket sequence (rare in interviews).

**Q8. What are the exact failure modes to check, and which bugs miss them?**
A: Three failure modes, each with a corresponding bug if not handled:

| Failure Mode | Example | Bug if Missed |
|---|---|---|
| Close with empty stack | `)(` | Calling `stack.pop()` on empty returns `undefined` in JS, which silently passes the `!== ch` check — you need an explicit empty-stack guard |
| Type mismatch at close | `([)]` | Only checking non-empty without type check lets mismatched closes pass |
| Unclosed openers remain | `(([` | Forgetting `stack.length === 0` at the end returns true when openers are unmatched |

The most common interview bug is the first one — forgetting that `stack.pop()` on an empty JS array returns `undefined` rather than throwing, so `undefined !== ')'` is `true` which accidentally produces the correct `false` result — but only by coincidence. In other languages (Python, Java), this throws an exception. Always guard explicitly.

**Q9. How does the problem change when the input can contain non-bracket characters?**
A: Simply ignore non-bracket characters — skip them and continue. This matters for problems like "validate expressions with operators" where parentheses are embedded in a larger expression. The stack only cares about bracket characters; everything else passes through without modifying state. Add an early `continue` (or restructure the conditionals) to skip unknown characters.

### Section 3: Minimum Removals & Additions

**Q10. What is the "minimum number of parentheses to remove to make valid" problem, and what is the approach?**
A: Given a string of `(` and `)` (single type), find the minimum number of characters to remove to make it valid. Two-pass or one-pass approach using counters:

One-pass with two counters — `open` (unmatched openers seen so far) and `close` (unmatched closers seen so far that can never be matched because no opener preceded them):
- `(` → `open++`
- `)` with `open > 0` → `open--` (this `)` matches an earlier `(`)
- `)` with `open === 0` → `close++` (this `)` has no opener — must be removed)

At the end, `open` unmatched openers also must be removed. Answer: `open + close`.

```js
function minRemoveToMakeValid(s) {
  let open = 0, close = 0;
  for (const ch of s) {
    if (ch === '(') {
      open++;
    } else if (ch === ')') {
      if (open > 0) open--; // matches an earlier '('
      else close++;         // unmatched ')' — must remove
    }
  }
  return open + close; // unmatched '(' + unmatched ')'
}
```

**Q11. What if you need to return the actual string after minimum removals (not just the count)?**
A: Use a stack of indices (not just characters). Push the index of every `(`. On `)`, if the stack is non-empty, pop (match found). If stack is empty, mark this `)` index for removal. After the traversal, all indices remaining in the stack are unmatched `(` — mark them for removal too. Finally, rebuild the string skipping marked indices:

```js
function minRemoveToMakeValidString(s) {
  const arr = s.split('');
  const stack = []; // indices of unmatched '('
  const toRemove = new Set();

  for (let i = 0; i < arr.length; i++) {
    if (arr[i] === '(') {
      stack.push(i);             // track index of opener
    } else if (arr[i] === ')') {
      if (stack.length > 0) {
        stack.pop();             // matched — remove from stack
      } else {
        toRemove.add(i);         // unmatched ')' — mark for removal
      }
    }
  }

  // remaining stack indices are unmatched '('
  for (const i of stack) toRemove.add(i);

  return arr.filter((_, i) => !toRemove.has(i)).join('');
}
```

**Q12. What is the "minimum additions to make valid" problem?**
A: Given a string of `(` and `)`, find the minimum number of brackets to *add* (not remove) to make it valid. The answer is identical in structure: count unmatched `(` and unmatched `)`. Unmatched `(` need a `)` added after them; unmatched `)` need a `(` added before them. The same counter logic from Q10 applies: `open + close` where `open` = unmatched openers at the end, `close` = unmatched closers encountered during the pass.

The insight: removing a bracket and adding its counterpart are duals of the same problem. The minimum number of characters to add equals the number of "gaps" in the matching — which is the same as the count of unmatched characters in the two-counter pass.

**Q13. How does the problem extend to multiple bracket types for minimum removals?**
A: Use a stack (not just counters) to track unmatched characters with their indices. The same push-on-open, pop-on-match logic applies. At the end, all indices in the stack represent unmatched brackets (of any type) that must be removed. Count or reconstruct as needed.

### Section 4: Generate & Count Valid Combinations

**Q14. How do you generate all valid combinations of n pairs of parentheses?**
A: Backtracking with two constraints: `open` count (openers placed so far) and `close` count (closers placed so far). At each step:
- Add `(` if `open < n` (more openers available).
- Add `)` if `close < open` (can only close what's been opened).
- When `open === close === n`, record the combination.

```js
function generateParentheses(n) {
  const result = [];

  function backtrack(current, open, close) {
    if (current.length === 2 * n) {
      result.push(current);
      return;
    }
    if (open < n) backtrack(current + '(', open + 1, close);
    if (close < open) backtrack(current + ')', open, close + 1);
  }

  backtrack('', 0, 0);
  return result;
}
```

The constraint `close < open` is the key invariant — it ensures `)` is never placed before a matching `(`, which would create an invalid prefix. This pruning eliminates all invalid paths early, making the recursion visit only valid combinations.

**Q15. How many valid combinations of n pairs exist, and what is the time complexity of generation?**
A: The count is the **n-th Catalan number**: `C(n) = (2n choose n) / (n+1)`. For n=3, C(3) = 5; for n=4, C(4) = 14; for n=10, C(10) = 16796. Catalan numbers grow roughly as `4^n / (n^(3/2) * sqrt(π))`.

Time complexity of generation: O(4^n / sqrt(n)) — proportional to the number of valid strings (each requires O(2n) work to build). Space: O(n) recursion stack depth plus O(4^n / sqrt(n)) for the output.

**Q16. What is the Catalan number, and where else does it appear?**
A: The n-th Catalan number counts the number of valid parenthesizations of n pairs. It also counts: the number of distinct binary search trees with n nodes, the number of triangulations of a convex polygon with n+2 sides, and the number of monotonic lattice paths from (0,0) to (n,n) that don't cross the diagonal. At the 5 YOE level, knowing this connection signals depth — you don't need to derive it, but naming it and connecting it to other problems impresses.

### Section 5: Wildcard & Advanced Variants

**Q17. How do you handle wildcard characters (`*`) that can represent `(`, `)`, or empty?**
A: The wildcard problem ("valid parenthesis string" with `*`) requires tracking a *range* of possible open bracket counts rather than a single count. Maintain `lo` (minimum possible unmatched openers) and `hi` (maximum possible unmatched openers):
- `(` → `lo++`, `hi++`
- `)` → `lo--`, `hi--`
- `*` → `lo--` (treat as `)` in worst case), `hi++` (treat as `(` in best case)
- If `hi < 0` at any point → impossible to balance → return false.
- Clamp `lo = Math.max(lo, 0)` — it can't go negative (can't have negative unmatched openers in reality).
- At the end: valid if `lo === 0` (minimum unmatched openers can reach 0).

```js
function checkValidString(s) {
  let lo = 0, hi = 0; // range of possible unmatched open count

  for (const ch of s) {
    if (ch === '(') { lo++; hi++; }
    else if (ch === ')') { lo--; hi--; }
    else { lo--; hi++; } // '*' — pessimistic and optimistic

    if (hi < 0) return false;       // even best case can't balance
    lo = Math.max(lo, 0);           // can't have negative unmatched
  }

  return lo === 0; // can we achieve 0 unmatched openers?
}
```

**Q18. Why does the range `[lo, hi]` approach work for wildcards?**
A: At any point, `lo` represents the minimum number of unmatched openers if every `*` is treated as `)` or empty (reducing openers), and `hi` represents the maximum if every `*` is treated as `(` (increasing openers). The actual count of unmatched openers, under any valid assignment of wildcards, lies somewhere in this range. If `hi < 0`, even the most optimistic assignment can't avoid a surplus of closers — invalid. If `lo > 0` at the end, even the most aggressive use of `*` as `)` leaves unmatched openers — invalid. If `lo === 0` is achievable, there exists a valid assignment.

**Q19. What is the "score of parentheses" problem, and how does a stack solve it?**
A: Given a valid parentheses string, compute its score: `()` scores 1, `(A)` scores `2 * score(A)`, `AB` scores `score(A) + score(B)`. Use a stack of integers tracking the "current depth score":
- Push `0` onto the stack at start (sentinel).
- `(` → push `0` (open a new depth level).
- `)` → pop the top value `v`:
  - If `v === 0`: the innermost pair `()` scores 1 → add 1 to the new top.
  - If `v > 0`: the inner content scored `v` → add `2 * v` to the new top.
- Final answer: stack top (the sentinel accumulates all scores).

```js
function scoreOfParentheses(s) {
  const stack = [0]; // sentinel — accumulates total score

  for (const ch of s) {
    if (ch === '(') {
      stack.push(0); // new level
    } else {
      const v = stack.pop();
      stack[stack.length - 1] += v === 0 ? 1 : 2 * v;
    }
  }

  return stack[0];
}
```

**Q20. How do you find the longest valid parentheses substring?**
A: Two approaches at O(n):

**Stack approach**: push indices onto the stack. Push `-1` as a sentinel base. On `(`: push the index. On `)`: pop the top. If stack is empty, push the current index as the new base. If stack is non-empty, compute length as `i - stack[stack.length - 1]` and update max:

```js
function longestValidParentheses(s) {
  const stack = [-1]; // sentinel base index
  let maxLen = 0;

  for (let i = 0; i < s.length; i++) {
    if (s[i] === '(') {
      stack.push(i);
    } else {
      stack.pop();
      if (stack.length === 0) {
        stack.push(i); // new base: last unmatched ')'
      } else {
        maxLen = Math.max(maxLen, i - stack[stack.length - 1]);
      }
    }
  }

  return maxLen;
}
```

**Two-pass counter approach** (O(1) space): left-to-right pass counting `(` and `)`. When counts are equal, record length. When `)` count exceeds `(`, reset both. Repeat right-to-left (catches valid strings that left-to-right misses due to unmatched openers). Return the maximum length seen in either pass.

### Section 6: Scenario / Interview-Style Questions

**Q21. "You're given a string that may contain letters, digits, and parentheses. Return the minimum number of parentheses to remove to make it valid. How do you handle non-bracket characters?"**
A: Non-bracket characters are transparent — they don't affect bracket matching. Ignore them during the traversal. Only `(` and `)` (or `{`, `[` for multi-type) affect the stack or counters. Process bracket characters with the standard algorithm; skip everything else with a `continue`. The answer (removal count or reconstructed string) is unaffected by the non-bracket content.

**Q22. "An interviewer asks you to validate a string with only `()`. You give the counter solution. They say 'now extend it to `()[]{}`.' Why does your solution break, and how do you fix it?"**
A: The counter solution tracks balance (a single integer) — it detects imbalance but not type mismatch. `([)]` has counter `0` at the end (balanced count) but is invalid because the brackets are interleaved. Adding more bracket types makes type-ordering essential. The fix: replace the single counter with a stack. Push openers onto the stack; on a closer, verify the stack top is the matching opener — if not, immediately invalid. The stack enforces both balance and ordering.

**Q23. "Design a system that validates code snippets for balanced brackets in real time as the user types. What data structure and algorithm do you use, and what are the performance requirements?"**
A: Real-time (per-keystroke) revalidation of the full string is O(n) per keystroke — O(n²) total for an n-character file, which is too slow for large files. Better design options:

- **Incremental stack state**: maintain the stack state between keystrokes. On insert at position `i`, reprocess from `i` to the end (O(n - i) per keystroke, amortized O(n) for appends at the end which is the common case). For insertions in the middle, O(n) in the worst case but editors accept this for bracket highlighting.
- **Syntax tree / rope**: real editors (VS Code, Neovim) use incremental parsing with syntax trees (tree-sitter) that reparse only the affected region — O(k) where k is the size of the changed region, typically O(1) for single-character edits.

For an interview context, the expected answer is: "for append-only input, maintain the stack state and push/pop on each new character — O(1) per keystroke." Mention that full-document revalidation on every edit is O(n) per edit and sketch the incremental approach as a follow-up.

**Q24. "A colleague proposes solving 'generate all valid parentheses' with dynamic programming instead of backtracking. Is that valid? How would it work?"**
A: Yes — DP is a valid alternative. Let `dp[i]` = list of all valid strings of exactly `i` pairs. Base case: `dp[0] = [""]`. Recurrence: for each `j` from `0` to `i-1`, combine every string in `dp[j]` (inner content) wrapped in `()` with every string in `dp[i-1-j]` (outer suffix): `"(" + inner + ")" + suffix`. Build up to `dp[n]`:

```
dp[0] = [""]
dp[1] = ["()"]
dp[2] = ["(())", "()()"]
dp[3] = ["((()))", "(()())", "(())()", "()(())", "()()()"]
```

This is correct but typically slower in practice than backtracking because it builds and stores all intermediate strings. Backtracking prunes invalid prefixes early; DP builds only valid complete strings but must copy and concatenate strings repeatedly. Both are O(4^n / sqrt(n)) asymptotically — the DP approach has higher constant factors due to string concatenation. Backtracking is preferred in interviews for its simplicity.

## Problem 1 — Valid Parentheses (Multi-Type)

### Problem
Given a string `s` containing only `(`, `)`, `{`, `}`, `[`, `]`, return `true` if the string is valid. A string is valid if every open bracket is closed by the same type of bracket in the correct order.

```
Input:  s = "()"         → true
Input:  s = "()[]{}"     → true
Input:  s = "(]"         → false
Input:  s = "([)]"       → false
Input:  s = "{[]}"       → true
```

### Pattern Recognition
Canonical stack problem. Nesting requires LIFO matching — a stack naturally tracks the most recently opened unmatched bracket.

### Key Insight
Push openers; on closers, the top of the stack must be the matching opener. Three failure conditions: type mismatch, close on empty stack, non-empty stack at end.

### Approach
Map each closer to its expected opener. Traverse: push openers, pop and verify on closers. Return `stack.length === 0` at the end.

### Solution

```js
function isValid(s) {
  const stack = [];
  // map: closer → expected opener
  const match = { ')': '(', ']': '[', '}': '{' };

  for (const ch of s) {
    if (ch === '(' || ch === '[' || ch === '{') {
      stack.push(ch);                            // open — push
    } else {
      // close bracket
      if (stack.length === 0) return false;      // nothing to match
      if (stack[stack.length - 1] !== match[ch]) return false; // type mismatch
      stack.pop();                               // matched — remove
    }
  }

  return stack.length === 0; // all openers must be matched
}
```

### Dry Run

```
s = "([)]"

stack=[], ch='(' → push → stack=['(']
stack=['('], ch='[' → push → stack=['(','[']
stack=['(','['], ch=')' → match[')']='(' → top='[' ≠ '(' → return false ✓


s = "{[]}"

stack=[], ch='{' → push → stack=['{']
stack=['{'], ch='[' → push → stack=['{','[']
stack=['{','['], ch=']' → match[']']='[' → top='[' = '[' → pop → stack=['{']
stack=['{'], ch='}' → match['}]='{' → top='{' = '{' → pop → stack=[]

stack.length===0 → return true ✓
```

### Complexity
- Time: O(n) — one pass, O(1) per character.
- Space: O(n) — stack holds at most n/2 openers.

### Edge Cases
- Empty string `""` → stack stays empty → return true (valid by convention).
- Single character `"("` → push, never popped → stack non-empty → false.
- Single character `")"` → close on empty stack → false.
- All openers `"((("` → stack has 3 entries → false.
- All closers `")))"` → first close on empty stack → false.
- Alternating valid `"()()()"` → stack empties after each pair → true.

### Follow-up Questions
- "Handle non-bracket characters?" → Add an `else` branch that does nothing (skip unknown characters).
- "Return which bracket is unmatched?" → Store `{char, index}` objects in the stack; after traversal, the stack top's index is the first unmatched opener.
- "Make it work for custom bracket pairs defined at runtime?" → Replace the hardcoded map with a parameter `Map<string, string>` of closer → opener pairs.

## Problem 2 — Minimum Remove to Make Valid Parentheses

### Problem
Given a string `s` of lowercase letters and parentheses `(` and `)`, remove the minimum number of parentheses to make the string valid. Return any valid result.

```
Input:  s = "lee(t(c)o)de)"   → "lee(t(c)o)de"
Input:  s = "a)b(c)d"         → "ab(c)d"
Input:  s = "))(("            → ""
Input:  s = "(a(b(c)d)"       → "a(b(c)d)"
```

### Pattern Recognition
Stack of indices variant — need to identify *which* brackets to remove, not just count them. Tracking indices allows reconstruction.

### Key Insight
A stack of indices of unmatched `(` brackets lets us find exactly which openers are unmatched at the end. Unmatched `)` are identified in-place (empty stack when `)` encountered). Both sets must be removed.

### Approach
1. Walk left to right. On `(`: push its index. On `)`: if stack non-empty, pop (matched). Else mark this `)` index for removal.
2. After traversal, all indices remaining in the stack are unmatched `(` — also mark for removal.
3. Rebuild string filtering out marked indices.

### Solution

```js
function minRemoveToMakeValid(s) {
  const arr = s.split('');
  const stack = [];       // indices of unmatched '('
  const remove = new Set();

  for (let i = 0; i < arr.length; i++) {
    if (arr[i] === '(') {
      stack.push(i);              // push index of opener
    } else if (arr[i] === ')') {
      if (stack.length > 0) {
        stack.pop();              // matched — discard the opener index
      } else {
        remove.add(i);            // unmatched ')' — mark for removal
      }
    }
    // letters: skip
  }

  // all remaining indices in stack are unmatched '('
  for (const i of stack) remove.add(i);

  // rebuild string without removed indices
  return arr.filter((_, i) => !remove.has(i)).join('');
}
```

### Dry Run

```
s = "a)b(c)d"
arr = ['a',')',b','(','c',')','d']

i=0 'a': skip
i=1 ')': stack empty → remove.add(1) → remove={1}
i=2 'b': skip
i=3 '(': stack.push(3) → stack=[3]
i=4 'c': skip
i=5 ')': stack=[3] non-empty → stack.pop() → stack=[] (index 3 matched with index 5)
i=6 'd': skip

stack empty → no unmatched '('
remove = {1}

filter: skip index 1 → "ab(c)d" ✓


s = "))(("
arr = [')',')','(','(']

i=0 ')': stack empty → remove.add(0)
i=1 ')': stack empty → remove.add(1)
i=2 '(': stack.push(2)
i=3 '(': stack.push(3)

stack=[2,3] → remove.add(2), remove.add(3)
remove={0,1,2,3}

filter: all removed → "" ✓
```

### Complexity
- Time: O(n) — one pass + one filter pass.
- Space: O(n) — stack and remove set hold at most n indices.

### Edge Cases
- No parentheses → no removals → return original string.
- All characters removable `"))(("` → return empty string.
- Already valid → stack and remove set stay empty → return original.
- `"()"` → stack push then pop → both empty → return `"()"`.
- Nested `"((("` → all pushed, none popped → all marked for removal → return `""`.

### Follow-up Questions
- "Return the count of removals only (not the string)?" → Count elements in the remove set: `stack.length + unmatched_close_count`. No set needed — just two counters (see Q10 in Part 1).
- "Handle multiple bracket types?" → Generalize the stack to hold `{char, index}` pairs. Match by type; unmatched of any type get collected.
- "What if you can also insert brackets (not just remove)?" → Different problem — minimum additions are counted by the same counters but no reconstruction is required.

## Problem 3 — Generate Parentheses

### Problem
Given `n` pairs of parentheses, generate all combinations of well-formed parentheses strings.

```
Input:  n = 3
Output: ["((()))", "(()())", "(())()", "()(())", "()()()"]

Input:  n = 1
Output: ["()"]
```

### Pattern Recognition
Backtracking — build strings character by character, pruning invalid prefixes early using the two invariants: `open < n` and `close < open`.

### Key Insight
At any prefix position, the placement is valid if: there are openers left to place (`open < n`), or there are unclosed openers that can be closed (`close < open`). These two constraints together generate exactly the set of valid parentheses strings with zero wasted computation.

### Approach
Recursive backtracking: at each step, try adding `(` (if `open < n`) or `)` (if `close < open`). When the string reaches length `2n`, it is a valid complete combination — add to result.

### Solution

```js
function generateParenthesis(n) {
  const result = [];

  function backtrack(current, open, close) {
    // base case: full length string — always valid by construction
    if (current.length === 2 * n) {
      result.push(current);
      return;
    }

    // can we add an opener?
    if (open < n) {
      backtrack(current + '(', open + 1, close);
    }

    // can we add a closer?
    // only if there's an unmatched opener (close < open)
    if (close < open) {
      backtrack(current + ')', open, close + 1);
    }
  }

  backtrack('', 0, 0);
  return result;
}
```

### Dry Run

```

backtrack('', 0, 0)
  open<2 → backtrack('(', 1, 0)
    open<2 → backtrack('((', 2, 0)
      close<open → backtrack('(()', 2, 1)
        close<open → backtrack('(())', 2, 2)
          length=4=2n → result.push('(())') ✓
    close<open → backtrack('()', 1, 1)
      open<2 → backtrack('()(', 2, 1)
        close<open → backtrack('()()', 2, 2)
          length=4 → result.push('()()') ✓

Result: ["(())", "()()"] ✓
```

### Complexity
- Time: O(4^n / sqrt(n)) — Catalan number of strings × O(n) to build each.
- Space: O(n) recursion depth + O(4^n / sqrt(n)) output.

### Edge Cases
- `n = 0` → `backtrack('', 0, 0)`: `current.length = 0 = 2*0` → immediately push `""`. Result: `[""]`. (Some problems define n=0 as returning empty array — clarify with interviewer.)
- `n = 1` → only `"()"` — one valid string.
- Large n (e.g., n=8): 1430 strings — backtracking handles this without issue.

### Follow-up Questions
- "Count the number of valid strings without generating them?" → Return the n-th Catalan number: `(2n choose n) / (n+1)`.
- "Generate in lexicographic order?" → The current recursion (try `(` before `)` at each step) already produces lexicographically sorted output.
- "DP approach?" → `dp[i]` = all strings with i pairs; build from `dp[0]` up using the recurrence described in Q24 of Part 1.

## Problem 4 — Longest Valid Parentheses

### Problem
Given a string containing only `(` and `)`, return the length of the longest valid (well-formed) parentheses substring.

```
Input:  s = "(()"        → 2
Input:  s = ")()())"      → 4
Input:  s = ""            → 0
Input:  s = "()(())"      → 6
```

### Pattern Recognition
Stack of indices — track the "base" (last unmatched `)` position) alongside open brackets. Every time a match is made, the valid substring length is `currentIndex - stackTop`. This is a non-obvious extension of the basic parentheses stack.

### Key Insight
The stack always holds the index of the last "barrier" — either the index of the last unmatched `)` (which resets the base) or the index of an unmatched `(`. When a `)` is matched, the valid substring extends from the current index back to the index below the now-matched `(` on the stack (or from the sentinel at the bottom if the stack only had the sentinel).

### Approach
Push `-1` as a sentinel base index. On `(`: push its index. On `)`: pop the top. If stack is now empty, push current index as the new base (this `)` is unmatched — new "floor"). If stack is non-empty, compute `i - stack[top]` as the current valid length and update max.

### Solution

```js
function longestValidParentheses(s) {
  const stack = [-1]; // sentinel: base index for length calculation
  let maxLen = 0;

  for (let i = 0; i < s.length; i++) {
    if (s[i] === '(') {
      stack.push(i);    // push index of opener
    } else {
      stack.pop();      // pop: either matches a '(' or pops the sentinel

      if (stack.length === 0) {
        // no base left — this ')' is unmatched, becomes new base
        stack.push(i);
      } else {
        // stack top is the last unmatched index
        // valid substring runs from stack.top+1 to i
        maxLen = Math.max(maxLen, i - stack[stack.length - 1]);
      }
    }
  }

  return maxLen;
}
```

### Dry Run

```
s = ")()())"
     0 1 2 3 4 5

stack=[-1], maxLen=0

i=0 ')': pop(-1) → stack=[] → empty → push(0) → stack=[0]
i=1 '(': push(1) → stack=[0,1]
i=2 ')': pop(1) → stack=[0] → non-empty → len=2-0=2 → maxLen=2
i=3 '(': push(3) → stack=[0,3]
i=4 ')': pop(3) → stack=[0] → non-empty → len=4-0=4 → maxLen=4
i=5 ')': pop(0) → stack=[] → empty → push(5) → stack=[5]

Return maxLen = 4 ✓


s = "()(())"
     0 1 2 3 4 5

stack=[-1], maxLen=0

i=0 '(': push(0) → stack=[-1,0]
i=1 ')': pop(0) → stack=[-1] → non-empty → len=1-(-1)=2 → maxLen=2
i=2 '(': push(2) → stack=[-1,2]
i=3 '(': push(3) → stack=[-1,2,3]
i=4 ')': pop(3) → stack=[-1,2] → non-empty → len=4-2=2 → maxLen=2
i=5 ')': pop(2) → stack=[-1] → non-empty → len=5-(-1)=6 → maxLen=6

Return maxLen = 6 ✓
```

### Complexity
- Time: O(n) — one pass, each index pushed and popped at most once.
- Space: O(n) — stack holds at most n indices.

### Edge Cases
- Empty string → loop never runs → return 0.
- All `(` → stack grows to n; never popped by `)` → maxLen stays 0.
- All `)` → each pops the sentinel, then pushes itself as new base → maxLen stays 0.
- Single valid pair `"()"` → push 0, pop on 1, len = 1-(-1) = 2. Correct.
- Entire string valid `"(())"` → at `i=3`: stack=[-1], len = 3-(-1) = 4. Correct.

### Follow-up Questions
- "O(1) space solution?" → Two-pass counter approach: left-to-right counting `(` as +1 and `)` as -1; when counts equal, record length; when `)` count exceeds, reset. Repeat right-to-left. Return max length seen.
- "Return the actual substring?" → Track the `start` index: `start = stack[stack.length-1] + 1` when updating maxLen. Store `bestStart` and `bestLen`.
- "What about `[]` and `{}` too?" → Stack of indices approach still works — push index of any opener; on closer, pop and verify type match. Unmatched (type mismatch or empty pop) becomes the new base.

## Problem 5 — Valid Parenthesis String (With Wildcards)

### Problem
Given a string `s` containing `(`, `)`, and `*` (where `*` can be `(`, `)`, or empty string), return `true` if it can be valid.

```
Input:  s = "()"     → true
Input:  s = "(*)"    → true
Input:  s = "(*))"   → true
Input:  s = "*(("    → false
Input:  s = "(**))"  → false  — wait: *=empty, *=empty → "()" valid? No: "()))" invalid. *="(", *=")" → "(()))" invalid. *="(", *=empty → "(())" then ")" → 5 chars "(())" + ")" → "(())" is valid, but original is "((**))" which is... let's use a cleaner example.
Input:  s = "(*)"    → true  (* can be ")" → "()" valid; or * empty → "()" valid)
Input:  s = "((*)"   → false (can't balance no matter what * becomes)
```

### Pattern Recognition
Wildcard variant — exact count tracking fails because `*` creates ambiguity. Track a range `[lo, hi]` of possible unmatched opener counts.

### Key Insight
`lo` = minimum possible unmatched openers (treat `*` pessimistically as `)` or empty). `hi` = maximum possible unmatched openers (treat `*` optimistically as `(`). The actual unmatched count is somewhere in `[lo, hi]`. If `hi < 0` → impossible. Clamp `lo = max(lo, 0)`. Valid if `lo === 0` at end.

### Approach
Maintain `lo` and `hi`. Update per character: `(` increments both; `)` decrements both; `*` decrements `lo` and increments `hi`. Short-circuit if `hi < 0`. Clamp `lo`. Return `lo === 0`.

### Solution

```js
function checkValidString(s) {
  let lo = 0; // min possible unmatched '(' (pessimistic about '*')
  let hi = 0; // max possible unmatched '(' (optimistic about '*')

  for (const ch of s) {
    if (ch === '(') {
      lo++;   // definitely adds an unmatched opener
      hi++;
    } else if (ch === ')') {
      lo--;   // pessimistically closes an opener
      hi--;   // optimistically closes an opener
    } else {
      // '*' can be '(' (hi++), ')' (lo--), or '' (no change)
      lo--;   // treat '*' as ')' in worst case
      hi++;   // treat '*' as '(' in best case
    }

    // even optimistically, we can't have negative unmatched openers
    if (hi < 0) return false;

    // can't go below 0 — negative means we've already closed everything
    lo = Math.max(lo, 0);
  }

  // lo === 0 means it's possible to have 0 unmatched openers
  return lo === 0;
}
```

### Dry Run

```
s = "(*)"

ch='(': lo=1, hi=1
ch='*': lo=0, hi=2   (lo--=0, hi++=2; clamp lo=max(0,0)=0)
ch=')': lo=-1, hi=1  → clamp lo=max(-1,0)=0; hi=1≥0 ok

End: lo=0 → return true ✓


s = "((*)"
ch='(': lo=1, hi=1
ch='(': lo=2, hi=2
ch='*': lo=1, hi=3   (lo--=1, hi++=3; clamp lo=max(1,0)=1)
ch=')': lo=0, hi=2   (lo--=0, hi--=2)

End: lo=0 → return true

Hmm — let's verify manually: 
"((*)" — * can be ')' → "(())" valid ✓  
So true is correct.


s = "*(("
ch='*': lo=-1→clamp 0, hi=1
ch='(': lo=1, hi=2
ch='(': lo=2, hi=3

End: lo=2 ≠ 0 → return false ✓
(No way to close 2 unmatched openers with no remaining characters)
```

### Complexity
- Time: O(n) — single pass.
- Space: O(1) — two integer variables.

### Edge Cases
- All `*` → `lo` keeps clamping to 0; `hi` grows; end: `lo=0` → true (all `*` can be empty).
- `"*((("` → hi never reaches 0 at end; lo > 0 → false.
- Empty string → lo=0 → return true.
- No wildcards → degenerates to standard counter-based check.

### Follow-up Questions
- "Stack-based approach for wildcards?" → Two stacks — one for indices of `(`, one for indices of `*`. On `)`: try to pop from `(` stack (prefers matching with openers); if empty, pop from `*` stack (use wildcard as opener). After traversal, match remaining `(` with `*` (wildcard as closer — only valid if `*` index > `(` index). Remaining unmatched `(` → false.
- "Return which values each `*` should take?" → Reconstruct assignments using the stack approach — track which `*` was used as `(` vs `)` vs empty.

## Problem 6 — Score of Parentheses

### Problem
Given a valid parentheses string `s`, compute its score by these rules: `()` scores 1; `(A)` scores `2 * score(A)`; `AB` scores `score(A) + score(B)`.

```
Input:  s = "()"         → 1
Input:  s = "(())"       → 2
Input:  s = "()()"       → 2
Input:  s = "(()(()))"   → 6
```

### Pattern Recognition
Stack of integers — track accumulated score at each nesting depth. Each depth level accumulates its sub-score; on closing, contribute to the parent depth.

### Key Insight
The stack holds the "work-in-progress" score at each open depth. A `0` on the stack means nothing has been scored at that depth yet. When `)` pops a `0`, the innermost `()` pair scores 1. When `)` pops a positive value, a wrapped group scores `2 * value`.

### Approach
Push `0` as a sentinel. On `(`: push `0` (open a new depth, starting score 0). On `)`: pop the top value `v`. If `v === 0` → this depth was `()` → contribute `1` to the new top. If `v > 0` → this depth had inner content scoring `v` → contribute `2 * v` to the new top. Final answer is `stack[0]`.

### Solution

```js
function scoreOfParentheses(s) {
  const stack = [0]; // sentinel — collects final score

  for (const ch of s) {
    if (ch === '(') {
      stack.push(0); // new nesting depth — score starts at 0
    } else {
      const v = stack.pop(); // score accumulated at this depth

      // add contribution to the parent depth
      const contribution = v === 0 ? 1 : 2 * v;
      stack[stack.length - 1] += contribution;
    }
  }

  return stack[0]; // sentinel holds the total score
}
```

### Dry Run

```
s = "(()(()))"

stack=[0]

'(': push 0 → stack=[0,0]
'(': push 0 → stack=[0,0,0]
')': pop 0 → v=0 → contribution=1 → stack=[0,0+1]=[0,1]
'(': push 0 → stack=[0,1,0]
'(': push 0 → stack=[0,1,0,0]
')': pop 0 → v=0 → contribution=1 → stack=[0,1,0+1]=[0,1,1]
')': pop 1 → v=1 → contribution=2*1=2 → stack=[0,1+2]=[0,3]
')': pop 3 → v=3 → contribution=2*3=6 → stack=[0+6]=[6]

Return stack[0] = 6 ✓

Verify: "(()(()))"
= ( "()" + "(())" ) = "()" scores 1; "(())" scores 2*(1)=2; sum=3; wrapped: 2*3=6 ✓
```

### Complexity
- Time: O(n) — one pass.
- Space: O(n) — stack depth equals nesting depth, at most n/2.

### Edge Cases
- `"()"` → push 0, pop 0, contribution=1, stack[0]=1 → return 1. Correct.
- `"(())"` → nested once: inner `()` scores 1, wrapped → 2*1=2. Correct.
- Deeply nested `"(((...)))"` with k pairs → score = 2^(k-1). Stack depth k.
- Multiple adjacent groups `"()()()"` → each `()` adds 1 to sentinel → return 3.

### Follow-up Questions
- "O(1) space solution?" → Use a bit-counting trick: for each `)`, its contribution is `2^depth` where depth is the current nesting level. Track depth with a counter; add `2^depth` to the answer when `)` closes a `()`. No stack needed for valid strings.
- "What if the string might be invalid?" → Add validity checking (empty stack guard on `)`) — return -1 or throw on invalid input.

## Common Bugs Checklist

Before finalizing any parentheses solution, verify:

1. **Empty stack guard on close bracket** — always check `stack.length > 0` before `stack.pop()` on a close bracket. In JS, `[].pop()` returns `undefined` silently; in other languages it throws. Handle explicitly.

2. **Final stack check** — after the loop, `return stack.length === 0` (not just `return true`). Forgetting this passes `"((("` as valid.

3. **Sentinel initialization** — for longest valid substring: initialize `stack = [-1]`, not `stack = []`. Without the sentinel, the first valid pair length calculation is wrong.

4. **`lo` clamping in wildcard variant** — after updating `lo`, always `lo = Math.max(lo, 0)`. Without this, `lo` goes negative and gives wrong results.

5. **Backtracking constraint order** — in generate parentheses, check `open < n` before `close < open`. Getting the order wrong doesn't break correctness (both constraints are checked) but matters if you add memoization later.

6. **Index tracking for reconstruction** — when you need to return the actual string after removals (not just count), use a stack of indices, not characters. Tracking characters loses position information needed for reconstruction.
