# DSA: Dutch National Flag / 3-Way Partitioning — Theory, Interview Q&A & Practical Problems

---

## Part 1 — Theory & Interview Q&A

---

### Section 1: Fundamentals

**Q1. What is the Dutch National Flag (DNF) algorithm?**
A: The Dutch National Flag algorithm, devised by Edsger Dijkstra, partitions an array into three contiguous groups in a single O(n) pass with O(1) extra space, using three pointers. Its classic form sorts an array of 0s, 1s, and 2s (mirroring the three bands of the Dutch flag) so that all 0s come first, all 1s in the middle, and all 2s last — without a general-purpose sort.

```
Input:  [2, 0, 1, 2, 1, 0, 0, 2, 1]
Output: [0, 0, 0, 1, 1, 1, 2, 2, 2]
```

**Q2. What are the three pointers used, and what does each track?**
A: Three indices partition the array into four conceptual regions as the algorithm runs:

```
low, mid, high

[0 .. low-1]   → confirmed 0s (the "low" band)
[low .. mid-1] → confirmed 1s (the "mid" band)
[mid .. high]  → unexplored region (not yet classified)
[high+1 .. n-1]→ confirmed 2s (the "high" band)
```

`low` and `mid` start at index 0; `high` starts at the last index. `mid` is the active scan pointer — it walks forward, classifying one element at a time, while `low` and `high` mark the boundaries of the already-sorted 0-band and 2-band.

**Q3. What is the core algorithm logic?**
A: At each step, examine `nums[mid]` and take one of three actions:

```
if nums[mid] === 0:
    swap(nums[low], nums[mid])
    low++; mid++          // both advance: a 0 was placed correctly, mid region grows past it

if nums[mid] === 1:
    mid++                 // already in the right place, just move on

if nums[mid] === 2:
    swap(nums[mid], nums[high])
    high--                // mid does NOT advance — the swapped-in value is unexamined
```

Loop continues while `mid <= high`.

```js
function sortColors(nums) {
  let low = 0, mid = 0, high = nums.length - 1;

  while (mid <= high) {
    if (nums[mid] === 0) {
      [nums[low], nums[mid]] = [nums[mid], nums[low]];
      low++; mid++;
    } else if (nums[mid] === 1) {
      mid++;
    } else {
      [nums[mid], nums[high]] = [nums[high], nums[mid]];
      high--;
    }
  }
  return nums;
}
```

**Q4. Why does swapping with `high` NOT advance `mid`, while swapping with `low` DOES advance `mid`?**
A: This is the single most important — and most commonly mis-implemented — detail in DNF:
- When swapping `nums[low]` and `nums[mid]`: the value moving into `mid`'s old position came from `low`, and everything in `[low..mid-1]` was already confirmed to be 1s (that invariant is maintained by the loop), so the newly swapped-in value at `mid` is guaranteed to be a 1. It's safe to advance `mid` past it.
- When swapping `nums[mid]` and `nums[high]`: the value moving into `mid`'s position came from `high`, which is in the *unexplored* high region — it could be a 0, 1, or 2. `mid` must re-examine this new value on the next iteration, so it must NOT advance.

Advancing `mid` after a high-swap is the classic bug that causes unsorted output.

**Q5. What is the time and space complexity of the DNF algorithm?**
A:
- **Time**: O(n) — each element is visited by `mid` at most once (a 0 or 1 classification always advances `mid`; a 2 classification triggers a re-examination but shrinks the unexplored region by one from the other end, so the total number of comparisons is still bounded by O(n)).
- **Space**: O(1) — three integer pointers, no auxiliary array. All work is done via in-place swaps.
- Compare to a general sort: O(n log n) time — DNF exploits the fact that there are only 3 distinct values to achieve linear time, similar to how counting sort exploits a small value range.

**Q6. How does DNF relate to the classic "partition around a pivot" step in Quicksort (Lomuto/Hoare)?**
A: Standard Quicksort partitioning is a **2-way** partition: split into "less than pivot" and "greater than or equal to pivot." DNF is the **3-way** generalization: split into "less than pivot," "equal to pivot," and "greater than pivot." This matters enormously for arrays with many duplicate values — standard 2-way partitioning degrades toward O(n²) when most elements equal the pivot (e.g., an array of all identical values), while 3-way partitioning groups all the duplicates together in one pass and never recurses into the "equal" region, giving O(n) behavior in that case instead.

**Q7. Why is DNF also called "3-way partitioning," and how does it generalize beyond 0/1/2?**
A: The 0/1/2 sorting problem is the canonical teaching example, but the same three-pointer technique generalizes to **partition an array into "less than pivot," "equal to pivot," and "greater than pivot"** for any comparable value, not just the literal integers 0, 1, 2:

```js
function threeWayPartition(nums, pivot) {
  let low = 0, mid = 0, high = nums.length - 1;

  while (mid <= high) {
    if (nums[mid] < pivot) {
      [nums[low], nums[mid]] = [nums[mid], nums[low]];
      low++; mid++;
    } else if (nums[mid] === pivot) {
      mid++;
    } else {
      [nums[mid], nums[high]] = [nums[high], nums[mid]];
      high--;
    }
  }
  return { lowBound: low, highBound: high }; // [0..low-1] < pivot, [low..high] === pivot, [high+1..n-1] > pivot
}
```

This is exactly the partitioning subroutine used in **3-way Quicksort** (Dutch-flag Quicksort), which is the standard optimization used in production sort implementations (e.g., Java's `Arrays.sort` for primitives, many `std::sort` implementations) to handle duplicate-heavy inputs efficiently.

### Section 2: Invariants & Correctness

**Q8. What loop invariant guarantees DNF's correctness?**
A: At the start (and end) of every iteration, the array satisfies:

```
nums[0 .. low-1]    all equal to 0 (or "< pivot")
nums[low .. mid-1]  all equal to 1 (or "== pivot")
nums[mid .. high]   unclassified — not yet examined
nums[high+1 .. n-1] all equal to 2 (or "> pivot")
```

Every iteration either shrinks the unclassified region by advancing `mid` (0 or 1 case) or by retreating `high` (2 case), while never violating the three completed regions' guarantees. When `mid > high`, the unclassified region is empty and the array is fully partitioned.

**Q9. Why must the loop condition be `mid <= high`, not `mid < high`?**
A: The unclassified region is `[mid..high]` inclusive on both ends. If `mid === high`, there is still exactly one unclassified element to examine — using `mid < high` would terminate the loop one iteration early and leave that single element unclassified. This is a common off-by-one bug.

**Q10. Can DNF be implemented stably (preserving the relative order of equal elements)?**
A: No — the in-place swapping (especially the `high`-swap) does not preserve relative order among equal elements, since elements are moved via swaps rather than shifts. If stability is required, a different approach (e.g., three separate output buckets, then concatenate, or counting-sort style with an output array) is needed at the cost of O(n) extra space. In practice, stability is rarely required for the 0/1/2-sort or 3-way-partition use cases (colors, boolean flags, pivot buckets), so the in-place swap version is almost always preferred.

**Q11. What happens if you use two pointers instead of three (naive approach)?**
A: A naive two-pointer approach (e.g., one pass to push all 0s to the front, then a second pass to push all 2s to the back) works but requires **two full passes** over the array, or a more complex single pass that's harder to reason about and more bug-prone. The three-pointer DNF approach elegantly does both partitions simultaneously in a single pass by maintaining all three regions' invariants concurrently — this is the core insight that makes it a single O(n) pass rather than O(n) + O(n).

### Section 3: Advanced Patterns & Trade-offs

**Q12. When should you reach for 3-way partitioning instead of a standard sort?**
A:
- **Array has a small, known number of distinct values** (0/1/2 sort, boolean partitioning, categorizing into 3 buckets) → DNF, O(n) beats O(n log n).
- **Array has many duplicate values and needs general sorting** → 3-way Quicksort (DNF-based partition step) avoids the O(n²) worst case that plain 2-way Quicksort suffers on duplicate-heavy data.
- **Need to partition around a pivot for a selection algorithm** (e.g., finding the k-th smallest, median-of-medians, or Quickselect) → 3-way partitioning handles duplicate pivots gracefully, avoiding repeated re-partitioning of the "equal" region.
- **Array has more than 3 distinct values or values aren't known in advance** → DNF doesn't directly apply; use counting sort (small known range) or a general comparison sort.

**Q13. How does 3-way partitioning improve Quicksort's worst case for duplicate-heavy arrays?**
A: Standard Quicksort with 2-way partitioning treats all "equal to pivot" elements as belonging to one side (typically "not less than pivot"), which means an array of mostly-identical values causes wildly unbalanced partitions on every recursive call — degrading to O(n²). By using DNF to create three regions (`< pivot`, `== pivot`, `> pivot`) and **only recursing into the "less than" and "greater than" regions** — never into the "equal" region, since it's already fully sorted relative to the pivot — arrays with many duplicates are handled in O(n) per partitioning level with far fewer recursive calls, restoring near-O(n log n) behavior even in adversarial duplicate-heavy inputs.

**Q14. What is the relationship between DNF and counting sort?**
A: Both exploit a small, known set of distinct values to beat the O(n log n) comparison-sort lower bound. Counting sort explicitly counts occurrences of each value and reconstructs the array from those counts (O(n + k) time, O(k) extra space for the count array, where k is the value range). DNF achieves a similar linear-time result *in-place* with O(1) space via swapping, but is naturally suited only to exactly 3 categories (or a binary partition as a 2-pointer special case) — for more than 3 distinct values, counting sort or a generalized bucket approach is more natural than nesting multiple DNF passes.

**Q15. Can DNF's technique be adapted for a "4-way" or "k-way" partition?**
A: Not directly with three pointers — the elegant single-pass invariant relies on exactly three regions being trackable with three pointers. For k distinct categories, the standard approach is either: (a) counting sort if k is small and known, using an auxiliary count/offset array, or (b) recursively applying 3-way partitioning (e.g., partition into "first half of categories" vs "second half" vs — this doesn't map cleanly to DNF's swap logic). In practice, k > 3 category problems are solved with counting sort rather than by extending DNF's pointer scheme.

### Section 4: Scenario / Interview-Style Questions

**Q16. "You're given an array of integers that are only ever 0, 1, or 2, representing red/white/blue balls, and asked to sort it in a single pass without extra memory. Walk me through your approach."**
A: This is the canonical DNF problem. State the three-pointer invariant up front: `low` marks the boundary of confirmed 0s, `mid` is the active scanner, `high` marks the boundary of confirmed 2s. Walk through the three cases (`nums[mid]` is 0, 1, or 2) and explicitly call out that swapping with `high` does not advance `mid`, since the swapped-in value is unexamined. This single-pass, O(1)-space, three-case walkthrough is exactly what interviewers are listening for.

**Q17. "A colleague implements the 0/1/2 sort by doing two separate passes — one to move all 0s left, one to move all 2s right. What's the trade-off versus DNF, and would you push back?"**
A: The two-pass approach is still O(n) time and O(1) space, so asymptotically it's not "wrong" — but it does roughly 2x the work of the single-pass DNF approach and is arguably harder to get right (each pass needs its own careful swap/pointer logic, and interleaving the two passes correctly to avoid disturbing already-placed elements is fiddly). In an interview, demonstrating the single-pass three-pointer version signals a stronger grasp of the invariant-based reasoning that DNF is built on — I'd mention the two-pass approach as valid but note DNF is the tighter, more standard solution.

**Q18. "You're implementing Quicksort for a dataset with heavy duplication (e.g., sorting by a status field with only a handful of possible values). Standard 2-way Quicksort is timing out on this data. What's happening and how do you fix it?"**
A: Heavy duplication causes standard 2-way partitioning to produce maximally unbalanced splits (all "equal" elements clustering on one side of the pivot every time), degrading to O(n²) across the many low-diversity recursive calls. The fix is 3-way (Dutch-flag) partitioning in the Quicksort partition step: partition into `< pivot`, `== pivot`, `> pivot` regions, and only recurse into the two inequality regions, skipping the (already fully sorted) equal region entirely. This restores near-linearithmic performance even when large runs of duplicate values exist.

**Q19. "Extend the classic problem: instead of 0/1/2, you're given an array of objects with a `priority` field that can be `'low'`, `'medium'`, or `'high'`, and need to group them (order among the same priority doesn't matter). How do you apply DNF here?"**
A: Map the three string categories to the same three-region logic: treat `'low'` as the 0-equivalent, `'medium'` as the 1-equivalent, and `'high'` as the 2-equivalent (or use a comparator against a pivot value if there isn't a natural three-way categorical mapping). The pointer logic is unchanged — only the comparison (`nums[mid] === 'low'` etc., instead of `=== 0`) differs. This demonstrates that DNF is really a **pattern for any 3-category in-place partition**, not just literal integers.

## Problem 1 — Sort Colors (0/1/2 Sort, Classic DNF)

### Problem
Given an array `nums` with `n` objects colored red, white, or blue (represented as `0`, `1`, `2`), sort them in-place so that objects of the same color are adjacent, in the order red, white, blue — without using a library sort function.

```
Input:  nums = [2, 0, 2, 1, 1, 0]
Output: [0, 0, 1, 1, 2, 2]

Input:  nums = [2, 0, 1]
Output: [0, 1, 2]
```

### Pattern Recognition
Exactly three distinct known values, in-place, single-pass required — the canonical Dutch National Flag problem.

### Key Insight
Maintain three pointers (`low`, `mid`, `high`) that keep the invariant: everything before `low` is a confirmed 0, everything between `low` and `mid` is a confirmed 1, everything after `high` is a confirmed 2, and `[mid..high]` is unexplored. Classify `nums[mid]` and either advance `mid` (0 or 1 case) or swap with `high` and shrink the unexplored region from the right (2 case, without advancing `mid`).

### Approach
Initialize `low = mid = 0`, `high = n - 1`. Loop while `mid <= high`, branching on `nums[mid]`.

### Solution

```js
function sortColors(nums) {
  let low = 0, mid = 0, high = nums.length - 1;

  while (mid <= high) {
    if (nums[mid] === 0) {
      [nums[low], nums[mid]] = [nums[mid], nums[low]];
      low++;
      mid++;
    } else if (nums[mid] === 1) {
      mid++;
    } else { // nums[mid] === 2
      [nums[mid], nums[high]] = [nums[high], nums[mid]];
      high--;
      // mid does NOT advance — swapped-in value from `high` is unexamined
    }
  }

  return nums;
}
```

### Dry Run

```
nums = [2, 0, 2, 1, 1, 0]
low=0, mid=0, high=5

mid=0, nums[0]=2 → swap(nums[0],nums[5]) → [0,0,2,1,1,2], high=4
  low=0, mid=0, high=4

mid=0, nums[0]=0 → swap(nums[0],nums[0]) → [0,0,2,1,1,2], low=1, mid=1
  low=1, mid=1, high=4

mid=1, nums[1]=0 → swap(nums[1],nums[1]) → [0,0,2,1,1,2], low=2, mid=2
  low=2, mid=2, high=4

mid=2, nums[2]=2 → swap(nums[2],nums[4]) → [0,0,1,1,2,2], high=3
  low=2, mid=2, high=3

mid=2, nums[2]=1 → mid++ → mid=3
  low=2, mid=3, high=3

mid=3, nums[3]=1 → mid++ → mid=4
  low=2, mid=4, high=3

mid(4) > high(3) → loop ends

Result: [0, 0, 1, 1, 2, 2] ✓
```

### Complexity
- Time: O(n) — `mid` makes at most n forward steps total; `high` makes at most n backward steps total; each iteration does O(1) work.
- Space: O(1) — in-place swaps, three integer pointers.

### Edge Cases
- All same value (e.g., all 1s): `mid` walks straight through without any swaps — still O(n), correctly a no-op result.
- Already sorted: works correctly, though it may still perform some no-op swaps (e.g., `swap(nums[low], nums[mid])` when they're already in the right place at `low === mid`).
- Single element: loop runs at most once (or zero times if `high` starts below `mid`, impossible here since `high = n-1 = 0 = mid`), correctly classifies the single value.
- Empty array: `high = -1`, loop condition `mid <= high` is `0 <= -1`, false immediately — returns the empty array unchanged.

### Follow-up Questions
- "Can you do this with only two passes and a counting approach instead?" → Yes: count occurrences of 0, 1, 2 in one pass, then overwrite the array with the correct counts of each value in a second pass — also O(n) time, O(1) space (excluding output), but two passes instead of one; DNF is the tighter single-pass answer.
- "What if there were 4 distinct values instead of 3?" → DNF's three-pointer scheme doesn't directly extend; use counting sort with a small known value range instead.

## Problem 2 — Three-Way Partition Around a Pivot (Generalized DNF)

### Problem
Given an array `nums` and a `pivot` value, rearrange the array in-place so that all elements less than `pivot` come first, followed by all elements equal to `pivot`, followed by all elements greater than `pivot`. Return the index range `[low, high]` where `low` is the start of the "equal" region and `high` is its (inclusive) end.

```
Input:  nums = [9, 12, 5, 10, 14, 3, 10], pivot = 10
Output: nums rearranged e.g. [9, 5, 3, 10, 10, 14, 12], equalRange = [3, 4]
(exact positions within each region may vary — only the region boundaries are guaranteed)
```

### Pattern Recognition
Direct generalization of the 0/1/2 sort — instead of comparing to literal 0/1/2, compare each element to an arbitrary `pivot` value using `<`, `===`, `>`. This is exactly the partitioning subroutine used inside 3-way Quicksort.

### Key Insight
Same three-region invariant as classic DNF, just parameterized by a comparison against `pivot` instead of literal equality checks against 0 and 2.

### Approach
Identical pointer logic to Problem 1, with `nums[mid] < pivot`, `nums[mid] === pivot`, `nums[mid] > pivot` replacing the `0`/`1`/`2` checks.

### Solution

```js
function threeWayPartition(nums, pivot) {
  let low = 0, mid = 0, high = nums.length - 1;

  while (mid <= high) {
    if (nums[mid] < pivot) {
      [nums[low], nums[mid]] = [nums[mid], nums[low]];
      low++;
      mid++;
    } else if (nums[mid] === pivot) {
      mid++;
    } else {
      [nums[mid], nums[high]] = [nums[high], nums[mid]];
      high--;
    }
  }

  // [0..low-1] < pivot, [low..high] === pivot, [high+1..n-1] > pivot
  return { equalRangeStart: low, equalRangeEnd: high };
}
```

### Dry Run

```
nums = [9, 12, 5, 10, 14, 3, 10], pivot = 10
low=0, mid=0, high=6

mid=0, nums[0]=9 <10  → swap(0,0), low=1, mid=1 → [9,12,5,10,14,3,10]
mid=1, nums[1]=12 >10 → swap(1,6) → [9,10,5,10,14,3,12], high=5
mid=1, nums[1]=10 ==10→ mid=2
mid=2, nums[2]=5 <10  → swap(low=1,mid=2) → [9,5,10,10,14,3,12], low=2, mid=3
mid=3, nums[3]=10==10 → mid=4
mid=4, nums[4]=14>10  → swap(4,5) → [9,5,10,10,3,14,12], high=4
mid=4, nums[4]=3 <10  → swap(low=2,mid=4) → [9,5,3,10,10,14,12], low=3, mid=5
mid(5) > high(4) → loop ends

Result: [9,5,3,10,10,14,12], equalRange = [3,4] ✓
(indices 3-4 hold the two 10s; indices 0-2 are all <10; indices 5-6 are all >10)
```

### Complexity
- Time: O(n) — same single-pass argument as classic DNF.
- Space: O(1) — in-place, three pointers.

### Edge Cases
- No elements equal to pivot: `low` and `high` end up adjacent with an empty "equal" region (`low > high` is possible... actually `equalRangeStart` could exceed `equalRangeEnd`, signaling an empty middle band) — the array is still correctly split into `<pivot` and `>pivot` regions.
- All elements equal to pivot: `mid` walks straight through, `low` stays 0, `high` stays `n-1` — entire array is the "equal" region, correct.
- Pivot not present in array at all: same as "no elements equal to pivot" case above — algorithm still correctly produces a valid `<`/`>` split, just with an empty middle band.

### Follow-up Questions
- "How is this used inside Quicksort?" → After partitioning around a randomly chosen pivot, recurse only into `nums[0..low-1]` and `nums[high+1..n-1]` — skip the equal region entirely, since it's already in final sorted position relative to every other element.
- "What if the pivot is chosen as the median for guaranteed balance?" → Combine with median-of-medians or median-of-three pivot selection for worst-case guarantees; the 3-way partition step itself is unchanged.

## Problem 3 — Segregate Positive and Negative Numbers (2-Way Special Case)

### Problem
Given an array of integers, rearrange it in-place so that all negative numbers appear before all non-negative numbers. Relative order within each group does not need to be preserved. Do this in a single pass with O(1) extra space.

```
Input:  nums = [-1, 2, -3, 4, 5, -6, -7, 8]
Output: e.g. [-1, -7, -6, -3, 5, 4, 2, 8]  (negatives first, non-negatives after — exact order may vary)
```

### Pattern Recognition
This is DNF collapsed to only two regions instead of three — equivalent to treating "negative" as the 0-equivalent and "non-negative" as the 2-equivalent, with no "middle" category. It's effectively the classic Lomuto/Hoare partition step, but framed through the DNF two-pointer lens.

### Key Insight
Only two pointers are needed since there are only two categories: `low` marks the boundary of confirmed negatives, and a single scanning pointer sweeps the array, swapping negatives into the `low` region as they're found.

### Approach
Maintain `low = 0` as the boundary of the negative region. Sweep with a single pointer `i` from 0 to n-1: whenever `nums[i] < 0`, swap it into position `low` and advance `low`. (This is structurally the `low`/`mid` half of full DNF, with no separate `high` region needed since there's no third category.)

### Solution

```js
function segregateNegatives(nums) {
  let low = 0;

  for (let i = 0; i < nums.length; i++) {
    if (nums[i] < 0) {
      [nums[low], nums[i]] = [nums[i], nums[low]];
      low++;
    }
  }

  return nums;
}
```

### Dry Run

```
nums = [-1, 2, -3, 4, 5, -6, -7, 8]
low=0

i=0, nums[0]=-1 <0 → swap(0,0) → unchanged, low=1
i=1, nums[1]=2  → no swap
i=2, nums[2]=-3 <0 → swap(low=1,i=2) → [-1,-3,2,4,5,-6,-7,8], low=2
i=3, nums[3]=4  → no swap
i=4, nums[4]=5  → no swap
i=5, nums[5]=-6 <0 → swap(low=2,i=5) → [-1,-3,-6,4,5,2,-7,8], low=3
i=6, nums[6]=-7 <0 → swap(low=3,i=6) → [-1,-3,-6,-7,5,2,4,8], low=4
i=7, nums[7]=8  → no swap

Result: [-1,-3,-6,-7,5,2,4,8]  — first 4 elements all negative ✓
```

### Complexity
- Time: O(n) — single pass.
- Space: O(1) — one extra pointer, in-place swaps.

### Edge Cases
- All negative: every element triggers a swap-with-self as `low` tracks `i` exactly — still correct, just redundant self-swaps.
- All non-negative: `low` never advances past 0 — array unchanged, correctly has zero negatives at the front.
- Empty array / single element: loop runs 0 or 1 times respectively, trivially correct.

### Follow-up Questions
- "What if you also need negatives sorted among themselves and positives sorted among themselves?" → This 2-way partition only groups them; a subsequent sort within each region (or a stable partition approach) is needed if internal order matters.
- "Extend to 3 categories: negative, zero, positive?" → This becomes exactly the classic DNF problem again, with pivot effectively at 0 — reuse Problem 2's `threeWayPartition` directly.

## Problem 4 — Sort an Array of 0s, 1s, and 2s Using Counting (Alternative to DNF)

### Problem
Same as Problem 1 (sort an array of only 0s, 1s, and 2s), but the interviewer asks you to solve it a second way — using counting instead of the three-pointer swap technique — to compare trade-offs.

```
Input:  nums = [2, 0, 2, 1, 1, 0]
Output: [0, 0, 1, 1, 2, 2]
```

### Pattern Recognition
Small, fixed, known set of values (0, 1, 2) → counting sort is a valid alternative to DNF, useful to present as a trade-off discussion in interviews.

### Key Insight
Since there are only 3 distinct values, count how many of each appear in one pass, then overwrite the array in a second pass using those counts directly — no comparisons or swaps needed during the overwrite phase.

### Approach
Pass 1: tally `count[0]`, `count[1]`, `count[2]`. Pass 2: fill the array with `count[0]` zeros, then `count[1]` ones, then `count[2]` twos.

### Solution

```js
function sortColorsCounting(nums) {
  const count = [0, 0, 0];

  for (const num of nums) {
    count[num]++;
  }

  let idx = 0;
  for (let value = 0; value <= 2; value++) {
    for (let c = 0; c < count[value]; c++) {
      nums[idx++] = value;
    }
  }

  return nums;
}
```

### Dry Run

```
nums = [2, 0, 2, 1, 1, 0]

Pass 1 (counting):
count[0]=2 (two 0s), count[1]=2 (two 1s), count[2]=2 (two 2s)

Pass 2 (overwrite):
idx=0: write 0,0 (count[0]=2) → nums=[0,0,_,_,_,_], idx=2
idx=2: write 1,1 (count[1]=2) → nums=[0,0,1,1,_,_], idx=4
idx=4: write 2,2 (count[2]=2) → nums=[0,0,1,1,2,2], idx=6

Result: [0,0,1,1,2,2] ✓
```

### Complexity
- Time: O(n) — two linear passes (counting, then overwriting).
- Space: O(1) — the count array has a fixed size of 3, independent of n.

### Edge Cases
- Same as Problem 1's edge cases (all-same-value, already sorted, empty, single element) — all handled naturally since counting is agnostic to input order.

### Follow-up Questions
- "Which approach is better — DNF or counting — and why?" → Both are O(n) time, O(1) space, so asymptotically equivalent. DNF does everything in a single pass with in-place swaps and no auxiliary counting structure; counting sort is arguably simpler to reason about and less bug-prone (no tricky "does mid advance" logic) but requires two explicit passes and is less "elegant" as a demonstration of pointer manipulation. In an interview, presenting DNF as the primary answer and counting sort as an alternative shows breadth.
- "Does the counting approach generalize better to k distinct values than DNF?" → Yes — counting sort trivially extends to any fixed k (just widen the `count` array), whereas DNF's three-pointer scheme is specifically built around exactly 3 categories.

## Quick Reference — Pattern Decision Tree

```
Does the problem involve partitioning/sorting an array with a SMALL, KNOWN number of distinct values or categories, in-place, in one pass?
│
├── EXACTLY 3 categories (e.g., 0/1/2, red/white/blue, <pivot/==pivot/>pivot)
│   └── Dutch National Flag (3-pointer: low, mid, high) → O(n) time, O(1) space
│
├── EXACTLY 2 categories (e.g., negative/non-negative, even/odd)
│   └── DNF collapses to 2-pointer partition (Lomuto-style) → O(n) time, O(1) space
│
├── MORE THAN 3 categories, values known and small range
│   └── Counting Sort → O(n + k) time, O(k) space
│
├── PARTITIONING AS A QUICKSORT SUBROUTINE, duplicate-heavy data expected
│   └── 3-way (Dutch-flag) Quicksort partition — only recurse into < and > regions
│
├── NEED STABILITY (preserve relative order within each category)
│   └── DNF's in-place swaps are NOT stable — use bucket/counting with an output array instead
│
└── VALUES ARE NOT KNOWN IN ADVANCE / continuous range
    └── DNF and counting sort don't apply — use a general comparison sort, O(n log n)
```

## Common Bugs Checklist

Before submitting any Dutch National Flag / 3-way partition solution, verify:

1. **Does `mid` advance after a `high`-swap?** — It must NOT. The value swapped in from `high` is unexamined and needs to be classified on the next iteration. Advancing `mid` here is the #1 DNF bug and produces incorrectly unsorted output.

2. **Does `mid` advance after a `low`-swap?** — It must. The invariant guarantees everything in `[low..mid-1]` was already confirmed as the "middle" category, so the value swapped into `mid`'s old slot from `low` is guaranteed correct and doesn't need re-examination.

3. **Loop condition is `mid <= high`, not `mid < high`?** — Using strict `<` terminates one iteration too early and leaves the last unclassified element unexamined.

4. **Pointers initialized correctly?** — `low = 0`, `mid = 0`, `high = n - 1`. A common mistake is initializing `high = n` (off-by-one, causes an out-of-bounds access on the first `high`-swap).

5. **Comparison direction consistent with pivot semantics?** — In the generalized 3-way partition, double-check `<`, `===`, `>` map to the intended "low," "equal," and "high" regions — flipping the comparison direction silently reverses the sort order.

6. **Assuming stability when it isn't guaranteed?** — If downstream code depends on relative order being preserved within a category, DNF's swap-based approach will silently violate that assumption; use an explicit stable bucketing approach instead.

---

**Final Tip:** At the 5 YOE level, interviewers expect immediate recognition of "sort/partition an array with a small fixed number of known categories, in place, single pass" as the Dutch National Flag pattern, and expect the three-pointer invariant to be stated *before* any code is written: "everything before low is confirmed low-category, everything between low and mid is confirmed mid-category, everything after high is confirmed high-category, and mid to high is unexplored." The detail that most separates strong candidates is correctly explaining — out loud, before coding — *why* `mid` doesn't advance after a swap with `high`. That single invariant is the crux of the entire algorithm.
