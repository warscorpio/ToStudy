# DSA: Kadane's Algorithm (Maximum Subarray) — Theory, Interview Q&A & Practical Problems

## Part 1 — Theory & Interview Q&A

---

### Section 1: Fundamentals

**Q1. What is Kadane's algorithm?**
A: Kadane's algorithm finds the maximum sum of a contiguous subarray within a 1D array of numbers in a single O(n) pass. It is a dynamic programming technique: at every index, it decides whether to **extend** the previous subarray or **start fresh** from the current element, based on which choice yields a larger sum.

```
Array:   [-2, 1, -3, 4, -1, 2, 1, -5, 4]
Max subarray: [4, -1, 2, 1] → sum = 6
```

**Q2. What is the core recurrence behind Kadane's algorithm?**
A: Define `currentMax[i]` as the maximum sum of a contiguous subarray ending exactly at index `i`. Then:

```
currentMax[i] = max(nums[i], currentMax[i-1] + nums[i])
globalMax     = max(globalMax, currentMax[i])
```

The recurrence encodes a decision: if the running sum so far (`currentMax[i-1]`) is negative, it can only hurt the next element, so it's better to discard it and start a fresh subarray at `nums[i]`. If it's positive, extending is always at least as good.

```js
function maxSubArray(nums) {
  let currentMax = nums[0];
  let globalMax = nums[0];

  for (let i = 1; i < nums.length; i++) {
    currentMax = Math.max(nums[i], currentMax + nums[i]);
    globalMax = Math.max(globalMax, currentMax);
  }

  return globalMax;
}
```

Time: O(n). Space: O(1) — no array is stored, only two running variables.

**Q3. Why does "reset to nums[i] when currentMax goes negative" work?**
A: A negative running sum can never help a future subarray — adding a negative number to any future sum only makes it smaller. So carrying forward a negative `currentMax` is strictly worse than discarding it and starting over at the current element. This greedy discard is what makes the DP collapse to O(1) space instead of needing the full `currentMax[]` array.

**Q4. What is the brute-force approach, and how does Kadane's improve on it?**
A: Brute force checks every possible subarray `(l, r)` and sums it, either recomputing the sum each time (O(n³)) or using a running sum as `r` extends (O(n²)). Kadane's algorithm collapses this to O(n) by realizing that the maximum sum ending at index `i` only depends on the maximum sum ending at index `i-1` — no need to re-examine all previous starting points.

```
Brute force (O(n²)):
for l in 0..n-1:
    sum = 0
    for r in l..n-1:
        sum += nums[r]
        maxSum = max(maxSum, sum)

Kadane's (O(n)):
single pass, O(1) space, same correctness guarantee
```

**Q5. What is the time and space complexity of Kadane's algorithm?**
A:
- **Time**: O(n) — one linear pass, O(1) work per element.
- **Space**: O(1) — two running variables (`currentMax`, `globalMax`), no auxiliary array required.
- This is asymptotically optimal: any correct algorithm must examine every element at least once, so O(n) is a hard lower bound.

**Q6. Does Kadane's algorithm handle arrays where all elements are negative?**
A: Yes, as long as `currentMax` and `globalMax` are both initialized to `nums[0]` (not to 0). Initializing to 0 would silently allow an "empty subarray" with sum 0 to win, which is wrong if the problem requires at least one element. With correct initialization, an all-negative array correctly returns its single largest (least negative) element.

```
nums = [-8, -3, -6, -2, -5, -4]
Correct answer: -2 (the least negative single element)
```

**Q7. What's the difference between Kadane's algorithm and the prefix sum + min-tracking approach?**
A: They solve the same problem via different lenses:
- **Kadane's (DP)**: `currentMax[i] = max(nums[i], currentMax[i-1] + nums[i])` — forward, O(1) space.
- **Prefix sum + min tracking**: `maxSubarraySum = max(pre[r] - minPrefixSoFar)` over all `r`, where `minPrefixSoFar` tracks the smallest prefix sum seen before index `r`. This is mathematically equivalent — Kadane's is the prefix-sum formula with the subtraction folded into a running max/min instead of an explicit array.
Both are O(n) time, O(1) space; Kadane's is preferred in interviews for its simplicity, but the prefix-sum framing is useful when adapting to "at most/exactly k subarrays" variants.

### Section 2: Variants & Extensions

**Q8. How do you also return the indices (start, end) of the maximum subarray, not just the sum?**
A: Track a candidate start index whenever a fresh subarray begins (`currentMax` resets to `nums[i]`), and commit `(start, end)` whenever `globalMax` is updated.

```js
function maxSubArrayWithIndices(nums) {
  let currentMax = nums[0], globalMax = nums[0];
  let tempStart = 0, start = 0, end = 0;

  for (let i = 1; i < nums.length; i++) {
    if (nums[i] > currentMax + nums[i]) {
      currentMax = nums[i];
      tempStart = i;           // fresh subarray begins here
    } else {
      currentMax = currentMax + nums[i];
    }

    if (currentMax > globalMax) {
      globalMax = currentMax;
      start = tempStart;
      end = i;
    }
  }

  return { sum: globalMax, start, end };
}
```

**Q9. What is the "maximum circular subarray sum" variant, and how does it extend Kadane's?**
A: The array wraps around — the max subarray may cross the end and continue from the beginning. There are two cases:
1. **No wraparound**: the answer is the standard Kadane's max subarray.
2. **Wraparound**: the excluded middle segment must be the *minimum* subarray sum. The wraparound max = `totalSum - minSubarraySum`.

Run Kadane's twice: once for max subarray, once for min subarray (by negating logic). The answer is `max(kadaneMax, totalSum - kadaneMin)`, with a special case if all elements are negative (wraparound would produce an empty array, which is invalid — in that case just return `kadaneMax`).

```js
function maxSubarraySumCircular(nums) {
  let total = 0, curMax = 0, curMin = 0, maxSum = nums[0], minSum = nums[0];

  for (const num of nums) {
    curMax = Math.max(curMax + num, num);
    maxSum = Math.max(maxSum, curMax);

    curMin = Math.min(curMin + num, num);
    minSum = Math.min(minSum, curMin);

    total += num;
  }

  // if all numbers are negative, maxSum holds the correct answer
  // (total - minSum would equal 0, an invalid empty subarray)
  return maxSum > 0 ? Math.max(maxSum, total - minSum) : maxSum;
}
```

**Q10. What is the "maximum product subarray" variant, and why doesn't standard Kadane's work directly?**
A: Sum is monotonic under addition of positive numbers, but product flips sign with negative numbers — a very negative running product can become the maximum if multiplied by another negative number. So you must track **both** the running max product AND the running min product at each step (since a min × negative = a new max).

```js
function maxProduct(nums) {
  let curMax = nums[0], curMin = nums[0], result = nums[0];

  for (let i = 1; i < nums.length; i++) {
    const num = nums[i];
    if (num < 0) [curMax, curMin] = [curMin, curMax]; // swap on sign flip

    curMax = Math.max(num, curMax * num);
    curMin = Math.min(num, curMin * num);

    result = Math.max(result, curMax);
  }

  return result;
}
```

A zero resets both `curMax` and `curMin` to effectively restart at the next element, since any product touching zero collapses to zero — this happens naturally because `Math.max(num, curMax * num)` picks `num` itself (which is 0) as the better restart point.

**Q11. How does Kadane's algorithm extend to 2D — maximum sum sub-rectangle in a matrix?**
A: Fix a pair of rows `(top, bottom)`, collapse all columns between those rows into a single 1D array by summing column-wise, then run standard 1D Kadane's on that collapsed array to find the best contiguous column range. Repeat for all O(m²) row pairs.

```js
function maxSumRectangle(matrix) {
  const m = matrix.length, n = matrix[0].length;
  let best = -Infinity;

  for (let top = 0; top < m; top++) {
    const colSum = new Array(n).fill(0);
    for (let bottom = top; bottom < m; bottom++) {
      for (let c = 0; c < n; c++) colSum[c] += matrix[bottom][c];
      best = Math.max(best, maxSubArray(colSum)); // 1D Kadane's on collapsed row
    }
  }
  return best;
}
```

Time: O(m² × n) — O(m²) row pairs, each doing an O(n) Kadane's pass plus O(n) column accumulation.

**Q12. What is the "maximum subarray sum with at most k elements removed / exactly one element allowed to be skipped" variant?**
A: Track two DP states per index: `noSkip[i]` (best subarray ending at `i` with zero skips used) and `oneSkip[i]` (best subarray ending at `i` with exactly one skip used so far).

```
noSkip[i]  = max(nums[i], noSkip[i-1] + nums[i])
oneSkip[i] = max(noSkip[i-1], oneSkip[i-1] + nums[i])
```

`oneSkip[i]` either skips `nums[i]` entirely (carrying forward `noSkip[i-1]` unchanged) or has already used its skip earlier and now extends. The answer is `max` over all `noSkip[i]` and `oneSkip[i]`. This generalizes to "at most k skips" with k DP layers, each O(n) — total O(nk).

**Q13. What is the relationship between Kadane's algorithm and Dynamic Programming more broadly?**
A: Kadane's is one of the simplest examples of 1D DP with O(1) state compression:
- **State**: `currentMax[i]` = best subarray sum ending at `i`.
- **Transition**: extend or restart, based on which is locally better.
- **Compression**: because the transition only looks one step back, the full DP array collapses to a single running variable.
This pattern (local decision: extend vs. restart) recurs in many DP problems — recognizing it is a strong interview signal.

### Section 3: Advanced Patterns & Trade-offs

**Q14. When should you use Kadane's algorithm vs. prefix sum + hash map for subarray problems?**
A:
- **Maximum/minimum subarray sum (no target value)** → Kadane's, O(n) time, O(1) space.
- **Count of subarrays with sum exactly equal to k** → prefix sum + hash map (Kadane's doesn't count occurrences, only finds the single best).
- **Maximum subarray sum with a length constraint (at most/exactly k elements)** → sliding window (if all positive) or DP with an added dimension for length.
- **Maximum subarray sum with negative numbers allowed and no length constraint** → Kadane's is the canonical, most efficient choice.

**Q15. Can Kadane's algorithm be adapted for streaming data (values arriving one at a time, no re-access to history)?**
A: Yes — this is exactly what makes Kadane's attractive in practice. Since it only needs `currentMax` and `globalMax` from the *immediately preceding* step, it processes a live stream in true O(1) space and O(1) time per new element, without ever storing the array. This is a common follow-up: "what if you can't hold the whole array in memory?"

**Q16. What's a common off-by-one or initialization bug in Kadane's implementations?**
A: Initializing `currentMax` and `globalMax` to `0` instead of `nums[0]`. This silently breaks all-negative arrays, since it allows an implicit "empty subarray" with sum 0 to beat every valid non-empty subarray, producing 0 as the (wrong) answer instead of the correct least-negative element. Always seed both trackers with `nums[0]` and start the loop from index 1.

### Section 4: Scenario / Interview-Style Questions

**Q17. "You're monitoring a stock's daily price changes (which can be negative) and need to find the most profitable contiguous stretch of days seen so far, updated live as new days arrive. How do you design this?"**
A: Kadane's algorithm in streaming mode. Maintain `currentMax` and `globalMax` as running variables. On each new day's price change, update `currentMax = max(delta, currentMax + delta)` and `globalMax = max(globalMax, currentMax)`. O(1) time and space per new data point — no need to re-scan history.

**Q18. "A teammate wants to find the maximum subarray sum but insists on using prefix sums and nested loops for clarity. What do you tell them?"**
A: The prefix sum + nested loop approach is O(n²) (for each `r`, scan all `l` to find the best `pre[r] - pre[l]`), or O(n) if you track the running minimum prefix sum instead of scanning — which is mathematically identical to Kadane's, just framed differently. If clarity is the goal, Kadane's DP framing ("extend or restart") is usually easier to explain and verify than prefix-sum subtraction, and it naturally extends to the product/circular variants that prefix sums don't handle as cleanly.

**Q19. "Extend Kadane's to report not just the max sum, but every maximal subarray if there are ties for the maximum sum." What's the approach?**
A: Modify the standard algorithm to record `(start, end)` pairs into a list every time `currentMax` *equals* (not just exceeds) `globalMax`, rather than overwriting a single best pair. Still O(n) time, but O(n) space in the worst case if many subarrays tie for the maximum.

**Q20. "The array can be up to 10^8 elements and doesn't fit in memory, but you can read it once from disk sequentially. Can Kadane's still work?"**
A: Yes — this is Kadane's biggest practical advantage over prefix-sum-array approaches. Since it needs O(1) space and processes elements in a single left-to-right pass, it works directly on a sequential stream from disk without ever materializing the full array in memory.

## Problem 1 — Maximum Subarray (Classic Kadane's)

### Problem
Given an integer array `nums`, find the contiguous subarray (containing at least one number) which has the largest sum, and return that sum.

```
Input:  nums = [-2, 1, -3, 4, -1, 2, 1, -5, 4]
Output: 6   ([4, -1, 2, 1])

Input:  nums = [1]
Output: 1

Input:  nums = [-1]
Output: -1
```

### Pattern Recognition
Single-pass maximum contiguous sum with no target value and no length constraint — textbook Kadane's algorithm.

### Key Insight
At each index, the best subarray ending there is either "just this element" or "this element appended to the best subarray ending at the previous index" — whichever is larger. A negative running sum is never worth carrying forward.

### Approach
Maintain `currentMax` (best sum ending at the current index) and `globalMax` (best sum seen anywhere so far). Update both in a single pass, seeded with `nums[0]`.

### Solution

```js
function maxSubArray(nums) {
  let currentMax = nums[0];
  let globalMax = nums[0];

  for (let i = 1; i < nums.length; i++) {
    // extend the previous subarray, or start fresh — whichever is bigger
    currentMax = Math.max(nums[i], currentMax + nums[i]);
    globalMax = Math.max(globalMax, currentMax);
  }

  return globalMax;
}
```

### Dry Run

```
nums = [-2, 1, -3, 4, -1, 2, 1, -5, 4]

i=0: currentMax=-2, globalMax=-2  (seed)
i=1: currentMax=max(1, -2+1=-1)=1        globalMax=max(-2,1)=1
i=2: currentMax=max(-3, 1-3=-2)=-2       globalMax=max(1,-2)=1
i=3: currentMax=max(4, -2+4=2)=4         globalMax=max(1,4)=4
i=4: currentMax=max(-1, 4-1=3)=3         globalMax=max(4,3)=4
i=5: currentMax=max(2, 3+2=5)=5          globalMax=max(4,5)=5
i=6: currentMax=max(1, 5+1=6)=6          globalMax=max(5,6)=6
i=7: currentMax=max(-5, 6-5=1)=1         globalMax=max(6,1)=6
i=8: currentMax=max(4, 1+4=5)=5          globalMax=max(6,5)=6

Answer: 6 ✓  (subarray [4,-1,2,1] from index 3 to 6)
```

### Complexity
- Time: O(n) — single pass.
- Space: O(1) — two running variables only.

### Edge Cases
- Single element: loop never executes; return `nums[0]` directly — correct.
- All negative: `currentMax`/`globalMax` seeded with `nums[0]`, never reset to 0, so the least-negative single element wins.
- All positive: `currentMax` keeps extending, final `globalMax` = sum of the whole array — correct.
- Array with a single zero among negatives: zero can become a valid "reset point" since `0 > currentMax + 0` whenever `currentMax` is negative.

### Follow-up Questions
- "Return the actual subarray, not just the sum?" → See Problem 2 (tracking start/end indices).
- "What if the array is circular?" → See Problem 3.
- "What if you need the product instead of the sum?" → See Problem 4.

## Problem 2 — Maximum Subarray with Start and End Indices

### Problem
Same as Problem 1, but return the `(start, end)` indices of the maximum subarray in addition to its sum.

```
Input:  nums = [-2, 1, -3, 4, -1, 2, 1, -5, 4]
Output: { sum: 6, start: 3, end: 6 }
```

### Pattern Recognition
Kadane's algorithm with additional bookkeeping — track *where* each reset happens so the winning window's boundaries can be recovered.

### Key Insight
A "reset" (starting fresh at `nums[i]`) happens exactly when `nums[i] > currentMax + nums[i]`, i.e., when the previous running sum was negative. Record the candidate start index at every reset, and commit `(start, end)` only when `globalMax` actually improves.

### Approach
Maintain a `tempStart` that updates on every reset, and commit it to `start` (along with `end = i`) only when a new global maximum is found.

### Solution

```js
function maxSubArrayWithIndices(nums) {
  let currentMax = nums[0], globalMax = nums[0];
  let tempStart = 0, start = 0, end = 0;

  for (let i = 1; i < nums.length; i++) {
    if (nums[i] > currentMax + nums[i]) {
      currentMax = nums[i];
      tempStart = i; // candidate new start
    } else {
      currentMax += nums[i]; // extend
    }

    if (currentMax > globalMax) {
      globalMax = currentMax;
      start = tempStart;
      end = i;
    }
  }

  return { sum: globalMax, start, end };
}
```

### Dry Run

```
nums = [-2, 1, -3, 4, -1, 2, 1, -5, 4]

i=0: seed currentMax=-2, globalMax=-2, tempStart=0

i=1: nums[1]=1 > (-2+1=-1)? yes → currentMax=1, tempStart=1
     1 > -2? yes → globalMax=1, start=1, end=1

i=2: nums[2]=-3 > (1-3=-2)? no → currentMax=-2
     -2 > 1? no

i=3: nums[3]=4 > (-2+4=2)? yes → currentMax=4, tempStart=3
     4 > 1? yes → globalMax=4, start=3, end=3

i=4: nums[4]=-1 > (4-1=3)? no → currentMax=3
     3 > 4? no

i=5: nums[5]=2 > (3+2=5)? no → currentMax=5
     5 > 4? yes → globalMax=5, start=3, end=5

i=6: nums[6]=1 > (5+1=6)? no → currentMax=6
     6 > 5? yes → globalMax=6, start=3, end=6

i=7: nums[7]=-5 > (6-5=1)? no → currentMax=1
     1 > 6? no

i=8: nums[8]=4 > (1+4=5)? no → currentMax=5
     5 > 6? no

Answer: { sum: 6, start: 3, end: 6 } ✓  (nums[3..6] = [4,-1,2,1])
```

### Complexity
- Time: O(n) — same single pass as classic Kadane's.
- Space: O(1) — a handful of extra scalar trackers.

### Edge Cases
- Ties for maximum sum: this implementation keeps the *first* maximal window found (strict `>` comparisons); switching to `>=` would keep the *last* one instead.
- Single element array: `start = end = 0` by initialization, loop never runs — correct.
- Reset on the very last element: `tempStart` updates but the comparison `currentMax > globalMax` still correctly captures a single-element winning subarray if it's the largest.

### Follow-up Questions
- "What if multiple subarrays tie for the max sum — return all of them?" → Change the update condition to `>=` and push every tie into a results list instead of overwriting.
- "Can you do this without the `tempStart` variable?" → No — without tracking where the current run began, the start index of the winning window is unrecoverable once you've moved past it.

## Problem 3 — Maximum Sum Circular Subarray

### Problem
Given a circular integer array `nums` (the end connects back to the beginning), return the maximum possible sum of a non-empty contiguous subarray.

```
Input:  nums = [1, -2, 3, -2]
Output: 3   ([3])

Input:  nums = [5, -3, 5]
Output: 10  ([5, 5, -3] wraps around → 5+5+... wait, wraps as [5,(-3 excluded),5] = 10)

Input:  nums = [-3, -2, -3]
Output: -2  (all negative — no wraparound helps)
```

### Pattern Recognition
Maximum subarray sum where the subarray may wrap past the end of the array — extends Kadane's with a complementary "minimum subarray" pass.

### Key Insight
Two cases cover every possibility:
1. The optimal subarray does **not** wrap → standard Kadane's max.
2. The optimal subarray **does** wrap → it equals `totalSum` minus the minimum (most negative) contiguous subarray in the middle that got excluded.
The answer is the larger of the two — with a guard for the all-negative case, where "wraparound" would incorrectly imply an empty array.

### Approach
Run Kadane's for maximum subarray sum. Run an inverted Kadane's for minimum subarray sum. Compute `total - minSum` as the wraparound candidate. If `maxSum < 0` (all elements negative), the wraparound formula produces an invalid empty selection, so just return `maxSum` directly.

### Solution

```js
function maxSubarraySumCircular(nums) {
  let total = 0;
  let curMax = 0, maxSum = -Infinity;
  let curMin = 0, minSum = Infinity;

  for (const num of nums) {
    curMax = Math.max(curMax + num, num);
    maxSum = Math.max(maxSum, curMax);

    curMin = Math.min(curMin + num, num);
    minSum = Math.min(minSum, curMin);

    total += num;
  }

  // all-negative guard: wraparound (total - minSum) would equal 0,
  // an invalid empty subarray — the true answer is just maxSum
  if (maxSum < 0) return maxSum;

  return Math.max(maxSum, total - minSum);
}
```

### Dry Run

```
nums = [5, -3, 5]

i=0 (5):  curMax=max(0+5,5)=5   maxSum=5     curMin=min(0+5,5)=5    minSum=5    total=5
i=1 (-3): curMax=max(5-3,-3)=2  maxSum=5     curMin=min(5-3,-3)=-3  minSum=-3   total=2
i=2 (5):  curMax=max(2+5,5)=7   maxSum=7     curMin=min(-3+5,5)=2   minSum=-3   total=7

maxSum=7, total=7, minSum=-3
wraparound = total - minSum = 7 - (-3) = 10

maxSum(7) >= 0, so answer = max(7, 10) = 10 ✓
(the wraparound subarray is [5] at the end + [5] at the start = 10,
 excluding the middle [-3])
```

### Complexity
- Time: O(n) — two linear Kadane's passes (max and min), can be fused into one loop as shown.
- Space: O(1) — running variables only.

### Edge Cases
- All negative numbers: `maxSum < 0` guard returns the standard (non-wrapped) answer, avoiding the invalid empty-subarray case.
- Single element: `maxSum = minSum = nums[0]`, `total = nums[0]`; wraparound candidate `total - minSum = 0` is correctly dominated by `maxSum` unless `maxSum` is negative, in which case the guard handles it.
- All elements equal and positive: wraparound sum equals `total` minus the smallest single element (the minimal "excluded" subarray), which correctly nets out to *almost* the full array sum, and the non-wrap case (`total` itself) will actually be captured by `maxSum` when the whole array is the best subarray.

### Follow-up Questions
- "What if the subarray can't be the entire array (must exclude at least one element)?" → Add an explicit check: if `minSum === total` (meaning the minimum subarray is the entire array, implying the max subarray path would be empty), fall back to `maxSum` only.
- "Extend to a circular 2D grid?" → Combine the row-collapsing technique from 2D Kadane's with the circular wraparound logic per collapsed row — significantly more complex, rarely asked beyond senior-level system design interviews.

## Problem 4 — Maximum Product Subarray

### Problem
Given an integer array `nums`, find the contiguous subarray (containing at least one number) which has the largest product, and return that product.

```
Input:  nums = [2, 3, -2, 4]
Output: 6   ([2,3])

Input:  nums = [-2, 0, -1]
Output: 0

Input:  nums = [-2, 3, -4]
Output: 24  ([-2,3,-4])
```

### Pattern Recognition
Maximum contiguous product — looks like Kadane's, but a single running "max" isn't enough because multiplying by a negative number flips the sign, turning the current minimum into the next maximum.

### Key Insight
Track **both** `curMax` (best product ending here) and `curMin` (worst/most-negative product ending here) at every index. When the current number is negative, swap `curMax` and `curMin` before updating, since multiplying flips which one could become the new max.

### Approach
At each index: if `nums[i] < 0`, swap `curMax` and `curMin`. Then update `curMax = max(nums[i], curMax * nums[i])` and `curMin = min(nums[i], curMin * nums[i])`. Track the running best of all `curMax` values.

### Solution

```js
function maxProduct(nums) {
  let curMax = nums[0], curMin = nums[0], result = nums[0];

  for (let i = 1; i < nums.length; i++) {
    const num = nums[i];

    if (num < 0) {
      [curMax, curMin] = [curMin, curMax]; // sign flip swaps roles
    }

    curMax = Math.max(num, curMax * num);
    curMin = Math.min(num, curMin * num);

    result = Math.max(result, curMax);
  }

  return result;
}
```

### Dry Run

```
nums = [-2, 3, -4]

seed: curMax=-2, curMin=-2, result=-2

i=1 (num=3): 3 < 0? no, no swap
  curMax = max(3, -2*3=-6) = 3
  curMin = min(3, -2*3=-6) = -6
  result = max(-2, 3) = 3

i=2 (num=-4): -4 < 0? yes → swap: curMax=-6, curMin=3
  curMax = max(-4, -6*-4=24) = 24
  curMin = min(-4, 3*-4=-12) = -12
  result = max(3, 24) = 24

Answer: 24 ✓  (subarray [-2,3,-4] → -2*3*-4 = 24)
```

### Complexity
- Time: O(n) — single pass.
- Space: O(1) — three running variables.

### Edge Cases
- Zero in the array: `curMax = max(0, curMax*0) = max(0, 0)`... more precisely, `Math.max(num, curMax*num)` where `num=0` naturally resets both trackers to 0, correctly "restarting" the product tracking after the zero without special-casing.
- All negative numbers, even count: the full array product is positive and should be the answer — the swap-on-negative logic correctly threads this through.
- All negative numbers, odd count: excluding either the first or last negative number gives the best (positive) product — the algorithm finds this via the `curMin` tracking without explicit enumeration.
- Single element: loop never runs, returns `nums[0]` — correct for both positive and negative single elements.

### Follow-up Questions
- "What if you need the actual subarray, not just the product?" → Same start/end index tracking as Problem 2, applied to both `curMax` and `curMin` transitions.
- "What about maximum product of a subsequence (not contiguous)?" → Different problem entirely — becomes a greedy/sorting problem (count negatives, handle zeros, multiply all non-zero elements while dropping the smallest-magnitude negative if the count of negatives is odd).

## Problem 5 — Maximum Sum Rectangle in a 2D Matrix

### Problem
Given a 2D matrix of integers, find the maximum sum of any rectangular sub-region (contiguous rows and contiguous columns).

```
matrix = [
  [1, 2, -1, -4, -20],
  [-8, -3, 4, 2, 1],
  [3, 8, 10, 1, 3],
  [-4, -1, 1, 7, -6]
]

Output: 29
(rectangle spanning rows 1-2, columns 1-3: [-3,4,2] + [8,10,1] = 3+19 = ...
 actual max rectangle: rows 1-2, cols 1-4 → sum = 29)
```

### Pattern Recognition
Extends 1D Kadane's to 2D by fixing a pair of boundary rows and collapsing the matrix between them into a 1D array via column sums, then running Kadane's on that collapsed array.

### Key Insight
For any fixed pair `(top, bottom)`, the best rectangle using exactly those row boundaries is the best contiguous *column range*, found by running 1D Kadane's on the column sums between those rows. Trying every row pair and keeping the best result covers all possible rectangles.

### Approach
For each `top` from 0 to m-1: maintain a running `colSum` array, initialized to zero. For each `bottom` from `top` to m-1: add `matrix[bottom][c]` into `colSum[c]` for every column, then run 1D Kadane's on `colSum` to find the best contiguous column range for this row pair. Track the global best across all `(top, bottom)` pairs.

### Solution

```js
function maxSubArray1D(arr) {
  let curMax = arr[0], best = arr[0];
  for (let i = 1; i < arr.length; i++) {
    curMax = Math.max(arr[i], curMax + arr[i]);
    best = Math.max(best, curMax);
  }
  return best;
}

function maxSumRectangle(matrix) {
  const m = matrix.length, n = matrix[0].length;
  let best = -Infinity;

  for (let top = 0; top < m; top++) {
    const colSum = new Array(n).fill(0);

    for (let bottom = top; bottom < m; bottom++) {
      for (let c = 0; c < n; c++) {
        colSum[c] += matrix[bottom][c]; // accumulate rows top..bottom
      }
      best = Math.max(best, maxSubArray1D(colSum)); // 1D Kadane's on collapsed row
    }
  }

  return best;
}
```

### Dry Run

```
matrix (3x3 for brevity):
[[1, -2, 3],
 [4, 5, -1],
 [-2, 3, 4]]

top=0:
  colSum=[0,0,0]
  bottom=0: colSum=[1,-2,3]  → Kadane's([1,-2,3]) = 3
    best=3
  bottom=1: colSum=[5,3,2]   → Kadane's([5,3,2]) = 10
    best=10
  bottom=2: colSum=[3,6,6]   → Kadane's([3,6,6]) = 15
    best=15

top=1:
  colSum=[0,0,0]
  bottom=1: colSum=[4,5,-1]  → Kadane's([4,5,-1]) = 9
    best still 15
  bottom=2: colSum=[2,8,3]   → Kadane's([2,8,3]) = 13
    best still 15

top=2:
  colSum=[0,0,0]
  bottom=2: colSum=[-2,3,4]  → Kadane's([-2,3,4]) = 7
    best still 15

Answer: 15 ✓ (rows 0-2, columns 1-2: [-2+3, 5+-1, 3+4] wait —
 actual winning window is rows 0-2, all 3 columns: sum=3+10... 
 traced value confirms 15 from the row-collapse at top=0,bottom=2)
```

### Complexity
- Time: O(m² × n) — O(m²) row pairs, each doing O(n) work (column accumulation + 1D Kadane's).
- Space: O(n) — the `colSum` array.
- If `n < m`, transpose the matrix first and iterate over column pairs instead, to keep the O(n²) factor on the smaller dimension.

### Edge Cases
- Single row matrix: reduces directly to 1D Kadane's — `top = bottom = 0` is the only iteration.
- Single column matrix: `colSum` has one entry; Kadane's on a single-element array just returns that element.
- All negative matrix: the answer is the single largest (least negative) cell — 1D Kadane's on each collapsed row correctly returns this since it's seeded with the first element, not zero.

### Follow-up Questions
- "What if you also need the actual rectangle's boundaries, not just the sum?" → Combine with the start/end index tracking from Problem 2 inside the 1D Kadane's call, then map the resulting column range back to `(top, bottom, colStart, colEnd)`.
- "Can this be done faster than O(m² × n)?" → Not with a fundamentally different asymptotic approach for the general case — O(m² × n) (or O(min(m,n)² × max(m,n)) after choosing the smaller dimension to square) is the standard accepted complexity for this problem.

## Problem 6 — Best Time to Buy and Sell Stock (Single Transaction)

### Problem
Given an array `prices` where `prices[i]` is the price of a stock on day `i`, find the maximum profit from a single buy followed by a single sell (buy must happen before sell). Return 0 if no profit is possible.

```
Input:  prices = [7, 1, 5, 3, 6, 4]
Output: 5   (buy at 1, sell at 6)

Input:  prices = [7, 6, 4, 3, 1]
Output: 0   (prices only fall — no profitable transaction)
```

### Pattern Recognition
This is Kadane's algorithm in disguise: transform the price array into a **daily change array** (`prices[i] - prices[i-1]`), and the answer becomes the maximum subarray sum of that change array — the best contiguous run of gains.

### Key Insight
Profit from buying on day `l` and selling on day `r` equals `prices[r] - prices[l]`, which is exactly the sum of daily deltas `delta[l+1] + delta[l+2] + ... + delta[r]` where `delta[i] = prices[i] - prices[i-1]`. Maximizing this sum over any contiguous range of deltas is precisely the maximum subarray sum problem, with the additional constraint that a "no transaction" (profit 0) is always a valid fallback.

### Approach
Either explicitly build the delta array and run Kadane's, or track it implicitly with a running minimum price seen so far and the best profit achievable by selling today — these are equivalent formulations.

### Solution

```js
// Formulation A: explicit Kadane's on price deltas
function maxProfitKadane(prices) {
  let currentMax = 0, globalMax = 0;

  for (let i = 1; i < prices.length; i++) {
    const delta = prices[i] - prices[i - 1];
    currentMax = Math.max(0, currentMax + delta); // reset floor at 0 = "no transaction"
    globalMax = Math.max(globalMax, currentMax);
  }

  return globalMax;
}

// Formulation B: running minimum (equivalent, more common phrasing)
function maxProfitRunningMin(prices) {
  let minPriceSoFar = prices[0], maxProfit = 0;

  for (let i = 1; i < prices.length; i++) {
    maxProfit = Math.max(maxProfit, prices[i] - minPriceSoFar);
    minPriceSoFar = Math.min(minPriceSoFar, prices[i]);
  }

  return maxProfit;
}
```

### Dry Run

```
prices = [7, 1, 5, 3, 6, 4]
deltas (from i=1): [1-7, 5-1, 3-5, 6-3, 4-6] = [-6, 4, -2, 3, -2]

Kadane's on deltas (floor at 0):
currentMax=0, globalMax=0

delta=-6: currentMax=max(0, 0-6)=0        globalMax=0
delta=4:  currentMax=max(0, 0+4)=4        globalMax=4
delta=-2: currentMax=max(0, 4-2)=2        globalMax=4
delta=3:  currentMax=max(0, 2+3)=5        globalMax=5
delta=-2: currentMax=max(0, 5-2)=3        globalMax=5

Answer: 5 ✓ (matches buy at 1, sell at 6)
```

### Complexity
- Time: O(n) — single pass, either formulation.
- Space: O(1) — running variables only (no need to materialize the full delta array).

### Edge Cases
- Strictly decreasing prices: every delta is negative; `currentMax` stays floored at 0 → `globalMax = 0`, correctly signaling "don't transact."
- Single price (array length 1): no valid transaction possible → return 0 (loop never executes in either formulation).
- All identical prices: every delta is 0 → `globalMax = 0` — correct, no profit possible.

### Follow-up Questions
- "What if multiple transactions are allowed (buy/sell repeatedly)?" → Different greedy: sum every positive daily delta (`prices[i] - prices[i-1]` when positive), since you can capture every uptick independently.
- "What if there's a transaction fee or cooldown period?" → Requires a fuller DP with explicit "holding" and "not holding" states per day — Kadane's alone no longer suffices once state beyond the immediately preceding value matters.

## Quick Reference — Pattern Decision Tree

```
Does the problem ask for a maximum (or minimum) contiguous subarray/subrange?
│
├── MAXIMUM SUM, no extra constraints
│   └── Kadane's Algorithm → O(n) time, O(1) space
│
├── MAXIMUM SUM + need the actual (start, end) window
│   └── Kadane's + track reset index → O(n) time, O(1) space
│
├── MAXIMUM SUM, array is CIRCULAR (wraps around)
│   └── Kadane's (max) + Kadane's (min) → answer = max(kadaneMax, total - kadaneMin)
│       with an all-negative guard
│
├── MAXIMUM PRODUCT (not sum)
│   └── Track running max AND min simultaneously, swap on negative → O(n), O(1)
│
├── MAXIMUM SUM SUB-RECTANGLE in a 2D matrix
│   └── Fix row pairs, collapse to 1D via column sums, run 1D Kadane's
│       → O(m² × n) or O(min(m,n)² × max(m,n))
│
├── SINGLE BUY/SELL MAX PROFIT (stock-price style)
│   └── Kadane's on price deltas (floor at 0) ≡ running-minimum formulation
│
├── COUNT of subarrays with a specific sum (not "the max")
│   └── NOT Kadane's — use Prefix Sum + Hash Map instead
│
└── MAXIMUM SUM with at most k elements SKIPPED
    └── Kadane's-style DP with an extra "skip budget" dimension → O(nk)
```

## Common Bugs Checklist

Before submitting any Kadane's algorithm solution, verify:

1. **Correct initialization?** — `currentMax` and `globalMax` must be seeded with `nums[0]`, never with `0`. Seeding with `0` silently breaks all-negative arrays by allowing an invalid "empty subarray" to win.

2. **Reset condition correct?** — `currentMax = max(nums[i], currentMax + nums[i])`, not `max(0, currentMax + nums[i])` — the latter is only correct for problems (like max-profit) where a "do nothing" fallback of 0 is explicitly valid.

3. **Product variant swaps on negative?** — For maximum product subarray, forgetting to swap `curMax`/`curMin` before updating on a negative number is the single most common bug — it silently drops the case where two negatives multiply into a new maximum.

4. **Circular variant's all-negative guard?** — Without checking `maxSum < 0` before computing `total - minSum`, an all-negative array incorrectly returns 0 (an invalid empty wraparound selection) instead of the correct least-negative element.

5. **2D extension direction?** — Always collapse along the *larger* dimension's rows/columns and square the *smaller* dimension for row/column pairs, to keep the O(m² × n) factor as small as possible.

6. **Off-by-one in index tracking?** — When recovering `(start, end)`, the reset index (`tempStart`) must be committed to `start` only when `globalMax` actually improves — committing on every reset (even non-winning ones) gives wrong boundaries.

**Final Tip:** At the 5 YOE level, interviewers expect instant recognition of "maximum contiguous subarray, no target sum" as Kadane's algorithm, and expect you to articulate the single-line intuition before coding: "at each index, either extend the previous run or start fresh — whichever gives a bigger sum right now." From there, the circular, product, 2D, and stock-profit variants are all "Kadane's plus one twist" — stating which twist applies (min-tracking for circular, dual max/min for product, row-collapsing for 2D, delta-transform for stock profit) is the strongest signal of real understanding versus memorized code.
