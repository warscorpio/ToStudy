# DSA: Prefix Sum & Difference Arrays — Theory, Interview Q&A & Practical Problems

---

## Part 1 — Theory & Interview Q&A

---

### Section 1: Fundamentals

**Q1. What is a prefix sum array?**
A: A prefix sum array `pre` is a precomputed auxiliary array where `pre[i]` stores the sum of all elements from index `0` to `i` (inclusive) of the original array. Once built in O(n), it answers any subarray sum query `sum(l, r)` in O(1) — no recomputation, no re-traversal. It is one of the most fundamental preprocessing techniques in DSA, applicable wherever repeated range queries over a static array are needed.

```
Original:   [3,  1,  4,  1,  5,  9,  2,  6]
Prefix:     [3,  4,  8,  9, 14, 23, 25, 31]

pre[i] = original[0] + original[1] + ... + original[i]
```

**Q2. How do you build a prefix sum array?**
A: One forward pass — each entry is the previous prefix sum plus the current element:

```js
function buildPrefix(nums) {
  const pre = new Array(nums.length);
  pre[0] = nums[0];
  for (let i = 1; i < nums.length; i++) {
    pre[i] = pre[i - 1] + nums[i];
  }
  return pre;
}
```

Time: O(n). Space: O(n). After this, `pre[i]` is the sum of `nums[0..i]`.

**Q3. How do you query the sum of any subarray `[l, r]` using the prefix array?**
A: Use the subtraction formula:

```
sum(l, r) = pre[r] - pre[l - 1]     (when l > 0)
sum(0, r) = pre[r]                   (when l = 0)
```

The formula works because `pre[r]` includes elements from index 0 to r, and `pre[l-1]` includes elements from index 0 to l−1 — subtracting removes exactly the elements before index l, leaving the sum from l to r.

```js
function rangeSum(pre, l, r) {
  return l === 0 ? pre[r] : pre[r] - pre[l - 1];
}
```

**Q4. What is the "sentinel" (or "shifted") prefix sum pattern, and why is it useful?**
A: Add a leading zero to make the formula uniform — no special case for `l === 0`:

```js
function buildPrefixSentinel(nums) {
  const pre = new Array(nums.length + 1).fill(0);
  for (let i = 0; i < nums.length; i++) {
    pre[i + 1] = pre[i] + nums[i]; // pre[0] = 0 is the sentinel
  }
  return pre;
}

// query: sum of nums[l..r]
function rangeSum(pre, l, r) {
  return pre[r + 1] - pre[l]; // always works, no l===0 check needed
}
```

`pre[0] = 0` acts as a sentinel — `rangeSum(pre, 0, r) = pre[r+1] - pre[0] = pre[r+1]`. This is the preferred pattern in competitive programming and interviews because it eliminates the edge-case branch entirely.

**Q5. What is the time and space complexity of the prefix sum technique?**
A:
- **Build**: O(n) time, O(n) space.
- **Query**: O(1) time per query.
- **Total for q queries**: O(n + q) — compare to O(n × q) for recomputing each range sum naively.

The technique is worth using whenever q ≫ 1 and the array is static (doesn't change between queries). If the array is updated frequently, a more advanced structure (Fenwick tree / Binary Indexed Tree, or Segment Tree) is needed — those support both updates and queries in O(log n).

**Q6. What happens to prefix sum when the array has updates (mutable array)?**
A: A prefix sum array is a static preprocessing structure — any update to `nums[i]` invalidates all `pre[j]` for `j >= i` and requires an O(n) rebuild. For mutable arrays with range queries use:
- **Fenwick Tree (BIT)**: O(log n) point update + O(log n) prefix query. Simpler to implement.
- **Segment Tree**: O(log n) range update + O(log n) range query. More general (supports non-sum aggregates like max/min/gcd).

Prefix sums are the right tool when the array is read-only after initial construction — which covers most interview problems.

### Section 2: 2D Prefix Sums

**Q7. How do you extend prefix sums to a 2D matrix?**
A: Build a 2D prefix sum table `pre[i][j]` = sum of all elements in the rectangle `[0..i][0..j]` (top-left to `(i,j)`). Built using the inclusion-exclusion principle:

```
pre[i][j] = matrix[i][j]
           + pre[i-1][j]    (sum of rectangle above)
           + pre[i][j-1]    (sum of rectangle to the left)
           - pre[i-1][j-1]  (subtracted because it was added twice)
```

With a sentinel row and column of zeros (1-indexed), the formula becomes uniform:

```js
function build2DPrefix(matrix) {
  const m = matrix.length, n = matrix[0].length;
  const pre = Array.from({length: m + 1}, () => new Array(n + 1).fill(0));

  for (let i = 1; i <= m; i++) {
    for (let j = 1; j <= n; j++) {
      pre[i][j] = matrix[i-1][j-1]
                + pre[i-1][j]
                + pre[i][j-1]
                - pre[i-1][j-1];
    }
  }
  return pre;
}
```

**Q8. How do you query the sum of a sub-rectangle in a 2D prefix sum?**
A: Given top-left `(r1, c1)` and bottom-right `(r2, c2)` (0-indexed in original matrix, 1-indexed in prefix table):

```
sum = pre[r2+1][c2+1]
    - pre[r1][c2+1]      (remove rectangle above)
    - pre[r2+1][c1]      (remove rectangle to the left)
    + pre[r1][c1]        (add back the corner subtracted twice)
```

```js
function query2D(pre, r1, c1, r2, c2) {
  return pre[r2+1][c2+1]
       - pre[r1][c2+1]
       - pre[r2+1][c1]
       + pre[r1][c1];
}
```

O(1) per query after O(m×n) build. This is the direct 2D analogue of the 1D formula.

**Q9. What interview problems require 2D prefix sums?**
A: Any problem involving repeated sum queries over rectangular sub-regions of a matrix:
- "Number of rectangles with sum equal to target" — fix two rows, reduce to 1D subarray sum using column prefix sums.
- "Maximal square of 1s" — prefix sum counts of 1s in sub-rectangles (though DP is more common for the classic version).
- "Count sub-matrices that sum to target" — 2D prefix sum + hash map, O(m² × n).
- "Image smoothing / box blur" — compute average over k×k windows using 2D prefix sums in O(1) per window instead of O(k²).

### Section 3: Difference Arrays

**Q10. What is a difference array?**
A: A difference array `diff` transforms the problem of applying multiple range updates into O(1) updates each, with a final O(n) reconstruction pass. `diff[i]` stores the *change* from `nums[i-1]` to `nums[i]`:

```
diff[0] = nums[0]
diff[i] = nums[i] - nums[i-1]   (for i > 0)
```

The original array is recoverable from `diff` by taking the prefix sum of `diff`:
```
nums[i] = diff[0] + diff[1] + ... + diff[i]
```

**Q11. How do you apply a range update using a difference array?**
A: To add value `v` to every element in `nums[l..r]`:
```
diff[l]     += v   // range starts here — increase begins
diff[r + 1] -= v   // range ends here — increase stops (guard: r+1 <= n)
```

After all updates are applied to `diff`, reconstruct the final array with a single prefix sum pass. Each update is O(1); reconstruction is O(n) once at the end.

```js
function applyRangeUpdates(n, updates) {
  // updates = [[l, r, v], ...] — add v to nums[l..r]
  const diff = new Array(n + 1).fill(0); // +1 guard for r+1 = n

  for (const [l, r, v] of updates) {
    diff[l] += v;
    if (r + 1 <= n) diff[r + 1] -= v;
  }

  // reconstruct: prefix sum of diff = final array
  const result = new Array(n).fill(0);
  result[0] = diff[0];
  for (let i = 1; i < n; i++) {
    result[i] = result[i - 1] + diff[i];
  }
  return result;
}
```

**Q12. Why does the difference array trick work?**
A: The difference array is the discrete derivative of the original array — `diff[i]` encodes the slope change at position `i`. Adding `v` to a range `[l, r]` means the value rises by `v` at `l` and falls by `v` after `r`. Encoding this as two point updates (`+v` at `l`, `-v` at `r+1`) captures the slope change at both ends. Taking the prefix sum of `diff` (integration) reconstructs the actual values — the `+v` propagates from `l` rightward and the `-v` cancels it after `r`. Mathematically: prefix sum and difference array are inverses of each other.

**Q13. What is the time complexity comparison between naïve range updates and the difference array approach?**
A:
- **Naïve**: each range update iterates over `r - l + 1` elements → O(n) per update. With k updates before a single read: O(n × k) total.
- **Difference array**: each update is O(1); one O(n) reconstruction at the end → O(k + n) total.

The difference array wins decisively when k is large (many updates before the final array is needed) and the updates must be applied before reconstruction. If queries interleave with updates, a different structure is needed.

**Q14. What is the relationship between prefix sum and difference array?**
A: They are inverse operations — dual structures:
- **Prefix sum of array A**: transforms A into P where `P[i] = A[0] + ... + A[i]` (integration / accumulation).
- **Difference array of array A**: transforms A into D where `D[i] = A[i] - A[i-1]` (differentiation / change).
- `prefix_sum(difference_array(A)) = A` — taking the prefix sum of the difference array reconstructs A.
- `difference_array(prefix_sum(A))` = A — taking the difference of the prefix sum also reconstructs A.

This duality means: when you need O(1) range queries after O(n) build → prefix sum. When you need O(1) range updates with O(n) final read → difference array.

**Q15. Can prefix sum and difference array be combined?**
A: Yes — for problems requiring both range updates and range queries efficiently on a static-size array. Apply all updates via the difference array (O(1) each), then build a prefix sum of the reconstructed array for O(1) range queries. Total: O(k + n) updates + O(n) build + O(1) per query. This is sufficient for many interview problems that separate the "update phase" from the "query phase." For interleaved updates and queries, use a Fenwick tree or Segment tree.

### Section 4: Subarray Sum Problems

**Q16. How does prefix sum help find subarrays with a given sum?**
A: The key insight: `sum(l, r) = target` ↔ `pre[r] - pre[l-1] = target` ↔ `pre[l-1] = pre[r] - target`. So as you compute `pre[r]` left to right, you ask: "have I seen the value `pre[r] - target` before?" A hash map from prefix sum value to count answers this in O(1). This turns a naive O(n²) subarray search into O(n) with O(n) space.

```js
function subarraySum(nums, target) {
  const prefixCount = new Map([[0, 1]]); // sentinel: empty prefix has sum 0
  let prefixSum = 0, count = 0;

  for (const num of nums) {
    prefixSum += num;
    count += prefixCount.get(prefixSum - target) || 0;
    prefixCount.set(prefixSum, (prefixCount.get(prefixSum) || 0) + 1);
  }

  return count;
}
```

The `Map([[0, 1]])` sentinel handles subarrays starting at index 0 (where `pre[l-1] = pre[-1] = 0`).

**Q17. Why does the hash map need `[0, 1]` as an initial entry?**
A: Without it, subarrays starting from index 0 are missed. If `prefixSum === target` at some index `i`, then the subarray `nums[0..i]` has sum = target — `pre[l-1] = pre[-1] = 0` is what we look up. The sentinel `0 → 1` ensures this lookup succeeds. Without it, those subarrays are silently uncounted — a classic off-by-one that's easy to get wrong under interview pressure.

**Q18. How does prefix sum apply to problems with negative numbers — where sliding window fails?**
A: Sliding window requires monotonic properties (adding always increases, removing always decreases) — negative numbers break this. Prefix sum + hash map handles negative numbers naturally because it doesn't depend on monotonicity. `pre[r] - pre[l-1] = target` works for any integer values. This is why "subarray sum equals k" uses prefix sum even though it looks superficially similar to sliding window problems.

**Q19. What is the "subarray with sum divisible by k" pattern, and how does modular arithmetic extend prefix sums?**
A: `sum(l, r) % k === 0` ↔ `pre[r] % k === pre[l-1] % k`. So two indices with the same prefix sum modulo k form a valid subarray. Walk left to right, storing `(prefixSum % k)` values in a hash map. For each new `rem = prefixSum % k`, the number of valid subarrays ending here equals how many times `rem` appeared before. Handle negative remainders: `rem = ((prefixSum % k) + k) % k` to normalize to `[0, k-1]` in languages where `%` can return negative values.

**Q20. What is the "longest subarray with sum equal to k" pattern?**
A: Store the *first* index at which each prefix sum is seen (not the count). For each `pre[r]`, if `pre[r] - k` was seen at index `l-1`, then the subarray `nums[l..r]` has sum k and length `r - (l-1) = r - l + 1`. Record the maximum such length:

```js
function longestSubarraySum(nums, k) {
  const firstSeen = new Map([[0, -1]]); // sentinel: prefix sum 0 seen at index -1
  let prefixSum = 0, maxLen = 0;

  for (let i = 0; i < nums.length; i++) {
    prefixSum += nums[i];
    if (firstSeen.has(prefixSum - k)) {
      maxLen = Math.max(maxLen, i - firstSeen.get(prefixSum - k));
    }
    if (!firstSeen.has(prefixSum)) { // only store the FIRST occurrence
      firstSeen.set(prefixSum, i);
    }
  }
  return maxLen;
}
```

Storing only the first occurrence maximizes the length — an earlier `l` gives a longer `[l..r]` span.

### Section 5: Advanced Patterns & Trade-offs

**Q21. When should you choose prefix sum over a sliding window?**
A:
- **Array has negative numbers** → prefix sum (sliding window needs monotonicity).
- **Problem asks for count of subarrays** (not just existence or max length) → prefix sum + hash map.
- **Problem involves modular conditions** (`sum % k`) → prefix sum with modular hash map.
- **Multiple independent range queries on a static array** → prefix sum for O(1) per query.
- **All values positive, looking for min/max length window** → sliding window (O(1) space vs O(n) for prefix sum).

**Q22. What is the "running XOR prefix" technique, and what problems does it solve?**
A: Replace addition with XOR in the prefix structure. `pre[i] = nums[0] XOR nums[1] XOR ... XOR nums[i]`. Then `XOR(l, r) = pre[r] XOR pre[l-1]` because XOR is its own inverse (`a XOR a = 0`). Used in:
- "Find the subarray with XOR equal to k" → same hash map pattern as sum.
- "Single number" problems — XOR all elements; pairs cancel out.
- "Find missing number" — XOR 1..n with all array elements.
The prefix XOR pattern is identical structurally to prefix sum — just swap `+` for `^` and `subtraction` for `XOR`.

**Q23. How do you handle a 2D difference array for rectangle range updates?**
A: To add value `v` to all cells in rectangle `(r1,c1)` to `(r2,c2)`:
```
diff[r1][c1]     += v
diff[r1][c2+1]   -= v
diff[r2+1][c1]   -= v
diff[r2+1][c2+1] += v
```
After all updates, reconstruct the 2D array by applying 2D prefix sums (row-wise then column-wise). This is the 2D analogue of the 1D difference array — each update is O(1), reconstruction is O(m×n). Used in problems like "corporate flight bookings" extended to a grid, or "bombing enemies."

**Q24. What are the space optimization opportunities for prefix sums?**
A: In many problems, you don't need to store the full prefix array — just a running variable:
- **Running prefix**: if you only need `pre[i]` once before moving to `i+1`, use a single `prefixSum` variable updated in-place — O(1) space instead of O(n).
- **Hash map over full prefix array**: for subarray count/length problems, the hash map replaces the prefix array — still O(n) space, but you never store all prefix values simultaneously.
- **Reuse input array**: some problems allow overwriting the original array with prefix sums in-place — O(1) extra space (though this destroys original values, so confirm it's allowed).

### Section 6: Scenario / Interview-Style Questions

**Q25. "You have a large read-only array and need to answer 10,000 range sum queries on it. How do you design this efficiently?"**
A: Build a prefix sum array once in O(n). Each of the 10,000 queries answers in O(1) using `pre[r] - pre[l-1]`. Total: O(n + q) where q = 10,000. Compare to naive O(n × q) = O(10,000n) — prefix sum is 10,000× faster on the query side. If the array is updated between queries → switch to a Fenwick tree (O(log n) per update and query). State this trade-off explicitly.

**Q26. "A logistics company applies thousands of price adjustments to delivery zones (each covering a contiguous range of zip codes). At the end of the day, they read every zone's final price. Design the data structure."**
A: Classic difference array use case. Represent zip codes as indices 0..n-1. Each price adjustment is a range update `[l, r, +v]` or `[l, r, -v]`. Apply each update to a difference array in O(1). At end of day, reconstruct the final prices with a single O(n) prefix sum pass. Total: O(k + n) for k adjustments and n zones — far better than O(k × n) if updates were applied naively.

**Q27. "During a code review, a colleague iterates over the original array inside every range sum query — O(n) per query inside an O(n) outer loop, making it O(n²) overall. How do you fix it without changing the algorithm's structure significantly?"**
A: Add a one-time O(n) prefix sum build before the outer loop. Replace the inner loop's sum computation with `pre[r] - pre[l-1]` — O(1). The outer loop's O(n) iterations each now cost O(1) → total O(n). This is the canonical prefix-sum optimization and the exact situation it was designed for. Mention also: this only works if the array doesn't change during the outer loop; if it does, a Fenwick tree is needed.

**Q28. "You're asked to find the number of subarrays whose sum equals k in an array that includes negative numbers. A teammate suggests using sliding window. What do you tell them, and what do you use instead?"**
A: Sliding window requires all values to be positive — it relies on the monotonic property that adding elements always increases the sum. With negative numbers, adding an element can decrease the sum, so there's no principled way to decide when to expand or contract the window. The correct approach is prefix sum + hash map: compute running prefix sums, check `prefixCount[prefixSum - k]` at each step. O(n) time, O(n) space, handles any integer values including negatives.

## Problem 1 — Range Sum Query (Static Array)

### Problem
Given an integer array `nums`, handle multiple queries of the form `sumRange(left, right)` — return the sum of elements between indices `left` and `right` (inclusive). The array does not change after initialization.

```
Input:  nums = [-2, 0, 3, -5, 2, -1]
Queries: sumRange(0,2) → 1, sumRange(2,5) → -1, sumRange(0,5) → -3
```

### Pattern Recognition
Multiple range sum queries on a static array — textbook prefix sum. Build once, query in O(1).

### Key Insight
`sum(l, r) = pre[r+1] - pre[l]` using the sentinel (shifted) prefix array.

### Approach
Build `pre[0..n]` where `pre[0] = 0` and `pre[i] = pre[i-1] + nums[i-1]`. Every query becomes a subtraction of two prefix values.

### Solution

```js
class NumArray {
  constructor(nums) {
    const n = nums.length;
    this.pre = new Array(n + 1).fill(0); // pre[0] = 0 sentinel

    for (let i = 0; i < n; i++) {
      this.pre[i + 1] = this.pre[i] + nums[i];
    }
    // pre[i] = sum of nums[0..i-1]
    // pre[i+1] - pre[j] = sum of nums[j..i]
  }

  sumRange(left, right) {
    return this.pre[right + 1] - this.pre[left];
    // sum of nums[left..right]
    // = (sum of nums[0..right]) - (sum of nums[0..left-1])
    // = pre[right+1] - pre[left]
  }
}
```

### Dry Run

```
nums = [-2, 0, 3, -5, 2, -1]

Build prefix (sentinel):
pre[0] = 0
pre[1] = 0 + (-2) = -2
pre[2] = -2 + 0 = -2
pre[3] = -2 + 3 = 1
pre[4] = 1 + (-5) = -4
pre[5] = -4 + 2 = -2
pre[6] = -2 + (-1) = -3

pre = [0, -2, -2, 1, -4, -2, -3]

sumRange(0, 2): pre[3] - pre[0] = 1 - 0 = 1 ✓
sumRange(2, 5): pre[6] - pre[2] = -3 - (-2) = -1 ✓
sumRange(0, 5): pre[6] - pre[0] = -3 - 0 = -3 ✓
```

### Complexity
- Build: O(n) time, O(n) space.
- Query: O(1) time.
- Total for q queries: O(n + q).

### Edge Cases
- Single element: `sumRange(0, 0) = pre[1] - pre[0] = nums[0]` — correct.
- Entire array: `sumRange(0, n-1) = pre[n] - pre[0] = pre[n]` — correct.
- Negative values: formula handles any integers — no special casing needed.
- `left === right`: point query, returns `nums[left]` — correct.

### Follow-up Questions
- "What if the array is updated between queries?" → Replace with a Fenwick tree (BIT): O(log n) update, O(log n) query.
- "What if queries are for the maximum of a range instead of sum?" → Prefix sum doesn't generalize to max (max is not invertible). Use a Segment tree or Sparse table for O(1) range max queries.

## Problem 2 — Subarray Sum Equals K

### Problem
Given an integer array `nums` and an integer `k`, return the total number of subarrays whose sum equals `k`. The array may contain negative numbers.

```
Input:  nums = [1, 1, 1], k = 2
Output: 2  ([1,1] at indices [0,1] and [1,2])

Input:  nums = [1, 2, 3], k = 3
Output: 2  ([3] and [1,2])

Input:  nums = [-1, -1, 1], k = 0
Output: 1  ([-1, -1, 1])
```

### Pattern Recognition
Count of subarrays with a given sum, array may have negatives → sliding window fails → prefix sum + hash map. The formula `sum(l,r) = pre[r] - pre[l-1] = k` means we look up `pre[r] - k` in a map of previously seen prefix sums.

### Key Insight
For every position `r`, count how many previous prefix sums equal `pre[r] - k`. Each such previous position `l-1` gives a valid subarray `nums[l..r]`. A hash map from prefix sum value → count of occurrences answers this in O(1).

### Approach
Walk left to right maintaining `prefixSum`. At each step, check how many times `prefixSum - k` has appeared in the map — that's the count of valid subarrays ending at the current index. Then record the current `prefixSum` in the map.

### Solution

```js
function subarraySum(nums, k) {
  // sentinel: prefix sum of 0 has been seen once (represents the empty prefix)
  const prefixCount = new Map([[0, 1]]);
  let prefixSum = 0;
  let count = 0;

  for (const num of nums) {
    prefixSum += num;

    // how many previous prefixes sum to (prefixSum - k)?
    // each one forms a valid subarray ending here
    count += prefixCount.get(prefixSum - k) || 0;

    // record current prefix sum
    prefixCount.set(prefixSum, (prefixCount.get(prefixSum) || 0) + 1);
  }

  return count;
}
```

### Dry Run

```
nums = [1, 1, 1], k = 2
prefixCount = {0:1}, prefixSum = 0, count = 0

num=1: prefixSum=1, look up (1-2)=-1 → not in map → count=0
       map={0:1, 1:1}

num=1: prefixSum=2, look up (2-2)=0 → in map, count=1 → count=1
       map={0:1, 1:1, 2:1}

num=1: prefixSum=3, look up (3-2)=1 → in map, count=1 → count=2
       map={0:1, 1:1, 2:1, 3:1}

Answer: 2 ✓
```

```
nums = [-1, -1, 1], k = 0
prefixCount = {0:1}, prefixSum = 0, count = 0

num=-1: prefixSum=-1, look up (-1-0)=-1 → not in map → count=0
        map={0:1, -1:1}

num=-1: prefixSum=-2, look up (-2-0)=-2 → not in map → count=0
        map={0:1, -1:1, -2:1}

num=1:  prefixSum=-1, look up (-1-0)=-1 → in map (count=1) → count=1
        map={0:1, -1:2, -2:1}

Answer: 1 ✓
```

### Complexity
- Time: O(n) — one pass, O(1) hash map operations.
- Space: O(n) — hash map stores at most n+1 distinct prefix sums.

### Edge Cases
- All negative numbers: prefix sums are decreasing; hash map handles them correctly.
- `k = 0`: subarrays that sum to zero — the sentinel `{0:1}` ensures that a prefix sum of 0 at any position counts subarrays from index 0.
- Duplicate prefix sums: the map stores counts, not just presence — multiple subarrays with the same prefix sum are all counted correctly.
- Single element equal to k: `prefixSum = k`, look up `k - k = 0` → sentinel gives count 1. Correct.

### Follow-up Questions
- "Find the actual subarrays, not just the count?" → Store `prefix → [list of indices]` instead of counts; reconstruct subarray bounds from the stored indices.
- "Maximum length subarray with sum k?" → Store `prefix → first index seen` instead of counts; track max `i - firstSeen[prefixSum - k]`.
- "Number of subarrays with sum divisible by k?" → Store `(prefixSum % k)` as map key instead of `prefixSum`.

## Problem 3 — Product of Array Except Self

### Problem
Given an integer array `nums`, return an array `answer` where `answer[i]` is the product of all elements of `nums` except `nums[i]`. You must run in O(n) without using the division operation.

```
Input:  nums = [1, 2, 3, 4]
Output: [24, 12, 8, 6]

Input:  nums = [-1, 1, 0, -3, 3]
Output: [0, 0, 9, 0, 0]
```

### Pattern Recognition
`answer[i]` = (product of all elements to the left of i) × (product of all elements to the right of i). This is a prefix product (left pass) multiplied by a suffix product (right pass) — the multiplicative analogue of prefix sum.

### Key Insight
Build a prefix product array `left[i]` = product of `nums[0..i-1]` (everything left of i). Build a suffix product array `right[i]` = product of `nums[i+1..n-1]` (everything right of i). Then `answer[i] = left[i] * right[i]`.

**Space optimization**: compute left products into `answer` directly on the first pass; fold in right products on the second pass using a single running variable — O(1) extra space.

### Approach
Pass 1 (left to right): `answer[i]` = product of all elements before index i. Start with `answer[0] = 1` (nothing to the left).
Pass 2 (right to left): multiply `answer[i]` by the running product of all elements after index i. Running variable `rightProduct` starts at 1.

### Solution

```js
function productExceptSelf(nums) {
  const n = nums.length;
  const answer = new Array(n);

  // Pass 1: answer[i] = product of nums[0..i-1]
  answer[0] = 1; // nothing to the left of index 0
  for (let i = 1; i < n; i++) {
    answer[i] = answer[i - 1] * nums[i - 1];
  }
  // answer = [1, 1, 2, 6] for nums=[1,2,3,4]

  // Pass 2: multiply by product of nums[i+1..n-1] (right products)
  let rightProduct = 1; // nothing to the right of last index
  for (let i = n - 1; i >= 0; i--) {
    answer[i] *= rightProduct;       // fold in right product
    rightProduct *= nums[i];         // extend right product leftward
  }

  return answer;
}
```

### Dry Run

```
nums = [1, 2, 3, 4]

Pass 1 (left products):
answer[0] = 1
answer[1] = answer[0] * nums[0] = 1 * 1 = 1
answer[2] = answer[1] * nums[1] = 1 * 2 = 2
answer[3] = answer[2] * nums[2] = 2 * 3 = 6
answer = [1, 1, 2, 6]

Pass 2 (fold in right products, rightProduct starts at 1):
i=3: answer[3] *= 1 → answer[3]=6;  rightProduct = 1*4 = 4
i=2: answer[2] *= 4 → answer[2]=8;  rightProduct = 4*3 = 12
i=1: answer[1] *= 12 → answer[1]=12; rightProduct = 12*2 = 24
i=0: answer[0] *= 24 → answer[0]=24; rightProduct = 24*1 = 24

answer = [24, 12, 8, 6] ✓
```

### Complexity
- Time: O(n) — two linear passes.
- Space: O(1) extra (output array doesn't count per problem statement).

### Edge Cases
- Array contains zero(s): the running products become 0 where the zero propagates — handled naturally without special casing.
- Two or more zeros: all answers are 0 — correct (every product includes at least one 0).
- Array of length 2: `answer = [nums[1], nums[0]]` — both passes handle it correctly.
- Negative numbers: multiplication handles sign changes naturally.

### Follow-up Questions
- "What if division were allowed?" → Total product ÷ `nums[i]` — but breaks for zeros (division by zero). Need separate handling for zero count: 0 zeros → divide; 1 zero → only index of zero is non-zero; 2+ zeros → all zeros. Division approach is messier despite seeming simpler.
- "Extend to suffix sum / prefix max / prefix min?" → Same two-pass structure; replace multiplication with sum, max, or min as appropriate.

## Problem 4 — Contiguous Array (Equal 0s and 1s)

### Problem
Given a binary array `nums`, return the maximum length of a contiguous subarray with an equal number of 0s and 1s.

```
Input:  nums = [0, 1]
Output: 2

Input:  nums = [0, 1, 0]
Output: 2

Input:  nums = [0, 1, 1, 0, 1, 1, 1, 0]
Output: 4
```

### Pattern Recognition
"Equal count of two values in a subarray" — transform the problem to "subarray sum = 0" and apply the prefix sum + hash map pattern. Replace every 0 with -1; now a subarray with equal 0s and 1s has sum 0 (the 1s and -1s cancel).

### Key Insight
After the transformation: we need the longest subarray with sum = 0. Using prefix sums, `sum(l, r) = 0` ↔ `pre[r] = pre[l-1]`. Store the *first index* at which each prefix sum is seen. When you encounter the same prefix sum again at index `r`, the subarray from `firstSeen[pre[r]] + 1` to `r` has sum 0 — compute its length.

### Approach
Walk left to right. Maintain running `prefixSum` (with 0→-1 transformation). Store the first index each prefix sum is seen. On each step: if the current prefix sum was seen before at index `j`, update `maxLen = max(maxLen, i - j)`. If not seen, record it.

### Solution

```js
function findMaxLength(nums) {
  // sentinel: prefix sum 0 first seen at index -1
  // (before the array starts — represents the empty prefix)
  const firstSeen = new Map([[0, -1]]);
  let prefixSum = 0, maxLen = 0;

  for (let i = 0; i < nums.length; i++) {
    // transform: 0 → -1, 1 → +1
    prefixSum += nums[i] === 0 ? -1 : 1;

    if (firstSeen.has(prefixSum)) {
      // same prefix sum seen before at index j
      // subarray (j+1)..i has sum 0 → equal 0s and 1s
      maxLen = Math.max(maxLen, i - firstSeen.get(prefixSum));
    } else {
      // only store the FIRST occurrence to maximize subarray length
      firstSeen.set(prefixSum, i);
    }
  }

  return maxLen;
}
```

### Dry Run

```
nums = [0, 1, 1, 0, 1, 1, 1, 0]
transformed = [-1, 1, 1, -1, 1, 1, 1, -1]

firstSeen = {0: -1}, prefixSum = 0, maxLen = 0

i=0: prefixSum=0+(-1)=-1, not seen → firstSeen={0:-1, -1:0}
i=1: prefixSum=-1+1=0,    seen at j=-1 → len=1-(-1)=2 → maxLen=2
i=2: prefixSum=0+1=1,     not seen → firstSeen={..., 1:2}
i=3: prefixSum=1+(-1)=0,  seen at j=-1 → len=3-(-1)=4 → maxLen=4
i=4: prefixSum=0+1=1,     seen at j=2 → len=4-2=2 → maxLen=4
i=5: prefixSum=1+1=2,     not seen → firstSeen={..., 2:5}
i=6: prefixSum=2+1=3,     not seen → firstSeen={..., 3:6}
i=7: prefixSum=3+(-1)=2,  seen at j=5 → len=7-5=2 → maxLen=4

Answer: 4 ✓
```

### Complexity
- Time: O(n) — single pass, O(1) hash map operations.
- Space: O(n) — hash map stores at most n+1 prefix sums.

### Edge Cases
- All zeros: prefix sum keeps decreasing; never repeats → no valid subarray → return 0.
- All ones: same as above in the opposite direction.
- Single element: no equal subarray possible → return 0.
- Entire array is balanced: `pre[n-1]` comes back to 0 at the last index; `i - firstSeen[0] = n - (-1) = n+1`... wait — recalculate: `i - firstSeen.get(0) = (n-1) - (-1) = n`. Return n correctly.

### Follow-up Questions
- "Equal count of any two values (not just 0 and 1)?" → Map one value to +1 and the other to -1; same approach.
- "Count of subarrays with equal 0s and 1s (not just longest)?" → Use a count map instead of firstSeen; same pattern as subarray sum equals k.

## Problem 5 — Range Sum Query 2D (Immutable)

### Problem
Given a 2D matrix `matrix`, handle multiple queries of the form `sumRegion(row1, col1, row2, col2)` — return the sum of elements in the rectangle defined by its upper-left `(row1, col1)` and lower-right `(row2, col2)` corners.

```
matrix = [
  [3, 0, 1, 4, 2],
  [5, 6, 3, 2, 1],
  [1, 2, 0, 1, 5],
  [4, 1, 0, 1, 7],
  [1, 0, 3, 0, 5]
]

sumRegion(2,1,4,3) → 8
sumRegion(1,1,2,2) → 11
sumRegion(1,2,2,4) → 12
```

### Pattern Recognition
Multiple range sum queries on a static 2D matrix — 2D prefix sum. Build once in O(m×n), query in O(1).

### Key Insight
Inclusion-exclusion: `sum(r1,c1,r2,c2) = pre[r2+1][c2+1] - pre[r1][c2+1] - pre[r2+1][c1] + pre[r1][c1]`.

### Approach
Build `pre[i][j]` = sum of all elements in rectangle `(0,0)` to `(i-1, j-1)` (1-indexed with sentinel row/column of zeros). Each query uses the four-corner inclusion-exclusion formula.

### Solution

```js
class NumMatrix {
  constructor(matrix) {
    const m = matrix.length, n = matrix[0].length;
    // pre[i][j] = sum of matrix[0..i-1][0..j-1]
    this.pre = Array.from({length: m + 1}, () => new Array(n + 1).fill(0));

    for (let i = 1; i <= m; i++) {
      for (let j = 1; j <= n; j++) {
        this.pre[i][j] = matrix[i-1][j-1]
                        + this.pre[i-1][j]   // sum of rectangle above
                        + this.pre[i][j-1]   // sum of rectangle to the left
                        - this.pre[i-1][j-1];// remove the overlapping corner
      }
    }
  }

  sumRegion(row1, col1, row2, col2) {
    // inclusion-exclusion with 1-indexed prefix table
    return this.pre[row2+1][col2+1]
         - this.pre[row1][col2+1]     // remove rectangle above
         - this.pre[row2+1][col1]     // remove rectangle to the left
         + this.pre[row1][col1];      // add back the corner (subtracted twice)
  }
}
```

### Dry Run

```
matrix (3×3 for brevity):
[[3, 0, 1],
 [5, 6, 3],
 [1, 2, 0]]

Build pre (4×4 with sentinel row/col of 0):
pre[1][1] = 3 + 0 + 0 - 0 = 3
pre[1][2] = 0 + 3 + 0 - 0 = 3
pre[1][3] = 1 + 3 + 0 - 0 = 4
pre[2][1] = 5 + 3 + 0 - 0 = 8
pre[2][2] = 6 + 8 + 3 - 3 = 14
pre[2][3] = 3 + 14 + 4 - 3 = 18
pre[3][1] = 1 + 8 + 0 - 0 = 9
pre[3][2] = 2 + 9 + 14 - 8 = 17
pre[3][3] = 0 + 17 + 18 - 14 = 21

sumRegion(0,0,1,1): pre[2][2] - pre[0][2] - pre[2][0] + pre[0][0]
                  = 14 - 0 - 0 + 0 = 14
Manual check: 3+0+5+6 = 14 ✓

sumRegion(1,1,2,2): pre[3][3] - pre[1][3] - pre[3][1] + pre[1][1]
                  = 21 - 4 - 9 + 3 = 11
Manual check: 6+3+2+0 = 11 ✓
```

### Complexity
- Build: O(m×n) time, O(m×n) space.
- Query: O(1) time.
- Total for q queries: O(m×n + q).

### Edge Cases
- Single cell query `(r,c,r,c)`: `pre[r+1][c+1] - pre[r][c+1] - pre[r+1][c] + pre[r][c]` = `matrix[r][c]`. Correct.
- Query covering entire matrix `(0,0,m-1,n-1)`: `pre[m][n] - 0 - 0 + 0 = pre[m][n]`. Correct.
- Negative values: formula handles any integers.

### Follow-up Questions
- "What if the matrix is updated?" → 2D Fenwick tree for O(log m × log n) update and query.
- "Count sub-matrices with sum equal to target?" → For each pair of rows (r1, r2), collapse columns into a 1D array using prefix sums, then apply the 1D "subarray sum = k" hash map approach. O(m² × n).

## Problem 6 — Car Fleet / Corporate Flight Bookings (Difference Array)

### Problem
There are `n` seats on flights labeled `1` to `n`. You are given a list of `bookings` where `bookings[i] = [first, last, seats]` represents a booking for flights `first` through `last` (inclusive) for `seats` seats each. Return an array `answer` where `answer[i]` is the total number of seats booked on flight `i`.

```
Input:  n = 5, bookings = [[1,2,10],[2,3,20],[2,5,25]]
Output: [10, 55, 45, 25, 25]

Explanation:
Flight 1: booking 1 → 10
Flight 2: booking 1 + 2 + 3 → 10+20+25 = 55
Flight 3: booking 2 + 3 → 20+25 = 45
Flight 4: booking 3 → 25
Flight 5: booking 3 → 25
```

### Pattern Recognition
Multiple range additions followed by a single read of all values — textbook difference array. Each booking `[first, last, seats]` is a range update `+seats` to flights `first..last`. After all bookings, read the final seat count for each flight.

### Key Insight
Instead of incrementing every index in `[first..last]` for each booking (O(n) per booking), record `+seats` at `diff[first-1]` and `-seats` at `diff[last]` (using 1-based indices, 0-indexed array). One prefix sum pass reconstructs the final counts.

### Approach
- Create a `diff` array of size `n + 1` (extra slot for the sentinel subtraction).
- For each booking `[first, last, seats]`: `diff[first-1] += seats`, `diff[last] -= seats`.
- Prefix sum of `diff[0..n-1]` gives the final seat count per flight.

### Solution

```js
function corpFlightBookings(bookings, n) {
  const diff = new Array(n + 1).fill(0); // +1 for guard at diff[last]

  for (const [first, last, seats] of bookings) {
    diff[first - 1] += seats;  // 1-indexed flight → 0-indexed array
    diff[last] -= seats;       // sentinel: subtract after the range ends
  }

  // prefix sum reconstructs final counts
  const result = new Array(n);
  result[0] = diff[0];
  for (let i = 1; i < n; i++) {
    result[i] = result[i - 1] + diff[i];
  }

  return result;
}
```

### Dry Run

```
n=5, bookings=[[1,2,10],[2,3,20],[2,5,25]]
diff = [0, 0, 0, 0, 0, 0]  (size 6)

booking [1,2,10]: diff[0]+=10, diff[2]-=10 → diff=[10,0,-10,0,0,0]
booking [2,3,20]: diff[1]+=20, diff[3]-=20 → diff=[10,20,-10,-20,0,0]
booking [2,5,25]: diff[1]+=25, diff[5]-=25 → diff=[10,45,-10,-20,0,-25]

Prefix sum reconstruction:
result[0] = 10
result[1] = 10 + 45 = 55
result[2] = 55 + (-10) = 45
result[3] = 45 + (-20) = 25
result[4] = 25 + 0 = 25

Answer: [10, 55, 45, 25, 25] ✓
```

### Complexity
- Updates: O(k) for k bookings — each booking is O(1).
- Reconstruction: O(n).
- Total: O(k + n) vs O(k × n) naïve.

### Edge Cases
- Single flight booking `[i, i, seats]`: `diff[i-1] += seats`, `diff[i] -= seats` — only flight `i` is incremented. Correct.
- All bookings on the same range: sums accumulate at `diff[first-1]`; the sentinel subtraction cancels at `diff[last]`. Correct.
- `last === n` (booking covers last flight): `diff[n] -= seats` — this uses the guard index, safely within array bounds. Without the `+1` size, this would be an out-of-bounds write.
- Overlapping bookings of different lengths: difference array handles any overlap pattern naturally.

### Follow-up Questions
- "What if you also need range sum queries during the booking phase?" → Combine difference array (for updates) + prefix sum build (for queries) as a two-phase approach. If queries interleave with updates, use a Fenwick tree.
- "2D version: add v to all cells in a rectangle, then read the grid?" → 2D difference array: four point updates per rectangle update, one 2D prefix sum pass for reconstruction.

## Problem 7 — Minimum Value to Get Positive Step-by-Step Sum

### Problem
Given an array `nums`, return the minimum positive value of `startValue` such that the step-by-step sum (startValue + running prefix sum) is always ≥ 1 at every step.

```
Input:  nums = [-3, 2, -3, 4, 2]
Output: 5

Input:  nums = [1, 2]
Output: 1

Input:  nums = [1, -2, -3]
Output: 5
```

### Pattern Recognition
The running total at step `i` is `startValue + pre[i]`. We need `startValue + pre[i] >= 1` for all `i`, i.e., `startValue >= 1 - pre[i]` for all `i`. The binding constraint is the minimum prefix sum. So `startValue = max(1, 1 - minPrefixSum)`.

### Key Insight
Build the prefix sums. Find the minimum prefix sum. The required startValue ensures that even at the most negative prefix, the total is at least 1.

### Solution

```js
function minStartValue(nums) {
  let prefixSum = 0;
  let minPrefix = 0; // track the minimum prefix sum seen

  for (const num of nums) {
    prefixSum += num;
    minPrefix = Math.min(minPrefix, prefixSum);
  }

  // startValue + minPrefix >= 1 → startValue >= 1 - minPrefix
  return Math.max(1, 1 - minPrefix);
}
```

### Dry Run

```
nums = [-3, 2, -3, 4, 2]

prefixSum: 0 → -3 → -1 → -4 → 0 → 2
minPrefix: min seen = -4

startValue = max(1, 1-(-4)) = max(1, 5) = 5

Verify: 5 + (-3)=2, 5+(-1)=4, 5+(-4)=1, 5+0=5, 5+2=7 → all ≥ 1 ✓
```

### Complexity
- Time: O(n) — single pass.
- Space: O(1) — running variables only, no prefix array stored.

### Edge Cases
- All positive numbers: `minPrefix >= 0` → `startValue = max(1, 1-minPrefix) = 1`.
- Single large negative: `minPrefix = nums[0]` → `startValue = 1 - nums[0]`.
- `minPrefix = 0`: `startValue = max(1, 1) = 1` — minimum valid positive start.

### Follow-up Questions
- "Return the minimum startValue such that the sum never exceeds a maximum cap?" → Track `maxPrefix`; `startValue <= cap - maxPrefix`. Combine both constraints for a range.

## Quick Reference — Pattern Decision Tree

```
Does the problem involve a contiguous subarray/range of a static array?
│
├── RANGE SUM QUERY (multiple queries, array unchanged)
│   └── Prefix Sum → O(n) build, O(1) per query
│
├── COUNT / FIND subarrays with sum = k
│   ├── All positive, fixed length k → Sliding Window
│   ├── Any integers, count subarrays → Prefix Sum + Hash Map (count map)
│   └── Any integers, longest subarray → Prefix Sum + Hash Map (first-seen map)
│
├── EQUAL COUNTS of two values
│   └── Transform (0→-1, 1→+1) then longest subarray sum = 0
│       → Prefix Sum + Hash Map (first-seen map)
│
├── PRODUCT (not sum) of all elements except self
│   └── Prefix Product (left pass) × Suffix Product (right pass)
│
├── RANGE UPDATES then final read
│   └── Difference Array → O(1) per update, O(n) reconstruction
│
├── RANGE UPDATES + RANGE QUERIES (interleaved)
│   └── Fenwick Tree / BIT → O(log n) each
│
└── 2D MATRIX rectangle sum queries
    └── 2D Prefix Sum → O(m×n) build, O(1) per query
```

## Common Bugs Checklist

Before submitting any prefix sum or difference array solution, verify:

1. **Sentinel initialized?** — `pre[0] = 0` for shifted prefix, `prefixCount = {0:1}` for hash map pattern. Missing sentinel causes wrong answers on subarrays starting at index 0.

2. **Query formula correct?** — `sum(l,r) = pre[r+1] - pre[l]` (shifted) or `pre[r] - pre[l-1]` with `l>0` guard. Wrong formula is the #1 bug.

3. **First-seen vs count map?** — Longest subarray → store first index. Count of subarrays → store count. Using the wrong one gives wrong answers silently.

4. **Difference array guard index?** — `diff` has size `n+1`, not `n`. Without it, `diff[r+1]` when `r = n-1` writes out of bounds.

5. **Negative modulo?** — In subarray sum divisible by k: `rem = ((prefixSum % k) + k) % k` to handle negative prefix sums in languages where `%` can return negative values.

6. **Update order in hash map?** — Look up `prefixSum - k` *before* inserting `prefixSum`. Inserting first lets the current index pair with itself, counting zero-length subarrays.

**Final Tip:** At the 5 YOE level, the technique selection is the most important signal — interviewers expect you to immediately recognize "prefix sum + hash map" for subarray count/length problems, "difference array" for batch range updates, and "2D prefix sum" for rectangle queries. The implementation is then near-mechanical. Practice stating the key formula out loud before coding: "sum of nums[l..r] equals pre[r+1] minus pre[l]" or "add v to range [l,r] means diff[l] += v, diff[r+1] -= v." Candidates who state the formula first and then derive the code from it look far more confident than those who try to remember the code directly.
