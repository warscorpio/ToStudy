# DSA: Two-Pointer Technique — Interview Q&A (5 YOE Level)

---

## Section 1: Fundamentals

**Q1. What is the two-pointer technique?**
A: The two-pointer technique is a pattern where two index variables traverse a data structure — typically an array or string — simultaneously, moving toward or away from each other (or in the same direction at different speeds) to solve a problem in a single pass. Instead of using a nested loop to compare all pairs (O(n²)), two pointers reduce the search space intelligently on each step, typically achieving O(n) time with O(1) extra space. It is one of the most frequently applied patterns in array and string problems at interviews.

**Q2. What are the two main variants of the two-pointer technique?**
A:
- **Opposite-end pointers (converging)** — one pointer starts at the left (`lo = 0`), one at the right (`hi = n - 1`), and they move toward each other until they meet. Used when the problem involves pairs across the whole array — pair sum, container with most water, trapping rain water, reversing arrays, palindrome checks.
- **Same-direction pointers (sliding / fast-slow)** — both pointers start at or near the left and move right, but at different speeds or with different conditions governing each one. Used for problems like removing duplicates in-place, finding the middle of a linked list, detecting cycles (Floyd's algorithm), or the sliding window pattern.

**Q3. Why does the two-pointer technique work — what is the core invariant?**
A: On every step, at least one pointer moves, and the move provably eliminates a subset of candidates that cannot contain the answer. The technique is valid only when the data has a structure (usually sorted order, or a geometric relationship) that lets you make that guarantee. Without such structure, moving a pointer doesn't eliminate anything, and the approach is unsound. The core discipline is always being able to answer: "why is it safe to discard everything between the old pointer position and the new one?"

**Q4. What preprocessing is usually required for the opposite-end variant?**
A: The array must be **sorted** (or the problem already guarantees a structure equivalent to sorted order). Sorting is required because it gives the monotonic property that makes discarding candidates safe: if `arr[lo] + arr[hi] < target`, increasing `lo` is the only way to increase the sum — moving `hi` left would only decrease it further. Without sorted order this reasoning breaks down.

**Q5. What is the time and space complexity of a typical two-pointer solution?**
A: O(n) time for the two-pointer pass itself (each pointer moves at most n steps, and they never cross), plus O(n log n) if a sort is required as preprocessing. Space is O(1) — the only extra memory is the two index variables. This compares favorably to brute-force O(n²) time / O(1) space or hash-map approaches that are often O(n) time but O(n) space.

## Section 2: Pair Sum (Two Sum on a Sorted Array)

**Q6. State the pair sum problem and its two-pointer solution.**
A: Given a **sorted** array of integers and a target value, find two indices `i` and `j` (where `i < j`) such that `arr[i] + arr[j] === target`. Return the indices (or the values, depending on the variant).

```js
function pairSum(arr, target) {
  let lo = 0, hi = arr.length - 1;

  while (lo < hi) {
    const sum = arr[lo] + arr[hi];
    if (sum === target) return [lo, hi];
    if (sum < target) lo++;  // need a larger sum — move left pointer right
    else hi--;               // need a smaller sum — move right pointer left
  }
  return []; // no pair found
}
```

Time: O(n) | Space: O(1)

**Q7. Why is it safe to move `lo` right when the sum is too small?**
A: Because the array is sorted, `arr[lo]` is the smallest value the left pointer can currently offer. If `arr[lo] + arr[hi] < target`, then pairing `arr[lo]` with *any* element to the left of `hi` (which is even smaller than `arr[hi]`) will produce an even smaller sum — none of those pairs can reach the target. So we can permanently discard `arr[lo]` as a left candidate and advance `lo`. Symmetrically, if the sum is too large, `arr[hi]` paired with anything to the right of `lo` would be even larger — discard `arr[hi]` and move `hi` left.

**Q8. What if the input is unsorted — do you sort it first, and what's the trade-off vs a hash map?**
A: Two options:
- **Sort + two pointers**: O(n log n) time, O(1) or O(log n) space (sorting in-place). Loses original indices — if the problem asks for indices of the original array (like LeetCode's classic Two Sum), you'd need to store index information before sorting.
- **Hash map**: O(n) time, O(n) space. Preserves original indices directly. Walk the array once; for each element check if `target - element` is already in the map; if not, store the current element.

The right choice depends on constraints: if the array is already sorted or you can sort it, two pointers wins on space. If original indices matter and you can't sort, hash map wins. At 5 YOE level, you're expected to name both trade-offs without being asked.

**Q9. How do you handle duplicates in pair sum — find all unique pairs?**
A: After finding a valid pair, skip over duplicate values on both sides before continuing:
```js
function allPairs(arr, target) {
  const result = [];
  let lo = 0, hi = arr.length - 1;

  while (lo < hi) {
    const sum = arr[lo] + arr[hi];
    if (sum === target) {
      result.push([arr[lo], arr[hi]]);
      while (lo < hi && arr[lo] === arr[lo + 1]) lo++;
      while (lo < hi && arr[hi] === arr[hi - 1]) hi--;
      lo++; hi--;
    } else if (sum < target) lo++;
    else hi--;
  }
  return result;
}
```
The duplicate skipping ensures each unique pair appears exactly once in the output.

**Q10. How does pair sum extend to three-sum (find all unique triplets summing to zero)?**
A: Sort the array. For each element at index `k` (the fixed first element), run the pair sum two-pointer pattern on the subarray `[k+1 ... n-1]` with target `= -arr[k]`. Skip duplicate values of `arr[k]` between outer iterations. Total complexity: O(n²) — one O(n) outer pass times an O(n) two-pointer inner pass. This extends further to four-sum with another outer loop: O(n³). The pattern generalizes cleanly — always sort first, fix all but the last two elements with outer loops, use two pointers for the innermost pair.

## Section 3: Container With Most Water

**Q11. State the "container with most water" problem.**
A: Given an array `height` of n non-negative integers where `height[i]` represents a vertical line at position `i`, find the two lines that together with the x-axis form a container that holds the most water. The area of water between lines `i` and `j` (where `i < j`) is `Math.min(height[i], height[j]) * (j - i)`. Return the maximum area.

```js
function maxWater(height) {
  let lo = 0, hi = height.length - 1;
  let maxArea = 0;

  while (lo < hi) {
    const area = Math.min(height[lo], height[hi]) * (hi - lo);
    maxArea = Math.max(maxArea, area);

    if (height[lo] <= height[hi]) lo++;
    else hi--;
  }
  return maxArea;
}
```

Time: O(n) | Space: O(1)

**Q12. Why is it safe to move the pointer at the shorter line — why doesn't the optimal answer get skipped?**
A: This is the key insight the interviewer is probing. The area is constrained by `Math.min(height[lo], height[hi])` — the *shorter* of the two lines is the bottleneck. If we move the *taller* line's pointer inward, we definitely decrease the width (`hi - lo` shrinks by 1), and the height can only stay the same or decrease (since the new line might be shorter or the same — but the bottleneck was already the shorter line, so the best we could do is match it). We cannot possibly get a larger area by moving the taller pointer. Moving the shorter pointer is the only move that could reveal a taller line and potentially compensate for the reduced width. Therefore discarding the shorter line's current position is always safe.

**Q13. Prove more rigorously that the optimal pair is never skipped.**
A: Proof by contradiction. Suppose the optimal pair is `(i*, j*)` and the algorithm skips it — meaning at some point `lo = i*` and `hi > j*`, and we move `lo` right (skipping `i*`). For that to happen, `height[lo] <= height[hi]` must hold, i.e. `height[i*] <= height[hi]`. The area of any pair `(i*, k)` for `j* <= k <= hi` is at most `Math.min(height[i*], height[k]) * (k - i*)`. Since `height[i*] <= height[hi]` and `k <= hi`, the width `(k - i*) <= (hi - i*)`, and the height is at most `height[i*]`. But the area already computed at `(lo=i*, hi)` is `Math.min(height[i*], height[hi]) * (hi - i*) = height[i*] * (hi - i*)` — which is at least as large as any pair `(i*, k)` for `k <= hi`. So skipping `i*` by moving `lo` means we already found a result at least as good as `(i*, j*)`. Contradiction — the algorithm doesn't skip the optimum.

**Q14. What's the difference between "container with most water" and "trapping rain water" — can the same two-pointer approach solve both?**
A: They are related but distinct:
- **Container with most water** — you choose *two* lines from the array to form a container. The water height is `min(height[lo], height[hi])` and width is `hi - lo`. Two pointers work perfectly — converge from both ends, always moving the shorter side.
- **Trapping rain water** — water is trapped *between* bars across the *entire* array, not just between two chosen endpoints. Every bar can potentially hold water above it. The two-pointer approach still works (track `maxLeft` and `maxRight` as pointers converge, adding trapped water at each step), but the logic is different — you're accumulating water at each index, not finding a single maximum pair. Both problems use converging two pointers, but the state tracked and update logic differ significantly.

**Q15. What would a brute-force solution look like for container with most water, and why is it worse?**
A: Brute force checks every pair `(i, j)` where `i < j`:
```js
function maxWaterBrute(height) {
  let maxArea = 0;
  for (let i = 0; i < height.length; i++) {
    for (let j = i + 1; j < height.length; j++) {
      maxArea = Math.max(maxArea, Math.min(height[i], height[j]) * (j - i));
    }
  }
  return maxArea;
}
```
O(n²) time, O(1) space. For n = 100,000, brute force makes 5 billion comparisons — completely infeasible. The two-pointer solution makes exactly n − 1 steps (each step advances one pointer by one), so it handles n = 100,000 trivially. The problem is a textbook case of where recognizing the two-pointer invariant yields a 10,000x+ speedup over brute force.

## Section 4: Patterns, Variants & Extensions

**Q16. What is the sliding window pattern, and how does it differ from opposite-end two pointers?**
A: Sliding window is a same-direction two-pointer variant where `lo` and `hi` both start at 0 and `hi` expands the window right while `lo` shrinks it from the left when a condition is violated. Used for subarray/substring problems: longest substring without repeating characters, minimum window substring, maximum sum subarray of size k. The key difference from opposite-end: both pointers move in the same direction and the window between them represents a *current candidate*, not a pair of endpoints. The window expands greedily and contracts when it becomes invalid.

**Q17. What is the fast-slow pointer (Floyd's) variant, and what problems does it solve?**
A: Fast and slow pointers both start at the head of a linked list (or array). The slow pointer moves one step at a time; the fast pointer moves two. Problems solved:
- **Cycle detection** — if a cycle exists, fast and slow will eventually meet inside it. If fast reaches null, there's no cycle.
- **Finding the cycle entry point** — after detection, reset one pointer to head and advance both one step at a time; they meet at the cycle entry.
- **Finding the middle of a linked list** — when fast reaches the end, slow is at the middle.
- **Finding the k-th from last node** — advance fast k steps first, then move both together; when fast hits null, slow is k from the end.

**Q18. How do you apply two pointers to remove duplicates from a sorted array in-place?**
A: Same-direction two pointers: `slow` tracks the position of the last unique element written; `fast` scans ahead. When `arr[fast] !== arr[slow]`, copy `arr[fast]` to `arr[slow + 1]` and advance `slow`. At the end, `slow + 1` is the count of unique elements:
```js
function removeDuplicates(arr) {
  if (!arr.length) return 0;
  let slow = 0;
  for (let fast = 1; fast < arr.length; fast++) {
    if (arr[fast] !== arr[slow]) {
      slow++;
      arr[slow] = arr[fast];
    }
  }
  return slow + 1;
}
```
O(n) time, O(1) space. The slow pointer marks the "clean" prefix; fast discovers new unique values.

**Q19. How do you use two pointers to check if a string is a palindrome, ignoring non-alphanumeric characters?**
A: Opposite-end pointers, with each pointer skipping non-alphanumeric characters before comparing:
```js
function isPalindrome(s) {
  let lo = 0, hi = s.length - 1;
  while (lo < hi) {
    while (lo < hi && !isAlphanumeric(s[lo])) lo++;
    while (lo < hi && !isAlphanumeric(s[hi])) hi--;
    if (s[lo].toLowerCase() !== s[hi].toLowerCase()) return false;
    lo++; hi--;
  }
  return true;
}
function isAlphanumeric(c) {
  return /[a-zA-Z0-9]/.test(c);
}
```
O(n) time, O(1) space. The pointers skip irrelevant characters in place — no need to build a cleaned string.

**Q20. When should you reach for a hash map instead of two pointers?**
A: Two pointers require either sorted input or a geometric/monotonic property. Reach for a hash map when:
- The array is unsorted and sorting would lose required index information.
- The problem requires O(n) time and you can't afford O(n log n) sorting.
- You need to count occurrences or group elements, not just find pairs.
- The "complement" of each element (target - current) needs O(1) lookup across arbitrary positions.

At 5 YOE, interviewers expect you to mention both approaches, state the trade-off (two pointers: O(1) space but needs sorting; hash map: O(n) space but handles unsorted input), and choose appropriately based on problem constraints.

## Section 5: Complexity Analysis & Edge Cases

**Q21. Walk through the complexity analysis for three-sum using two pointers.**
A: Sort: O(n log n). Outer loop: O(n) iterations (one per unique first element, skipping duplicates). Inner two-pointer pass: O(n) per outer iteration in the worst case (pointers traverse the subarray once). Total: O(n log n + n²) = O(n²). Space: O(1) ignoring the output array (or O(k) where k is the number of triplets found). This is optimal for three-sum — a comparison-based lower bound argument shows you can't do better than O(n²) for the general case.

**Q22. What are the key edge cases to handle in pair sum and container with most water?**
A: For pair sum:
- Empty array or array with fewer than 2 elements — return early.
- No valid pair exists — return `[]` or `-1` depending on the spec.
- Duplicate values — handle if the problem asks for all unique pairs (skip duplicates after finding a match).
- Integer overflow — in languages with fixed-size integers (Java, C++), `arr[lo] + arr[hi]` can overflow; use `long` or check before adding. In JS, numbers are 64-bit floats so overflow is rarely a concern in interviews.

For container with most water:
- Array of length 2 — only one pair; the loop handles it naturally.
- All equal heights — any pair gives the same height; width decreases as pointers converge; the algorithm finds the widest (first and last) correctly.
- Monotonically increasing or decreasing heights — the algorithm still works; it just moves one pointer all the way across.

**Q23. How do you prove the two-pointer approach terminates?**
A: On every iteration of the `while (lo < hi)` loop, at least one pointer moves: `lo` increments or `hi` decrements. Since `lo` starts at 0 and `hi` starts at `n - 1`, and the loop exits when `lo >= hi`, the loop runs at most `n - 1` iterations. The pointers cannot stall (the `if`/`else` always advances exactly one of them), so termination is guaranteed in O(n) steps.

**Q24. What happens if both pointers need to move on a match — is that always correct?**
A: For pair sum (finding a single pair), you return immediately on a match — no need to move. For finding *all* pairs or triplets, after recording a match you advance both pointers (`lo++; hi--`) and then skip duplicates. This is correct because: after a match at `(lo, hi)`, the pair `(lo, hi-1)` has a smaller sum (since the array is sorted and you've decreased the right element) and the pair `(lo+1, hi)` also has a smaller sum — neither can be a match for the same target. So both pointers must move. Skipping duplicates on top of that ensures uniqueness of results.

## Section 6: Scenario / Interview-Style Questions

**Q25. "Given a sorted array of integers, find all unique quadruplets that sum to a given target. Walk through your approach."**
A: Extend the three-sum approach by adding another outer loop. Sort the array. Two outer loops fix the first two elements (indices `a` and `b`), then run the two-pointer inner pass on `[b+1 ... n-1]` with target `= target - arr[a] - arr[b]`. Skip duplicates at all four levels. Complexity: O(n³) — two O(n) outer loops × one O(n) inner two-pointer pass. Space: O(1) ignoring output.

The pattern is clear: k-sum on a sorted array is always O(n^(k-1)) using this approach — fix k-2 elements with nested loops, two-pointer the last pair.

**Q26. "An interviewer asks you to solve container with most water, then follow up: what if the lines have width (each bar has width 1 and can hold water above it)?" What problem is that and how does your approach change?**
A: That's the trapping rain water problem. The two-pointer structure is similar but the logic changes: instead of tracking a single maximum area between two chosen endpoints, you compute water trapped above *every* bar in the array.

Two-pointer approach for trapping rain water:
```js
function trap(height) {
  let lo = 0, hi = height.length - 1;
  let maxLeft = 0, maxRight = 0, water = 0;

  while (lo < hi) {
    if (height[lo] <= height[hi]) {
      maxLeft = Math.max(maxLeft, height[lo]);
      water += maxLeft - height[lo];
      lo++;
    } else {
      maxRight = Math.max(maxRight, height[hi]);
      water += maxRight - height[hi];
      hi--;
    }
  }
  return water;
}
```
The invariant: whichever side has the smaller current height, that side's water contribution is fully determined by `maxLeft` or `maxRight` — the other side is guaranteed to be at least as tall, so it won't limit the water on this side. O(n) time, O(1) space.

**Q27. "You have an array of integers (unsorted). Find if any two numbers sum to a target. What's your approach, and would you use two pointers?"**
A: Two pointers are not the first choice here — the array is unsorted and sorting is O(n log n). If n is large and time is critical, a hash set gives O(n) time with O(n) space:
```js
function hasPairSum(arr, target) {
  const seen = new Set();
  for (const num of arr) {
    if (seen.has(target - num)) return true;
    seen.add(num);
  }
  return false;
}
```
Two pointers become appropriate if: the array is already sorted, memory is constrained (O(1) space required), or sorting is acceptable given the constraints. Always state the trade-off explicitly — interviewers at this level expect you to choose deliberately, not reflexively.

**Q28. "What's the most common mistake candidates make when implementing two-pointer solutions?"**
A: Four patterns account for most bugs:
1. **Forgetting to sort first** — applying opposite-end two pointers on an unsorted array and being confused when it produces wrong answers. The technique requires a monotonic property to be valid.
2. **Infinite loop from not advancing a pointer** — writing a condition that neither increments `lo` nor decrements `hi` in some branch, causing the loop to stall forever. Every branch must move at least one pointer.
3. **Off-by-one on the loop condition** — using `lo <= hi` instead of `lo < hi` for pair-finding (you don't want to pair an element with itself), or vice versa for problems where `lo === hi` is a valid state.
4. **Incorrect duplicate skipping** — skipping duplicates before recording a result (missing valid pairs) or not skipping at all (recording the same pair multiple times). The order is: record the result, *then* skip duplicates, *then* advance both pointers.

## Problem 1 — Two Sum II (Sorted Input)

### Problem
Given a **1-indexed** sorted array of integers `numbers` and a target integer, return the indices `[index1, index2]` (1-based) of the two numbers that add up to `target`. Exactly one solution is guaranteed. You may not use the same element twice.

```
Input:  numbers = [2, 7, 11, 15], target = 9
Output: [1, 2]

Input:  numbers = [2, 3, 4], target = 6
Output: [1, 3]
```

### Intuition
The array is already sorted — that's the signal. Sorted order gives a **monotonic** property: moving the left pointer right increases the sum; moving the right pointer left decreases it. This is precisely what two pointers exploit. A hash map would also work but wastes O(n) space when O(1) is achievable.

### Approach
Place `lo` at index 0, `hi` at the last index. On each step:
- Sum too small → the only way to increase it is to move `lo` right (larger value).
- Sum too large → the only way to decrease it is to move `hi` left (smaller value).
- Sum equals target → done.

Each step discards at least one element permanently. The loop runs at most n times.

### Solution

```js
function twoSum(numbers, target) {
  let lo = 0, hi = numbers.length - 1;

  while (lo < hi) {
    const sum = numbers[lo] + numbers[hi];

    if (sum === target) {
      return [lo + 1, hi + 1]; // convert to 1-based indices
    } else if (sum < target) {
      lo++; // current lo paired with anything <= hi gives sum <= current sum
    } else {
      hi--; // current hi paired with anything >= lo gives sum >= current sum
    }
  }

  return []; // problem guarantees a solution, so this is unreachable
}
```

### Dry Run

```
numbers = [2, 7, 11, 15], target = 9

Step 1: lo=0 (2), hi=3 (15) → sum=17 > 9 → hi--
Step 2: lo=0 (2), hi=2 (11) → sum=13 > 9 → hi--
Step 3: lo=0 (2), hi=1 (7)  → sum=9  = 9 → return [1, 2] ✓
```

### Complexity
- Time: O(n) — each pointer moves at most n steps total.
- Space: O(1) — two index variables only.

### Edge Cases
- Array of exactly 2 elements → single iteration, returns immediately.
- Target is `2 * numbers[0]` (both at left end) → `hi` converges all the way to `lo+1`.
- Target is `2 * numbers[n-1]` (both at right end) → `lo` converges all the way to `hi-1`.

### Follow-up Questions
- "What if the array is unsorted?" → Sort first (O(n log n), loses indices) or use a hash map (O(n) time/space, preserves indices).
- "What if there can be zero or multiple solutions?" → Remove the guarantee and collect all pairs; add duplicate-skipping logic after a match.

## Problem 2 — Three Sum (All Unique Triplets)

### Problem
Given an unsorted integer array `nums`, return all unique triplets `[nums[i], nums[j], nums[k]]` such that `i`, `j`, `k` are distinct and `nums[i] + nums[j] + nums[k] === 0`.

```
Input:  nums = [-4, -1, -1, 0, 1, 2]
Output: [[-1, -1, 2], [-1, 0, 1]]

Input:  nums = [0, 0, 0]
Output: [[0, 0, 0]]
```

### Intuition
Three-sum = one fixed element + two-sum on the remainder. Sort first, fix the leftmost element of the triplet with an outer loop, then run the standard two-pointer pair-sum on the subarray to its right. Duplicate skipping is required at two levels — for the fixed element and for the pair.

### Approach
1. Sort `nums`.
2. Iterate `k` from `0` to `n-3`. Skip `k` if `nums[k] === nums[k-1]` (duplicate outer element).
3. For each `k`, set `lo = k+1`, `hi = n-1`, target = `-nums[k]`.
4. Run pair-sum two pointers. On a match: record, skip duplicate `lo` values, skip duplicate `hi` values, then advance both.

### Solution

```js
function threeSum(nums) {
  nums.sort((a, b) => a - b);
  const result = [];

  for (let k = 0; k < nums.length - 2; k++) {
    // skip duplicate values for the fixed element
    if (k > 0 && nums[k] === nums[k - 1]) continue;

    // early exit: smallest possible triplet sum is already > 0
    if (nums[k] > 0) break;

    let lo = k + 1, hi = nums.length - 1;

    while (lo < hi) {
      const sum = nums[k] + nums[lo] + nums[hi];

      if (sum === 0) {
        result.push([nums[k], nums[lo], nums[hi]]);

        // skip duplicates for lo
        while (lo < hi && nums[lo] === nums[lo + 1]) lo++;
        // skip duplicates for hi
        while (lo < hi && nums[hi] === nums[hi - 1]) hi--;

        lo++; // advance past the matched element
        hi--;
      } else if (sum < 0) {
        lo++;
      } else {
        hi--;
      }
    }
  }

  return result;
}
```

### Dry Run

```
nums = [-4, -1, -1, 0, 1, 2]  (already sorted)

k=0: nums[k]=-4, lo=1(-1), hi=5(2) → sum=-3 < 0 → lo++
     lo=2(-1), hi=5(2) → sum=-3 < 0 → lo++
```

- Only two distinct values (e.g., `[-1, -1, 2]`) → handled correctly by duplicate skipping.

- "Extend to four-sum." → Add another outer loop (O(n³) total); same duplicate-skipping discipline at three levels.

## Problem 3 — Container With Most Water

### Problem
Given an integer array `height` of length `n`, find two lines that together with the x-axis form a container that holds the most water. Return the maximum amount of water.

```
Input:  height = [1, 8, 6, 2, 5, 4, 8, 3, 7]
Output: 49

Input:  height = [1, 1]
Output: 1
```

### Intuition
The area between lines `i` and `j` is `min(height[i], height[j]) * (j - i)`. Two forces compete: width (want pointers far apart) and height (want tall lines). Starting with the widest possible window and greedily moving the shorter line inward is the key insight — moving the taller line can never improve the area (the bottleneck is already the shorter one), so we discard it safely.

### Approach
Start with `lo = 0`, `hi = n - 1` (maximum width). On each step, compute the area. Move whichever pointer points to the shorter line (if equal, move either — convention: move `lo`). This is the only move that could possibly find a taller constraining line to compensate for the width reduction.

### Solution

```js
function maxArea(height) {
  let lo = 0, hi = height.length - 1;
  let maxWater = 0;

  while (lo < hi) {
    const h = Math.min(height[lo], height[hi]);
    const w = hi - lo;
    maxWater = Math.max(maxWater, h * w);

    // move the pointer at the shorter line — it's the bottleneck
    // moving the taller line can only decrease or maintain height,
    // while width always decreases → area can only shrink or stay same
    if (height[lo] <= height[hi]) {
      lo++;
    } else {
      hi--;
    }
  }

  return maxWater;
}
```

```
indices:  0  1  2  3  4  5  6  7  8

lo=0(1),  hi=8(7) → area = min(1,7)*8 = 8  → maxWater=8  → height[0]<height[8] → lo++
lo=1(8),  hi=8(7) → area = min(8,7)*7 = 49 → maxWater=49 → height[1]>height[8] → hi--
lo=1(8),  hi=7(3) → area = min(8,3)*6 = 18 → maxWater=49 → height[7]<height[1] → hi--
lo=1(8),  hi=6(8) → area = min(8,8)*5 = 40 → maxWater=49 → height[6]<=height[1] → lo++
```

### Complexity
- Time: O(n) — each pointer moves at most n steps total, loop runs exactly n−1 times.
- Space: O(1).

### Edge Cases
- Array of length 2 → single iteration, returns immediately.
- All equal heights → area = `height[0] * (n-1)` found on the first iteration; algorithm still works correctly as pointers converge.
- Monotonically increasing heights → `lo` never moves (always shorter); `hi` walks all the way left.

### Follow-up Questions
- "What's the brute-force and its complexity?" → O(n²) nested loops checking every pair.
- "Extend to trapping rain water." → Different problem — accumulate water above every bar, not just between two chosen lines. Requires tracking `maxLeft` and `maxRight` as pointers converge.

## Problem 4 — Trapping Rain Water

### Problem
Given `n` non-negative integers representing an elevation map where each bar has width 1, compute how much water it can trap after raining.

```
Input:  height = [0, 1, 0, 2, 1, 0, 1, 3, 2, 1, 2, 1]
Output: 6

Input:  height = [4, 2, 0, 3, 2, 5]
Output: 9
```

### Intuition
Water above bar `i` is determined by the shorter of the tallest bar to its left and the tallest bar to its right: `min(maxLeft, maxRight) - height[i]`. A naive O(n²) approach precomputes this for every bar. The two-pointer insight: if `height[lo] <= height[hi]`, then `maxRight >= height[hi] >= height[lo]`, so the water at `lo` is fully determined by `maxLeft` alone — you don't need to know the exact `maxRight`. Process the side with the shorter current bar and you always have enough information.

### Approach
`lo` starts at 0, `hi` at n−1. Track `maxLeft` (tallest seen from left so far) and `maxRight` (tallest seen from right so far). Whichever side's current bar is shorter, process it: update that side's max and add `max - height[pointer]` to the total.

### Solution

```js
function trap(height) {
  let lo = 0, hi = height.length - 1;
  let maxLeft = 0, maxRight = 0;
  let water = 0;

  while (lo < hi) {
    if (height[lo] <= height[hi]) {
      // right side is at least as tall as left side
      // → water at lo depends only on maxLeft
      maxLeft = Math.max(maxLeft, height[lo]);
      water += maxLeft - height[lo]; // 0 if height[lo] is a new max
      lo++;
    } else {
      // left side is taller than right side
      // → water at hi depends only on maxRight
      maxRight = Math.max(maxRight, height[hi]);
      water += maxRight - height[hi];
      hi--;
    }
  }

  return water;
}
```

### Dry Run

```
height = [4, 2, 0, 3, 2, 5]

lo=0(4), hi=5(5): height[0]<=height[5] → maxLeft=max(0,4)=4, water+=4-4=0, lo++
lo=1(2), hi=5(5): height[1]<=height[5] → maxLeft=max(4,2)=4, water+=4-2=2, lo++
lo=2(0), hi=5(5): height[2]<=height[5] → maxLeft=max(4,0)=4, water+=4-0=4, lo++
lo=3(3), hi=5(5): height[3]<=height[5] → maxLeft=max(4,3)=4, water+=4-3=1, lo++
lo=4(2), hi=5(5): height[4]<=height[5] → maxLeft=max(4,2)=4, water+=4-2=2, lo++
lo=5 not < hi=5 → exit

Total water = 0+2+4+1+2 = 9 ✓
```

### Complexity
- Time: O(n) — each pointer moves at most n steps.
- Space: O(1) — no prefix arrays needed (unlike the naive precomputation approach).

### Edge Cases
- Empty array or single element → return 0 (no water possible).
- Monotonically increasing or decreasing → no water trapped; all `maxLeft - height[lo]` or `maxRight - height[hi]` terms are 0.
- Flat array → no water trapped.

### Follow-up Questions
- "What's the O(n) space approach?" → Precompute `leftMax[]` and `rightMax[]` arrays, then a single pass to sum `min(leftMax[i], rightMax[i]) - height[i]`. Two pointers achieve the same in O(1) space.
- "How does this differ from container with most water?" → Here every bar participates and you sum trapped water across all positions. Container with most water picks only two lines and finds maximum area between them.

## Problem 5 — Remove Duplicates from Sorted Array (In-Place)

### Problem
Given a sorted array `nums`, remove duplicates **in-place** so each unique element appears only once. Return the count `k` of unique elements. The first `k` elements of `nums` must contain the unique values in sorted order — the rest doesn't matter.

```
Input:  nums = [1, 1, 2]
Output: 2, nums = [1, 2, _]

Input:  nums = [0,0,1,1,1,2,2,3,3,4]
Output: 5, nums = [0, 1, 2, 3, 4, _, _, _, _, _]
```

### Intuition
Same-direction two-pointer variant. `slow` tracks the write position (end of the deduplicated prefix); `fast` scans ahead looking for new unique values. When `fast` finds a value different from `nums[slow]`, copy it to `nums[slow+1]` and advance `slow`. The gap between `slow` and `fast` is filled with duplicates that are being skipped over.

### Approach
- `slow = 0` (last confirmed unique position).
- `fast` starts at 1, scans to the end.
- When `nums[fast] !== nums[slow]`: `slow++`, `nums[slow] = nums[fast]`.
- Return `slow + 1`.

### Solution

```js
function removeDuplicates(nums) {
  if (nums.length === 0) return 0;

  let slow = 0; // marks end of unique prefix

  for (let fast = 1; fast < nums.length; fast++) {
    if (nums[fast] !== nums[slow]) {
      // found a new unique value — extend the unique prefix
      slow++;
      nums[slow] = nums[fast];
    }
    // if equal, fast just skips over the duplicate
  }

  return slow + 1; // length of unique prefix
}
```

### Dry Run

```

slow=0(0), fast=1(0): equal → skip
slow=0(0), fast=2(1): different → slow=1, nums[1]=1 → [0,1,1,1,1,2,2,3,3,4]
slow=1(1), fast=3(1): equal → skip
slow=1(1), fast=4(1): equal → skip
slow=1(1), fast=5(2): different → slow=2, nums[2]=2 → [0,1,2,1,1,2,2,3,3,4]
slow=2(2), fast=6(2): equal → skip
slow=2(2), fast=7(3): different → slow=3, nums[3]=3 → [0,1,2,3,1,2,2,3,3,4]
slow=3(3), fast=8(3): equal → skip
slow=3(3), fast=9(4): different → slow=4, nums[4]=4 → [0,1,2,3,4,2,2,3,3,4]

Return slow+1 = 5 ✓
First 5 elements: [0, 1, 2, 3, 4]
```

### Complexity
- Time: O(n) — `fast` visits every element exactly once.
- Space: O(1) — in-place modification, two pointer variables.

### Edge Cases
- Empty array → return 0 immediately.
- All duplicates (e.g., `[2,2,2,2]`) → `fast` scans all, `slow` never moves past 0; return 1.
- No duplicates → `slow` tracks `fast-1` always; every element is copied to itself; return `n`.

### Follow-up Questions
- "Allow at most 2 duplicates instead of 1." → Change the condition: compare `nums[fast]` with `nums[slow-1]` (two positions back) instead of `nums[slow]`. If different from both, include it.
- "Do this for an unsorted array." → Two pointers won't work — use a `Set` to track seen values: O(n) time, O(n) space.

## Problem 6 — Valid Palindrome (With Character Filtering)

### Problem
A phrase is a palindrome if it reads the same forwards and backwards after converting uppercase to lowercase and removing all non-alphanumeric characters. Given a string `s`, return `true` if it is a palindrome.

```
Input:  s = "A man, a plan, a canal: Panama"
Output: true

Input:  s = "race a car"
Output: false
```

### Intuition
Classic opposite-end two pointers on a string. Instead of building a cleaned version (O(n) space), skip non-alphanumeric characters in-place as the pointers converge. Compare only valid characters. Space stays O(1).

### Approach
`lo` at 0, `hi` at `s.length - 1`. On each step:
- Advance `lo` right while it points at a non-alphanumeric character.
- Advance `hi` left while it points at a non-alphanumeric character.
- Compare `s[lo]` and `s[hi]` (case-insensitive). Mismatch → return false.
- Both match → `lo++`, `hi--`.

### Solution

```js
function isPalindrome(s) {
  let lo = 0, hi = s.length - 1;

  while (lo < hi) {
    // skip non-alphanumeric from left
    while (lo < hi && !isAlphanumeric(s[lo])) lo++;
    // skip non-alphanumeric from right
    while (lo < hi && !isAlphanumeric(s[hi])) hi--;

    if (s[lo].toLowerCase() !== s[hi].toLowerCase()) return false;

    lo++;
    hi--;
  }

  return true;
}

function isAlphanumeric(c) {
  return (c >= 'a' && c <= 'z') ||
         (c >= 'A' && c <= 'Z') ||
         (c >= '0' && c <= '9');
}
```

### Dry Run

```
s = "A man, a plan, a canal: Panama"

lo=0(A),  hi=29(a) → both alpha → A==a ✓ → lo=1, hi=28
lo=1( ),  hi=28(m) → lo skips space → lo=2(m)
lo=2(m),  hi=28(m) → m==m ✓ → lo=3, hi=27
lo=3(a),  hi=27(a) → a==a ✓ → lo=4, hi=26
lo=4(n),  hi=26(n) → n==n ✓ → ...
(continues until pointers meet)
→ return true ✓
```

### Complexity
- Time: O(n) — each character visited at most once by either pointer.
- Space: O(1) — no cleaned copy of the string built.

### Edge Cases
- Empty string → `lo=0`, `hi=-1`, loop never runs → return `true` (empty string is a palindrome by convention).
- All non-alphanumeric (e.g., `",.;"`) → both pointers skip everything, meet immediately → return `true`.
- Single character → `lo=0`, `hi=0`, loop condition `lo < hi` is false → return `true`.

### Follow-up Questions
- "What if you need to check if any permutation of the string is a palindrome?" → Count character frequencies. A palindrome permutation has at most one character with an odd frequency. O(n) time, O(1) space (only 26 lowercase letters).
- "Shortest palindrome by deleting at most one character?" → Two pointers; on first mismatch, try skipping `lo` or `hi` and check if the remainder is a palindrome.

## Problem 7 — Sort Colors (Dutch National Flag)

### Problem
Given an array `nums` with values `0`, `1`, and `2` (representing red, white, blue), sort it **in-place** so that all `0`s come first, then `1`s, then `2`s. Do it in a single pass without using a sort function.

```
Input:  nums = [2, 0, 2, 1, 1, 0]
Output: [0, 0, 1, 1, 2, 2]

Input:  nums = [2, 0, 1]
Output: [0, 1, 2]
```

### Intuition
Three-pointer variant of the two-pointer pattern (Dutch National Flag algorithm). Maintain three regions: `[0..lo-1]` all 0s, `[lo..mid-1]` all 1s, `[hi+1..n-1]` all 2s. `mid` is the exploration frontier. Everything in `[mid..hi]` is unclassified. Scan `mid` forward: swap 0s to the left region, 2s to the right region, leave 1s in place.

### Approach
- `lo = 0` (next position for a 0)
- `mid = 0` (current element under examination)
- `hi = n - 1` (next position for a 2)

While `mid <= hi`:
- `nums[mid] === 0` → swap with `nums[lo]`, `lo++`, `mid++`
- `nums[mid] === 1` → `mid++` (already in place)
- `nums[mid] === 2` → swap with `nums[hi]`, `hi--` (don't advance `mid` — the swapped-in element is unexamined)

### Solution

```js
function sortColors(nums) {
  let lo = 0, mid = 0, hi = nums.length - 1;

  while (mid <= hi) {
    if (nums[mid] === 0) {
      [nums[lo], nums[mid]] = [nums[mid], nums[lo]];
      lo++;
      mid++; // nums[lo] was in [lo..mid-1] (a 1) — safe to advance mid
    } else if (nums[mid] === 1) {
      mid++; // 1 is already in the correct region
    } else { // nums[mid] === 2
      [nums[mid], nums[hi]] = [nums[hi], nums[mid]];
      hi--; // don't advance mid — swapped element is unexamined
    }
  }
}
```

### Dry Run

```
nums = [2, 0, 2, 1, 1, 0]
lo=0, mid=0, hi=5

mid=0(2): swap nums[0] and nums[5] → [0,0,2,1,1,2], hi=4
mid=0(0): swap nums[0] and nums[0] → [0,0,2,1,1,2], lo=1, mid=1
mid=1(0): swap nums[1] and nums[1] → [0,0,2,1,1,2], lo=2, mid=2
mid=2(2): swap nums[2] and nums[4] → [0,0,1,1,2,2], hi=3
mid=2(1): mid=3
mid=3(1): mid=4
mid=4 > hi=3 → exit

Result: [0, 0, 1, 1, 2, 2] ✓
```

### Complexity
- Time: O(n) — `mid` only moves forward; `hi` only moves backward; each element processed once.
- Space: O(1) — in-place swaps only.

### Edge Cases
- All same value → trivially sorted; one pointer races to the end.
- Already sorted → no swaps needed; `mid` and `lo` advance in lockstep.
- Two elements only → handles correctly in at most 2 iterations.

### Follow-up Questions
- "Why not just count 0s, 1s, 2s and overwrite? (counting sort)" → Valid — O(n) time, O(1) space, two passes. Dutch flag does it in one pass and generalizes to cases where you can't enumerate values.
- "Generalize to k colors." → For k > 3, the Dutch flag trick doesn't directly apply; use a different approach (e.g., quicksort partition with a pivot per color in sequence).

## Problem 8 — Minimum Size Subarray Sum (Sliding Window)

### Problem
Given an array of positive integers `nums` and a positive integer `target`, return the **minimum length** of a subarray whose sum is greater than or equal to `target`. Return 0 if no such subarray exists.

```
Input:  target = 7, nums = [2, 3, 1, 2, 4, 3]
Output: 2  (subarray [4,3])

Input:  target = 4, nums = [1, 4, 4]
Output: 1  (subarray [4])
```

### Intuition
Same-direction two pointers — the sliding window pattern. `lo` and `hi` both start at 0 and move right. Expand `hi` to grow the window until the sum meets the target, then shrink from `lo` to find the minimum valid window. This works because all values are positive: adding elements always increases the sum (expanding helps), removing elements always decreases it (shrinking can only invalidate).

### Approach
- Maintain `windowSum` of elements between `lo` and `hi` (inclusive).
- Expand `hi`: add `nums[hi]` to `windowSum`.
- While `windowSum >= target`: record `hi - lo + 1` as a candidate answer, subtract `nums[lo]` and advance `lo`.
- Result: minimum recorded window length.

### Solution

```js
function minSubarrayLen(target, nums) {
  let lo = 0;
  let windowSum = 0;
  let minLen = Infinity;

  for (let hi = 0; hi < nums.length; hi++) {
    windowSum += nums[hi]; // expand window

    while (windowSum >= target) {
      minLen = Math.min(minLen, hi - lo + 1);
      windowSum -= nums[lo]; // shrink window from left
      lo++;
    }
  }

  return minLen === Infinity ? 0 : minLen;
}
```

### Dry Run

```
target=7, nums=[2,3,1,2,4,3]

hi=0: windowSum=2  < 7
hi=1: windowSum=5  < 7
hi=2: windowSum=6  < 7
hi=3: windowSum=8  >= 7 → minLen=4(hi=3,lo=0), subtract 2, lo=1 → windowSum=6 < 7
hi=4: windowSum=10 >= 7 → minLen=4(hi=4,lo=1), subtract 3, lo=2 → windowSum=7
                        >= 7 → minLen=min(4,3)=3(hi=4,lo=2), subtract 1, lo=3 → windowSum=6 < 7
hi=5: windowSum=9  >= 7 → minLen=min(3,3)=3(hi=5,lo=3), subtract 2, lo=4 → windowSum=7
                        >= 7 → minLen=min(3,2)=2(hi=5,lo=4), subtract 4, lo=5 → windowSum=3 < 7

Return 2 ✓
```

### Complexity
- Time: O(n) — `lo` and `hi` each traverse the array at most once (total 2n moves).
- Space: O(1).

### Edge Cases
- No valid subarray → return 0 (`minLen` stays `Infinity`).
- Single element >= target → returns 1.
- Entire array needed → `lo` never advances until the last step; returns `n`.

### Follow-up Questions
- "What if values can be negative?" → Sliding window breaks (adding elements no longer guarantees sum increases). Need prefix sums + a deque or segment tree — O(n log n).
- "Maximum size subarray with sum <= target?" → Flip the condition: expand `hi`, shrink `lo` when sum exceeds target, track maximum window length.

## Problem 9 — Longest Substring Without Repeating Characters

### Problem
Given a string `s`, find the length of the **longest substring** without repeating characters.

```
Input:  s = "abcabcbb"
Output: 3  ("abc")

Input:  s = "pwwkew"
Output: 3  ("wke")
```

### Intuition
Same-direction sliding window. A `Set` (or character frequency map) tracks what's in the current window. Expand `hi` to include new characters; when a duplicate is found, shrink `lo` until the duplicate is removed. Because we track the window's content, we always know the exact moment the window becomes invalid.

### Approach
- `lo = 0`, `Set` of characters in the current window.
- Scan `hi` from 0 to n−1.
- If `s[hi]` is already in the set → remove `s[lo]` from the set and advance `lo` (repeat until the duplicate is gone).
- Add `s[hi]` to the set.
- Update max length as `hi - lo + 1`.

### Solution

```js
function lengthOfLongestSubstring(s) {
  const window = new Set();
  let lo = 0, maxLen = 0;

  for (let hi = 0; hi < s.length; hi++) {
    // shrink from left until the window no longer contains s[hi]
    while (window.has(s[hi])) {
      window.delete(s[lo]);
      lo++;
    }

    window.add(s[hi]);
    maxLen = Math.max(maxLen, hi - lo + 1);
  }

  return maxLen;
}
```

**Optimized variant** — instead of a Set, use a Map storing the last seen index of each character. When a duplicate is found, jump `lo` directly to `lastSeen[char] + 1` without iterating:

```js
function lengthOfLongestSubstringFast(s) {
  const lastSeen = new Map();
  let lo = 0, maxLen = 0;

  for (let hi = 0; hi < s.length; hi++) {
    if (lastSeen.has(s[hi]) && lastSeen.get(s[hi]) >= lo) {
      // jump lo past the previous occurrence
      lo = lastSeen.get(s[hi]) + 1;
    }
    lastSeen.set(s[hi], hi);
    maxLen = Math.max(maxLen, hi - lo + 1);
  }

  return maxLen;
}
```

### Dry Run (optimized variant)

```
s = "abcabcbb"

hi=0(a): lastSeen={a:0}, lo=0, maxLen=1
hi=1(b): lastSeen={a:0,b:1}, lo=0, maxLen=2
hi=2(c): lastSeen={a:0,b:1,c:2}, lo=0, maxLen=3
hi=3(a): lastSeen[a]=0 >= lo=0 → lo=1; lastSeen={a:3,b:1,c:2}, maxLen=3
hi=4(b): lastSeen[b]=1 >= lo=1 → lo=2; lastSeen={a:3,b:4,c:2}, maxLen=3
hi=5(c): lastSeen[c]=2 >= lo=2 → lo=3; lastSeen={a:3,b:4,c:5}, maxLen=3
hi=6(b): lastSeen[b]=4 >= lo=3 → lo=5; lastSeen={a:3,b:6,c:5}, maxLen=3
hi=7(b): lastSeen[b]=6 >= lo=5 → lo=7; lastSeen={b:7,...}, maxLen=3

Return 3 ✓
```

### Complexity
- Time: O(n) — Set variant: each character added/removed at most once. Map variant: O(n) with O(1) per step.
- Space: O(min(n, m)) where m is the character set size (26 for lowercase, 128 for ASCII).

### Edge Cases
- Empty string → return 0 (loop never runs).
- All same character (e.g., `"aaaa"`) → `lo` chases `hi`; maxLen stays 1.
- All unique characters → `lo` never moves; maxLen = n.

### Follow-up Questions
- "At most 2 distinct characters in the window?" → Replace `Set` with a frequency `Map`; shrink when `map.size > 2`. General version: "at most k distinct characters."
- "Longest substring with at most k replacements?" → Track the count of the most frequent character in the window; shrink when `(window size - max frequency) > k`.

## Recognition Checklist — When to Use Two Pointers

Ask these questions in order when you see an array/string problem:

1. **Does sorted order (or a geometric property) let me eliminate candidates by moving a pointer?** → Opposite-end two pointers.
2. **Am I looking for a contiguous subarray/substring that satisfies a condition, and does adding/removing elements monotonically affect the condition?** → Sliding window (same-direction two pointers).
3. **Is this a linked list problem involving position (middle, k-from-end, cycle)?** → Fast-slow pointers.
4. **Do I need to partition in-place with multiple regions?** → Three-pointer / Dutch flag variant.

If none of these apply, consider: hash map (O(n) space, no sort needed), prefix sums (subarray sums), or a different paradigm entirely.

---

**Final Tip:** In an interview, always verbalize the invariant before coding — "I'll maintain the property that everything to the left of `lo` is [X] and everything to the right of `hi` is [Y]." Interviewers at the 5 YOE level reward candidates who can prove their solution is correct, not just candidates who can produce code that passes examples. The two minutes spent stating the invariant out loud saves ten minutes of debugging and signals the exact level of rigor they're looking for.
