# Node.js Buffer: Binary Data Handling and Encoding — Interview Q&A (5 YOE Level)

---

## Section 1: Fundamentals

**Q1. What is a Buffer in Node.js and why does it exist — isn't JavaScript's string enough?**

A: A `Buffer` is a fixed-length, contiguous allocation of raw memory outside the V8 heap. It represents a sequence of bytes — the lowest-level data primitive in Node.js. JavaScript strings are not sufficient for systems programming because they are always Unicode text: they can't represent arbitrary binary sequences without corruption or overhead.

The problem strings cause with binary data:

```javascript
// Strings corrupt binary data:
const binaryData = Buffer.from([0xFF, 0xFE, 0x00, 0x01]);
const asString = binaryData.toString(); // Decoded as UTF-8: '��\x00\x01'

// Round-tripping through a string is lossy:
const backToBuffer = Buffer.from(asString);
console.log(backToBuffer);
// <Buffer ef bf bd ef bf bd 00 01>  ← NOT the original bytes!
// 0xFF and 0xFE became UTF-8 replacement sequences (3 bytes each)
// Binary data is now corrupted — can't recover original bytes

// Why this happens: JavaScript strings are UTF-16 internally
// V8 stores strings as sequences of UTF-16 code units
// When you coerce raw bytes to a string, V8 tries to interpret them as text
// Invalid UTF-8 sequences get replaced with the replacement character U+FFFD
```

What Buffer gives you that strings cannot:

```javascript
// 1. Exact byte representation — no encoding interpretation
const buf = Buffer.from([0xFF, 0x00, 0xAB, 0xCD]);
console.log(buf[0]); // 255 — exact byte value, no corruption

// 2. Zero-copy views into the same memory
const slice = buf.slice(1, 3);
slice[0] = 0x99; // Modifies the ORIGINAL buffer — shared memory
console.log(buf[1]); // 0x99 — mutation is reflected

// 3. Off-heap allocation — doesn't pressure V8 GC
// Large binary payloads (image data, file contents) won't trigger
// garbage collection pauses the way large string allocations would

// 4. Interop with OS and network APIs
// fs, net, crypto, zlib — all work in bytes, not characters
// Buffer is the currency of I/O in Node.js
```

Buffers implement the `Uint8Array` interface — every Buffer IS a Uint8Array:

```javascript
const buf = Buffer.alloc(4);
console.log(buf instanceof Uint8Array); // true
console.log(Buffer.isBuffer(buf));      // true

// Buffer adds Node.js-specific methods on top of Uint8Array:
// .toString(encoding), .write(), .readUInt32BE(), .copy() etc.
// These don't exist on plain Uint8Array
```

**Q2. What are the different ways to create a Buffer and when should you use each?**

A: Five main creation APIs, each with a distinct purpose and safety profile:

```javascript
// 1. Buffer.alloc(size, fill?, encoding?) — SAFE: zero-initialized memory
const safe = Buffer.alloc(16);
console.log(safe); // <Buffer 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00>
// Guarantees no previous memory contents — use for security-sensitive data

const filled = Buffer.alloc(8, 0xAB);
console.log(filled); // <Buffer ab ab ab ab ab ab ab ab>

// 2. Buffer.allocUnsafe(size) — FAST but contains uninitialized memory
const unsafe = Buffer.allocUnsafe(16);
// Contents are whatever was in that memory region before — could be old passwords,
// keys, anything. Must be FULLY WRITTEN before any reads or external exposure.
// ~10x faster than alloc() for large buffers because no zeroing step

// When allocUnsafe is safe to use: immediately overwrite all bytes
const frame = Buffer.allocUnsafe(1024);
frame.fill(0);         // Explicit zero-fill before use
// OR write every byte via stream/protocol before handing off

// 3. Buffer.from(array) — from a byte array
const fromArray = Buffer.from([0x48, 0x65, 0x6C, 0x6C, 0x6F]);
console.log(fromArray.toString()); // 'Hello'

// 4. Buffer.from(string, encoding?) — encode a string as bytes
const fromStr = Buffer.from('Hello, World!', 'utf8');
const fromB64 = Buffer.from('SGVsbG8=', 'base64');
const fromHex = Buffer.from('48656c6c6f', 'hex');

// 5. Buffer.from(buffer) — copy an existing Buffer
const original = Buffer.from('secret');
const copy = Buffer.from(original); // Independent copy — mutations don't affect original
copy[0] = 0x00;
console.log(original.toString()); // 'secret' — unchanged

// 6. Buffer.from(arrayBuffer, byteOffset?, length?) — view into an ArrayBuffer
// Zero-copy — shares memory with the ArrayBuffer
const ab = new ArrayBuffer(8);
const view = Buffer.from(ab);
view[0] = 42;
console.log(new Uint8Array(ab)[0]); // 42 — same memory

// 7. Buffer.concat(list, totalLength?) — join multiple Buffers
const chunks: Buffer[] = [];
readableStream.on('data', chunk => chunks.push(chunk));
readableStream.on('end', () => {
    const complete = Buffer.concat(chunks); // One contiguous buffer
});
```

The allocUnsafe security warning in practice:

```javascript
// DANGEROUS — partial write, then read:
const buf = Buffer.allocUnsafe(32);
buf.write('password'); // Writes 8 bytes, bytes 8-31 are uninitialized
sendToClient(buf);     // Client receives 8 bytes of 'password' + 24 bytes of heap garbage
                       // Potentially exposing old memory contents

// SAFE pattern with allocUnsafe (write everything before reading):
const packet = Buffer.allocUnsafe(4 + payload.length);
packet.writeUInt32BE(payload.length, 0); // Write header (bytes 0-3)
payload.copy(packet, 4);                  // Write payload (bytes 4-N)
socket.write(packet);                     // Now safe — every byte intentionally set
```

## Section 2: Encodings

**Q3. What encodings does Node.js Buffer support and what are the byte-level semantics of each?**

A: Node.js supports six encodings natively. Each defines a different mapping between bytes and characters/symbols:

```javascript
const text = 'Hello 🌍';

// utf8 (alias: utf-8) — variable-width, 1-4 bytes per character
// THE default encoding everywhere in Node.js
const utf8Buf = Buffer.from(text, 'utf8');
console.log(utf8Buf.length); // 10: H(1)+e(1)+l(1)+l(1)+o(1)+space(1)+🌍(4) = 10 bytes
// ASCII chars: 1 byte each (0x00-0x7F)
// Extended: 2-4 bytes using leading 0xC0, 0xE0, 0xF0 patterns
console.log(utf8Buf);
// <Buffer 48 65 6c 6c 6f 20 f0 9f 8c 8d>
//  H     e     l     l     o     sp   🌍 (4 bytes: F0 9F 8C 8D)

// utf16le (alias: utf-16le, ucs2, ucs-2) — fixed 2 bytes per BMP char, 4 for surrogate pairs
// JavaScript strings are internally UTF-16 — this is a zero-copy conversion for ASCII-range text
const utf16Buf = Buffer.from('Hello', 'utf16le');
console.log(utf16Buf.length); // 10: 5 chars × 2 bytes each
console.log(utf16Buf);
// <Buffer 48 00 65 00 6c 00 6c 00 6f 00>
// Each char stored as little-endian 16-bit value

// latin1 (alias: binary, iso-8859-1) — exactly 1 byte per character, values 0x00-0xFF
// Only covers the first 256 Unicode code points
// Critical for binary protocols: treats each byte as a char with the same code point
const latin1Buf = Buffer.from('café', 'latin1');
console.log(latin1Buf.length); // 4 — always one byte per char
// é → 0xE9 (correct in latin1), not 0xC3 0xA9 (as it would be in UTF-8)

// ascii — 7-bit only, strips the high bit (byte & 0x7F)
// Lossy for non-ASCII: 0xFF → 0x7F (corrupts data)
// Only use when you KNOW input is pure 7-bit ASCII
const asciiBuf = Buffer.from('Hello', 'ascii');
console.log(asciiBuf.length); // 5

// base64 — 3 bytes → 4 ASCII characters (33% size overhead)
// Used for encoding binary data in text contexts: JSON, HTTP headers, data URIs
const b64Buf = Buffer.from('SGVsbG8gV29ybGQ=', 'base64');
console.log(b64Buf.toString('utf8')); // 'Hello World'

// base64url — URL-safe base64: replaces + with -, / with _, removes = padding
// Used in JWT tokens, URL parameters, OAuth
const b64urlBuf = Buffer.from('SGVsbG8-V29ybGQ', 'base64url');

// hex — each byte as two lowercase hex digits (00-ff), 2× size
const hexBuf = Buffer.from('48656c6c6f', 'hex');
console.log(hexBuf.toString('utf8')); // 'Hello'
```

Encoding size comparison for the same data:

```javascript
const data = Buffer.from('Hello, World!'); // 13 bytes of source data

console.log(data.toString('utf8').length);    // 13  chars (100% of bytes)
console.log(data.toString('base64').length);  // 20  chars (154% of bytes — 4/3 ratio)
console.log(data.toString('hex').length);     // 26  chars (200% of bytes — 2× ratio)
console.log(data.toString('latin1').length);  // 13  chars (100% — lossless for 0-255)

// Choosing the right encoding:
// utf8    → default; text data; files; HTTP bodies; JSON values
// base64  → binary in JSON; email attachments; data URIs; API tokens
// base64url → JWT; URL params; OAuth tokens (no +/= special chars)
// hex     → debug output; checksums; crypto key display; MAC addresses
// latin1  → legacy protocols; binary-safe string operations; HTTP/1.1 raw headers
// utf16le → Windows file formats; COM interfaces; legacy Windows APIs
```

**Q4. What is the difference between `Buffer.from(str, encoding)` and `buf.toString(encoding)` — are they inverse operations?**

A: Yes — they are inverse operations for any lossless encoding. `Buffer.from(str, enc)` encodes a string into bytes; `buf.toString(enc)` decodes bytes back into a string. Round-tripping through any valid encoding returns the original string:

```javascript
// Round-trip: string → buffer → string
const original = 'Hello, 世界 🌍';

// UTF-8 round-trip (lossless for all Unicode):
const utf8Buf = Buffer.from(original, 'utf8');
const recovered = utf8Buf.toString('utf8');
console.log(recovered === original); // true

// Base64 round-trip:
const b64 = Buffer.from(original, 'utf8').toString('base64');
const fromB64 = Buffer.from(b64, 'base64').toString('utf8');
console.log(fromB64 === original); // true

// Hex round-trip:
const hex = Buffer.from(original, 'utf8').toString('hex');
const fromHex = Buffer.from(hex, 'hex').toString('utf8');
console.log(fromHex === original); // true

// LOSSY encoding — latin1 cannot represent non-latin1 characters:
const latin1Buf = Buffer.from(original, 'latin1');
// '世' (U+4E16) exceeds 0xFF — only the low byte (0x16) is stored
const recovered2 = latin1Buf.toString('latin1');
console.log(recovered2 === original); // false — '世界 🌍' is corrupted
```

The encoding mismatch trap — one of the most common bugs in Node.js:

```javascript
// WRONG: encode as UTF-8, decode as latin1:
const buf = Buffer.from('café', 'utf8');
// UTF-8: c(63) a(61) f(66) é(C3 A9) — 5 bytes
console.log(buf.toString('latin1')); // 'cafÃ©' — mojibake!
// C3 is 'Ã' in latin1, A9 is '©' in latin1

// WRONG: encode as base64, decode as utf8:
const b64 = 'SGVsbG8=';
console.log(Buffer.from(b64, 'utf8').toString()); // 'SGVsbG8=' — decoded as UTF-8 chars
// You didn't decode the base64 — you just stored the ASCII characters 'S','G','V',...

// CORRECT: decode base64 first, then interpret result:
console.log(Buffer.from(b64, 'base64').toString('utf8')); // 'Hello'
```

A practical pattern — always be explicit about encoding at boundaries:

```javascript
// At API boundary: incoming base64 string → work with bytes → outgoing base64
function processBase64Payload(input: string): string {
    // Step 1: decode from base64 to raw bytes
    const bytes = Buffer.from(input, 'base64');

    // Step 2: operate on bytes
    const processed = xorEncrypt(bytes, key);

    // Step 3: encode back to base64 for transport
    return processed.toString('base64');
}
```

**Q5. How does base64 encoding work mechanically, and what is base64url?**

A: Base64 encodes arbitrary bytes using only 64 printable ASCII characters (`A-Z`, `a-z`, `0-9`, `+`, `/`) plus `=` for padding. Every 3 bytes of input become 4 base64 characters:

```
Input bytes:  M        a        n
Binary:       01001101 01100001 01101110
Groups of 6:  010011 | 010110 | 000101 | 101110
Base64 index: 19       22       5        46
Base64 char:  T        W        F        u
Result:       TWFu
```

Padding with `=` when input length is not a multiple of 3:

```javascript
// 1 byte remaining → 2 base64 chars + '=='
Buffer.from([0x4D]).toString('base64');        // 'TQ=='
// 0x4D = 01001101 → 010011 | 01(0000) → T Q → 'TQ=='

// 2 bytes remaining → 3 base64 chars + '='
Buffer.from([0x4D, 0x61]).toString('base64'); // 'TWE='

// 3 bytes → 4 base64 chars, no padding
Buffer.from([0x4D, 0x61, 0x6E]).toString('base64'); // 'TWFu'

// Verifying in Node.js:
const bytes = Buffer.from([72, 101, 108, 108, 111]); // 'Hello'
console.log(bytes.toString('base64')); // 'SGVsbG8='
// 72  101 108   → 010010 000110 010101 101100 → S G V s
// 108 111       → 011011 000110 1111(00)       → b G 8 =
```

Base64url is a variant used in URLs and JWTs — same algorithm, different character mapping:

```javascript
// base64:    uses + and / which are special in URLs, and = padding
// base64url: uses - and _ instead, drops = padding

// Standard base64:
const b64 = Buffer.from('data+with/special==chars').toString('base64');
// Might contain: +, /, = — all must be percent-encoded in URLs

// URL-safe base64:
const b64url = Buffer.from('data').toString('base64url');
// Never contains +, /, or = — safe in URL path segments and query strings
console.log(b64url); // 'ZGF0YQ'  (no trailing =)

// Manual conversion between the two (for compatibility with legacy systems):
const toBase64url = (b64: string) =>
    b64.replace(/\+/g, '-').replace(/\//g, '_').replace(/=/g, '');

const fromBase64url = (b64url: string) => {
    const padded = b64url + '=='.slice(0, (4 - b64url.length % 4) % 4);
    return padded.replace(/-/g, '+').replace(/_/g, '/');
};

// JWT tokens use base64url: header.payload.signature
// Each segment is base64url-encoded JSON (header/payload) or raw bytes (signature)
const [headerB64, payloadB64, sigB64] = token.split('.');
const header = JSON.parse(Buffer.from(headerB64, 'base64url').toString('utf8'));
const payload = JSON.parse(Buffer.from(payloadB64, 'base64url').toString('utf8'));
```

## Section 3: Reading and Writing Binary Data

**Q6. How do you read and write multi-byte integers from a Buffer — what is endianness?**

A: Buffers store raw bytes. When a value spans multiple bytes (a 32-bit integer, a 64-bit float), you need to specify the **byte order** — which end (big or little) goes first in memory.

```
Value: 0x12345678 (decimal: 305,419,896)

Big-endian (BE) — most significant byte first:
Byte 0: 0x12
Byte 1: 0x34
Byte 2: 0x56
Byte 3: 0x78
Network protocols (TCP/IP, HTTP/2, DNS) use big-endian ("network byte order")

Little-endian (LE) — least significant byte first:
Byte 0: 0x78
Byte 1: 0x56
Byte 2: 0x34
Byte 3: 0x12
x86/x64 CPUs use little-endian; most file formats do too (BMP, WAV, ZIP)
```

Node.js Buffer provides explicit BE and LE methods for every integer width:

```javascript
const buf = Buffer.alloc(16);

// Unsigned integers:
buf.writeUInt8(255, 0);             // 1 byte  — no endianness (single byte)
buf.writeUInt16BE(0x1234, 1);       // 2 bytes big-endian:    12 34
buf.writeUInt16LE(0x1234, 3);       // 2 bytes little-endian: 34 12
buf.writeUInt32BE(0x12345678, 5);   // 4 bytes big-endian:    12 34 56 78
buf.writeUInt32LE(0x12345678, 9);   // 4 bytes little-endian: 78 56 34 12
buf.writeBigUInt64BE(0x123456789ABCDEFn, 13); // 8 bytes big-endian

// Signed integers:
buf.writeInt8(-1, 0);               // Stored as 0xFF (two's complement)
buf.writeInt16BE(-256, 0);          // Stored as 0xFF 0x00
buf.writeInt32LE(-1, 0);            // Stored as 0xFF 0xFF 0xFF 0xFF

// Floating point:
buf.writeFloatBE(3.14, 0);          // 4-byte IEEE 754 float, big-endian
buf.writeDoubleBE(Math.PI, 4);      // 8-byte IEEE 754 double, big-endian

// Reading back:
const uint32 = buf.readUInt32BE(5); // 0x12345678
const float  = buf.readFloatBE(0);  // 3.14 (approximately)

// Variable-length integer reading:
buf.readUIntBE(0, 3);  // Read 3 bytes as big-endian unsigned int (byteLength: 1-6)
buf.readUIntLE(0, 6);  // Read 6 bytes as little-endian unsigned int
```

Practical example — parsing a binary protocol header:

```typescript
// Binary packet format (big-endian, as is standard for network protocols):
// Byte 0:    version (uint8)
// Bytes 1-2: message type (uint16)
// Bytes 3-6: payload length (uint32)
// Bytes 7-N: payload

function parsePacketHeader(buf: Buffer): { version: number; type: number; payloadLength: number } {
    if (buf.length < 7) throw new Error(`Header too short: ${buf.length} bytes`);

    return {
        version:       buf.readUInt8(0),
        type:          buf.readUInt16BE(1),
        payloadLength: buf.readUInt32BE(3),
    };
}

function buildPacket(type: number, payload: Buffer): Buffer {
    const header = Buffer.alloc(7);
    header.writeUInt8(1, 0);                  // version = 1
    header.writeUInt16BE(type, 1);             // message type
    header.writeUInt32BE(payload.length, 3);   // payload length

    return Buffer.concat([header, payload]);
}
```

**Q7. What is the difference between `Buffer.slice()`, `Buffer.subarray()`, and `Buffer.copy()`?**

A: These three methods interact with Buffer memory very differently — confusing them causes subtle mutation bugs or unnecessary allocations:

```javascript
const original = Buffer.from([1, 2, 3, 4, 5, 6, 7, 8]);

// --- slice() and subarray() — SHARED MEMORY (zero-copy views) ---

const sliced = original.slice(2, 6);     // Returns Buffer viewing bytes 2-5
const subarr = original.subarray(2, 6);  // Identical behavior in modern Node.js

// Mutation through the slice affects the original:
sliced[0] = 99;
console.log(original); // <Buffer 01 02 63 04 05 06 07 08>
//                                       ↑ 0x63 = 99 — original mutated!

// Reading from the slice reflects original changes:
original[3] = 77;
console.log(sliced); // <Buffer 63 4d 05 06>
//                                   ↑ 0x4D = 77 — slice reflects mutation

// --- copy() — INDEPENDENT COPY ---

const copied = Buffer.alloc(4);
original.copy(copied, 0, 2, 6); // copy(target, targetStart, sourceStart, sourceEnd)
// Copies bytes 2-5 from original into copied starting at position 0

copied[0] = 255;
console.log(original[2]); // 99 — original unchanged, copy is independent
console.log(copied);       // <Buffer ff 4d 05 06>

// slice() vs subarray() — historical context:
// In Node.js < 17.5: slice() returned a Buffer, subarray() returned a Uint8Array
// In Node.js ≥ 17.5: slice() was deprecated in favor of subarray()
// Both now return a Buffer that shares memory
// Prefer subarray() in new code — it matches the Uint8Array spec

// Gotcha: Buffer.from(buffer) makes an independent copy — use when you need isolation:
const independent = Buffer.from(original.subarray(2, 6)); // Copy, not a view
independent[0] = 0;
console.log(original[2]); // Still 99 — independent copy confirmed
```

When to use each:

```javascript
// Use subarray() (or slice()) when:
// - You need a window into a larger buffer for reading
// - You want to pass a sub-section to a function without copying
// - The original buffer will stay alive at least as long as the slice

function processHeader(packet: Buffer): void {
    const header = packet.subarray(0, 7); // Zero-copy: no allocation
    parsePacketHeader(header);            // Read-only access to first 7 bytes
}

// Use copy() when:
// - You need to modify the sub-section without affecting the original
// - The original may be released or modified independently
// - Building a new buffer from parts of existing ones

function buildAckPacket(original: Buffer): Buffer {
    const ack = Buffer.alloc(original.length);
    original.copy(ack);         // Independent copy — safe to modify
    ack.writeUInt8(0x06, 0);    // Set ACK flag in copy
    return ack;
}
```

**Q8. How do you safely compare Buffers — why is `===` wrong?**

A: `===` on Buffers compares references, not contents. Two Buffers with identical bytes are not `===` unless they are literally the same object. Use `Buffer.compare()` or `buf.equals()`:

```javascript
const a = Buffer.from('hello');
const b = Buffer.from('hello');

// WRONG: reference comparison
console.log(a === b);           // false — different objects in memory

// CORRECT: content comparison
console.log(a.equals(b));       // true  — byte-by-byte comparison
console.log(Buffer.compare(a, b)); // 0   — 0 means equal (like strcmp)

// Buffer.compare() for sorting — returns -1, 0, or 1:
const buffers = [
    Buffer.from('banana'),
    Buffer.from('apple'),
    Buffer.from('cherry')
];

buffers.sort(Buffer.compare);
console.log(buffers.map(b => b.toString()));
// ['apple', 'banana', 'cherry'] — lexicographic byte order

// Checking if a buffer starts/ends with a sequence:
const packet = Buffer.from([0xFF, 0xFE, 0x00, 0x01, 0x02]);
const magic = Buffer.from([0xFF, 0xFE]);

// Manual prefix check:
const startsWithMagic = packet.subarray(0, magic.length).equals(magic); // true

// Security: timing-safe comparison for secrets (prevents timing attacks)
import crypto from 'crypto';

function safeCompare(a: Buffer, b: Buffer): boolean {
    if (a.length !== b.length) return false;
    // crypto.timingSafeEqual: takes same time regardless of where bytes differ
    // Prevents attackers from inferring secret content by measuring response time
    return crypto.timingSafeEqual(a, b);
}

// Why timing-safe matters:
// Regular comparison: short-circuits at first mismatch
// → attacker sends guesses, measures response time, deduces bytes one by one
// → can crack a 32-byte secret in 32×256 guesses instead of 256^32
// timingSafeEqual always compares all bytes — constant time
```

## Section 4: Real-World Binary Patterns

**Q9. How do you handle binary file I/O — reading file headers, magic bytes, and binary formats?**

A: Most binary file formats have a structured header at a known byte offset. Buffers with the read methods make this mechanical:

```typescript
import fs from 'fs/promises';

// PNG file format:
// Bytes 0-7:  Magic signature: 89 50 4E 47 0D 0A 1A 0A
// Bytes 8-11: IHDR chunk length (uint32 BE)
// Bytes 12-15: Chunk type 'IHDR'
// Bytes 16-19: Image width (uint32 BE)
// Bytes 20-23: Image height (uint32 BE)
// Byte 24:    Bit depth (uint8)
// Byte 25:    Color type (uint8)

const PNG_MAGIC = Buffer.from([0x89, 0x50, 0x4E, 0x47, 0x0D, 0x0A, 0x1A, 0x0A]);

interface PNGInfo {
    width: number;
    height: number;
    bitDepth: number;
    colorType: string;
}

async function readPNGHeader(filePath: string): Promise<PNGInfo> {
    const fd = await fs.open(filePath, 'r');
    try {
        const header = Buffer.alloc(26);
        await fd.read(header, 0, 26, 0); // Read exactly 26 bytes from offset 0

        // Verify magic bytes
        if (!header.subarray(0, 8).equals(PNG_MAGIC)) {
            throw new Error('Not a PNG file');
        }

        const width     = header.readUInt32BE(16);
        const height    = header.readUInt32BE(20);
        const bitDepth  = header.readUInt8(24);
        const colorType = header.readUInt8(25);

        const colorTypes: Record<number, string> = {
            0: 'Grayscale', 2: 'RGB', 3: 'Indexed', 4: 'Grayscale+Alpha', 6: 'RGBA'
        };

        return { width, height, bitDepth, colorType: colorTypes[colorType] ?? 'Unknown' };
    } finally {
        await fd.close();
    }
}

// Reading a binary format incrementally using streams + buffer accumulation:
async function parseBinaryFrames(stream: NodeJS.ReadableStream): Promise<Frame[]> {
    const frames: Frame[] = [];
    const chunks: Buffer[] = [];

    for await (const chunk of stream) {
        chunks.push(chunk as Buffer);
    }

    const data = Buffer.concat(chunks);
    let offset = 0;

    while (offset < data.length) {
        // Each frame: 4-byte length header + N-byte payload
        if (offset + 4 > data.length) break; // Incomplete header
        const frameLen = data.readUInt32BE(offset);
        offset += 4;

        if (offset + frameLen > data.length) break; // Incomplete frame
        const payload = data.subarray(offset, offset + frameLen); // Zero-copy slice
        frames.push(parseFrame(payload));
        offset += frameLen;
    }

    return frames;
}
```

**Q10. How do you convert between Buffer and common web formats — data URIs, multipart, hex digests?**

A: Several web and protocol formats exchange binary data in specific text encodings. Buffer makes each conversion mechanical:

```typescript
// 1. Data URI (embedded images in HTML/CSS)
// Format: data:[mediatype][;base64],<data>
function bufferToDataURI(buf: Buffer, mimeType: string): string {
    return `data:${mimeType};base64,${buf.toString('base64')}`;
}

function dataURIToBuffer(dataURI: string): { buf: Buffer; mimeType: string } {
    const match = dataURI.match(/^data:([^;]+);base64,(.+)$/);
    if (!match) throw new Error('Invalid data URI');
    return {
        mimeType: match[1],
        buf: Buffer.from(match[2], 'base64')
    };
}

// Usage:
const imageData = await fs.readFile('logo.png');
const dataURI = bufferToDataURI(imageData, 'image/png');
// 'data:image/png;base64,iVBORw0KGgo...'  → embeds directly in <img src="...">

// 2. Crypto hash digests (hex display)
import crypto from 'crypto';

function sha256Hex(data: Buffer | string): string {
    return crypto.createHash('sha256').update(data).digest('hex');
    // digest('hex') returns a 64-char hex string (32 bytes × 2 hex chars per byte)
}

function sha256Base64(data: Buffer | string): string {
    return crypto.createHash('sha256').update(data).digest('base64');
    // 44 chars (32 bytes → base64, 33% more compact than hex)
}

// Verify file integrity:
async function verifyChecksum(filePath: string, expectedHex: string): Promise<boolean> {
    const data = await fs.readFile(filePath);
    const actual = sha256Hex(data);
    return crypto.timingSafeEqual(
        Buffer.from(actual, 'hex'),
        Buffer.from(expectedHex, 'hex')
    );
}

// 3. Hex encoding for display / logging (never log raw buffers containing secrets)
function redactedLog(label: string, secret: Buffer): void {
    // Show first 4 bytes as hex, redact the rest
    const preview = secret.subarray(0, 4).toString('hex');
    console.log(`${label}: ${preview}... [${secret.length} bytes, redacted]`);
}

// 4. HTTP multipart boundary parsing (simplified)
function parseMultipartBoundary(body: Buffer, boundary: string): Buffer[] {
    const delimiter = Buffer.from(`--${boundary}`);
    const parts: Buffer[] = [];
    let start = 0;

    while (start < body.length) {
        const idx = body.indexOf(delimiter, start);
        if (idx === -1) break;

        const partStart = idx + delimiter.length + 2; // Skip \r\n after boundary
        const nextIdx = body.indexOf(delimiter, partStart);
        if (nextIdx === -1) break;

        // Each part: headers + \r\n\r\n + body
        const part = body.subarray(partStart, nextIdx - 2); // Trim trailing \r\n
        const headerEnd = part.indexOf(Buffer.from('\r\n\r\n'));
        if (headerEnd !== -1) {
            parts.push(part.subarray(headerEnd + 4)); // Body after headers
        }
        start = nextIdx;
    }
    return parts;
}

// 5. Buffer in JSON (JSON has no binary type — must encode)
// Common patterns:
const secretKey = crypto.randomBytes(32);

// Option A: hex string in JSON (readable, verbose)
const asHex = { key: secretKey.toString('hex') };

// Option B: base64 string in JSON (compact, standard)
const asB64 = { key: secretKey.toString('base64') };

// Option C: array of bytes in JSON (rarely useful, very verbose)
const asArray = { key: Array.from(secretKey) };

// Decoding on the other side:
const keyFromHex = Buffer.from(asHex.key, 'hex');
const keyFromB64 = Buffer.from(asB64.key, 'base64');
```

**Q11. How does Buffer interact with crypto operations — hashing, HMAC, and encryption?**

A: All of Node.js's `crypto` module operates on Buffers. Understanding the binary boundary is essential for correct crypto code:

```typescript
import crypto from 'crypto';

// --- Hashing ---
// Input: string or Buffer; Output: Buffer (via .digest()) or string (via .digest(encoding))
const hash = crypto.createHash('sha256');
hash.update('first chunk');        // Can call update() multiple times (streaming hash)
hash.update(Buffer.from([0x00]));  // Mix strings and Buffers
const digest: Buffer = hash.digest();           // Raw 32 bytes
const hexDigest: string = hash.digest('hex');   // '...' 64 hex chars

// WRONG: calling digest() twice — hash is finalized after first digest() call
const h = crypto.createHash('sha256').update('data');
h.digest('hex');  // OK
h.digest('hex');  // Error: HashFinalizeError — hash already finalized

// --- HMAC ---
const hmacKey = crypto.randomBytes(32); // 256-bit key
const mac = crypto
    .createHmac('sha256', hmacKey)
    .update(message)
    .digest(); // Raw 32-byte MAC

// Verify HMAC — MUST use timingSafeEqual:
function verifyHMAC(message: Buffer, receivedMAC: Buffer, key: Buffer): boolean {
    const expected = crypto.createHmac('sha256', key).update(message).digest();
    if (expected.length !== receivedMAC.length) return false;
    return crypto.timingSafeEqual(expected, receivedMAC); // Constant-time
}

// --- Symmetric Encryption (AES-256-GCM) ---
// GCM mode: provides authentication (no separate HMAC needed)
function encrypt(plaintext: Buffer, key: Buffer): { iv: Buffer; ciphertext: Buffer; tag: Buffer } {
    const iv = crypto.randomBytes(12); // 96-bit IV: standard for GCM
    const cipher = crypto.createCipheriv('aes-256-gcm', key, iv);

    const ciphertext = Buffer.concat([
        cipher.update(plaintext),   // Encrypt in chunks
        cipher.final()              // Flush final block
    ]);
    const tag = cipher.getAuthTag(); // 16-byte authentication tag (after final())

    return { iv, ciphertext, tag };
}

function decrypt(ciphertext: Buffer, key: Buffer, iv: Buffer, tag: Buffer): Buffer {
    const decipher = crypto.createDecipheriv('aes-256-gcm', key, iv);
    decipher.setAuthTag(tag); // Must set BEFORE calling update/final

    try {
        return Buffer.concat([
            decipher.update(ciphertext),
            decipher.final() // Throws if authentication tag is invalid
        ]);
    } catch {
        throw new Error('Decryption failed: authentication tag mismatch');
    }
}

// --- Key Derivation ---
// Converting a password (string) to a key (Buffer):
async function deriveKey(password: string, salt: Buffer): Promise<Buffer> {
    return new Promise((resolve, reject) => {
        crypto.pbkdf2(
            password,
            salt,
            310_000,   // Iterations — OWASP 2023 recommendation for PBKDF2-SHA256
            32,        // Key length in bytes (256 bits)
            'sha256',
            (err, key) => err ? reject(err) : resolve(key)
        );
    });
}

// Usage — encrypt a string payload:
const key = await deriveKey('user-password', crypto.randomBytes(32));
const payload = Buffer.from(JSON.stringify({ userId: 123, exp: Date.now() }));
const { iv, ciphertext, tag } = encrypt(payload, key);

// Serialize for storage/transport: concatenate IV + tag + ciphertext, then base64
const stored = Buffer.concat([iv, tag, ciphertext]).toString('base64');
```

## Section 5: Performance and Memory

**Q12. How does Buffer memory allocation work — what is the Buffer pool?**

A: Node.js maintains an internal **pre-allocated memory pool** (8KB by default) for small Buffer allocations. When you call `Buffer.allocUnsafe(n)` for `n < 4096` bytes, Node.js carves out a chunk from this pool instead of asking the OS for new memory — making small buffer allocation very fast.

```javascript
// Visualizing the pool:
//
//  ┌─────────────────────────────────────────────────────────────┐
//  │                  8KB Pool (ArrayBuffer)                     │
//  │  ┌──────┐┌──────────┐┌───┐┌────────┐┌──────────────────┐  │
//  │  │ 64B  ││  128B    ││32B││  256B  ││    remaining...  │  │
//  │  │buf1  ││  buf2    ││bu3││  buf4  ││                  │  │
//  │  └──────┘└──────────┘└───┘└────────┘└──────────────────┘  │
//  └─────────────────────────────────────────────────────────────┘
//  All share the same underlying ArrayBuffer — no separate OS allocations

// The pool threshold: Buffer.poolSize / 2 = 4096 bytes
// Below threshold:  Buffer.allocUnsafe() → pool allocation (fast, shared ArrayBuffer)
// Above threshold:  Buffer.allocUnsafe() → dedicated OS allocation (slower)
// Buffer.alloc():   NEVER uses pool (zero-fills, no shortcuts)

// Observing pool behavior:
const a = Buffer.allocUnsafe(10);
const b = Buffer.allocUnsafe(10);

// a and b SHARE the underlying ArrayBuffer if both are from the pool:
console.log(a.buffer === b.buffer); // true — same 8KB ArrayBuffer!
console.log(a.byteOffset);          // e.g., 0
console.log(b.byteOffset);          // e.g., 10  — starts right after a

// DANGER: if you pass a.buffer to another context (e.g., Worker thread transfer):
// transferring the ArrayBuffer invalidates BOTH a and b — they share it!
const shared = a.buffer; // This is the full 8KB pool, not just 10 bytes
// Never transfer .buffer directly from a small pooled allocation

// Safe transfer: always copy to a dedicated ArrayBuffer first:
const isolated = a.buffer.slice(a.byteOffset, a.byteOffset + a.byteLength);
worker.postMessage({ buf: isolated }, [isolated]); // Safe transfer
```

Memory management implications:

```javascript
// Large Buffers (≥ 4KB) are GC-tracked but memory is off-heap:
// V8 GC knows about the Buffer object (on heap) but not the raw memory (off heap)
// A long-lived Buffer reference prevents the memory from being freed
// This is a common source of memory leaks in streaming code:

class LeakyCache {
    private cache = new Map<string, Buffer>();

    store(key: string, data: Buffer): void {
        this.cache.set(key, data); // Buffer memory held forever if cache grows unbounded
    }
}

// Fix: use LRU cache with eviction, or store only what you need:
class SafeCache {
    private cache = new Map<string, Buffer>();
    private readonly maxSize = 100;

    store(key: string, data: Buffer): void {
        if (this.cache.size >= this.maxSize) {
            const firstKey = this.cache.keys().next().value;
            this.cache.delete(firstKey); // Evict oldest
        }
        this.cache.set(key, data);
    }
}
```

**Q13. What is the performance difference between string concatenation and Buffer.concat(), and when does it matter?**

A: String concatenation for building large outputs is significantly slower than Buffer operations because each `+` creates a new string allocation. For binary data, building an array of chunks and calling `Buffer.concat()` once at the end is the standard pattern:

```javascript
// SLOW: building a large payload with string concatenation
function buildPayloadSlow(records: Record<string, unknown>[]): Buffer {
    let result = '';
    for (const record of records) {
        result += JSON.stringify(record) + '\n'; // New string allocation each iteration
    }
    return Buffer.from(result, 'utf8'); // One final allocation
}
// For 100k records: ~100k string allocations, GC pressure, O(N²) total bytes copied

// FAST: collecting chunks and concatenating once
function buildPayloadFast(records: Record<string, unknown>[]): Buffer {
    const chunks: Buffer[] = [];
    for (const record of records) {
        chunks.push(Buffer.from(JSON.stringify(record) + '\n', 'utf8'));
    }
    return Buffer.concat(chunks); // One final allocation, O(N) total bytes copied
}
// For 100k records: 100k small allocations but no repeated copying

// FASTEST for known total size: pre-allocate and write directly
function buildPayloadPrealloc(records: Record<string, unknown>[]): Buffer {
    // If you know total size in advance:
    const serialized = records.map(r => Buffer.from(JSON.stringify(r) + '\n'));
    const totalSize = serialized.reduce((sum, b) => sum + b.length, 0);

    const result = Buffer.allocUnsafe(totalSize);
    let offset = 0;
    for (const buf of serialized) {
        buf.copy(result, offset); // Copies directly into pre-allocated memory
        offset += buf.length;
    }
    return result;
}

// For streaming scenarios: never concat at all — pipe chunks directly:
async function streamPayload(records: Record<string, unknown>[], res: Response): Promise<void> {
    for (const record of records) {
        // Write each chunk directly — no accumulation, O(1) memory
        const ok = res.write(JSON.stringify(record) + '\n');
        if (!ok) await new Promise(resolve => res.once('drain', resolve));
    }
    res.end();
}
```

## Section 6: Scenario-Based Questions

**Q14. "What's wrong with this code? The HMAC verification seems to always return true."**

```javascript
function verifyToken(token, secret) {
    const [data, mac] = token.split('.');
    const expected = crypto.createHmac('sha256', secret)
        .update(data)
        .digest('hex');
    return expected == mac;
}
```

A: Two bugs — one correctness issue and one critical security vulnerability:

```javascript
// Bug 1: Using == instead of === (minor, but sloppy)
// == does type coercion — '0' == false is true in JS
// For string comparison this happens to work, but === is always correct

// Bug 2: CRITICAL — timing attack vulnerability
// String comparison with == / === short-circuits at the first differing character
// An attacker can probe the MAC byte-by-byte:
//   - Send MAC '00...' → gets rejected at char 0 very quickly
//   - Send MAC 'a0...' → takes slightly longer (first char matches)
//   - Send MAC 'ab...' → takes even longer
// By measuring response time, the attacker can reconstruct the valid MAC
// without knowing the secret — breaking the HMAC protection entirely

// Bug 3 (subtle): comparing hex strings instead of raw bytes
// Two different hex strings could theoretically represent the same bytes
// with different cases — 'AB' vs 'ab' — safer to compare raw Buffers

// Fixed version:
function verifyToken(token: string, secret: string): boolean {
    const [data, receivedMacHex] = token.split('.');
    if (!data || !receivedMacHex) return false;

    const expected = crypto.createHmac('sha256', secret)
        .update(data)
        .digest(); // Raw Buffer, not hex string

    const received = Buffer.from(receivedMacHex, 'hex');

    // Length check first — timingSafeEqual requires equal lengths
    if (expected.length !== received.length) return false;

    // Constant-time comparison — always takes the same time regardless of content
    return crypto.timingSafeEqual(expected, received);
}
```

**Q15. "You receive a binary WebSocket message. How do you parse it if it's a custom binary protocol with a type byte, a 2-byte sequence number, and a variable-length JSON payload?"**

A: The pattern is: validate length, read fixed-width fields, then decode the variable-length section:

```typescript
import WebSocket from 'ws';

// Protocol definition:
// Byte 0:    Message type (uint8)
//   0x01 = command, 0x02 = response, 0x03 = event, 0xFF = heartbeat
// Bytes 1-2: Sequence number (uint16 BE)
// Bytes 3-6: Payload length (uint32 BE)
// Bytes 7-N: JSON payload (utf8)

const HEADER_SIZE = 7;

enum MessageType {
    Command   = 0x01,
    Response  = 0x02,
    Event     = 0x03,
    Heartbeat = 0xFF,
}

interface ParsedMessage {
    type: MessageType;
    sequence: number;
    payload: unknown;
}

function parseMessage(raw: Buffer): ParsedMessage {
    if (raw.length < HEADER_SIZE) {
        throw new Error(`Message too short: ${raw.length} < ${HEADER_SIZE}`);
    }

    const type          = raw.readUInt8(0);
    const sequence      = raw.readUInt16BE(1);
    const payloadLength = raw.readUInt32BE(3);

    if (raw.length !== HEADER_SIZE + payloadLength) {
        throw new Error(
            `Length mismatch: header says ${payloadLength} bytes, ` +
            `got ${raw.length - HEADER_SIZE}`
        );
    }

    const payloadBuf = raw.subarray(HEADER_SIZE); // Zero-copy slice
    const payload = payloadBuf.length > 0
        ? JSON.parse(payloadBuf.toString('utf8'))
        : null;

    return { type, sequence, payload };
}

function buildMessage(type: MessageType, sequence: number, payload: unknown): Buffer {
    const payloadBuf = payload !== null
        ? Buffer.from(JSON.stringify(payload), 'utf8')
        : Buffer.alloc(0);

    const msg = Buffer.allocUnsafe(HEADER_SIZE + payloadBuf.length);
    msg.writeUInt8(type, 0);
    msg.writeUInt16BE(sequence, 1);
    msg.writeUInt32BE(payloadBuf.length, 3);
    payloadBuf.copy(msg, HEADER_SIZE);

    return msg;
}

// WebSocket handler:
const wss = new WebSocket.Server({ port: 8080 });

wss.on('connection', (ws) => {
    let seqCounter = 0;

    ws.on('message', (data: Buffer) => {
        try {
            const msg = parseMessage(data);

            if (msg.type === MessageType.Heartbeat) {
                // Echo heartbeat back
                ws.send(buildMessage(MessageType.Heartbeat, msg.sequence, null));
                return;
            }

            // Handle command, dispatch response
            const response = handleCommand(msg.payload);
            ws.send(buildMessage(MessageType.Response, seqCounter++, response));

        } catch (err) {
            console.error('Failed to parse message:', err);
            ws.close(1002, 'Protocol error');
        }
    });
});
```

**Q16. "You need to stream a 2GB file upload, compute its SHA-256 hash on the fly, and store both the file and the hash — without loading the file into memory. How?"**

A: The solution is a Transform stream that passes data through unchanged while computing the hash incrementally — a "tee" with a side effect:

```typescript
import { pipeline } from 'stream/promises';
import { Transform } from 'stream';
import crypto from 'crypto';
import fs from 'fs';

class HashingPassThrough extends Transform {
    private hash = crypto.createHash('sha256');
    public digest: Buffer | null = null;

    _transform(chunk: Buffer, _enc: string, callback: Function): void {
        this.hash.update(chunk); // Feed chunk to hash computation
        this.push(chunk);        // Pass chunk through unchanged
        callback();
    }

    _flush(callback: Function): void {
        this.digest = this.hash.digest(); // Finalize hash when stream ends
        callback();
    }
}

async function handleFileUpload(
    req: NodeJS.ReadableStream,
    uploadId: string
): Promise<{ path: string; sha256: string; sizeBytes: number }> {

    const tmpPath = `/tmp/upload-${uploadId}`;
    const hasher = new HashingPassThrough();
    let sizeBytes = 0;

    // Count bytes as they pass through
    const sizeCounter = new Transform({
        transform(chunk: Buffer, _, cb) {
            sizeBytes += chunk.length;
            this.push(chunk);
            cb();
        }
    });

    await pipeline(
        req,            // HTTP request body — incoming file bytes
        sizeCounter,    // Count bytes
        hasher,         // Compute SHA-256 while passing through
        fs.createWriteStream(tmpPath)  // Write to disk
        // Memory usage: O(1) — one chunk in memory at a time regardless of file size
    );

    // After pipeline completes, hasher.digest is populated
    const sha256 = hasher.digest!.toString('hex');

    return { path: tmpPath, sha256, sizeBytes };
}

// Usage in Express:
app.post('/upload', async (req, res) => {
    const uploadId = crypto.randomUUID();
    try {
        const result = await handleFileUpload(req, uploadId);
        res.json(result);
        // { path: '/tmp/upload-...', sha256: 'a3f...', sizeBytes: 2147483648 }
    } catch (err) {
        await fs.promises.unlink(`/tmp/upload-${uploadId}`).catch(() => {});
        res.status(500).json({ error: 'Upload failed' });
    }
});
```

| `Buffer.alloc(n)` | Allocate n zero-filled bytes | ✅ Yes | Slower — zero-fills; use for security-sensitive data |

**Tip for interviews:** Six things separate strong candidates on this topic: (1) knowing that **`Buffer` is a `Uint8Array` subclass** — not a custom thing, but a typed array with extra Node.js methods; this comes up when interoperating with browser APIs, Worker threads (where you transfer `ArrayBuffer`, not `Buffer`), and `SharedArrayBuffer`; (2) understanding the **`allocUnsafe` pool** — small allocations share an 8KB `ArrayBuffer`, which means `.buffer` on a small Buffer gives you the whole pool, not just your bytes; transferring `.buffer` to a Worker invalidates all other Buffers carved from that pool; (3) being precise about **encoding at every boundary** — the most common binary bugs are encoding mismatches (`Buffer.from(b64str, 'utf8')` instead of `'base64'`), and strong candidates name the encoding explicitly at every `from()`/`toString()` call; (4) knowing the **`subarray()` vs `copy()` distinction** — slice is a zero-copy view into shared memory (mutations affect the original), copy is independent; confusing them causes data corruption bugs that are hard to reproduce; (5) using **`crypto.timingSafeEqual` for any MAC or token comparison** — explaining timing attacks concretely (not just "use timingSafeEqual because security") shows real production awareness; and (6) the **streaming hash pattern** — computing SHA-256 on the fly via a passthrough Transform rather than loading a file into memory to hash it is a standard pattern that comes up in file upload, integrity checking, and content-addressable storage systems.
