# API Gateway Pattern — Interview Q&A (5 YOE Level)

---

## Section 1: Fundamentals

**Q1. What is the API Gateway Pattern and what problem does it solve?**
A: An API Gateway is a single entry point that sits between external clients (mobile apps, web frontends, third-party partners) and a collection of backend microservices. Every inbound request passes through the gateway before being routed to the appropriate downstream service.

Without a gateway, clients face three problems that grow worse as the service count increases:

- **Client-side complexity** — a mobile app for a lending platform must know the address of the Loan Service, KYC Service, NACH Service, Bureau Service, and Disbursement Service independently. Any service relocation or decomposition breaks the client.
- **Duplicated cross-cutting concerns** — authentication, rate limiting, request logging, SSL termination, and correlation ID injection must be implemented separately in every service. A change to the auth scheme requires updating ten services.
- **Chatty clients** — a loan dashboard page may need data from the Loan Service, Applicant Service, EMI Service, and Notification Service. Without a gateway, the mobile client makes four round trips over a mobile network. With a gateway, one request fans out to four services and returns a single composed response.

The gateway solves these by centralising cross-cutting concerns and providing a stable, client-optimised interface in front of a changing service topology.

**Q2. What are the core responsibilities of an API Gateway?**
A:

| Responsibility | What it does | Alternative without a gateway |
|---|---|---|
| **Request routing** | Maps incoming URL/method to the correct downstream service | Client must know all service addresses |
| **Authentication** | Validates JWT / API key before the request reaches any service | Every service validates tokens independently |
| **Rate limiting** | Throttles clients by IP, API key, or tenant | Every service implements its own limiter |
| **SSL termination** | Handles TLS; downstream services communicate over plain HTTP inside the VPC | Every service manages its own TLS cert |
| **Request/response transformation** | Translates protocol, aggregates responses, renames fields | Client adapts to each service's schema |
| **Load balancing** | Distributes requests across service instances | Client hard-codes one instance |
| **Circuit breaking** | Stops routing to failing services; returns cached or fallback response | Client receives cascading 500s |
| **Observability** | Centralised access logs, latency metrics, tracing | Fragmented logs across services |
| **BFF (Backend for Frontend)** | Composes multiple service responses into a client-optimised shape | Client makes N requests; reassembles on device |

**Q3. What is the difference between an API Gateway, a Reverse Proxy, and a Load Balancer?**
A: These are often confused because all three sit in front of backend services — but they operate at different layers and have different scopes:

```
Internet
    │
    ▼
Load Balancer         ← Layer 4 (TCP/IP); distributes connections by IP/port;
    │                   no HTTP awareness; fastest; no routing logic
    ▼
Reverse Proxy         ← Layer 7 (HTTP); terminates SSL; caches; hides backend;
    │                   forwards requests to ONE backend type; limited logic
    ▼
API Gateway           ← Layer 7 (HTTP) + Application logic; routes to MANY
    │                   different backend services; auth; rate limit; transform;
    │                   aggregate; circuit break; BFF composition
    ▼
Microservices
```

In practice:
- **Load Balancer** (AWS NLB, HAProxy) — routes TCP connections; used for distributing across gateway instances themselves.
- **Reverse Proxy** (Nginx, Caddy) — HTTP-aware; SSL termination, static file serving, basic URL rewriting. Knows about one upstream application.
- **API Gateway** (AWS API Gateway, Kong, custom NestJS gateway) — knows about *many* upstream services; implements cross-cutting application concerns; provides a product API surface.

A production setup often layers all three: `NLB → Nginx (reverse proxy / SSL) → API Gateway → Microservices`.

**Q4. What are the different types of API Gateway deployments?**
A:

**1. Managed / Cloud Gateway** — AWS API Gateway, Azure API Management, Google Cloud Endpoints. Fully managed; zero infrastructure overhead; tight cloud integration (Lambda, IAM, WAF). Limited customisation; vendor lock-in; can be expensive at high volume.

**2. Self-hosted OSS Gateway** — Kong, KrakenD, Traefik, Tyk. Runs in your Kubernetes cluster. Plugin-based; highly customisable; cloud-agnostic. Requires ops expertise to run.

**3. Custom NestJS Gateway** — a NestJS application that acts as the gateway. Full control; same language as your services; team can own it end-to-end. Requires building routing, auth, rate limiting, and circuit breaking yourself (or via libraries). Best for platforms where the gateway contains significant BFF logic.

**4. Service Mesh sidecar (Istio, Linkerd)** — not technically a gateway but handles service-to-service concerns (mTLS, retries, circuit breaking) at the infrastructure layer. Complements a gateway; doesn't replace it.

In a fintech lending platform on AWS, the typical choice is: **AWS ALB → Kong or custom NestJS gateway → NestJS microservices**. The gateway handles auth, rate limiting, routing, and BFF aggregation. The service mesh handles service-to-service mTLS and retries inside the cluster.

**Q6. How do you implement the core HTTP proxy that forwards requests to downstream services?**
A:

```typescript
// proxy/proxy.service.ts
import { Injectable, HttpException } from '@nestjs/common';
import { HttpService } from '@nestjs/axios';
import { ConfigService } from '@nestjs/config';
import { Request } from 'express';
import { firstValueFrom, timeout, catchError } from 'rxjs';
import { AxiosError } from 'axios';

export interface ProxyOptions {
  targetService: string;       // service name → resolved to base URL via config
  path:          string;       // downstream path to forward to
  timeoutMs?:    number;       // per-request timeout (default 10s)
  stripPrefix?:  string;       // remove this prefix from the incoming URL before forwarding
}

@Injectable()
export class ProxyService {
  constructor(
    private readonly httpService: HttpService,
    private readonly config:      ConfigService,
  ) {}

  async forward<T>(
    req:     Request,
    options: ProxyOptions,
  ): Promise<T> {
    const baseUrl    = this.resolveServiceUrl(options.targetService);
    const targetUrl  = `${baseUrl}${options.path}`;
    const timeoutMs  = options.timeoutMs ?? 10_000;

    // Forward the headers that matter; strip hop-by-hop headers
    const forwardHeaders = this.buildForwardHeaders(req);

    try {
      const response = await firstValueFrom(
        this.httpService
          .request<T>({
            method:  req.method as any,
            url:     targetUrl,
            headers: forwardHeaders,
            data:    ['POST', 'PUT', 'PATCH'].includes(req.method) ? req.body : undefined,
            params:  req.query,
          })
          .pipe(
            timeout(timeoutMs),
            catchError((err: AxiosError) => {
              throw this.translateError(err, options.targetService);
            }),
          ),
      );

      return response.data;
    } catch (err) {
      if (err instanceof HttpException) throw err;
      throw new HttpException(
        { message: `Gateway error communicating with ${options.targetService}` },
        502,
      );
    }
  }

  private resolveServiceUrl(serviceName: string): string {
    const url = this.config.get<string>(`SERVICES.${serviceName.toUpperCase()}_URL`);
    if (!url) throw new Error(`No URL configured for service: ${serviceName}`);
    return url;
  }

  private buildForwardHeaders(req: Request): Record<string, string> {
    return {
      // Propagate tracing
      'x-correlation-id': req.headers['x-correlation-id'] as string ?? '',
      'x-tenant-id':      req.headers['x-tenant-id'] as string ?? '',
      // Forward auth context — downstream services trust the gateway's assertion
      'x-user-id':        (req as any).user?.id ?? '',
      'x-user-roles':     JSON.stringify((req as any).user?.roles ?? []),
      // Content type
      'content-type':     req.headers['content-type'] as string ?? 'application/json',
      // Do NOT forward: Authorization header with raw JWT (downstream uses x-user-id instead)
      // Do NOT forward: host, connection, transfer-encoding (hop-by-hop)
    };
  }

  private translateError(err: AxiosError, serviceName: string): HttpException {
    if (err.code === 'ECONNREFUSED' || err.code === 'ECONNRESET') {
      return new HttpException(
        { message: `Service ${serviceName} is unavailable`, code: 'SERVICE_UNAVAILABLE' },
        503,
      );
    }

    if (err.code === 'ETIMEDOUT') {
      return new HttpException(
        { message: `Service ${serviceName} timed out`, code: 'GATEWAY_TIMEOUT' },
        504,
      );
    }

    // Downstream returned an error — proxy its status and body
    if (err.response) {
      return new HttpException(err.response.data, err.response.status);
    }

    return new HttpException({ message: 'Bad Gateway' }, 502);
  }
}
```

// routes/loan/loan-gateway.controller.ts
import { Controller, All, Req, Param, UseGuards, HttpCode } from '@nestjs/common';
import { Request } from 'express';
import { ProxyService } from '../../proxy/proxy.service';
import { JwtAuthGuard } from '../../core/guards/jwt-auth.guard';
import { RolesGuard }   from '../../core/guards/roles.guard';
import { Roles }        from '../../core/decorators/roles.decorator';

@Controller('v1/loans')
@UseGuards(JwtAuthGuard, RolesGuard)
export class LoanGatewayController {
  constructor(private readonly proxy: ProxyService) {}

  // Proxy all loan application routes to Loan Service
  @All('applications')
  @HttpCode(200)
  async proxyApplications(@Req() req: Request): Promise<unknown> {
    return this.proxy.forward(req, {
      targetService: 'loan',
      path:          '/loan-applications',
      timeoutMs:     8_000,
    });
  }

  @All('applications/:id')
  async proxyApplicationById(
    @Req() req: Request,
    @Param('id') id: string,
  ): Promise<unknown> {
    return this.proxy.forward(req, {
      targetService: 'loan',
      path:          `/loan-applications/${id}`,
    });
  }

  @All('applications/:id/sanction')
  @Roles('CREDIT_MANAGER', 'BRANCH_MANAGER')
  async proxySanction(
    @Req() req: Request,
    @Param('id') id: string,
  ): Promise<unknown> {
    return this.proxy.forward(req, {
      targetService: 'loan',
      path:          `/loan-applications/${id}/sanction`,
      timeoutMs:     15_000, // sanctioning involves BRE evaluation — longer timeout
    });
  }
}

## Section 3: Authentication and Authorisation at the Gateway

**Q8. How does the API Gateway handle JWT authentication so downstream services don't repeat it?**
A: The gateway validates the JWT once. Downstream services trust the gateway — they never re-validate the token. The gateway communicates the verified identity via internal headers:

```typescript
// core/guards/jwt-auth.guard.ts
import { Injectable, CanActivate, ExecutionContext, UnauthorizedException } from '@nestjs/common';
import { JwtService } from '@nestjs/jwt';
import { Reflector }  from '@nestjs/core';
import { Request }    from 'express';

@Injectable()
export class JwtAuthGuard implements CanActivate {
  constructor(
    private readonly jwtService: JwtService,
    private readonly reflector:  Reflector,
  ) {}

  canActivate(context: ExecutionContext): boolean {
    // Allow routes marked @Public() to skip auth
    const isPublic = this.reflector.getAllAndOverride<boolean>('isPublic', [
      context.getHandler(),
      context.getClass(),
    ]);
    if (isPublic) return true;

    const request = context.switchToHttp().getRequest<Request>();
    const token   = this.extractToken(request);

    if (!token) throw new UnauthorizedException('Missing authentication token');

    try {
      const payload = this.jwtService.verify(token);
      // Attach to request — ProxyService reads this to set x-user-id, x-user-roles
      request['user'] = {
        id:       payload.sub,
        email:    payload.email,
        roles:    payload.roles ?? [],
        tenantId: payload.tenantId,
      };
      return true;
    } catch (err) {
      throw new UnauthorizedException(
        err.name === 'TokenExpiredError' ? 'Token has expired' : 'Invalid token',
      );
    }
  }

  private extractToken(req: Request): string | undefined {
    const authHeader = req.headers['authorization'];
    if (authHeader?.startsWith('Bearer ')) return authHeader.split(' ')[1];

    // Also accept token in cookie (for browser-originated requests)
    return req.cookies?.['access_token'];
  }
}
```

Downstream services then trust the forwarded headers from the gateway — they do not import `JwtService` or validate tokens:

```typescript
// loan-service/src/core/decorators/current-user.decorator.ts
// Downstream service reads user identity from the gateway-forwarded headers
export const CurrentUser = createParamDecorator(
  (data: unknown, ctx: ExecutionContext): AuthenticatedUser => {
    const request = ctx.switchToHttp().getRequest();
    return {
      id:    request.headers['x-user-id'],
      roles: JSON.parse(request.headers['x-user-roles'] ?? '[]'),
    };
  },
);
```

**Security note:** This trust model works only when downstream services are *not* publicly accessible — they must be inside a private VPC/network and accept connections only from the gateway's IP range. If a downstream service is publicly reachable, it must validate the token itself.

**Q9. How do you handle API Key authentication for NBFC partner integrations alongside JWT for mobile clients?**
A: Support multiple auth schemes via a composite guard that tries each scheme in order:

```typescript
// core/guards/composite-auth.guard.ts
@Injectable()
export class CompositeAuthGuard implements CanActivate {
  constructor(
    private readonly jwtGuard:    JwtAuthGuard,
    private readonly apiKeyGuard: ApiKeyGuard,
    private readonly reflector:   Reflector,
  ) {}

  async canActivate(context: ExecutionContext): Promise<boolean> {
    const isPublic = this.reflector.getAllAndOverride<boolean>('isPublic', [
      context.getHandler(), context.getClass(),
    ]);
    if (isPublic) return true;

    const request = context.switchToHttp().getRequest<Request>();

    // Mobile / web clients use JWT Bearer
    if (request.headers['authorization']?.startsWith('Bearer ')) {
      return this.jwtGuard.canActivate(context);
    }

    // NBFC partner integrations use API key
    if (request.headers['x-api-key']) {
      return this.apiKeyGuard.canActivate(context);
    }

    throw new UnauthorizedException('No authentication credentials provided');
  }
}

// core/guards/api-key.guard.ts
@Injectable()
export class ApiKeyGuard implements CanActivate {
  constructor(
    private readonly apiKeyService: ApiKeyService,
    private readonly redis:         Redis,
  ) {}

  async canActivate(context: ExecutionContext): Promise<boolean> {
    const request = context.switchToHttp().getRequest<Request>();
    const rawKey  = request.headers['x-api-key'] as string;

    if (!rawKey) throw new UnauthorizedException('Missing API key');

    // Cache API key lookups — avoid DB round trip on every request
    const cacheKey = `api_key:${this.hashKey(rawKey)}`;
    let tenant      = await this.redis.get(cacheKey);

    if (!tenant) {
      const record = await this.apiKeyService.validate(rawKey);
      if (!record || !record.active) {
        throw new UnauthorizedException('Invalid or revoked API key');
      }
      tenant = JSON.stringify(record);
      await this.redis.setex(cacheKey, 300, tenant); // cache 5 minutes
    }

    const tenantRecord = JSON.parse(tenant);

    // Attach identity — same shape as JWT-authenticated user
    request['user'] = {
      id:       tenantRecord.serviceAccountId,
      roles:    tenantRecord.permissions,
      tenantId: tenantRecord.tenantId,
      authType: 'API_KEY',
    };

    return true;
  }

  private hashKey(key: string): string {
    return createHash('sha256').update(key).digest('hex');
  }
}
```

## Section 4: Rate Limiting and Circuit Breaking

**Q10. How do you implement distributed rate limiting at the gateway level with per-client and per-route granularity?**
A:

```typescript
// core/rate-limit/gateway-rate-limit.service.ts
export interface RateLimitPolicy {
  windowSeconds: number;
  maxRequests:   number;
  keyStrategy:   'ip' | 'api-key' | 'user-id' | 'tenant';
}

// Per-route policies defined in a central config
const ROUTE_POLICIES: Record<string, RateLimitPolicy> = {
  'POST:/v1/loans/applications':         { windowSeconds: 60,  maxRequests: 5,    keyStrategy: 'user-id' },  // 5 applications per minute per user
  'POST:/v1/kyc/pan-verify':             { windowSeconds: 60,  maxRequests: 10,   keyStrategy: 'tenant'  },  // 10 PAN verifications per minute per tenant
  'POST:/v1/nach/mandates':              { windowSeconds: 3600, maxRequests: 20,   keyStrategy: 'tenant'  },  // 20 mandate registrations per hour per tenant
  'GET:/v1/loans/applications':          { windowSeconds: 60,  maxRequests: 120,  keyStrategy: 'user-id' },  // reads are lenient
  'DEFAULT':                             { windowSeconds: 60,  maxRequests: 300,  keyStrategy: 'ip'      },  // global fallback
};

@Injectable()
export class GatewayRateLimitService {
  constructor(@Inject('REDIS_CLIENT') private readonly redis: Redis) {}

  async checkLimit(req: Request): Promise<{ allowed: boolean; remaining: number; resetAt: number }> {
    const routeKey  = `${req.method}:${this.normaliseRoute(req.path)}`;
    const policy    = ROUTE_POLICIES[routeKey] ?? ROUTE_POLICIES['DEFAULT'];
    const clientKey = this.extractClientKey(req, policy.keyStrategy);
    const redisKey  = `gw_rl:${routeKey}:${clientKey}`;

    const pipeline = this.redis.pipeline();
    pipeline.incr(redisKey);
    pipeline.expire(redisKey, policy.windowSeconds);
    pipeline.ttl(redisKey);

    const [[, count], , [, ttl]] = (await pipeline.exec()) as any;

    const resetAt   = Math.floor(Date.now() / 1000) + (ttl as number);
    const remaining = Math.max(0, policy.maxRequests - (count as number));
    const allowed   = (count as number) <= policy.maxRequests;

    return { allowed, remaining, resetAt };
  }

  private extractClientKey(req: Request, strategy: RateLimitPolicy['keyStrategy']): string {
    switch (strategy) {
      case 'user-id':  return (req as any).user?.id   ?? req.ip;
      case 'api-key':  return this.hashKey(req.headers['x-api-key'] as string ?? '');
      case 'tenant':   return (req as any).user?.tenantId ?? req.ip;
      case 'ip':
      default:         return req.ip;
    }
  }

  private normaliseRoute(path: string): string {
    return path
      .replace(/[0-9a-f-]{36}/gi, ':id')  // UUIDs
      .replace(/\/\d+/g, '/:id')           // numeric IDs
      .replace(/\?.*$/, '');               // strip query string
  }

  private hashKey(key: string): string {
    return createHash('sha256').update(key).digest('hex').slice(0, 16);
  }
}
```

**Q11. How do you implement a Circuit Breaker at the gateway to protect clients from cascading failures in downstream services?**
A:

```typescript
// core/interceptors/circuit-breaker.interceptor.ts
import { Injectable, NestInterceptor, ExecutionContext, CallHandler, ServiceUnavailableException } from '@nestjs/common';
import { Observable, throwError } from 'rxjs';
import { catchError, timeout } from 'rxjs/operators';

enum CircuitState { CLOSED, OPEN, HALF_OPEN }

interface CircuitBreakerState {
  state:            CircuitState;
  failureCount:     number;
  lastFailureTime:  number;
  successCount:     number;  // consecutive successes in HALF_OPEN
}

@Injectable()
export class CircuitBreakerInterceptor implements NestInterceptor {
  private readonly circuits = new Map<string, CircuitBreakerState>();

  private readonly FAILURE_THRESHOLD   = 5;   // open after 5 consecutive failures
  private readonly RECOVERY_TIMEOUT_MS = 30_000; // try again after 30s
  private readonly HALF_OPEN_SUCCESSES = 2;   // 2 successes → close the circuit

  intercept(context: ExecutionContext, next: CallHandler): Observable<any> {
    const request     = context.switchToHttp().getRequest();
    const serviceName = this.extractServiceName(request.path);
    const circuit     = this.getOrCreateCircuit(serviceName);

    if (circuit.state === CircuitState.OPEN) {
      const elapsed = Date.now() - circuit.lastFailureTime;

      if (elapsed < this.RECOVERY_TIMEOUT_MS) {
        // Circuit is open and recovery timeout has not passed — reject immediately
        throw new ServiceUnavailableException(
          `Service ${serviceName} is temporarily unavailable. Circuit is open.`,
        );
      }

      // Recovery timeout passed — move to HALF_OPEN; allow one probe request
      circuit.state        = CircuitState.HALF_OPEN;
      circuit.successCount = 0;
    }

    return next.handle().pipe(
      catchError((err) => {
        this.onFailure(serviceName, circuit);
        return throwError(() => err);
      }),
      // tap for success path
      ...[{
        // RxJS tap equivalent inline
      }],
    );
  }

  private onFailure(serviceName: string, circuit: CircuitBreakerState): void {
    circuit.failureCount++;
    circuit.lastFailureTime = Date.now();

    if (
      circuit.state === CircuitState.HALF_OPEN ||
      circuit.failureCount >= this.FAILURE_THRESHOLD
    ) {
      circuit.state = CircuitState.OPEN;
      console.error(`Circuit OPENED for service: ${serviceName}`);
    }
  }

  private onSuccess(serviceName: string, circuit: CircuitBreakerState): void {
    if (circuit.state === CircuitState.HALF_OPEN) {
      circuit.successCount++;
      if (circuit.successCount >= this.HALF_OPEN_SUCCESSES) {
        circuit.state        = CircuitState.CLOSED;
        circuit.failureCount = 0;
        console.log(`Circuit CLOSED for service: ${serviceName}`);
      }
    } else {
      circuit.failureCount = 0; // reset on success in CLOSED state
    }
  }

  private getOrCreateCircuit(serviceName: string): CircuitBreakerState {
    if (!this.circuits.has(serviceName)) {
      this.circuits.set(serviceName, {
        state: CircuitState.CLOSED, failureCount: 0,
        lastFailureTime: 0,         successCount: 0,
      });
    }
    return this.circuits.get(serviceName)!;
  }

  private extractServiceName(path: string): string {
    // /v1/loans/applications → loan
    const match = path.match(/^\/v\d+\/([a-z-]+)/);
    return match?.[1] ?? 'unknown';
  }
}
```

For production, use a battle-tested library like `cockatiel` or `opossum` rather than a hand-rolled circuit breaker:

```typescript
import * as CircuitBreaker from 'opossum';

@Injectable()
export class ProxyService {
  private readonly breakers = new Map<string, CircuitBreaker>();

  private getBreakerForService(serviceName: string): CircuitBreaker {
    if (!this.breakers.has(serviceName)) {
      const breaker = new CircuitBreaker(this.callDownstream.bind(this), {
        timeout:              10_000,  // 10s timeout counts as a failure
        errorThresholdPercentage: 50,  // open if 50% of requests fail
        resetTimeout:         30_000,  // try again after 30s
        volumeThreshold:      5,       // minimum 5 requests before tripping
      });

      breaker.on('open',     () => this.logger.error(`Circuit OPEN: ${serviceName}`));
      breaker.on('halfOpen', () => this.logger.warn(`Circuit HALF-OPEN: ${serviceName}`));
      breaker.on('close',    () => this.logger.log(`Circuit CLOSED: ${serviceName}`));
      breaker.fallback(() => ({ error: 'Service temporarily unavailable', cached: true }));

      this.breakers.set(serviceName, breaker);
    }
    return this.breakers.get(serviceName)!;
  }
}
```

## Section 5: BFF — Backend for Frontend

**Q12. What is the Backend for Frontend pattern and when do you apply it at the gateway?**
A: A Backend for Frontend (BFF) is a gateway-layer aggregation layer that composes multiple service responses into a single, client-optimised payload. Instead of the mobile app making four requests and joining the data on the device, the BFF makes four requests in parallel and returns one composed response.

BFF is appropriate when:
- **Clients are chatty** — a single screen needs data from 3+ services
- **Client diversity** — mobile app needs a thin payload; ops portal needs a rich payload from the same services
- **Protocol mismatch** — mobile client speaks REST; internal services speak gRPC
- **Response shaping** — field names, currency formats, and date formats differ between the service contract and the client contract

```typescript
// bff/mobile/loan-dashboard.controller.ts
// Mobile app loan dashboard — needs loan, EMI schedule, and notification summary
// in one request instead of three

interface LoanDashboardResponse {
  loan:              LoanSummary;
  nextEmi:           EmiSummary | null;
  unreadNotifications: number;
  mandateStatus:     'ACTIVE' | 'INACTIVE' | 'PENDING';
}

@Controller('v1/bff/mobile/loan-dashboard')
@UseGuards(JwtAuthGuard)
export class LoanDashboardController {
  constructor(private readonly dashboardService: LoanDashboardService) {}

  @Get(':loanId')
  async getDashboard(
    @Param('loanId') loanId: string,
    @Req() req: Request,
  ): Promise<LoanDashboardResponse> {
    return this.dashboardService.composeDashboard(loanId, req);
  }
}

// bff/mobile/loan-dashboard.service.ts
@Injectable()
export class LoanDashboardService {
  constructor(private readonly proxy: ProxyService) {}

  async composeDashboard(loanId: string, req: Request): Promise<LoanDashboardResponse> {
    // Fan out to three services in parallel — total latency = slowest service
    const [loan, emiSchedule, notifications, mandate] = await Promise.allSettled([
      this.proxy.forward(req, { targetService: 'loan',         path: `/loan-applications/${loanId}` }),
      this.proxy.forward(req, { targetService: 'collection',   path: `/emi-schedule/${loanId}` }),
      this.proxy.forward(req, { targetService: 'notification', path: `/notifications/unread-count` }),
      this.proxy.forward(req, { targetService: 'nach',         path: `/mandates/by-loan/${loanId}` }),
    ]);

    // Handle partial failures gracefully — return what we have
    if (loan.status === 'rejected') {
      throw new NotFoundException(`Loan ${loanId} not found`);
    }

    const loanData         = (loan as PromiseFulfilledResult<any>).value;
    const emiData          = emiSchedule.status === 'fulfilled' ? emiSchedule.value : null;
    const notifCount       = notifications.status === 'fulfilled' ? notifications.value?.count : 0;
    const mandateData      = mandate.status === 'fulfilled' ? mandate.value : null;

    return {
      loan: {
        id:              loanData.id,
        status:          loanData.status,
        approvedAmount:  loanData.approvedAmount,
        disbursedAmount: loanData.disbursedAmount,
        outstandingAmount: loanData.outstandingAmount,
      },
      nextEmi: emiData ? this.findNextEmi(emiData.schedule) : null,
      unreadNotifications: notifCount ?? 0,
      mandateStatus: mandateData?.status ?? 'INACTIVE',
    };
  }

  private findNextEmi(schedule: any[]): EmiSummary | null {
    const today = new Date();
    const next  = schedule
      .filter(e => e.status === 'PENDING' && new Date(e.dueDate) >= today)
      .sort((a, b) => new Date(a.dueDate).getTime() - new Date(b.dueDate).getTime())[0];

    if (!next) return null;
    return {
      amount:    next.amount,
      dueDate:   next.dueDate,
      daysUntil: Math.ceil((new Date(next.dueDate).getTime() - today.getTime()) / 86_400_000),
    };
  }
}
```

**Q13. How do you handle partial failures in BFF aggregation without failing the entire response?**
A: Use `Promise.allSettled` (not `Promise.all`) so one failing service does not abort the others. Define which sub-responses are mandatory vs optional:

```typescript
async composeDashboard(loanId: string, req: Request): Promise<LoanDashboardResponse> {
  const [loan, emi, notifications, mandate] = await Promise.allSettled([
    this.fetchLoan(loanId, req),           // MANDATORY — dashboard is meaningless without it
    this.fetchEmiSchedule(loanId, req),    // OPTIONAL — show placeholder if unavailable
    this.fetchNotificationCount(req),      // OPTIONAL — show 0 if unavailable
    this.fetchMandateStatus(loanId, req),  // OPTIONAL — show UNKNOWN if unavailable
  ]);

  // Mandatory check — fail fast if loan data is unavailable
  if (loan.status === 'rejected') {
    const err = loan.reason;
    throw err instanceof HttpException ? err : new ServiceUnavailableException('Loan service unavailable');
  }

  // Optional — log degradation but return partial response
  if (emi.status === 'rejected') {
    this.logger.warn('EMI schedule unavailable for dashboard', {
      loanId, error: emi.reason?.message,
    });
  }

  return {
    loan:               (loan as PromiseFulfilledResult<any>).value,
    nextEmi:            emi.status  === 'fulfilled' ? this.findNextEmi(emi.value) : null,
    unreadNotifications: notifications.status === 'fulfilled' ? notifications.value.count : 0,
    mandateStatus:      mandate.status === 'fulfilled' ? mandate.value.status : 'UNKNOWN',
    _degraded:          [emi, notifications, mandate].some(r => r.status === 'rejected'),
  };
}
```

The `_degraded` flag in the response tells the client that some data is stale or missing — the mobile app can show a partial dashboard with a "refresh" nudge rather than a blank error screen.

## Section 6: Observability at the Gateway

**Q14. How do you implement centralised request tracing and metrics at the gateway?**
A:

```typescript
// core/interceptors/gateway-observability.interceptor.ts
import { Injectable, NestInterceptor, ExecutionContext, CallHandler } from '@nestjs/common';
import { Observable } from 'rxjs';
import { tap, catchError } from 'rxjs/operators';
import { MetricsService } from '../metrics/metrics.service';

@Injectable()
export class GatewayObservabilityInterceptor implements NestInterceptor {
  constructor(
    private readonly metrics: MetricsService,
    private readonly logger:  AppLogger,
  ) {}

  intercept(context: ExecutionContext, next: CallHandler): Observable<any> {
    const req         = context.switchToHttp().getRequest();
    const res         = context.switchToHttp().getResponse();
    const start       = Date.now();
    const route       = `${req.method} ${this.normaliseRoute(req.path)}`;
    const correlationId = req.headers['x-correlation-id'];

    return next.handle().pipe(
      tap(() => {
        const latencyMs = Date.now() - start;

        // Prometheus-style metrics
        this.metrics.incrementCounter('gateway_requests_total', {
          route,
          method:     req.method,
          status:     String(res.statusCode),
          service:    this.extractService(req.path),
          tenant:     req.headers['x-tenant-id'] as string ?? 'unknown',
        });

        this.metrics.recordHistogram('gateway_request_duration_ms', latencyMs, {
          route,
          service: this.extractService(req.path),
        });

        // Structured access log — goes to CloudWatch / Elasticsearch
        this.logger.log('GatewayAccess', `${route} ${res.statusCode}`, {
          correlationId,
          latencyMs,
          userId:    req['user']?.id,
          tenantId:  req.headers['x-tenant-id'],
          ip:        req.ip,
          userAgent: req.headers['user-agent'],
        });
      }),

      catchError((err) => {
        const latencyMs = Date.now() - start;

        this.metrics.incrementCounter('gateway_errors_total', {
          route,
          errorCode: String(err.status ?? 500),
          service:   this.extractService(req.path),
        });

        this.logger.error('GatewayError', `${route} failed`, {
          correlationId,
          latencyMs,
          errorCode:    err.status ?? 500,
          errorMessage: err.message,
        });

        throw err;
      }),
    );
  }

  private normaliseRoute(path: string): string {
    return path
      .replace(/[0-9a-f-]{36}/gi, ':id')
      .replace(/\/\d+/g, '/:id');
  }

  private extractService(path: string): string {
    const match = path.match(/^\/v\d+\/([a-z-]+)/);
    return match?.[1] ?? 'unknown';
  }
}
```

## Section 7: Common Anti-Patterns and Pitfalls

**Q15. What are the most common API Gateway mistakes in a fintech microservices platform?**
A:

**Anti-pattern 1 — The Fat Gateway: business logic leaks into the gateway:**
```typescript
// ❌ Gateway deciding eligibility — business logic in the wrong layer
@Controller('v1/loans/applications')
export class LoanGatewayController {
  async apply(@Body() dto: CreateLoanDto, @Req() req: Request): Promise<unknown> {
    // Business rule check in the gateway — wrong
    if (dto.requestedAmount > 10_000_000_00) {
      throw new BadRequestException('Amount exceeds maximum limit');
    }
    const bureauScore = await this.bureauService.fetch(dto.pan); // gateway calling bureau directly
    if (bureauScore < 650) {
      throw new UnprocessableEntityException('Low bureau score');
    }
    return this.proxy.forward(req, { targetService: 'loan', path: '/loan-applications' });
  }
}

// ✅ Gateway routes and enforces cross-cutting concerns; business logic lives in Loan Service
async apply(@Body() dto: CreateLoanDto, @Req() req: Request): Promise<unknown> {
  return this.proxy.forward(req, {
    targetService: 'loan',
    path:          '/loan-applications',
  });
  // Loan Service validates amount limits, pulls bureau score, enforces eligibility
}
```

**Anti-pattern 2 — Bypassing the gateway for internal service-to-service calls:**
```typescript
// ❌ KYC Service calling Loan Service directly — bypasses auth, rate limiting, tracing
// kyc-service/src/services/kyc.service.ts
const loanData = await axios.get(`http://loan-service:3001/loan-applications/${loanId}`);

// ✅ Service-to-service calls use the service mesh (Istio mTLS) or a typed HTTP client
// with proper service account credentials — not the public gateway
// Internal calls do not need the external-facing gateway
```

**Anti-pattern 3 — Gateway as a single point of failure without redundancy:**
```typescript
// ❌ Single gateway instance with no health check or auto-scaling
// main.ts — listening on port 3000 with no readiness/liveness probe

// ✅ Health check endpoint for Kubernetes probes
@Controller('health')
@Public() // skip auth
export class HealthController {
  @Get('live')
  liveness(): { status: string } {
    return { status: 'ok' };  // process is alive
  }

  @Get('ready')
  async readiness(): Promise<{ status: string; services: Record<string, string> }> {
    // Check that downstream services are reachable before accepting traffic
    const checks = await Promise.allSettled([
      this.proxy.ping('loan'),
      this.proxy.ping('kyc'),
      this.proxy.ping('nach'),
    ]);
    const services = {
      loan: checks[0].status === 'fulfilled' ? 'up' : 'down',
      kyc:  checks[1].status === 'fulfilled' ? 'up' : 'down',
      nach: checks[2].status === 'fulfilled' ? 'up' : 'down',
    };
    const allUp = Object.values(services).every(s => s === 'up');
    if (!allUp) throw new ServiceUnavailableException({ status: 'degraded', services });
    return { status: 'ok', services };
  }
}
```

**Anti-pattern 4 — Forwarding the raw JWT to downstream services:**
```typescript
// ❌ Forwarding the raw Authorization header downstream
// Now every downstream service must validate JWTs — defeats the purpose of centralised auth
private buildForwardHeaders(req: Request): Record<string, string> {
  return {
    'authorization': req.headers['authorization'] as string, // ← wrong
  };
}

// ✅ Gateway validates the JWT; downstream services receive trusted identity headers
private buildForwardHeaders(req: Request): Record<string, string> {
  return {
    'x-user-id':    req['user'].id,
    'x-user-roles': JSON.stringify(req['user'].roles),
    'x-tenant-id':  req['user'].tenantId,
    // Raw JWT is NOT forwarded downstream
  };
}
```

**Anti-pattern 5 — No timeout on downstream calls — gateway threads pile up:**
```typescript
// ❌ No timeout — if Loan Service hangs, gateway worker threads exhaust
return this.proxy.forward(req, { targetService: 'loan', path: '/loan-applications' });

// ✅ Every downstream call has a timeout; long operations use async patterns
return this.proxy.forward(req, {
  targetService: 'loan',
  path:          '/loan-applications',
  timeoutMs:     8_000,   // 8s max; client gets 504 if exceeded
});
```

**Q17. "Your Loan Service starts returning 503s under load. How does the API Gateway protect clients and other services from this failure?"**
A: The gateway applies three layers of protection:

```
Client Request
      │
      ▼
1. Rate Limiter           ← Reduces load on the gateway and downstream
      │
      ▼
2. Circuit Breaker        ← After 5 failures, opens circuit; returns 503 immediately
      │                      without touching Loan Service; lets it recover
      ▼
3. Fallback / Cache       ← Return last cached response if available (read endpoints)
                             Return 503 with Retry-After header for write endpoints
```

```typescript
// ProxyService — integrates circuit breaker + cache fallback
async forward<T>(req: Request, options: ProxyOptions): Promise<T> {
  const isReadRequest = req.method === 'GET';
  const cacheKey      = isReadRequest ? this.buildCacheKey(req) : null;

  // For GET requests, try cache first (stale-while-revalidate)
  if (cacheKey) {
    const cached = await this.redis.get(cacheKey);
    if (cached) {
      const parsed = JSON.parse(cached);
      // Return cached response; revalidate in background
      this.revalidateInBackground(req, options, cacheKey).catch(() => {});
      return { ...parsed, _stale: true };
    }
  }

  // Circuit breaker wraps the actual HTTP call
  try {
    const result = await this.getBreakerForService(options.targetService)
      .fire(req, options);

    // Cache successful GET responses
    if (cacheKey) {
      await this.redis.setex(cacheKey, 60, JSON.stringify(result)); // 60s cache
    }

    return result;
  } catch (err) {
    // Circuit is open — check for stale cache before failing
    if (cacheKey) {
      const staleCache = await this.redis.get(`stale:${cacheKey}`);
      if (staleCache) {
        this.logger.warn(`Serving stale cache for ${options.targetService} — circuit open`);
        return { ...JSON.parse(staleCache), _stale: true, _cachedAt: new Date().toISOString() };
      }
    }

    // No cache available — return 503 with retry guidance
    throw new ServiceUnavailableException({
      message:    `${options.targetService} is temporarily unavailable`,
      retryAfter: 30,
      code:       'CIRCUIT_OPEN',
    });
  }
}
```

## Quick Reference: API Gateway Pattern Cheat Sheet

```
API GATEWAY PATTERN — QUICK REFERENCE
───────────────────────────────────────

WHAT THE GATEWAY OWNS
  ✅ Request routing (URL → downstream service)
  ✅ SSL termination
  ✅ Authentication (JWT validation, API key lookup)
  ✅ Authorisation (role enforcement at route level)
  ✅ Rate limiting (per IP / user / tenant / route)
  ✅ Circuit breaking (stop routing to failing services)
  ✅ Correlation ID propagation
  ✅ Request/response logging (access log)
  ✅ BFF aggregation (fan-out + compose)
  ✅ Protocol translation (REST ↔ gRPC, REST ↔ WebSocket)

WHAT THE GATEWAY MUST NOT OWN
  ❌ Business logic (eligibility rules, loan limits)
  ❌ Database queries (no ORM, no direct DB access)
  ❌ Domain exceptions (gateway speaks HTTP status codes only)
  ❌ Service-to-service orchestration (belongs in a saga/orchestrator)

FORWARD HEADERS TO DOWNSTREAM
  x-correlation-id  → trace the request across services
  x-tenant-id       → multi-tenancy context
  x-user-id         → verified user identity (NOT the raw JWT)
  x-user-roles      → JSON array of verified roles
  Never forward: raw Authorization Bearer token

CIRCUIT BREAKER STATES
  CLOSED    → normal; requests flow through
  OPEN      → failing; reject immediately; return 503
  HALF-OPEN → recovery probe; 1 request allowed through
  Trip threshold: 5 consecutive failures or 50% error rate
  Recovery timeout: 30s

BFF AGGREGATION
  Use Promise.allSettled — not Promise.all
  Define mandatory vs optional sub-responses
  Fail fast on mandatory failures; degrade gracefully on optional
  Return _degraded: true flag when partial data is served

RATE LIMITING STRATEGIES
  Per-IP        → external / unauthenticated traffic
  Per-user-id   → authenticated mobile / web clients
  Per-tenant    → NBFC partner integrations (B2B)
  Per-route     → stricter on write endpoints (POST /loans)
  Storage       → Redis (distributed; survives gateway restart)

DEPLOYMENT TOPOLOGY
  Internet → NLB (Layer 4) → API Gateway (NestJS / Kong)
          → VPC-internal services (not publicly reachable)
  Gateway is the ONLY entry point for external traffic

HEALTH CHECKS
  GET /health/live  → liveness (is the process running?)
  GET /health/ready → readiness (are downstream services reachable?)

CLIENT TYPE SEPARATION
  Mobile app    → /v1/bff/mobile/*   JWT; strict rate limit; thin BFF payload
  Ops portal    → /v1/bff/ops/*      JWT; relaxed rate limit; rich BFF payload
  B2B partners  → /v1/api/*          API key; per-tenant rate limit; direct proxy

FINTECH CONSIDERATIONS
  → API key cache in Redis (avoid DB round trip per request)
  → Crypto-hash API keys before storing in cache (sha256)
  → PII never logged at gateway (x-user-id only; no PAN, phone, Aadhaar)
  → Separate rate limits for bureau, NACH, disbursement endpoints
  → Retry-After header on 429 and 503 for RBI-compliant partner integrations
```
