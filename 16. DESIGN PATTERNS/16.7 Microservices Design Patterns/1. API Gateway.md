# Microservices Design Patterns: API Gateway — Interview Q&A (5 YOE Level)

---

## Section 1: Fundamentals

**Q1. What is the API Gateway pattern?**
A: An API Gateway is a server that acts as the single entry point for all client requests into a microservices system. Rather than clients communicating directly with individual downstream services — each with its own host, port, protocol, and authentication scheme — every request enters through the gateway, which handles cross-cutting infrastructure concerns (authentication, TLS termination, rate limiting, request routing, protocol translation) and forwards the request to the appropriate upstream service or set of services. The pattern was popularised alongside the microservices movement as the answer to the "how do clients talk to a system of dozens of services?" problem. Every major cloud provider offers a managed API gateway (AWS API Gateway, GCP Apigee, Azure API Management); open-source implementations include Kong, Traefik, and Envoy; and teams also build custom gateways in NestJS or Express for more control.

**Q2. What problem does the API Gateway pattern solve, and what breaks without it?**
A: It solves the *client-to-microservices coupling* problem — when clients communicate directly with individual services, a cascade of structural problems emerges:

- **Client complexity explosion** — the mobile app must know the host, port, and API contract of 20 different services. When any service moves, scales, or changes its contract, the client must update.
- **Cross-cutting concern duplication** — every service must independently implement authentication, TLS termination, rate limiting, CORS headers, and request logging. Each implementation is slightly different; bugs are multiplied.
- **Protocol mismatch** — a client speaks HTTP/1.1 REST over the public internet; an internal service speaks gRPC over HTTP/2 or communicates via message queues. Without a gateway, the client is forced to match the internal protocol.
- **No single place to enforce security** — adding a new auth requirement means touching every service. Adding a new rate limit means touching every service. Adding request logging means touching every service.
- **Service discovery exposure** — direct client-to-service communication requires exposing every service's address publicly. The internal network topology becomes public knowledge.
- **No unified observability** — distributed across 20 services, request-level metrics and tracing require each service to independently emit them correctly.

Without an API gateway, the microservices architecture's internal complexity is fully exposed to every client. With a gateway, clients see one stable interface regardless of how many services exist behind it.

**Q3. What are the core responsibilities of an API Gateway?**
A: Six well-defined responsibilities:

1. **Request routing** — maps an incoming request (method + path) to one or more upstream services. `GET /loans/:id` → Loan Service; `POST /payments` → Payment Service. Routing rules may be static (config-driven) or dynamic (service registry-driven).

2. **Authentication and authorisation** — validates the caller's identity (JWT verification, API key validation, OAuth 2.0 token introspection) before the request reaches any upstream service. Authorisation decisions (can this caller access this resource?) may live here or be delegated to a dedicated policy engine (OPA, Casbin).

3. **TLS termination** — accepts HTTPS from external clients and forwards HTTP internally. The internal network is trusted; end-to-end encryption between services is a separate mTLS concern.

4. **Rate limiting and throttling** — caps requests per client, per IP, per API key, or per endpoint to protect downstream services from overload and abuse.

5. **Request and response transformation** — rewrites headers, query parameters, or request bodies before forwarding (e.g., injecting `X-User-Id` from the decoded JWT); rewrites or filters response payloads before returning to the client.

6. **Observability** — emits access logs, request metrics (latency, error rates), and distributed trace spans for every request passing through.

What the gateway is *not* responsible for:
- Core business logic (that belongs in downstream services).
- Client-specific data aggregation and transformation (that belongs in a BFF).
- Persistent data storage.
- Domain-level authorisation rules (can this customer see this specific loan? — that belongs in the downstream service).

**Q4. How does the API Gateway differ from a Load Balancer, a Reverse Proxy, and a BFF?**
A:

| Dimension              | Load Balancer                                        | Reverse Proxy                                          | API Gateway                                                     | BFF                                                                   |
|------------------------|------------------------------------------------------|--------------------------------------------------------|-----------------------------------------------------------------|-----------------------------------------------------------------------|
| Primary purpose        | Distribute traffic across identical instances        | Forward requests to one backend, hide it from client   | Cross-cutting infrastructure for a microservices system         | Client-specific aggregation and transformation                        |
| Request awareness      | Layer 4 (TCP) or Layer 7 (HTTP) — minimal inspection | Layer 7 — full HTTP awareness                          | Layer 7 — full application-layer awareness including auth       | Full application awareness — reads/transforms bodies                  |
| Auth                   | None                                                 | None or basic                                          | Central authentication for all services                         | Verifies tokens passed by gateway; enforces ownership                 |
| Business logic         | None                                                 | None                                                   | None — pure infrastructure                                      | Lightweight presentation-layer logic for one client                   |
| Routing targets        | Multiple identical instances of one service          | One backend (or a small set)                           | Many different services based on path/method/header             | Many downstream services — aggregated for one client type             |
| Owned by               | Infrastructure/platform team                         | Infrastructure/platform team                           | Infrastructure/platform team                                    | Frontend team that owns the client                                    |
| Examples               | AWS ELB, HAProxy, Nginx (upstream block)             | Nginx, Caddy, Apache                                   | Kong, AWS API Gateway, Traefik, Envoy                           | A NestJS service owned by the mobile team                             |

In a typical fintech architecture: the load balancer distributes incoming internet traffic across multiple gateway instances; each gateway instance reverse-proxies to the appropriate BFF or downstream service; the BFF aggregates data from multiple downstream services for its specific client.

**Q5. What are the two primary architectural positions for an API Gateway, and what are the trade-offs of each?**
A:

**Position 1 — Edge Gateway (client-facing, external):**
- Sits at the edge of the network, directly facing the internet.
- Handles TLS termination, DDoS protection, IP allowlisting, and public-facing rate limiting.
- Routes to BFFs or directly to internal services.
- Managed services (AWS API Gateway, Cloudflare) or self-hosted (Kong, Traefik).
- Trade-off: single point of failure if not highly available; every public request passes through it.

**Position 2 — Internal Gateway / Service Mesh Sidecar:**
- Sits inside the network, between internal services.
- Handles service-to-service auth (mTLS), internal rate limiting, circuit breaking, and observability.
- Implemented via service mesh (Istio, Linkerd) as a sidecar proxy (Envoy) alongside each service.
- Trade-off: adds latency and operational complexity; requires investment in mesh infrastructure.

Most production fintech systems use both: an edge gateway for external traffic and a service mesh for internal service-to-service communication. At 5 YOE, understanding the edge gateway in depth is more commonly tested; knowing that the service mesh exists and what problem it solves is enough for the internal layer.

```typescript
// src/routing/proxy.service.ts
import { Injectable, Logger, HttpException, GatewayTimeoutException } from "@nestjs/common";
import { HttpService }    from "@nestjs/axios";
import { ConfigService }  from "@nestjs/config";
import { firstValueFrom } from "rxjs";
import { timeout }        from "rxjs/operators";
import axios, { AxiosError } from "axios";

@Injectable()
export class ProxyService {
  private readonly logger = new Logger(ProxyService.name);

  constructor(private readonly http: HttpService) {}

  async forward(params: {
    method:        string;
    upstreamUrl:   string;
    headers:       Record<string, string>;
    body?:         unknown;
    query?:        Record<string, string>;
    timeoutMs?:    number;
    traceId:       string;
  }): Promise<{ status: number; headers: Record<string, string>; data: unknown }> {
    const effectiveTimeout = params.timeoutMs ?? 5000;

    const start = Date.now();
    try {
      const response = await firstValueFrom(
        this.http.request({
          method:  params.method,
          url:     params.upstreamUrl,
          headers: {
            ...params.headers,
            "x-trace-id":    params.traceId,
            "x-gateway-hop": "1",               // mark as gateway-forwarded
          },
          data:    params.body,
          params:  params.query,
        }).pipe(
          timeout(effectiveTimeout),
        ),
      );

      this.logger.log({
        level:        "info",
        type:         "upstream_response",
        upstream:     params.upstreamUrl,
        status:       response.status,
        durationMs:   Date.now() - start,
        traceId:      params.traceId,
      });

      return {
        status:  response.status,
        headers: this.filterResponseHeaders(response.headers),
        data:    response.data,
      };
    } catch (err: any) {
      this.logger.error({
        level:      "error",
        type:       "upstream_error",
        upstream:   params.upstreamUrl,
        error:      err.message,
        durationMs: Date.now() - start,
        traceId:    params.traceId,
      });

      if (axios.isAxiosError(err)) {
        const axiosErr = err as AxiosError;
        if (axiosErr.code === "ECONNABORTED" || axiosErr.message.includes("timeout")) {
          throw new GatewayTimeoutException(`Upstream timeout: ${params.upstreamUrl}`);
        }
        if (axiosErr.response) {
          // Forward upstream error status — don't swallow 4xx errors
          throw new HttpException(axiosErr.response.data, axiosErr.response.status);
        }
        throw new HttpException("Upstream service unavailable", 502);
      }
      throw err;
    }
  }

  // Strip hop-by-hop headers before returning to client
  private filterResponseHeaders(headers: Record<string, unknown>): Record<string, string> {
    const blocked = new Set([
      "connection", "keep-alive", "transfer-encoding", "upgrade",
      "proxy-authenticate", "proxy-authorization", "te", "trailer",
    ]);
    return Object.fromEntries(
      Object.entries(headers)
        .filter(([key]) => !blocked.has(key.toLowerCase()))
        .map(([k, v]) => [k, String(v)])
    );
  }
}

// src/gateway/gateway.controller.ts
@Controller()
export class GatewayController {
  constructor(
    private readonly proxy:       ProxyService,
    private readonly routeReg:    RouteRegistryService,
    private readonly reqTransform: RequestTransformer,
  ) {}

  @All("*")
  @UseGuards(ConditionalAuthGuard)   // applies auth only when route requires it
  @UseInterceptors(RateLimitInterceptor)
  async handle(
    @Req()  req: AuthenticatedRequest,
    @Res()  res: Response,
  ): Promise<void> {
    const route = this.routeReg.match(req.method, req.path);
    if (!route) {
      res.status(404).json({ errorCode: "NOT_FOUND", message: "Route not found" });
      return;
    }

    // Request transformation — inject user context from JWT
    const transformedHeaders = this.reqTransform.transform(req, route);

    const upstreamUrl = this.resolveUrl(route.upstreamUrl, req.params, req.query as any);

    const upstream = await this.proxy.forward({
      method:      req.method,
      upstreamUrl,
      headers:     transformedHeaders,
      body:        req.body,
      query:       req.query as Record<string, string>,
      timeoutMs:   route.timeoutMs,
      traceId:     req.headers["x-trace-id"] as string ?? crypto.randomUUID(),
    });

    // Copy upstream status and response to client
    res.status(upstream.status);
    Object.entries(upstream.headers).forEach(([k, v]) => res.setHeader(k, v));
    res.json(upstream.data);
  }

  private resolveUrl(template: string, params: Record<string, string>, query: Record<string, string>): string {
    // Replace :param placeholders with actual values
    return template.replace(/:([a-zA-Z]+)/g, (_, key) => params[key] ?? `:${key}`);
  }
}
```

```typescript
// src/auth/jwt.strategy.ts

import { Injectable, UnauthorizedException } from "@nestjs/common";
import { PassportStrategy }                  from "@nestjs/passport";
import { ExtractJwt, Strategy }              from "passport-jwt";
import { ConfigService }                     from "@nestjs/config";
import { JwksClient }                        from "jwks-rsa";

export interface JwtPayload {
  sub:        string;       // customerId
  name:       string;
  role:       "customer" | "admin" | "partner";
  tenantId:   string;
  iat:        number;
  exp:        number;
  jti:        string;       // JWT ID — for revocation checking
}

@Injectable()
export class JwtStrategy extends PassportStrategy(Strategy) {
  private readonly jwksClient: JwksClient;

  constructor(private readonly config: ConfigService) {
    super({
      jwtFromRequest:    ExtractJwt.fromAuthHeaderAsBearerToken(),
      ignoreExpiration:  false,
      // Dynamic key retrieval from JWKS endpoint — supports key rotation
      secretOrKeyProvider: async (request, rawJwtToken, done) => {
        const decoded = JSON.parse(Buffer.from(rawJwtToken.split(".")[0], "base64").toString());
        const key = await jwksClient.getSigningKey(decoded.kid);
        done(null, key.getPublicKey());
      },
    });

    this.jwksClient = new JwksClient({
      jwksUri:    config.get<string>("AUTH_JWKS_URI")!,
      cache:      true,
      cacheMaxEntries: 10,
      cacheMaxAge: 600_000,   // 10 minutes
    });
  }

  async validate(payload: JwtPayload): Promise<JwtPayload> {
    // Additional validation beyond signature and expiry
    if (!payload.sub)      throw new UnauthorizedException("Missing subject claim");
    if (!payload.tenantId) throw new UnauthorizedException("Missing tenantId claim");

    // Optional: check token revocation (Redis blacklist for logout)
    const isRevoked = await this.tokenRevocationCache.isRevoked(payload.jti);
    if (isRevoked) throw new UnauthorizedException("Token has been revoked");

    return payload;
  }
}

// ─── Request transformer — injects user context as headers for downstream ──────

// src/transformers/request.transformer.ts

@Injectable()
export class RequestTransformer {
  transform(req: AuthenticatedRequest, route: RouteDefinition): Record<string, string> {
    const headers: Record<string, string> = {
      // Forward safe original headers
      "content-type":    req.headers["content-type"] ?? "application/json",
      "accept":          req.headers["accept"]         ?? "application/json",
      "accept-language": req.headers["accept-language"] ?? "en-IN",
      "x-trace-id":      req.traceId,
      "x-forwarded-for": req.ip,
      "x-request-id":    crypto.randomUUID(),
    };

    // Inject user claims from decoded JWT — downstream services trust these headers
    // because they come from the gateway (internal network — not from the client directly)
    if (req.user) {
      headers["x-user-id"]     = req.user.sub;
      headers["x-user-role"]   = req.user.role;
      headers["x-tenant-id"]   = req.user.tenantId;
      headers["x-user-name"]   = encodeURIComponent(req.user.name);
    }

    // Route-specific additional headers
    if (route.addHeaders) {
      Object.assign(headers, route.addHeaders);
    }

    // NEVER forward these — they should never reach upstream from a client
    const blocked = ["authorization", "cookie", "x-forwarded-host"];
    blocked.forEach(h => delete headers[h]);

    // If downstream needs auth, use a service-to-service token, not the user's JWT
    // This prevents clients from crafting arbitrary user-context headers
    headers["authorization"] = `Bearer ${this.serviceToken}`;

    return headers;
  }

  private get serviceToken(): string {
    // Service account JWT — pre-signed with the gateway's service identity
    // Downstream services verify this to confirm the request came through the gateway
    return process.env.GATEWAY_SERVICE_TOKEN!;
  }
}
```

A:

```typescript
// src/rate-limiting/redis-rate-limiter.ts

import { Injectable }      from "@nestjs/common";
import { RedisClient }     from "redis";

export interface RateLimitProfile {
  requests:     number;   // max requests
  windowSeconds: number;  // per this window
  burstAllowed:  number;  // allowed burst above the base rate
}

const RATE_LIMIT_PROFILES: Record<string, RateLimitProfile> = {
  public:   { requests: 100,  windowSeconds: 60,  burstAllowed: 20  },
  standard: { requests: 300,  windowSeconds: 60,  burstAllowed: 50  },
  write:    { requests: 50,   windowSeconds: 60,  burstAllowed: 10  },
  auth:     { requests: 10,   windowSeconds: 60,  burstAllowed: 5   },
  kyc:      { requests: 5,    windowSeconds: 300, burstAllowed: 2   },
  partner:  { requests: 1000, windowSeconds: 60,  burstAllowed: 200 },
};

export interface RateLimitResult {
  allowed:        boolean;
  remaining:      number;
  resetAt:        Date;
  retryAfterMs?:  number;
}

@Injectable()
export class RedisRateLimiter {
  constructor(private readonly redis: RedisClient) {}

  // Sliding window counter using a Lua script — atomic, no race conditions
  private readonly SLIDING_WINDOW_SCRIPT = `
    local key        = KEYS[1]
    local now        = tonumber(ARGV[1])
    local window     = tonumber(ARGV[2])
    local limit      = tonumber(ARGV[3])
    local burst      = tonumber(ARGV[4])
    local windowStart = now - window * 1000

    -- Remove expired entries
    redis.call("ZREMRANGEBYSCORE", key, 0, windowStart)

    -- Count current window
    local count = redis.call("ZCARD", key)

    -- Check limit + burst
    if count >= (limit + burst) then
      local oldest = redis.call("ZRANGE", key, 0, 0, "WITHSCORES")
      local resetAt = tonumber(oldest[2]) + window * 1000
      return { 0, limit - count, resetAt }
    end

    -- Allow request — add current timestamp
    redis.call("ZADD", key, now, now .. "-" .. math.random(1, 100000))
    redis.call("PEXPIRE", key, window * 1000)

    return { 1, limit - count - 1, now + window * 1000 }
  `;

  async checkLimit(params: {
    identifier:   string;   // customerId, IP, or API key
    profileName:  string;
    endpoint:     string;
  }): Promise<RateLimitResult> {
    const profile = RATE_LIMIT_PROFILES[params.profileName];
    if (!profile) throw new Error(`Unknown rate limit profile: ${params.profileName}`);

    // Key includes identifier + endpoint for per-route limiting
    const key       = `rl:${params.identifier}:${params.endpoint}`;
    const now       = Date.now();
    const result    = await this.redis.eval(
      this.SLIDING_WINDOW_SCRIPT,
      1,
      key,
      String(now),
      String(profile.windowSeconds),
      String(profile.requests),
      String(profile.burstAllowed),
    ) as [number, number, number];

    const [allowed, remaining, resetAtMs] = result;
    const resetAt = new Date(resetAtMs);

    return {
      allowed:       allowed === 1,
      remaining:     Math.max(0, remaining),
      resetAt,
      retryAfterMs:  allowed ? undefined : resetAt.getTime() - now,
    };
  }
}

// ─── Rate limit interceptor ───────────────────────────────────────────────────

// src/rate-limiting/rate-limit.interceptor.ts
@Injectable()
export class RateLimitInterceptor implements NestInterceptor {
  constructor(private readonly limiter: RedisRateLimiter) {}

  async intercept(context: ExecutionContext, next: CallHandler): Promise<Observable<unknown>> {
    const req   = context.switchToHttp().getRequest<AuthenticatedRequest>();
    const res   = context.switchToHttp().getResponse<Response>();
    const route = req.matchedRoute as RouteDefinition;

    // Rate limit by user ID for authenticated requests; by IP for public
    const identifier = req.user?.sub ?? req.ip;

    const result = await this.limiter.checkLimit({
      identifier,
      profileName: route.rateLimitKey,
      endpoint:    `${req.method}:${route.publicPath}`,
    });

    // Always set rate limit headers — standard practice
    res.setHeader("X-RateLimit-Limit",     String(RATE_LIMIT_PROFILES[route.rateLimitKey].requests));
    res.setHeader("X-RateLimit-Remaining", String(result.remaining));
    res.setHeader("X-RateLimit-Reset",     String(Math.ceil(result.resetAt.getTime() / 1000)));

    if (!result.allowed) {
      res.setHeader("Retry-After", String(Math.ceil(result.retryAfterMs! / 1000)));
      throw new HttpException(
        {
          errorCode:   "RATE_LIMIT_EXCEEDED",
          message:     "Too many requests. Please slow down.",
          retryAfterMs: result.retryAfterMs,
        },
        429,
      );
    }

    return next.handle();
  }
}
```

**Q9. How does the gateway implement circuit breaking to protect downstream services from cascade failures?**
A:

```typescript
// src/circuit-breaker/circuit-breaker.service.ts

export type CircuitState = "CLOSED" | "OPEN" | "HALF_OPEN";

interface CircuitBreakerConfig {
  failureThreshold:    number;   // failures before opening
  successThreshold:    number;   // successes in HALF_OPEN before closing
  timeoutMs:           number;   // how long to stay OPEN before trying HALF_OPEN
  monitoringWindowMs:  number;   // rolling window for counting failures
}

@Injectable()
export class CircuitBreakerService {
  private circuits = new Map<string, CircuitBreaker>();

  private readonly DEFAULT_CONFIG: CircuitBreakerConfig = {
    failureThreshold:   5,
    successThreshold:   2,
    timeoutMs:          30_000,
    monitoringWindowMs: 60_000,
  };

  getOrCreate(serviceId: string, config?: Partial<CircuitBreakerConfig>): CircuitBreaker {
    if (!this.circuits.has(serviceId)) {
      this.circuits.set(serviceId, new CircuitBreaker(serviceId, {
        ...this.DEFAULT_CONFIG,
        ...config,
      }));
    }
    return this.circuits.get(serviceId)!;
  }

  getState(serviceId: string): CircuitState {
    return this.circuits.get(serviceId)?.state ?? "CLOSED";
  }
}

class CircuitBreaker {
  private _state: CircuitState  = "CLOSED";
  private failures:   number    = 0;
  private successes:  number    = 0;
  private lastFailAt: number    = 0;
  private readonly logger       = new Logger("CircuitBreaker");

  constructor(
    private readonly serviceId: string,
    private readonly config:    CircuitBreakerConfig,
  ) {}

  get state(): CircuitState { return this._state; }

  async execute<T>(fn: () => Promise<T>): Promise<T> {
    if (this._state === "OPEN") {
      const elapsed = Date.now() - this.lastFailAt;
      if (elapsed < this.config.timeoutMs) {
        throw new ServiceUnavailableException(
          `Circuit OPEN for ${this.serviceId} — retry in ${Math.ceil((this.config.timeoutMs - elapsed) / 1000)}s`
        );
      }
      // Timeout elapsed — try HALF_OPEN
      this._state = "HALF_OPEN";
      this.logger.warn(`Circuit HALF_OPEN for ${this.serviceId}`);
    }

    try {
      const result = await fn();
      this.onSuccess();
      return result;
    } catch (err) {
      this.onFailure();
      throw err;
    }
  }

  private onSuccess(): void {
    if (this._state === "HALF_OPEN") {
      this.successes++;
      if (this.successes >= this.config.successThreshold) {
        this._state   = "CLOSED";
        this.failures = 0;
        this.successes = 0;
        this.logger.log(`Circuit CLOSED for ${this.serviceId}`);
      }
    } else {
      this.failures = Math.max(0, this.failures - 1);  // decay failures on success
    }
  }

  private onFailure(): void {
    this.failures++;
    this.lastFailAt = Date.now();

    if (this.failures >= this.config.failureThreshold) {
      this._state = "OPEN";
      this.logger.error(`Circuit OPEN for ${this.serviceId} after ${this.failures} failures`);
    }
  }
}
```

```typescript
@Injectable()
export class AccessLogMiddleware implements NestMiddleware {
  private readonly SENSITIVE_HEADERS = new Set([
    "authorization", "cookie", "x-api-key", "x-gateway-service-token",
  ]);

  private readonly SENSITIVE_BODY_FIELDS = new Set([
    "password", "pin", "otp", "cardNumber", "cvv", "pan", "aadhaar",
    "accountNumber", "ifscCode", "vpa",
  ]);

  use(req: Request, res: Response, next: NextFunction): void {

    const start    = Date.now();

    // Attach trace ID to request — picked up by all downstream calls
    req.headers["x-trace-id"] = traceId;
    (req as any).traceId      = traceId;

    // Log request — sanitised
    const requestLog = {
      type:      "access_log_request",
      traceId,
      method:    req.method,
      path:      req.path,
      query:     this.sanitiseQuery(req.query),
      userAgent: req.headers["user-agent"],
      ip:        req.ip,
      headers:   this.sanitiseHeaders(req.headers),
      bodySize:  req.headers["content-length"] ?? "unknown",
      // Never log the body for security — only log size
    };

    console.log(JSON.stringify(requestLog));

    // Intercept response to log result
    const originalSend = res.json.bind(res);
    res.json = (body: unknown) => {
      const responseLog = {
        type:       "access_log_response",
        traceId,
        method:     req.method,
        path:       req.path,
        statusCode: res.statusCode,
        durationMs: Date.now() - start,
        // Log response body only for errors — never for 2xx (may contain PII)
        ...(res.statusCode >= 400 ? { errorBody: this.sanitiseBody(body) } : {}),
      };
      console.log(JSON.stringify(responseLog));
      return originalSend(body);
    };

    next();
  }

  private sanitiseHeaders(headers: IncomingHttpHeaders): Record<string, string> {
    return Object.fromEntries(
      Object.entries(headers)
        .filter(([key]) => !this.SENSITIVE_HEADERS.has(key.toLowerCase()))
        .map(([k, v]) => [k, Array.isArray(v) ? v[0] : v ?? ""])
    );
  }

  private sanitiseQuery(query: Record<string, unknown>): Record<string, unknown> {
    return Object.fromEntries(
      Object.entries(query).map(([k, v]) =>
        this.SENSITIVE_BODY_FIELDS.has(k.toLowerCase()) ? [k, "[REDACTED]"] : [k, v]
      )
    );
  }

  private sanitiseBody(body: unknown): unknown {
    if (!body || typeof body !== "object") return body;
    return Object.fromEntries(
      Object.entries(body as Record<string, unknown>).map(([k, v]) =>
        this.SENSITIVE_BODY_FIELDS.has(k.toLowerCase()) ? [k, "[REDACTED]"] : [k, v]
      )
    );
  }
}
```

```typescript
// 1. Subdomain: tenant-a.api.finapp.in
// 2. Header: X-Tenant-ID: tenant-a
// 3. JWT claim: { tenantId: "tenant-a" } in the decoded token

@Injectable()
export class TenantResolutionMiddleware implements NestMiddleware {
  constructor(private readonly tenantRegistry: TenantRegistryService) {}

  async use(req: Request, _res: Response, next: NextFunction): Promise<void> {
    const tenantId = this.extractTenantId(req);

    if (!tenantId) {
      throw new BadRequestException("Cannot resolve tenant from request");
    }

    // Validate tenant exists and is active
    const tenant = await this.tenantRegistry.findById(tenantId);
    if (!tenant) throw new UnauthorizedException(`Unknown tenant: ${tenantId}`);
    if (!tenant.isActive) throw new ForbiddenException(`Tenant ${tenantId} is suspended`);

    // Attach tenant context to request — routing and rate limiting use it
    (req as any).tenant = tenant;

    // Inject tenant ID as header for downstream services
    req.headers["x-tenant-id"]   = tenantId;
    req.headers["x-tenant-tier"] = tenant.tier;   // "sandbox" | "standard" | "enterprise"

    next();
  }

  private extractTenantId(req: Request): string | null {
    // Strategy 1: subdomain
    const host      = req.hostname;
    const subdomain = host.split(".")[0];
    if (subdomain && subdomain !== "api") return subdomain;

    // Strategy 2: explicit header
    const headerTenant = req.headers["x-tenant-id"] as string;
    if (headerTenant) return headerTenant;

    // Strategy 3: JWT claim (populated after auth middleware runs)
    const user = (req as any).user;
    if (user?.tenantId) return user.tenantId;

    return null;
  }
}
```

```typescript
@Injectable()
export class CompositeAuthGuard implements CanActivate {
  constructor(
    private readonly jwtStrategy:    JwtStrategy,
    private readonly apiKeyStrategy: ApiKeyStrategy,
    private readonly routeRegistry:  RouteRegistryService,
  ) {}

  async canActivate(context: ExecutionContext): Promise<boolean> {
    const req   = context.switchToHttp().getRequest<Request>();
    const route = this.routeRegistry.match(req.method, req.path);

    if (!route?.authRequired) return true;   // public route

    const authHeader = req.headers.authorization as string;
    const apiKey     = req.headers["x-api-key"] as string;

    // API key path — for partner integrations
    if (apiKey) {
      const partner = await this.apiKeyStrategy.validateApiKey(apiKey);
      if (!partner) throw new UnauthorizedException("Invalid API key");

      (req as any).user = {
        sub:      partner.partnerId,
        role:     "partner",
        tenantId: partner.tenantId,
        scopes:   partner.allowedScopes,
      };
      return true;
    }

    // JWT path — for end users
    if (authHeader?.startsWith("Bearer ")) {
      const token   = authHeader.slice(7);
      const payload = await this.jwtStrategy.verify(token);

      (req as any).user = payload;
      return true;
    }

    throw new UnauthorizedException("Authentication required");
  }
}

// ─── API key strategy — rate limited and scoped ───────────────────────────────

@Injectable()
export class ApiKeyStrategy {
  constructor(
    private readonly apiKeyDao: ApiKeyDao,
    private readonly redis:     RedisClient,
  ) {}

  async validateApiKey(key: string): Promise<PartnerIdentity | null> {
    // Cache API key lookups — avoids DB hit on every request
    const cacheKey = `apikey:${this.hashKey(key)}`;
    const cached   = await this.redis.get(cacheKey);

    if (cached) {
      return JSON.parse(cached) as PartnerIdentity;
    }

    // DB lookup — verify key hash (never store raw keys)
    const record = await this.apiKeyDao.findByHash(this.hashKey(key));
    if (!record || !record.isActive) return null;
    if (record.expiresAt && record.expiresAt < new Date()) return null;

    const identity: PartnerIdentity = {
      partnerId:     record.partnerId,
      tenantId:      record.tenantId,
      allowedScopes: record.scopes,
      tier:          record.tier,
    };

    // Cache for 5 minutes — key changes are eventually consistent
    await this.redis.setex(cacheKey, 300, JSON.stringify(identity));
    return identity;
  }

  private hashKey(key: string): string {
    return createHash("sha256").update(key).digest("hex");
  }
}
```

```typescript
// src/routing/canary-router.service.ts

export interface CanaryRoute {
  routeId:        string;
  stableUpstream: string;
  canaryUpstream: string;
  canaryPercent:  number;   // 0–100
  stickySession:  boolean;  // same user always gets same variant
  enabledForRoles?: string[];
  enabledForTenants?: string[];
}

@Injectable()
export class CanaryRouterService {
  constructor(
    private readonly redis:      RedisClient,
    private readonly config:     ConfigService,
  ) {}

  async resolveUpstream(route: RouteDefinition, req: AuthenticatedRequest): Promise<string> {
    const canaryConfig = await this.getCanaryConfig(route.publicPath);
    if (!canaryConfig) return route.upstreamUrl;

    // Role-based canary — only opt in certain roles
    if (canaryConfig.enabledForRoles &&
        !canaryConfig.enabledForRoles.includes(req.user?.role ?? "")) {
      return canaryConfig.stableUpstream;
    }

    // Determine if this user is in the canary cohort
    const inCanary = await this.isUserInCanaryCohort(
      req.user?.sub ?? req.ip,
      canaryConfig,
    );

    const upstream = inCanary ? canaryConfig.canaryUpstream : canaryConfig.stableUpstream;

    // Tag request so both variants are separately tracked in metrics
    req.headers["x-canary-variant"] = inCanary ? "canary" : "stable";

    return upstream;
  }

  private async isUserInCanaryCohort(
    userId:  string,
    config:  CanaryRoute,
  ): Promise<boolean> {
    if (config.stickySession) {
      // Sticky: store the assignment in Redis so the user always gets the same variant
      const cacheKey = `canary:${config.routeId}:${userId}`;
      const cached   = await this.redis.get(cacheKey);

      if (cached !== null) return cached === "canary";

      const assignment = Math.random() * 100 < config.canaryPercent ? "canary" : "stable";
      await this.redis.setex(cacheKey, 86400, assignment);  // 24h sticky assignment
      return assignment === "canary";
    }

    // Non-sticky: consistent hash — same user ID → same bucket, but no Redis
    const hash   = this.consistentHash(userId);
    return (hash % 100) < config.canaryPercent;
  }

  private consistentHash(input: string): number {
    let hash = 0;
    for (let i = 0; i < input.length; i++) {
      hash = ((hash << 5) - hash) + input.charCodeAt(i);
      hash |= 0;
    }
    return Math.abs(hash);
  }

  private async getCanaryConfig(path: string): Promise<CanaryRoute | null> {
    // Load from Redis (updated by deployment pipeline during rollout)
    const raw = await this.redis.get(`canary:config:${path}`);
    return raw ? JSON.parse(raw) : null;
  }
}
```

```typescript
  async handleConnection(socket: Socket): Promise<void> {
    const token = socket.handshake.auth.token as string;
    if (!token) { socket.disconnect(); return; }

    try {
      const payload = await this.jwtService.verifyAsync(token);

      // Rate limit WebSocket connections per user
      const rl = await this.rateLimiter.checkLimit({
        identifier:  payload.sub,
        profileName: "standard",
        endpoint:    "websocket:connect",
      });

      if (!rl.allowed) {
        socket.emit("error", { code: "RATE_LIMIT_EXCEEDED" });
        socket.disconnect();
        return;

      this.connections.set(socket.id, { socket, customerId: payload.sub });

      // Join the user's personal room — for targeted push
      socket.join(`user:${payload.sub}`);

      // Forward connection upstream to the relevant service
      await this.upstream.notifyConnect(payload.sub, socket.id);
    } catch {
      socket.disconnect();
    }
  }

  handleDisconnect(socket: Socket): void {
    const conn = this.connections.get(socket.id);
    if (conn) {
      this.upstream.notifyDisconnect(conn.customerId, socket.id);
      this.connections.delete(socket.id);
    }
  }

  // Push real-time events to a specific user — called by internal services via HTTP
  sendToUser(customerId: string, event: string, data: unknown): void {
    this.server.to(`user:${customerId}`).emit(event, data);
  }

  // Receive messages from the client and forward upstream
  @SubscribeMessage("loan-status-subscribe")
  async handleLoanSubscribe(socket: Socket, payload: { loanId: string }): Promise<void> {
```

```typescript
// src/cache/response-cache.interceptor.ts

@Injectable()
export class ResponseCacheInterceptor implements NestInterceptor {
  private readonly logger = new Logger(ResponseCacheInterceptor.name);

  constructor(private readonly redis: RedisClient) {}

  async intercept(ctx: ExecutionContext, next: CallHandler): Promise<Observable<unknown>> {
    const req   = ctx.switchToHttp().getRequest<AuthenticatedRequest>();
    const res   = ctx.switchToHttp().getResponse<Response>();
    const route = req.matchedRoute as RouteDefinition;

    // Only cache GET requests that are explicitly marked as cacheable
    if (req.method !== "GET" || !route.cacheConfig) {
      return next.handle();
    }

    const { ttlSeconds, scope } = route.cacheConfig;

    // Cache key: user-scoped or global
    const cacheKey = scope === "user"
      ? `gw:cache:${req.user?.sub}:${req.path}:${this.hashQuery(req.query)}`
      : `gw:cache:global:${req.path}:${this.hashQuery(req.query)}`;

    // Check ETag for conditional requests
    const ifNoneMatch = req.headers["if-none-match"] as string;

    try {
      const cached = await this.redis.get(cacheKey);
      if (cached) {
        const parsed  = JSON.parse(cached) as CachedResponse;
        const etag    = parsed.etag;

        if (ifNoneMatch && ifNoneMatch === etag) {
          // Client already has the latest version
          res.status(304).end();
          return new Observable(s => s.complete());
        }

        // Serve cached response
        res.setHeader("X-Cache",       "HIT");
        res.setHeader("ETag",          etag);
        res.setHeader("Cache-Control", `max-age=${ttlSeconds}, private`);
        res.status(200).json(parsed.body);
        return new Observable(s => s.complete());
      }
    } catch {
      // Redis failure — proceed without cache (fail open)
      this.logger.warn("Response cache read failed — proceeding without cache");
    }

    // Cache miss — let the request through and cache the response
    return next.handle().pipe(
      tap(async (body) => {
        try {
          const etag = `"${this.hashBody(body)}"`;
          await this.redis.setex(cacheKey, ttlSeconds, JSON.stringify({ body, etag }));
          res.setHeader("X-Cache",       "MISS");
          res.setHeader("ETag",          etag);
          res.setHeader("Cache-Control", `max-age=${ttlSeconds}, private`);
        } catch {
          this.logger.warn("Response cache write failed");
        }
      }),
    );
  }

  private hashQuery(query: Record<string, unknown>): string {
    // Stable hash regardless of key ordering
    const sorted = Object.keys(query).sort().map(k => `${k}=${query[k]}`).join("&");
    return createHash("md5").update(sorted).digest("hex").slice(0, 8);
  }

  private hashBody(body: unknown): string {
    return createHash("md5").update(JSON.stringify(body)).digest("hex").slice(0, 16);
  }
}
```

**Q19. What are the security pitfalls specific to API gateways in a fintech context?**
A: Several gateway-specific security risks demand explicit handling:

```typescript
// ─── Pitfall 1: Header injection — client sends forged x-user-id ─────────────

// ❌ Unsafe: downstream trusts x-user-id set by the client
// A malicious client sends: GET /loans with Header: X-User-Id: admin-id
// Downstream service grants admin access

// ✅ Gateway strips all x-* user-context headers from incoming requests
// and re-injects them from the validated JWT

const BLOCKED_INCOMING_HEADERS = [
  "x-user-id", "x-user-role", "x-tenant-id",
  "x-gateway-hop", "x-internal-*",
];

function stripDangerousHeaders(req: Request): void {
  BLOCKED_INCOMING_HEADERS.forEach(h => {
    // Pattern matching for wildcard headers
    if (h.endsWith("*")) {
      const prefix = h.slice(0, -1);
      Object.keys(req.headers)
        .filter(k => k.startsWith(prefix))
        .forEach(k => delete req.headers[k]);
    } else {
      delete req.headers[h];
    }
  });
}

// ─── Pitfall 2: Path traversal in routing ─────────────────────────────────────

// ❌ Vulnerable: user can traverse to unintended upstream paths
// Request: GET /v1/loans/../../../admin/internal-config
// resolveUrl maps this to: upstream/admin/internal-config

function resolveUrl(template: string, params: Record<string, string>): string {
  const url = template.replace(/:([a-zA-Z]+)/g, (_, k) => params[k] ?? "");
  // ✅ Normalise path — removes ../ traversal attempts
  const normalised = new URL(url).href;
  // ✅ Verify the resolved URL still starts with the expected upstream
  if (!normalised.startsWith(process.env.EXPECTED_UPSTREAM_BASE!)) {
    throw new BadRequestException("Path traversal detected");
  }
  return normalised;
}

// ─── Pitfall 3: Mass assignment via forwarded body ────────────────────────────

// If the gateway passes the full request body to a downstream service,
// a client may inject fields the service trusts but shouldn't accept from clients.
// Fix: gateway or BFF strips non-allowed body fields for write operations.

// ─── Pitfall 4: JWT clock skew — accepting expired tokens ────────────────────

const payload = await jwtService.verifyAsync(token, {
  clockTolerance: 30,   // allow 30s clock skew — no more
  // Never set this to a large value in fintech
});

// ─── Pitfall 5: Token replay after logout ─────────────────────────────────────

// JWTs are stateless — a logged-out token is still cryptographically valid.
// Fix: maintain a Redis blacklist of revoked JTIs.

async validateJwt(token: string): Promise<JwtPayload> {
  const payload    = await jwtService.verifyAsync(token);
  const isRevoked  = await redis.exists(`jti:revoked:${payload.jti}`);
  if (isRevoked) throw new UnauthorizedException("Token has been revoked (logout)");
  return payload;
}

// On logout: add JTI to blacklist with TTL = remaining token lifetime
async logout(token: string): Promise<void> {
  const payload    = jwtService.decode(token) as JwtPayload;
  const remainingMs = payload.exp * 1000 - Date.now();
  if (remainingMs > 0) {
    await redis.setex(`jti:revoked:${payload.jti}`, Math.ceil(remainingMs / 1000), "1");
  }
}
```

**Q21. "Design the API gateway layer for a fintech super-app that serves mobile, web, and partner integrations, with 10 million daily active users and a peak of 50,000 requests per second."**
A:

```
Traffic flow:
Internet → CDN (Cloudflare) → Edge Load Balancer → API Gateway Cluster → BFFs / Services

─── Tier 1: CDN + DDoS Protection ───────────────────────────────────────────────
- Cloudflare in front of everything
- Caches static assets, blocks malicious IPs and bot traffic
- Absorbs DDoS before it reaches the gateway
- Rate limits at the Cloudflare layer for very aggressive abusers

─── Tier 2: Load Balancer ────────────────────────────────────────────────────────
- AWS ALB or GCP Load Balancer
- TLS termination (offload from gateway)
- Health check aware — removes unhealthy gateway instances
- Least-connections algorithm — appropriate for variable-duration requests

─── Tier 3: API Gateway Cluster ─────────────────────────────────────────────────
- 20 gateway instances across 3 availability zones (auto-scaling group)
- Each instance: NestJS + Node.js 20, 2 vCPU, 4 GB RAM
- Horizontally scalable: all state in Redis Cluster (rate limits, circuit breaker, token cache)
- No sticky sessions — any instance can serve any request

Gateway responsibilities at this scale:
1. JWT verification: JWKS cached in-process (10-minute TTL) → <1ms per request
2. Rate limiting: Redis sliding window Lua script → ~2ms per request
3. Routing: in-memory trie → <0.1ms
4. Request forwarding: connection pooled → depends on upstream latency
5. Access logging: async (write to Kafka, not synchronous file I/O)

─── Tier 4: BFFs ────────────────────────────────────────────────────────────────
- Mobile BFF: 10 instances, auto-scaling
- Web BFF: 8 instances, auto-scaling
- Partner BFF: 5 instances (lower traffic, higher timeout tolerance)

─── Estimated capacity per gateway instance ──────────────────────────────────────
- Each instance: ~2,500 req/s (event-loop limited, mostly I/O-bound)
- 20 instances: 50,000 req/s — matches the peak requirement

─── Redis Cluster sizing for rate limiting ───────────────────────────────────────
- 50,000 req/s × 2 Redis ops per request = 100,000 Redis ops/s
- Redis single node: ~200,000 ops/s → one primary + 2 replicas is sufficient
- Use Redis Cluster with 3 shards for HA and future growth headroom
```

**Q22. "A payment service is intermittently timing out under load. Some requests take 30 seconds before failing. How do you configure the gateway to protect other services and clients from being affected?"**
A:

```typescript
// ─── Problem: 30-second upstream timeout exhausts gateway connections ──────────
// While 100 requests are waiting on the payment service, 100 connections are held.
// New requests queue behind them. Gateway appears "slow" even for unrelated services.

// ─── Fix 1: Aggressive per-route timeout ──────────────────────────────────────

const ROUTE_REGISTRY: RouteDefinition[] = [
  {
    method: "POST", publicPath: "/v1/payments",
    upstreamUrl: `${PAYMENT_SERVICE_URL}/payments`,
    timeoutMs: 10_000,  // never wait more than 10s — payment service SLA is 8s
    rateLimitKey: "write",
  },
];

// Client receives 504 Gateway Timeout at 10s instead of waiting 30s
// Connection is released back to the pool — other requests can proceed

// ─── Fix 2: Circuit breaker on the payment service ────────────────────────────

const circuitConfig: Partial<CircuitBreakerConfig> = {
  failureThreshold:   3,        // open after 3 consecutive timeouts
  timeoutMs:          30_000,   // stay open for 30s
  successThreshold:   2,        // close after 2 consecutive successes in HALF_OPEN
  monitoringWindowMs: 60_000,
};

// After 3 timeouts: circuit opens → gateway immediately returns 503 without
// hitting the payment service → connection pool is protected
// After 30s: HALF_OPEN → 1 test request → if success, CLOSED → traffic restored

// ─── Fix 3: Retry with backoff for idempotent payment status checks ────────────

@Injectable()
export class RetryingProxyService extends ProxyService {
  async forwardWithRetry(params: ForwardParams & { maxRetries: number }): Promise<UpstreamResponse> {
    let lastError: Error | null = null;

    for (let attempt = 0; attempt <= params.maxRetries; attempt++) {
      try {
        return await this.forward(params);
      } catch (err: any) {
        lastError = err;

        // Only retry on network errors and 5xx — never on 4xx (client error)
        const isRetryable = !err.status || err.status >= 500;
        if (!isRetryable || attempt === params.maxRetries) throw err;

        // Exponential backoff: 100ms, 200ms, 400ms
        await this.sleep(Math.pow(2, attempt) * 100);
      }
    }
    throw lastError!;
  }
}

// ─── Fix 4: Return cached response for GET /payments/:id during degradation ────

// While the circuit is OPEN, return the last known payment status from cache
// instead of failing immediately — payment status changes slowly

async getPaymentStatus(paymentId: string, token: string): Promise<PaymentStatusDto> {
  if (this.circuits.getState("payment-service") === "OPEN") {
    const cached = await this.cache.get<PaymentStatusDto>(`payment:${paymentId}`);
    if (cached) {
      // Return stale response with a header indicating degraded mode
      return { ...cached, _stale: true, _staleSince: new Date().toISOString() };
    }
  }
  return this.forwardToPaymentService(paymentId, token);
}

// ─── Fix 5: Upstream telemetry — alert before the circuit needs to open ────────

// Alert fires at p99 > 5s → ops team investigates before customers are affected
```

**Q23. "Your security team flags that API keys are being shared by partners and used from multiple IP addresses simultaneously. How do you enhance the gateway's API key security without breaking existing partners?"**
A:

```typescript
// ─── Enhanced API key validation ──────────────────────────────────────────────

@Injectable()
export class EnhancedApiKeyStrategy {
  async validateApiKey(key: string, req: Request): Promise<PartnerIdentity | null> {
    const identity = await this.baseValidate(key);
    if (!identity) return null;

    // Enhancement 1: IP allowlist (optional per partner — not breaking for partners without it)
    if (identity.allowedIps && identity.allowedIps.length > 0) {
      const clientIp = req.ip;
      if (!identity.allowedIps.includes(clientIp)) {
        this.securityAudit.log("api_key_ip_mismatch", {
          partnerId: identity.partnerId,
          expectedIps: identity.allowedIps,
          actualIp:   clientIp,
        });
        throw new UnauthorizedException("Request origin not in API key allowlist");
      }
    }

    // Enhancement 2: Detect anomalous concurrent usage
    const concurrencyKey = `apikey:active:${identity.partnerId}`;
    const activeCount    = await this.redis.incr(concurrencyKey);
    await this.redis.expire(concurrencyKey, 60);

    if (activeCount > identity.maxConcurrentRequests ?? 100) {
      this.securityAudit.log("api_key_concurrent_limit", {
        partnerId:    identity.partnerId,
        activeCount,
        limit:        identity.maxConcurrentRequests,
      });
      // Alert, but don't block immediately — could be a legitimate traffic spike
      // Block after sustained violation
    }

    // Enhancement 3: HMAC request signing (opt-in, phased rollout)
    if (identity.requiresSignature) {
      const signature       = req.headers["x-signature"] as string;
      const timestamp       = req.headers["x-timestamp"] as string;
      const expectedSig     = this.computeHmac(identity.signingSecret, req.method, req.path, timestamp, req.body);

      if (!timingSafeEqual(Buffer.from(signature), Buffer.from(expectedSig))) {
        throw new UnauthorizedException("Invalid request signature");
      }

      // Reject replayed requests — timestamp must be within 5 minutes
      const requestAge = Date.now() - parseInt(timestamp, 10);
      if (requestAge > 5 * 60 * 1000) {
        throw new UnauthorizedException("Request timestamp too old — possible replay attack");
      }
    }

    return identity;
  }

  private computeHmac(secret: string, method: string, path: string, timestamp: string, body: unknown): string {
    const message = `${method}\n${path}\n${timestamp}\n${JSON.stringify(body ?? {})}`;
    return createHmac("sha256", secret).update(message).digest("hex");
  }
}

// ─── Migration path — non-breaking rollout ────────────────────────────────────

// Phase 2: Require IP registration in the partner portal (UI change, no API change)
// Phase 3: Enforce IP allowlist for new API keys; grandfather existing keys with 90-day notice
// Phase 4: Require HMAC signing for new keys; deprecation notice for unsigned keys
```

```typescript
// X-Gateway: kong → Kong (new)

// Any discrepancy is logged — auth failures, different error codes, missing headers.

// Operated by a shadow traffic middleware on the load balancer:
function shadowMode(req, res, next) {
```

**Q25. "How do you explain the difference between an API Gateway, a BFF, and a reverse proxy to a product manager asking why the company has three different 'API things'?"**
A: A clean, non-technical explanation using concrete analogies:

> "Think of our fintech system like a large hospital. We have many departments — the Loans department, the Payments department, the KYC department, each doing its own specialised work. Patients (our users) and visitors (partner companies) need to reach the right department.
>
> **The reverse proxy** is like the hospital's security checkpoint at the main entrance — it checks that everyone who enters is allowed, and it directs traffic to the right building. It doesn't know anything about medicine; it just manages the flow of people in and out safely.
>
> **The API gateway** is like the main reception desk just inside the entrance. It handles everything that's true for *every* visitor regardless of which department they're going to: 'Do you have a valid ID card?' (authentication), 'Are you allowed in this wing?' (rate limiting), 'You've come in the wrong way — use the east entrance instead' (routing). It doesn't know what the Loans department does or what the mobile app needs; it just enforces the common rules that apply to everyone.
>
> **The BFF** is like a dedicated patient coordinator who works specifically for one type of patient — say, outpatients who come via the mobile app. The coordinator knows exactly what an outpatient needs for their visit: they pre-collect information from Loans, Payments, and KYC on the patient's behalf, arrange it neatly in the order the patient will need it, and present it all in one go rather than making the patient walk to three different desks. There's a different coordinator for inpatients (the web dashboard), and another for visiting doctors (third-party partners) — each knows their audience's specific needs.
>
> So why three? Because they solve three different problems. The security checkpoint is infrastructure — it's the same for everyone. The reception desk enforces common rules — the same for everyone. The patient coordinator provides a personalised experience — different for each type of visitor. Collapsing them into one would mean either the reception desk becomes overwhelmed with patient-specific knowledge, or the coordinator gets bogged down checking IDs. Each does its job and stays out of the others'."

**Tip for the Interview:** At the 5 YOE level, API gateway questions surface as system design problems — "design the API layer for a system with 50,000 requests per second," "a downstream service is timing out and affecting everything — how does the gateway help," or "how do you add rate limiting without touching 20 microservices?" The answers that land demonstrate five things: (1) you can articulate the gateway's precise scope — infrastructure concerns only, never business logic, and the distinction from BFF is crisp; (2) you know the implementation details cold — Redis sliding window rate limiting, JWKS-based JWT verification with key rotation, circuit breaker state machine, and stateless horizontal scaling via Redis; (3) you understand the security surface — header injection from clients, path traversal, token replay, and JTI revocation; (4) you can size a gateway cluster for a real traffic number — event loop capacity, connection pool, Redis ops/s; and (5) you've thought through the failure modes — circuit breaking, graceful degradation on Redis failure, timeout configuration, and high-availability deployment. In fintech specifically, the security pitfalls angle — header injection, token revocation after logout, API key HMAC signing — demonstrates domain-relevant thinking that goes beyond generic gateway knowledge.
