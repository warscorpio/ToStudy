### Section 1: OpenAPI and Swagger Fundamentals

**Q1. What is OpenAPI, what is Swagger, and what does `@nestjs/swagger` specifically provide?**
A: **OpenAPI** is a language-agnostic specification (formerly called Swagger Specification) for describing REST APIs as a machine-readable document — a JSON or YAML file that describes every endpoint, its parameters, request bodies, responses, authentication schemes, and data schemas. The current version is OpenAPI 3.0.

**Swagger** is the ecosystem of tooling built around OpenAPI: Swagger UI (a browser-based interactive API explorer), Swagger Editor (an IDE for writing specs), and Swagger Codegen (generates client SDKs from a spec).

**`@nestjs/swagger`** introspects a NestJS application at bootstrap time to automatically generate an OpenAPI 3.0 document from the existing code — controllers, DTOs, decorators — without maintaining a separate spec file. It provides:

```
@nestjs/swagger provides:
  1. SwaggerModule          → mounts Swagger UI at a configured path
  2. DocumentBuilder        → fluent API to configure the document (title, version, tags, security)
  3. Decorator set          → annotate controllers and DTOs to enrich the generated document
  4. CLI Plugin             → TypeScript compiler plugin that auto-generates @ApiProperty
                              decorators from TypeScript type hints (optional, zero-decorator approach)
  5. Mapped types           → PartialType, PickType, OmitType, IntersectionType that preserve
                              OpenAPI metadata (unlike @nestjs/mapped-types which doesn't)
```

```
The generated OpenAPI document describes:
  ├── info        → title, description, version, contact, license
  ├── servers     → base URLs for the API
  ├── paths       → each route with its HTTP method, parameters, body, responses
  ├── components
  │   ├── schemas      → DTO shapes (reusable, referenced by $ref)
  │   └── securitySchemes → Bearer, API Key, OAuth2, Cookie
  └── security    → global security requirements
```

**Q2. How do you bootstrap Swagger in a NestJS application and what does each `DocumentBuilder` method configure?**
A: Swagger is set up in `main.ts` after the application is created but before it starts listening. The `DocumentBuilder` configures document-level metadata; `SwaggerModule.createDocument` introspects the app; `SwaggerModule.setup` mounts the UI.

```ts
// main.ts
import { NestFactory }      from '@nestjs/core';
import { SwaggerModule, DocumentBuilder } from '@nestjs/swagger';
import { AppModule }        from './app.module';
import { ValidationPipe }   from '@nestjs/common';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);

  // ── Validation (add before Swagger so ValidationPipe errors are also documented) ──
  app.useGlobalPipes(new ValidationPipe({ transform: true, whitelist: true }));

  // ── DocumentBuilder — document-level metadata ──────────────────────────────────
  const config = new DocumentBuilder()
    .setTitle('MyCompany API')                       // document title (shown in UI header)
    .setDescription('The MyCompany REST API docs')  // document description (supports Markdown)
    .setVersion('1.0.0')                            // API version string
    .setContact(                                    // contact info (optional)
      'Platform Team',
      'https://mycompany.com/team',
      'api-support@mycompany.com',
    )
    .setLicense('MIT', 'https://opensource.org/licenses/MIT') // license info
    .setTermsOfService('https://mycompany.com/terms')

    // Servers — base URLs (Swagger UI sends requests here):
    .addServer('https://api.mycompany.com', 'Production')
    .addServer('https://staging-api.mycompany.com', 'Staging')
    .addServer('http://localhost:3000', 'Local')

    // Security schemes — HOW the API can be authenticated:
    .addBearerAuth(                                 // JWT Bearer token
      { type: 'http', scheme: 'bearer', bearerFormat: 'JWT' },
      'access-token',                              // reference name used in @ApiBearerAuth('access-token')
    )
    .addApiKey(                                    // API Key in header
      { type: 'apiKey', in: 'header', name: 'X-API-Key' },
      'api-key',
    )
    .addOAuth2(                                    // OAuth2
      {
        type: 'oauth2',
        flows: {
          authorizationCode: {
            authorizationUrl: 'https://auth.mycompany.com/oauth/authorize',
            tokenUrl:         'https://auth.mycompany.com/oauth/token',
            scopes: { read: 'Read access', write: 'Write access' },
          },
        },
      },
      'oauth2',
    )
    .addCookieAuth('session')                      // Cookie-based auth

    // Tags — group endpoints in the UI (mirrors @ApiTags on controllers):
    .addTag('users',    'User management endpoints')
    .addTag('products', 'Product catalog endpoints')
    .addTag('orders',   'Order management endpoints')

    .build();

  // ── Generate the document ──────────────────────────────────────────────────────
  const document = SwaggerModule.createDocument(app, config, {
    include:         [UsersModule, ProductsModule],  // only document these modules (optional)
    deepScanRoutes:  true,    // scan nested routers
    extraModels:     [PaginatedResponseDto, ErrorResponseDto],  // register models not used in routes
    operationIdFactory: (controllerKey, methodKey) =>
      `${controllerKey}_${methodKey}`,              // custom operationId format
  });

  // ── Mount Swagger UI ───────────────────────────────────────────────────────────
  SwaggerModule.setup('api/docs', app, document, {
    swaggerOptions: {
      persistAuthorization:  true,    // keep auth token across page refreshes
      displayRequestDuration: true,   // show request time in UI
      filter:                true,    // enable search filter box
      showExtensions:        true,
      tagsSorter:            'alpha', // sort tags alphabetically
      operationsSorter:      'alpha', // sort operations alphabetically
      docExpansion:          'none',  // collapse all by default ('list', 'full', 'none')
      tryItOutEnabled:       false,   // disable "Try it out" in production
    },
    customCss:       '.swagger-ui .topbar { display: none }', // hide the top bar
    customSiteTitle: 'MyCompany API Docs',
    jsonDocumentUrl: 'api/docs-json', // expose raw JSON at this path
    yamlDocumentUrl: 'api/docs-yaml', // expose raw YAML at this path
  });

  await app.listen(3000);
  console.log('Swagger UI: http://localhost:3000/api/docs');
}
bootstrap();
```

### Section 2: Controller and Endpoint Decorators

**Q3. What are the primary controller-level and method-level decorators and what does each add to the OpenAPI document?**
A: Decorators at the controller and method level document the structure and behavior of endpoints:

```ts
import {
  ApiTags, ApiOperation, ApiResponse, ApiOkResponse, ApiCreatedResponse,
  ApiBadRequestResponse, ApiUnauthorizedResponse, ApiForbiddenResponse,
  ApiNotFoundResponse, ApiConflictResponse, ApiInternalServerErrorResponse,
  ApiBearerAuth, ApiCookieAuth, ApiParam, ApiQuery, ApiHeader, ApiBody,
  ApiConsumes, ApiProduces, ApiExcludeEndpoint, ApiExcludeController,
} from '@nestjs/swagger';

@ApiTags('users')                   // groups this controller under the 'users' tag in UI
@ApiBearerAuth('access-token')      // all endpoints require Bearer token (schema name must match addBearerAuth)
@ApiUnauthorizedResponse({ description: 'Missing or invalid token' })  // applies to ALL methods
@Controller('users')
export class UsersController {

  @ApiOperation({
    summary:     'List all users',           // short one-line description (shown in endpoint title)
    description: 'Returns a paginated list of users. Supports filtering by role and status.',
    operationId: 'listUsers',               // unique ID used by codegen tools
    deprecated:  false,                     // marks endpoint as deprecated in UI
    externalDocs: {                         // link to external documentation
      description: 'Full filtering guide',
      url: 'https://docs.mycompany.com/users/filtering',
    },
  })
  @ApiOkResponse({
    description: 'Paginated list of users',
    type:        PaginatedUsersResponseDto,  // → generates $ref to PaginatedUsersResponseDto schema
  })
  @ApiBadRequestResponse({ description: 'Invalid query parameters' })
  @ApiQuery({ name: 'page',   type: Number,  required: false, example: 1 })
  @ApiQuery({ name: 'limit',  type: Number,  required: false, example: 20, maximum: 100 })
  @ApiQuery({ name: 'role',   enum: UserRole, required: false })
  @ApiQuery({ name: 'search', type: String,  required: false, description: 'Full-text search' })
  @Get()
  findAll(@Query() query: FindUsersQueryDto) { /* ... */ }

  @ApiOperation({ summary: 'Get user by ID' })
  @ApiParam({
    name:        'id',
    type:        Number,
    description: 'The user ID',
    example:     42,
    required:    true,
  })
  @ApiOkResponse({ type: UserResponseDto })
  @ApiNotFoundResponse({ description: 'User not found' })
  @Get(':id')
  findOne(@Param('id') id: number) { /* ... */ }

  @ApiOperation({ summary: 'Create a new user' })
  @ApiBody({
    type:        CreateUserDto,         // the request body schema
    description: 'User creation payload',
    examples: {                         // multiple request body examples:
      minimal: {
        summary: 'Minimal user',
        value:   { name: 'Alice', email: 'alice@example.com', role: 'user' },
      },
      admin: {
        summary: 'Admin user',
        value:   { name: 'Bob', email: 'bob@example.com', role: 'admin', department: 'IT' },
      },
    },
  })
  @ApiCreatedResponse({ type: UserResponseDto, description: 'User created successfully' })
  @ApiConflictResponse({ description: 'Email already in use' })
  @Post()
  create(@Body() dto: CreateUserDto) { /* ... */ }

  @ApiOperation({ summary: 'Upload user avatar' })
  @ApiConsumes('multipart/form-data')    // tell Swagger the content type
  @ApiBody({
    schema: {
      type:       'object',
      properties: {
        file: { type: 'string', format: 'binary' },  // binary file upload
      },
    },
  })
  @ApiOkResponse({ description: 'Avatar uploaded' })
  @Post(':id/avatar')
  @UseInterceptors(FileInterceptor('file'))
  uploadAvatar(
    @Param('id') id: number,
    @UploadedFile() file: Express.Multer.File,
  ) { /* ... */ }

  @ApiExcludeEndpoint()   // hide this endpoint from Swagger UI entirely
  @Get('internal-debug')
  internalDebug() { /* ... */ }
}

@ApiExcludeController()   // hide ALL endpoints in this controller
@Controller('internal')
export class InternalController { /* ... */ }
```

**Q4. What is the difference between `@ApiResponse` and its typed shorthand variants?**
A: `@ApiResponse` is the base decorator accepting a full configuration object including the `status` field. The typed shorthands are pre-configured with specific status codes — they exist purely for readability and to reduce boilerplate:

```ts
// Base decorator — explicit status code required:
@ApiResponse({ status: 200, description: 'User found', type: UserResponseDto })
@ApiResponse({ status: 400, description: 'Validation failed' })
@ApiResponse({ status: 401, description: 'Unauthorized' })
@ApiResponse({ status: 404, description: 'Not found' })

// Named shorthands — status code baked in:
@ApiOkResponse({ description: 'User found', type: UserResponseDto })         // 200
@ApiCreatedResponse({ description: 'Created', type: UserResponseDto })        // 201
@ApiAcceptedResponse({ description: 'Processing' })                           // 202
@ApiNoContentResponse({ description: 'Deleted' })                             // 204
@ApiBadRequestResponse({ description: 'Validation failed' })                  // 400
@ApiUnauthorizedResponse({ description: 'Missing token' })                    // 401
@ApiForbiddenResponse({ description: 'Insufficient permissions' })            // 403
@ApiNotFoundResponse({ description: 'Resource not found' })                   // 404
@ApiConflictResponse({ description: 'Duplicate entry' })                      // 409
@ApiGoneResponse({ description: 'Resource deleted' })                         // 410
@ApiUnprocessableEntityResponse({ description: 'Business rule violation' })   // 422
@ApiTooManyRequestsResponse({ description: 'Rate limit exceeded' })           // 429
@ApiInternalServerErrorResponse({ description: 'Unexpected error' })          // 500

// All accept the same options:
@ApiOkResponse({
  description: 'Paginated results',
  type:        PaginatedDto,
  isArray:     false,     // type is PaginatedDto itself (which contains an array)
  headers: {              // document response headers:
    'X-Total-Count': {
      description: 'Total number of records',
      schema: { type: 'integer' },
    },
    'X-Request-Id': {
      description: 'Unique request identifier',
      schema: { type: 'string' },
    },
  },
})
```

### Section 3: `@ApiProperty` — DTO Documentation

**Q5. What is `@ApiProperty` and what are all the options it accepts?**
A: `@ApiProperty()` annotates class properties to generate their OpenAPI schema definition. Without it (and without the CLI plugin), properties are invisible in the generated document. Every property that should appear in the Swagger UI must be decorated.

```ts
import { ApiProperty, ApiPropertyOptional, ApiHideProperty } from '@nestjs/swagger';

export class CreateUserDto {
  @ApiProperty({
    // Core type descriptor:
    type:        String,          // JS type (String, Number, Boolean, Date) or class
    // For arrays: type: [String] OR isArray: true, type: String
    // For nested DTO: type: () => AddressDto (use arrow fn to avoid circular ref issues)
    // For union: oneOf: [{ $ref: getSchemaPath(DogDto) }, { $ref: getSchemaPath(CatDto) }]

    // Documentation:
    description: 'Full display name of the user',
    example:     'Alice Johnson',          // shown as default value in UI
    examples: {                            // multiple named examples
      short: { value: 'Ali', summary: 'Short name' },
      full:  { value: 'Alice Johnson', summary: 'Full name' },
    },

    // Presence:
    required:    true,                    // false → makes it optional in schema
    nullable:    false,                   // true → adds null to allowed types
    default:     undefined,              // default value if not provided
    readOnly:    false,                   // true → only in responses, not requests
    writeOnly:   false,                   // true → only in requests (passwords), not responses

    // String constraints (generates JSON Schema keywords):
    minLength:   2,
    maxLength:   100,
    pattern:     '^[A-Za-z ]+$',        // regex pattern
    format:      'email',               // 'email' | 'uri' | 'uuid' | 'date' | 'date-time' | 'binary'

    // Number constraints:
    minimum:        0,
    maximum:        150,
    exclusiveMinimum: true,
    exclusiveMaximum: false,
    multipleOf:     1,                  // must be multiple of N

    // Array constraints:
    isArray:      false,               // makes this property an array
    minItems:     1,
    maxItems:     100,
    uniqueItems:  true,

    // Enum:
    enum:         UserRole,            // enum object OR array of values
    enumName:     'UserRole',         // name used for the $ref in generated schema
  })
  name: string;

  // @ApiPropertyOptional = @ApiProperty({ required: false }) — shorthand:
  @ApiPropertyOptional({
    description: 'User biography',
    example:     'Software engineer at MyCompany',
    maxLength:   500,
  })
  bio?: string;

  // @ApiHideProperty — property exists on the class but is excluded from the schema:
  @ApiHideProperty()
  internalFlag: boolean;  // not visible in Swagger UI, not sent to clients

  // Nested DTO:
  @ApiProperty({
    type:        () => AddressDto,    // arrow function prevents circular reference issues
    description: 'User billing address',
  })
  address: AddressDto;

  // Array of primitives:
  @ApiProperty({
    type:     [String],              // shorthand for isArray: true, type: String
    example:  ['admin', 'editor'],
    uniqueItems: true,
  })
  roles: string[];

  // Array of nested DTOs:
  @ApiProperty({
    type:    () => [OrderDto],       // arrow function + array
    isArray: true,
  })
  recentOrders: OrderDto[];

  // Enum property:
  @ApiProperty({
    enum:     UserStatus,
    example:  UserStatus.Active,
    enumName: 'UserStatus',          // creates a named schema component: #/components/schemas/UserStatus
  })
  status: UserStatus;

  // Date:
  @ApiProperty({
    type:    String,
    format:  'date-time',
    example: '2024-01-15T09:30:00Z',
  })
  createdAt: Date;

  // Raw schema (escape hatch for complex types):
  @ApiProperty({
    schema: {
      oneOf: [
        { type: 'string' },
        { type: 'number' },
        { $ref: '#/components/schemas/ComplexType' },
      ],
    },
  })
  flexible: string | number | ComplexType;
}
```

**Q6. What is the difference between `type` accepting a class vs a primitive in `@ApiProperty`, and how do you handle circular references?**
A: When `type` is a NestJS/TypeScript class, Swagger generates a `$ref` to that class's schema (defined in `components/schemas`). When `type` is a JavaScript primitive (`String`, `Number`, `Boolean`) it generates an inline schema. Arrow functions for the `type` field defer evaluation, breaking circular reference cycles.

```ts
// Primitive types (inline schema):
@ApiProperty({ type: String })   // → { "type": "string" }
@ApiProperty({ type: Number })   // → { "type": "number" }
@ApiProperty({ type: Boolean })  // → { "type": "boolean" }

// Class types (generates $ref):
@ApiProperty({ type: AddressDto })
// → { "$ref": "#/components/schemas/AddressDto" }
// AddressDto schema is defined in components/schemas/AddressDto

// ── Circular Reference Problem ─────────────────────────────────────────
// Without arrow function: when this file is parsed, UserDto may not be defined yet
// (if there's a mutual import, TypeScript hasn't evaluated the class)

// ❌ May cause circular reference or undefined class issues:
export class PostDto {
  @ApiProperty({ type: UserDto })    // UserDto evaluated at decoration time
  author: UserDto;
}

export class UserDto {
  @ApiProperty({ type: PostDto })    // PostDto evaluated at decoration time
  posts: PostDto[];                  // if PostDto isn't defined yet → undefined → schema missing
}

// ✓ Arrow function defers evaluation to runtime (after all classes are loaded):
export class PostDto {
  @ApiProperty({ type: () => UserDto })  // evaluated lazily — UserDto is defined by then
  author: UserDto;
}

export class UserDto {
  @ApiProperty({ type: () => [PostDto] }) // array: () => [PostDto] or isArray + () => PostDto
  posts: PostDto[];
}

// ── Self-referential (recursive) types ────────────────────────────────
export class CategoryDto {
  @ApiProperty()
  id: number;

  @ApiProperty()
  name: string;

  @ApiPropertyOptional({
    type:    () => [CategoryDto],   // arrow function + array
    isArray: true,
  })
  children?: CategoryDto[];         // a category can have subcategories
}
```

### Section 4: Mapped Types with Swagger Awareness

**Q7. Why must you use mapped types from `@nestjs/swagger` instead of `@nestjs/mapped-types` when using Swagger?**
A: `@nestjs/mapped-types` (`PartialType`, `PickType`, `OmitType`, `IntersectionType`) copies `class-validator` and `class-transformer` metadata — but NOT `@ApiProperty` metadata. When you generate a mapped type, Swagger sees none of the parent's properties.

`@nestjs/swagger` re-exports the same functions with an additional step: they copy both the validation metadata AND the OpenAPI metadata. The API is identical — only the import path differs.

```ts
// ❌ Wrong import — loses @ApiProperty metadata:
import { PartialType } from '@nestjs/mapped-types';

export class UpdateUserDto extends PartialType(CreateUserDto) {}
// In Swagger UI: UpdateUserDto schema has NO properties → body is documented as {}

// ✓ Correct import — preserves @ApiProperty metadata:
import { PartialType, PickType, OmitType, IntersectionType } from '@nestjs/swagger';

export class UpdateUserDto extends PartialType(CreateUserDto) {}
// In Swagger UI: UpdateUserDto schema has all CreateUserDto properties, all marked optional ✓

// ── All four mapped types with Swagger ────────────────────────────────

// PartialType — all properties become optional:
export class UpdateProductDto extends PartialType(CreateProductDto) {}
// Swagger: all @ApiProperty fields shown as not required

// PickType — only selected properties:
export class ProductSummaryDto extends PickType(ProductDto, ['id', 'name', 'price'] as const) {}
// Swagger: only id, name, price appear in schema

// OmitType — all properties except selected:
export class CreateProductPublicDto extends OmitType(CreateProductDto, ['internalNotes', 'cost'] as const) {}
// Swagger: all ProductDto fields EXCEPT internalNotes and cost

// IntersectionType — merge two DTOs:
export class CreateOrderWithAddressDto extends IntersectionType(
  CreateOrderDto,
  AddressDto,
) {}
// Swagger: all fields from both DTOs combined in one schema

// Composing mapped types:
export class UpdateProductPublicDto extends PartialType(
  OmitType(CreateProductDto, ['cost', 'internalId'] as const)
) {}
// Swagger: all public fields, all optional (for PATCH)
```

### Section 5: Advanced Schema Patterns

**Q8. How do you document polymorphic types using `oneOf`, `anyOf`, and `allOf` in `@nestjs/swagger`?**
A: Polymorphic schemas (a field that can be one of several types) use JSON Schema composition keywords. `@nestjs/swagger` exposes these through `ApiProperty`'s `schema` option and the `getSchemaPath` helper.

```ts
import { ApiProperty, ApiExtraModels, getSchemaPath } from '@nestjs/swagger';

// ── oneOf — the value is exactly ONE of the listed schemas ────────────

// First: register the possible types so Swagger knows their schemas exist:
@ApiExtraModels(DogDto, CatDto, BirdDto)
@Controller('pets')
export class PetsController {

  @ApiOkResponse({
    schema: {
      properties: {
        data: {
          oneOf: [
            { $ref: getSchemaPath(DogDto) },   // $ref to DogDto schema
            { $ref: getSchemaPath(CatDto) },
            { $ref: getSchemaPath(BirdDto) },
          ],
        },
      },
    },
  })
  @Get(':id')
  findOne() { /* ... */ }
}

// On a DTO property:
export class CreatePetDto {
  @ApiProperty({
    oneOf: [
      { $ref: getSchemaPath(DogSpecificDto) },
      { $ref: getSchemaPath(CatSpecificDto) },
    ],
    discriminator: {               // tells the UI which type to use based on a field:
      propertyName: 'type',
      mapping: {
        dog: getSchemaPath(DogSpecificDto),
        cat: getSchemaPath(CatSpecificDto),
      },
    },
  })
  details: DogSpecificDto | CatSpecificDto;

  @ApiProperty({ enum: ['dog', 'cat'] })
  type: 'dog' | 'cat';
}

// ── allOf — the value must satisfy ALL schemas (composition/extension) ─
export class AuditedUserDto {
  @ApiProperty({
    allOf: [
      { $ref: getSchemaPath(UserDto) },         // all UserDto properties
      { $ref: getSchemaPath(AuditFieldsDto) },  // PLUS all AuditFieldsDto properties
    ],
  })
  user: UserDto & AuditFieldsDto;
}

// ── Generic wrapper types ──────────────────────────────────────────────
// Challenge: TypeScript generics are erased at runtime — class Paginated<T>
// can't be introspected. Solution: factory function + @ApiExtraModels

export class PaginatedDto<T> {
  @ApiProperty()
  total: number;

  @ApiProperty()
  page: number;

  @ApiProperty()
  lastPage: number;

  // items: T[] — the T is unknown to Swagger at runtime
  items: T[];
}

// Factory function to create a typed schema reference:
export const ApiPaginatedResponse = <TModel extends Type<unknown>>(model: TModel) => {
  return applyDecorators(
    ApiExtraModels(PaginatedDto, model),    // register both schemas
    ApiOkResponse({
      schema: {
        allOf: [
          { $ref: getSchemaPath(PaginatedDto) },    // PaginatedDto base
          {
            properties: {
              items: {
                type:  'array',
                items: { $ref: getSchemaPath(model) }, // items: UserDto[]
              },
            },
          },
        ],
      },
    }),
  );
};

// Usage as a custom decorator:
@ApiPaginatedResponse(UserDto)   // → documents Paginated<UserDto> response
@Get()
findAll(): Promise<PaginatedDto<UserDto>> { /* ... */ }
```

**Q9. How do you document enum types and what is `enumName` used for?**
A: Without `enumName`, every enum property generates an inline schema with all enum values repeated at each usage. With `enumName`, Swagger generates a named schema component (`#/components/schemas/UserStatus`) and references it — less duplication, consistent naming in generated SDKs.

```ts
// Define the enum:
export enum UserStatus {
  Active   = 'active',
  Inactive = 'inactive',
  Banned   = 'banned',
  Pending  = 'pending',
}

export enum UserRole {
  Admin     = 'admin',
  Manager   = 'manager',
  User      = 'user',
  ReadOnly  = 'read_only',
}

// DTO properties:
export class UserDto {
  // Without enumName — inline schema repeated at every usage:
  @ApiProperty({ enum: UserStatus })
  status: UserStatus;
  // Generated: { "enum": ["active", "inactive", "banned", "pending"], "type": "string" }

  // With enumName — generates $ref to named component:
  @ApiProperty({ enum: UserStatus, enumName: 'UserStatus' })
  status: UserStatus;
  // Generated: { "$ref": "#/components/schemas/UserStatus" }
  // components/schemas/UserStatus: { "enum": ["active", "inactive", "banned", "pending"], "type": "string" }

  // Enum query parameter — @ApiQuery:
  @ApiQuery({ name: 'status', enum: UserStatus, required: false, enumName: 'UserStatus' })
  // Swagger UI shows a dropdown with enum values ✓
}

// Numeric enum (less common but supported):
export enum Priority { Low = 1, Medium = 2, High = 3 }

@ApiProperty({
  enum:     Priority,
  enumName: 'Priority',
  example:  Priority.High,
})
priority: Priority;
// Generated: { "$ref": "#/components/schemas/Priority" }
// components/schemas/Priority: { "enum": [1, 2, 3], "type": "integer" }
```

### Section 6: Security Documentation

**Q10. How do you document authentication and apply security requirements per endpoint?**
A: Security is configured in two places: the `DocumentBuilder` declares the available authentication schemes; decorators on controllers and methods declare which schemes are required for which endpoints.

```ts
// ── DocumentBuilder — declare available schemes ──────────────────────
new DocumentBuilder()
  .addBearerAuth(
    {
      type:         'http',
      scheme:       'bearer',
      bearerFormat: 'JWT',
      description:  'Enter your JWT access token',
      in:           'header',
    },
    'access-token',    // ← reference name used in @ApiBearerAuth()
  )
  .addBearerAuth(
    { type: 'http', scheme: 'bearer', bearerFormat: 'JWT' },
    'refresh-token',   // ← different name for refresh token endpoint
  )
  .addApiKey(
    {
      type: 'apiKey',
      in:   'header',
      name: 'X-API-Key',
      description: 'API Key for service-to-service calls',
    },
    'api-key',
  )
  .addBasicAuth(undefined, 'basic-auth')
  .addOAuth2({
    type:  'oauth2',
    flows: {
      password: {
        tokenUrl: '/auth/token',
        scopes:   { 'users:read': 'Read users', 'users:write': 'Write users' },
      },
    },
  }, 'oauth2')

// ── Controller-level security — applies to ALL methods ────────────────
@ApiBearerAuth('access-token')   // all endpoints in this controller require Bearer
@Controller('users')
export class UsersController {

  // ── Method-level overrides / additions ────────────────────────────
  @ApiBearerAuth('access-token')      // Bearer AND API key both accepted
  @ApiSecurity('api-key')             // generic security decorator
  @Get()
  findAll() { /* ... */ }

  @ApiSecurity({})                    // OVERRIDE: no security required for this endpoint
  @Get('public-count')                // (empty object = no auth needed)
  publicCount() { /* ... */ }

  @ApiBearerAuth('refresh-token')     // different token for refresh
  @Post('refresh')
  refresh() { /* ... */ }
}

// ── Multiple security requirements (AND vs OR) ────────────────────────
// AND (both required simultaneously):
// Achieved by stacking decorators — Swagger treats multiple as "all must be satisfied"

// OR (any one is sufficient):
// Both schemes listed in the same security array entry:
@ApiSecurity({ 'access-token': [], 'api-key': [] })  // Bearer OR api-key
// (This is less common — NestJS doesn't have a dedicated decorator for OR logic)
```

### Section 7: The CLI Plugin

**Q11. What is the `@nestjs/swagger` CLI plugin and what does it auto-generate?**
A: The CLI plugin hooks into the TypeScript compiler using the TS compiler API. It reads the TypeScript type information at build time and automatically adds `@ApiProperty()` decorators to DTO class properties — eliminating the need to write them by hand for straightforward cases.

```json
// nest-cli.json — enable the plugin:
{
  "collection": "@nestjs/schematics",
  "sourceRoot":  "src",
  "compilerOptions": {
    "plugins": [
      {
        "name":    "@nestjs/swagger",
        "options": {
          "dtoFileNameSuffix":      [".dto.ts", ".entity.ts"],  // which files to process
          "controllerFileNameSuffix": [".controller.ts"],
          "classValidatorShim":     true,     // infer @ApiProperty from class-validator decorators
          "dtoKeyOfComment":        "description",  // use JSDoc @description as description
          "introspectComments":     true,     // use JSDoc comments as description source
          "readonly":               false,    // add readOnly: true to readonly properties
        }
      }
    ]
  }
}
```

```ts
// Without plugin — must write @ApiProperty manually:
export class CreateUserDto {
  @IsString() @MinLength(2)
  @ApiProperty({ type: String, minLength: 2 })  // manual
  name: string;

  @IsEmail()
  @ApiProperty({ type: String, format: 'email' }) // manual
  email: string;
}

// With plugin enabled — TypeScript types and class-validator decorators are read:
export class CreateUserDto {
  @IsString() @MinLength(2)
  name: string;               // plugin auto-generates: @ApiProperty({ type: String, minLength: 2 })

  @IsEmail()
  email: string;              // plugin auto-generates: @ApiProperty({ type: String, format: 'email' })

  @IsOptional() @IsNumber()
  age?: number;               // plugin auto-generates: @ApiProperty({ type: Number, required: false })
}
// With introspectComments: true:
/**
 * @description The full display name of the user
 * @example Alice Johnson
 */
name: string; // → @ApiProperty({ description: 'The full display name of the user', example: 'Alice Johnson' })
```

Plugin limitations — still need manual `@ApiProperty` for:
```ts
// Enum types (plugin can't infer enum values at build time):
@ApiProperty({ enum: UserRole, enumName: 'UserRole' })
role: UserRole;

// Generic types (type parameter is erased):
@ApiProperty({ type: () => [UserDto] })
items: UserDto[];

// Union types (oneOf — plugin doesn't generate composite schemas):
@ApiProperty({ oneOf: [{ $ref: getSchemaPath(DogDto) }, ...] })
pet: DogDto | CatDto;

// Raw schema (escape hatch cases):
@ApiProperty({ schema: { additionalProperties: { type: 'string' } } })
metadata: Record<string, string>;

// Descriptions, examples, custom formats (business context only you know):
@ApiProperty({ description: 'ISO 4217 currency code', example: 'USD' })
currency: string;
```

### Section 8: Scenario / Interview-Style Questions

**Q12. "How do you expose multiple separate Swagger documents from one NestJS application — for example, a public API and an admin API?"**
A: Call `SwaggerModule.setup` multiple times, each with a different path and a different `DocumentBuilder` / `SwaggerModule.createDocument` result. Use module filtering and tag grouping to control what appears in each document.

```ts
async function bootstrap() {
  const app = await NestFactory.create(AppModule);

  // ── Public API document ────────────────────────────────────────────
  const publicConfig = new DocumentBuilder()
    .setTitle('MyCompany Public API')
    .setVersion('1.0')
    .addBearerAuth(undefined, 'access-token')
    .build();

  const publicDocument = SwaggerModule.createDocument(app, publicConfig, {
    include: [UsersModule, ProductsModule, OrdersModule],  // only public modules
    // OR: use @ApiTags + filter by tag — only works with custom filtering
  });

  SwaggerModule.setup('docs/public', app, publicDocument, {
    swaggerOptions: { persistAuthorization: true },
  });

  // ── Admin API document ─────────────────────────────────────────────
  const adminConfig = new DocumentBuilder()
    .setTitle('MyCompany Admin API')
    .setVersion('1.0')
    .setDescription('Internal admin endpoints — not publicly accessible')
    .addBearerAuth(undefined, 'admin-token')
    .addApiKey({ type: 'apiKey', in: 'header', name: 'X-Admin-Key' }, 'admin-key')
    .build();

  const adminDocument = SwaggerModule.createDocument(app, adminConfig, {
    include: [AdminModule, UsersModule, AnalyticsModule, AuditModule],
  });

  SwaggerModule.setup('docs/admin', app, adminDocument);

  // ── Internal / Developer document (all endpoints) ─────────────────
  const internalConfig = new DocumentBuilder()
    .setTitle('MyCompany Internal API (All Endpoints)')
    .setVersion('1.0')
    .addBearerAuth(undefined, 'access-token')
    .build();

  const internalDocument = SwaggerModule.createDocument(app, internalConfig);
  // No `include` → documents everything

  // Protect the internal docs endpoint:
  app.use('docs/internal', basicAuth({ users: { dev: 'secret' } }));
  SwaggerModule.setup('docs/internal', app, internalDocument);

  await app.listen(3000);
  // Public docs:   http://localhost:3000/docs/public
  // Admin docs:    http://localhost:3000/docs/admin
  // Internal docs: http://localhost:3000/docs/internal (basic auth protected)
}
```

**Q13. "A developer added `@ApiProperty` to all their DTO fields but Swagger still shows an empty schema. What are all the causes?"**
A: Several common reasons cause Swagger to show empty schemas despite correct-looking decorator usage:

```ts
// Cause 1: Using PartialType/PickType/OmitType from @nestjs/mapped-types:
import { PartialType } from '@nestjs/mapped-types';       // ← WRONG for Swagger
import { PartialType } from '@nestjs/swagger';            // ← CORRECT

// Cause 2: Returning an interface instead of a class from the route:
interface UserData { name: string; email: string; } // ← interface has no runtime metadata
// Fix: use a class with @ApiProperty decorators — interfaces are erased by TypeScript

// Cause 3: @ApiResponse type pointing to a plain object / interface:
@ApiOkResponse({ type: UserData })      // interface — no schema registered
// Fix: @ApiOkResponse({ type: UserResponseDto }) where UserResponseDto is a class

// Cause 4: Circular references without arrow functions:
@ApiProperty({ type: AddressDto })       // ← AddressDto undefined at decoration time
// Fix: @ApiProperty({ type: () => AddressDto })

// Cause 5: Forgetting to set `type` for arrays:
@ApiProperty({ isArray: true })          // isArray with no type → schema is missing element type
// Fix: @ApiProperty({ type: UserDto, isArray: true })
//   or: @ApiProperty({ type: () => [UserDto] })

// Cause 6: Not registering extra models used only inside oneOf/anyOf:
@ApiProperty({ oneOf: [{ $ref: getSchemaPath(DogDto) }] })
// DogDto is never used as a route param/body type → schema not auto-registered
// Fix: @ApiExtraModels(DogDto) on the controller or add to SwaggerModule.createDocument extraModels

// Cause 7: CLI plugin configured but rebuilding hasn't run:
// Plugin only runs during build — the generated metadata is added at compile time
// After changing DTOs: must run: npm run build (or tsc) before swagger reflects changes
// In watch mode: tsc -w picks up changes automatically

// Cause 8: @ApiResponse without a type AND the DTO class has no @ApiProperty decorators:
@ApiOkResponse({ description: 'Success' })  // no type → no schema
// Fix: add type: UserResponseDto AND ensure UserResponseDto has @ApiProperty fields
```

## Problem 3 — Response DTOs with `@Exclude` and `@ApiHideProperty`

### Problem
A `UserEntity` has sensitive fields (`password`, `resetToken`, `twoFactorSecret`). The response DTO strips them with `@Exclude` from class-transformer. Ensure Swagger doesn't document them either, and show only response-appropriate fields.

```ts
// ❌ Problem — @Exclude hides at runtime but Swagger still shows these fields:
export class UserResponseDto {
  @ApiProperty() id: number;
  @ApiProperty() email: string;

  @Exclude()
  @ApiProperty()         // ← Swagger still documents this!
  password: string;

  @Exclude()
  @ApiProperty()
  resetToken: string;
}
```

### Solution: `@ApiHideProperty` + `readOnly` + Response-specific DTOs

```ts
// user-response.dto.ts
export class UserResponseDto {
  @ApiProperty({
    description: 'Unique user identifier',
    example:     42,
    readOnly:    true,   // signals: only in responses, not in request bodies
  })
  id: number;

  @ApiProperty({
    description: 'Display name',
    example:     'Alice Johnson',
    readOnly:    true,
  })
  name: string;

  @ApiProperty({
    description: 'Email address',
    example:     'alice@example.com',
    format:      'email',
    readOnly:    true,
  })
  email: string;

  @ApiProperty({
    enum:     UserRole,
    enumName: 'UserRole',
    readOnly: true,
  })
  role: UserRole;

  @ApiProperty({
    description: 'Account creation timestamp',
    type:        String,
    format:      'date-time',
    readOnly:    true,
    example:     '2024-01-15T09:30:00Z',
  })
  createdAt: Date;

  // ── Sensitive fields — excluded from BOTH Swagger AND runtime response ──

  @ApiHideProperty()   // completely absent from Swagger schema
  @Exclude()           // excluded from class-transformer serialization
  password: string;

  @ApiHideProperty()
  @Exclude()
  resetToken: string;

  @ApiHideProperty()
  @Exclude()
  twoFactorSecret: string;

  @ApiHideProperty()
  @Exclude()
  deletedAt: Date;     // soft-delete timestamp — not exposed to clients

  // ── Conditionally visible field ─────────────────────────────────────
  @ApiPropertyOptional({
    description: 'User profile completion percentage (only included for own-user responses)',
    type:        Number,
    minimum:     0,
    maximum:     100,
    example:     75,
    readOnly:    true,
  })
```

## Problem 4 — Documenting Paginated and Cursor-Based Responses

### Problem
Document two pagination styles used across the API: offset pagination (`PaginatedDto<T>`) for list endpoints and cursor pagination (`CursorPaginatedDto<T>`) for feed endpoints. Both use a generic wrapper that TypeScript generics can't express in Swagger without extra work.

```ts
// ❌ The naive attempt — generic type lost at runtime:
@ApiOkResponse({ type: PaginatedDto })   // type parameter T is lost — Swagger shows PaginatedDto with unknown items
findAll(): Promise<PaginatedDto<UserDto>> { /* ... */ }
```

### Solution: Composite Schema Decorators

```ts
// pagination.dto.ts
export class PaginationMetaDto {
  @ApiProperty({ example: 1,   description: 'Current page number' })
  page: number;

  @ApiProperty({ example: 20,  description: 'Items per page' })
  limit: number;

  @ApiProperty({ example: 150, description: 'Total number of items across all pages' })
  total: number;

  @ApiProperty({ example: 8,   description: 'Total number of pages' })
  totalPages: number;

  @ApiProperty({ example: true,  description: 'Whether a next page exists' })
  hasNextPage: boolean;

  @ApiProperty({ example: false, description: 'Whether a previous page exists' })
  hasPrevPage: boolean;
}

export class PaginatedDto<T> {
  items: T[];    // documented via the generic schema decorator below

// ── Generic response decorator factory ────────────────────────────────
import { applyDecorators, Type } from '@nestjs/common';
import { ApiExtraModels, ApiOkResponse, getSchemaPath } from '@nestjs/swagger';

export const ApiPaginatedResponse = <TModel extends Type<unknown>>(
  model: TModel,
  options?: { description?: string },
) =>
  applyDecorators(
    ApiExtraModels(PaginatedDto, PaginationMetaDto, model),
    ApiOkResponse({
      description: options?.description ?? `Paginated list of ${model.name}`,
      schema: {
        allOf: [
          { $ref: getSchemaPath(PaginatedDto) },
          {
            properties: {
              items: {
                type:  'array',
                items: { $ref: getSchemaPath(model) },
              },
            },
            required: ['items'],
          },
        ],
      },
    }),
  );

export const ApiCursorPaginatedResponse = <TModel extends Type<unknown>>(
  model: TModel,
  options?: { description?: string },
) =>
  applyDecorators(
    ApiExtraModels(CursorPaginatedDto, CursorDto, model),
    ApiOkResponse({
      description: options?.description ?? `Cursor-paginated ${model.name} feed`,
      schema: {
        allOf: [
          { $ref: getSchemaPath(CursorPaginatedDto) },
          {
            properties: {
              items: {
                type:  'array',
                items: { $ref: getSchemaPath(model) },
              },
            },
            required: ['items'],
          },
        ],
      },
    }),
  );
```

```ts
export class CreateProductDto {
  /**
   * @description The product display name
   * @example Wireless Headphones
   */
  @IsString() @MinLength(3) @MaxLength(100)
  name: string;

   * @example 49.99
```

### Step 3: What Still Needs Manual Decoration

```ts
// Cases the plugin CANNOT handle — must add @ApiProperty manually:
export class CreateProductDto {

  // ── CASE 1: Enum types ─────────────────────────────────────────────
  // Plugin knows the type is ProductStatus but can't infer enum values
  @ApiProperty({ enum: ProductStatus, enumName: 'ProductStatus', example: ProductStatus.Active })
  @IsEnum(ProductStatus)
  status: ProductStatus;

  // ── CASE 2: Union / oneOf types ────────────────────────────────────
  // Plugin can't generate oneOf schema from TypeScript union type
  @ApiExtraModels(DigitalProductDto, PhysicalProductDto)
  @ApiProperty({
    oneOf: [
      { $ref: getSchemaPath(DigitalProductDto) },
      { $ref: getSchemaPath(PhysicalProductDto) },
    ],
    discriminator: { propertyName: 'type' },
  })
  @ValidateNested() @Type(() => Object)
  details: DigitalProductDto | PhysicalProductDto;

  // ── CASE 3: Generic / parameterized types ──────────────────────────
  // TypeScript generics are erased — plugin sees only the raw class
  @ApiProperty({ type: () => [TagDto], isArray: true })
  @ValidateNested({ each: true }) @Type(() => TagDto)
  tags: Array<TagDto>;   // or: TagDto[] — both need explicit type

  // ── CASE 4: Dictionary / Record types ──────────────────────────────
  @ApiPropertyOptional({
    description:          'Locale-to-name mapping for i18n',
    type:                 'object',
    additionalProperties: { type: 'string' },
    example:              { en: 'Headphones', es: 'Auriculares' },
  })
  @IsOptional() @IsObject()
  localizedNames?: Record<string, string>;

  // ── CASE 5: Circular / self-referential ────────────────────────────
  @ApiPropertyOptional({ type: () => CategoryDto })  // arrow function required
  @IsOptional() @ValidateNested() @Type(() => CategoryDto)
  parentCategory?: CategoryDto;

  // ── CASE 6: External library types (no class-validator) ────────────
  @ApiProperty({
    type:        String,
    format:      'binary',
    description: 'Product main image file',
  })
  // No class-validator decorator — plugin has nothing to infer from
  image: Express.Multer.File;

  // ── CASE 7: Computed / derived properties ──────────────────────────
  @ApiProperty({
    description: 'Price including tax (read-only, computed server-side)',
    readOnly:    true,
    example:     54.99,
  })
  // Not in request body — only in response
  get priceWithTax(): number {
    return this.price * 1.1;
  }

  // ── CASE 8: Example values with business meaning ────────────────────
  // Plugin can add the type but not business-meaningful example values
  @ApiProperty({
    description: 'ISO 4217 currency code for the product price',
    example:     'USD',
    pattern:     '^[A-Z]{3}$',   // 3 uppercase letters
    minLength:   3,
    maxLength:   3,
  })
  @IsString() @Length(3, 3) @Matches(/^[A-Z]{3}$/)
  currencyCode: string;
  // Plugin: @ApiProperty({ type: String, minLength: 3, maxLength: 3, pattern: '^[A-Z]{3}$' })
  // Manual adds: description and example — worth it for documentation quality
}
```

## Quick Reference — `@nestjs/swagger` Cheat Sheet

```
SETUP (main.ts):
  const config = new DocumentBuilder()
    .setTitle / .setVersion / .setDescription
    .addBearerAuth(scheme, name) / .addApiKey / .addOAuth2
    .addServer / .addTag
    .build()
  const doc = SwaggerModule.createDocument(app, config, { include, extraModels })
  SwaggerModule.setup('docs', app, doc, { swaggerOptions, customCss, ... })

CONTROLLER DECORATORS:
  @ApiTags('name')               → groups controller under a tag in UI
  @ApiBearerAuth('scheme-name')  → marks endpoints as requiring Bearer auth
  @ApiSecurity('scheme')         → generic security decorator
  @ApiExcludeController()        → hides entire controller from Swagger

METHOD DECORATORS:
  @ApiOperation({ summary, description, deprecated, operationId })
  @ApiParam({ name, type, description, example, required })
  @ApiQuery({ name, type, enum, required, example, description })
  @ApiHeader({ name, description, required })
  @ApiBody({ type, description, examples })
  @ApiConsumes('multipart/form-data')     → request content type
  @ApiProduces('application/pdf')         → response content type
  @ApiExcludeEndpoint()                   → hide one endpoint

RESPONSE DECORATORS (shorthand):
  @ApiOkResponse({ type, description, isArray, headers })        → 200
  @ApiCreatedResponse({ type, description })                     → 201
  @ApiNoContentResponse                                          → 204
  @ApiBadRequestResponse({ description })                        → 400
  @ApiUnauthorizedResponse({ description })                      → 401
  @ApiForbiddenResponse({ description })                         → 403
  @ApiNotFoundResponse({ description })                          → 404
  @ApiConflictResponse({ description })                          → 409
  @ApiTooManyRequestsResponse({ description })                   → 429
  @ApiInternalServerErrorResponse({ description })               → 500

DTO DECORATORS:
  @ApiProperty({ type, description, example, required, nullable,
                 enum, enumName, isArray, format, readOnly, writeOnly,
                 minimum, maximum, minLength, maxLength, pattern,
                 oneOf, anyOf, allOf, schema })
  @ApiPropertyOptional(...)   → shorthand for required: false
  @ApiHideProperty()          → exclude from schema entirely

GENERIC TYPES pattern:
  @ApiExtraModels(WrapperDto, ItemDto)          → register schemas
  schema: { allOf: [
    { $ref: getSchemaPath(WrapperDto) },
    { properties: { items: { $ref: getSchemaPath(ItemDto) } } }
  ]}

MAPPED TYPES (import from @nestjs/swagger, NOT @nestjs/mapped-types):
  PartialType(Dto)            → all fields optional + all @ApiProperty preserved
  PickType(Dto, ['a','b'])    → only selected fields
  OmitType(Dto, ['a','b'])    → all except selected
  IntersectionType(A, B)      → all fields from both

CLI PLUGIN (nest-cli.json plugins):
  Infers from: TypeScript types + class-validator decorators + JSDoc comments
  Still needs manual @ApiProperty for: enums, oneOf, Record<>, circular refs,
                                       business-meaningful examples and descriptions

COMMON BUGS:
  Empty schema           → PartialType from @nestjs/mapped-types (wrong package)
  Missing $ref           → class used in oneOf not in @ApiExtraModels
  Circular ref error     → use type: () => ClassName (arrow function)
  Enum shows as string   → add enumName to generate named schema component
  isArray with no type   → always pair isArray: true with type: TheClass
  No schema in response  → returned type is interface (not class) or missing @ApiProperty
  Auth button does nothing → scheme name in @ApiBearerAuth('X') ≠ name in addBearerAuth('X')
  tryItOut fails in prod → CORS not allowing swagger-ui origin; add swagger URL to CORS allowlist
  Plugin not reflecting  → must rebuild (tsc / npm run build) after changing DTOs

PRODUCTION CONSIDERATIONS:
  Disable tryItOutEnabled: true in production (prevents accidental prod calls from docs UI)
  Hide docs behind auth: app.use('/docs', basicAuth(...)) or restrict by IP
  Multiple documents: call SwaggerModule.setup multiple times with different paths
  JSON endpoint: jsonDocumentUrl option → use for SDK generation (openapi-generator)
  Versioned docs: one document per version with include: [V1Module] / [V2Module]
```

**Final Tip:** At the 5 YOE level, `@nestjs/swagger` questions test whether you understand the distinction between **what NestJS reflects at runtime** versus **what TypeScript knows at compile time** — the fundamental constraint that shapes every documentation pattern. The highest-signal answer on generic responses: "TypeScript generics are erased at runtime — `PaginatedDto<UserDto>` becomes just `PaginatedDto` at runtime, so NestJS can't introspect `T`. The fix is the `allOf` pattern: register both schemas with `@ApiExtraModels`, then describe the composite schema manually as `allOf: [{ $ref: PaginatedDto }, { properties: { items: { $ref: UserDto } } }]`. I wrap this in a custom `@ApiPaginatedResponse(UserDto)` decorator so it stays one line per endpoint." For mapped types: "The single most common Swagger bug I've seen is importing `PartialType` from `@nestjs/mapped-types` instead of `@nestjs/swagger`. `@nestjs/mapped-types` only copies class-validator metadata — it doesn't touch OpenAPI metadata, so the Swagger schema is completely empty for every mapped type. The fix is changing one import path." For the CLI plugin: "The plugin eliminates the tedious one-to-one mapping between class-validator decorators and `@ApiProperty` options — `@IsString() @MinLength(2)` automatically becomes `{ type: String, minLength: 2 }` in the schema. But it can't infer enum values, union types, or business context. I use it for structural properties and add manual `@ApiProperty` for enums, `oneOf`, and any property where the example or description has real documentation value for API consumers."
