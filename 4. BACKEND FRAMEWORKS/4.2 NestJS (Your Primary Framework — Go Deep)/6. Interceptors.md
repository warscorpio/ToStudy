# NestJS Interceptors: `NestInterceptor`, RxJS, Response Transformation, Logging, Caching — Interview Q&A (5 YOE Level)

---

## Section 1: Fundamentals

**Q1. What is a NestJS interceptor and where does it sit in the request/response lifecycle?**

A: An interceptor is a class implementing `NestInterceptor` that wraps around a route handler — it runs code both before and after the handler executes. This is the key distinction from middleware (which only runs before) and filters (which only run on errors). Interceptors use RxJS Observables to express this two-phase, wrap-around behaviour:

```
Request lifecycle (with interceptors):

  Incoming Request
       │
       ▼
  Middleware (app.use)          ← before only
       │
       ▼
  Guards (canActivate)          ← before only, throws on rejection
       │
       ▼
  Interceptors (before phase)   ← BEFORE handler
       │
       ▼
  Pipes (transform/validate)    ← before handler, per-param
       │
       ▼
  Route Handler                 ← executes business logic
       │
       ▼
  Interceptors (after phase)    ← AFTER handler (wraps the Observable)
       │
       ▼
  Exception Filters             ← only on errors thrown downstream
       │
       ▼
  Response sent to client
```

The interceptor's two-phase structure in code:

```typescript
import {
    Injectable, NestInterceptor,
    ExecutionContext, CallHandler,
} from '@nestjs/common';
import { Observable } from 'rxjs';
import { tap } from 'rxjs/operators';

@Injectable()
export class LifecycleInterceptor implements NestInterceptor {
    intercept(context: ExecutionContext, next: CallHandler): Observable<any> {

        // ── BEFORE PHASE ──────────────────────────────────────────────
        // Runs synchronously before the handler is called.
        // You have access to the request, can read/mutate headers, check context.
        console.log('Before handler');

        // next.handle() invokes the route handler and returns an Observable
        // that emits the handler's return value (the response body).
        return next.handle().pipe(

            // ── AFTER PHASE ───────────────────────────────────────────
            // The pipe() operators run after the handler returns.
            // tap() is a side-effect operator — lets you observe without transforming.
            tap(responseData => {
                console.log('After handler, response:', responseData);
            }),
        );
    }
}
```

What `NestInterceptor` requires:

```typescript
// The interface definition:
export interface NestInterceptor<T = any, R = any> {
    intercept(
        context: ExecutionContext,  // HTTP context: request, response, handler metadata
        next: CallHandler<T>,      // Gateway to the route handler — call next.handle() to proceed
    ): Observable<R> | Promise<Observable<R>>;
    // Must return an Observable — this IS the response stream
    // If you don't call next.handle(), the route handler never executes
}

// The two generic parameters:
// T = the type the route handler returns (input to your interceptor)
// R = the type your interceptor emits (what the client receives)
// Commonly written as NestInterceptor<any, any> — type-checking the full chain is complex
```

**Q2. What is `ExecutionContext` and `CallHandler` — what can you access from each?**

A: These two parameters give the interceptor everything it needs to inspect the request and control execution:

```typescript
import { ExecutionContext, CallHandler } from '@nestjs/common';
import { Observable } from 'rxjs';

@Injectable()
export class ContextAwareInterceptor implements NestInterceptor {
    intercept(context: ExecutionContext, next: CallHandler): Observable<any> {

        // ── ExecutionContext ──────────────────────────────────────────────
        // Abstraction over the underlying transport (HTTP, WebSocket, gRPC, etc.)

        // For HTTP (Express adapter):
        const request  = context.switchToHttp().getRequest<Request>();
        const response = context.switchToHttp().getResponse<Response>();

        // Common request properties:
        const method     = request.method;         // 'GET', 'POST', etc.
        const url        = request.url;            // '/users/42?active=true'
        const path       = request.path;           // '/users/42'
        const body       = request.body;           // Parsed request body
        const headers    = request.headers;        // All request headers
        const params     = request.params;         // Route params: { id: '42' }
        const query      = request.query;          // Query string: { active: 'true' }
        const ip         = request.ip;             // Client IP
        const user       = (request as any).user;  // Attached by auth guard

        // Handler and class metadata:
        const handler    = context.getHandler();   // The route handler method itself
        const controller = context.getClass();     // The controller class

        // Read custom metadata set by decorators:
        import { Reflector } from '@nestjs/core';
        // (Reflector injected via constructor — see Q6 example)
        // const roles = this.reflector.get<string[]>('roles', handler);

        // ── CallHandler ───────────────────────────────────────────────────
        // The gateway to the next step in the pipeline (route handler or next interceptor).
        // next.handle() returns an Observable<T> where T is the handler's return type.
        // You MUST return an Observable from intercept() — that Observable IS the response.

        // Option 1: proceed normally
        return next.handle();

        // Option 2: wrap the observable with operators
        return next.handle().pipe(
            // ... RxJS operators
        );

        // Option 3: short-circuit — don't call next.handle() at all
        // The handler never executes. Useful for caching:
        // const cached = this.cache.get(cacheKey);
        // if (cached) return of(cached);  ← of() creates an Observable from a value
        // return next.handle();

        // Option 4: run async code before calling next.handle()
        // You can await things before returning:
        // const startTime = Date.now();
        // await this.rateLimiter.check(request.ip);  // throws if rate limit exceeded
        // return next.handle();
    }
}
```

## Section 2: RxJS in Interceptors

**Q3. Why does NestJS use RxJS Observables in interceptors — what operators do you actually need to know?**

A: NestJS uses Observables because the `CallHandler.handle()` abstraction must work across multiple transports (HTTP, WebSocket, gRPC) where a handler might emit one value, many values, or stream values over time. For typical HTTP interceptors you only need a small subset of RxJS:

```typescript
import { map, tap, catchError, timeout, switchMap, of, throwError } from 'rxjs';
import { TimeoutError } from 'rxjs';

// ── map() ─────────────────────────────────────────────────────────────────────
// Transform the response value. Most common operator in response-shaping interceptors.
return next.handle().pipe(
    map(data => ({
        success: true,
        data,
        timestamp: new Date().toISOString(),
    })),
);
// Handler returns: { id: 1, name: 'Alice' }
// Client receives: { success: true, data: { id: 1, name: 'Alice' }, timestamp: '...' }

// ── tap() ─────────────────────────────────────────────────────────────────────
// Side effects without transforming the value. Used for logging, metrics, audit trails.
return next.handle().pipe(
    tap({
        next: (data) => logger.log('Handler succeeded', data),
        error: (err)  => logger.error('Handler threw', err),
        complete: ()  => logger.log('Stream complete'),
    }),
);

// ── catchError() ──────────────────────────────────────────────────────────────
// Intercept errors from the handler. Transform or re-throw.
import { catchError, throwError } from 'rxjs';
import { BadGatewayException } from '@nestjs/common';

return next.handle().pipe(
    catchError(err => {
        if (err.code === 'ECONNREFUSED') {
            // Transform infrastructure error to a clean HTTP error:
            return throwError(() => new BadGatewayException('Upstream service unavailable'));
        }
        return throwError(() => err); // Re-throw unchanged
    }),
);

// ── timeout() ─────────────────────────────────────────────────────────────────
// Emit a TimeoutError if the Observable doesn't complete within N milliseconds.
import { timeout, catchError } from 'rxjs';
import { RequestTimeoutException, TimeoutError } from '@nestjs/common';

return next.handle().pipe(
    timeout(5000),
    catchError(err => {
        if (err instanceof TimeoutError) {
            return throwError(() => new RequestTimeoutException('Handler timed out'));
        }
        return throwError(() => err);
    }),
);

// ── switchMap() ───────────────────────────────────────────────────────────────
// Replace the Observable with another Observable — used when the after-phase
// needs to make async calls based on the handler's result.
return next.handle().pipe(
    switchMap(async (data) => {
        await this.auditLog.record(data); // Async operation in after-phase
        return data;                       // Pass the original data through
    }),
);

// ── of() ──────────────────────────────────────────────────────────────────────
// Create an Observable that emits a single value immediately.
// Used to short-circuit and return a cached value without calling next.handle():
import { of } from 'rxjs';

const cached = await this.cache.get(key);
if (cached) {
    return of(cached); // Returns cached value — handler never runs
}
return next.handle();

// ── finalize() ────────────────────────────────────────────────────────────────
// Runs after Observable completes OR errors — like a finally block.
// Perfect for cleanup and timing measurements:
import { finalize } from 'rxjs/operators';

const startTime = Date.now();
return next.handle().pipe(
    finalize(() => {
        const duration = Date.now() - startTime;
        this.metrics.recordLatency(duration); // Runs whether handler succeeds or throws
    }),
);
```

## Section 3: Applying Interceptors

**Q4. How do you apply interceptors — what are the differences between `@UseInterceptors`, controller-level, and global application?**

A: Interceptors can be applied at four scopes, each with different reach. Narrower scopes override broader ones:

```typescript
import {
    UseInterceptors, Controller, Get,
    NestInterceptor, ExecutionContext, CallHandler,
} from '@nestjs/common';
import { Observable } from 'rxjs';
import { map } from 'rxjs/operators';

// ── Scope 1: Global — all routes in the application ───────────────────────────
// In main.ts:
async function bootstrap() {
    const app = await NestFactory.create(AppModule);

    // Option A: instance (no DI — cannot inject services):
    app.useGlobalInterceptors(new LoggingInterceptor());

    // Option B: via module (DI works — can inject services):
    // Use APP_INTERCEPTOR token in AppModule providers (see below)

    await app.listen(3000);
}

// Preferred global registration (DI-aware):
import { APP_INTERCEPTOR } from '@nestjs/core';
@Module({
    providers: [
        { provide: APP_INTERCEPTOR, useClass: LoggingInterceptor },
        { provide: APP_INTERCEPTOR, useClass: TransformInterceptor },
        // Multiple APP_INTERCEPTOR entries — all are applied in order
    ],
})
export class AppModule {}

// ── Scope 2: Controller — all routes in one controller ────────────────────────
@Controller('users')
@UseInterceptors(LoggingInterceptor, TransformInterceptor)
// Multiple interceptors: applied in order left-to-right for before phase,
// right-to-left for after phase (like middleware stack)
export class UserController {}

// ── Scope 3: Route handler — one specific endpoint ────────────────────────────
@Controller('users')
export class UserController {
    @Get(':id')
    @UseInterceptors(CacheInterceptor) // Only this route gets caching
    findOne(@Param('id') id: string) {
        return this.userService.findById(id);
    }
}

// ── Scope 4: Passing an instance with options ─────────────────────────────────
// When the interceptor needs configuration at the point of use:
@Get('report')
@UseInterceptors(new TimeoutInterceptor(10_000)) // 10-second timeout for this route
generateReport() { ... }

// Execution order for multiple interceptors:
// @UseInterceptors(A, B, C) — before phase: A → B → C → handler
//                           — after phase:  handler → C → B → A (reverse)
// Same as middleware: outermost interceptor wraps everything
```

## Section 4: Common Interceptor Patterns

**Q5. How do you implement a response transformation interceptor that wraps every response in a standard envelope?**

A: Response transformation is the most common interceptor use case in production APIs. It ensures every endpoint returns a consistent shape without modifying individual handlers:

```typescript
import {
    Injectable, NestInterceptor,
    ExecutionContext, CallHandler,
} from '@nestjs/common';
import { Observable } from 'rxjs';
import { map } from 'rxjs/operators';
import { Request } from 'express';

// Standard API response envelope:
export interface ApiResponse<T> {
    success: boolean;
    data: T;
    meta: {
        timestamp: string;
        requestId: string;
        path: string;
        version: string;
    };
}

@Injectable()
export class TransformInterceptor<T>
    implements NestInterceptor<T, ApiResponse<T>>
{
    intercept(
        context: ExecutionContext,
        next: CallHandler<T>,
    ): Observable<ApiResponse<T>> {
        const request = context.switchToHttp().getRequest<Request>();

        return next.handle().pipe(
            map((data): ApiResponse<T> => ({
                success: true,
                data,
                meta: {
                    timestamp: new Date().toISOString(),
                    requestId: (request as any).id ?? 'unknown',
                    path: request.path,
                    version: 'v1',
                },
            })),
        );
    }
}

// Handler before interceptor:
@Get('users')
findAll() {
    return [{ id: 1, name: 'Alice' }, { id: 2, name: 'Bob' }];
}
// Client receives without interceptor:
// [{ id: 1, name: 'Alice' }, { id: 2, name: 'Bob' }]

// Client receives WITH TransformInterceptor:
// {
//   "success": true,
//   "data": [{ "id": 1, "name": "Alice" }, { "id": 2, "name": "Bob" }],
//   "meta": {
//     "timestamp": "2024-01-15T10:30:00.000Z",
//     "requestId": "req-uuid-123",
//     "path": "/users",
//     "version": "v1"
//   }
// }

// Excluding specific routes from transformation using custom metadata:
export const SkipTransform = () => SetMetadata('skipTransform', true);

@Injectable()
export class TransformInterceptor<T> implements NestInterceptor<T, ApiResponse<T> | T> {
    constructor(private readonly reflector: Reflector) {}

    intercept(context: ExecutionContext, next: CallHandler<T>): Observable<any> {
        const skip = this.reflector.getAllAndOverride<boolean>('skipTransform', [
            context.getHandler(),
            context.getClass(),
        ]);

        if (skip) return next.handle(); // Pass through unchanged

        const request = context.switchToHttp().getRequest<Request>();
        return next.handle().pipe(
            map(data => ({
                success: true,
                data,
                meta: { timestamp: new Date().toISOString(), path: request.path },
            })),
        );
    }
}

// Usage:
@Get('download')
@SkipTransform() // This endpoint returns a raw Buffer — skip the envelope
downloadFile() {
    return this.fileService.getBuffer(); // Returned as-is
}
```

**Q6. How do you implement a logging interceptor that captures request details, response time, and handler metadata?**

A: A production logging interceptor combines the before phase (record start time, request details) with the after phase (`finalize` for timing, `tap` for response) and reads handler metadata via the `Reflector`:

```typescript
import {
    Injectable, NestInterceptor,
    ExecutionContext, CallHandler,
    Logger,
} from '@nestjs/common';
import { Reflector } from '@nestjs/core';
import { Observable } from 'rxjs';
import { tap, finalize } from 'rxjs/operators';
import { Request, Response } from 'express';

// Custom decorator to tag sensitive routes:
export const SensitiveRoute = () => SetMetadata('sensitive', true);
export const OperationName   = (name: string) => SetMetadata('operationName', name);

@Injectable()
export class LoggingInterceptor implements NestInterceptor {
    private readonly logger = new Logger(LoggingInterceptor.name);

    constructor(private readonly reflector: Reflector) {}

    intercept(context: ExecutionContext, next: CallHandler): Observable<any> {
        const request  = context.switchToHttp().getRequest<Request>();
        const response = context.switchToHttp().getResponse<Response>();
        const handler  = context.getHandler();
        const ctrl     = context.getClass();

        // Read custom metadata from the handler or controller:
        const isSensitive = this.reflector.getAllAndOverride<boolean>('sensitive', [
            handler, ctrl,
        ]);
        const operationName = this.reflector.getAllAndOverride<string>('operationName', [
            handler, ctrl,
        ]) ?? `${ctrl.name}.${handler.name}`;

        const startTime   = Date.now();
        const requestId   = (request as any).id ?? 'unknown';
        const method      = request.method;
        const url         = request.url;
        const userAgent   = request.headers['user-agent'];
        const userId      = (request as any).user?.id;

        // ── BEFORE: log the incoming request ─────────────────────────
        this.logger.log({
            event: 'request.received',
            requestId,
            operation: operationName,
            method,
            url: isSensitive ? '[REDACTED]' : url,
            userId,
            userAgent,
        });

        return next.handle().pipe(
            // ── AFTER SUCCESS: log response ───────────────────────────
            tap((responseBody) => {
                const duration    = Date.now() - startTime;
                const statusCode  = response.statusCode;
                const bodySize    = JSON.stringify(responseBody)?.length ?? 0;

                this.logger.log({
                    event:       'request.completed',
                    requestId,
                    operation:   operationName,
                    statusCode,
                    durationMs:  duration,
                    responseSizeBytes: bodySize,
                    userId,
                });
            }),

            // ── AFTER ERROR: log failure ──────────────────────────────
            // tap's second arg fires on error (but doesn't catch it)
            tap({
                error: (err) => {
                    const duration = Date.now() - startTime;
                    this.logger.error({
                        event:      'request.failed',
                        requestId,
                        operation:  operationName,
                        durationMs: duration,
                        error: {
                            name:    err.name,
                            message: err.message,
                            status:  err.status,
                        },
                        userId,
                    });
                },
            }),

            // ── finalize: always runs (success OR error) ──────────────
            // Use for metrics emission regardless of outcome:
            finalize(() => {
                const duration = Date.now() - startTime;
                this.metrics?.recordHttpLatency(method, url, duration);
            }),
        );
    }
}

// Registration with DI (so Logger, Reflector, metrics can be injected):
@Module({
    providers: [
        {
            provide: APP_INTERCEPTOR,
            useClass: LoggingInterceptor,
        },
    ],
})
export class AppModule {}

// Usage with custom metadata:
@Controller('payments')
export class PaymentController {
    @Post('charge')
    @SensitiveRoute()          // URL will be [REDACTED] in logs
    @OperationName('charge-card')
    chargeCard(@Body() dto: ChargeDto) { ... }
}
```

**Q7. How do you implement a caching interceptor that short-circuits the handler on cache hit?**

A: The caching pattern is the canonical example of using `of()` to short-circuit `next.handle()`. When there is a cache hit, the handler never executes — the cached value is returned as an Observable directly:

```typescript
import {
    Injectable, NestInterceptor,
    ExecutionContext, CallHandler,
    SetMetadata,
} from '@nestjs/common';
import { Reflector } from '@nestjs/core';
import { Observable, of } from 'rxjs';
import { tap } from 'rxjs/operators';
import { CACHE_MANAGER } from '@nestjs/cache-manager';
import { Cache } from 'cache-manager';
import { Inject } from '@nestjs/common';
import { Request } from 'express';

// Decorator to set per-route TTL:
export const CacheTTL = (ttlSeconds: number) => SetMetadata('cacheTTL', ttlSeconds);
// Decorator to skip caching:
export const NoCache  = () => SetMetadata('noCache', true);

@Injectable()
export class HttpCacheInterceptor implements NestInterceptor {
    constructor(
        @Inject(CACHE_MANAGER) private readonly cacheManager: Cache,
        private readonly reflector: Reflector,
    ) {}

    async intercept(context: ExecutionContext, next: CallHandler): Promise<Observable<any>> {
        const request = context.switchToHttp().getRequest<Request>();

        // Only cache GET requests — POST/PUT/PATCH/DELETE must always hit the handler:
        if (request.method !== 'GET') {
            return next.handle();
        }

        // Check if caching is disabled for this route:
        const noCache = this.reflector.getAllAndOverride<boolean>('noCache', [
            context.getHandler(),
            context.getClass(),
        ]);
        if (noCache) return next.handle();

        // Build cache key from URL + authenticated user (prevent cross-user cache leaks):
        const userId   = (request as any).user?.id ?? 'anonymous';
        const cacheKey = `http:${request.url}:user:${userId}`;

        // ── Cache hit: return cached value, handler never executes ────
        const cached = await this.cacheManager.get<unknown>(cacheKey);
        if (cached !== null && cached !== undefined) {
            return of(cached); // Observable that emits cached value immediately
        }

        // ── Cache miss: run handler, store result ─────────────────────
        const ttlSeconds = this.reflector.getAllAndOverride<number>('cacheTTL', [
            context.getHandler(),
            context.getClass(),
        ]) ?? 60; // Default: 60 seconds

        return next.handle().pipe(
            tap(async (responseData) => {
                // Store in cache after the handler returns successfully:
                await this.cacheManager.set(cacheKey, responseData, ttlSeconds * 1000);
                // Note: cache-manager v5 uses milliseconds, v4 uses seconds — check your version
            }),
        );
    }
}

// Usage on controllers and routes:
@Controller('products')
export class ProductController {
    @Get()
    @CacheTTL(300)         // Cache product list for 5 minutes
    findAll() { ... }

    @Get(':id')
    @CacheTTL(600)         // Cache individual products for 10 minutes
    findOne(@Param('id') id: string) { ... }

    @Post()
    @NoCache()             // POST requests skip caching anyway (method check handles it)
    create(@Body() dto: CreateProductDto) { ... }

    @Get('admin/stats')
    @NoCache()             // Stats are real-time — never cache
    getStats() { ... }
}

// Cache invalidation on mutation — in the service layer or a separate interceptor:
@Injectable()
export class CacheInvalidationInterceptor implements NestInterceptor {
    constructor(
        @Inject(CACHE_MANAGER) private readonly cache: Cache,
        private readonly reflector: Reflector,
    ) {}

    async intercept(context: ExecutionContext, next: CallHandler): Promise<Observable<any>> {
        return next.handle().pipe(
            tap(async () => {
                const patterns = this.reflector.get<string[]>(
                    'invalidateCache',
                    context.getHandler(),
                );
                if (patterns?.length) {
                    await Promise.all(patterns.map(key => this.cache.del(key)));
                }
            }),
        );
    }
}

// Custom decorator for cache invalidation:
export const InvalidateCache = (...keys: string[]) => SetMetadata('invalidateCache', keys);

@Put(':id')
@InvalidateCache('http:/products', 'http:/products/:id')
update(@Param('id') id: string, @Body() dto: UpdateProductDto) { ... }
```

**Q8. How do you implement a timeout interceptor and why is it important for production APIs?**

A: Without timeouts, a slow dependency (database, external API) can hold a connection open indefinitely, exhausting the thread pool or event loop and causing a cascading failure. A timeout interceptor imposes a deadline on every request:

```typescript
import {
    Injectable, NestInterceptor,
    ExecutionContext, CallHandler,
    RequestTimeoutException,
    SetMetadata,
} from '@nestjs/common';
import { Reflector } from '@nestjs/core';
import { Observable, throwError, TimeoutError } from 'rxjs';
import { timeout, catchError } from 'rxjs/operators';

// Decorator to override default timeout per route:
export const Timeout = (ms: number) => SetMetadata('timeout', ms);

const DEFAULT_TIMEOUT_MS = 5_000; // 5 seconds for all routes

@Injectable()
export class TimeoutInterceptor implements NestInterceptor {
    constructor(private readonly reflector: Reflector) {}

    intercept(context: ExecutionContext, next: CallHandler): Observable<any> {
        // Allow per-handler override:
        const timeoutMs = this.reflector.getAllAndOverride<number>('timeout', [
            context.getHandler(),
            context.getClass(),
        ]) ?? DEFAULT_TIMEOUT_MS;

        return next.handle().pipe(
            timeout(timeoutMs),
            catchError(err => {
                if (err instanceof TimeoutError) {
                    const request = context.switchToHttp().getRequest();
                    return throwError(() => new RequestTimeoutException(
                        `Request to ${request.method} ${request.path} ` +
                        `timed out after ${timeoutMs}ms`,
                    ));
                }
                return throwError(() => err); // Re-throw non-timeout errors unchanged
            }),
        );
    }
}

// Route-level timeout overrides:
@Controller('reports')
export class ReportController {
    // Default 5s timeout for all routes in this controller...

    @Get('summary')
    getSummary() { ... } // Uses default 5s

    @Get('full')
    @Timeout(30_000)     // Heavy report — 30-second timeout
    getFullReport() { ... }

    @Get('health')
    @Timeout(500)        // Health check must be fast — 500ms timeout
    healthCheck() { ... }
}

// The timeout operator emits a TimeoutError if the Observable does not
// emit (or complete) within the specified duration.
// For HTTP: "not emitting" means the route handler has not returned.
// This covers: slow DB queries, hanging HTTP calls to external services,
//              CPU-intensive synchronous operations, deadlocks.
```

## Section 5: Advanced Patterns

**Q9. How do you implement an audit logging interceptor that writes to a database — including async operations in the after phase?**

A: Database writes in the after phase require async operations inside the pipe. The `switchMap` or `tap` operators can accommodate this, but with important caveats about error handling:

```typescript
import {
    Injectable, NestInterceptor,
    ExecutionContext, CallHandler,
} from '@nestjs/common';
import { Observable } from 'rxjs';
import { switchMap, tap, catchError } from 'rxjs/operators';
import { Request } from 'express';
import { AuditLogService } from './audit-log.service';

export interface AuditEntry {
    userId:     string;
    action:     string;
    resource:   string;
    resourceId: string | null;
    outcome:    'success' | 'failure';
    metadata:   Record<string, unknown>;
    timestamp:  Date;
}

@Injectable()
export class AuditInterceptor implements NestInterceptor {
    constructor(private readonly auditLog: AuditLogService) {}

    intercept(context: ExecutionContext, next: CallHandler): Observable<any> {
        const request    = context.switchToHttp().getRequest<Request>();
        const handler    = context.getHandler();
        const user       = (request as any).user;

        if (!user) return next.handle(); // Don't audit unauthenticated requests

        const action     = `${request.method} ${request.path}`;
        const resourceId = request.params.id ?? null;
        const startTime  = Date.now();

        return next.handle().pipe(
            // ── On success: write audit log AFTER handler completes ───
            switchMap(async (responseData) => {
                // switchMap replaces the Observable with a new one (async):
                try {
                    await this.auditLog.write({
                        userId:     user.id,
                        action,
                        resource:   request.path.split('/')[1] ?? 'unknown',
                        resourceId,
                        outcome:    'success',
                        metadata: {
                            durationMs:  Date.now() - startTime,
                            statusCode:  200,
                        },
                        timestamp: new Date(),
                    });
                } catch (auditErr) {
                    // IMPORTANT: audit log failure must NOT fail the request.
                    // The user already received their response — silently log the failure:
                    console.error('Audit log write failed:', auditErr);
                }
                return responseData; // Pass the original response through
            }),

            // ── On error: audit the failure ───────────────────────────
            catchError(err => {
                // Fire-and-forget audit of the error:
                this.auditLog.write({
                    userId:     user.id,
                    action,
                    resource:   request.path.split('/')[1] ?? 'unknown',
                    resourceId,
                    outcome:    'failure',
                    metadata: {
                        durationMs: Date.now() - startTime,
                        error: { name: err.name, message: err.message, status: err.status },
                    },
                    timestamp: new Date(),
                }).catch(auditErr => console.error('Audit log write failed:', auditErr));

                // Re-throw the original error so it propagates normally:
                return throwError(() => err);
            }),
        );
    }
}

// Why switchMap instead of tap for async writes:
// tap() starts the async operation but doesn't wait for it — the response
// is sent to the client before the DB write completes (fire-and-forget).
// switchMap() awaits the async operation before emitting, so you can
// guarantee the audit log is written before the response is finalised.
// Choose tap() for non-critical side effects, switchMap() when ordering matters.
```

**Q10. How do you use interceptors for rate limiting and circuit breaking?**

A: Interceptors can implement cross-cutting throttling and resilience patterns that apply across all routes without modifying individual handlers:

```typescript
import {
    Injectable, NestInterceptor,
    ExecutionContext, CallHandler,
    HttpException, HttpStatus,
    ServiceUnavailableException,
} from '@nestjs/common';
import { Observable, throwError } from 'rxjs';
import { catchError, tap } from 'rxjs/operators';
import { Request } from 'express';

// ── Per-user rate limiting interceptor ───────────────────────────────────────
@Injectable()
export class RateLimitInterceptor implements NestInterceptor {
    // Simple in-memory window (use Redis for multi-instance production):
    private readonly windows = new Map<string, { count: number; resetAt: number }>();
    private readonly limit   = 100;   // 100 requests
    private readonly windowMs = 60_000; // per 60 seconds

    async intercept(context: ExecutionContext, next: CallHandler): Promise<Observable<any>> {
        const request = context.switchToHttp().getRequest<Request>();
        const key     = (request as any).user?.id ?? request.ip;
        const now     = Date.now();

        const window  = this.windows.get(key);

        if (!window || window.resetAt < now) {
            // New window:
            this.windows.set(key, { count: 1, resetAt: now + this.windowMs });
        } else if (window.count >= this.limit) {
            // Limit exceeded:
            const retryAfter = Math.ceil((window.resetAt - now) / 1000);
            const response   = context.switchToHttp().getResponse();
            response.setHeader('Retry-After', retryAfter);
            response.setHeader('X-RateLimit-Limit', this.limit);
            response.setHeader('X-RateLimit-Remaining', 0);
            throw new HttpException('Too Many Requests', HttpStatus.TOO_MANY_REQUESTS);
        } else {
            window.count++;
            const response = context.switchToHttp().getResponse();
            response.setHeader('X-RateLimit-Limit', this.limit);
            response.setHeader('X-RateLimit-Remaining', this.limit - window.count);
        }

        return next.handle();
    }
}

// ── Circuit breaker interceptor ───────────────────────────────────────────────
// Open circuit after N consecutive failures — stops calling the handler
// until a cooldown period elapses.
enum CircuitState { CLOSED, OPEN, HALF_OPEN }

@Injectable()
export class CircuitBreakerInterceptor implements NestInterceptor {
    private state          = CircuitState.CLOSED;
    private failureCount   = 0;
    private lastFailure    = 0;
    private readonly failureThreshold = 5;
    private readonly cooldownMs       = 30_000; // 30 seconds

    intercept(context: ExecutionContext, next: CallHandler): Observable<any> {
        const now = Date.now();

        // Check if cooldown period has elapsed (OPEN → HALF_OPEN):
        if (this.state === CircuitState.OPEN) {
            if (now - this.lastFailure > this.cooldownMs) {
                this.state = CircuitState.HALF_OPEN; // Allow one probe request
            } else {
                return throwError(() => new ServiceUnavailableException(
                    'Service temporarily unavailable — circuit open',
                ));
            }
        }

        return next.handle().pipe(
            tap(() => {
                // Success: reset circuit
                this.failureCount = 0;
                if (this.state === CircuitState.HALF_OPEN) {
                    this.state = CircuitState.CLOSED;
                }
            }),
            catchError(err => {
                this.failureCount++;
                this.lastFailure = Date.now();

                if (this.failureCount >= this.failureThreshold) {
                    this.state = CircuitState.OPEN;
                }

                return throwError(() => err);
            }),
        );
    }
}

// In production: use a library like `opossum` for production-grade circuit breaking,
// or Resilience4j patterns. The above illustrates the interceptor integration point.
```

**Q11. How do you implement an interceptor that serialises response data using class-transformer `plainToInstance`?**

A: NestJS's built-in `ClassSerializerInterceptor` uses `class-transformer` to apply `@Exclude()` and `@Expose()` decorators on response DTOs. Understanding how it works (and how to extend it) is essential for secure API design:

```typescript
import {
    Injectable, NestInterceptor,
    ExecutionContext, CallHandler,
    UseInterceptors, SerializeOptions,
} from '@nestjs/common';
import { ClassSerializerInterceptor, plainToInstance } from '@nestjs/common';
import { Exclude, Expose, Type } from 'class-transformer';
import { Observable } from 'rxjs';
import { map } from 'rxjs/operators';

// ── Response DTO with class-transformer decorators ────────────────────────────
export class UserResponseDto {
    @Expose()
    id: number;

    @Expose()
    email: string;

    @Expose()
    name: string;

    @Exclude()              // ← Never sent to the client
    password: string;

    @Exclude()              // ← Never sent to the client
    refreshToken: string;

    @Expose()
    @Type(() => Date)       // ← Ensure Date is serialised correctly
    createdAt: Date;
}

// ── Using NestJS built-in ClassSerializerInterceptor ──────────────────────────
@Controller('users')
@UseInterceptors(ClassSerializerInterceptor)
@SerializeOptions({
    strategy: 'excludeAll',    // Only @Expose() fields are included
    // Alternative: 'exposeAll' — all fields included unless @Exclude()
    excludeExtraneousValues: true,
})
export class UserController {
    @Get(':id')
    async findOne(@Param('id', ParseIntPipe) id: number): Promise<UserResponseDto> {
        const user = await this.userService.findById(id); // Returns User entity (has password)
        return plainToInstance(UserResponseDto, user);    // Strips excluded fields
        // ClassSerializerInterceptor then serialises this through class-transformer again
    }
}

// ── Custom serialisation interceptor (more control) ───────────────────────────
@Injectable()
export class SerializeInterceptor<T> implements NestInterceptor {
    constructor(private readonly dto: new (...args: any[]) => T) {}

    intercept(context: ExecutionContext, next: CallHandler): Observable<T | T[]> {
        return next.handle().pipe(
            map(data => {
                // Handle both single objects and arrays:
                if (Array.isArray(data)) {
                    return data.map(item =>
                        plainToInstance(this.dto, item, {
                            excludeExtraneousValues: true,
                            strategy: 'excludeAll',
                        }),
                    ) as T[];
                }
                return plainToInstance(this.dto, data, {
                    excludeExtraneousValues: true,
                    strategy: 'excludeAll',
                }) as T;
            }),
        );
    }
}

// Reusable decorator that bundles interceptor + DTO:
export function Serialize<T>(dto: new (...args: any[]) => T) {
    return UseInterceptors(new SerializeInterceptor(dto));
}

// Usage — clean decorator-based serialisation:
@Controller('users')
export class UserController {
    @Get()
    @Serialize(UserResponseDto)   // Automatically strips password, token etc.
    findAll() {
        return this.userService.findAll(); // Returns User[] with passwords
        // Interceptor transforms to UserResponseDto[] with passwords stripped
    }

    @Get(':id')
    @Serialize(UserResponseDto)
    findOne(@Param('id', ParseIntPipe) id: number) {
        return this.userService.findById(id);
    }
}
```

**Q13. "What's wrong with this interceptor? The response sometimes arrives empty."**

```typescript
@Injectable()
export class AuditInterceptor implements NestInterceptor {
    intercept(context: ExecutionContext, next: CallHandler): Observable<any> {
        return next.handle().pipe(
            tap(async (data) => {
                await this.auditLog.write({ data });
                return data;
            }),
        );
    }
}
```

A: Two bugs — `tap` ignores return values and fire-and-forget async makes the response independent of the audit write:

```typescript
// Bug 1: tap() ignores return values — 'return data' inside tap has no effect.
// tap() is only for side effects. Its return value is discarded.
// The Observable emits the ORIGINAL data regardless of what tap() returns.
// This specific code works by accident — data is passed through, not because of 'return data'.

// Bug 2: async function inside tap() — tap does NOT await the Promise.
// tap((async data => { await auditLog.write(...) })) means:
//   - tap fires the async function
//   - Async function returns a Promise immediately
//   - tap sees a Promise (truthy) — considers side effect "done"
//   - Observable completes, response is sent to client
//   - ... eventually the Promise resolves and DB write happens
// The audit write is fire-and-forget — if it fails, there's no error handling.
// If auditLog.write throws after the response is sent, it becomes an
// UnhandledPromiseRejection.

// The REAL bug causing "sometimes empty response":
// If tap() throws synchronously (not async), the Observable errors and the
// response may be empty depending on whether an error filter catches it.
// With async errors, they propagate inconsistently.

// FIXED: use switchMap for awaited async operations in the after-phase:
@Injectable()
export class AuditInterceptor implements NestInterceptor {
    intercept(context: ExecutionContext, next: CallHandler): Observable<any> {
        return next.handle().pipe(
            switchMap(async (data) => {
                // switchMap awaits the Promise before emitting the next value:
                try {
                    await this.auditLog.write({ data });
                } catch (err) {
                    // Audit failure is non-critical — log but don't fail the request:
                    this.logger.error('Audit write failed', err);
                }
                return data; // In switchMap, return value IS what the Observable emits
            }),
        );
    }
}

// ALTERNATIVELY: use tap for true fire-and-forget (if audit failure is acceptable):
return next.handle().pipe(
    tap((data) => {
        // No async here — call returns a Promise, ignore it explicitly:
        void this.auditLog.write({ data }).catch(err =>
            this.logger.error('Audit write failed', err)
        );
        // 'void' makes the intent explicit: we intentionally ignore this Promise
    }),
);
```

**Q14. "Design a complete interceptor stack for a production NestJS API: logging, transformation, caching, timeout, and serialisation."**

A: Ordering of interceptors matters — the stack is applied in declaration order (before phase) and reverse order (after phase):

```typescript
// The full interceptor stack for a production API.
// Registered globally via APP_INTERCEPTOR in order:

@Module({
    providers: [
        // Order matters: applied top-to-bottom for before phase,
        // bottom-to-top for after phase (like nested middleware).

        // 1. Timeout — outermost: must be first so it wraps EVERYTHING
        //    If timeout fires, no inner interceptor after-phase code runs.
        { provide: APP_INTERCEPTOR, useClass: TimeoutInterceptor },

        // 2. Logging — second: captures total duration including cache check time.
        //    Also captures timeout errors (because it wraps them).
        { provide: APP_INTERCEPTOR, useClass: LoggingInterceptor },

        // 3. Cache — third: if cache hit, handler and inner interceptors don't run.
        //    Response goes: Cache → Logging after → Timeout after.
        //    Transform NOT applied to cached responses (they're already transformed).
        //    (Consider whether you want to cache pre- or post-transform data.)
        { provide: APP_INTERCEPTOR, useClass: HttpCacheInterceptor },

        // 4. Transform — wraps the handler output in the API envelope.
        //    Applied BEFORE cache stores the result, so cache stores enveloped data.
        //    Or apply AFTER cache and store raw data — depends on your caching strategy.
        { provide: APP_INTERCEPTOR, useClass: TransformInterceptor },

        // 5. Serialize — innermost: strips sensitive fields from handler output.
        //    Closest to the handler — sees raw entity/DTO output before transform.
        { provide: APP_INTERCEPTOR, useClass: SerializeInterceptor },
    ],
})
export class AppModule {}

// Request path through the stack:
//
// BEFORE (top to bottom):
//   1. TimeoutInterceptor   — starts 5s timer
//   2. LoggingInterceptor   — records startTime, logs request.received
//   3. HttpCacheInterceptor — checks Redis: HIT → returns cached → skips 4,5, handler
//   4. TransformInterceptor — no before-phase code (pass-through)
//   5. SerializeInterceptor — no before-phase code (pass-through)
//       → HANDLER executes
//
// AFTER (bottom to top):
//   5. SerializeInterceptor — strips @Exclude() fields from entity
//   4. TransformInterceptor — wraps in { success, data, meta } envelope
//   3. HttpCacheInterceptor — stores result in Redis (already enveloped and serialised)
//   2. LoggingInterceptor   — logs request.completed with duration
//   1. TimeoutInterceptor   — cancels timer (if handler completed in time)

// Per-route configuration still works — decorators override global settings:
@Controller('products')
export class ProductController {
    @Get()
    @CacheTTL(300)           // 5-minute cache for product list
    @Timeout(3_000)          // 3-second timeout for this route
    @Serialize(ProductDto)   // Route-level serialisation override
    @SkipTransform()         // Custom response shape — skip the envelope
    findAll() { ... }

    @Post()
    @NoCache()               // Never cache mutations
    @AuditLog('create-product') // Additional audit interceptor via custom metadata
    create(@Body() dto: CreateProductDto) { ... }
}

// Complete module structure for the interceptor stack:
// src/interceptors/
//   interceptors.module.ts    ← registers all APP_INTERCEPTOR providers
//   timeout.interceptor.ts
//   logging.interceptor.ts
//   cache.interceptor.ts
//   transform.interceptor.ts
//   serialize.interceptor.ts
//   audit.interceptor.ts
//   index.ts                  ← barrel exports

@Module({
    providers: [
        { provide: APP_INTERCEPTOR, useClass: TimeoutInterceptor },
        { provide: APP_INTERCEPTOR, useClass: LoggingInterceptor },
        { provide: APP_INTERCEPTOR, useClass: HttpCacheInterceptor },
        { provide: APP_INTERCEPTOR, useClass: TransformInterceptor },
        { provide: APP_INTERCEPTOR, useClass: SerializeInterceptor },
    ],
    exports: [],
})
export class InterceptorsModule {}

// InterceptorsModule imported in AppModule — clean separation:
@Module({
    imports: [
        CoreModule,
        InterceptorsModule,  // ← All interceptors registered here
        // Feature modules...
    ],
})
export class AppModule {}
```

## Quick Reference Table

| Interceptor type | Key operator | `next.handle()` called? | Use case |
|---|---|---|---|
| Logging | `tap`, `finalize` | Yes — always | Request/response logging, metrics |
| Transformation | `map` | Yes — always | Response envelope, field renaming |
| Caching | `of` (on hit), `tap` (on miss) | No (hit) / Yes (miss) | HTTP response caching |
| Timeout | `timeout`, `catchError` | Yes | Request deadline enforcement |
| Serialisation | `map` + `plainToInstance` | Yes — always | Strip sensitive fields |
| Error translation | `catchError` | Yes | Map infra errors to HTTP errors |
| Rate limiting | Guard in before phase | No (if rejected) | Per-user request throttling |
| Audit logging | `switchMap` | Yes — always | Compliance audit trail |
| Circuit breaker | `catchError`, `tap` | No (if open) | Resilience pattern |

| RxJS operator | What it does in interceptors | Returns |
|---|---|---|
| `map(fn)` | Transform emitted value | New value |
| `tap(fn)` | Side effect, pass value through | Same value (fn return ignored) |
| `catchError(fn)` | Handle errors; re-throw or recover | New Observable |
| `finalize(fn)` | Run after complete OR error | Same Observable (passthrough) |
| `timeout(ms)` | Emit TimeoutError if no emission within ms | Same Observable |
| `switchMap(fn)` | Replace Observable with async result | New Observable from fn |
| `of(value)` | Create Observable emitting one value | Observable\<value\> |
| `throwError(fn)` | Create Observable that errors immediately | Observable (error) |

| Scope | How to register | Reaches |
|---|---|---|
| Global | `APP_INTERCEPTOR` in any module's providers | Every route in the app |
| Controller | `@UseInterceptors()` on controller class | All routes in that controller |
| Route | `@UseInterceptors()` on a method | Only that route |
| Instance | `new MyInterceptor(config)` in `@UseInterceptors` | One route, with config |

---

**Tip for interviews:** Six things separate strong candidates on this topic: (1) being precise that **interceptors run both before and after the handler**, unlike middleware (before only) and filters (errors only) — and articulating that `next.handle()` is the dividing line: code before it is the before phase, operators in `.pipe()` are the after phase; (2) knowing that **`tap()` ignores its return value and does not await async functions** — the most common interceptor bug is `tap(async data => { await something(); return data; })` where the await is invisible to the Observable and the return has no effect; `switchMap` is the correct operator when you need to await async operations in the after phase; (3) understanding how to **short-circuit with `of()`** for caching — not calling `next.handle()` means the route handler never executes, and returning `of(cachedValue)` creates an Observable that emits the cached value and completes; (4) knowing that **`finalize()` always runs** whether the Observable completes successfully or errors, making it the right operator for cleanup and timing measurements that must run regardless of outcome; (5) understanding **interceptor execution order** — multiple interceptors applied with `APP_INTERCEPTOR` or `@UseInterceptors(A, B, C)` execute A→B→C for the before phase and C→B→A (reverse) for the after phase, like nested try/finally blocks; and (6) knowing that **`intercept()` can be async** (returning `Promise<Observable<T>>`) which is necessary when the before phase needs to `await` something (like a cache lookup) before deciding whether to call `next.handle()`.
