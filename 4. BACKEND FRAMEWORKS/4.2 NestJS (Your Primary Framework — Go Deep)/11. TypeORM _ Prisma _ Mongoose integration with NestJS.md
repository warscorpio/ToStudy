# TypeORM / Prisma / Mongoose Integration with NestJS — Interview Q&A (5 YOE Level)

---

## Section 1: Fundamentals

**Q1. What are the key architectural differences between TypeORM, Prisma, and Mongoose — and how does each fit into NestJS's DI system?**

A: The three ORMs represent three distinct philosophies. Understanding the philosophy determines which patterns you use and what trade-offs you accept:

```
TypeORM — Active Record / Data Mapper ORM for relational DBs
  Philosophy: Entities are TypeScript classes decorated with column metadata.
              The ORM generates SQL at runtime from those classes.
  Fit with NestJS DI: Repository<Entity> is injected via @InjectRepository(Entity).
  Strength: Deep TypeScript integration, decorators feel natural in NestJS.
  Weakness: Complex queries need QueryBuilder; migrations can be fragile.

Prisma — Schema-first ORM with a generated, type-safe client
  Philosophy: Schema defined in schema.prisma (its own DSL).
              Prisma generates a fully-typed client at build time.
  Fit with NestJS DI: PrismaService extends PrismaClient, registered as a provider.
  Strength: Best-in-class type safety, readable query API, excellent migrations.
  Weakness: Schema DSL is separate from TypeScript; no decorator-based entities.

Mongoose — ODM (Object Document Mapper) for MongoDB
  Philosophy: Schemas define document structure; models wrap collections.
              Documents are semi-structured — schema is flexible.
  Fit with NestJS DI: Models are injected via @InjectModel(ModelName).
  Strength: Natural fit for MongoDB's document model; flexible schema.
  Weakness: JavaScript-era design; type safety requires extra work (interfaces/classes).
```

How each integrates with NestJS's DI container:

```typescript
// ── TypeORM ───────────────────────────────────────────────────────────────────
// App-level: registers the DataSource (connection pool)
TypeOrmModule.forRoot({ type: 'postgres', ... })

// Feature-level: registers Repository<Entity> for injection
TypeOrmModule.forFeature([User, Order])

// Injection:
@Injectable()
class UserService {
    constructor(
        @InjectRepository(User)
        private readonly userRepo: Repository<User>,
    ) {}
}

// ── Prisma ────────────────────────────────────────────────────────────────────
// No separate module — PrismaService is a plain injectable service
@Injectable()
class PrismaService extends PrismaClient implements OnModuleInit {
    async onModuleInit() { await this.$connect(); }
}

// Injection anywhere PrismaService is provided:
@Injectable()
class UserService {
    constructor(private readonly prisma: PrismaService) {}
}

// ── Mongoose ──────────────────────────────────────────────────────────────────
// App-level: registers the MongoDB connection
MongooseModule.forRoot('mongodb://localhost/mydb')

// Feature-level: registers the Model for injection
MongooseModule.forFeature([{ name: User.name, schema: UserSchema }])

// Injection:
@Injectable()
class UserService {
    constructor(
        @InjectModel(User.name)
        private readonly userModel: Model<UserDocument>,
    ) {}
}
```

## Section 2: TypeORM with NestJS

**Q2. How do you set up TypeORM in NestJS — module configuration, entities, and repositories?**

A: TypeORM setup has two layers — root configuration (once, in AppModule) and feature registration (once per domain module):

```typescript
// ── Installation ──────────────────────────────────────────────────────────────
// npm install @nestjs/typeorm typeorm pg
// npm install --save-dev @types/pg

// ── Entity definition ─────────────────────────────────────────────────────────
import {
    Entity, PrimaryGeneratedColumn, Column,
    CreateDateColumn, UpdateDateColumn, DeleteDateColumn,
    ManyToOne, OneToMany, Index, BeforeInsert,
} from 'typeorm';
import * as bcrypt from 'bcrypt';

@Entity('users')                        // Maps to 'users' table
@Index(['email'], { unique: true })     // Unique index on email
export class User {
    @PrimaryGeneratedColumn('uuid')     // UUID primary key
    id: string;

    @Column({ type: 'varchar', length: 255 })
    @Index()                            // Index for search performance
    email: string;

    @Column({ type: 'varchar', length: 100 })
    name: string;

    @Column({ select: false })          // Excluded from SELECT by default
    password: string;

    @Column({
        type: 'enum',
        enum: ['user', 'admin', 'moderator'],
        default: 'user',
    })
    role: 'user' | 'admin' | 'moderator';

    @Column({ type: 'boolean', default: false })
    isVerified: boolean;

    @OneToMany(() => Order, order => order.user)
    orders: Order[];

    @CreateDateColumn()                 // Auto-set on INSERT
    createdAt: Date;

    @UpdateDateColumn()                 // Auto-set on UPDATE
    updatedAt: Date;

    @DeleteDateColumn()                 // Soft delete — null when not deleted
    deletedAt: Date | null;

    @BeforeInsert()
    async hashPassword() {
        if (this.password) {
            this.password = await bcrypt.hash(this.password, 12);
        }
    }
}

@Entity('orders')
export class Order {
    @PrimaryGeneratedColumn('uuid')
    id: string;

    @ManyToOne(() => User, user => user.orders, { onDelete: 'CASCADE' })
    user: User;

    @Column({ type: 'decimal', precision: 10, scale: 2 })
    total: number;

    @Column({ type: 'varchar', default: 'pending' })
    status: string;

    @CreateDateColumn()
    createdAt: Date;
}

// ── Root module configuration (AppModule) ─────────────────────────────────────
import { TypeOrmModule } from '@nestjs/typeorm';
import { ConfigModule, ConfigService } from '@nestjs/config';

@Module({
    imports: [
        ConfigModule.forRoot({ isGlobal: true }),
        TypeOrmModule.forRootAsync({
            // Async form: reads config from ConfigService
            imports: [ConfigModule],
            useFactory: (config: ConfigService) => ({
                type: 'postgres',
                url: config.get<string>('DATABASE_URL'),

                // Entity discovery — avoid typos: use autoLoadEntities
                autoLoadEntities: true,    // Loads entities registered with forFeature()
                // OR explicit list:
                // entities: [User, Order, Product],

                // Migrations:
                migrations: ['dist/migrations/*.js'],
                migrationsRun: false,      // NEVER true in production (run explicitly)

                // Connection pool:
                extra: {
                    max: 20,               // Maximum connections
                    idleTimeoutMillis: 30_000,
                    connectionTimeoutMillis: 2_000,
                },

                // Development only:
                synchronize: config.get('NODE_ENV') === 'development',
                // synchronize: false in production — ALWAYS use migrations
                logging: config.get('NODE_ENV') === 'development',
            }),
            inject: [ConfigService],
        }),
    ],
})
export class AppModule {}

// ── Feature module registration ───────────────────────────────────────────────
@Module({
    imports: [
        TypeOrmModule.forFeature([User, Order]),
        // Makes Repository<User> and Repository<Order> available for injection
    ],
    providers: [UserService, UserRepository],
    controllers: [UserController],
    exports: [UserService],
})
export class UserModule {}
```

**Q3. What are the repository patterns in TypeORM — built-in `Repository<T>` vs custom repositories?**

A: TypeORM provides `Repository<T>` with standard CRUD methods. For complex queries, you create custom repositories that extend it:

```typescript
import {
    Injectable, NotFoundException,
} from '@nestjs/common';
import { InjectRepository } from '@nestjs/typeorm';
import {
    Repository, DataSource, FindOptionsWhere,
    FindManyOptions, ILike, Between, In,
} from 'typeorm';

// ── Using the built-in Repository<T> directly ─────────────────────────────────
@Injectable()
export class UserService {
    constructor(
        @InjectRepository(User)
        private readonly userRepo: Repository<User>,
    ) {}

    // Basic CRUD:
    async findAll(): Promise<User[]> {
        return this.userRepo.find({
            select: { id: true, email: true, name: true, role: true },
            where: { deletedAt: null },  // Exclude soft-deleted (TypeORM handles this with @DeleteDateColumn)
            order: { createdAt: 'DESC' },
        });
    }

    async findById(id: string): Promise<User> {
        const user = await this.userRepo.findOne({
            where: { id },
            relations: { orders: true },  // Load related orders
        });
        if (!user) throw new NotFoundException(`User ${id} not found`);
        return user;
    }

    async findByEmail(email: string): Promise<User | null> {
        return this.userRepo.findOne({
            where: { email },
            select: { id: true, email: true, password: true, role: true },
            // password is 'select: false' on entity — must explicitly request it
        });
    }

    async create(dto: CreateUserDto): Promise<User> {
        const user = this.userRepo.create(dto);   // Creates instance (no DB call)
        return this.userRepo.save(user);           // Inserts to DB
    }

    async update(id: string, dto: UpdateUserDto): Promise<User> {
        await this.userRepo.update(id, dto);       // UPDATE WHERE id = ?
        return this.findById(id);                  // Return updated entity
    }

    async softDelete(id: string): Promise<void> {
        await this.userRepo.softDelete(id);        // Sets deletedAt — row stays
    }

    async hardDelete(id: string): Promise<void> {
        await this.userRepo.delete(id);            // Deletes row permanently
    }

    // Filtering and pagination:
    async findWithFilters(params: {
        search?: string;
        role?: string;
        page?: number;
        limit?: number;
    }): Promise<{ data: User[]; total: number }> {
        const { search, role, page = 1, limit = 20 } = params;

        const where: FindOptionsWhere<User> = {};
        if (role)   where.role = role as any;
        if (search) where.name = ILike(`%${search}%`); // Case-insensitive LIKE

        const [data, total] = await this.userRepo.findAndCount({
            where,
            order:  { createdAt: 'DESC' },
            skip:   (page - 1) * limit,
            take:   limit,
        });

        return { data, total };
    }
}

// ── Custom repository — for complex queries ───────────────────────────────────
@Injectable()
export class UserRepository extends Repository<User> {
    constructor(private readonly dataSource: DataSource) {
        super(User, dataSource.createEntityManager());
    }

    // QueryBuilder for complex joins and conditions:
    async findActiveUsersWithOrderStats(): Promise<UserWithStats[]> {
        return this.createQueryBuilder('user')
            .leftJoin('user.orders', 'order')
            .select([
                'user.id',
                'user.email',
                'user.name',
                'COUNT(order.id)     AS "orderCount"',
                'SUM(order.total)    AS "totalSpent"',
                'MAX(order.createdAt) AS "lastOrderAt"',
            ])
            .where('user.isVerified = :verified', { verified: true })
            .andWhere('user.deletedAt IS NULL')
            .groupBy('user.id')
            .having('COUNT(order.id) > 0')
            .orderBy('"totalSpent"', 'DESC')
            .getRawMany();
    }

    // Bulk upsert:
    async upsertMany(users: Partial<User>[]): Promise<void> {
        await this.createQueryBuilder()
            .insert()
            .into(User)
            .values(users)
            .orUpdate(['name', 'role', 'updatedAt'], ['email'])
            // ON CONFLICT (email) DO UPDATE SET name=..., role=..., updatedAt=...
            .execute();
    }

    // Transaction-aware operations:
    async transferCredits(
        fromId: string,
        toId: string,
        amount: number,
    ): Promise<void> {
        await this.dataSource.transaction(async manager => {
            const userRepo = manager.getRepository(User);
            await userRepo.decrement({ id: fromId }, 'credits', amount);
            await userRepo.increment({ id: toId }, 'credits', amount);
            // Both updates in one transaction — atomic
        });
    }
}
```

**Q4. How do you handle TypeORM migrations in a NestJS project?**

A: Migrations are the production-safe alternative to `synchronize: true`. They represent schema changes as versioned SQL files that can be reviewed, tested, and rolled back:

```typescript
// ── datasource.ts — standalone DataSource for the CLI ────────────────────────
// The CLI needs a DataSource it can import without bootstrapping the NestJS app
import { DataSource } from 'typeorm';
import { config } from 'dotenv';
config(); // Load .env for CLI usage

export const AppDataSource = new DataSource({
    type: 'postgres',
    url: process.env.DATABASE_URL,
    entities:   ['src/**/*.entity.ts'],
    migrations: ['src/migrations/*.ts'],
    // CLI uses ts-node to run TypeScript migrations directly
});

// package.json scripts:
// "migration:generate": "typeorm-ts-node-commonjs migration:generate -d src/datasource.ts"
// "migration:run":      "typeorm-ts-node-commonjs migration:run -d src/datasource.ts"
// "migration:revert":   "typeorm-ts-node-commonjs migration:revert -d src/datasource.ts"
// "migration:show":     "typeorm-ts-node-commonjs migration:show -d src/datasource.ts"

// Generate: npx typeorm-ts-node-commonjs migration:generate src/migrations/AddUserRole -d src/datasource.ts
// TypeORM diffs current schema against entities and generates the migration

// ── Generated migration example ───────────────────────────────────────────────
import { MigrationInterface, QueryRunner } from 'typeorm';

export class AddUserRole1705000000000 implements MigrationInterface {
    name = 'AddUserRole1705000000000';

    async up(queryRunner: QueryRunner): Promise<void> {
        // Enum type must be created before the column:
        await queryRunner.query(
            `CREATE TYPE "public"."users_role_enum" AS ENUM('user', 'admin', 'moderator')`
        );
        await queryRunner.query(
            `ALTER TABLE "users" ADD "role" "public"."users_role_enum" NOT NULL DEFAULT 'user'`
        );
        await queryRunner.query(
            `CREATE INDEX "IDX_users_email" ON "users" ("email")`
        );
    }

    async down(queryRunner: QueryRunner): Promise<void> {
        await queryRunner.query(`DROP INDEX "IDX_users_email"`);
        await queryRunner.query(`ALTER TABLE "users" DROP COLUMN "role"`);
        await queryRunner.query(`DROP TYPE "public"."users_role_enum"`);
    }
}

// ── Running migrations at app startup (optional) ──────────────────────────────
// For containerised deployments, run migrations before the app starts:
@Injectable()
export class MigrationService implements OnModuleInit {
    constructor(
        @InjectDataSource() private readonly dataSource: DataSource,
    ) {}

    async onModuleInit(): Promise<void> {
        if (process.env.RUN_MIGRATIONS === 'true') {
            const pending = await this.dataSource.showMigrations();
            if (pending) {
                await this.dataSource.runMigrations({ transaction: 'all' });
                console.log('Migrations completed');
            }
        }
    }
}
```

## Section 3: Prisma with NestJS

**Q5. How do you set up Prisma in NestJS — schema, PrismaService, and module integration?**

A: Prisma's setup is simpler than TypeORM because there is no `forRoot`/`forFeature` pattern — `PrismaService` is a plain injectable that wraps `PrismaClient`:

```bash
# Installation:
npm install prisma @prisma/client
npx prisma init   # Creates prisma/schema.prisma and .env
```

```prisma
// prisma/schema.prisma

generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

model User {
  id          String    @id @default(uuid())
  email       String    @unique
  name        String
  password    String
  role        Role      @default(USER)
  isVerified  Boolean   @default(false)
  createdAt   DateTime  @default(now())
  updatedAt   DateTime  @updatedAt
  deletedAt   DateTime?             // Soft delete marker
  orders      Order[]
  profile     Profile?

  @@index([email])
  @@map("users")                   // Table name override
}

model Order {
  id        String   @id @default(uuid())
  total     Decimal  @db.Decimal(10, 2)
  status    String   @default("pending")
  createdAt DateTime @default(now())
  userId    String
  user      User     @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@index([userId])
  @@map("orders")
}

model Profile {
  id     String  @id @default(uuid())
  bio    String?
  avatar String?
  userId String  @unique
  user   User    @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@map("profiles")
}

enum Role {
  USER
  ADMIN
  MODERATOR
}
```

```typescript
// ── PrismaService — the central DI provider ───────────────────────────────────
import {
    Injectable, OnModuleInit, OnModuleDestroy, Logger,
} from '@nestjs/common';
import { PrismaClient, Prisma } from '@prisma/client';

@Injectable()
export class PrismaService extends PrismaClient implements OnModuleInit, OnModuleDestroy {
    private readonly logger = new Logger(PrismaService.name);

    constructor() {
        super({
            log: [
                { emit: 'event', level: 'query'  },
                { emit: 'event', level: 'error'  },
                { emit: 'event', level: 'warn'   },
            ],
            errorFormat: 'colorless',
        });
    }

    async onModuleInit(): Promise<void> {
        // Log slow queries:
        (this.$on as any)('query', (event: Prisma.QueryEvent) => {
            if (event.duration > 500) {
                this.logger.warn(`Slow query (${event.duration}ms): ${event.query}`);
            }
        });

        await this.$connect();
        this.logger.log('Prisma connected');
    }

    async onModuleDestroy(): Promise<void> {
        await this.$disconnect();
        this.logger.log('Prisma disconnected');
    }

    // Helper: soft delete (Prisma has no built-in soft delete)
    async softDelete(model: string, id: string): Promise<void> {
        await (this as any)[model].update({
            where: { id },
            data:  { deletedAt: new Date() },
        });
    }

    // Helper: transaction wrapper
    async executeInTransaction<T>(
        fn: (tx: Prisma.TransactionClient) => Promise<T>,
    ): Promise<T> {
        return this.$transaction(fn, {
            maxWait:  5_000,  // Max time to wait for a connection
            timeout:  10_000, // Max transaction duration
            isolationLevel: Prisma.TransactionIsolationLevel.ReadCommitted,
        });
    }
}

// ── PrismaModule — register as a global provider ──────────────────────────────
import { Global, Module } from '@nestjs/common';

@Global()                           // Available in ALL modules without importing
@Module({
    providers: [PrismaService],
    exports:   [PrismaService],
})
export class PrismaModule {}

// ── Feature service — inject PrismaService directly ───────────────────────────
@Injectable()
export class UserService {
    constructor(private readonly prisma: PrismaService) {}

    async findAll(params: {
        skip?: number;
        take?: number;
        where?: Prisma.UserWhereInput;
        orderBy?: Prisma.UserOrderByWithRelationInput;
    }): Promise<User[]> {
        return this.prisma.user.findMany({
            ...params,
            where: {
                ...params.where,
                deletedAt: null,           // Exclude soft-deleted
            },
            select: {
                id:         true,
                email:      true,
                name:       true,
                role:       true,
                isVerified: true,
                createdAt:  true,
                // password excluded — not in select
            },
        });
    }

    async findByIdOrThrow(id: string): Promise<User> {
        return this.prisma.user.findUniqueOrThrow({
            where: { id },
            include: { orders: true, profile: true },
        });
        // findUniqueOrThrow throws Prisma.NotFoundError if not found
    }

    async create(dto: CreateUserDto): Promise<User> {
        const hashedPassword = await bcrypt.hash(dto.password, 12);
        return this.prisma.user.create({
            data: {
                ...dto,
                password: hashedPassword,
                profile: dto.bio ? {
                    create: { bio: dto.bio }, // Nested write — creates profile atomically
                } : undefined,
            },
            select: { id: true, email: true, name: true, role: true },
        });
    }
}
```

**Q6. How do you write complex Prisma queries — relations, aggregations, raw SQL, and transactions?**

A: Prisma's API is designed for composability. Complex queries are built from typed options rather than strings:

```typescript
@Injectable()
export class OrderService {
    constructor(private readonly prisma: PrismaService) {}

    // ── Relations (include vs select) ─────────────────────────────────────────
    async findOrderWithDetails(id: string) {
        return this.prisma.order.findUniqueOrThrow({
            where: { id },
            include: {
                user: {
                    select: { id: true, email: true, name: true },
                    // include loads the full relation; select limits fields
                },
            },
        });
    }

    // ── Filtering with AND/OR/NOT ─────────────────────────────────────────────
    async findPendingHighValueOrders() {
        return this.prisma.order.findMany({
            where: {
                AND: [
                    { status: 'pending'  },
                    { total: { gte: 100 }},         // total >= 100
                    { user: { isVerified: true } },  // related record filter
                    { createdAt: { gte: new Date(Date.now() - 7 * 24 * 3600 * 1000) } },
                ],
            },
            orderBy: { total: 'desc' },
            take:    50,
        });
    }

    // ── Aggregations ──────────────────────────────────────────────────────────
    async getOrderStats() {
        const [count, aggregate] = await this.prisma.$transaction([
            this.prisma.order.count({ where: { status: 'pending' } }),
            this.prisma.order.aggregate({
                _sum:  { total: true },
                _avg:  { total: true },
                _max:  { total: true },
                _min:  { total: true },
                where: { status: { not: 'cancelled' } },
            }),
        ]);

        return {
            pendingCount: count,
            totalRevenue: aggregate._sum.total,
            averageOrder: aggregate._avg.total,
        };
    }

    // ── groupBy ───────────────────────────────────────────────────────────────
    async getRevenueByStatus() {
        return this.prisma.order.groupBy({
            by:    ['status'],
            _sum:  { total: true },
            _count: { id: true },
            orderBy: { _sum: { total: 'desc' } },
        });
    }

    // ── Raw SQL — when Prisma's API isn't expressive enough ───────────────────
    async getMonthlyRevenue(year: number): Promise<{ month: number; revenue: number }[]> {
        // $queryRaw is fully typed with Prisma.sql template literal:
        const result = await this.prisma.$queryRaw<{ month: number; revenue: number }[]>`
            SELECT
                EXTRACT(MONTH FROM created_at)::int AS month,
                SUM(total)::float                   AS revenue
            FROM orders
            WHERE
                EXTRACT(YEAR FROM created_at) = ${year}
                AND status != 'cancelled'
            GROUP BY month
            ORDER BY month
        `;
        // Prisma.sql automatically parameterises ${year} — no SQL injection
        return result;
    }

    // ── Transactions — interactive (not batch) ────────────────────────────────
    async placeOrder(userId: string, items: OrderItem[]): Promise<Order> {
        return this.prisma.$transaction(async (tx) => {
            // All operations inside use the same transaction:

            // 1. Verify user exists and is verified:
            const user = await tx.user.findUniqueOrThrow({
                where: { id: userId, isVerified: true },
            });

            // 2. Check stock for each item:
            for (const item of items) {
                const product = await tx.product.findUniqueOrThrow({
                    where: { id: item.productId },
                });
                if (product.stock < item.quantity) {
                    throw new Error(`Insufficient stock for ${product.name}`);
                    // Throwing inside $transaction rolls back ALL operations above
                }
            }

            // 3. Create the order:
            const total = items.reduce((sum, item) => sum + item.price * item.quantity, 0);
            const order = await tx.order.create({
                data: {
                    userId,
                    total,
                    status: 'pending',
                },
            });

            // 4. Decrement stock (all items):
            await Promise.all(items.map(item =>
                tx.product.update({
                    where: { id: item.productId },
                    data:  { stock: { decrement: item.quantity } },
                })
            ));

            return order;
            // If any step throws, ALL database changes are rolled back
        });
    }
}
```

**Q7. How do you handle Prisma migrations in production?**

A: Prisma Migrate is the first-class migration tool. It generates SQL migration files from schema changes and tracks which have been applied:

```bash
# Development workflow:
npx prisma migrate dev --name add_user_role
# → diffs schema.prisma against current DB
# → generates prisma/migrations/20240115_add_user_role/migration.sql
# → applies the migration
# → regenerates Prisma client

# Preview migration SQL without applying:
npx prisma migrate dev --create-only --name add_index

# Production deployment:
npx prisma migrate deploy
# → applies all pending migrations (does NOT generate new ones)
# → safe for CI/CD: non-destructive unless the migration itself is destructive

# Inspect current migration status:
npx prisma migrate status

# Reset DB (development only — destroys all data):
npx prisma migrate reset
```

```typescript
// ── Running migrations at app startup (for containerised deployments) ─────────
import { execSync } from 'child_process';

@Injectable()
export class MigrationService implements OnModuleInit {
    async onModuleInit(): Promise<void> {
        if (process.env.RUN_MIGRATIONS !== 'true') return;
        execSync('npx prisma migrate deploy', { stdio: 'inherit' });
    }
}

// ── Example generated migration ────────────────────────────────────────────────
// prisma/migrations/20240115000000_add_user_role/migration.sql:
// -- CreateEnum
// CREATE TYPE "Role" AS ENUM ('USER', 'ADMIN', 'MODERATOR');
//
// -- AlterTable
// ALTER TABLE "users" ADD COLUMN "role" "Role" NOT NULL DEFAULT 'USER';
// ALTER TABLE "users" ADD COLUMN "isVerified" BOOLEAN NOT NULL DEFAULT false;
//
// -- CreateIndex
// CREATE INDEX "users_email_idx" ON "users"("email");

// ── Seeding ───────────────────────────────────────────────────────────────────
// prisma/seed.ts:
import { PrismaClient } from '@prisma/client';
const prisma = new PrismaClient();

async function main() {
```

**Q9. How do you write Mongoose queries — CRUD, population, aggregation, and transactions?**

A: Mongoose models provide a rich query API. The key patterns for production usage:

```typescript
import { Injectable, NotFoundException } from '@nestjs/common';
import { InjectModel } from '@nestjs/mongoose';
import { Model, FilterQuery, Types, ClientSession } from 'mongoose';

@Injectable()
export class UserService {
    constructor(
        @InjectModel(User.name) private readonly userModel: Model<UserDocument>,
        @InjectModel(Order.name) private readonly orderModel: Model<OrderDocument>,
        @InjectConnection() private readonly connection: Connection,
    ) {}

    // ── Basic CRUD ─────────────────────────────────────────────────────────────
    async findAll(): Promise<UserDocument[]> {
        return this.userModel
            .find({ deletedAt: null })
            .select('-password')           // Exclude password field
            .sort({ createdAt: -1 })
            .lean()                        // Returns plain JS object (faster, not a Mongoose doc)
            .exec();
    }

    async findById(id: string): Promise<UserDocument> {
        if (!Types.ObjectId.isValid(id)) {
            throw new NotFoundException('Invalid ID format');
        }
        const user = await this.userModel
            .findById(id)
            .select('-password')
            .exec();
        if (!user) throw new NotFoundException(`User ${id} not found`);
        return user;
    }

    async findByEmail(email: string): Promise<UserDocument | null> {
        return this.userModel
            .findOne({ email: email.toLowerCase() })
            .select('+password')           // Include 'select: false' field
            .lean()
            .exec();
    }

    async create(dto: CreateUserDto): Promise<UserDocument> {
        const user = new this.userModel(dto);
        return user.save(); // Triggers pre-save hooks (password hashing)
    }

    async update(id: string, dto: UpdateUserDto): Promise<UserDocument> {
        const user = await this.userModel
            .findByIdAndUpdate(
                id,
                { $set: dto },             // $set: only update provided fields
                {
                    new:       true,       // Return the updated document
                    runValidators: true,   // Run schema validators on update
                    select:    '-password',
                },
            )
            .exec();
        if (!user) throw new NotFoundException(`User ${id} not found`);
        return user;
    }

    async softDelete(id: string): Promise<void> {
        await this.userModel.findByIdAndUpdate(id, { deletedAt: new Date() });
    }

    // ── Filtering and pagination ───────────────────────────────────────────────
    async findWithFilters(params: {
        search?: string;
        role?:   string;
        page?:   number;
        limit?:  number;
    }): Promise<{ data: UserDocument[]; total: number }> {
        const { search, role, page = 1, limit = 20 } = params;

        const filter: FilterQuery<UserDocument> = { deletedAt: null };
        if (role)   filter.role = role;
        if (search) filter.$text = { $search: search }; // Uses text index

        const [data, total] = await Promise.all([
            this.userModel
                .find(filter)
                .select('-password')
                .sort(search ? { score: { $meta: 'textScore' } } : { createdAt: -1 })
                .skip((page - 1) * limit)
                .limit(limit)
                .lean()
                .exec(),
            this.userModel.countDocuments(filter),
        ]);

        return { data, total };
    }

    // ── Population — joining related documents ─────────────────────────────────
    async findWithOrders(id: string): Promise<UserDocument> {
        return this.userModel
            .findById(id)
            .populate({
                path:   'orders',
                model:  'Order',
                select: 'total status createdAt',
                match:  { status: { $ne: 'cancelled' } }, // Filter populated docs
                options: { sort: { createdAt: -1 }, limit: 10 },
            })
            .select('-password')
            .exec();
    }

    // ── Aggregation pipeline ───────────────────────────────────────────────────
    async getRevenueByMonth(year: number) {
        return this.orderModel.aggregate([
            {
                $match: {
                    createdAt: {
                        $gte: new Date(`${year}-01-01`),
                        $lt:  new Date(`${year + 1}-01-01`),
                    },
                    status: { $ne: 'cancelled' },
                },
            },
            {
                $group: {
                    _id:     { $month: '$createdAt' },
                    revenue: { $sum: '$total' },
                    count:   { $sum: 1 },
                },
            },
            { $sort: { _id: 1 } },
            {
                $project: {
                    month:   '$_id',
                    revenue: 1,
                    count:   1,
                    _id:     0,
                },
            },
        ]);
    }

    // ── Transactions (requires replica set or MongoDB 4.4+) ───────────────────
    async transferCredits(
        fromId: string,
        toId: string,
        amount: number,
    ): Promise<void> {
        const session: ClientSession = await this.connection.startSession();

        try {
            session.startTransaction({
                readConcern:  { level: 'snapshot' },
                writeConcern: { w: 'majority' },
            });

            const from = await this.userModel.findById(fromId).session(session);
            const to   = await this.userModel.findById(toId).session(session);

            if (!from || !to) throw new NotFoundException('User not found');
            if ((from.credits ?? 0) < amount) throw new Error('Insufficient credits');

            await this.userModel.updateOne(
                { _id: fromId },
                { $inc: { credits: -amount } },
                { session },
            );
            await this.userModel.updateOne(
                { _id: toId },
                { $inc: { credits: amount } },
                { session },
            );

            await session.commitTransaction();
        } catch (err) {
            await session.abortTransaction();
            throw err;
        } finally {
            await session.endSession();
        }
    }
}
```

## Section 5: Side-by-Side Comparison and Choosing

**Q10. How do you decide between TypeORM, Prisma, and Mongoose — and what are the critical trade-offs?**

A: The choice depends on database type, team preferences, and type safety requirements:

```
Database first:
  PostgreSQL / MySQL / SQLite → TypeORM or Prisma
  MongoDB                     → Mongoose (or Prisma with MongoDB preview)

Type safety priority:
  Maximum type safety, auto-complete on queries → Prisma
  Good type safety, decorator-heavy style      → TypeORM
  Flexible, schema-optional                   → Mongoose

Schema management:
  Want migrations as versioned SQL files         → Prisma (best DX)
  Comfortable with code-first entity approach    → TypeORM
  Prefer JS-style schema definitions             → Mongoose

Query complexity:
  Complex joins, raw SQL needed frequently → TypeORM (QueryBuilder)
                                          OR Prisma ($queryRaw)
  Aggregation pipelines, text search      → Mongoose (native MongoDB API)

Performance:
  High-throughput reads (many concurrent)  → Prisma (connection pooling via PgBouncer)
  Bulk operations, upserts                → TypeORM (bulk save, upsert)
  Document storage, denormalized data     → Mongoose (native fit)
```

Common mistakes and how each ORM handles them:

```typescript
// ── N+1 Query Problem ─────────────────────────────────────────────────────────

// TypeORM — use eager loading or JOIN in QueryBuilder:
// BAD: N+1
const users = await userRepo.find();
for (const user of users) {
    user.orders = await orderRepo.find({ where: { user: { id: user.id } } }); // N queries
}
// GOOD: single JOIN
const users = await userRepo.find({ relations: { orders: true } });

// Prisma — include automatically JOINs:
// GOOD:
const users = await prisma.user.findMany({ include: { orders: true } }); // Single query

// Mongoose — populate is a separate query per document (similar to N+1 but batched):
// Moderate: populate sends 2 queries (one for users, one JOIN for all orders)
const users = await userModel.find().populate('orders');

// ── Type Safety ───────────────────────────────────────────────────────────────

// TypeORM — runtime errors if column name is wrong:
await userRepo.findOne({ where: { emal: 'x' } }); // typo: 'emal' — no compile error

// Prisma — compile error on typo:
await prisma.user.findFirst({ where: { emal: 'x' } }); // TypeScript error at compile time
// Property 'emal' does not exist on type 'UserWhereInput'

// Mongoose — no type safety without extra configuration:
await userModel.findOne({ emal: 'x' }); // Silently returns null — no error

// ── Transaction Support ───────────────────────────────────────────────────────

// TypeORM:   DataSource.transaction(async manager => { ... }) ✓ Excellent
// Prisma:    $transaction(async tx => { ... })                ✓ Excellent
// Mongoose:  session.startTransaction() / commitTransaction() ✓ Requires replica set

// ── Migration Support ─────────────────────────────────────────────────────────

// TypeORM:   typeorm migration:generate + migration:run     — Good but fragile on complex changes
// Prisma:    prisma migrate dev + prisma migrate deploy      — Best DX, always safe
// Mongoose:  No built-in migrations (migrate-mongo for external tooling)
```

## Section 6: Advanced Patterns

**Q11. How do you implement the repository pattern on top of TypeORM/Prisma/Mongoose to make the service layer ORM-agnostic?**

A: Abstracting the ORM behind a repository interface lets you swap implementations, test services in isolation, and keep business logic free of ORM-specific APIs:

```typescript
// ── Shared interface ───────────────────────────────────────────────────────────
export interface IUserRepository {
    findById(id: string): Promise<User | null>;
    findByEmail(email: string): Promise<User | null>;
    findAll(filter: UserFilter): Promise<{ data: User[]; total: number }>;
    create(dto: CreateUserDto): Promise<User>;
    update(id: string, dto: UpdateUserDto): Promise<User>;
    delete(id: string): Promise<void>;
}

export const USER_REPOSITORY = Symbol('IUserRepository');

// ── TypeORM implementation ─────────────────────────────────────────────────────
@Injectable()
export class TypeOrmUserRepository implements IUserRepository {
    constructor(
        @InjectRepository(UserEntity)
        private readonly repo: Repository<UserEntity>,
    ) {}

    async findById(id: string): Promise<User | null> {
        const entity = await this.repo.findOne({ where: { id } });
        return entity ? this.toUser(entity) : null;
    }

    async findByEmail(email: string): Promise<User | null> {
        const entity = await this.repo.findOne({
            where: { email },
            select: { id: true, email: true, password: true },
        });
        return entity ? this.toUser(entity) : null;
    }

    async findAll(filter: UserFilter) {
        const [entities, total] = await this.repo.findAndCount({
            where: filter.role ? { role: filter.role } : {},
            take:  filter.limit ?? 20,
            skip:  ((filter.page ?? 1) - 1) * (filter.limit ?? 20),
        });
        return { data: entities.map(this.toUser), total };
    }

    async create(dto: CreateUserDto): Promise<User> {
        const entity = this.repo.create(dto);
        const saved  = await this.repo.save(entity);
        return this.toUser(saved);
    }

    async update(id: string, dto: UpdateUserDto): Promise<User> {
        await this.repo.update(id, dto);
        return this.findById(id) as Promise<User>;
    }

    async delete(id: string): Promise<void> {
        await this.repo.softDelete(id);
    }

    private toUser(entity: UserEntity): User {
        return {
            id:         entity.id,
            email:      entity.email,
            name:       entity.name,
            role:       entity.role,
            isVerified: entity.isVerified,
            createdAt:  entity.createdAt,
        };
    }
}

// ── Prisma implementation ──────────────────────────────────────────────────────
@Injectable()
export class PrismaUserRepository implements IUserRepository {
    constructor(private readonly prisma: PrismaService) {}

    async findById(id: string): Promise<User | null> {
        const record = await this.prisma.user.findUnique({
            where: { id },
            select: { id: true, email: true, name: true, role: true,
                      isVerified: true, createdAt: true },
        });
        return record;
    }

    async findByEmail(email: string): Promise<User | null> {
        return this.prisma.user.findUnique({
            where: { email },
            select: { id: true, email: true, password: true },
        }) as Promise<User | null>;
    }

    async findAll(filter: UserFilter) {
        const where = { deletedAt: null, role: filter.role ?? undefined };
        const [data, total] = await this.prisma.$transaction([
            this.prisma.user.findMany({
                where,
                select: { id: true, email: true, name: true, role: true, createdAt: true },
                take:  filter.limit ?? 20,
                skip:  ((filter.page ?? 1) - 1) * (filter.limit ?? 20),
            }),
            this.prisma.user.count({ where }),
        ]);
        return { data, total };
    }

    async create(dto: CreateUserDto): Promise<User> {
        return this.prisma.user.create({ data: dto }) as Promise<User>;
    }

    async update(id: string, dto: UpdateUserDto): Promise<User> {
        return this.prisma.user.update({ where: { id }, data: dto }) as Promise<User>;
    }

    async delete(id: string): Promise<void> {
        await this.prisma.user.update({ where: { id }, data: { deletedAt: new Date() } });
    }
}

// ── Module — swap implementation via environment or feature flag ───────────────
@Module({
    imports: [TypeOrmModule.forFeature([UserEntity])],
    providers: [
        UserService,
        {
            provide: USER_REPOSITORY,
            // Swap at module level — service layer never changes:
            useClass: process.env.USE_PRISMA === 'true'
                ? PrismaUserRepository
                : TypeOrmUserRepository,
        },
    ],
    exports: [UserService],
})
export class UserModule {}

// ── Service layer — pure business logic, ORM-agnostic ─────────────────────────
@Injectable()
export class UserService {
    constructor(
        @Inject(USER_REPOSITORY)
        private readonly users: IUserRepository,
        private readonly mail: MailService,
    ) {}

    async createUser(dto: CreateUserDto): Promise<User> {
        const existing = await this.users.findByEmail(dto.email);
        if (existing) throw new ConflictException('Email already registered');

        const user = await this.users.create(dto);
        await this.mail.sendWelcome(user.email);  // Pure business logic
        return user;
    }
}
```

## Section 7: Scenario-Based Questions

**Q12. "Users are reporting slow page loads. You suspect N+1 queries. How do you diagnose and fix it across TypeORM, Prisma, and Mongoose?"**

A:

```typescript
// ── Detection ─────────────────────────────────────────────────────────────────

// TypeORM: enable query logging:
TypeOrmModule.forRoot({ logging: ['query', 'slow'], maxQueryExecutionTime: 500 })

// Prisma: log slow queries (see PrismaService onModuleInit in Q5)
// Prisma Studio (npx prisma studio) shows query count per operation

// Mongoose: enable debug mode
mongoose.set('debug', (collectionName, method, query) => {
    console.log(`Mongoose: ${collectionName}.${method}`, JSON.stringify(query));
});

// ── The N+1 bug (same in all ORMs) ───────────────────────────────────────────
// Getting a list of orders, then fetching each user separately:

// TypeORM N+1:
const orders = await orderRepo.find(); // 1 query
for (const order of orders) {
    order.user = await userRepo.findOne({ where: { id: order.userId } }); // N queries!
}

// TypeORM FIX — eager load with relations:
const orders = await orderRepo.find({
    relations: { user: true }, // Single JOIN query
});

// TypeORM FIX — QueryBuilder with explicit join:
const orders = await orderRepo
    .createQueryBuilder('order')
    .leftJoinAndSelect('order.user', 'user')
    .getMany(); // Single query

// Prisma N+1 — same problem if you nest calls in a loop:
const orders = await prisma.order.findMany();
for (const order of orders) {
    const user = await prisma.user.findUnique({ where: { id: order.userId } }); // N queries!
}

// Prisma FIX — include:
const orders = await prisma.order.findMany({
    include: { user: true }, // Prisma batches this as a single JOIN
});

// Mongoose N+1:
const orders = await orderModel.find();
for (const order of orders) {
    const user = await userModel.findById(order.userId); // N queries!
}

// Mongoose FIX — populate (2 queries total, not N+1):
const orders = await orderModel.find().populate('user', '-password');

// Mongoose FIX — aggregation with $lookup (single pipeline):
const orders = await orderModel.aggregate([
    {
        $lookup: {
            from:         'users',
            localField:   'userId',
            foreignField: '_id',
            as:           'user',
            pipeline: [{ $project: { password: 0 } }],
        },
    },
    { $unwind: '$user' }, // user is now an object, not an array
]);
```

**Q13. "You need to run a database operation that must succeed atomically across two models. Walk through the transaction pattern for each ORM."**

A: The canonical example — creating an order and decrementing product stock — must be atomic:

```typescript
// ── TypeORM transaction ────────────────────────────────────────────────────────
@Injectable()
export class OrderService {
    constructor(
        @InjectDataSource() private readonly dataSource: DataSource,
    ) {}

    async createOrder(userId: string, productId: string, qty: number): Promise<Order> {
        return this.dataSource.transaction(async (manager) => {
            // All operations use the transactional EntityManager:
            const product = await manager.findOneOrFail(Product, {
                where: { id: productId },
                lock:  { mode: 'pessimistic_write' }, // SELECT FOR UPDATE
            });

            if (product.stock < qty) {
                throw new BadRequestException('Insufficient stock');
            }

            await manager.decrement(Product, { id: productId }, 'stock', qty);

            const order = manager.create(Order, {
                userId,
                productId,
                quantity: qty,
                total:    product.price * qty,
            });

            return manager.save(Order, order);
        });
        // If any line throws, all changes roll back automatically
    }
}

// ── Prisma transaction ─────────────────────────────────────────────────────────
@Injectable()
export class OrderService {
    constructor(private readonly prisma: PrismaService) {}

    async createOrder(userId: string, productId: string, qty: number): Promise<Order> {
        return this.prisma.$transaction(async (tx) => {
            const product = await tx.product.findUniqueOrThrow({
                where: { id: productId },
            });

            if (product.stock < qty) {
                throw new BadRequestException('Insufficient stock');
            }

            // Both operations in the same transaction:
            const [order] = await Promise.all([
                tx.order.create({
                    data: {
                        userId,
                        productId,
                        quantity: qty,
                        total:    product.price * qty,
                    },
                }),
                tx.product.update({
                    where: { id: productId },
                    data:  { stock: { decrement: qty } },
                }),
            ]);

            return order;
        });
    }
}

// ── Mongoose transaction ────────────────────────────────────────────────────────
@Injectable()
export class OrderService {
    constructor(
        @InjectModel(Order.name)  private readonly orderModel: Model<OrderDocument>,
        @InjectModel(Product.name) private readonly productModel: Model<ProductDocument>,
        @InjectConnection() private readonly connection: Connection,
    ) {}

    async createOrder(userId: string, productId: string, qty: number): Promise<OrderDocument> {
        const session = await this.connection.startSession();
        session.startTransaction();

        try {
            const product = await this.productModel
                .findById(productId)
                .session(session);

            if (!product || product.stock < qty) {
                throw new BadRequestException('Insufficient stock');
            }

            const [order] = await this.orderModel.create(
                [{ userId, productId, quantity: qty, total: product.price * qty }],
                { session },
                // Note: create() with a session requires wrapping in an array
            );

            await this.productModel.updateOne(
                { _id: productId },
                { $inc: { stock: -qty } },
                { session },
            );

            await session.commitTransaction();
            return order;
        } catch (err) {
            await session.abortTransaction();
            throw err;
        } finally {
            await session.endSession();
        }
    }
}
```

## Quick Reference Table

| Feature | TypeORM | Prisma | Mongoose |
|---|---|---|---|
| **Database** | SQL (PG, MySQL, SQLite, MSSQL) | SQL + MongoDB (preview) | MongoDB only |
| **Schema definition** | Decorated TypeScript classes | `schema.prisma` DSL | JS Schema objects or decorated classes |
| **Type safety** | Good (entity types) | Excellent (generated client) | Fair (requires extra interfaces) |
| **DI injection token** | `@InjectRepository(Entity)` | `PrismaService` (plain service) | `@InjectModel(Name)` |
| **Module setup** | `TypeOrmModule.forRoot/Feature` | `PrismaModule` (custom global) | `MongooseModule.forRoot/Feature` |
| **Migrations** | `typeorm migration:generate/run` | `prisma migrate dev/deploy` | External tool (migrate-mongo) |
| **Transactions** | `DataSource.transaction(manager)` | `$transaction(tx)` | `session.startTransaction()` |
| **Raw queries** | `createQueryBuilder` / `query()` | `$queryRaw` / `$executeRaw` | `aggregate()` / native driver |
| **Soft delete** | `@DeleteDateColumn` + `softDelete()` | Manual `deletedAt` field | Manual `deletedAt` field |
| **Joins / Population** | `relations` option or QueryBuilder | `include` option | `.populate()` or `$lookup` |
| **Aggregations** | QueryBuilder `SELECT` + `GROUP BY` | `groupBy()` + `aggregate()` | Aggregate pipeline |
| **Hooks / Lifecycle** | `@BeforeInsert`, `@AfterUpdate` etc. | Middleware (`$use`) | Schema pre/post hooks |

| Scenario | Recommended ORM |
|---|---|
| New PostgreSQL project, team wants best type safety | Prisma |
| Existing NestJS project already using TypeORM | TypeORM (stay consistent) |
| MongoDB with flexible schema requirements | Mongoose |
| Need complex SQL JOIN queries | TypeORM (QueryBuilder) or Prisma ($queryRaw) |
| Need MongoDB aggregation pipelines | Mongoose |
| Want best migration DX | Prisma |
| Need soft delete built-in | TypeORM (`@DeleteDateColumn`) |
| Testing in isolation (mock the ORM) | All — use repository interface pattern (Q11) |

**Tip for interviews:** Six things separate strong candidates on this topic: (1) knowing that **TypeORM's `synchronize: true` must never be enabled in production** — it can drop columns and destroy data when entity definitions change, and migrations are the only safe schema management approach; (2) explaining the **N+1 query problem** concretely and its fix for each ORM — TypeORM's `relations` option and QueryBuilder `leftJoinAndSelect`, Prisma's `include`, and Mongoose's `populate` vs aggregation `$lookup` — and knowing that Mongoose's `populate` sends two queries (not N+1) while TypeORM and Prisma JOIN in a single query; (3) knowing that **Prisma's type safety comes from the generated client** — `prisma generate` must be re-run after schema changes, and the types are derived from `schema.prisma` not from TypeScript classes; (4) understanding **PrismaService as a lifecycle-aware provider** extending `PrismaClient` — `onModuleInit` calls `$connect()` and `onModuleDestroy` calls `$disconnect()`, and without these the connection pool isn't properly managed; (5) articulating the **repository interface pattern** (Q11) — abstracting the ORM behind an interface keeps business logic testable and ORM-agnostic, allows swapping implementations via `useClass` in the module, and is the pattern that distinguishes candidates who have built maintainable architectures from those who have only done tutorials; and (6) knowing **Mongoose's `select: false`** on the password field means you must use `select('+password')` to retrieve it — and the equivalent in TypeORM is also `select: false` on the column but requires explicitly listing `{ select: { password: true } }` in the query.
