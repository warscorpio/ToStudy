# Authentication in GraphQL — Context Injection: Interview Q&A (5 YOE Level)

---

## Section 1: GraphQL Context Fundamentals

**Q1. What is the GraphQL context, how is it created per request, and why is it the correct place for authentication data?**

A: The GraphQL context is a plain object that NestJS (via Apollo) creates once per request and passes to every resolver, guard, interceptor, and pipe that runs for that operation. It is the shared carrier of per-request state — auth user, DataLoaders, request ID, tracing spans — without any of that state leaking between requests:

```
Incoming GraphQL Request (HTTP POST /graphql)
           │
           ▼
  Apollo Server receives request
           │
           ▼
  context factory function runs  ← YOUR CODE: build the context object here
  { req, res, user, loaders }    ← context is assembled once
           │
           ▼
  Guards run            (context available via ExecutionContext)
           │
           ▼
  Interceptors (before) (context available via ExecutionContext)
           │
           ▼
  Resolver method       (@Context() injects the context object)
           │
           ▼
  Nested resolvers      (same context object — same reference, shared state)
           │
           ▼
  Interceptors (after)
```

Why context, not the resolver parameters directly:

```typescript
// ── WRONG: trying to access the request directly in a resolver ────────────────
// In REST you use @Req() — but @Req() does not work cleanly in GraphQL resolvers
// because the GraphQL execution engine doesn't pass Express req/res per-field.
// The context IS the mechanism for passing per-request data to resolvers.

// ── CORRECT: configure context in the module, inject it in resolvers ──────────

// app.module.ts (or a dedicated GraphQLModule)
import { GraphQLModule } from '@nestjs/graphql';
import { ApolloDriver, ApolloDriverConfig } from '@nestjs/apollo';
import { Request, Response }  from 'express';

@Module({
    imports: [
        GraphQLModule.forRoot<ApolloDriverConfig>({
            driver:      ApolloDriver,
            autoSchemaFile: join(process.cwd(), 'src/schema.gql'),

            // context factory — runs once per HTTP request.
            // The object it returns IS the context injected everywhere.
            context: ({ req, res }: { req: Request; res: Response }) => ({
                req,            // Raw Express request (headers, cookies, ip, etc.)
                res,            // Raw Express response (set cookies, headers)
                // Additional fields added here are available in every resolver:
                requestId: req.headers['x-request-id'] ?? crypto.randomUUID(),
                startTime: Date.now(),
                // user is NOT added here — it is added by the auth guard later,
                // OR by pre-populating from a token in the context factory (see Q2).
            }),
        }),
    ],
})
export class AppModule {}

// ── Injecting context in a resolver ──────────────────────────────────────────
import { Resolver, Query, Context } from '@nestjs/graphql';

interface GqlContext {
    req:       Request;
    res:       Response;
    requestId: string;
    user?:     JwtPayload; // Populated by auth guard or context factory
}

@Resolver(() => User)
export class UserResolver {
    // @Context() — injects the full context object
    @Query(() => User)
    me(@Context() ctx: GqlContext): User {
        return ctx.user; // User attached by guard or context factory
    }

    // @Context('user') — injects just the 'user' field from context
    @Query(() => [Post])
    myPosts(@Context('user') user: JwtPayload): Promise<Post[]> {
        return this.postService.findByUser(user.id);
    }

    // @Context('req') — injects just the raw request
    @Query(() => String)
    myIp(@Context('req') req: Request): string {
        return req.ip;
    }
}
```

**Q2. What are the two main patterns for attaching an authenticated user to the GraphQL context?**

A: The user can be attached either eagerly (in the context factory) or lazily (in a guard). Each has a different trade-off between simplicity and control:

```typescript
// ── Pattern A: Eager attachment in the context factory ────────────────────────
// The context factory decodes the JWT on every request (authenticated or not).
// The user is available immediately when any resolver runs.
// Public resolvers simply see ctx.user as undefined.

@Module({
    imports: [
        GraphQLModule.forRoot<ApolloDriverConfig>({
            driver: ApolloDriver,
            autoSchemaFile: true,

            context: async ({ req }: { req: Request }) => {
                const token = extractToken(req);
                let user: JwtPayload | undefined;

                if (token) {
                    try {
                        // Verify the JWT eagerly — failure means no user (not an error yet).
                        user = await jwtService.verifyAsync<JwtPayload>(token);
                    } catch {
                        // Invalid token — user stays undefined.
                        // Guarded resolvers will throw UnauthorizedException.
                    }
                }

                return { req, user };
            },
        }),
    ],
})
export class AppModule {}

// ── Pattern B: Lazy attachment via a Guard ────────────────────────────────────
// The context factory only passes req and res.
// A GqlAuthGuard runs before protected resolvers and attaches the user.
// The guard throws UnauthorizedException before the resolver runs if auth fails.
// Public resolvers don't run the guard — no token parsing overhead.

@Module({
    imports: [
        GraphQLModule.forRoot<ApolloDriverConfig>({
            driver: ApolloDriver,
            autoSchemaFile: true,
            context: ({ req, res }) => ({ req, res }), // Minimal context
        }),
    ],
})
export class AppModule {}

// GqlAuthGuard attaches user to context when placed on a resolver:
@Injectable()
export class GqlAuthGuard implements CanActivate {
    constructor(private readonly jwtService: JwtService) {}

    async canActivate(executionContext: ExecutionContext): Promise<boolean> {
        // CRITICAL: Must use GqlExecutionContext, NOT switchToHttp()
        // In GraphQL, switchToHttp() returns an empty context.
        const gqlCtx  = GqlExecutionContext.create(executionContext);
        const ctx      = gqlCtx.getContext<{ req: Request; user?: JwtPayload }>();
        const token    = extractToken(ctx.req);

        if (!token) throw new UnauthorizedException('No authentication token');

        try {
            ctx.user = await this.jwtService.verifyAsync<JwtPayload>(token);
            // Attaching to ctx.user mutates the shared context object.
            // The resolver and all nested resolvers now see ctx.user.
            return true;
        } catch (err) {
            throw new UnauthorizedException('Invalid or expired token');
        }
    }
}

// ── Token extraction helper (used by both patterns) ───────────────────────────
function extractToken(req: Request): string | undefined {
    // From Authorization header: "Bearer eyJhbGci..."
    const authHeader = req.headers.authorization;
    if (authHeader?.startsWith('Bearer ')) return authHeader.slice(7);

    // From cookie (for server-side rendering / httpOnly cookie auth):
    return req.cookies?.access_token;
}

// ── Trade-off summary ─────────────────────────────────────────────────────────
//
// Pattern A (eager — context factory):
//   ✓ User available to ALL resolvers automatically
//   ✓ No guard boilerplate on every protected resolver
//   ✓ Simpler for introspection/playground (no guard on root query)
//   ✗ JWT is decoded on EVERY request, even unauthenticated ones
//   ✗ Errors (expired token) must be handled silently in context factory
//   ✗ jwtService must be instantiated outside NestJS DI (or use forRootAsync)
//
// Pattern B (lazy — guard):
//   ✓ Full NestJS DI support in guards
//   ✓ Auth errors are thrown as proper UnauthorizedException
//   ✓ No overhead for truly public queries
//   ✗ Must add @UseGuards(GqlAuthGuard) to every protected resolver/class
//   ✗ User is not in context until after the guard runs
//
// RECOMMENDATION: Use Pattern A with forRootAsync for user population,
// and Pattern B (guards) for enforcement (throw if user is required but missing).
```

## Section 2: GqlExecutionContext — The Critical Difference

**Q3. Why is `GqlExecutionContext` required in GraphQL guards and interceptors — what breaks if you use `switchToHttp()`?**

A: This is the single most common GraphQL authentication bug in NestJS. Guards and interceptors written for REST use `context.switchToHttp()` — but in GraphQL, that call returns an object with empty request/response because the underlying transport is different:

```typescript
import { GqlExecutionContext } from '@nestjs/graphql';
import { ExecutionContext }    from '@nestjs/common';

// ── What switchToHttp() returns in GraphQL context ────────────────────────────
@Injectable()
export class BrokenGuard implements CanActivate {
    canActivate(context: ExecutionContext): boolean {
        // This is what you would write for a REST guard:
        const request = context.switchToHttp().getRequest<Request>();
        // In GraphQL: request is {} (empty object)
        // request.headers → undefined
        // request.headers.authorization → TypeError: Cannot read property 'authorization'
        //
        // The guard may return true by accident (no token check happens),
        // OR crashes silently and the resolver runs unauthenticated.
        // This is the worst kind of bug — it fails open, not closed.
        const token = request.headers?.authorization;
        return !!token; // Always false or crashes — never true
    }
}

// ── CORRECT: Use GqlExecutionContext ──────────────────────────────────────────
@Injectable()
export class GqlAuthGuard implements CanActivate {
    constructor(private readonly jwtService: JwtService) {}

    async canActivate(context: ExecutionContext): Promise<boolean> {
        // Step 1: Wrap the NestJS ExecutionContext with GqlExecutionContext:
        const gqlCtx = GqlExecutionContext.create(context);
        // GqlExecutionContext exposes GraphQL-specific methods:

        // Step 2: Extract the GraphQL context object (what was returned by context factory):
        const ctx = gqlCtx.getContext<GqlContext>();
        // ctx.req is the Express Request — this works correctly.
        // ctx.user is whatever your context factory attached.

        // Step 3: Access the request through ctx.req:
        const token = ctx.req?.headers?.authorization?.replace('Bearer ', '');

        // Step 4: Read GraphQL operation metadata:
        const info = gqlCtx.getInfo();         // GraphQLResolveInfo — field name, path, etc.
        const args = gqlCtx.getArgs<{ id: string }>(); // Resolver arguments
        const root = gqlCtx.getRoot();         // Root value (parent object for nested resolvers)

        if (!token) throw new UnauthorizedException('No token provided');

        try {
            ctx.user = await this.jwtService.verifyAsync(token);
            return true;
        } catch {
            throw new UnauthorizedException('Token invalid or expired');
        }
    }
}

// ── What GqlExecutionContext exposes (vs what ExecutionContext exposes) ─────────
//
// Method                            HTTP ExecutionContext   GqlExecutionContext
// ─────────────────────────────────────────────────────────────────────────────────
// context.switchToHttp().getRequest()  Express Request      ✗ empty object (broken)
// gqlCtx.getContext()                  ✗ not available      ✓ your context object
// gqlCtx.getArgs()                     ✗ not available      ✓ resolver @Args()
// gqlCtx.getInfo()                     ✗ not available      ✓ GraphQLResolveInfo
// gqlCtx.getRoot()                     ✗ not available      ✓ parent resolver value
// context.getHandler()                 ✓ controller method  ✓ resolver method
// context.getClass()                   ✓ controller class   ✓ resolver class
// context.getType()                    'http'               'graphql'
//
// context.getType() — use this to write guards that work for BOTH HTTP and GQL:

@Injectable()
export class UniversalAuthGuard implements CanActivate {
    async canActivate(context: ExecutionContext): Promise<boolean> {
        const type = context.getType<'http' | 'graphql'>();

        if (type === 'http') {
            const req = context.switchToHttp().getRequest<Request>();
            return this.validateToken(req.headers.authorization);
        }

        if (type === 'graphql') {
            const gqlCtx = GqlExecutionContext.create(context);
            const ctx    = gqlCtx.getContext<GqlContext>();
            return this.validateToken(ctx.req.headers.authorization);
        }

        return false;
    }

    private async validateToken(authHeader?: string): Promise<boolean> {
        const token = authHeader?.replace('Bearer ', '');
        if (!token) throw new UnauthorizedException();
        // ... verify token
        return true;
    }
}
```

**Q4. How do you use `Reflector` with GraphQL guards to implement `@Public()` and role-based access?**

A: `Reflector` reads `@SetMetadata()` decorator values from the resolver method or class. This works identically in GraphQL guards as in REST guards — the key is using `GqlExecutionContext` to get the right handler reference:

```typescript
import { Reflector }          from '@nestjs/core';
import { GqlExecutionContext } from '@nestjs/graphql';
import { SetMetadata }         from '@nestjs/common';

// ── Custom decorators ─────────────────────────────────────────────────────────
export const Public  = ()                => SetMetadata('isPublic', true);
export const Roles   = (...roles: string[]) => SetMetadata('roles', roles);
export const OwnData = ()                => SetMetadata('ownData', true);

// ── Guard that reads metadata ─────────────────────────────────────────────────
@Injectable()
export class GqlAuthGuard implements CanActivate {
    constructor(
        private readonly jwtService: JwtService,
        private readonly reflector:  Reflector,
    ) {}

    async canActivate(executionContext: ExecutionContext): Promise<boolean> {
        // Check @Public() — skip auth entirely for public resolvers:
        const isPublic = this.reflector.getAllAndOverride<boolean>('isPublic', [
            executionContext.getHandler(), // Resolver method
            executionContext.getClass(),   // Resolver class
        ]);
        if (isPublic) return true;

        // Get GraphQL context:
        const gqlCtx = GqlExecutionContext.create(executionContext);
        const ctx    = gqlCtx.getContext<GqlContext>();
        const token  = ctx.req?.headers?.authorization?.replace('Bearer ', '');

        if (!token) throw new UnauthorizedException('Authentication required');

        let user: JwtPayload;
        try {
            user = await this.jwtService.verifyAsync<JwtPayload>(token);
        } catch {
            throw new UnauthorizedException('Token invalid or expired');
        }

        // Attach user to context — now available in the resolver:
        ctx.user = user;

        // Check @Roles() — if required roles are specified, enforce them:
        const requiredRoles = this.reflector.getAllAndOverride<string[]>('roles', [
            executionContext.getHandler(),
            executionContext.getClass(),
        ]);
        if (!requiredRoles?.length) return true; // No role requirement

        const hasRole = requiredRoles.some(role => user.roles?.includes(role));
        if (!hasRole) {
            throw new ForbiddenException(
                `Requires one of [${requiredRoles.join(', ')}], user has [${user.roles?.join(', ')}]`
            );
        }
        return true;
    }
}

// ── Registering globally (applies to all resolvers) ───────────────────────────
@Module({
    providers: [
        { provide: APP_GUARD, useClass: GqlAuthGuard },
        // With this, EVERY query/mutation requires auth by default.
        // Use @Public() to opt out:
    ],
})
export class AppModule {}

// ── Using the decorators on resolvers ─────────────────────────────────────────
@Resolver(() => User)
export class UserResolver {
    @Query(() => User, { name: 'me' })
    // No decorator — protected by global guard, requires valid JWT:
    getMe(@Context('user') user: JwtPayload): Promise<User> {
        return this.userService.findById(user.id);
    }

    @Query(() => [User], { name: 'users' })
    @Roles('admin')   // Only admins can list all users:
    listUsers(): Promise<User[]> {
        return this.userService.findAll();
    }

    @Query(() => String, { name: 'health' })
    @Public()         // Health check — no auth required:
    health(): string {
        return 'ok';
    }

    @Mutation(() => User, { name: 'updateUser' })
    @Roles('admin', 'moderator')
    async updateUser(
        @Args('id') id: string,
        @Args('input') input: UpdateUserInput,
        @Context('user') user: JwtPayload,
    ): Promise<User> {
        return this.userService.update(id, input, user);
    }
}
```

## Section 3: Context Factory Patterns

**Q5. How do you use `forRootAsync` to inject services into the GraphQL context factory?**

A: The `context` factory in `GraphQLModule.forRoot()` is a plain function — it has no access to NestJS DI. To use services (JwtService, UserService) inside the context factory, you must use `forRootAsync`:

```typescript
import { GraphQLModule }         from '@nestjs/graphql';
import { ApolloDriver }          from '@nestjs/apollo';
import { ConfigService }         from '@nestjs/config';
import { JwtService }            from '@nestjs/jwt';

@Module({
    imports: [
        JwtModule.registerAsync({
            inject:      [ConfigService],
            useFactory:  (config: ConfigService) => ({
                secret:    config.get('JWT_SECRET'),
                signOptions: { expiresIn: '15m' },
            }),
        }),

        GraphQLModule.forRootAsync<ApolloDriverConfig>({
            driver: ApolloDriver,

            // Inject services that will be used in the context factory:
            inject: [JwtService, ConfigService],

            // useFactory receives injected services as arguments:
            useFactory: (jwtService: JwtService, config: ConfigService) => ({
                autoSchemaFile: join(process.cwd(), 'src/schema.gql'),
                sortSchema:     true,
                playground:     config.get('NODE_ENV') !== 'production',

                // context factory now has closure over jwtService:
                context: async ({ req, res }: { req: Request; res: Response }) => {
                    const token = req.headers.authorization?.replace('Bearer ', '');

                    let user: JwtPayload | undefined;
                    if (token) {
                        user = await jwtService
                            .verifyAsync<JwtPayload>(token)
                            .catch(() => undefined); // Silent failure — guard enforces auth
                    }

                    return {
                        req,
                        res,
                        user,
                        requestId: req.headers['x-request-id'] as string ?? crypto.randomUUID(),
                    };
                },

                // Format errors before sending to client:
                formatError: (error: GraphQLError) => {
                    const originalError = error.extensions?.originalError as any;
                    return {
                        message:    error.message,
                        statusCode: originalError?.statusCode ?? 500,
                        path:       error.path,
                        // Remove stack trace in production:
                        ...(config.get('NODE_ENV') !== 'production'
                            ? { extensions: error.extensions }
                            : {}),
                    };
                },
            }),
        }),
    ],
})
export class AppModule {}

// ── Strongly-typed context interface (define once, use everywhere) ────────────
// src/graphql/graphql-context.interface.ts
export interface GqlContext {
    req:        Request;
    res:        Response;
    user?:      JwtPayload;
    requestId:  string;
    loaders?:   DataLoaders; // See Q11 for DataLoader pattern
}

// Convenience type helper for resolvers:
export type AuthenticatedContext = GqlContext & { user: JwtPayload };
// Use when you know the resolver is protected and user is always present.

// ── Using the typed context in resolvers ──────────────────────────────────────
@Resolver(() => Post)
export class PostResolver {
    @Mutation(() => Post)
    createPost(
        @Args('input') input: CreatePostInput,
        @Context() ctx: AuthenticatedContext, // Typed — user is non-optional
    ): Promise<Post> {
        return this.postService.create(input, ctx.user.id);
    }

    @Query(() => [Post])
    @Public()
    publicPosts(@Context() ctx: GqlContext): Promise<Post[]> { // user may be undefined
        return this.postService.findPublic();
    }
}
```

**Q6. How do you set cookies or response headers from within a GraphQL resolver?**

A: GraphQL resolvers don't have direct access to the HTTP response, but the context carries the `res` object from Express. Setting cookies for auth tokens (e.g., refresh token as httpOnly cookie) requires accessing `ctx.res`:

```typescript
@Module({
    imports: [
        GraphQLModule.forRoot<ApolloDriverConfig>({
            driver: ApolloDriver,
            // IMPORTANT: includeCredentials — must pass res to context for mutations
            // to set cookies. Without this, res is undefined in context.
            context: ({ req, res }) => ({ req, res }),
        }),
    ],
})
export class AppModule {}

@Resolver()
export class AuthResolver {
    constructor(
        private readonly authService: AuthService,
        private readonly jwtService:  JwtService,
    ) {}

    @Mutation(() => AuthPayload)
    async login(
        @Args('input') input: LoginInput,
        @Context() ctx: GqlContext,
    ): Promise<AuthPayload> {
        const { user, accessToken, refreshToken } = await this.authService.login(input);

        // Set httpOnly cookie for refresh token — cannot be read by JS (XSS protection):
        ctx.res.cookie('refresh_token', refreshToken, {
            httpOnly:  true,
            secure:    process.env.NODE_ENV === 'production',
            sameSite:  'strict',
            maxAge:    7 * 24 * 60 * 60 * 1000, // 7 days in ms
            path:      '/graphql', // Restrict cookie to GraphQL endpoint
        });

        // Access token returned in the response body (short-lived, used by client):
        return { accessToken, user };
    }

    @Mutation(() => AuthPayload)
    async refreshToken(@Context() ctx: GqlContext): Promise<AuthPayload> {
        // Read the httpOnly cookie from the request:
        const refreshToken = ctx.req.cookies?.refresh_token;
        if (!refreshToken) throw new UnauthorizedException('No refresh token');

        const { accessToken, newRefreshToken } = await this.authService.refresh(refreshToken);

        // Rotate the refresh token cookie:
        ctx.res.cookie('refresh_token', newRefreshToken, {
            httpOnly: true,
            secure:   process.env.NODE_ENV === 'production',
            sameSite: 'strict',
            maxAge:   7 * 24 * 60 * 60 * 1000,
        });

        return { accessToken };
    }

    @Mutation(() => Boolean)
    logout(@Context() ctx: GqlContext): boolean {
        ctx.res.clearCookie('refresh_token', { path: '/graphql' });
        return true;
    }
}

// ── Required Express middleware for cookie parsing ─────────────────────────────
// In main.ts:
import * as cookieParser from 'cookie-parser';

async function bootstrap() {
    const app = await NestFactory.create(AppModule);
    app.use(cookieParser()); // Makes req.cookies available
    await app.listen(3000);
}

// ── Response headers (e.g., rate limit headers) ───────────────────────────────
@Query(() => [Product])
getProducts(@Context() ctx: GqlContext): Promise<Product[]> {
    ctx.res.setHeader('X-RateLimit-Limit',     '100');
    ctx.res.setHeader('X-RateLimit-Remaining', '99');
    return this.productService.findAll();
}
```

## Section 4: Authorization Patterns

**Q7. How do you implement field-level authorization in GraphQL — hiding specific fields from unauthorised users?**

A: Field-level auth in GraphQL goes beyond resolver-level guards. A user might be allowed to query a `User` object but not see the `email` or `salary` fields. There are three approaches:

```typescript
// ── Approach 1: Check in the field resolver ───────────────────────────────────
// The cleanest NestJS-native approach — add a @ResolveField() and throw there.

@Resolver(() => User)
export class UserResolver {
    // Anyone can query User.name:
    @ResolveField(() => String)
    name(@Parent() user: User): string {
        return user.name;
    }

    // Only the user themselves or admins can see email:
    @ResolveField(() => String, { nullable: true })
    email(
        @Parent()  user:    User,
        @Context() ctx:     GqlContext,
    ): string | null {
        const requestingUser = ctx.user;
        if (!requestingUser) return null; // Not authenticated — hide field

        const isSelf  = requestingUser.id === user.id;
        const isAdmin = requestingUser.roles?.includes('admin');

        if (!isSelf && !isAdmin) return null; // Forbidden — return null, not throw
        // Returning null is safer than throwing for field resolvers —
        // a throw aborts the ENTIRE query, null just omits this field.
        return user.email;
    }

    // Salary — admins and HR only:
    @ResolveField(() => Float, { nullable: true })
    @Roles('admin', 'hr')
    @UseGuards(GqlAuthGuard)
    salary(
        @Parent()  user: User,
        @Context() ctx:  GqlContext,
    ): number | null {
        return user.salary ?? null;
    }
}

// ── Approach 2: Dedicated field-auth decorator ────────────────────────────────
// A reusable decorator that wraps the field resolver in an auth check:
export function FieldAuth(...roles: string[]) {
    return applyDecorators(
        UseGuards(GqlAuthGuard),
        Roles(...roles),
    );
}

@Resolver(() => Employee)
export class EmployeeResolver {
    @ResolveField(() => Float, { nullable: true })
    @FieldAuth('admin', 'hr')
    salary(@Parent() emp: Employee): number {
        return emp.salary;
    }

    @ResolveField(() => String, { nullable: true })
    @FieldAuth('admin')
    ssn(@Parent() emp: Employee): string {
        return emp.ssn;
    }
}

// ── Approach 3: Schema directive (declarative, schema-first) ──────────────────
// Define an @auth directive in SDL — applied directly in the type definition.
// More powerful but requires more setup.

// schema.gql:
// directive @auth(roles: [String!]!) on FIELD_DEFINITION
//
// type User {
//   id:     ID!
//   name:   String!
//   email:  String! @auth(roles: ["self", "admin"])
//   salary: Float   @auth(roles: ["admin", "hr"])
// }

// Directive implementation:
import { SchemaDirectiveVisitor } from '@graphql-tools/utils';
import { defaultFieldResolver, GraphQLField } from 'graphql';

export class AuthDirective extends SchemaDirectiveVisitor {
    visitFieldDefinition(field: GraphQLField<any, any>) {
        const { resolve = defaultFieldResolver } = field;
        const { roles } = this.args as { roles: string[] };

        field.resolve = async (source, args, context: GqlContext, info) => {
            const user = context.user;
            if (!user) throw new AuthenticationError('Not authenticated');

            const hasRole = roles.some(role => {
                if (role === 'self') return user.id === source.id;
                return user.roles?.includes(role);
            });

            if (!hasRole) throw new ForbiddenError(`Requires one of: ${roles.join(', ')}`);

            return resolve.call(this, source, args, context, info);
        };
    }
}

// ── Which approach to use? ────────────────────────────────────────────────────
// @ResolveField + guard:   Best for most cases — NestJS-native, type-safe, testable
// Custom decorator:        When the same auth pattern repeats across many fields
// Schema directive:        When you want auth expressed declaratively in the schema
//                          (useful for tooling, documentation, schema-first workflows)
```

**Q8. How do you implement ownership-based authorization — "a user can only edit their own data"?**

A: Ownership checks require both the authenticated user (from context) and the resource owner (from the database). The guard cannot do this alone — it needs to run after the resource is fetched, which is a resolver concern:

```typescript
// ── Pattern A: Check in the resolver (simplest) ───────────────────────────────
@Resolver(() => Post)
export class PostResolver {
    @Mutation(() => Post)
    @UseGuards(GqlAuthGuard) // Ensures ctx.user exists
    async updatePost(
        @Args('id')    id:    string,
        @Args('input') input: UpdatePostInput,
        @Context('user') user: JwtPayload,
    ): Promise<Post> {
        const post = await this.postService.findById(id);
        if (!post) throw new NotFoundException('Post not found');

        // Ownership check — admins can bypass:
        if (post.authorId !== user.id && !user.roles?.includes('admin')) {
            throw new ForbiddenException('You can only edit your own posts');
        }
        return this.postService.update(id, input);
    }
}

// ── Pattern B: OwnData guard + resource fetcher ───────────────────────────────
// Encapsulate ownership logic in a reusable guard with metadata.
// The guard fetches the resource and compares ownership.

// Decorator to declare which arg identifies the resource:
export const ResourceId   = (paramName = 'id') => SetMetadata('resourceId', paramName);
export const ResourceType = (type: string)     => SetMetadata('resourceType', type);

@Injectable()
export class OwnershipGuard implements CanActivate {
    constructor(
        private readonly reflector:  Reflector,
        private readonly postService: PostService,
    ) {}

    async canActivate(executionContext: ExecutionContext): Promise<boolean> {
        const gqlCtx      = GqlExecutionContext.create(executionContext);
        const ctx         = gqlCtx.getContext<GqlContext>();
        const user        = ctx.user;

        if (!user) throw new UnauthorizedException();
        if (user.roles?.includes('admin')) return true; // Admins bypass ownership

        const args        = gqlCtx.getArgs<Record<string, string>>();
        const resourceId  = this.reflector.get<string>('resourceId', executionContext.getHandler());
        const resourceType = this.reflector.get<string>('resourceType', executionContext.getHandler());

        const id = args[resourceId ?? 'id'];
        if (!id) return true; // No ID — let resolver handle it

        let resource: { authorId?: string; userId?: string } | null = null;
        if (resourceType === 'post')    resource = await this.postService.findById(id);
        // Add more resource types as needed...

        if (!resource) throw new NotFoundException();

        const ownerId = resource.authorId ?? resource.userId;
        if (ownerId !== user.id) {
            throw new ForbiddenException('Resource does not belong to you');
        }
        return true;
    }
}

@Mutation(() => Post)

@ResourceId('id')
@ResourceType('post')
deletePost(@Args('id') id: string): Promise<boolean> {
    return this.postService.delete(id);
}

// For complex authorization rules, a policy library like CASL is more maintainable
// than inline checks or custom guards.
// npm install @casl/ability

import { defineAbility, AbilityBuilder, createMongoAbility } from '@casl/ability';

@Injectable()
export class AbilityFactory {
    createForUser(user: JwtPayload) {
        const { can, cannot, build } = new AbilityBuilder(createMongoAbility);

        if (user.roles.includes('admin')) {
            can('manage', 'all'); // Admin can do everything
        } else {
            can('read', 'Post');              // Everyone can read posts
            can('create', 'Post');            // Logged-in users can create
            can('update', 'Post', { authorId: user.id }); // Only own posts
            can('delete', 'Post', { authorId: user.id });
            cannot('delete', 'Post', { published: true }); // Can't delete published
        }

        return build();
    }
}
```

## Section 5: Subscriptions

**Q9. How does authentication work for GraphQL subscriptions — why is it different from queries and mutations?**

A: Subscriptions use WebSocket connections, not HTTP. The context factory (which receives `req` and `res`) does NOT run for subscription connections — instead, NestJS provides separate `onConnect` and `onDisconnect` hooks:

```typescript
// ── Subscription context setup ────────────────────────────────────────────────
@Module({
    imports: [
        GraphQLModule.forRootAsync<ApolloDriverConfig>({
            driver: ApolloDriver,
            inject: [JwtService],
            useFactory: (jwtService: JwtService) => ({
                autoSchemaFile: true,
                installSubscriptionHandlers: true, // Enable subscriptions

                // HTTP context factory — runs for queries and mutations:
                context: ({ req, res }) => ({ req, res }),

                // Subscription context — runs for WebSocket connections:
                subscriptions: {
                    'graphql-ws': {
                        // onConnect runs when a WebSocket connection is established.
                        // Return the context object for this subscription connection.
                        // Throw to reject the connection.
                        onConnect: async (connectionParams: Record<string, any>) => {
                            // connectionParams is what the client sends in the
                            // ConnectionInit message:
                            // client: { connectionParams: { Authorization: 'Bearer ...' } }
                            const authHeader =
                                connectionParams.Authorization ??
                                connectionParams.authorization;

                            if (!authHeader) {
                                // Throwing here rejects the WebSocket connection entirely:
                                throw new UnauthorizedException('Subscription requires auth');
                            }

                            const token = authHeader.replace('Bearer ', '');
                            try {
                                const user = await jwtService.verifyAsync<JwtPayload>(token);
                                // Return value becomes the subscription context:
                                return { user };
                            } catch {
                                throw new UnauthorizedException('Invalid subscription token');
                            }
                        },

                        onDisconnect: (ctx: any) => {
                            console.log('Subscription client disconnected:', ctx?.user?.id);
                        },
                    },

                    // Legacy subscriptions-transport-ws (older clients):
                    'subscriptions-transport-ws': {
                        onConnect: async (connectionParams: any) => {
                            const token = connectionParams?.authToken;
                            if (!token) throw new UnauthorizedException();
                            const user = await jwtService.verifyAsync<JwtPayload>(token);
                            return { user };
                        },
                    },
                },
            }),
        }),
    ],
})
export class AppModule {}

// ── Subscription resolver with context auth ───────────────────────────────────
import { Resolver, Subscription, Args, Context } from '@nestjs/graphql';
import { PubSub } from 'graphql-subscriptions';

const pubSub = new PubSub(); // In production: use Redis PubSub (see Q10)

@Resolver()
export class ChatResolver {
    @Subscription(() => Message, {
        // filter: runs for each published event — controls who receives it:
        filter: (payload: { messageAdded: Message }, variables, context: GqlContext) => {
            const { messageAdded } = payload;
            const user = context.user;

            // Only send to users who are members of the room:
            return messageAdded.roomId === variables.roomId
                && context.user?.allowedRooms?.includes(variables.roomId);
        },

        // resolve: transforms the payload before sending to the subscriber:
        resolve: (payload: { messageAdded: Message }) => payload.messageAdded,
    })
    async messageAdded(
        @Args('roomId') roomId: string,
        @Context() ctx: GqlContext,
    ): Promise<AsyncIterator<Message>> {
        // ctx.user is what onConnect returned — available here:
        if (!ctx.user) throw new UnauthorizedException('Must be authenticated to subscribe');

        const canAccess = await this.roomService.isMember(roomId, ctx.user.id);
        if (!canAccess) throw new ForbiddenException('Not a member of this room');

        return pubSub.asyncIterator(`MESSAGE_ADDED:${roomId}`);
    }
}
```

**Q10. How do you scale GraphQL subscriptions with Redis PubSub?**

A: The in-memory `PubSub` from `graphql-subscriptions` only works within a single Node.js process. For multiple instances, you need a Redis-backed PubSub that relays events across instances:

```typescript
// npm install graphql-redis-subscriptions ioredis

import { RedisPubSub } from 'graphql-redis-subscriptions';
import Redis from 'ioredis';

// ── Create the Redis PubSub (as a NestJS provider) ────────────────────────────
@Injectable()
export class PubSubService {
    readonly pubSub: RedisPubSub;

    constructor(private readonly config: ConfigService) {
        const options = {
            host:     this.config.get('REDIS_HOST'),
            port:     this.config.get<number>('REDIS_PORT'),
            password: this.config.get('REDIS_PASSWORD'),
            retryStrategy: (times: number) => Math.min(times * 50, 2000),
        };
        this.pubSub = new RedisPubSub({
            publisher:  new Redis(options),
            subscriber: new Redis(options), // PubSub requires TWO connections
        });
    }
}

// ── Module registration ───────────────────────────────────────────────────────
@Module({
    providers: [PubSubService, ChatResolver],
    exports:   [PubSubService],
})
export class PubSubModule {}

// ── Using in a resolver ───────────────────────────────────────────────────────
@Resolver()
export class ChatResolver {
    constructor(private readonly pubSubService: PubSubService) {}

    @Subscription(() => Message, {
        filter: (payload, vars) => payload.messageAdded.roomId === vars.roomId,
    })
    messageAdded(@Args('roomId') roomId: string) {
        return this.pubSubService.pubSub.asyncIterator(`MESSAGE_ADDED:${roomId}`);
    }

    @Mutation(() => Message)
    @UseGuards(GqlAuthGuard)
    async sendMessage(
        @Args('input') input: SendMessageInput,
        @Context('user') user: JwtPayload,
    ): Promise<Message> {
        const message = await this.messageService.create(input, user.id);
        // Redis publish — received by all instances subscribed to this key:
        await this.pubSubService.pubSub.publish(`MESSAGE_ADDED:${input.roomId}`, {
            messageAdded: message,
        });
        return message;
    }
}

// ── What happens with Redis PubSub across instances ───────────────────────────
//
// Instance A: client subscribes to MESSAGE_ADDED:room-1
//             → asyncIterator registered in Instance A's Redis subscriber
//
// Instance B: mutation sendMessage → pubSub.publish('MESSAGE_ADDED:room-1', ...)
//             → Event published to Redis channel 'MESSAGE_ADDED:room-1'
//             → Redis delivers to ALL subscribers of that channel
//             → Instance A's subscriber receives it
//             → Instance A pushes to the WebSocket client
```

## Section 6: Advanced Patterns

**Q11. How do you attach DataLoaders to context — why is this tied to authentication?**

A: DataLoaders solve the N+1 problem in GraphQL. They must be created per-request (not as singletons) to avoid cross-request data leakage — and since authentication determines what data a user can access, the DataLoader factory should be aware of the authenticated user:

```typescript
// npm install dataloader

import DataLoader from 'dataloader';

// ── DataLoader factory — creates new loaders per request ──────────────────────
@Injectable()
export class DataLoaderService {
    constructor(
        private readonly userRepo:    UserRepository,
        private readonly postRepo:    PostRepository,
    ) {}

    createLoaders(user?: JwtPayload): DataLoaders {
        return {
            // Batch function: receives an array of IDs, returns an array of results.
            // Must return results in the SAME ORDER as the input IDs.
            userLoader: new DataLoader<string, User | null>(async (ids) => {
                const users = await this.userRepo.findByIds([...ids]);
                const map   = new Map(users.map(u => [u.id, u]));

                return ids.map(id => {
                    const u = map.get(id) ?? null;
                    // Field-level auth in DataLoader — hide emails from non-admins:
                    if (u && !user?.roles?.includes('admin')) {
                        return { ...u, email: '[hidden]' }; // Redact sensitive fields
                    }
                    return u;
                });
            }),

            postsByUserLoader: new DataLoader<string, Post[]>(async (userIds) => {
                const posts = await this.postRepo.findByUserIds([...userIds]);
                // Group by userId:
                const map = new Map<string, Post[]>();
                posts.forEach(p => {
                    if (!map.has(p.authorId)) map.set(p.authorId, []);
                    map.get(p.authorId)!.push(p);
                });
                return userIds.map(id => map.get(id) ?? []);
            }),
        };
    }
}

export interface DataLoaders {
    userLoader:          DataLoader<string, User | null>;
    postsByUserLoader:   DataLoader<string, Post[]>;
}

// ── Attaching loaders to context in the factory ───────────────────────────────
@Module({
    imports: [
        GraphQLModule.forRootAsync<ApolloDriverConfig>({
            inject:      [JwtService, DataLoaderService],
            useFactory:  (jwtService: JwtService, loaderService: DataLoaderService) => ({
                autoSchemaFile: true,

                context: async ({ req, res }) => {
                    const token = req.headers.authorization?.replace('Bearer ', '');
                    let user: JwtPayload | undefined;
                    if (token) user = await jwtService.verifyAsync(token).catch(() => undefined);

                    return {
                        req,
                        res,
                        user,
                        // New DataLoader instances per request — no cross-request caching:
                        loaders: loaderService.createLoaders(user),
                    };
                },
            }),
        }),
    ],
})
export class AppModule {}

// ── Using DataLoaders in a resolver ──────────────────────────────────────────
@Resolver(() => Post)
export class PostResolver {
    // Resolve the author of a Post — uses DataLoader to batch user fetches:
    @ResolveField(() => User, { nullable: true })
    async author(
        @Parent() post: Post,
        @Context() ctx: GqlContext,
    ): Promise<User | null> {
        // All author requests within the same GraphQL operation are batched:
        return ctx.loaders!.userLoader.load(post.authorId);
        // Without DataLoader: N posts → N separate DB queries for authors.
        // With DataLoader:    N posts → 1 batched DB query for all authors.
    }
}

// ── Why DataLoaders must be per-request (auth safety) ─────────────────────────
// WRONG — singleton DataLoader (shared across all requests):
@Injectable()
export class WrongDataLoaderService {
    // Created once at module init — shared by ALL requests:
    readonly userLoader = new DataLoader<string, User>(async (ids) => {
        return this.userRepo.findByIds([...ids]);
        // DataLoader has an internal cache (Map<id, Promise<User>>).
        // User A's request fetches user-1 → cached.
        // User B's request asks for user-1 → gets User A's CACHED result.
        // If user-1's data was redacted for User A, User B sees the redacted version.
        // OR: User A should NOT see user-1 but it's cached from User B's request.
        // This is a data leak across users — critical security bug.
    });
}
// CORRECT: Always instantiate DataLoaders inside the context factory
// (per-request, not as a singleton).
```

**Q12. How do you implement query complexity and depth limiting to prevent GraphQL abuse?**

A: Without limits, a malicious client can craft deeply nested or exponentially expensive queries. These protections are configured at the Apollo Server level and can incorporate the authenticated user's role:

```typescript
import { createComplexityLimitRule } from 'graphql-validation-complexity';
import depthLimit                    from 'graphql-depth-limit';

@Module({
    imports: [
        GraphQLModule.forRootAsync<ApolloDriverConfig>({
            inject:     [JwtService],
            useFactory: (jwtService: JwtService) => ({
                autoSchemaFile: true,

                // ── Depth limiting ────────────────────────────────────────────
                // Rejects queries deeper than N levels.
                // Prevents: { user { posts { author { posts { author { ... } } } } } }
                validationRules: [
                    depthLimit(7), // Max 7 levels of nesting for everyone
                ],

                // ── Complexity limiting ───────────────────────────────────────
                // Each field contributes to a complexity score.
                // Reject if score exceeds the max.
                plugins: [
                    {
                        requestDidStart: () => ({
                            didResolveOperation: ({ request, document }) => {
                                const complexity = getComplexity({
                                    schema,
                                    operationName: request.operationName,
                                    query:         document,
                                    variables:     request.variables,
                                    estimators: [
                                        // List fields cost fieldCount * childComplexity:
                                        fieldExtensionsEstimator(),
                                        // Default: 1 per scalar, fieldCount for lists:
                                        simpleEstimator({ defaultComplexity: 1 }),
                                    ],
                                });

                                // Different limits for different user roles:
                                const user   = request.http?.headers.get('x-user-role');
                                const limit  = user === 'admin' ? 2000 : 500;

                                if (complexity > limit) {
                                    throw new GraphQLError(
                                        `Query complexity ${complexity} exceeds limit ${limit}`,
                                        { extensions: { code: 'QUERY_TOO_COMPLEX' } }
                                    );
                                }
                            },
                        }),
                    },
                ],

                // ── Introspection — disable in production ─────────────────────
                // Introspection reveals your entire schema — valuable for attackers.
                introspection: process.env.NODE_ENV !== 'production',

                // ── Persisted queries — only allow pre-registered queries ─────
                // For production: use APQ (Automatic Persisted Queries) to
                // only allow queries the server has seen before.
                // This prevents arbitrary query injection entirely.
            }),
        }),
    ],
})
export class AppModule {}

// ── Per-field complexity annotation ───────────────────────────────────────────
// Annotate expensive fields with their complexity cost:
@ObjectType()
export class User {
    @Field(() => ID)
    id: string;

    @Field(() => String)
    name: string;

    // Fetching posts is expensive — annotate with higher complexity:
    @Field(() => [Post], { complexity: (options) => options.childComplexity * 10 })
    posts: Post[];

    // Very expensive aggregation — always costs 50:
    @Field(() => Analytics, { complexity: 50 })
    analytics: Analytics;
}
```

**Q14. "A protected resolver always returns null — the guard seems to pass but the user is never in context."**

A: This is the classic `switchToHttp()` in a GraphQL guard bug combined with two other common failure modes:

```typescript
// ── Root Cause 1: Using switchToHttp() in the guard (fails silently) ─────────
@Injectable()
export class BrokenGuard implements CanActivate {
    async canActivate(context: ExecutionContext): Promise<boolean> {
        // In GraphQL, this returns an empty object — no error thrown:
        const req   = context.switchToHttp().getRequest();
        const token = req.headers?.authorization; // undefined — no headers in GQL context

        // Token is undefined — no auth check runs.
        // Depending on guard logic, this might return true (guard "passes").
        // The resolver runs but ctx.user is never set.
        return !!token; // false → guard actually throws 403... but only sometimes
    }
}

// DIAGNOSIS: Add logging to the guard to detect this:
const type = context.getType(); // Logs 'graphql' — confirm it's reaching the guard
const req  = context.switchToHttp().getRequest();
console.log('Request keys:', Object.keys(req)); // Logs [] (empty) — confirms the bug

// FIX:
@Injectable()
export class FixedGuard implements CanActivate {
    async canActivate(context: ExecutionContext): Promise<boolean> {
        const gqlCtx = GqlExecutionContext.create(context);
        const ctx    = gqlCtx.getContext<GqlContext>();         // Correct
        const token  = ctx.req?.headers?.authorization?.replace('Bearer ', '');
        // ... rest of auth logic
    }
}

// ── Root Cause 2: Guard attached but context factory already ran without DI ───
// When using forRoot() instead of forRootAsync(), the context factory is a plain
// function — it cannot inject JwtService.
// Developer tries to import jwtService outside DI: new JwtService() — it uses
// a different secret or no secret, and verifyAsync always fails silently.

// WRONG — jwtService instantiated manually, ignores config:
GraphQLModule.forRoot({
    context: async ({ req }) => {
        const svc   = new JwtService({ secret: 'hardcoded' }); // Wrong secret
        const token = req.headers.authorization?.replace('Bearer ', '');
        const user  = await svc.verifyAsync(token!).catch(() => undefined);
        return { req, user }; // user is always undefined if secret doesn't match
    },
})

// FIX — use forRootAsync with inject:
GraphQLModule.forRootAsync({
    inject:      [JwtService],
    useFactory:  (jwtService: JwtService) => ({
        context: async ({ req }) => {
            const user = await jwtService.verifyAsync(...).catch(() => undefined);
            return { req, user };
        },
    }),
})

// ── Root Cause 3: Guard is global but only applies to HTTP, not GraphQL ───────
// APP_GUARD applies to BOTH HTTP and GraphQL — but if the guard uses
// switchToHttp() internally, it fails for GQL as described above.
// The guard "passes" (or throws a 403 for all GQL), masking the real issue.
// FIX: Use context.getType() to branch, or write separate GQL-specific guards.

// ── Root Cause 4: Mutation type vs Query type mismatch ────────────────────────
// Developer defines a mutation but queries it as a query in the playground:
// @Mutation(() => User) getMe()  — calling this as a Query will never match.
// The resolver is never called — client receives null silently.
// FIX: Check schema with introspection — ensure operation type matches decorator.
```

**Q15. "Design a complete auth system for a NestJS GraphQL API: JWT, refresh tokens, role-based access, field-level security, and subscription auth."**

A: The complete wiring for a production GraphQL auth system, all working together:

```typescript
// ── Module structure ─────────────────────────────────────────────────────────
// src/
//   app.module.ts
//   graphql/
//     graphql.module.ts      ← GraphQLModule.forRootAsync, context factory
//     context.interface.ts   ← GqlContext type definition
//   auth/
//     auth.module.ts
//     auth.resolver.ts       ← login, logout, refreshToken mutations
//     auth.service.ts        ← token generation, validation, refresh
//     gql-auth.guard.ts      ← GqlExecutionContext-aware JWT guard
//     roles.guard.ts         ← Role enforcement using Reflector
//     decorators.ts          ← @Public(), @Roles(), @CurrentUser()
//   users/
//     user.resolver.ts       ← field-level auth on email, salary
//     user.service.ts
//   pubsub/
//     pubsub.module.ts       ← Redis PubSub provider

// ── context.interface.ts ──────────────────────────────────────────────────────
export interface JwtPayload {
    sub:    string;  // User ID
    email:  string;
    roles:  string[];
    iat?:   number;
    exp?:   number;
}
export interface GqlContext {
    req:        Request;
    res:        Response;
    user?:      JwtPayload;
    requestId:  string;
    loaders:    DataLoaders;
}

// ── decorators.ts ─────────────────────────────────────────────────────────────
export const Public      = ()             => SetMetadata('isPublic', true);
export const Roles       = (...r: string[]) => SetMetadata('roles', r);
// @CurrentUser() — injects user directly from context (no manual ctx.user):
export const CurrentUser = createParamDecorator(
    (_data: unknown, context: ExecutionContext): JwtPayload | undefined => {
        const gqlCtx = GqlExecutionContext.create(context);
        return gqlCtx.getContext<GqlContext>().user;
    },
);

// ── gql-auth.guard.ts ─────────────────────────────────────────────────────────
@Injectable()
export class GqlAuthGuard implements CanActivate {
    constructor(
        private readonly jwtService: JwtService,
        private readonly reflector:  Reflector,
    ) {}

    async canActivate(ec: ExecutionContext): Promise<boolean> {
        const isPublic = this.reflector.getAllAndOverride<boolean>('isPublic', [
            ec.getHandler(), ec.getClass(),
        ]);
        if (isPublic) return true;

        const gqlCtx = GqlExecutionContext.create(ec);
        const ctx    = gqlCtx.getContext<GqlContext>();
        const token  = ctx.req.headers.authorization?.replace('Bearer ', '')
                    ?? ctx.req.cookies?.access_token;

        if (!token) throw new UnauthorizedException('Authentication required');

        try {
            ctx.user = await this.jwtService.verifyAsync<JwtPayload>(token);
        } catch (err) {
            throw new UnauthorizedException(
                err.name === 'TokenExpiredError' ? 'Token expired' : 'Invalid token'
            );
        }

        const required = this.reflector.getAllAndOverride<string[]>('roles', [
            ec.getHandler(), ec.getClass(),
        ]);
        if (!required?.length) return true;

        if (!required.some(r => ctx.user!.roles.includes(r))) {
            throw new ForbiddenException(`Requires one of: [${required.join(', ')}]`);
        }
        return true;
    }
}

// ── auth.resolver.ts ──────────────────────────────────────────────────────────
@Resolver()
export class AuthResolver {
    @Mutation(() => AuthPayload)
    @Public()
    async login(
        @Args('input') input: LoginInput,
        @Context() ctx: GqlContext,
    ): Promise<AuthPayload> {
        const { user, accessToken, refreshToken } = await this.authService.login(input);
        ctx.res.cookie('refresh_token', refreshToken, {
            httpOnly: true, secure: true, sameSite: 'strict',
            maxAge: 7 * 24 * 60 * 60 * 1000,
        });
        return { accessToken, user };
    }

    @Mutation(() => AuthPayload)
    @Public()
    async refreshToken(@Context() ctx: GqlContext): Promise<AuthPayload> {
        const rt = ctx.req.cookies?.refresh_token;
        if (!rt) throw new UnauthorizedException('No refresh token');
        const { accessToken, newRefreshToken } = await this.authService.refresh(rt);
        ctx.res.cookie('refresh_token', newRefreshToken, {
            httpOnly: true, secure: true, sameSite: 'strict',
            maxAge: 7 * 24 * 60 * 60 * 1000,
        });
        return { accessToken };
    }

    @Mutation(() => Boolean)
    logout(@Context() ctx: GqlContext): boolean {
        ctx.res.clearCookie('refresh_token', { path: '/graphql' });
        return true;
    }
}

// ── user.resolver.ts — field-level security ───────────────────────────────────
@Resolver(() => User)
@UseGuards(GqlAuthGuard) // Protect the whole resolver
export class UserResolver {
    @Query(() => User)
    me(@CurrentUser() user: JwtPayload): Promise<User> { // @CurrentUser() decorator
        return this.userService.findById(user.id);
    }

    @Query(() => [User])
    @Roles('admin')
    users(): Promise<User[]> {
        return this.userService.findAll();
    }

    @ResolveField(() => String, { nullable: true })
    email(@Parent() target: User, @Context() ctx: GqlContext): string | null {
        const viewer = ctx.user!;
        return (viewer.id === target.id || viewer.roles.includes('admin'))
            ? target.email : null;
    }

    @ResolveField(() => Float, { nullable: true })
    salary(@Parent() target: User, @Context() ctx: GqlContext): number | null {
        return ctx.user!.roles.includes('hr') || ctx.user!.roles.includes('admin')
            ? target.salary : null;
    }
}

// ── app.module.ts — registering global guard ──────────────────────────────────
@Module({
    imports:   [GraphQLModule (forRootAsync), AuthModule, UserModule, PubSubModule],
    providers: [
        // Global guard: protects ALL resolvers by default.
        // Use @Public() to opt out on specific resolvers.
        { provide: APP_GUARD, useClass: GqlAuthGuard },
    ],
})
export class AppModule {}

// ── Complete request flow for a protected mutation ────────────────────────────
// POST /graphql { query: 'mutation { updatePost(id: ...) { ... } }' }
// Headers: Authorization: Bearer <access_token>
// Cookies:  refresh_token=<refresh_token>
//
// 1. Apollo receives HTTP POST
// 2. context factory runs:
//    → Decodes JWT → ctx.user = { id: 'user-1', roles: ['user'] }
//    → Creates DataLoaders scoped to user
//    → Attaches requestId
// 3. GqlAuthGuard (global, via APP_GUARD):
//    → GqlExecutionContext.create(ec).getContext() → ctx
//    → Verifies ctx.user exists (already set by context factory)
//    → Reads @Roles() metadata → none required for this mutation
//    → Returns true
// 4. Resolver method runs:
//    → @CurrentUser() extracts ctx.user
//    → Checks post ownership
//    → Calls service
// 5. @ResolveField email:
//    → Checks viewer.id === target.id → true → returns email
// 6. Response assembled and sent to client
```

## Quick Reference Tables

### Context Access by Stage

| Stage | How to access GraphQL context | Key method |
|---|---|---|
| Context factory | Function argument `{ req, res }` | Return the context object |
| Guard | `GqlExecutionContext.create(ec).getContext()` | `switchToHttp()` is WRONG |
| Interceptor | `GqlExecutionContext.create(ec).getContext()` | `switchToHttp()` is WRONG |
| Resolver param | `@Context()` or `@Context('field')` | Direct injection |
| Custom param decorator | `GqlExecutionContext.create(ec).getContext()` | Inside `createParamDecorator` |
| Subscription `filter/resolve` | Third argument `(payload, variables, context)` | Plain function arg |
| Subscription `onConnect` | Return value becomes context | `connectionParams` arg |

### Auth Pattern Comparison

| Pattern | Auth runs | DI available | Token decode | Best for |
|---|---|---|---|---|
| Context factory (eager) | Every request | Via `forRootAsync` | Once, silently | Simple apps, playground auth |
| Guard (lazy) | Protected resolvers | Full DI | On each guarded call | Precise control, mixed public/private |
| `onConnect` hook | WS handshake only | Via `forRootAsync` | Once per connection | Subscription auth |
| Field resolver check | On field resolution | Full DI | Not needed (user in ctx) | Selective field visibility |
| CASL policy | In resolver | Full DI | Not needed | Complex ownership rules |

### Common Mistakes

| Mistake | Symptom | Fix |
|---|---|---|
| `switchToHttp()` in GQL guard | Guard passes, `req` is `{}`, user never set | Use `GqlExecutionContext.create(ec).getContext()` |
| `forRoot()` with service in context | `jwtService` is undefined, token never decoded | Switch to `forRootAsync` with `inject` |
| Singleton DataLoader | Data leaked between users | Instantiate DataLoaders inside context factory |
| `HttpException` in subscription handler | Error silently swallowed or wrongly formatted | Use `ForbiddenError`/`AuthenticationError` from `apollo-server-errors` |
| `APP_GUARD` with `switchToHttp()` guard | All GQL requests 403 or unauthenticated | Write GQL-aware guard; use `context.getType()` to branch |
| Missing `cookieParser` middleware | `ctx.req.cookies` is `undefined` | `app.use(cookieParser())` in `main.ts` |
| `@WebSocketServer()` on a GQL gateway | Not applicable — GQL subscriptions use their own WS | Use `installSubscriptionHandlers` in GraphQL config |

**Tip for interviews:** Eight things separate strong candidates on this topic: (1) knowing that **`switchToHttp()` in a GraphQL guard returns an empty object** — every guard you ever write for a GraphQL endpoint must use `GqlExecutionContext.create(executionContext).getContext()` instead, and confusing these two is the most common and most dangerous GraphQL auth bug (it fails open); (2) understanding the **two-phase auth model**: a context factory that silently decodes the token (no throw) populates `ctx.user` for every request, and a guard that throws `UnauthorizedException` enforces that the user exists for protected resolvers — the factory tolerates invalid tokens, the guard rejects them; (3) knowing that **`forRootAsync` with `inject` is required** whenever the context factory needs a NestJS service (JwtService, ConfigService) — `forRoot` with a plain function cannot use DI and leads to manual instantiation bugs; (4) being precise that **DataLoaders must be created per-request inside the context factory** — a singleton DataLoader caches across users and is a data-leak security vulnerability; (5) knowing that **GraphQL subscriptions use `onConnect` for authentication**, not the HTTP context factory, because subscriptions use WebSocket connections with `connectionParams` instead of HTTP headers; (6) understanding **field-level authorization** — returning `null` from a field resolver is safer than throwing (a throw aborts the whole query), and the context carries the requesting user's identity for the comparison; (7) knowing that `@CurrentUser()` is a **custom param decorator** built with `createParamDecorator` and `GqlExecutionContext.create(ec)` — it is the idiomatic way to inject the authenticated user into a resolver without manually destructuring `@Context()`; and (8) understanding **query complexity and depth limits** — without them, a single deeply nested GraphQL query can cause exponential database load, and the limits should scale with the user's role (admins get higher limits than anonymous users).
