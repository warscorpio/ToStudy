# NestJS GraphQL: Resolvers, Queries, Mutations, Subscriptions — Interview Q&A (5 YOE Level)

---

## Section 1: Fundamentals

**Q1. What is GraphQL and how does NestJS integrate it — what are the two approach options?**

A: GraphQL is a query language and runtime for APIs where the client specifies exactly what data it needs. Instead of multiple REST endpoints returning fixed shapes, a single `/graphql` endpoint accepts typed queries. NestJS integrates GraphQL through `@nestjs/graphql` which wraps Apollo Server (or Mercurius for Fastify):

```
REST vs GraphQL:

REST:
  GET /users/42          → { id, email, name, password, internalId, ... } (fixed shape)
  GET /users/42/orders   → separate request
  GET /users/42/profile  → separate request

GraphQL:
  POST /graphql
  query {
    user(id: "42") {
      email
      name            ← client chooses exactly these fields
      orders {
        id
        total
      }
    }
  }
  → { user: { email, name, orders: [...] } } — single request, exact shape
```

The two NestJS GraphQL approaches:

```typescript
// ── Approach 1: Code First (recommended for NestJS) ───────────────────────────
// TypeScript classes + decorators define the schema.
// NestJS generates the SDL (Schema Definition Language) automatically.
// Strength: single source of truth — types and schema stay in sync.

import { ObjectType, Field, Int, ID } from '@nestjs/graphql';

@ObjectType()                          // Defines a GraphQL type
export class User {
    @Field(() => ID)                   // GraphQL ID scalar
    id: string;

    @Field()                           // Inferred as String
    email: string;

    @Field({ nullable: true })         // Optional field
    name?: string;

    @Field(() => Int)                  // Must be explicit for numbers
    age: number;

    // NO @Field() → field is NOT in the GraphQL schema (private)
    password: string;
}

// Generated SDL (in schema.gql):
// type User {
//   id: ID!
//   email: String!
//   name: String
//   age: Int!
// }

// ── Approach 2: Schema First ───────────────────────────────────────────────────
// SDL file defines the schema; NestJS generates TypeScript interfaces from it.
// Strength: non-developers can read/edit the schema.
// Weakness: types can drift from implementation; more boilerplate.

// schema.graphql:
// type User {
//   id: ID!
//   email: String!
//   name: String
//   age: Int!
// }
//
// NestJS generates UserModel interface from the SDL.
// Resolver implements the interface.
// This guide focuses on Code First — the dominant approach in NestJS projects.

// ── Module setup ──────────────────────────────────────────────────────────────
import { GraphQLModule } from '@nestjs/graphql';
import { ApolloDriver, ApolloDriverConfig } from '@nestjs/apollo';
import { join } from 'path';

@Module({
    imports: [
        GraphQLModule.forRoot<ApolloDriverConfig>({
            driver:       ApolloDriver,
            autoSchemaFile: join(process.cwd(), 'src/schema.gql'),
            // autoSchemaFile: true → generates in memory (no file written)
            sortSchema:   true,        // Alphabetical ordering in SDL
            playground:   process.env.NODE_ENV !== 'production',
            introspection: process.env.NODE_ENV !== 'production',
            context: ({ req, res }) => ({ req, res }),
            // context is available in every resolver via @Context()
        }),
        UserModule,
        OrderModule,
    ],
})
export class AppModule {}
```

**Q2. What is a resolver and how does it differ from an Express controller?**

A: A resolver is a class decorated with `@Resolver()` that maps GraphQL operations (queries, mutations, subscriptions) to handler methods. Each handler is responsible for one field in the schema. The key difference from a controller is that resolvers compose — a type resolver can add fields to an object returned by a query resolver, enabling the nested shape GraphQL promises:

```typescript
import { Resolver, Query, Mutation, Args, Parent, ResolveField } from '@nestjs/graphql';

// Controller analogy:
// @Controller('users') → @Resolver(() => User)
// @Get(':id')          → @Query()
// @Post()              → @Mutation()
// @Get(':id/orders')   → @ResolveField()

@Resolver(() => User)     // This resolver handles fields on the User type
export class UserResolver {
    constructor(
        private readonly userService:  UserService,
        private readonly orderService: OrderService,
    ) {}

    // Top-level query — responds to: query { user(id: "42") { ... } }
    @Query(() => User, { nullable: true, name: 'user' })
    async getUser(@Args('id', { type: () => ID }) id: string): Promise<User | null> {
        return this.userService.findById(id);
    }

    // Field resolver — runs when the 'orders' field is requested on a User
    // ONLY runs if the client asks for 'orders' — lazy loading
    @ResolveField(() => [Order])
    async orders(@Parent() user: User): Promise<Order[]> {
        return this.orderService.findByUserId(user.id);
        // @Parent() gives you the parent User object already resolved
        // This is how GraphQL avoids over-fetching: this method
        // only runs when the client explicitly requests 'orders'
    }

    // Field resolver for a computed field not on the User entity:
    @ResolveField(() => String)
    fullName(@Parent() user: User): string {
        return `${user.firstName} ${user.lastName}`;
    }
}

// Key differences from REST controllers:
//
// 1. Composition: UserResolver + OrderResolver can both add fields to User type
// 2. Selective execution: @ResolveField runs ONLY if that field is requested
// 3. Single endpoint: all operations go to POST /graphql
// 4. Typed arguments: @Args validates input via GraphQL's type system
// 5. No HTTP status codes: errors are returned in the 'errors' array in the response
```

## Section 2: Object Types and Scalars

**Q3. How do you define GraphQL types, fields, and scalars in NestJS code-first?**

A: The `@ObjectType()`, `@Field()`, `@InputType()`, and scalar decorators form the type system backbone. Each decorator maps TypeScript to GraphQL type definitions:

```typescript
import {
    ObjectType, InputType, Field, ID, Int, Float,
    GraphQLISODateTime, registerEnumType,
} from '@nestjs/graphql';
import { IsEmail, MinLength, IsOptional, IsEnum } from 'class-validator';

// ── Enums ─────────────────────────────────────────────────────────────────────
export enum UserRole {
    USER  = 'USER',
    ADMIN = 'ADMIN',
    MOD   = 'MODERATOR',
}

registerEnumType(UserRole, {
    name:        'UserRole',
    description: 'The role of the user in the system',
    valuesMap: {
        MOD: { description: 'Moderator with limited admin access' },
    },
});

// ── Output type (returned by queries/mutations) ────────────────────────────────
@ObjectType({ description: 'A registered user' })
export class User {
    @Field(() => ID, { description: 'UUID primary key' })
    id: string;

    @Field({ description: 'Unique email address' })
    email: string;

    @Field({ nullable: true })
    name?: string;

    @Field(() => Int, { defaultValue: 0 })
    age: number;

    @Field(() => Float, { nullable: true })
    creditBalance?: number;           // Float for decimal values

    @Field(() => UserRole)
    role: UserRole;

    @Field(() => Boolean)
    isVerified: boolean;

    @Field(() => GraphQLISODateTime) // ISO 8601 date-time scalar
    createdAt: Date;

    @Field(() => GraphQLISODateTime, { nullable: true })
    updatedAt?: Date;

    // NOT decorated — excluded from GraphQL schema:
    password: string;
    refreshToken: string;
}

// ── Input types (arguments to mutations) ──────────────────────────────────────
// InputType = like ObjectType but used as arguments; supports class-validator
@InputType({ description: 'Input for creating a new user' })
export class CreateUserInput {
    @Field()
    @IsEmail()
    email: string;

    @Field({ nullable: true })
    @IsOptional()
    name?: string;

    @Field()
    @MinLength(8, { message: 'Password must be at least 8 characters' })
    password: string;

    @Field(() => UserRole, { defaultValue: UserRole.USER })
    @IsEnum(UserRole)
    role: UserRole = UserRole.USER;
}

@InputType()
export class UpdateUserInput {
    @Field({ nullable: true })
    @IsOptional()
    name?: string;

    @Field({ nullable: true })
    @IsOptional()
    @MinLength(8)
    password?: string;

    @Field(() => Boolean, { nullable: true })
    @IsOptional()
    isVerified?: boolean;
}

// ── Pagination types ───────────────────────────────────────────────────────────
@ObjectType({ isAbstract: true }) // isAbstract: not added to schema — only for extension
export class PaginatedResult {
    @Field(() => Int)
    total: number;

    @Field(() => Int)
    page: number;

    @Field(() => Int)
    limit: number;

    @Field(() => Boolean)
    hasNextPage: boolean;
}

// Extend for each paginated entity — the Relay-style cursor approach:
@ObjectType()
export class PaginatedUsers extends PaginatedResult {
    @Field(() => [User])
    items: User[];
}

// ── Custom scalars ─────────────────────────────────────────────────────────────
import { Scalar, CustomScalar } from '@nestjs/graphql';
import { Kind, ValueNode } from 'graphql';

@Scalar('JSON', () => Object)
export class JSONScalar implements CustomScalar<unknown, unknown> {
    description = 'Arbitrary JSON value';

    parseValue(value: unknown): unknown {
        return value; // From client input (variables)
    }

    serialize(value: unknown): unknown {
        return value; // To client (query result)
    }

    parseLiteral(ast: ValueNode): unknown {
        // Inline value in query document (rare)
        if (ast.kind === Kind.STRING) return JSON.parse(ast.value);
        return null;
    }
}

// Register custom scalars in module:
@Module({
    providers: [JSONScalar],
})
export class ScalarsModule {}
```

## Section 3: Queries

**Q4. How do you implement queries — single items, lists, filtering, and pagination?**

A: Queries are the read operations in GraphQL. `@Query()` decorator maps a resolver method to a top-level query field. Arguments come via `@Args()`:

```typescript
import {
    Resolver, Query, Args, Int, ID,
    ArgsType, Field,
} from '@nestjs/graphql';
import { IsOptional, Min, Max, IsEnum } from 'class-validator';

// ── ArgsType — group related arguments into a class ───────────────────────────
// Cleaner than multiple @Args() parameters for complex queries
@ArgsType()
export class GetUsersArgs {
    @Field(() => Int, { defaultValue: 1 })
    @Min(1)
    page: number = 1;

    @Field(() => Int, { defaultValue: 20 })
    @Min(1) @Max(100)
    limit: number = 20;

    @Field({ nullable: true })
    @IsOptional()
    search?: string;

    @Field(() => UserRole, { nullable: true })
    @IsOptional()
    @IsEnum(UserRole)
    role?: UserRole;

    @Field({ nullable: true })
    @IsOptional()
    sortBy?: string;

    @Field(() => Boolean, { nullable: true, defaultValue: false })
    sortDesc: boolean = false;
}

@ArgsType()
export class GetUserArgs {
    @Field(() => ID)
    id: string;
}

// ── Query resolver ─────────────────────────────────────────────────────────────
@Resolver(() => User)
export class UserResolver {
    constructor(private readonly userService: UserService) {}

    // Single item — nullable because user might not exist
    @Query(() => User, {
        nullable:    true,
        name:        'user',         // Overrides method name in schema
        description: 'Find a user by ID',
        complexity:  5,              // For query complexity limiting
    })
    async getUser(
        @Args() args: GetUserArgs,
        // OR explicit single arg:
        // @Args('id', { type: () => ID }) id: string,
    ): Promise<User | null> {
        return this.userService.findById(args.id);
    }

    // List with filtering and pagination:
    @Query(() => PaginatedUsers, {
        name:        'users',
        description: 'List users with optional filtering and pagination',
    })
    async getUsers(@Args() args: GetUsersArgs): Promise<PaginatedUsers> {
        const { data, total } = await this.userService.findAll(args);

        return {
            items:       data,
            total,
            page:        args.page,
            limit:       args.limit,
            hasNextPage: args.page * args.limit < total,
        };
    }

    // Multiple argument types combined:
    @Query(() => User, { nullable: true, name: 'userByEmail' })
    async getUserByEmail(
        @Args('email', { type: () => String }) email: string,
    ): Promise<User | null> {
        return this.userService.findByEmail(email);
    }

    // Query with context access (e.g., current user from auth guard):
    @Query(() => User, { name: 'me' })
    @UseGuards(GqlAuthGuard)
    async getCurrentUser(@CurrentUser() user: User): Promise<User> {
        // @CurrentUser() is a custom decorator that reads from GQL context
        return this.userService.findById(user.id);
    }
}

// How clients use these queries:
/*
query GetUser {
  user(id: "uuid-123") {
    id
    email
    name
    role
    createdAt
  }
}

query ListUsers {
  users(page: 1, limit: 10, role: ADMIN, search: "alice") {
    items {
      id
      email
      role
    }
    total
    page
    hasNextPage
  }
}

query Me {
  me {
    id
    email
    isVerified
  }
}
*/
```

## Section 4: Mutations

**Q5. How do you implement mutations — create, update, delete operations with input validation?**

A: Mutations are write operations. `@Mutation()` maps a method to a GraphQL mutation. Inputs use `@InputType()` classes which integrate with `class-validator` via the `ValidationPipe`:

```typescript
import { Resolver, Mutation, Args, ID } from '@nestjs/graphql';
import { UseGuards, UsePipes, ValidationPipe } from '@nestjs/common';

// ── Return types for mutations ─────────────────────────────────────────────────
@ObjectType()
export class DeleteResult {
    @Field(() => Boolean)
    success: boolean;

    @Field({ nullable: true })
    message?: string;
}

@ObjectType()
export class AuthPayload {
    @Field()
    accessToken: string;

    @Field()
    refreshToken: string;

    @Field(() => User)
    user: User;
}

// ── Mutation resolver ──────────────────────────────────────────────────────────
@Resolver(() => User)
@UsePipes(new ValidationPipe({
    transform:    true,       // Auto-coerce types (string → number where decorated)
    whitelist:    true,       // Strip fields not in the Input DTO
    forbidNonWhitelisted: true,
}))
export class UserMutationResolver {
    constructor(
        private readonly userService: UserService,
        private readonly authService: AuthService,
    ) {}

    // Create:
    @Mutation(() => User, {
        name:        'createUser',
        description: 'Register a new user account',
    })
    async createUser(
        @Args('input') input: CreateUserInput,
        // @Args('input', { type: () => CreateUserInput }) also valid
    ): Promise<User> {
        return this.userService.create(input);
        // class-validator runs on 'input' via ValidationPipe
        // If validation fails: UserInputError is thrown with field-level messages
    }

    // Update — authenticated:
    @Mutation(() => User, { name: 'updateUser' })
    @UseGuards(GqlAuthGuard)
    async updateUser(
        @Args('id', { type: () => ID }) id: string,
        @Args('input') input: UpdateUserInput,
        @CurrentUser() currentUser: User,
    ): Promise<User> {
        // Authorization: user can only update themselves (unless admin)
        if (currentUser.id !== id && currentUser.role !== UserRole.ADMIN) {
            throw new ForbiddenError('Cannot update another user\'s account');
        }
        return this.userService.update(id, input);
    }

    // Delete with return type:
    @Mutation(() => DeleteResult, { name: 'deleteUser' })
    @UseGuards(GqlAuthGuard, AdminGuard)
    async deleteUser(
        @Args('id', { type: () => ID }) id: string,
    ): Promise<DeleteResult> {
        await this.userService.softDelete(id);
        return { success: true, message: `User ${id} deleted` };
    }

    // Authentication mutation:
    @Mutation(() => AuthPayload, { name: 'login' })
    async login(
        @Args('email') email: string,
        @Args('password') password: string,
    ): Promise<AuthPayload> {
        return this.authService.login(email, password);
        // Returns { accessToken, refreshToken, user }
    }

    // Mutation with file upload:
    @Mutation(() => User, { name: 'uploadAvatar' })
    @UseGuards(GqlAuthGuard)
    async uploadAvatar(
        @Args('file', { type: () => GraphQLUpload }) file: FileUpload,
        @CurrentUser() user: User,
    ): Promise<User> {
        const { createReadStream, filename, mimetype } = await file;
        const url = await this.storageService.upload(createReadStream(), filename, mimetype);
        return this.userService.update(user.id, { avatarUrl: url });
    }
}

// Client usage:
/*
mutation CreateUser {
  createUser(input: {
    email: "alice@example.com"
    name: "Alice"
    password: "securepassword"
    role: USER
  }) {
    id
    email
    name
    createdAt
  }
}

mutation UpdateUser {
  updateUser(id: "uuid-123", input: { name: "Alice Smith" }) {
    id
    name
    updatedAt
  }
}

mutation Login {
  login(email: "alice@example.com", password: "securepassword") {
    accessToken
    user {
      id
      email
      role
    }
  }
}
*/
```

## Section 5: Field Resolvers and the N+1 Problem

**Q6. How do `@ResolveField()` work and what is the N+1 problem — how does DataLoader solve it?**

A: `@ResolveField()` runs a separate resolver for a single field on an object type. When resolving a list of users each with their orders, a naïve implementation makes one database call per user — the N+1 problem. DataLoader solves this by batching all individual lookups into a single database call:

```typescript
// ── The N+1 problem ───────────────────────────────────────────────────────────
// Client query:
// query {
//   users {         ← 1 DB call → returns 10 users
//     id
//     orders {      ← @ResolveField runs for EACH user → 10 DB calls!
//       total
//     }
//   }
// }

// NAÏVE (N+1 — 11 queries for 10 users):
@Resolver(() => User)
export class UserResolver {
    @ResolveField(() => [Order])
    async orders(@Parent() user: User): Promise<Order[]> {
        return this.orderService.findByUserId(user.id);
        // Called 10 times → 10 separate SELECT queries
    }
}

// ── DataLoader solution ────────────────────────────────────────────────────────
// npm install dataloader

import DataLoader from 'dataloader';
import { Injectable, Scope } from '@nestjs/common';

@Injectable({ scope: Scope.REQUEST }) // New instance per request — critical!
export class OrdersByUserLoader {
    private loader: DataLoader<string, Order[]>;

    constructor(private readonly orderService: OrderService) {
        this.loader = new DataLoader<string, Order[]>(
            async (userIds: readonly string[]) => {
                // Called ONCE with all user IDs collected during this request
                const orders = await this.orderService.findByUserIds([...userIds]);
                // Returns: Order[] for ALL userIds in one DB call

                // DataLoader requires results in the SAME ORDER as keys:
                const ordersByUserId = new Map<string, Order[]>();
                for (const order of orders) {
                    const list = ordersByUserId.get(order.userId) ?? [];
                    list.push(order);
                    ordersByUserId.set(order.userId, list);
                }

                return userIds.map(id => ordersByUserId.get(id) ?? []);
                // If userId had no orders: return [] (not undefined — DataLoader needs exact count)
            },
            {
                // Options:
                cache: true,    // Default: cache per-request (same userId only loaded once)
                maxBatchSize: 100, // Don't batch more than 100 at once
            },
        );
    }

    load(userId: string): Promise<Order[]> {
        return this.loader.load(userId);
    }
}

// ── How DataLoader batches ─────────────────────────────────────────────────────
// When 10 users are resolved, each calls loader.load(userId).
// DataLoader collects all .load() calls made in the current event loop tick.
// On the next tick, it calls the batch function ONCE with all 10 IDs.
// Result: 2 queries total (1 for users + 1 for all their orders).

// ── Resolver using DataLoader ─────────────────────────────────────────────────
@Resolver(() => User)
export class UserResolver {
    constructor(private readonly ordersByUserLoader: OrdersByUserLoader) {}

    @ResolveField(() => [Order])
    async orders(@Parent() user: User): Promise<Order[]> {
        return this.ordersByUserLoader.load(user.id);
        // Each call schedules a load — DataLoader batches them all
    }
}

// ── Module registration ────────────────────────────────────────────────────────
// DataLoader MUST be REQUEST-scoped — a new instance per request ensures
// the cache is cleared between requests (no cross-request data leaks)
@Module({
    providers: [
        UserResolver,
        OrdersByUserLoader,     // REQUEST scoped — new instance per request
        OrderService,
    ],
})
export class UserModule {}

// ── Making DataLoader available in context ─────────────────────────────────────
// Alternative pattern: create DataLoaders in the GraphQL context factory
// so resolvers access them via @Context() instead of injection:
GraphQLModule.forRoot({
    context: ({ req }) => ({
        req,
        loaders: {
            orders: new OrdersByUserLoader(orderService),
            // All loaders created fresh per request
        },
    }),
});

// Resolver with context-based DataLoader:
@ResolveField(() => [Order])
async orders(
    @Parent() user: User,
    @Context() ctx: { loaders: { orders: OrdersByUserLoader } },
): Promise<Order[]> {
    return ctx.loaders.orders.load(user.id);
}
```

## Section 6: Subscriptions

**Q7. What are GraphQL subscriptions and how do you implement them in NestJS?**

A: Subscriptions are long-lived GraphQL operations that push data to clients in real time over WebSockets. Unlike queries and mutations (request-response), a subscription opens a persistent connection and the server pushes events as they occur:

```typescript
// npm install @nestjs/websockets @nestjs/platform-socket.io graphql-subscriptions

// ── Setup — enable subscriptions in GraphQL module ─────────────────────────────
import { GraphQLModule } from '@nestjs/graphql';
import { ApolloDriver } from '@nestjs/apollo';
import { PubSub } from 'graphql-subscriptions';

// PubSub — in-memory event bus (for development / single-instance)
// In production: use graphql-redis-subscriptions or graphql-postgres-subscriptions
export const PUB_SUB = 'PUB_SUB';

@Module({
    imports: [
        GraphQLModule.forRoot({
            driver: ApolloDriver,
            autoSchemaFile: true,
            subscriptions: {
                'graphql-ws': true,          // Modern WebSocket protocol (recommended)
                'subscriptions-transport-ws': true, // Legacy protocol for older clients
            },
            context: ({ req, connectionParams }) => ({
                req,
                connectionParams, // Available in subscription context (for auth)
            }),
        }),
    ],
    providers: [
        {
            provide: PUB_SUB,
            useValue: new PubSub(),          // Single in-memory PubSub instance
        },
    ],
})
export class AppModule {}

// ── Event type definitions ─────────────────────────────────────────────────────
@ObjectType()
export class OrderStatusUpdate {
    @Field(() => ID)
    orderId: string;

    @Field()
    newStatus: string;

    @Field()
    previousStatus: string;

    @Field(() => GraphQLISODateTime)
    updatedAt: Date;
}

@ObjectType()
export class NewMessage {
    @Field(() => ID)
    id: string;

    @Field()
    content: string;

    @Field(() => User)
    sender: User;

    @Field(() => ID)
    roomId: string;

    @Field(() => GraphQLISODateTime)
    sentAt: Date;
}

// Trigger event names (constants prevent typos):
export const ORDER_STATUS_UPDATED = 'orderStatusUpdated';
export const NEW_MESSAGE          = 'newMessage';
export const USER_JOINED_ROOM     = 'userJoinedRoom';

// ── Subscription resolver ──────────────────────────────────────────────────────
import {
    Resolver, Subscription, Mutation, Args,
    ResolveField, Parent, ID, Context,
} from '@nestjs/graphql';
import { PubSub } from 'graphql-subscriptions';
import { Inject } from '@nestjs/common';
import { withFilter } from 'graphql-subscriptions';

@Resolver()
export class OrderSubscriptionResolver {
    constructor(
        @Inject(PUB_SUB) private readonly pubSub: PubSub,
        private readonly orderService: OrderService,
    ) {}

    // ── Basic subscription — all events ───────────────────────────────────────
    @Subscription(() => OrderStatusUpdate, {
        name:        'orderStatusUpdated',
        description: 'Subscribe to status changes for any order',
    })
    orderStatusUpdated() {
        // Returns an AsyncIterator — NestJS uses it to push events to the client
        return this.pubSub.asyncIterableIterator(ORDER_STATUS_UPDATED);
    }

    // ── Filtered subscription — only events matching a condition ──────────────
    @Subscription(() => OrderStatusUpdate, {
        name: 'orderUpdated',
        filter(payload: { orderStatusUpdated: OrderStatusUpdate }, variables: { orderId: string }) {
            // filter() receives the event payload and the subscription variables
            // Return true to send to THIS subscriber, false to skip
            return payload.orderStatusUpdated.orderId === variables.orderId;
        },
        resolve(payload: { orderStatusUpdated: OrderStatusUpdate }): OrderStatusUpdate {
            // resolve() transforms the raw event before sending to client
            return payload.orderStatusUpdated;
        },
    })
    orderUpdated(@Args('orderId', { type: () => ID }) orderId: string) {
        return this.pubSub.asyncIterableIterator(ORDER_STATUS_UPDATED);
    }

    // ── Authenticated subscription — filter based on context ──────────────────
    @Subscription(() => NewMessage, {
        name: 'newMessage',
        filter(
            payload: { newMessage: NewMessage },
            variables: { roomId: string },
            context: { req: Request },
        ) {
            const userId = (context.req as any).user?.id;
            // Only deliver if message is for the requested room AND user has access:
            return (
                payload.newMessage.roomId === variables.roomId
                // Could also check if userId is a member of roomId
            );
        },
    })
    @UseGuards(GqlAuthGuard)
    newMessage(@Args('roomId', { type: () => ID }) roomId: string) {
        return this.pubSub.asyncIterableIterator(NEW_MESSAGE);
    }
```

**Q8. How do you scale subscriptions beyond a single Node.js process in production?**

A: The in-memory `PubSub` only works within one process. In a horizontally scaled deployment (multiple pods/processes), events published in process A won't reach subscribers connected to process B. Redis PubSub solves this:

```typescript
// npm install graphql-redis-subscriptions ioredis

import { RedisPubSub } from 'graphql-redis-subscriptions';
import Redis from 'ioredis';

// ── Redis PubSub — shared across all instances ────────────────────────────────
@Module({
    imports: [ConfigModule],
    providers: [
        {
            provide: PUB_SUB,
            inject:  [ConfigService],
            useFactory: (config: ConfigService): RedisPubSub => {
                const options = {
                    host:     config.get('REDIS_HOST'),
                    port:     config.get<number>('REDIS_PORT'),
                    password: config.get('REDIS_PASSWORD'),
                    retryStrategy: (times: number) => Math.min(times * 50, 2000),
                };
                return new RedisPubSub({
                    publisher:  new Redis(options),
                    subscriber: new Redis(options),
                    // Two separate connections: one for publishing, one for subscribing
                    // This is required by Redis's PubSub model
                });
            },
        },
    ],
    exports: [PUB_SUB],
})
export class PubSubModule {}

// ── How it works across instances ─────────────────────────────────────────────
//
// Instance A (pod 1): client connected, listening to ORDER_STATUS_UPDATED
// Instance B (pod 2): mutation called → pubSub.publish(ORDER_STATUS_UPDATED, {...})
//   → Instance B's RedisPubSub publishes to Redis channel
//   → Redis broadcasts to ALL subscribers (both pods)
//   → Instance A's RedisPubSub receives it
//   → Delivers to the WebSocket client connected to Instance A
//
// Result: events flow across all instances via Redis as the message broker

// ── WebSocket authentication ───────────────────────────────────────────────────
// HTTP guards run on the initial WebSocket handshake, not per-message.
// Pass credentials in connectionParams from the client:
GraphQLModule.forRoot({
    subscriptions: {
        'graphql-ws': {
            onConnect: async (connectionParams) => {
                const token = connectionParams?.Authorization?.replace('Bearer ', '');
                if (!token) throw new Error('Unauthenticated');

                const user = await authService.validateToken(token);
                if (!user) throw new Error('Invalid token');

                // Returned value is merged into context for ALL operations on this connection:
                return { user };
            },
            onDisconnect: async (ctx) => {
                // Cleanup when client disconnects
                console.log('Client disconnected');
            },
        },
    },
    context: ({ req, extra }) => ({
        req,
        user: extra?.user, // From onConnect
    }),
});

// Resolver uses context for auth:
@Subscription(() => NewMessage, {
    filter(payload, variables, context) {
        const userId = context.user?.id;
        if (!userId) throw new ForbiddenError('Not authenticated');
        return payload.newMessage.roomId === variables.roomId;
    },
})
```

## Section 7: Guards, Context, and Authentication

**Q9. How do authentication and guards work in GraphQL — how does NestJS bridge HTTP guards with GraphQL?**

A: NestJS guards work in GraphQL but the `ExecutionContext` is different — it's a GraphQL context, not HTTP. The `GqlExecutionContext` adapts it:

```typescript
import {
    Injectable, CanActivate, ExecutionContext,
    createParamDecorator,
} from '@nestjs/common';
import { GqlExecutionContext } from '@nestjs/graphql';
import { AuthGuard } from '@nestjs/passport';

// ── GQL-aware auth guard ───────────────────────────────────────────────────────
@Injectable()
export class GqlAuthGuard extends AuthGuard('jwt') {
    // Override getRequest() — GraphQL context vs HTTP context:
    getRequest(context: ExecutionContext): Request {
        const ctx = GqlExecutionContext.create(context);
        return ctx.getContext<{ req: Request }>().req;
        // GraphQL context holds 'req' — extract it for the JWT strategy
    }
}

// ── Role-based guard ───────────────────────────────────────────────────────────
@Injectable()
export class RolesGuard implements CanActivate {
    constructor(private readonly reflector: Reflector) {}

    canActivate(context: ExecutionContext): boolean {
        const requiredRoles = this.reflector.getAllAndOverride<UserRole[]>('roles', [
            context.getHandler(),
            context.getClass(),
        ]);
        if (!requiredRoles) return true;

        const ctx     = GqlExecutionContext.create(context);
        const request = ctx.getContext<{ req: any }>().req;
        const user    = request.user;

        return requiredRoles.some(role => user?.role === role);
    }
}

// ── Custom decorators to access context ───────────────────────────────────────
export const CurrentUser = createParamDecorator(
    (_data: unknown, context: ExecutionContext): User => {
        const ctx = GqlExecutionContext.create(context);
        return ctx.getContext<{ req: any }>().req.user;
    },
);

export const Roles = (...roles: UserRole[]) => SetMetadata('roles', roles);

// ── Usage on resolvers ────────────────────────────────────────────────────────
@Resolver(() => User)
export class UserResolver {
    @Query(() => User, { name: 'me' })
    @UseGuards(GqlAuthGuard)               // JWT required
    async getCurrentUser(
        @CurrentUser() user: User,         // From JWT payload via guard
    ): Promise<User> {
        return this.userService.findById(user.id);
    }

    @Mutation(() => User, { name: 'promoteToAdmin' })
    @UseGuards(GqlAuthGuard, RolesGuard)   // JWT + role check
    @Roles(UserRole.ADMIN)                 // Only admins
    async promoteToAdmin(
        @Args('userId', { type: () => ID }) userId: string,
        @CurrentUser() admin: User,
    ): Promise<User> {
        return this.userService.setRole(userId, UserRole.ADMIN);
    }
}

// ── Global guard setup ─────────────────────────────────────────────────────────
@Module({
    providers: [
        {
            provide: APP_GUARD,
            useClass: GqlAuthGuard,        // Applied to ALL resolvers globally
        },
    ],
})
export class AppModule {}

// Opt-out for public resolvers:
export const Public = () => SetMetadata('isPublic', true);

// Modified GqlAuthGuard that respects @Public():
@Injectable()
export class GqlAuthGuard extends AuthGuard('jwt') {
    constructor(private reflector: Reflector) { super(); }

    canActivate(context: ExecutionContext) {
        const isPublic = this.reflector.getAllAndOverride<boolean>('isPublic', [
            context.getHandler(),
            context.getClass(),
        ]);
        if (isPublic) return true;
        return super.canActivate(context);
    }

    getRequest(context: ExecutionContext) {
        const ctx = GqlExecutionContext.create(context);
        return ctx.getContext<{ req: Request }>().req;
    }
}

// Usage:
@Query(() => [User], { name: 'publicUsers' })
@Public()              // No auth required — accessible without JWT
async getPublicUsers() {
    return this.userService.findVerified();
}
```

## Section 8: Error Handling

**Q10. How does error handling work in GraphQL — what is the difference from REST error handling?**

A: GraphQL never returns HTTP 4xx/5xx for application errors (except 200 for success, 400 for bad request body, 500 for catastrophic failure). Application errors are returned inside the `errors` array in a `200 OK` response. NestJS maps exceptions to GraphQL errors:

```typescript
import {
    NotFoundException, ForbiddenException,
    BadRequestException,
} from '@nestjs/common';
import {
    UserInputError, ForbiddenError,
    ApolloError,
} from '@nestjs/apollo';

// ── How GraphQL returns errors ─────────────────────────────────────────────────
// Successful response:
// { "data": { "user": { "id": "1", "email": "a@b.com" } } }

// Error response (still HTTP 200):
// {
//   "data": { "user": null },
//   "errors": [{
//     "message": "User not found",
//     "extensions": { "code": "NOT_FOUND", "path": ["user"] }
//   }]
// }

// Both can appear together (partial success — some fields resolved, some errored)

// ── NestJS exception → GraphQL error mapping ──────────────────────────────────
@Resolver(() => User)
export class UserResolver {
    @Query(() => User, { nullable: true, name: 'user' })
    async getUser(@Args('id', { type: () => ID }) id: string): Promise<User> {
        const user = await this.userService.findById(id);
        if (!user) {
            // NestJS HttpException → converted to GraphQL error by filter
            throw new NotFoundException(`User ${id} not found`);
            // OR use Apollo's typed errors directly:
            // throw new UserInputError(`User ${id} not found`, { id });
        }
        return user;
    }
}

// ── Custom exception filter for GraphQL ───────────────────────────────────────
import { Catch, ArgumentsHost } from '@nestjs/common';
import { GqlExceptionFilter, GqlArgumentsHost } from '@nestjs/graphql';
import { GraphQLError } from 'graphql';

@Catch()
export class GqlExceptionFilter implements GqlExceptionFilter {
    catch(exception: unknown, host: ArgumentsHost) {
        const gqlHost = GqlArgumentsHost.create(host);

        if (exception instanceof NotFoundException) {
            return new GraphQLError(exception.message, {
                extensions: {
                    code:      'NOT_FOUND',
                    timestamp: new Date().toISOString(),
                },
            });
        }

        if (exception instanceof ForbiddenException) {
            return new GraphQLError(exception.message, {
                extensions: { code: 'FORBIDDEN' },
            });
        }

        if (exception instanceof BadRequestException) {
            const response = exception.getResponse() as any;
            return new GraphQLError('Validation failed', {
                extensions: {
                    code:   'BAD_USER_INPUT',
                    fields: response.message,
                },
            });
        }

        // Unknown error — don't leak internals in production
        return new GraphQLError('Internal server error', {
            extensions: { code: 'INTERNAL_SERVER_ERROR' },
        });
    }
}

// ── Apollo Server error formatting ────────────────────────────────────────────
GraphQLModule.forRoot({
    formatError: (error: GraphQLError) => {
        const originalError = error.originalError;

        // In production, hide internal error details:
        if (process.env.NODE_ENV === 'production') {
            if (!originalError || !(originalError instanceof HttpException)) {
                return new GraphQLError('Internal server error', {
                    extensions: { code: 'INTERNAL_SERVER_ERROR' },
                });
            }
        }

        return {
            message:    error.message,
            locations:  error.locations,
            path:       error.path,
            extensions: {
                ...error.extensions,
                timestamp: new Date().toISOString(),
            },
        };
    },
});

// ── Validation errors via class-validator ──────────────────────────────────────
// ValidationPipe automatically converts validation errors to UserInputError:
@Mutation(() => User)
@UsePipes(new ValidationPipe({ transform: true, whitelist: true }))
async createUser(@Args('input') input: CreateUserInput): Promise<User> {

}
```

## Section 10: Scenario-Based Questions

**Q12. "Clients are complaining that fetching a list of 50 posts each with their author takes 10 seconds. Diagnose and fix."**

A: Classic N+1 — 50 posts + 50 separate author queries. The fix is DataLoader batching:

```typescript
// ── Diagnosis ─────────────────────────────────────────────────────────────────
// Enable Apollo tracing to see per-resolver timing:
GraphQLModule.forRoot({
    plugins: [ApolloServerPluginInlineTrace()],
});
// Apollo Studio / Apollo Sandbox shows per-field execution times
// → 'author' field: 200ms × 50 = 10,000ms

// Or: enable ORM query logging
// → 50 sequential SELECT queries for users by ID

// ── The broken code ───────────────────────────────────────────────────────────
@Resolver(() => Post)
export class PostResolver {
    @ResolveField(() => User)
    async author(@Parent() post: Post): Promise<User> {
        return this.userService.findById(post.authorId); // Called 50 times!
    }
}

// ── Fix: DataLoader ────────────────────────────────────────────────────────────
@Injectable({ scope: Scope.REQUEST })
export class UserByIdLoader {
    private loader: DataLoader<string, User | null>;

    constructor(private readonly userService: UserService) {
        this.loader = new DataLoader(async (ids: readonly string[]) => {
            // ONE query for ALL ids:
            const users = await this.userService.findByIds([...ids]);
            const map   = new Map(users.map(u => [u.id, u]));
            return ids.map(id => map.get(id) ?? null);
        });
    }

    load(id: string): Promise<User | null> {
        return this.loader.load(id);
    }
}

@Resolver(() => Post)
export class PostResolver {
    constructor(private readonly userLoader: UserByIdLoader) {}

    @ResolveField(() => User, { nullable: true })
    async author(@Parent() post: Post): Promise<User | null> {
        return this.userLoader.load(post.authorId);
        // 50 .load() calls → batched into 1 query: WHERE id IN (id1, id2, ..., id50)
    }
}

// Result: 2 queries total (1 for posts, 1 for all authors) → < 50ms
```

**Q13. "Design a real-time collaborative task board: queries to list tasks, mutations to create/update tasks, and subscriptions for live updates."**

A: The complete resolver architecture for a real-time feature:

```typescript
// ── Types ─────────────────────────────────────────────────────────────────────
@ObjectType()
export class Task {
    @Field(() => ID)   id: string;
    @Field()           title: string;
    @Field()           description: string;
    @Field()           status: string;     // 'todo' | 'in_progress' | 'done'
    @Field(() => ID)   boardId: string;
    @Field(() => User, { nullable: true }) assignee?: User;
    @Field(() => ID, { nullable: true })   assigneeId?: string;
    @Field(() => Int)  position: number;   // For ordering
    @Field(() => GraphQLISODateTime) createdAt: Date;
    @Field(() => GraphQLISODateTime) updatedAt: Date;
}

@ObjectType()
export class TaskEvent {
    @Field()
    type: string;    // 'CREATED' | 'UPDATED' | 'DELETED' | 'MOVED'

    @Field(() => Task)
    task: Task;

    @Field(() => User)
    triggeredBy: User;

    @Field(() => GraphQLISODateTime)
    occurredAt: Date;
}

@InputType()
export class CreateTaskInput {
    @Field() @MinLength(1) @MaxLength(200) title: string;
    @Field({ nullable: true }) description?: string;
    @Field(() => ID) boardId: string;
    @Field(() => ID, { nullable: true }) assigneeId?: string;
    @Field(() => Int, { defaultValue: 0 }) position: number;
}

@InputType()
export class UpdateTaskInput {
    @Field({ nullable: true }) @MaxLength(200) title?: string;
    @Field({ nullable: true }) description?: string;
    @Field({ nullable: true }) status?: string;
    @Field(() => ID, { nullable: true }) assigneeId?: string;
    @Field(() => Int, { nullable: true }) position?: number;
}

// Event channels:
const TASK_EVENTS = (boardId: string) => `taskEvents:${boardId}`;

// ── Resolver ──────────────────────────────────────────────────────────────────
@Resolver(() => Task)
@UseGuards(GqlAuthGuard)
export class TaskResolver {
    constructor(
        @Inject(PUB_SUB) private readonly pubSub: PubSub,
        private readonly taskService:   TaskService,
        private readonly userByIdLoader: UserByIdLoader,
    ) {}

    // ── Queries ───────────────────────────────────────────────────────────────
    @Query(() => [Task], { name: 'tasks' })
    async getTasks(
        @Args('boardId', { type: () => ID }) boardId: string,
        @Args('status', { nullable: true })   status?: string,
        @CurrentUser() user: User,
    ): Promise<Task[]> {
        await this.taskService.assertBoardAccess(boardId, user.id);
        return this.taskService.findByBoard(boardId, { status });
    }

    @Query(() => Task, { name: 'task', nullable: true })
    async getTask(
        @Args('id', { type: () => ID }) id: string,
        @CurrentUser() user: User,
    ): Promise<Task | null> {
        const task = await this.taskService.findById(id);
        if (task) await this.taskService.assertBoardAccess(task.boardId, user.id);
        return task;
    }

    // ── Field resolver ────────────────────────────────────────────────────────
    @ResolveField(() => User, { nullable: true })
    async assignee(@Parent() task: Task): Promise<User | null> {
        if (!task.assigneeId) return null;
        return this.userByIdLoader.load(task.assigneeId); // DataLoader batch
    }

    // ── Mutations ─────────────────────────────────────────────────────────────
    @Mutation(() => Task, { name: 'createTask' })
    async createTask(
        @Args('input') input: CreateTaskInput,
        @CurrentUser() user: User,
    ): Promise<Task> {
        await this.taskService.assertBoardAccess(input.boardId, user.id);

        const task = await this.taskService.create({ ...input, createdById: user.id });

        // Publish to all subscribers of this board:
        await this.pubSub.publish(TASK_EVENTS(input.boardId), {
            taskEvent: { type: 'CREATED', task, triggeredBy: user, occurredAt: new Date() },
        });

        return task;
    }

    @Mutation(() => Task, { name: 'updateTask' })
    async updateTask(
        @Args('id', { type: () => ID }) id: string,
        @Args('input') input: UpdateTaskInput,
        @CurrentUser() user: User,
    ): Promise<Task> {
        const existing = await this.taskService.findByIdOrThrow(id);
        await this.taskService.assertBoardAccess(existing.boardId, user.id);

        const updated = await this.taskService.update(id, input);

        await this.pubSub.publish(TASK_EVENTS(existing.boardId), {
            taskEvent: { type: 'UPDATED', task: updated, triggeredBy: user, occurredAt: new Date() },
        });

        return updated;
    }

    @Mutation(() => Boolean, { name: 'deleteTask' })
    async deleteTask(
        @Args('id', { type: () => ID }) id: string,
        @CurrentUser() user: User,
    ): Promise<boolean> {
        const task = await this.taskService.findByIdOrThrow(id);
        await this.taskService.assertBoardAccess(task.boardId, user.id);

        await this.taskService.delete(id);

        await this.pubSub.publish(TASK_EVENTS(task.boardId), {
            taskEvent: { type: 'DELETED', task, triggeredBy: user, occurredAt: new Date() },
        });

        return true;
    }

    // ── Subscription ──────────────────────────────────────────────────────────
    @Subscription(() => TaskEvent, {
        name: 'taskEvents',
        filter(
            payload: { taskEvent: TaskEvent },
            variables: { boardId: string },
            context: { user: User },
        ) {
            // Only send events for the requested board to this subscriber:
            return payload.taskEvent.task.boardId === variables.boardId;
            // Additional filter: don't send back events triggered BY this user
            // (they already see the mutation response):
            // && payload.taskEvent.triggeredBy.id !== context.user?.id
        },
    })
    taskEvents(@Args('boardId', { type: () => ID }) boardId: string) {
        return this.pubSub.asyncIterableIterator(TASK_EVENTS(boardId));
    }
}
```

**Tip for interviews:** Six things separate strong candidates on this topic: (1) explaining **why `@ResolveField()` causes the N+1 problem** and what DataLoader does to fix it — DataLoader collects all `.load()` calls made in a single event loop tick and batches them into one database query, and the critical detail is that the DataLoader must be **REQUEST-scoped** (`scope: Scope.REQUEST`) to prevent cross-request data leaks from the per-request cache; (2) knowing that **GraphQL always returns HTTP 200** for application errors — the `errors` array in the response body carries error information, and HTTP 4xx/5xx only appear for transport-level failures (invalid JSON, missing query), which changes how you write API clients and error handling middleware; (3) being precise about the **`filter()` function in `@Subscription()`** — it receives `(payload, variables, context)` and returns a boolean: `true` delivers the event to this subscriber, `false` skips it, and it's how you implement per-user or per-room event routing without sending all events to all clients; (4) understanding **`GqlExecutionContext.create(context)`** — guards and interceptors receive an `ExecutionContext` which doesn't expose the GraphQL context directly; you must call `GqlExecutionContext.create(context).getContext()` to access `req` and `user` inside a guard, and forgetting this is the most common auth bug in NestJS GraphQL projects; (5) knowing the **two approach options** (code-first vs schema-first) and articulating why code-first is generally preferred in NestJS — TypeScript classes are the single source of truth for both types and schema, eliminating drift between SDL and implementation; and (6) knowing that **in-memory `PubSub` doesn't work with multiple processes** — in a horizontally scaled production deployment, you must use Redis PubSub (or Postgres LISTEN/NOTIFY) so that events published in one pod are delivered to subscribers connected to other pods.
