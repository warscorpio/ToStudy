## Topic A: Mapped Type Fundamentals

### Section A1: Core Mechanics

**Q1. What is a mapped type, and what is the fundamental syntax that defines one?**

A: A mapped type constructs a new object type by iterating over the keys of an existing type and specifying what each property's type should be. The syntax is a type alias with a computed property signature: `{ [K in UnionType]: ValueType }`. The `in` keyword iterates `K` over each member of `UnionType`, and `ValueType` is an expression (which may reference `K`) that becomes the type of the property at key `K`. The most common form uses `keyof T` as the union — mapping over all keys of an existing type `T`.

```typescript
// The identity mapped type — same shape as T, same types:
type Identity<T> = {
  [K in keyof T]: T[K]; // K iterates over T's keys; T[K] preserves each value type
};

// Mapping over a fixed union (non-homomorphic):
type StringRecord = {
  [K in 'name' | 'email' | 'phone']: string;
};
// Result: { name: string; email: string; phone: string }

// Three parts of a mapped type:
// { [K  in  keyof T]:  T[K]       }
//    ↑       ↑          ↑
//  type   iterates   value type
//  param  over this  (may reference K)

// Mapped types always produce object types — not primitives, not arrays.
// The result shape mirrors the iterated union.
```

**Q2. What does `keyof T` produce, and what are its edge cases for different type shapes?**

A: `keyof T` produces a union of all **enumerable property keys** of type `T`. For most interfaces and object types, this is a union of string literals. For types with numeric keys, the union includes `number`. For types with symbol properties, the union includes `unique symbol`. Three important edge cases: `keyof any = string | number | symbol`; `keyof { [key: string]: V } = string | number` (index signature — number included because `obj[0]` and `obj['0']` access the same value); `keyof never = string | number | symbol`; `keyof unknown = never`.

```typescript
interface User { id: number; name: string; email: string; }
type UserKeys = keyof User; // "id" | "name" | "email"

// String index signature:
type Dict = { [key: string]: number };
type DictKeys = keyof Dict; // string | number (number included because obj[0] === obj['0'])

// Numeric keys:
type Point = { 0: string; 1: number };
type PointKeys = keyof Point; // 0 | 1  (numeric literals, not strings!)

// Class with methods:
class Circle { radius = 0; area() { return Math.PI * this.radius ** 2; } }
type CircleKeys = keyof Circle; // "radius" | "area"

// Edge cases:
type K1 = keyof any;     // string | number | symbol
type K2 = keyof never;   // string | number | symbol (never has all keys)
type K3 = keyof unknown; // never (unknown has no known keys)
type K4 = keyof {};      // never (empty object has no own keys)

// keyof in mapped types — iterates over the union:
type Stringified<T> = { [K in keyof T]: string };
// Iterates over "id" | "name" | "email" for User
// Result: { id: string; name: string; email: string }
```

**Q3. What is an indexed access type `T[K]`, and how does it work with union keys?**

A: An indexed access type `T[K]` retrieves the type of property `K` in type `T`. When `K` is a union type, `T[K]` distributes across the union and returns the union of all the corresponding property types. This makes `T[keyof T]` produce the union of all value types in `T`, and makes mapped types like `{ [K in keyof T]: T[K] }` correctly associate each key with its own value type — not the union of all value types.

```typescript
interface Product { id: number; name: string; price: number; inStock: boolean; }

// Single key access:
type ProductId   = Product['id'];    // number
type ProductName = Product['name'];  // string

// Union key access — distributes over the union:
type StringProps = Product['name'];                    // string
type NumProps    = Product['id' | 'price'];            // number | number = number
type AllValues   = Product[keyof Product];             // number | string | boolean

// In a mapped type, T[K] gets each individual property's type — NOT the union:
type Same<T> = { [K in keyof T]: T[K] };
// For Product:
// K = 'id':      T[K] = Product['id']    = number
// K = 'name':    T[K] = Product['name']  = string
// K = 'price':   T[K] = Product['price'] = number
// K = 'inStock': T[K] = Product['inStock'] = boolean
// Result: { id: number; name: string; price: number; inStock: boolean } ✓

// Nested indexed access:
type Address = { street: string; city: string; zip: string; };
type UserWithAddress = { id: number; address: Address };
type Zip = UserWithAddress['address']['zip']; // string (chain nested access)
type AddressValues = UserWithAddress['address'][keyof Address]; // string (all address values)
```

**Q4. What is the difference between mapping over `keyof T` and mapping over an explicit union type?**

A: The difference is homomorphism — whether the mapped type is "derived from" a known source type. Mapping over `keyof T` is **homomorphic**: TypeScript knows the result is structurally related to `T` and automatically copies `readonly` and `?` modifiers from `T`'s properties. Mapping over an explicit union like `'a' | 'b' | 'c'` (or `string`) is **non-homomorphic**: TypeScript has no source type to copy modifiers from, so the result has no modifiers unless you explicitly add them. This is why `Partial<{ readonly x: number }>` gives `{ readonly x?: number }` — `readonly` from the source is preserved even though `Partial` only adds `?`.

```typescript
// Homomorphic — preserves modifiers from source type T:
type Partial<T>   = { [K in keyof T]?: T[K] };
type Readonly<T>  = { readonly [K in keyof T]: T[K] };

// Source type has readonly:
type Source = { readonly id: number; name?: string };

type P = Partial<Source>;
// { readonly id?: number; name?: string }
//    ↑ readonly PRESERVED from Source.id, even though Partial only adds ?

// Non-homomorphic — no source type, no modifier preservation:
type StringMap = { [K in 'a' | 'b']: string };
// { a: string; b: string } — no readonly, no ?, regardless of any source

// Record<K, V> is non-homomorphic:
type R = Record<'x' | 'y', number>;
// { x: number; y: number } — K extends keyof any, not keyof T

// Why it matters — Partial preserves readonly:
interface Config { readonly host: string; readonly port: number; timeout?: number; }
type PartialConfig = Partial<Config>;
// { readonly host?: string; readonly port?: number; timeout?: number }
// readonly is preserved on host and port — homomorphic behavior ✓
```

**Q5. How does TypeScript resolve mapped types step by step — walk through the evaluation?**

A: TypeScript evaluates a mapped type `{ [K in keyof T]: F(K, T) }` by: (1) Computing `keyof T` to get the union of keys; (2) For each member `K` of that union, substituting `K` into the value expression `F(K, T)` to get a single property type; (3) Copying modifiers from `T[K]` to the result property (for homomorphic types), then applying any explicit modifier additions/removals; (4) Assembling all the resulting properties into a new object type. The result is structurally a fresh type, but TypeScript understands its relationship to `T` for modifier preservation.

```typescript
// Full resolution trace for Partial<User>:
interface User { id: number; name: string; email?: string; }
type Partial<T> = { [K in keyof T]?: T[K] };

// type PartialUser = Partial<User>
// Step 1: keyof User = 'id' | 'name' | 'email'
// Step 2: Iterate K over 'id' | 'name' | 'email':
//   K = 'id':
//     Value: T[K] = User['id'] = number
//     Modifier from source: not optional (User.id has no ?)
//     Apply mapped type's ?: → id becomes optional
//     Result property: id?: number
//   K = 'name':
//     Value: User['name'] = string
//     Modifier from source: not optional
//     Apply ?: → name becomes optional
//     Result: name?: string
//   K = 'email':
//     Value: User['email'] = string (the ? from User.email is the modifier; the type is string)
//     Source is already optional; applying ?: again is idempotent
//     Result: email?: string
// Step 3: Assemble:
//   { id?: number; name?: string; email?: string }

type PartialUser = Partial<User>;
// PartialUser = { id?: number; name?: string; email?: string } ✓
```

## Topic B: Modifiers & Key Remapping

### Section B1: Modifier Syntax

**Q6. What are the `readonly` and `?` modifiers in mapped types, and how do you add vs remove them?**

A: Mapped types can add or remove the two property modifiers — `readonly` (prevents assignment after initialization) and `?` (makes the property optional). Adding a modifier: write it before the key (`readonly [K in ...]` for readonly, `[K in ...]?` after the bracket for optional). Removing a modifier: prefix it with `-` (`-readonly` removes readonly, `-?` removes optional). Adding can also be written with `+` prefix (`+readonly`, `+?`) but `+` is the default and usually omitted.

```typescript
// ─── ADDING MODIFIERS ──────────────────────────────────────────────────────

type MakeReadonly<T>  = { readonly [K in keyof T]: T[K] };
type MakeOptional<T>  = { [K in keyof T]?: T[K] };
type MakeBoth<T>      = { readonly [K in keyof T]?: T[K] };

// ─── REMOVING MODIFIERS ────────────────────────────────────────────────────

type Mutable<T>   = { -readonly [K in keyof T]: T[K] }; // removes readonly from ALL props
type Required<T>  = { [K in keyof T]-?: T[K] };          // removes ? from ALL props
type Concrete<T>  = { -readonly [K in keyof T]-?: T[K] }; // removes BOTH

// ─── DEMONSTRATION ─────────────────────────────────────────────────────────

type Frozen = { readonly id: number; readonly name?: string };

type Thawed = Mutable<Frozen>;
// { id: number; name?: string }  ← readonly removed, ? preserved

type Filled = Required<Frozen>;
// { readonly id: number; readonly name: string }  ← ? removed, readonly preserved

type Plain = Concrete<Frozen>;
// { id: number; name: string }  ← both removed ✓

// ─── IDEMPOTENCY ───────────────────────────────────────────────────────────

// Adding readonly to an already-readonly property: no-op
// Removing ? from a non-optional property: no-op
// TypeScript handles these gracefully — no errors, no double-modifier effects
```

**Q7. What is the `as` clause for key remapping (TypeScript 4.1+), and what patterns does it unlock?**

A: The `as` clause in a mapped type renames the key produced for each iteration: `{ [K in keyof T as NewKeyExpression]: T[K] }`. The expression after `as` must produce a type that is a valid property key (`string | number | symbol`). It can reference `K` to transform the original key into a new key. The `as` clause enables three patterns: (1) **rename keys** using template literal types; (2) **filter keys** by mapping unwanted keys to `never` (a key with type `never` is excluded from the result); (3) **generate new keys** from old ones using conditional types or template literals.

```typescript
// ─── RENAMING KEYS ─────────────────────────────────────────────────────────

type Prefixed<T, P extends string> = {
  [K in keyof T as `${P}_${string & K}`]: T[K]
  //                ↑ template literal using K as a string
};

type User = { id: number; name: string };
type PrefixedUser = Prefixed<User, 'user'>;
// { user_id: number; user_name: string }

// Capitalize keys:
type Capitalized<T> = {
  [K in keyof T as Capitalize<string & K>]: T[K]
};
type CapUser = Capitalized<User>;
// { Id: number; Name: string }

// ─── FILTERING KEYS (as never removes the key) ─────────────────────────────

type OnlyStrings<T> = {
  [K in keyof T as T[K] extends string ? K : never]: T[K]
  //               ↑ if value is string, keep K; otherwise → never (removed)
};

interface Mixed { id: number; name: string; active: boolean; label: string }
type StringFields = OnlyStrings<Mixed>;
// { name: string; label: string }   id and active are removed ✓

// ─── GENERATING NEW KEYS ─────────────────────────────────────────────────

type Getters<T> = {
  [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K]
};

type UserGetters = Getters<User>;
// { getId: () => number; getName: () => string }
```

**Q8. How do template literal types combine with mapped types for systematic type generation?**

A: Template literal types (`\`prefix${T}suffix\``) used in the `as` clause of a mapped type allow systematic generation of new property names from existing ones. TypeScript distributes template literals over union types: if `K = 'click' | 'focus'`, then `` `on${Capitalize<K>}` `` produces `'onClick' | 'onFocus'`. This enables generating: event handler maps from event name unions, getter/setter pairs from data properties, API endpoint maps from resource names, and more — all statically typed without code generation.

```typescript
type EventNames = 'click' | 'focus' | 'blur' | 'change';

// Generate event handler type map:
type EventHandlers = {
  [E in EventNames as `on${Capitalize<E>}`]: (event: Event) => void;
};
// {
//   onClick:  (event: Event) => void;
//   onFocus:  (event: Event) => void;
//   onBlur:   (event: Event) => void;
//   onChange: (event: Event) => void;
// }

// Getter/setter pair generation from data model:
type GettersAndSetters<T> = {
  [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K];
} & {
  [K in keyof T as `set${Capitalize<string & K>}`]: (value: T[K]) => void;
};

interface Config { host: string; port: number; timeout: number; }
type ConfigAccessors = GettersAndSetters<Config>;
// {
//   getHost: () => string;     setHost: (value: string) => void;
//   getPort: () => number;     setPort: (value: number) => void;
//   getTimeout: () => number;  setTimeout: (value: number) => void;
// }

// API endpoint generation:
type Resources = 'user' | 'product' | 'order';
type ApiEndpoints = {
  [R in Resources as `get${Capitalize<R>}s`]: () => Promise<unknown[]>;
} & {
  [R in Resources as `get${Capitalize<R>}ById`]: (id: string) => Promise<unknown>;
} & {
  [R in Resources as `create${Capitalize<R>}`]: (data: unknown) => Promise<unknown>;
};
// { getUsers, getUserById, createUser, getProducts, getProductById, createProduct, ... }
```

## Topic C: Utility Types & Custom Patterns

### Section C1: Standard Utility Types Dissected

**Q9. How are `Partial<T>`, `Required<T>`, and `Readonly<T>` implemented, and what are their modifier semantics?**

A: These three utility types each apply a single modifier change across all properties. `Partial` adds `?`; `Required` removes `?` with `-?`; `Readonly` adds `readonly`. All three are homomorphic (use `keyof T`) so they preserve any existing modifiers from the source type that they don't explicitly change. `Partial` preserves existing `readonly`. `Required` preserves existing `readonly`. `Readonly` preserves existing `?`.

```typescript
// Implementations:
type Partial<T>  = { [K in keyof T]?:          T[K] }; // adds ?
type Required<T> = { [K in keyof T]-?:          T[K] }; // removes ? with -?
type Readonly<T> = { readonly [K in keyof T]:   T[K] }; // adds readonly

// Resolution traces:

// Partial<{ id: number; name?: string }>:
// K='id':   id?:  number    (was not optional, now is; no readonly to copy)
// K='name': name?: string   (was optional, stays optional)
// Result: { id?: number; name?: string }

// Required<{ readonly id: number; name?: string }>:
// K='id':   readonly id:  number  (readonly preserved; ? not present, -? is no-op)
// K='name': name: string          (? removed by -?; no readonly to copy)
// Result: { readonly id: number; name: string }

// Combined — make all readonly AND optional:
type ReadonlyPartial<T> = { readonly [K in keyof T]?: T[K] };

interface Entity { id: number; name: string; createdAt: Date; }
type PartialEntity  = Partial<Entity>;
// { id?: number; name?: string; createdAt?: Date }

type RequiredEntity = Required<Partial<Entity>>;
// { id: number; name: string; createdAt: Date } — back to original ✓

type FrozenEntity = Readonly<Entity>;
// { readonly id: number; readonly name: string; readonly createdAt: Date }
```

**Q10. How are `Pick<T, K>`, `Omit<T, K>`, and `Record<K, V>` implemented?**

A: `Pick` maps over a constrained subset of keys. `Omit` maps over all keys except the excluded ones (implemented via `Exclude`). `Record` maps over a union of any keys to a uniform value type. `Pick` and `Record` are direct mapped types; `Omit` is a composition (`Pick` with `Exclude`).

```typescript
// Implementations:
type Pick<T, K extends keyof T>           = { [P in K]: T[P] };
type Record<K extends keyof any, V>       = { [P in K]: V };
type Omit<T, K extends string | number | symbol> = Pick<T, Exclude<keyof T, K>>;
// Exclude<'a'|'b'|'c', 'b'> = 'a' | 'c'  (filters union members matching K)

// Resolution traces:

interface User { id: number; name: string; email: string; password: string; }

// Pick<User, 'id' | 'name'>:
// K = 'id' | 'name'   (constraint: extends keyof User → must be valid User keys)
// P iterates: 'id', 'name'
// Result: { id: number; name: string }

// Omit<User, 'password'>:
// Exclude<'id'|'name'|'email'|'password', 'password'> = 'id'|'name'|'email'
// Pick<User, 'id'|'name'|'email'>
// Result: { id: number; name: string; email: string }

// Record<'GET' | 'POST' | 'PUT', Handler>:
// P iterates: 'GET', 'POST', 'PUT'
// Each maps to Handler
// Result: { GET: Handler; POST: Handler; PUT: Handler }

// Practical composition:
type UserPublic = Omit<User, 'password'>;       // { id, name, email }
type UserCreate = Omit<User, 'id'>;             // { name, email, password }
type UserUpdate = Partial<Omit<User, 'id'>>;    // { name?, email?, password? }
type UserResponse = Pick<User, 'id' | 'name' | 'email'>; // { id, name, email }
```

**Q11. How do you filter and transform properties by value type using `as never` key remapping?**

A: The `as` clause combined with a conditional type enables property-level filtering. If the conditional resolves to `never`, that property is excluded from the result. If it resolves to `K` (the original key), the property is included. This pattern implements `PickByValue` and `OmitByValue` — selecting properties whose value types match (or don't match) a target type.

```typescript
// Filter-IN: keep only properties whose value type extends V:
type PickByValue<T, V> = {
  [K in keyof T as T[K] extends V ? K : never]: T[K]
};

// Filter-OUT: keep only properties whose value type does NOT extend V:
type OmitByValue<T, V> = {
  [K in keyof T as T[K] extends V ? never : K]: T[K]
};

interface Entity {
  id:        number;
  name:      string;
  email:     string;
  age:       number;
  active:    boolean;
  createdAt: Date;
  tags:      string[];
}

type StringProps   = PickByValue<Entity, string>;
// { name: string; email: string }  — only string-typed properties

type NumberProps   = PickByValue<Entity, number>;
// { id: number; age: number }

type FunctionProps<T> = PickByValue<T, Function>;
// Useful for extracting method names from a class type

type NonMethodProps<T> = OmitByValue<T, Function>;
// Useful for extracting data properties from a class type

// Value type extraction — get the union of all values:
type ValuesOf<T> = T[keyof T];
type EntityValues = ValuesOf<Entity>;
// number | string | boolean | Date | string[]

// Extract keys matching a value type (as a union of keys):
type KeysOfType<T, V> = {
  [K in keyof T]: T[K] extends V ? K : never;
}[keyof T]; // indexed access over keyof T to get the union of matching keys

type StringKeys = KeysOfType<Entity, string>; // "name" | "email"
type NumberKeys = KeysOfType<Entity, number>; // "id" | "age"
```

## Topic D: Advanced Mapped Type Patterns

**Q12. What is a "deep" utility type, and how does conditional recursion enable `DeepPartial` and `DeepReadonly`?**

A: Standard `Partial<T>` makes top-level properties optional, but nested object properties remain required. A deep variant applies the transformation recursively to all nested object types. The pattern: check if the current value type is an object type (using `T extends object`); if so, apply the deep type recursively; if not (primitives, functions, dates), return `T` as-is. The recursion terminates naturally when it reaches non-object types.

```typescript
// DeepPartial — recursively makes all nested properties optional:
type DeepPartial<T> = T extends Date | Function | RegExp
  ? T  // ← these are objects but should not be recursed into
  : T extends object
    ? { [K in keyof T]?: DeepPartial<T[K]> }  // ← recurse into object
    : T; // ← primitive — base case

// DeepReadonly — recursively makes all nested properties readonly:
type DeepReadonly<T> = T extends Date | Function | RegExp
  ? T
  : T extends object
    ? { readonly [K in keyof T]: DeepReadonly<T[K]> }
    : T;

// DeepRequired — recursively makes all nested properties required:
type DeepRequired<T> = T extends Date | Function | RegExp
  ? T
  : T extends object
    ? { [K in keyof T]-?: DeepRequired<T[K]> }
    : T;

// DeepMutable — recursively removes readonly from all nested properties:
type DeepMutable<T> = T extends Date | Function | RegExp
  ? T
  : T extends object
    ? { -readonly [K in keyof T]: DeepMutable<T[K]> }
    : T;

// Resolution trace for DeepPartial:
interface OrderForm {
  customer: { name: string; email: string };
  items: { productId: string; quantity: number }[];
  payment: { method: string; amount: number };
}

type PartialOrderForm = Partial<OrderForm>;
// {
//   customer?: { name: string; email: string }; // nested props still required!
//   items?: { productId: string; quantity: number }[];
//   payment?: { method: string; amount: number };
// }

type DeepPartialOrderForm = DeepPartial<OrderForm>;
// {
//   customer?:  { name?: string; email?: string };   // ← nested props now optional too ✓
//   items?:     { productId?: string; quantity?: number }[];
//   payment?:   { method?: string; amount?: number };
// }

// The Date/Function/RegExp guard prevents infinite recursion on built-in objects:
// Without it: Date extends object → DeepPartial<Date> → { [K in keyof Date]?: ... }
// That would produce { getTime?: ...; toString?: ... } — wrong!
```

**Q13. How does the `as` clause interact with conditional types to enable complex key transformations?**

A: The `as` clause can contain any expression that evaluates to `string | number | symbol | never`, including conditional types with multiple branches, template literal expressions, and utility types. When the conditional type in `as` is complex — involving nested conditions or inference — TypeScript resolves it for each `K` independently, allowing highly specific key transformations: keeping some keys unchanged, renaming others, filtering others to `never`, all in a single mapped type.

```typescript
// Rename optional properties by adding 'Optional' suffix, keep required ones as-is:
type AnnotateOptional<T> = {
  [K in keyof T as undefined extends T[K]
    ? `${string & K}_optional`
    : K
  ]: T[K]
};

interface Form { name: string; email: string; phone?: string; bio?: string; }
type AnnotatedForm = AnnotateOptional<Form>;
// {
//   name:          string;
//   email:         string;
//   phone_optional?: string; // renamed!
//   bio_optional?:   string; // renamed!
// }

// Generate both a required key and its optional variant:
type WithDefaults<T> = {
  [K in keyof T as K]: T[K];           // required version
} & {
  [K in keyof T as `${string & K}Default`]: T[K]; // default value properties
};

type ThemeConfig = { color: string; size: number };
type ThemeWithDefaults = WithDefaults<ThemeConfig>;
// { color: string; size: number; colorDefault: string; sizeDefault: number }

// Conditional rename based on value type:
type SmartRename<T> = {
  [K in keyof T as T[K] extends (...args: any[]) => any
    ? `${string & K}Handler`    // methods → rename with Handler suffix
    : T[K] extends boolean
      ? `is${Capitalize<string & K>}` // booleans → rename with is prefix
      : K                             // everything else → keep as-is
  ]: T[K]
};

interface Widget {
  label:   string;
  onClick: () => void;
  visible: boolean;
  count:   number;
}

type RenamedWidget = SmartRename<Widget>;
// {
//   label:          string;
//   onClickHandler: () => void;   ← method renamed
//   isVisible:      boolean;      ← boolean renamed
//   count:          number;       ← unchanged
// }
```

**Q14. What is a homomorphic vs non-homomorphic mapped type, and what are the practical implications?**

A: A **homomorphic** mapped type iterates over `keyof T` (or `keyof SomeTypeBasedOnT`). TypeScript recognizes this pattern and: copies `readonly` and `?` modifiers from the source type into the result (before any explicit modifier additions/removals), and understands the result as structurally isomorphic to `T`. A **non-homomorphic** mapped type iterates over a union not derived from `keyof T` — a literal union, `string`, `number`, etc. TypeScript generates a fresh type with no inherited modifiers.

```typescript
interface Source { readonly x: number; y?: string; }

// HOMOMORPHIC — modifiers from Source are copied:
type Homo<T>    = { [K in keyof T]: T[K] };
type H = Homo<Source>;
// { readonly x: number; y?: string }  ← readonly and ? PRESERVED ✓

// NON-HOMOMORPHIC — no source type to copy from:
type NonHomo    = { [K in 'x' | 'y']: string };
// { x: string; y: string }  ← no modifiers, even though we named the same keys

// The subtle case — keyof T via a type parameter:
type MustBeHomomorphic<T> = { [K in keyof T]-?: T[K] };
// Still homomorphic! T is the source, -? REMOVES ? (explicit removal overrides copy)
// Result for Source: { readonly x: number; y: string }
//                                          ↑ ? removed, readonly preserved

// Record<K, V> — non-homomorphic despite looking similar:
type R = Record<keyof Source, number>;
// { x: number; y: number }  ← modifiers NOT preserved (not [K in keyof T] form)

// Practical implication: if you need to preserve readonly/? from the source,
// your mapped type MUST use [K in keyof T] (or a parameter that is keyof T).
// If you use [K in SomeUnion], write your own modifiers explicitly.
```

**Q15. What are `RequiredKeys<T>`, `OptionalKeys<T>`, and `ReadonlyKeys<T>` — utility types for introspecting type shape?**

A: These meta-utility types extract which keys have specific modifiers, using conditional types and the special behavior of `undefined extends T[K]` (for optional check) and `{} extends Pick<T, K>` or `ReadonlyKeys` detection. They produce key unions rather than transformed object types — useful for constraining generic parameters or building higher-level utilities.

```typescript
// OptionalKeys: keys where the property type includes undefined as a possible assignment
type OptionalKeys<T> = {
  [K in keyof T]-?: undefined extends T[K] ? K : never;
}[keyof T];

// RequiredKeys: complement of OptionalKeys
type RequiredKeys<T> = {
  [K in keyof T]-?: undefined extends T[K] ? never : K;
}[keyof T];

// ReadonlyKeys: keys where removing readonly changes the type
// (uses the fact that { readonly [K]: ... } differs from { [K]: ... } for mutable check)
type ReadonlyKeys<T> = {
  [K in keyof T]-?: (<U>() => U extends Pick<T, K>        ? 1 : 2) extends
                    (<U>() => U extends Pick<Mutable<T>, K>? 1 : 2) ? never : K;
}[keyof T];
type Mutable<T> = { -readonly [K in keyof T]: T[K] };

// Usage:
interface UserForm {
  readonly id: number;
  name: string;
  email?: string;
  phone?: string;
}

type OptK   = OptionalKeys<UserForm>;  // "email" | "phone"
type ReqK   = RequiredKeys<UserForm>;  // "id" | "name"
type RoK    = ReadonlyKeys<UserForm>;  // "id"

// Build a type that splits required and optional sections:
type Split<T> = {
  required: Pick<T, RequiredKeys<T>>;
  optional: Pick<T, OptionalKeys<T>>;
};
type SplitUserForm = Split<UserForm>;
// {
//   required: { readonly id: number; name: string };
//   optional: { email?: string; phone?: string };
// }
```

## Topic E: Interview-Style Questions

**Q16. What are the common mistakes when writing mapped types, and how do you debug them?**

A: Five common mistakes:

**1. Losing literal types in values**: `{ [K in keyof T]: T[K] }` is the correct identity; `{ [K in keyof T]: string }` replaces all values with `string`. Always use `T[K]` for the original value type.

**2. `keyof T` gives `never` unexpectedly**: if `T` is `unknown` or `{}`, `keyof T` is `never` and the mapped type produces `{}`. Check your type constraints — `T extends object` is often needed.

**3. `as` clause must produce a key type, not a value**: in `{ [K in keyof T as Expression]: ... }`, `Expression` must be a string/number/symbol/never type. Using a value expression (a JavaScript expression) in a type position is a common confusion.

**4. Missing the `string &` intersection for string-typed keys in template literals**: template literal types require string operands. `K` from `keyof T` is `string | number | symbol`. You must write `` `prefix_${string & K}` `` to force string context. Without `string &`, TypeScript errors.

**5. Non-homomorphic when you meant homomorphic**: using `[K in SomePrecomputedUnion]` instead of `[K in keyof T]` loses modifier preservation.

```typescript
// Mistake 1 — accidental value replacement:
type BadCopy<T> = { [K in keyof T]: string };  // replaces ALL values with string ✗
type GoodCopy<T> = { [K in keyof T]: T[K] };   // preserves each value type ✓

// Mistake 4 — missing `string &` in template literal:
type Bad<T>  = { [K in keyof T as `get_${K}`]: T[K] };
//                                          ↑ Error: K is string|number|symbol
type Good<T> = { [K in keyof T as `get_${string & K}`]: T[K] }; // ✓

// Debugging mapped types — hover in VSCode or use type assertions:
type Debug<T> = T extends any ? T : never; // identity that forces expansion
type Check = Debug<Partial<{ x: number; y: string }>>; // hover to see full expansion
```

**Q17. How do mapped types compose with other TypeScript features — intersection, conditional types, and generics?**

A: Mapped types compose freely with all other type constructs. With **intersection** (`&`): combine two mapped types to get a type with both sets of properties — used for getter/setter generation or adding computed properties alongside existing ones. With **conditional types**: use conditional types inside the value position to transform each value differently based on its type; use conditional types in the `as` clause to filter or rename based on value type. With **generics**: mapped types are generic when they reference a type parameter; they become fully concrete only when the type parameter is provided — enabling reusable utility types.

```typescript
// Intersection of two mapped types:
type WithGetters<T> = { [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K] };
type WithSetters<T> = { [K in keyof T as `set${Capitalize<string & K>}`]: (v: T[K]) => void };
type WithAccessors<T> = T & WithGetters<T> & WithSetters<T>;
// Original properties PLUS getter methods PLUS setter methods

// Conditional type in value position — transform based on value type:
type Serialize<T> = {
  [K in keyof T]: T[K] extends Date
    ? string             // Dates become strings (for JSON serialization)
    : T[K] extends object
      ? Serialize<T[K]>  // nested objects → recursively serialize
      : T[K];            // primitives pass through unchanged
};

interface Post { title: string; body: string; publishedAt: Date; author: { name: string; joinedAt: Date } }
type SerializedPost = Serialize<Post>;
// {
//   title:       string;
//   body:        string;
//   publishedAt: string;  ← Date → string ✓
//   author: {
//     name:     string;
//     joinedAt: string;  ← nested Date → string ✓
//   }
// }

// Generic mapped type that adds metadata to each property:
type WithTimestamps<T> = {
  [K in keyof T]: { value: T[K]; lastModified: Date; modifiedBy: string };
};
```

**Q18. In one sentence each, state what each major mapped type pattern does.**

A:
- **`{ [K in keyof T]: T[K] }`** — identity mapped type: produces a structurally identical copy of T, preserving all modifiers.
- **`{ [K in keyof T]?: T[K] }`** — adds `?` to every property, making all optional (Partial).
- **`{ [K in keyof T]-?: T[K] }`** — removes `?` from every property, making all required (Required).
- **`{ readonly [K in keyof T]: T[K] }`** — adds `readonly` to every property (Readonly).
- **`{ -readonly [K in keyof T]: T[K] }`** — removes `readonly` from every property (Mutable).
- **`{ [K in keyof T as K extends Filter ? K : never]: T[K] }`** — keeps only keys that match the filter union (PickByValue-style).
- **`{ [K in keyof T as \`prefix_${string & K}\`]: T[K] }`** — renames every key by prepending a prefix using template literal types.
- **`{ [K in K]: V }`** where `K extends keyof any` — creates a type with specific keys all mapping to the same value type V (Record).
- **`T extends object ? { [K in keyof T]: Deep<T[K]> } : T`** — recursively applies a transformation to all levels of a nested type (deep utility types).
- **`{ [K in keyof T]: T[K] extends V ? K : never }[keyof T]`** — extracts the union of keys whose value type matches V (KeysOfType).

// ════════════════════════════════════════════════════════════════════════════
// SOURCE TYPE
// ════════════════════════════════════════════════════════════════════════════

interface User {
  readonly id:   number;
  name:          string;
  email?:        string;
  readonly role: 'admin' | 'user';
}

// ════════════════════════════════════════════════════════════════════════════
// PARTIAL<T> — adds ? to all properties
// ════════════════════════════════════════════════════════════════════════════

type Partial<T> = { [K in keyof T]?: T[K] };
type PartialUser = Partial<User>;

// Resolution:
// keyof User = 'id' | 'name' | 'email' | 'role'
// K='id':    readonly id?:   number              (readonly preserved + ? added)
// K='name':  name?:          string              (? added)
// K='email': email?:         string              (already ?, adding ? is idempotent)
// K='role':  readonly role?: 'admin' | 'user'   (readonly preserved + ? added)
// Result: { readonly id?: number; name?: string; email?: string; readonly role?: 'admin' | 'user' }

// ════════════════════════════════════════════════════════════════════════════
// REQUIRED<T> — removes ? from all properties
// ════════════════════════════════════════════════════════════════════════════

type Required<T> = { [K in keyof T]-?: T[K] };
type RequiredUser = Required<User>;

// Resolution:
// K='id':    readonly id:   number              (readonly preserved; no ? to remove)
// K='name':  name:          string              (no ? to remove)
// K='email': email:         string              (? removed by -?)
// K='role':  readonly role: 'admin' | 'user'   (readonly preserved)
// Result: { readonly id: number; name: string; email: string; readonly role: 'admin' | 'user' }

// ════════════════════════════════════════════════════════════════════════════
// READONLY<T> — adds readonly to all properties
// ════════════════════════════════════════════════════════════════════════════

type Readonly<T> = { readonly [K in keyof T]: T[K] };
type ReadonlyUser = Readonly<User>;

// Resolution:
// K='id':    readonly id:    number              (already readonly; no change)
// K='name':  readonly name:  string              (readonly added)
// K='email': readonly email?: string             (readonly added; ? preserved)
// K='role':  readonly role:  'admin' | 'user'   (already readonly; no change)

// ════════════════════════════════════════════════════════════════════════════
// MUTABLE<T> — removes readonly from all properties (not in TS stdlib)
// ════════════════════════════════════════════════════════════════════════════

type Mutable<T> = { -readonly [K in keyof T]: T[K] };
type MutableUser = Mutable<User>;

// Result: { id: number; name: string; email?: string; role: 'admin' | 'user' }
// readonly removed from id and role; email? preserved

// ════════════════════════════════════════════════════════════════════════════
// PICK<T, K> — select a subset of keys
// ════════════════════════════════════════════════════════════════════════════

type Pick<T, K extends keyof T> = { [P in K]: T[P] };
type UserPublic = Pick<User, 'id' | 'name'>;

// K is constrained to keyof User = 'id' | 'name' | 'email' | 'role'
// P iterates over 'id' | 'name':
// P='id':   readonly id: number   (modifier preserved from User.id)
// P='name': name: string          (no modifiers from User.name)
// Result: { readonly id: number; name: string }

// ════════════════════════════════════════════════════════════════════════════
// OMIT<T, K> — exclude a subset of keys
// ════════════════════════════════════════════════════════════════════════════

type Exclude<T, U> = T extends U ? never : T; // distribute over union
type Omit<T, K extends keyof any> = Pick<T, Exclude<keyof T, K>>;

type UserWithoutEmail = Omit<User, 'email'>;
// Exclude<'id'|'name'|'email'|'role', 'email'> = 'id' | 'name' | 'role'
// Pick<User, 'id'|'name'|'role'>
// Result: { readonly id: number; name: string; readonly role: 'admin' | 'user' }

// ════════════════════════════════════════════════════════════════════════════
// RECORD<K, V> — create a type with specific keys all mapped to V
// ════════════════════════════════════════════════════════════════════════════

type Record<K extends keyof any, V> = { [P in K]: V };

type RolePermissions = Record<'admin' | 'user' | 'moderator', string[]>;
// { admin: string[]; user: string[]; moderator: string[] }

// Non-homomorphic — no source T, so no modifier preservation:
const perms: RolePermissions = {
  admin:     ['read', 'write', 'delete'],
  user:      ['read'],
  moderator: ['read', 'write'],
};

// ════════════════════════════════════════════════════════════════════════════
// COMPOSITION EXAMPLES — TypeScript patterns in the wild
// ════════════════════════════════════════════════════════════════════════════

// Update type: Omit primary key (id), make everything else optional
type UpdateDto<T, PK extends keyof T = 'id'> = Partial<Omit<T, PK>>;

type UserUpdateDto = UpdateDto<User>;
// Omit<User, 'id'> = { name: string; email?: string; role: 'admin' | 'user' }
// Partial<that>    = { name?: string; email?: string; role?: 'admin' | 'user' }
// (readonly on role also partially preserved — but role is now optional)

// Read-only response type: all fields required + readonly:
type ResponseDto<T> = Readonly<Required<T>>;
type UserResponse = ResponseDto<User>;
// { readonly id: number; readonly name: string; readonly email: string; readonly role: 'admin'|'user' }

## Implementation 3 — Filter and Transform Patterns

### Challenge
Build a library of filter-and-transform mapped types that select, exclude, or restructure properties based on their value types — for real-world property classification scenarios.

### Implementation

```typescript
// ════════════════════════════════════════════════════════════════════════════
// PICK / OMIT BY VALUE TYPE
// ════════════════════════════════════════════════════════════════════════════

type PickByValue<T, V> = {
  [K in keyof T as T[K] extends V ? K : never]: T[K]
};

type OmitByValue<T, V> = {
  [K in keyof T as T[K] extends V ? never : K]: T[K]
};

// Type resolution trace for PickByValue<Entity, string>:
interface Entity {
  id:          number;
  name:        string;
  description: string;
  active:      boolean;
  createdAt:   Date;
  tags:        string[];
}

// K='id':          T[K]=number.  number extends string? NO  → never (removed)
// K='name':        T[K]=string.  string extends string? YES → 'name' (kept)
// K='description': T[K]=string.  YES → 'description' (kept)
// K='active':      T[K]=boolean. NO  → never (removed)
// K='createdAt':   T[K]=Date.    NO  → never (removed)
// K='tags':        T[K]=string[].string[] extends string? NO → never (removed)
// Result: { name: string; description: string }

type StringFields  = PickByValue<Entity, string>;   // { name: string; description: string }
type NumberFields  = PickByValue<Entity, number>;   // { id: number }
type BooleanFields = PickByValue<Entity, boolean>;  // { active: boolean }

// Function/method extraction:
type FunctionKeys<T>    = PickByValue<T, Function>;
type NonFunctionKeys<T> = OmitByValue<T, Function>;

class UserService {
  userId = '123';
  userName = 'Alice';
  getUser() { return {}; }
  updateUser(data: unknown) { }
}

type ServiceMethods = FunctionKeys<UserService>;
// { getUser: () => {}; updateUser: (data: unknown) => void }

type ServiceData = NonFunctionKeys<UserService>;
// { userId: string; userName: string }

// ════════════════════════════════════════════════════════════════════════════
// TRANSFORM VALUES BY TYPE
// ════════════════════════════════════════════════════════════════════════════

// Replace all Date values with string (for JSON serialization):
type JsonSafe<T> = {
  [K in keyof T]: T[K] extends Date
    ? string                          // Date → ISO string
    : T[K] extends Date[]
      ? string[]                      // Date[] → string[]
      : T[K] extends object
        ? JsonSafe<T[K]>              // nested object → recurse
        : T[K];                       // primitive → unchanged
};

interface Post {
  id:          number;
  title:       string;
  publishedAt: Date;
  author:      { name: string; joinedAt: Date };
  tags:        string[];
}

type JsonPost = JsonSafe<Post>;
// {
//   id:          number;
//   title:       string;
//   publishedAt: string;      ← Date → string ✓
//   author: {
//     name:     string;
//     joinedAt: string;       ← nested Date → string ✓
//   };
//   tags:        string[];    ← string[] unchanged ✓
// }

// Make optional properties nullable instead of optional:
// Optional (x?: T) → nullable (x: T | null) for database representation
type NullableOptional<T> = {
  [K in keyof T]-?: undefined extends T[K]
    ? Exclude<T[K], undefined> | null  // was optional → now nullable, not undefined
    : T[K];                            // was required → unchanged
};

type DbUser = NullableOptional<User>;
// { readonly id: number; name: string; email: string | null; readonly role: 'admin'|'user' }
// email was optional (email?: string) → now nullable (email: string | null) ✓

// ════════════════════════════════════════════════════════════════════════════
// FLATTEN NESTED TYPES (one level)
// ════════════════════════════════════════════════════════════════════════════

// Spread an object type — useful for spreading nested objects into a parent:
type Spread<T> = { [K in keyof T]: T[K] };

// Merge two types, with B overriding A on key conflicts:
type Merge<A, B> = Omit<A, keyof B> & B;

// ════════════════════════════════════════════════════════════════════════════
// EXTRACT VALUE TYPE UNION
// ════════════════════════════════════════════════════════════════════════════

type ValuesOf<T> = T[keyof T];
type KeysOfValue<T, V> = { [K in keyof T]: T[K] extends V ? K : never }[keyof T];

// Example:
type StatusMap = {
  pending:  0;
  active:   1;
  inactive: 2;
  deleted:  3;
};

type AllStatuses = ValuesOf<StatusMap>; // 0 | 1 | 2 | 3
type AllStatusNames = keyof StatusMap;  // 'pending' | 'active' | 'inactive' | 'deleted'
type ActiveKey = KeysOfValue<StatusMap, 1>; // 'active'
```

## Implementation 4 — Deep Recursive Types

### Challenge
Implement deep recursive variants of the standard utility types that apply transformations at every nesting level, with correct handling of special object types (Date, RegExp, Function).

### Implementation

```typescript
// ════════════════════════════════════════════════════════════════════════════
// THE LEAF TYPE GUARD — what should NOT be recursed into?
// ════════════════════════════════════════════════════════════════════════════

// These are objects but should be treated as atomic values:
type LeafTypes = Date | RegExp | Function | Error | Map<any, any> | Set<any> | Promise<any>;

// Is T a "plain" object we should recurse into?
type IsPlainObject<T> = T extends LeafTypes ? false : T extends object ? true : false;

// ════════════════════════════════════════════════════════════════════════════
// DEEP PARTIAL — recursively make all properties optional
// ════════════════════════════════════════════════════════════════════════════

type DeepPartial<T> =
  T extends LeafTypes ? T :              // atomic → pass through
  T extends (infer E)[] ? DeepPartial<E>[] : // array → recurse into element type
  T extends object ? { [K in keyof T]?: DeepPartial<T[K]> } : // object → recurse
  T;                                     // primitive → pass through

// ════════════════════════════════════════════════════════════════════════════
// DEEP READONLY — recursively make all properties readonly
// ════════════════════════════════════════════════════════════════════════════

type DeepReadonly<T> =
  T extends LeafTypes ? T :
  T extends (infer E)[] ? ReadonlyArray<DeepReadonly<E>> :
  T extends object ? { readonly [K in keyof T]: DeepReadonly<T[K]> } :
  T;

// ════════════════════════════════════════════════════════════════════════════
// DEEP REQUIRED — recursively make all properties required
// ════════════════════════════════════════════════════════════════════════════

type DeepRequired<T> =
  T extends LeafTypes ? T :
  T extends (infer E)[] ? DeepRequired<E>[] :
  T extends object ? { [K in keyof T]-?: DeepRequired<T[K]> } :
  T;

// ════════════════════════════════════════════════════════════════════════════
// RESOLUTION TRACE — DeepPartial on a nested type
// ════════════════════════════════════════════════════════════════════════════

interface LoanApplication {
  id:       string;
  amount:   number;
  borrower: {
    id:      string;
    name:    string;
    address: {
      street: string;
      city:   string;
      zip:    string;
    };
  };
  documents: {
    type:   string;
    url:    string;
    uploadedAt: Date;
  }[];
}

type PartialApplication = Partial<LoanApplication>;
// {
//   id?:     string;
//   amount?: number;
//   borrower?: {          // ← nested borrower is optional BUT its fields are still required!
//     id: string;         // ← NOT optional
//     name: string;       // ← NOT optional
//     address: { ... };   // ← NOT optional
//   };
//   documents?: { ... }[];
// }

type DeepPartialApplication = DeepPartial<LoanApplication>;
// Resolution:
// T = LoanApplication (plain object → recurse into { [K]?: DeepPartial<T[K]> })
// K='id':     id?: DeepPartial<string> = id?: string    (primitive)
// K='amount': amount?: DeepPartial<number> = amount?: number (primitive)
// K='borrower':
//   DeepPartial<{id:string, name:string, address:{...}}>
//   → plain object → recurse:
//   { id?: string; name?: string; address?: DeepPartial<{street,city,zip}> }
//   DeepPartial<{street,city,zip}> → { street?: string; city?: string; zip?: string }
// K='documents':
//   T[K] = { type: string; url: string; uploadedAt: Date }[]
//   → array → DeepPartial<element>[]
//   element = { type: string; url: string; uploadedAt: Date }
//   → plain object → { type?: string; url?: string; uploadedAt?: Date }  (Date is a leaf ✓)
//   Result: { type?: string; url?: string; uploadedAt?: Date }[]
//
// Final result:
// {
//   id?:     string;
//   amount?: number;
//   borrower?: {
//     id?:   string;
//     name?: string;
//     address?: {
//       street?: string;
//       city?:   string;
//       zip?:    string;
//     };
//   };
//   documents?: {
//     type?:       string;
//     url?:        string;
//     uploadedAt?: Date;    ← Date preserved as-is (LeafType guard) ✓
//   }[];
// }

// ════════════════════════════════════════════════════════════════════════════
// DEEP MERGE — merge two types recursively
// ════════════════════════════════════════════════════════════════════════════

type DeepMerge<A, B> =
  B extends LeafTypes ? B :
  A extends LeafTypes ? B :
  A extends object ? B extends object
    ? { [K in keyof A | keyof B]:
        K extends keyof B
          ? K extends keyof A
            ? DeepMerge<A[K], B[K]>  // in both: deep merge
            : B[K]                    // only in B: use B
          : K extends keyof A
            ? A[K]                    // only in A: use A
            : never                   // impossible
      }
    : B
  : B;
```

## Implementation 6 — Advanced Patterns: Union to Record, Optional/Required Key Extraction

### Challenge
Build advanced mapped type utilities that manipulate type structure at a meta level — converting union types to object types, extracting key sets as unions, and creating type-safe merge utilities.

### Implementation

```typescript
// ════════════════════════════════════════════════════════════════════════════
// UNION TO RECORD — convert a union of string literals to an object type
// ════════════════════════════════════════════════════════════════════════════

// Simple: all values same type
type UnionToRecord<K extends string, V> = { [P in K]: V };

type HttpMethod = 'GET' | 'POST' | 'PUT' | 'PATCH' | 'DELETE';
type MethodHandler = (path: string, handler: Function) => void;
type RouterMethods = UnionToRecord<Lowercase<HttpMethod>, MethodHandler>;
// { get: MethodHandler; post: MethodHandler; put: MethodHandler; ... }

// Complex: each union member maps to a specific type
type DiscriminantToType<T extends { kind: string }> = {
  [K in T['kind']]: Extract<T, { kind: K }>
};

type Shape =
  | { kind: 'circle';    radius: number }
  | { kind: 'rectangle'; width: number; height: number }
  | { kind: 'triangle';  base: number; height: number };

type ShapeMap = DiscriminantToType<Shape>;
// {
//   circle:    { kind: 'circle'; radius: number };
//   rectangle: { kind: 'rectangle'; width: number; height: number };
//   triangle:  { kind: 'triangle'; base: number; height: number };
// }

// Access specific variant:
type CircleType = ShapeMap['circle']; // { kind: 'circle'; radius: number }

// ════════════════════════════════════════════════════════════════════════════
// OPTIONAL AND REQUIRED KEY EXTRACTION
// ════════════════════════════════════════════════════════════════════════════

// Technique: map each key to itself or never, then index to get the union
type OptionalKeys<T> = {
  [K in keyof T]-?: {} extends Pick<T, K> ? K : never;
}[keyof T];

type RequiredKeys<T> = {
  [K in keyof T]-?: {} extends Pick<T, K> ? never : K;
}[keyof T];

// Resolution trace for OptionalKeys:
// {} extends Pick<T, K> is true when K is optional in T
// (because Pick of an optional key gives { k?: V }, and {} extends { k?: V } is true)
// (because { k?: V } allows absence, and {} has no k)

interface Config {
  host:     string;
  port:     number;
  timeout?: number;
  retries?: number;
}

type ConfigOptional = OptionalKeys<Config>; // 'timeout' | 'retries'
type ConfigRequired = RequiredKeys<Config>; // 'host' | 'port'

// Use to build separate required and optional sections:
type SplitOptional<T> = {
  required: Pick<T, RequiredKeys<T>>;
  optional: Partial<Pick<T, OptionalKeys<T>>>;
};

type SplitConfig = SplitOptional<Config>;
// {
//   required: { host: string; port: number };
//   optional: { timeout?: number; retries?: number };
// }

// ════════════════════════════════════════════════════════════════════════════
// TYPE-SAFE OBJECT MERGE WITH PRECEDENCE
// ════════════════════════════════════════════════════════════════════════════

// Merge: B overrides A, but the result type tracks which keys came from where
type Override<A, B> = Omit<A, keyof B> & B;

// Deep override:
type DeepOverride<A, B> = {
  [K in keyof A | keyof B]:
    K extends keyof B
      ? K extends keyof A
        ? B[K] extends object
          ? A[K] extends object
            ? DeepOverride<A[K], B[K]>  // both objects → recurse
            : B[K]                       // A is not object → B wins
          : B[K]                         // B is not object → B wins
        : B[K]                           // only in B
      : K extends keyof A
        ? A[K]                           // only in A
        : never;
};

// Spread helper — like Object.assign but type-safe:
declare function merge<A extends object, B extends object>(a: A, b: B): Override<A, B>;

const defaults = { timeout: 3000, retries: 3, verbose: false };
const overrides = { timeout: 5000, host: 'api.example.com' };
const merged = merge(defaults, overrides);
// type: { retries: number; verbose: boolean } & { timeout: number; host: string }
// = { retries: number; verbose: boolean; timeout: number; host: string }

// ════════════════════════════════════════════════════════════════════════════
// READONLY CONDITIONAL — preserve existing readonly in Partial-like types
// ════════════════════════════════════════════════════════════════════════════

// Partial that KEEPS existing readonly on readonly fields:
type PartialExceptReadonly<T> = {
  [K in keyof T as T extends { readonly [L in K]-?: T[K] } ? never : K]?: T[K]
} & {
  [K in keyof T as T extends { readonly [L in K]-?: T[K] } ? K : never]: T[K]
};

// Simpler: make only non-readonly fields optional:
type PartialMutable<T> = {
  [K in keyof T as {} extends Pick<Mutable<T>, K> ? K : never]?: T[K];
} & {
  [K in keyof T as {} extends Pick<Mutable<T>, K> ? never : K]: T[K];
};

// ════════════════════════════════════════════════════════════════════════════
// FLATTENED ENUM-LIKE FROM NESTED OBJECT
// ════════════════════════════════════════════════════════════════════════════

const AppRoutes = {
  auth: { login: '/auth/login', logout: '/auth/logout', refresh: '/auth/refresh' },
  users: { list: '/users', detail: '/users/:id', create: '/users' },
  loans: { list: '/loans', detail: '/loans/:id', disburse: '/loans/:id/disburse' },
} as const;

// Extract all route paths as a union:
type NestedValues<T> = T extends object
  ? { [K in keyof T]: NestedValues<T[K]> }[keyof T]
  : T;

type AppRoute = NestedValues<typeof AppRoutes>;
// '/auth/login' | '/auth/logout' | '/auth/refresh' | '/users' | '/users/:id' | ...

// Type-safe route lookup:
type RouteSection = keyof typeof AppRoutes; // 'auth' | 'users' | 'loans'
type SectionRoutes<S extends RouteSection> = typeof AppRoutes[S][keyof typeof AppRoutes[S]];
type AuthRoutes  = SectionRoutes<'auth'>;  // '/auth/login' | '/auth/logout' | '/auth/refresh'
type LoanRoutes  = SectionRoutes<'loans'>; // '/loans' | '/loans/:id' | '/loans/:id/disburse'
```

## Quick Reference — Mapped Type Pattern Decision Tree

```
WHAT DO YOU NEED TO BUILD?
│
├── TRANSFORM ALL PROPERTIES THE SAME WAY?
│   ├── Make all optional        → { [K in keyof T]?: T[K] }          (Partial)
│   ├── Make all required        → { [K in keyof T]-?: T[K] }         (Required)
│   ├── Make all readonly        → { readonly [K in keyof T]: T[K] }  (Readonly)
│   ├── Remove all readonly      → { -readonly [K in keyof T]: T[K] } (Mutable)
│   └── Change all value types   → { [K in keyof T]: NewType }
│
├── SELECT / EXCLUDE PROPERTIES?
│   ├── Select by key name       → { [K in AllowedKeys]: T[K] }           (Pick)
│   ├── Exclude by key name      → Pick<T, Exclude<keyof T, ExcludedKeys>> (Omit)
│   ├── Select by value type     → { [K in keyof T as T[K] extends V ? K : never]: T[K] }
│   └── Exclude by value type    → { [K in keyof T as T[K] extends V ? never : K]: T[K] }
│
├── RENAME KEYS?
│   ├── Add prefix/suffix        → { [K in keyof T as `prefix_${string & K}`]: T[K] }
│   ├── Generate getter names    → { [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K] }
│   ├── Generate event handlers  → { [K in keyof T as `on${Capitalize<string & K>}Change`]: ... }
│   └── Conditional rename       → { [K in keyof T as condition ? K : `renamed_${K}`]: T[K] }
│
├── CREATE FROM A KEY UNION (not from existing type T)?
│   └── Record<Keys, ValueType>  → { [K in Keys]: V }  (non-homomorphic)
│
├── APPLY RECURSIVELY TO NESTED TYPES?
│   └── T extends object
│         ? { [K in keyof T]: DeepUtility<T[K]> }
│         : T
│       Guard against LeafTypes = Date | Function | RegExp | Map | Set | Promise
│
└── MODIFIER PRESERVATION RULE:
    Homomorphic [K in keyof T]: preserves readonly and ? from source.
    Non-homomorphic [K in SomeUnion]: NO automatic modifier preservation.
    Use +/- prefix to explicitly add or remove modifiers:
      +readonly / readonly = add readonly
      -readonly            = remove readonly
      +? / ?              = add optional
      -?                   = remove optional (Required uses this)
```

## Common Bugs Checklist

Before using mapped types in production TypeScript, verify:

1. **Missing `string &` intersection in template literal key remapping?** — `` `prefix_${K}` `` where `K` comes from `keyof T` fails because `K` is `string | number | symbol`. Write `` `prefix_${string & K}` `` to constrain `K` to strings. Numeric and symbol keys are dropped (they can't be part of a template literal string type).

2. **Using `[K in SomePrecomputedUnion]` when you needed modifier preservation?** — If `SomePrecomputedUnion` was derived from `keyof T` before being passed in, TypeScript no longer sees it as homomorphic. Store the source type as a type parameter and use `[K in keyof T]` directly. Non-homomorphic = no automatic `readonly`/`?` copying.

3. **`as never` filter not working because the condition is wrong?** — `[K in keyof T as T[K] extends string ? K : never]` — if `T[K]` is `string | undefined` (from an optional property), `string | undefined extends string` is false. You may need `Exclude<T[K], undefined> extends string` to handle optional properties correctly.

4. **Deep recursive type hitting TypeScript's recursion limit?** — TypeScript limits type recursion depth (around 100 levels). For very deeply nested types, you may hit "Type instantiation is excessively deep" errors. Use explicit recursion limits or restructure your types to be shallower.

5. **Forgetting `LeafTypes` guard in deep utility types?** — `DeepPartial<Date>` without a guard produces `{ getTime?: () => number; toString?: () => string; ... }` — completely wrong. Always guard against `Date | Function | RegExp | Map | Set | Promise` (and other built-in classes) before recursing.

6. **`-?` removes the optional modifier but leaves `undefined` in the value type?** — `Required<{ x?: string }>` gives `{ x: string }` — TypeScript removes both `?` AND removes `undefined` from `string | undefined`. But with explicit `undefined` in a union (`x: string | undefined`), `Required` doesn't help — that's not the `?` modifier, that's an explicit union. Use `Exclude<T[K], undefined>` to remove explicit `undefined` from value types.

7. **`[K in keyof T]` iterates over class instance keys including methods?** — `keyof MyClass` includes method names (`getUser`, `save`, etc.) as well as properties. Use `OmitByValue<T, Function>` to filter them out when you only want data properties.

8. **`Omit<T, K>` doesn't preserve readonly modifiers on retained properties?** — This is a known TypeScript issue: `Omit` is implemented as `Pick<T, Exclude<keyof T, K>>`. `Pick` uses `{ [P in K]: T[P] }` — homomorphic, so it SHOULD preserve readonly. If you see loss of readonly, check your TypeScript version (fixed in newer versions) or use a manual implementation.

9. **Template literal distribution over union doesn't produce what you expect?** — `` `on${Capitalize<'click' | 'focus'>}` `` distributes correctly: `'onClick' | 'onFocus'`. But `Capitalize<string>` = `string` (not a union of all capitalized strings). Template literals distribute over union types, not over `string` as a whole type.

10. **`ValuesOf<T>` union loses discriminant information?** — `T[keyof T]` gives a union of value types, but each value is "detached" from its key. If you need key-value pairs as a union, use: `{ [K in keyof T]: { key: K; value: T[K] } }[keyof T]` — produces `{ key: 'id'; value: number } | { key: 'name'; value: string } | ...`.

11. **Conditional type in value position not distributing over union as expected?** — `T[K] extends string ? K : never` where `T[K]` is `string | number` does NOT distribute. Only top-level `T extends U ? X : Y` (where T is the type parameter) distributes. Inside a mapped type value, write the full condition or use a distributive helper type.

12. **Using `Partial<T>` where `DeepPartial<T>` was needed?** — `Partial` makes top-level properties optional. Nested object properties remain required. This causes runtime errors when you try to spread `{}` into a deeply nested position. Always clarify whether "partial" means one-level or deep for the use case.

---

**Final Tip:** At the 5 YOE level, the decisive signal for mapped types is articulating **three things** before writing the type: (1) **What am I iterating over?** — "I'm iterating over `keyof T` (homomorphic — modifier-preserving) vs over a fixed union (non-homomorphic — no modifier inheritance)." (2) **What key does each iteration produce?** — "Keep the key as-is (`K`), rename it with a template literal, or filter it out with `never` in the `as` clause." (3) **What value type does each iteration produce?** — "Preserve `T[K]` (original type), wrap it (`T[K] | null`, `() => T[K]`), conditionally transform it (`T[K] extends Date ? string : T[K]`), or replace it entirely." For key remapping: *"I use `` `get${Capitalize<string & K>}` `` — the `string &` is mandatory because `K` from `keyof T` is `string | number | symbol`, and template literals require string operands."* For modifier removal: *"I use `-?` to remove optional from every property — this is `Required<T>`'s implementation; `-readonly` is the `Mutable<T>` pattern that TypeScript doesn't ship but every codebase needs."*
